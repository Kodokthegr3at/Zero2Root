## 1. IR dan forensik: hubungan keduanya

Incident response bertujuan menghentikan serangan dan memulihkan layanan secepatnya. Forensik bertujuan menjawab dengan bukti apa yang terjadi, bagaimana, dan sejak kapan. Keduanya berjalan bersamaan: tim IR butuh jawaban forensik untuk tahu apa yang harus dibersihkan, dan analis forensik butuh tim IR agar bukti tidak rusak saat penahanan.

| Pertanyaan | Dijawab dengan |
|:---|:---|
| Bagaimana penyerang masuk? | Log web, email, artefak eksekusi |
| Kapan pertama kali masuk? | Timeline |
| Mesin mana saja yang tersentuh? | Log autentikasi, artefak lateral movement |
| Data apa yang diambil? | Log jaringan, artefak akses file |
| Apakah masih ada di dalam? | Pemeriksaan persistence, memori |

## 2. Urutan volatilitas

Bukti yang paling cepat hilang diambil lebih dulu (RFC 3227).

| Urutan | Bukti | Hilang ketika |
|:---|:---|:---|
| 1 | Register CPU, cache | Hitungan nanodetik |
| 2 | RAM: proses, koneksi jaringan, kunci enkripsi | Mesin dimatikan |
| 3 | Status jaringan, tabel ARP | Beberapa menit |
| 4 | File sementara, swap | Reboot atau pembersihan |
| 5 | Disk | Ditimpa |
| 6 | Log jarak jauh, backup | Rotasi log |

Kesalahan yang sering terjadi adalah langsung mencabut kabel listrik. Memori hilang, padahal malware fileless ([LC-074](3.%20Threat%20Hunting%20%26%20Detection%20Engineering%20%28Sigma%2C%20YARA%2C%20ATT%26CK%29.md)) hanya hidup di RAM. Kalau memungkinkan, ambil image memori dulu, baru isolasi jaringan.

## 3. Chain of custody dan integritas bukti

Kalau kasus bisa berujung ke pengadilan atau HR, bukti harus bisa dibuktikan tidak berubah.

```bash
# Hash bukti segera setelah akuisisi
sha256sum disk.img > disk.img.sha256

# Verifikasi kapan pun nanti
sha256sum -c disk.img.sha256
```

Formulir chain of custody minimal berisi:

| Kolom | Contoh |
|:---|:---|
| ID bukti | EV-2026-014-01 |
| Deskripsi | Laptop Dell Latitude, S/N XXXX, disk NVMe 512 GB |
| Diambil oleh / waktu | Analis A, 2026-10-16 14:05 WIB |
| Hash SHA-256 | `9f86d0...` |
| Diserahkan ke / waktu / alasan | Analis B, 2026-10-16 16:30, analisis |

Prinsipnya: analisis selalu dilakukan pada salinan, bukan pada bukti asli.

## 4. Akuisisi: disk dan memori

### 4.1 Memori

| OS | Alat gratis | Contoh |
|:---|:---|:---|
| Windows | WinPmem, DumpIt, Magnet RAM Capture | `winpmem.exe mem.raw` |
| Linux | LiME (modul kernel), AVML | `sudo avml mem.lime` |
| VM | Snapshot hypervisor | File `.vmem` di VMware |

### 4.2 Disk

```bash
# Image disk penuh (sambungkan disk bukti lewat write blocker)
sudo dc3dd if=/dev/sdb of=disk.img hash=sha256 log=akuisisi.log

# Alternatif: ewfacquire membuat format E01 yang terkompresi dan menyimpan metadata
sudo ewfacquire /dev/sdb
```

### 4.3 Triage collection

Image disk 1 TB bisa makan waktu berjam-jam. Untuk banyak mesin, kumpulkan artefak penting saja:

| Alat | Kegunaan |
|:---|:---|
| KAPE | Mengumpulkan artefak Windows (registry, event log, Prefetch) dalam hitungan menit |
| Velociraptor | Koleksi dan hunting ke ratusan endpoint sekaligus |
| UAC (Unix-like Artifacts Collector) | Versi untuk Linux dan macOS |

## 5. Forensik memori dengan Volatility 3

```bash
pip install volatility3
vol -f mem.raw windows.info          # cek profil OS
vol -f mem.raw windows.pslist        # daftar proses
vol -f mem.raw windows.pstree        # proses beserta parent
vol -f mem.raw windows.cmdline       # command line tiap proses
vol -f mem.raw windows.netscan       # koneksi jaringan
vol -f mem.raw windows.malfind       # memori yang executable dan mencurigakan (indikasi injeksi)
vol -f mem.raw windows.dlllist --pid 1234
```

Yang perlu dicari:

| Tanda | Contoh |
|:---|:---|
| Nama mirip proses sistem | `svch0st.exe`, `lsas.exe` |
| Lokasi salah | `svchost.exe` berjalan dari `C:\Users\...\AppData` |
| Parent salah | `svchost.exe` yang parent-nya bukan `services.exe` |
| Koneksi keluar dari proses yang tidak wajar | `notepad.exe` terhubung ke port 443 |
| Hasil `malfind` | Region memori `PAGE_EXECUTE_READWRITE` berisi header `MZ` |

Proses Windows yang normal dan parent-nya perlu dihafal: `System` → `smss.exe` → `wininit.exe` → `services.exe` → `svchost.exe`, dan `wininit.exe` → `lsass.exe`. Hanya boleh ada satu `lsass.exe`.

## 6. Artefak Windows yang paling sering dipakai

| Artefak | Lokasi | Menjawab |
|:---|:---|:---|
| Event Log | `C:\Windows\System32\winevt\Logs\*.evtx` | Login (4624/4625), proses (4688), service baru (7045), log dihapus (1102) |
| Prefetch | `C:\Windows\Prefetch\*.pf` | Program apa yang pernah dijalankan, kapan, berapa kali |
| Amcache | `C:\Windows\AppCompat\Programs\Amcache.hve` | Program yang dijalankan, lengkap dengan hash SHA-1 |
| ShimCache | Registry `SYSTEM` | Program yang pernah ada di disk |
| Registry Run keys | `HKLM\...\Run`, `HKCU\...\Run` | Persistence |
| Scheduled Tasks | `C:\Windows\System32\Tasks\` | Persistence |
| LNK & Jump Lists | `%AppData%\Microsoft\Windows\Recent\` | File apa yang dibuka user |
| ShellBags | Registry `NTUSER.DAT`, `UsrClass.dat` | Folder apa yang pernah dibuka |
| $MFT, $UsnJrnl | Root NTFS | File dibuat, diubah, dihapus ([LC-006](../../basics/OperatingSystem/id/Windows%20File%20System.md)) |
| Browser history | Profil Chrome/Edge/Firefox | Situs yang dikunjungi dan file yang diunduh |

Event ID tambahan untuk IR:

| ID | Arti |
|:---|:---|
| 4720 | Akun user dibuat |
| 4732 | User ditambahkan ke grup lokal (misalnya Administrators) |
| 4698 | Scheduled task dibuat |
| 7045 | Service baru dipasang |
| 1102 | Log keamanan dihapus, hampir selalu tanda bahaya |
| 4648 | Login dengan kredensial eksplisit (runas, lateral movement) |

Alat parsing gratis dari Eric Zimmerman (EZ Tools): `PECmd` untuk Prefetch, `AmcacheParser`, `RECmd` untuk registry, `MFTECmd`, `EvtxECmd`, dan Timeline Explorer untuk membaca hasilnya. Untuk event log, Hayabusa dan Chainsaw bisa langsung memindai `.evtx` memakai aturan Sigma ([LC-074](3.%20Threat%20Hunting%20%26%20Detection%20Engineering%20%28Sigma%2C%20YARA%2C%20ATT%26CK%29.md)).

```powershell
PECmd.exe -d C:\kasus\Prefetch --csv C:\kasus\out
hayabusa.exe csv-timeline -d C:\kasus\evtx -o timeline.csv
```

## 7. Artefak Linux

| Artefak | Lokasi | Menjawab |
|:---|:---|:---|
| Log autentikasi | `/var/log/auth.log`, `/var/log/secure`, `journalctl` | Login, sudo ([LC-072](1.%20SOC%20%26%20Log%20Analysis.md)) |
| Riwayat shell | `~/.bash_history`, `~/.zsh_history` | Perintah yang diketik |
| Login terakhir | `last`, `lastb`, `/var/log/wtmp` | Siapa login, dari mana |
| Cron | `/etc/crontab`, `/var/spool/cron/`, `/etc/cron.*` | Persistence ([LC-025](../../linux/id/18.%20Task%20Scheduling.md)) |
| systemd | `/etc/systemd/system/`, `~/.config/systemd/user/` | Service persistence |
| SSH keys | `~/.ssh/authorized_keys` | Backdoor berbasis key |
| User baru | `/etc/passwd`, `/etc/shadow` | Akun tambahan, UID 0 selain root |
| File baru | `find / -newermt "2026-10-15" -type f` | Apa yang berubah sejak tanggal insiden |
| Proses | `/proc/<pid>/exe`, `/proc/<pid>/cmdline` | Binary yang sudah dihapus tapi masih berjalan |

Trik penting: penyerang sering menghapus binary setelah dijalankan. Kalau prosesnya masih hidup, file aslinya bisa diambil kembali:

```bash
ls -l /proc/*/exe 2>/dev/null | grep deleted
sudo cp /proc/4242/exe /kasus/recovered_4242.bin
```

## 8. Membangun timeline

Timeline menggabungkan banyak sumber menjadi satu urutan kejadian.

```bash
# Plaso: parse image disk menjadi satu timeline
log2timeline.py --storage-file kasus.plaso disk.img
psort.py -o l2tcsv -w timeline.csv kasus.plaso "date > '2026-10-15'"
```

Contoh timeline yang sudah diringkas analis:

| Waktu (UTC) | Sumber | Kejadian |
|:---|:---|:---|
| 10-15 08:02 | Email gateway | Email "Invoice_Okt.xlsm" diterima oleh rina@ |
| 10-15 08:05 | Prefetch | `EXCEL.EXE` dijalankan |
| 10-15 08:05 | Sysmon 1 | Excel meluncurkan `powershell -enc ...` |
| 10-15 08:06 | Zeek conn | Koneksi ke 203.0.113.99:443 |
| 10-15 08:06 | Registry | Run key `Updater` dibuat |
| 10-15 13:40 | 4624 tipe 3 | Akun rina login ke FILESRV01 |
| 10-15 13:52 | Zeek conn | Upload 2,1 GB dari FILESRV01 ke 203.0.113.99 |

Dari timeline ini kelihatan pintu masuk (phishing), persistence, lateral movement, dan exfiltration, lengkap dengan jamnya.

## 9. Menulis laporan insiden

| Bagian | Isi |
|:---|:---|
| Ringkasan eksekutif | 1 paragraf untuk manajemen: apa yang terjadi, dampaknya, statusnya sekarang |
| Ruang lingkup | Sistem yang diperiksa, rentang waktu |
| Timeline | Tabel seperti di bagian 8 |
| Temuan teknis | Per temuan: bukti, artefak, teknik ATT&CK |
| IOC | IP, domain, hash, nama file, Run key |
| Akar masalah | Kenapa serangan bisa berhasil |
| Rekomendasi | Jangka pendek (sudah dilakukan) dan jangka panjang |

Tulis fakta dan sumbernya. Bedakan "terbukti" ("Prefetch menunjukkan `mimikatz.exe` dijalankan pukul 13:45") dari "dugaan" ("kemungkinan kredensial domain ikut dicuri").

## 10. Latihan

### Task 1: konsep

1. Mana yang harus diambil lebih dulu: image disk atau image memori? Kenapa?
2. Event ID Windows untuk service baru dipasang?
3. Artefak Windows apa yang menunjukkan program pernah dijalankan beserta hitungannya?
4. Kenapa analisis dilakukan pada salinan, bukan bukti asli?

<details><summary>Kunci jawaban</summary>

1. Memori, karena paling volatil dan langsung hilang saat mesin mati.
2. 7045
3. Prefetch
4. Supaya bukti asli tidak berubah, hash-nya tetap sama, dan chain of custody tetap valid.

</details>

### Task 2: baca output Volatility

```text
PID   PPID  ImageFileName   Path
4     0     System
388   4     smss.exe        \SystemRoot\System32\smss.exe
512   388   wininit.exe     C:\Windows\System32\wininit.exe
620   512   services.exe    C:\Windows\System32\services.exe
636   512   lsass.exe       C:\Windows\System32\lsass.exe
```

1. Proses mana yang palsu? Sebutkan dua alasannya.
2. Susun rantai proses dari awal sampai proses palsu itu.
3. Plugin Volatility apa yang kamu jalankan berikutnya untuk proses itu?

<details><summary>Kunci jawaban</summary>

1. PID 2210 `svchost.exe`. Lokasinya di `AppData\Roaming`, bukan `System32`, dan parent-nya `powershell.exe`, bukan `services.exe`.
2. `EXCEL.EXE` (2988) → `powershell.exe` (3104) → `svchost.exe` palsu (2210).
3. `windows.netscan` untuk melihat koneksinya, `windows.cmdline --pid 2210`, `windows.malfind --pid 2210`, lalu dump proses untuk dianalisis ([LC-063](../../malware-analysis/id/1.%20Static%20Malware%20Analysis%20Fundamentals.md)).

</details>
