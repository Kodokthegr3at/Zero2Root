## 1. Kenapa memantau jaringan

Log host ([LC-072](1.%20SOC%20%26%20Log%20Analysis.md)) bisa dihapus penyerang setelah ia jadi root. Trafik jaringan lebih sulit dipalsukan karena sudah lewat sebelum penyerang sempat membersihkan jejak. Selain itu, perangkat seperti printer, kamera IP, dan IoT ([LC-070](../../hardware-iot/id/Hardware%20%26%20IoT%20Security%20%E2%80%94%20Interfaces%2C%20Firmware%20%26%20Automotive.md)) sering tidak punya log sama sekali, tapi trafiknya tetap terlihat di jaringan.

Sensor NSM biasanya dipasang di titik keluar masuk jaringan, menerima salinan trafik dari port mirror (SPAN) atau network TAP.

```
 Internet ── Firewall ── Switch ──┬── Server
                            │     └── Laptop
                       port mirror
                            │
                       ┌────▼────┐
                       │ Sensor  │  Zeek + Suricata + rekam PCAP
                       └────┬────┘
                            ▼
                          SIEM
```

## 2. Tiga jenis data jaringan

| Jenis | Isi | Ukuran | Contoh alat | Kapan dipakai |
|:---|:---|:---|:---|:---|
| Full packet capture | Setiap byte | Sangat besar | tcpdump, Wireshark | Bukti lengkap, analisis mendalam |
| Log transaksi | Ringkasan per protokol (DNS query, HTTP request, sertifikat TLS) | Sedang | Zeek | Investigasi harian, threat hunting |
| Flow | Siapa ke siapa, berapa byte | Kecil | NetFlow, IPFIX | Melihat pola besar, data bisa disimpan berbulan-bulan |
| Alert | Hanya yang cocok signature | Sangat kecil | Suricata, Snort | Deteksi otomatis |

Praktik yang umum: simpan flow berbulan-bulan, log Zeek beberapa minggu, dan PCAP lengkap hanya beberapa hari karena ukurannya.

## 3. Wireshark untuk analisis paket

Merekam paket sudah dibahas di [LC-032](../../linux/id/25.%20Linux%20Networking%20%E2%80%94%20Diagnostics%20%26%20Packet%20Analysis.md). Di sini fokusnya membaca PCAP untuk mencari tanda serangan.

### 3.1 Filter tampilan yang sering dipakai

| Tujuan | Filter |
|:---|:---|
| Trafik dari/ke satu IP | `ip.addr == 10.0.0.5` |
| Hanya HTTP request | `http.request` |
| Login HTTP lewat POST | `http.request.method == "POST"` |
| DNS query saja | `dns.flags.response == 0` |
| SYN tanpa ACK (indikasi port scan) | `tcp.flags.syn == 1 && tcp.flags.ack == 0` |
| Nama server di TLS (SNI) | `tls.handshake.extensions_server_name` |
| Paket dengan kata tertentu | `frame contains "password"` |

### 3.2 Menu yang paling membantu

1. **Statistics > Conversations**: urutkan berdasarkan byte. Koneksi keluar yang sangat besar bisa berarti exfiltration.
2. **Statistics > Protocol Hierarchy**: protokol aneh (misalnya IRC atau Tor) langsung kelihatan.
3. **Follow > TCP Stream**: membaca percakapan utuh seperti chat.
4. **File > Export Objects > HTTP**: mengambil file yang didownload lewat HTTP, misalnya malware. Buka hanya di VM analisis ([LC-063](../../malware-analysis/id/1.%20Static%20Malware%20Analysis%20Fundamentals.md)).

### 3.3 tshark untuk hal yang berulang

```bash
# 10 domain yang paling sering di-query
tshark -r capture.pcap -Y "dns.flags.response==0" -T fields -e dns.qry.name \
  | sort | uniq -c | sort -rn | head

# Semua User-Agent HTTP
tshark -r capture.pcap -Y http.request -T fields -e http.user_agent | sort -u
```

## 4. Zeek: mengubah trafik jadi log

Zeek tidak memberi alert. Ia membaca trafik lalu menulis log rapi per protokol. Log ini yang nanti dicari analis.

```bash
# Proses file PCAP, hasilnya file .log di folder saat ini
zeek -C -r capture.pcap
ls
# conn.log  dns.log  http.log  ssl.log  files.log  weird.log ...
```

| File log | Isinya |
|:---|:---|
| `conn.log` | Setiap koneksi: IP, port, durasi, byte |
| `dns.log` | Query DNS dan jawabannya |
| `http.log` | Method, host, URI, User-Agent, status |
| `ssl.log` | Versi TLS, SNI, info sertifikat |
| `files.log` | File yang lewat, lengkap dengan hash |
| `weird.log` | Hal yang tidak sesuai standar protokol |

`zeek-cut` mengambil kolom tertentu:

```bash
# Koneksi yang paling lama
cat conn.log | zeek-cut id.orig_h id.resp_h id.resp_p duration | sort -k4 -rn | head

# Host HTTP yang dikunjungi
cat http.log | zeek-cut host uri | sort | uniq -c | sort -rn | head
```

## 5. Suricata: IDS berbasis signature

Suricata mencocokkan trafik dengan ribuan aturan. Aturan gratis yang paling umum adalah Emerging Threats Open.

### 5.1 Anatomi satu aturan

```text
alert http any any -> any any (msg:"Kemungkinan SQLi di URI"; \
    http.uri; content:"UNION"; nocase; content:"SELECT"; nocase; \
    sid:1000001; rev:1;)
```

| Bagian | Arti |
|:---|:---|
| `alert` | Aksi: beri alert (di mode IPS bisa `drop`) |
| `http any any -> any any` | Protokol, sumber, tujuan |
| `msg` | Teks yang muncul di alert |
| `http.uri; content:"UNION"` | Cari kata `UNION` di URI |
| `nocase` | Abaikan huruf besar kecil |
| `sid` | ID unik aturan; aturan buatan sendiri pakai angka di atas 1000000 |

### 5.2 Menjalankan pada PCAP

```bash
sudo suricata -r capture.pcap -S lokal.rules -l ./out
cat out/fast.log
# Alert juga tersimpan dalam format JSON di out/eve.json
jq 'select(.event_type=="alert") | .alert.signature' out/eve.json | sort | uniq -c
```

### 5.3 Keterbatasan

Signature hanya menangkap yang sudah dikenal. Trafik HTTPS isinya terenkripsi, jadi Suricata hanya bisa melihat metadata seperti SNI, sertifikat, dan JA3. Di sinilah log Zeek dan threat hunting ([LC-074](3.%20Threat%20Hunting%20%26%20Detection%20Engineering%20%28Sigma%2C%20YARA%2C%20ATT%26CK%29.md)) mengisi celahnya.

## 6. Pola serangan yang terlihat di jaringan

| Pola | Yang terlihat | Cara mengecek |
|:---|:---|:---|
| Port scan | Satu IP mengirim SYN ke banyak port, kebanyakan dibalas RST | `conn.log`: banyak koneksi state `REJ` atau `S0` dari satu sumber |
| Brute force | Ratusan koneksi pendek ke port 22/3389/445 | `conn.log` dikelompokkan per sumber dan port tujuan |
| Beaconing | Koneksi ke IP yang sama dengan jeda nyaris sama | Hitung selisih waktu antar koneksi; jeda konstan seperti 60 detik itu mencurigakan |
| DNS tunneling | Subdomain sangat panjang dan acak, banyak record TXT | `dns.log`: panjang `query` di atas 50 karakter |
| Exfiltration | Upload besar ke IP yang jarang dipakai | `conn.log`: `orig_bytes` jauh lebih besar dari `resp_bytes` |
| ARP spoofing | Satu MAC mengaku memiliki banyak IP | Wireshark: `arp.duplicate-address-detected` ([LC-042](../../networking/id/ARP%20%26%20Local%20Network%20Attacks.md)) |

Contoh mencari kandidat DNS tunneling di Zeek:

```bash
cat dns.log | zeek-cut query | awk 'length($1) > 50' | head
```

## 7. Latihan

### Task 1: konsep

1. Data jaringan apa yang paling kecil ukurannya tapi bisa disimpan paling lama?
2. Zeek menghasilkan alert atau log?
3. Kenapa Suricata kesulitan mendeteksi serangan di dalam HTTPS?
4. Koneksi ke satu IP setiap 60 detik selama 8 jam termasuk pola apa?

<details><summary>Kunci jawaban</summary>

1. Flow (NetFlow/IPFIX)
2. Log. Zeek tidak fokus pada alert.
3. Isi trafik terenkripsi, jadi yang bisa dicocokkan hanya metadata (SNI, sertifikat, JA3).
4. Beaconing, kemungkinan malware yang menghubungi C2.

</details>

### Task 2: analisis conn.log

Potongan `conn.log` (kolom: waktu, IP sumber, IP tujuan, port, orig_bytes, resp_bytes):

```text
10:00:00 10.0.0.23 185.199.10.5 443 320 1200
10:01:00 10.0.0.23 185.199.10.5 443 318 1200
10:02:00 10.0.0.23 185.199.10.5 443 321 1200
10:02:30 10.0.0.40 10.0.0.1 53 60 120
10:03:00 10.0.0.23 185.199.10.5 443 319 1200
10:05:12 10.0.0.31 203.0.113.80 443 734003200 4100
10:06:00 10.0.0.12 10.0.0.50 22 0 0
10:06:00 10.0.0.12 10.0.0.50 23 0 0
10:06:00 10.0.0.12 10.0.0.50 80 0 0
10:06:01 10.0.0.12 10.0.0.50 445 0 0
```

1. Host mana yang menunjukkan beaconing?
2. Host mana yang kemungkinan melakukan exfiltration, dan berapa kira-kira datanya?
3. Host mana yang melakukan port scan?

<details><summary>Kunci jawaban</summary>

1. `10.0.0.23` ke `185.199.10.5`, tiap 60 detik dengan ukuran hampir sama.
2. `10.0.0.31` mengirim sekitar 700 MB ke `203.0.113.80` dan hanya menerima 4 KB.
3. `10.0.0.12` mencoba port 22, 23, 80, 445 di `10.0.0.50` dalam satu detik tanpa data.

</details>

### Task 3: tulis aturan Suricata

Tulis aturan yang memberi alert kalau User-Agent HTTP mengandung `sqlmap`. Jalankan pada PCAP yang kamu rekam sendiri saat menjalankan sqlmap ke DVWA lokal.

<details><summary>Contoh jawaban</summary>

```text

    http.user_agent; content:"sqlmap"; nocase; sid:1000002; rev:1;)
```

</details>

## 8. Referensi cepat

```text
WIRESHARK
  ip.addr==X · http.request · dns.flags.response==0 · tls.handshake.extensions_server_name
  Statistics > Conversations · Follow TCP Stream · Export Objects > HTTP

ZEEK
  zeek -C -r file.pcap
  cat conn.log | zeek-cut id.orig_h id.resp_h id.resp_p orig_bytes resp_bytes

SURICATA
  suricata -r file.pcap -S my.rules -l out/   →  out/fast.log, out/eve.json
  alert <proto> src port -> dst port (msg:"..."; content:"..."; sid:1000001; rev:1;)

POLA
  scan: banyak port, tanpa data · beacon: jeda konstan · exfil: orig_bytes >> resp_bytes
  DNS tunnel: query sangat panjang
```
