## 1. Deteksi pasif vs threat hunting

Di [LC-072](1.%20SOC%20%26%20Log%20Analysis.md) kamu menunggu alert datang. Masalahnya, penyerang yang terampil sengaja menghindari aturan yang sudah ada. Threat hunting membalik urutannya: kamu berasumsi sudah ada yang berhasil masuk, lalu mencari buktinya.

| | Monitoring berbasis alert | Threat hunting |
|:---|:---|:---|
| Pemicu | Aturan SIEM terpicu | Hipotesis dari analis |
| Pertanyaan | "Alert ini asli atau tidak?" | "Kalau penyerang ada di sini, jejak apa yang ia tinggalkan?" |
| Hasil | Tiket insiden | Insiden baru, atau aturan deteksi baru |
| Frekuensi | Terus-menerus | Terjadwal, misalnya mingguan |

Hunt yang tidak menemukan apa-apa tetap berguna kalau menghasilkan aturan deteksi baru, karena berikutnya pola itu tertangkap otomatis.

## 2. MITRE ATT&CK sebagai bahasa bersama

ATT&CK menyusun perilaku penyerang dalam 14 taktik (tujuan) yang masing-masing berisi teknik (cara).

| Taktik | Contoh teknik | ID |
|:---|:---|:---|
| Initial Access | Phishing | T1566 |
| Execution | PowerShell | T1059.001 |
| Persistence | Scheduled Task | T1053.005 |
| Privilege Escalation | Exploitation for Privilege Escalation | T1068 |
| Defense Evasion | Clear Windows Event Logs | T1070.001 |
| Credential Access | LSASS Memory | T1003.001 |
| Discovery | Account Discovery | T1087 |
| Lateral Movement | Remote Services: SMB | T1021.002 |
| Command and Control | Web Protocols | T1071.001 |
| Exfiltration | Exfiltration Over C2 Channel | T1041 |

Taktik yang tidak tercantum di tabel: Reconnaissance, Resource Development, Collection, dan Impact.

Dengan ATT&CK, laporan seperti "penyerang dump LSASS" bisa ditulis sebagai T1003.001, sehingga tim lain langsung tahu teknik mana yang dimaksud. ATT&CK Navigator (gratis, berbasis web) dipakai untuk mewarnai teknik mana yang sudah punya deteksi dan mana yang belum.

## 3. Piramida rasa sakit

David Bianco menyusun indikator berdasarkan seberapa sulit penyerang menggantinya:

```
                 ▲  TTP                 ← paling sulit diganti, deteksi paling awet
                ▲▲  Tools
               ▲▲▲  Artefak host/jaringan
              ▲▲▲▲  Domain
             ▲▲▲▲▲  Alamat IP
            ▲▲▲▲▲▲  Hash file           ← paling mudah diganti (ubah 1 byte, hash berubah)
```

Aturan yang memblokir satu hash berhenti berguna begitu penyerang mengompilasi ulang malware-nya. Aturan yang mendeteksi "proses Office meluncurkan PowerShell" tetap berguna walau malware-nya berganti. Usahakan deteksimu berada di lapisan atas piramida.

## 4. Siklus hunting berbasis hipotesis

```
 1. Hipotesis ──► 2. Kumpulkan data ──► 3. Analisis ──► 4. Temuan
      ▲                                                    │
      └──── 5. Otomatisasi: jadikan aturan deteksi ◄────────┘
```

Contoh:

| Langkah | Isi |
|:---|:---|
| Hipotesis | "Penyerang memakai `certutil.exe` untuk mendownload payload (T1105)." |
| Data | Sysmon Event ID 1 (pembuatan proses), 30 hari terakhir |
| Analisis | Cari `certutil` dengan argumen `-urlcache` atau `http` |
| Temuan | 2 kejadian: satu dari admin yang sah, satu dari laptop marketing jam 23:40 |
| Otomatisasi | Tulis aturan Sigma, kecualikan akun admin yang sah |

Hipotesis yang bagus biasanya datang dari laporan threat intel terbaru, teknik ATT&CK yang belum punya deteksi, atau anomali dari baseline.

## 5. Sysmon: telemetri Windows yang layak

Log bawaan Windows kurang detail. Sysmon menambahkan event yang jauh lebih kaya.

| Event ID | Kejadian | Contoh pertanyaan hunting |
|:---|:---|:---|
| 1 | Pembuatan proses (lengkap dengan command line dan parent) | Proses apa yang diluncurkan oleh `winword.exe`? |
| 3 | Koneksi jaringan | Proses apa yang terhubung keluar ke port 4444? |
| 7 | DLL dimuat | Ada DLL yang dimuat dari folder Temp? |
| 10 | Akses ke proses lain | Siapa yang membuka handle ke `lsass.exe`? |
| 11 | File dibuat | Ada file `.exe` baru di `AppData`? |
| 13 | Nilai registry diubah | Ada entri baru di `Run` key? |
| 22 | Query DNS | Proses mana yang meng-query domain aneh? |

Instalasi dengan konfigurasi komunitas yang umum dipakai (SwiftOnSecurity atau Olaf Hartong sysmon-modular):

```powershell
.\Sysmon64.exe -accepteula -i sysmonconfig.xml
# Log muncul di: Applications and Services Logs > Microsoft > Windows > Sysmon > Operational
```

Hubungan parent dan child sering menjadi petunjuk paling kuat:

| Parent | Child | Kenapa mencurigakan |
|:---|:---|:---|
| `winword.exe`, `excel.exe` | `powershell.exe`, `cmd.exe` | Makro berbahaya (T1566 + T1059) |
| `w3wp.exe` (IIS) | `cmd.exe`, `whoami.exe` | Web shell ([LC-052](../../web/Vulnerabilities/id/6.%20File%20Upload%20Vulnerabilities%20%26%20Web%20Shells.md)) |
| `services.exe` | `cmd.exe` dengan argumen acak | Service baru dari PsExec (T1021.002) |
| `explorer.exe` | `rundll32.exe` tanpa argumen | Injeksi atau loader malware |

## 6. Sigma: aturan deteksi yang portabel

Satu aturan Sigma bisa dikonversi menjadi query Splunk, Elastic, Sentinel, dan lainnya. Kamu cukup menulisnya sekali.

```yaml
title: Certutil Mendownload File
id: 5f1c3a9e-2b7d-4c1e-9a3f-1d2e3f4a5b6c
status: experimental
description: Mendeteksi certutil.exe yang dipakai untuk mendownload file dari URL
references:
  - https://attack.mitre.org/techniques/T1105/
tags:
  - attack.command_and_control
  - attack.t1105
logsource:
  category: process_creation
  product: windows
detection:
  selection_img:
    Image|endswith: '\certutil.exe'
  selection_args:
    CommandLine|contains:
      - 'urlcache'
      - 'http'
  condition: selection_img and selection_args
falsepositives:
  - Admin yang memakai certutil untuk mengunduh CRL
level: high
```

Konversi ke query SIEM memakai `sigma-cli`:

```bash
pip install sigma-cli
sigma plugin install splunk
sigma convert -t splunk -p sysmon certutil_download.yml
# Contoh hasil:
# Image="*\\certutil.exe" CommandLine IN ("*urlcache*", "*http*")
```

Repositori SigmaHQ di GitHub berisi lebih dari 3000 aturan siap pakai. Baca dulu beberapa sebelum menulis aturan sendiri.

## 7. YARA: mengenali file berbahaya

Sigma bekerja pada log, YARA bekerja pada isi file atau memori. Kamu sudah melihat `strings` di [LC-063](../../malware-analysis/id/1.%20Static%20Malware%20Analysis%20Fundamentals.md); YARA mengubah temuan itu menjadi aturan.

```yara
rule Contoh_Downloader_Sederhana
{
    meta:
        author = "kodoktheGr3at"
        description = "Downloader yang memakai URLDownloadToFile dan cmd"
        date = "2026-10-16"

    strings:
        $api   = "URLDownloadToFileA" ascii
        $cmd   = "cmd.exe /c" ascii nocase
        $ua    = "Mozilla/4.0 (compatible; MSIE 6.0" ascii
        $mz    = { 4D 5A }               // header file PE

    condition:
        $mz at 0 and filesize < 500KB and 2 of ($api, $cmd, $ua)
}
```

```bash
yara -r contoh.yar ./sampel/        # pindai folder
yara -s contoh.yar file.exe         # tampilkan string yang cocok
```

Tips agar aturan YARA tidak terlalu banyak false positive:

1. Gabungkan beberapa string dengan `2 of (...)`, jangan bergantung pada satu string.
2. Pakai string yang unik untuk malware itu, misalnya path PDB, mutex, atau typo khas pembuatnya.
3. Batasi dengan `filesize` dan `$mz at 0`.
4. Uji pada folder berisi file bersih, misalnya `C:\Windows\System32`, untuk melihat berapa yang ikut tertangkap.

## 8. Mengukur kualitas deteksi

| Ukuran | Pertanyaan |
|:---|:---|
| Cakupan | Berapa persen teknik ATT&CK yang relevan sudah punya deteksi? |
| Presisi | Dari 100 alert, berapa yang true positive? |
| Ketahanan | Kalau penyerang mengganti nama file atau IP, apakah aturan masih bekerja? |
| Waktu deteksi | Berapa lama dari kejadian sampai alert muncul? |

Deteksi perlu diuji. Atomic Red Team (gratis, dari Red Canary) menyediakan tes kecil per teknik ATT&CK. Jalankan tesnya di VM lab, lalu cek apakah aturanmu terpicu.

```powershell
# Contoh di VM lab: jalankan tes untuk T1105 lalu periksa SIEM
Invoke-AtomicTest T1105 -TestNumbers 7
```

### Task 2: baca event Sysmon

```text
EventID=1  Time=21:14:02  User=CORP\rina
  ParentImage=C:\Program Files\Microsoft Office\root\Office16\EXCEL.EXE
  Image=C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe
  CommandLine=powershell -nop -w hidden -enc SQBFAFgAIAAoAE4AZQB3AC0ATwBiAGoA...
EventID=3  Time=21:14:03  Image=...\powershell.exe  DestinationIp=203.0.113.99  DestinationPort=443
EventID=13 Time=21:14:05  Image=...\powershell.exe
  TargetObject=HKCU\Software\Microsoft\Windows\CurrentVersion\Run\Updater
```

1. Kenapa event pertama mencurigakan? Sebutkan tiga alasan.
2. Petakan ketiga event ke teknik ATT&CK.
3. Apa yang terjadi di event 13 dan kenapa itu penting untuk incident response?

<details><summary>Kunci jawaban</summary>

1. Excel meluncurkan PowerShell, ada flag `-w hidden` untuk menyembunyikan jendela, dan perintahnya di-encode base64 (`-enc`). Jamnya juga di luar jam kerja.
2. Event 1: T1566.001 (phishing attachment) dan T1059.001 (PowerShell), plus T1027 (obfuscation). Event 3: T1071.001 (C2 lewat web). Event 13: T1547.001 (Registry Run Key).
3. Malware memasang persistence di Run key, jadi ia akan berjalan lagi setiap Rina login. Saat pembersihan, key ini harus dihapus.

</details>

### Task 3: tulis aturan Sigma

Tulis aturan Sigma untuk mendeteksi proses Office (`winword.exe`, `excel.exe`, `powerpnt.exe`) yang meluncurkan `powershell.exe` atau `cmd.exe`. Konversi ke query Splunk atau Elastic dengan `sigma-cli`.

<details><summary>Contoh jawaban</summary>

```yaml
title: Office Meluncurkan Shell
status: experimental
logsource:
  category: process_creation
  product: windows
detection:
  parent:
    ParentImage|endswith:
      - '\winword.exe'
      - '\excel.exe'
      - '\powerpnt.exe'
  child:
    Image|endswith:
      - '\powershell.exe'
      - '\cmd.exe'
  condition: parent and child
level: high
tags:
  - attack.t1059
```

</details>
