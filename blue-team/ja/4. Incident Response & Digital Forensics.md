## 1. IRとフォレンジックの関係

インシデント対応の目的は、攻撃を止めてできるだけ早くサービスを戻すことである。フォレンジックの目的は、何が、どのように、いつから起きたかを証拠で答えることである。両者は並行して進む。IRは何を掃除すべきか知るためにフォレンジックの答えを必要とし、フォレンジックは封じ込めの際に証拠を壊さないためにIRの協力を必要とする。

| 問い | 答えるもの |
|:---|:---|
| 攻撃者はどうやって入ったか | Webログ、メール、実行アーティファクト |
| 最初に入ったのはいつか | タイムライン |
| どのマシンに触れたか | 認証ログ、横展開のアーティファクト |
| どのデータを持ち出したか | ネットワークログ、ファイルアクセスのアーティファクト |
| まだ中にいるか | 永続化の確認、メモリ |

## 2. 揮発性の順序

最も早く消える証拠から先に集める(RFC 3227)。

| 順序 | 証拠 | 失われるとき |
|:---|:---|:---|
| 1 | CPUレジスタ、キャッシュ | ナノ秒単位 |
| 2 | RAM: プロセス、ネットワーク接続、暗号鍵 | 電源が切れたとき |
| 3 | ネットワーク状態、ARPテーブル | 数分 |
| 4 | 一時ファイル、スワップ | 再起動や掃除 |
| 5 | ディスク | 上書きされたとき |
| 6 | リモートのログ、バックアップ | ログのローテーション |

よくある失敗は、いきなり電源ケーブルを抜くことである。メモリが消え、RAMにしか存在しないファイルレスマルウェア([LC-074](3.%20Threat%20Hunting%20%26%20Detection%20Engineering%20%28Sigma%2C%20YARA%2C%20ATT%26CK%29.md))の証拠も消える。可能ならまずメモリのイメージを取り、その後にネットワークを隔離する。

## 3. 証拠保全の記録と完全性

裁判や人事案件に発展しうるなら、証拠が変わっていないことを示せなければならない。

```bash
# 取得直後に証拠のハッシュを取る
sha256sum disk.img > disk.img.sha256

# 後でいつでも検証できる
sha256sum -c disk.img.sha256
```

Chain of custodyの書式に最低限必要な項目:

| 項目 | 例 |
|:---|:---|
| 証拠ID | EV-2026-014-01 |
| 説明 | Dell Latitudeノート、S/N XXXX、512 GB NVMeディスク |
| 取得者 / 時刻 | アナリストA、2026-10-16 14:05 (UTC+7) |
| SHA-256ハッシュ | `9f86d0...` |
| 引き渡し先 / 時刻 / 理由 | アナリストB、2026-10-16 16:30、分析のため |

原則: 分析は常にコピーに対して行い、原本には行わない。

## 4. 取得: ディスクとメモリ

### 4.1 メモリ

| OS | 無料ツール | 例 |
|:---|:---|:---|
| Windows | WinPmem、DumpIt、Magnet RAM Capture | `winpmem.exe mem.raw` |
| Linux | LiME(カーネルモジュール)、AVML | `sudo avml mem.lime` |
| VM | ハイパーバイザのスナップショット | VMwareの `.vmem` ファイル |

### 4.2 ディスク

```bash
# ディスク全体のイメージ(証拠ディスクは書き込み防止装置経由で接続する)
sudo dc3dd if=/dev/sdb of=disk.img hash=sha256 log=acquisition.log

# 別案: ewfacquireはメタデータ付きで圧縮されたE01形式を作る
sudo ewfacquire /dev/sdb
```

### 4.3 トリアージ収集

1 TBのディスクのイメージ取得には何時間もかかる。多数のマシンを扱うなら、重要なアーティファクトだけを集める。

| ツール | 用途 |
|:---|:---|
| KAPE | Windowsのアーティファクト(レジストリ、イベントログ、Prefetch)を数分で収集 |
| Velociraptor | 何百台ものエンドポイントで一斉に収集とハンティング |
| UAC (Unix-like Artifacts Collector) | LinuxとmacOS向け |

## 5. Volatility 3によるメモリフォレンジック

```bash
pip install volatility3
vol -f mem.raw windows.info          # OSを確認
vol -f mem.raw windows.pslist        # プロセス一覧
vol -f mem.raw windows.pstree        # 親付きのプロセス
vol -f mem.raw windows.cmdline       # 各プロセスのコマンドライン
vol -f mem.raw windows.netscan       # ネットワーク接続
vol -f mem.raw windows.malfind       # 怪しい実行可能メモリ(インジェクションの兆候)
vol -f mem.raw windows.dlllist --pid 1234
```

探すべきもの:

| 兆候 | 例 |
|:---|:---|
| システムプロセスに似せた名前 | `svch0st.exe`、`lsas.exe` |
| 場所が違う | `C:\Users\...\AppData` から動く `svchost.exe` |
| 親が違う | 親が `services.exe` でない `svchost.exe` |
| ありえないプロセスからの外向き通信 | `notepad.exe` がポート443に接続 |
| `malfind` の検出 | `MZ` ヘッダを含む `PAGE_EXECUTE_READWRITE` 領域 |

正常なWindowsのプロセスツリーは覚えておくこと: `System` → `smss.exe` → `wininit.exe` → `services.exe` → `svchost.exe`、そして `wininit.exe` → `lsass.exe`。`lsass.exe` は必ず1つだけである。

## 6. よく使うWindowsのアーティファクト

| アーティファクト | 場所 | 答えてくれること |
|:---|:---|:---|
| イベントログ | `C:\Windows\System32\winevt\Logs\*.evtx` | ログオン(4624/4625)、プロセス(4688)、新規サービス(7045)、ログ消去(1102) |
| Prefetch | `C:\Windows\Prefetch\*.pf` | どのプログラムが、いつ、何回実行されたか |
| Amcache | `C:\Windows\AppCompat\Programs\Amcache.hve` | 実行されたプログラムとSHA-1ハッシュ |
| ShimCache | `SYSTEM` レジストリハイブ | ディスク上に存在したプログラム |
| Runキー | `HKLM\...\Run`、`HKCU\...\Run` | 永続化 |
| スケジュールタスク | `C:\Windows\System32\Tasks\` | 永続化 |
| LNKとジャンプリスト | `%AppData%\Microsoft\Windows\Recent\` | ユーザーが開いたファイル |
| ShellBags | `NTUSER.DAT`、`UsrClass.dat` | 閲覧されたフォルダ |
| $MFT、$UsnJrnl | NTFSのルート | ファイルの作成、変更、削除([LC-006](../../basics/OperatingSystem/ja/Windows%20File%20System.md)) |
| ブラウザ履歴 | Chrome/Edge/Firefoxのプロファイル | 訪問サイトとダウンロード |

IRで追加で使うイベントID:

| ID | 意味 |
|:---|:---|
| 4720 | ユーザーアカウント作成 |
| 4732 | ローカルグループ(例: Administrators)へのユーザー追加 |
| 4698 | スケジュールタスク作成 |
| 7045 | 新しいサービスのインストール |
| 1102 | セキュリティログの消去。ほぼ必ず危険信号 |
| 4648 | 明示的な資格情報によるログオン(runas、横展開) |

Eric Zimmermanの無料パーサ群(EZ Tools): Prefetch用の `PECmd`、`AmcacheParser`、レジストリ用の `RECmd`、`MFTECmd`、`EvtxECmd`、結果を読むTimeline Explorer。イベントログについては、HayabusaとChainsawがSigmaルール([LC-074](3.%20Threat%20Hunting%20%26%20Detection%20Engineering%20%28Sigma%2C%20YARA%2C%20ATT%26CK%29.md))で `.evtx` を直接スキャンできる。

```powershell
PECmd.exe -d C:\case\Prefetch --csv C:\case\out
hayabusa.exe csv-timeline -d C:\case\evtx -o timeline.csv
```

## 7. Linuxのアーティファクト

| アーティファクト | 場所 | 答えてくれること |
|:---|:---|:---|
| 認証ログ | `/var/log/auth.log`、`/var/log/secure`、`journalctl` | ログイン、sudo([LC-072](1.%20SOC%20%26%20Log%20Analysis.md)) |
| シェル履歴 | `~/.bash_history`、`~/.zsh_history` | 入力されたコマンド |
| 最終ログイン | `last`、`lastb`、`/var/log/wtmp` | 誰がどこからログインしたか |
| cron | `/etc/crontab`、`/var/spool/cron/`、`/etc/cron.*` | 永続化([LC-025](../../linux/ja/18.%20Task%20Scheduling.md)) |
| systemd | `/etc/systemd/system/`、`~/.config/systemd/user/` | サービスによる永続化 |
| SSH鍵 | `~/.ssh/authorized_keys` | 鍵によるバックドア |
| 新しいユーザー | `/etc/passwd`、`/etc/shadow` | 追加アカウント、root以外のUID 0 |
| 新しいファイル | `find / -newermt "2026-10-15" -type f` | インシデント日以降に変わったもの |
| プロセス | `/proc/<pid>/exe`、`/proc/<pid>/cmdline` | ディスクから消されたが動いているバイナリ |

役立つ技: 攻撃者は実行後にバイナリを削除することが多い。プロセスがまだ生きていれば、元のファイルを取り戻せる。

```bash
ls -l /proc/*/exe 2>/dev/null | grep deleted
sudo cp /proc/4242/exe /case/recovered_4242.bin
```

## 8. タイムラインを作る

タイムラインは多数の情報源を1つの時系列にまとめる。

```bash
# Plaso: ディスクイメージを1つのタイムラインに解析する
log2timeline.py --storage-file case.plaso disk.img
psort.py -o l2tcsv -w timeline.csv case.plaso "date > '2026-10-15'"
```

アナリストが整理した後のタイムライン例:

| 時刻(UTC) | 情報源 | 出来事 |
|:---|:---|:---|
| 10-15 08:02 | メールゲートウェイ | メール「Invoice_Oct.xlsm」がrina@に配信 |
| 10-15 08:05 | Prefetch | `EXCEL.EXE` 実行 |
| 10-15 08:05 | Sysmon 1 | Excelが `powershell -enc ...` を起動 |
| 10-15 08:06 | Zeek conn | 203.0.113.99:443へ接続 |
| 10-15 08:06 | レジストリ | Runキー `Updater` 作成 |
| 10-15 13:40 | 4624 タイプ3 | アカウントrinaがFILESRV01にログオン |
| 10-15 13:52 | Zeek conn | FILESRV01から203.0.113.99へ2.1 GBのアップロード |

ここから侵入口(フィッシング)、永続化、横展開、持ち出しが、それぞれの時刻とともに読み取れる。

## 9. インシデント報告書を書く

| 節 | 内容 |
|:---|:---|
| エグゼクティブサマリー | 経営層向けの1段落。何が起き、影響は何で、現状はどうか |
| 範囲 | 調査したシステム、期間 |
| タイムライン | 8章のような表 |
| 技術的な発見 | 発見ごとに: 証拠、アーティファクト、ATT&CKテクニック |
| IOC | IP、ドメイン、ハッシュ、ファイル名、Runキー |
| 根本原因 | なぜ攻撃が成功したか |
| 推奨事項 | 短期(実施済み)と長期 |

事実とその出典を書く。「確認済み」(「Prefetchにより `mimikatz.exe` が13:45に実行されたことを確認」)と「推測」(「ドメインの資格情報も盗まれた可能性が高い」)を区別すること。

## 10. 演習

### Task 1: 概念

1. ディスクイメージとメモリイメージ、先に取るのはどちらか。なぜか。
2. 新しいサービスのインストールを示すWindowsイベントIDは?
3. プログラムが実行されたことと実行回数を示すWindowsアーティファクトは?
4. 原本ではなくコピーを分析するのはなぜか?

<details><summary>解答</summary>

1. メモリ。最も揮発性が高く、電源が切れた瞬間に消えるから。
2. 7045
3. Prefetch
4. 原本を変えずに保ち、ハッシュが一致し続け、Chain of custodyが有効なままになるように。

</details>

### Task 2: Volatilityの出力を読む

```text
PID   PPID  ImageFileName   Path
4     0     System
388   4     smss.exe        \SystemRoot\System32\smss.exe
512   388   wininit.exe     C:\Windows\System32\wininit.exe
620   512   services.exe    C:\Windows\System32\services.exe
636   512   lsass.exe       C:\Windows\System32\lsass.exe
812   620   svchost.exe     C:\Windows\System32\svchost.exe
2210  3104  svchost.exe     C:\Users\rina\AppData\Roaming\svchost.exe
3104  2988  powershell.exe  C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe
2988  2400  EXCEL.EXE       C:\Program Files\Microsoft Office\root\Office16\EXCEL.EXE
```

1. 偽物のプロセスはどれか。理由を2つ挙げよ。
2. 最初から偽プロセスまでのプロセスの連鎖を書け。
3. そのプロセスに対して次に実行するVolatilityプラグインは?

<details><summary>解答</summary>

1. PID 2210の `svchost.exe`。場所が `System32` ではなく `AppData\Roaming` であり、親が `services.exe` ではなく `powershell.exe` である。
2. `EXCEL.EXE`(2988) → `powershell.exe`(3104) → 偽の `svchost.exe`(2210)。
3. 接続を見る `windows.netscan`、`windows.cmdline --pid 2210`、`windows.malfind --pid 2210`、その後プロセスをダンプして分析する([LC-063](../../malware-analysis/ja/1.%20Static%20Malware%20Analysis%20Fundamentals.md))。

</details>
