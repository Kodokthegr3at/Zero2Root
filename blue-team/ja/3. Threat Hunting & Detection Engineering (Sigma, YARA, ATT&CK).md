## 重要な用語

この教材でよく出てくる言葉である。

| 用語 | 意味 |
|:---|:---|
| スレットハンティング | アラートを待たず、攻撃の痕跡を能動的に探すこと |
| 検知エンジニアリング | 検知ルールを設計し、書き、テストし、保守する仕事 |
| TTP | Tactics, Techniques, Procedures。攻撃者のやり方 |
| ATT&CK | MITREによる攻撃者TTPのカタログ。例: T1059 = Command and Scripting Interpreter |

| ベースライン | システムの正常な振る舞いの姿 |

## 1. 受動的な検知とスレットハンティング

LC-072ではアラートが来るのを待った。問題は、腕のよい攻撃者が既存のルールをわざと避けることである。スレットハンティングは順序を逆にする。誰かがすでに侵入していると仮定し、その証拠を探しに行く。

| | アラート駆動の監視 | スレットハンティング |
|:---|:---|:---|
| きっかけ | SIEMのルールが発火 | アナリストの仮説 |
| 問い | 「このアラートは本物か」 | 「攻撃者がここにいるなら、どんな痕跡を残すか」 |
| 成果 | インシデントチケット | 新しいインシデント、または新しい検知ルール |
| 頻度 | 常時 | 定期的。例: 毎週 |

何も見つからなかったハントでも、新しい検知ルールが生まれれば価値がある。次からはそのパターンが自動で捕まるからである。

## 2. 共通言語としてのMITRE ATT&CK

ATT&CKは攻撃者の行動を14のタクティク(目的)に整理し、それぞれにテクニック(手段)を収めている。

| タクティク | テクニック例 | ID |
|:---|:---|:---|
| Initial Access | Phishing | T1566 |
| Execution | PowerShell | T1059.001 |
| Persistence | Scheduled Task | T1053.005 |
| Privilege Escalation | Exploitation for Privilege Escalation | T1068 |
| Defense Evasion | Clear Windows Event Logs | T1070.001 |
| Credential Access | LSASS Memory | T1003.001 |
| Discovery | Account Discovery | T1087 |
| Lateral Movement | Remote Services: SMB | T1021.002 |
| Command and Control | Web Protocols | T1071.001 |
| Exfiltration | Exfiltration Over C2 Channel | T1041 |

表にないタクティク: Reconnaissance、Resource Development、Collection、Impact。

ATT&CKを使えば「攻撃者がLSASSをダンプした」はT1003.001と書け、他のチームにもどのテクニックか正確に伝わる。ATT&CK Navigator(無料、Webベース)では、検知があるテクニックとないテクニックを色分けできる。

## 3. 痛みのピラミッド

David Biancoは、攻撃者にとって変えにくい順に指標を並べた。

```
                 ▲  TTP                 ← 最も変えにくい。検知が長持ちする
                ▲▲  ツール
               ▲▲▲  ホスト/ネットワークの痕跡
              ▲▲▲▲  ドメイン
             ▲▲▲▲▲  IPアドレス
            ▲▲▲▲▲▲  ファイルハッシュ    ← 簡単に変わる(1バイト変えれば別のハッシュ)
```

1つのハッシュをブロックするルールは、攻撃者が再コンパイルした瞬間に役に立たなくなる。「OfficeのプロセスがPowerShellを起動した」を検知するルールは、マルウェアが変わっても働き続ける。検知はピラミッドの上の層を狙うこと。

## 4. 仮説駆動のハンティングサイクル

```
 1. 仮説 ──► 2. データ収集 ──► 3. 分析 ──► 4. 発見
    ▲                                        │
    └──── 5. 自動化: 検知ルールにする ◄────────┘
```

例:

| ステップ | 内容 |
|:---|:---|
| 仮説 | 「攻撃者は `certutil.exe` でペイロードをダウンロードしている(T1105)」 |
| データ | Sysmon イベントID 1(プロセス作成)、直近30日 |
| 分析 | 引数に `-urlcache` または `http` を含む `certutil` を探す |
| 発見 | 2件。1件は正当な管理者、1件はマーケティング部のノートPCで23:40 |
| 自動化 | Sigmaルールを書き、正当な管理者アカウントを除外する |

よい仮説は、最新の脅威インテリジェンスレポート、まだ検知のないATT&CKテクニック、ベースラインからの異常から生まれることが多い。

## 5. Sysmon: 使えるWindowsテレメトリ

Windows標準のログは詳細さに欠ける。Sysmonははるかに豊かなイベントを追加する。

| イベントID | 出来事 | ハンティングの問いの例 |
|:---|:---|:---|
| 1 | プロセス作成(コマンドラインと親付き) | `winword.exe` は何を起動したか |
| 3 | ネットワーク接続 | どのプロセスがポート4444へ外向き接続したか |
| 7 | DLLのロード | TempフォルダからDLLがロードされていないか |
| 10 | 他プロセスへのアクセス | 誰が `lsass.exe` のハンドルを開いたか |
| 11 | ファイル作成 | `AppData` に新しい `.exe` はないか |
| 13 | レジストリ値の変更 | `Run` キーに新しいエントリはないか |
| 22 | DNSクエリ | どのプロセスが怪しいドメインを問い合わせたか |

よく使われるコミュニティ設定(SwiftOnSecurity、またはOlaf Hartongのsysmon-modular)でインストールする。

```powershell
.\Sysmon64.exe -accepteula -i sysmonconfig.xml
# ログの場所: Applications and Services Logs > Microsoft > Windows > Sysmon > Operational
```

親子関係が最も強い手がかりになることが多い。

| 親 | 子 | 怪しい理由 |
|:---|:---|:---|
| `winword.exe`、`excel.exe` | `powershell.exe`、`cmd.exe` | 悪性マクロ(T1566 + T1059) |
| `w3wp.exe`(IIS) | `cmd.exe`、`whoami.exe` | Webシェル([LC-052](../../web/Vulnerabilities/ja/6.%20File%20Upload%20Vulnerabilities%20%26%20Web%20Shells.md)) |
| `services.exe` | ランダムな引数の `cmd.exe` | PsExecによる新規サービス(T1021.002) |
| `explorer.exe` | 引数なしの `rundll32.exe` | インジェクションまたはマルウェアローダー |

## 6. Sigma: 持ち運べる検知ルール

1つのSigmaルールは、Splunk、Elastic、Sentinelなどのクエリに変換できる。書くのは1回でよい。

```yaml
title: Certutilによるファイルダウンロード
id: 5f1c3a9e-2b7d-4c1e-9a3f-1d2e3f4a5b6c
status: experimental
description: certutil.exeがURLからファイルをダウンロードするのを検知する
references:
  - https://attack.mitre.org/techniques/T1105/
tags:
  - attack.command_and_control
  - attack.t1105
logsource:
  category: process_creation
  product: windows
detection:
  selection_img:
    Image|endswith: '\certutil.exe'
  selection_args:
    CommandLine|contains:
      - 'urlcache'
      - 'http'
  condition: selection_img and selection_args
falsepositives:
  - CRL取得のためにcertutilを使う管理者
level: high
```

`sigma-cli` でSIEMのクエリに変換する。

```bash
pip install sigma-cli
sigma plugin install splunk
sigma convert -t splunk -p sysmon certutil_download.yml
# 出力例:
# Image="*\\certutil.exe" CommandLine IN ("*urlcache*", "*http*")
```

GitHubのSigmaHQリポジトリには3000を超えるルールがある。自分で書く前にいくつか読んでおくとよい。

## 7. YARA: 悪性ファイルを見分ける

Sigmaはログに、YARAはファイルやメモリの中身に働く。LC-063で `strings` を見たが、YARAはその発見をルールにする。

```yara
rule Example_Simple_Downloader
{
    meta:
        author = "kodoktheGr3at"
        description = "URLDownloadToFileとcmdを使うダウンローダー"
        date = "2026-10-16"

    strings:
        $api   = "URLDownloadToFileA" ascii
        $cmd   = "cmd.exe /c" ascii nocase
        $ua    = "Mozilla/4.0 (compatible; MSIE 6.0" ascii
        $mz    = { 4D 5A }               // PEファイルのヘッダ

    condition:
        $mz at 0 and filesize < 500KB and 2 of ($api, $cmd, $ua)
}
```

```bash
yara -r example.yar ./samples/      # フォルダをスキャン
yara -s example.yar file.exe        # 一致した文字列を表示
```

YARAの誤検知を減らすコツ:

1. 1つの文字列に頼らず、`2 of (...)` で複数を組み合わせる。
2. そのマルウェア固有の文字列を使う。PDBパス、ミューテックス、作者特有のタイプミスなど。
3. `filesize` と `$mz at 0` で絞り込む。
4. `C:\Windows\System32` のようなクリーンなファイルのフォルダで試し、いくつ引っかかるか数える。

## 8. 検知の品質を測る

| 指標 | 問い |
|:---|:---|
| カバレッジ | 関係するATT&CKテクニックのうち、何パーセントに検知があるか |
| 精度 | 100件のアラートのうち、何件が真陽性か |
| 頑健性 | 攻撃者がファイル名やIPを変えても、ルールは発火するか |
| 検知までの時間 | 出来事からアラートまでどれくらいかかるか |

検知はテストが必要である。Atomic Red Team(Red Canary提供、無料)はATT&CKテクニックごとの小さなテストを用意している。ラボVMで実行し、ルールが発火するか確かめる。

```powershell
# ラボVMで: T1105のテストを実行し、SIEMを確認する
Invoke-AtomicTest T1105 -TestNumbers 7
```

## 9. 演習

### Task 1: 概念

1. 痛みのピラミッドで、攻撃者が最も簡単に変えられる指標は?
2. LSASSメモリダンプのATT&CK IDは?
3. プロセス作成を記録するSysmonイベントIDは?
4. SigmaとYARAの主な違いは?

<details><summary>解答</summary>

1. ファイルハッシュ
2. T1003.001
3. イベントID 1
4. Sigmaはログ(イベント)を、YARAはファイルやメモリの中身を照合する。

</details>

### Task 2: Sysmonイベントを読む

```text
EventID=1  Time=21:14:02  User=CORP\rina
  ParentImage=C:\Program Files\Microsoft Office\root\Office16\EXCEL.EXE
  Image=C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe
  CommandLine=powershell -nop -w hidden -enc SQBFAFgAIAAoAE4AZQB3AC0ATwBiAGoA...
EventID=3  Time=21:14:03  Image=...\powershell.exe  DestinationIp=203.0.113.99  DestinationPort=443
EventID=13 Time=21:14:05  Image=...\powershell.exe
  TargetObject=HKCU\Software\Microsoft\Windows\CurrentVersion\Run\Updater
```

1. 最初のイベントが怪しい理由を3つ挙げよ。
2. 3つのイベントをATT&CKテクニックに対応付けよ。
3. イベント13では何が起きており、なぜインシデント対応で重要か?

<details><summary>解答</summary>

1. ExcelがPowerShellを起動している、`-w hidden` でウィンドウを隠している、コマンドがbase64でエンコードされている(`-enc`)。さらに勤務時間外である。
2. イベント1: T1566.001(添付ファイルによるフィッシング)とT1059.001(PowerShell)、加えてT1027(難読化)。イベント3: T1071.001(WebによるC2)。イベント13: T1547.001(Registry Run Key)。
3. マルウェアがRunキーに永続化を仕込んだので、Rinaがログインするたびに再び動く。根絶の段階でこのキーを削除しなければならない。

</details>

### Task 3: Sigmaルールを書く

Officeのプロセス(`winword.exe`、`excel.exe`、`powerpnt.exe`)が `powershell.exe` または `cmd.exe` を起動したことを検知するSigmaルールを書け。`sigma-cli` でSplunkまたはElasticのクエリに変換すること。

<details><summary>解答例</summary>

```yaml
title: Officeがシェルを起動
status: experimental
logsource:
  category: process_creation
  product: windows
detection:
  parent:
    ParentImage|endswith:
      - '\winword.exe'
      - '\excel.exe'
      - '\powerpnt.exe'
  child:
    Image|endswith:
      - '\powershell.exe'
      - '\cmd.exe'
  condition: parent and child
level: high
tags:
  - attack.t1059
```

</details>

## 対応するレッドチームのレッスン

以下の攻撃は、それぞれ別のレッスンで攻撃者側の視点から扱っている。両方を並べて読むと、攻撃の手順から、どんな痕跡が残るかが見えてくる。

| レッスン | 攻撃者がすること | ここで探すもの |
|:---|:---|:---|
| [LC-060 Metasploit Framework & Exploitation](../../ethical-hacking/ja/3.%20Metasploit%20Framework%20%26%20Exploitation.md) | 初期の悪用とコマンド実行 | ATT&CK T1059: Sysmonイベント1での想定外の`powershell.exe`/`cmd.exe`の親プロセス |
| [LC-061 Privilege Escalation & Post-Exploitation](../../ethical-hacking/ja/4.%20Privilege%20Escalation%20%26%20Post-Exploitation.md) | 認証情報のダンプ、永続化、権限昇格 | T1003 `lsass.exe`へのアクセス（Sysmonイベント10）、T1053 新しいスケジュールタスク |
| [LC-052 File Upload Vulnerabilities & Web Shells](../../web/Vulnerabilities/ja/6.%20File%20Upload%20Vulnerabilities%20%26%20Web%20Shells.md) | Webシェルのアップロード | Webサーバーのプロセスがシェルや`whoami`を起動する |
| [LC-067 Offensive Python & Go for Pentesters](../../programming-security/ja/Offensive%20Python%20%26%20Go%20for%20Pentesters.md) | PythonとGoによる自作ツール | ハッシュはビルドごとに変わるため、痛みのピラミッドの上位にある振る舞いを追う |
| [LC-068 Social Engineering — Principles, Vectors & Defense](../../social-engineering/ja/Social%20Engineering%20%E2%80%94%20Principles%2C%20Vectors%20%26%20Defense.md) | 悪性文書を使ったフィッシング | T1566: Officeアプリがスクリプトインタープリタを起動する |
