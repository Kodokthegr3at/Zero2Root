## Key terms

| Term | Meaning |
|:---|:---|
| Threat hunting | Actively searching for signs of attack instead of waiting for alerts |
| Detection engineering | Designing, writing, testing, and maintaining detection rules |
| TTP | Tactics, Techniques, Procedures: how an attacker operates |
| ATT&CK | MITRE's catalog of attacker TTPs, e.g. T1059 = Command and Scripting Interpreter |

## 1. Passive detection vs threat hunting

In [LC-072](1.%20SOC%20%26%20Log%20Analysis.md) you waited for alerts. The trouble is that skilled attackers deliberately avoid existing rules. Threat hunting flips the order: you assume someone already got in, then go looking for proof.

| | Alert-driven monitoring | Threat hunting |
|:---|:---|:---|
| Trigger | A SIEM rule fires | An analyst's hypothesis |
| Question | "Is this alert real?" | "If an attacker were here, what traces would they leave?" |
| Output | An incident ticket | A new incident, or a new detection rule |
| Frequency | Continuous | Scheduled, e.g. weekly |

A hunt that finds nothing is still worth it if it produces a new detection rule, because next time that pattern gets caught automatically.

## 2. MITRE ATT&CK as a shared language

ATT&CK organizes attacker behavior into 14 tactics (goals), each holding techniques (methods).

| Tactic | Example technique | ID |
|:---|:---|:---|
| Initial Access | Phishing | T1566 |
| Execution | PowerShell | T1059.001 |
| Persistence | Scheduled Task | T1053.005 |
| Privilege Escalation | Exploitation for Privilege Escalation | T1068 |
| Defense Evasion | Clear Windows Event Logs | T1070.001 |
| Credential Access | LSASS Memory | T1003.001 |
| Discovery | Account Discovery | T1087 |
| Lateral Movement | Remote Services: SMB | T1021.002 |
| Command and Control | Web Protocols | T1071.001 |
| Exfiltration | Exfiltration Over C2 Channel | T1041 |

Tactics not listed above: Reconnaissance, Resource Development, Collection, and Impact.

With ATT&CK, a note like "attacker dumped LSASS" becomes T1003.001, and other teams know exactly which technique you mean. ATT&CK Navigator (free, web-based) lets you color in which techniques already have detections and which do not.

## 3. The pyramid of pain

David Bianco ranked indicators by how hard they are for an attacker to change:

```
                 ▲  TTPs                ← hardest to change, longest-lasting detection
                ▲▲  Tools
               ▲▲▲  Host/network artifacts
              ▲▲▲▲  Domains
             ▲▲▲▲▲  IP addresses
            ▲▲▲▲▲▲  File hashes         ← trivial to change (flip one byte, new hash)
```

A rule that blocks one hash stops working the moment the attacker recompiles. A rule that detects "an Office process launched PowerShell" keeps working when the malware changes. Aim your detections at the top of the pyramid.

## 4. The hypothesis-driven hunting loop

```
 1. Hypothesis ──► 2. Collect data ──► 3. Analyze ──► 4. Findings
      ▲                                                  │
      └──── 5. Automate: turn it into a detection ◄───────┘
```

Example:

| Step | Content |
|:---|:---|
| Hypothesis | "Attackers use `certutil.exe` to download payloads (T1105)." |
| Data | Sysmon Event ID 1 (process creation), last 30 days |
| Analysis | Look for `certutil` with `-urlcache` or `http` in the arguments |
| Findings | 2 hits: one legitimate admin, one marketing laptop at 23:40 |
| Automation | Write a Sigma rule, exclude the legitimate admin account |

Good hypotheses usually come from recent threat intel reports, ATT&CK techniques with no detection yet, or anomalies against the baseline.

## 5. Sysmon: Windows telemetry worth having

Windows' built-in logs lack detail. Sysmon adds much richer events.

| Event ID | What happened | Example hunting question |
|:---|:---|:---|
| 1 | Process creation (with command line and parent) | What did `winword.exe` launch? |
| 3 | Network connection | Which process connected out to port 4444? |
| 7 | DLL loaded | Was a DLL loaded from a Temp folder? |
| 10 | Process access | Who opened a handle to `lsass.exe`? |
| 11 | File created | Any new `.exe` in `AppData`? |
| 13 | Registry value set | Any new entry in a `Run` key? |
| 22 | DNS query | Which process queried an odd domain? |

Install with a popular community config (SwiftOnSecurity or Olaf Hartong's sysmon-modular):

```powershell
.\Sysmon64.exe -accepteula -i sysmonconfig.xml
# Logs appear under: Applications and Services Logs > Microsoft > Windows > Sysmon > Operational
```

Parent/child relationships are often the strongest clue:

| Parent | Child | Why it is suspicious |
|:---|:---|:---|
| `winword.exe`, `excel.exe` | `powershell.exe`, `cmd.exe` | Malicious macro (T1566 + T1059) |
| `w3wp.exe` (IIS) | `cmd.exe`, `whoami.exe` | Web shell ([LC-052](../../web/Vulnerabilities/en/6.%20File%20Upload%20Vulnerabilities%20%26%20Web%20Shells.md)) |
| `services.exe` | `cmd.exe` with random arguments | New service from PsExec (T1021.002) |
| `explorer.exe` | `rundll32.exe` with no arguments | Injection or malware loader |

## 6. Sigma: portable detection rules

One Sigma rule converts into Splunk, Elastic, Sentinel, and other query languages. You write it once.

```yaml
title: Certutil Downloading a File
id: 5f1c3a9e-2b7d-4c1e-9a3f-1d2e3f4a5b6c
status: experimental
description: Detects certutil.exe used to download a file from a URL
references:
  - https://attack.mitre.org/techniques/T1105/
tags:
  - attack.command_and_control
  - attack.t1105
logsource:
  category: process_creation
  product: windows
detection:
  selection_img:
    Image|endswith: '\certutil.exe'
  selection_args:
    CommandLine|contains:
      - 'urlcache'
      - 'http'
  condition: selection_img and selection_args
falsepositives:
  - Admins using certutil to fetch CRLs
level: high
```

Convert to a SIEM query with `sigma-cli`:

```bash
pip install sigma-cli
sigma plugin install splunk
sigma convert -t splunk -p sysmon certutil_download.yml
# Sample output:
# Image="*\\certutil.exe" CommandLine IN ("*urlcache*", "*http*")
```

The SigmaHQ repository on GitHub holds more than 3000 ready-made rules. Read a few before writing your own.

## 7. YARA: recognizing malicious files

Sigma works on logs; YARA works on file or memory contents. You met `strings` in [LC-063](../../malware-analysis/en/1.%20Static%20Malware%20Analysis%20Fundamentals.md), and YARA turns those findings into rules.

```yara
rule Example_Simple_Downloader
{
    meta:
        author = "kodoktheGr3at"
        description = "Downloader using URLDownloadToFile and cmd"
        date = "2026-10-16"

    strings:
        $api   = "URLDownloadToFileA" ascii
        $cmd   = "cmd.exe /c" ascii nocase
        $ua    = "Mozilla/4.0 (compatible; MSIE 6.0" ascii
        $mz    = { 4D 5A }               // PE file header

    condition:
        $mz at 0 and filesize < 500KB and 2 of ($api, $cmd, $ua)
}
```

```bash
yara -r example.yar ./samples/      # scan a folder
yara -s example.yar file.exe        # show matching strings
```

Keeping YARA false positives down:

1. Combine several strings with `2 of (...)` instead of relying on one.
2. Use strings unique to that malware: PDB paths, mutexes, the author's typos.
3. Constrain with `filesize` and `$mz at 0`.
4. Test against a folder of clean files, e.g. `C:\Windows\System32`, and count what matches.

## 8. Measuring detection quality

| Measure | Question |
|:---|:---|
| Coverage | What percentage of relevant ATT&CK techniques have a detection? |
| Precision | Out of 100 alerts, how many are true positives? |
| Robustness | If the attacker renames the file or switches IPs, does the rule still fire? |
| Time to detect | How long from event to alert? |

Detections need testing. Atomic Red Team (free, from Red Canary) provides small tests per ATT&CK technique. Run them in a lab VM and check whether your rules fire.

```powershell
# In a lab VM: run a T1105 test, then check the SIEM
Invoke-AtomicTest T1105 -TestNumbers 7
```

### Task 2: read Sysmon events

```text
EventID=1  Time=21:14:02  User=CORP\rina
  ParentImage=C:\Program Files\Microsoft Office\root\Office16\EXCEL.EXE
  Image=C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe
  CommandLine=powershell -nop -w hidden -enc SQBFAFgAIAAoAE4AZQB3AC0ATwBiAGoA...
EventID=3  Time=21:14:03  Image=...\powershell.exe  DestinationIp=203.0.113.99  DestinationPort=443
EventID=13 Time=21:14:05  Image=...\powershell.exe
  TargetObject=HKCU\Software\Microsoft\Windows\CurrentVersion\Run\Updater
```

1. Why is the first event suspicious? Give three reasons.
2. Map all three events to ATT&CK techniques.
3. What happens in event 13, and why does it matter for incident response?

<details><summary>Answer key</summary>

1. Excel launched PowerShell, the `-w hidden` flag hides the window, and the command is base64-encoded (`-enc`). It is also outside working hours.
2. Event 1: T1566.001 (phishing attachment) and T1059.001 (PowerShell), plus T1027 (obfuscation). Event 3: T1071.001 (web C2). Event 13: T1547.001 (Registry Run Key).
3. The malware set up persistence in a Run key, so it will start again every time Rina logs in. That key must be removed during eradication.

</details>

### Task 3: write a Sigma rule

Write a Sigma rule that detects an Office process (`winword.exe`, `excel.exe`, `powerpnt.exe`) launching `powershell.exe` or `cmd.exe`. Convert it to a Splunk or Elastic query with `sigma-cli`.

<details><summary>Sample answer</summary>

```yaml
title: Office Spawning a Shell
status: experimental
logsource:
  category: process_creation
  product: windows
detection:
  parent:
    ParentImage|endswith:
      - '\winword.exe'
      - '\excel.exe'
      - '\powerpnt.exe'
  child:
    Image|endswith:
      - '\powershell.exe'
      - '\cmd.exe'
  condition: parent and child
level: high
tags:
  - attack.t1059
```

</details>
