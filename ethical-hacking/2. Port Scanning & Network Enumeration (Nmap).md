## 1. 🎯 Scanning as Inventory (Authorized Networks Only)

### 🇮🇩 Bahasa Indonesia
Port scanning pada konteks profesional adalah **pengukuran permukaan jaringan**: host hidup, port listening, dan layanan yang diiklankan. Dilakukan hanya pada:

- Infrastruktur milik sendiri
- Lab CTF / VM yang Anda kontrol
- Engagement dengan **RoE tertulis**

$$
\text{Inventory usefulness} = \frac{\text{Accurate open ports}}{\text{False positives} + \text{Missed services}}
$$

### 🇬🇧 English
This note explains **protocol mechanics** and **defender-visible artifacts**. It is not an evasion cookbook for third-party networks.

### 🇯🇵 日本語
ここではプロトコルの仕組みと防御側から見える痕跡を学びます。第三者ネットワーク向けの回避手順は扱いません。

## 2. 🤝 TCP Three-Way Handshake (Mechanics)

```
Client                                Server
  │  SYN (seq=x)                        │
  │────────────────────────────────────>│
  │  SYN-ACK (seq=y, ack=x+1)           │
  │<────────────────────────────────────│
  │  ACK (ack=y+1)                      │
  │────────────────────────────────────>│
  │         ESTABLISHED                 │
```

State transitions (simplified):

$$
\text{LISTEN} \xrightarrow{\text{SYN}} \text{SYN-RCVD} \xrightarrow{\text{ACK}} \text{ESTABLISHED}
$$

$$
\text{CLOSED} \xrightarrow{\text{SYN}} \text{SYN-SENT} \xrightarrow{\text{SYN-ACK}} \text{ESTABLISHED}
$$

### Port response intuition

| Observer sees | Typical meaning |
|:---|:---|
| SYN-ACK | Something accepted the SYN (candidate open) |
| RST | Actively refused / closed |
| Silence / drop | Filtered, loss, or stealth ACL |

### 🇮🇩 Bahasa Indonesia
Firewall *drop* vs *reject* menghasilkan jejak berbeda di sisi klien dan di log keamanan—penting untuk blue team.

## 3. 🔍 SYN Scan vs Connect Scan (Protocol Knowledge)

### Connect scan (`-sT` concept)
Stack OS menyelesaikan handshake penuh lalu menutup. Terlihat seperti koneksi aplikasi singkat.

$$
\text{Cost}_{\text{connect}} \propto \text{full handshake} + \text{socket accounting}
$$

### SYN scan (`-sS` concept)
Pengirim mengamati SYN-ACK lalu biasanya mengirim RST (tidak menyelesaikan sesi aplikasi). Masih **paket kontrol TCP** yang sangat terlihat oleh NIDS modern.

```
SYN scan sketch (conceptual):
  Scanner --SYN--> Target
  Scanner <--SYN-ACK-- Target   ⇒ infer "open"
  Scanner --RST--> Target       ⇒ tear down early
```

### 🇬🇧 English
Historically SYN scan was called “half-open.” That does **not** mean invisible. Modern IDS correlates SYN floods, scan fan-out, and incomplete handshakes.

### 🇯🇵 日本語
SYNスキャンは「半開」と呼ばれても**不可視ではありません**。不完全ハンドシェイクは検知材料になります。

| Property | Connect | SYN (concept) |
|:---|:---|:---|
| Completes handshake | Yes | Often no |
| Needs raw sockets / privilege | Usually no | Often yes |
| App-layer logs | More likely | Less app, more network IDS |
| Stealth vs modern NIDS | Low | Still low if noisy |

## 4. 📦 UDP, ICMP & Ambiguity

UDP has no handshake. “Open” inference is statistical:

$$
\text{UDP open?} =
\begin{cases}
\text{response datagram} & \text{likely open/service} \\
\text{ICMP port unreachable} & \text{likely closed} \\
\text{timeout} & \text{open|filtered ambiguous}
\end{cases}
$$

Rate-limiting ICMP on routers increases ambiguity—defenders should document expected ICMP policy so SOC does not misread scans.

## 5. 🛠️ Common Nmap Flags for **Own-Network Inventory**

Gunakan hanya pada scope berizin. Contoh di bawah adalah **inventaris operasional**, bukan playbook serangan.

| Flag / option | Role in inventory |
|:---|:---|
| `-sn` | Host discovery without port scan |
| `-sV` | Service/version probes (noisier) |
| `-O` | OS fingerprint heuristics (unreliable alone) |
| `-p` / `-p-` | Port set control |
| `-T3` / `-T2` | Timing templates (lower = gentler) |
| `-oA basename` | Save normal + XML + grepable |
| `--reason` | Why Nmap classified a state |

```bash
# ── Authorized lab / own subnet inventory examples ───────────
# Replace CIDR with YOUR documented scope only.

nmap -sn 192.0.2.0/24 -oA lab_hosts
nmap -sV -p 22,80,443,3389 192.0.2.10 -oA lab_svc --reason
nmap -sU --top-ports 20 192.0.2.10 -oA lab_udp   # slow; expect ambiguity
```

### 🇮🇩 Bahasa Indonesia
`-A` (agresif) menggabungkan banyak probe—berguna di lab, berisiko di produksi tanpa jendela pemeliharaan.

### 🇬🇧 English
Prefer **targeted port lists** derived from CMDB over blind full-range scans on fragile OT/ICS segments.

## 6. 🚨 How Defenders Detect Scans

### Telemetry sources
- Firewall accept/deny counters
- Zeek/Suricata signatures for horizontal/vertical sweeps
- NetFlow / IPFIX: fan-out from one source to many ports/hosts
- Host agents: bursts of incomplete TCP

### Simple detection features

$$
\text{ScanScore} \approx w_1 \cdot \frac{\#\text{dst ports}}{\Delta t} + w_2 \cdot \frac{\#\text{dst hosts}}{\Delta t} + w_3 \cdot \#\text{incomplete TCP}
$$

Thresholds are environment-specific; tune against known admin scanners (Nessus windows, etc.) to reduce false positives.

```
         many ports
Single IP ──────────────► many hosts   = classic sweep pattern
              │
              ▼
     SOC alert / rate-limit / tarpit policy
```

### 🇯🇵 日本語
正規の脆弱性スキャン窓をカレンダー共有すると、アラートのノイズを減らせます。

## 7. 🛡️ Network Hardening Against Unwanted Scanning

| Control | Effect |
|:---|:---|
| Default-deny inbound | Shrink listening exposure |
| Segregation / microseg | Limit lateral fan-out value |
| SYN cookies / backlog tuning | Resilience to SYN floods |
| Geo / ASN allowlists (where apt) | Reduce internet noise |
| Banner minimization | Less free intel from `-sV` |
| Canary ports / honeyports | High-confidence alerts |
| Egress control | Compromised hosts scan less usefully |

### Stallings perspective
Confidentiality/integrity of services starts with **reducing unnecessary listeners**. Scanning is how attackers (and auditors) discover those listeners—so closing them is primary defense.

### Filter vs reject trade-off

| Policy | Attacker view | Defender ops |
|:---|:---|:---|
| REJECT (RST/ICMP) | Faster mapping | Clearer logs |
| DROP | Slower / ambiguous | Harder troubleshooting |

Pilih secara sadar per zona (DMZ vs internal).

## 8. ✅ Defensive & Lab Cheatsheet

```text
[ ] Written authorization / own lab confirmed
[ ] Change window notified for production inventory
[ ] Output saved (-oA) with date in filename
[ ] Timing tempered on sensitive segments
[ ] Results diffed against last CMDB export
[ ] Unexpected listeners ticketed for closure
[ ] SOC allowlisted or informed for scheduled scans
[ ] No scan of third-party SaaS without their consent
```

### Interpreting results for hardening

| Finding | Action |
|:---|:---|
| Unexpected RDP/SSH on internet | Move behind VPN / bastion |
| Dev tools on prod VLAN | Relocate network path |
| Many filtered obscure ports | Verify ACL intent |
| Version strings outdated | Patch pipeline |

## 🔐 Security Notes

| Risiko | Penyebab | Mitigasi |
|:---|:---|:---|
| Accidental DoS | Aggressive timing / huge ranges | `-T2`, narrow `-p`, rate limits |
| Legal exposure | Scanning without authority | RoE / ownership proof |
| Blind spots | DROP-only + no internal sensors | Internal network telemetry |
| Alert fatigue | Unannounced vuln scanners | Shared scan calendar |
| Over-trust OS detect | Fingerprint noise | Correlate with CMDB agents |
