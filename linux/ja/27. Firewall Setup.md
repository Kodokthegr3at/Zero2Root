## 重要な用語

この教材でよく出てくる言葉である。

| 用語 | 意味 |
|:---|:---|
| ファイアウォール | ネットワークトラフィックを許可または遮断する規則 |
| Netfilter | 実際にパケットをフィルタするカーネルのサブシステム |
| iptables / nftables | ファイアウォール規則を書く古い / 新しいツール |
| `ufw` / `firewalld` | nftablesの上に乗る、より扱いやすいフロントエンド |
| チェイン | トラフィックが照合される規則の列(INPUT、OUTPUT、FORWARD) |

| ステートフル | 単一パケットだけでなく、接続を追跡するファイアウォール |

## 1. Linux Netfilter — フィルタリングが行われる場所

Netfilterというカーネルサブシステムは、パケットを転送・許可・破棄する前にiptables/nftablesのルールと照合します。

```text
ACCEPT  |  DROP  |  REJECT  |  LOG  |  NAT
```

ホストファイアウォールは、ネットワークエッジのフィルタの後段に置かれる多層防御です。サーバーの基本方針は、inboundを拒否し、確立済み接続は許可し、必要なサービスだけに明示的な許可リストを設定することです。

```
Inbound packet
      │
      ▼
 PREROUTING (nat)
      │
      ▼
 INPUT (filter)  → ACCEPT / DROP
      │
      ▼
 Local process OR forward path
```

| フレームワーク | 対象ディストロ | バックエンド |
|:---|:---|:---|
| UFW | Ubuntu/Debian | iptables/nftバックエンド |
| firewalld | Fedora/RHEL/Alma | nftables |
| iptables | 汎用の低レベルCLI | レガシーCLI |
| nftables | 現代的なデフォルト | `nft` CLI |

理論的背景(DAC、MAC、ハードニングの柱)についてはノート26を参照してください。

## 2. iptables — テーブル、チェーン、ルール

iptablesはルールをテーブル(filter/nat/…)とチェーン(INPUT/FORWARD/OUTPUT)に整理します。ルールは上から下へ評価され、最初にマッチしたものが適用されます。

| テーブル | 用途 |
|:---|:---|
| `filter` | 許可/拒否(INPUT、FORWARD、OUTPUT) |
| `nat` | SNAT/DNAT/MASQUERADE |
| `mangle` | TTL/TOS/マーク |
| `raw` | コネクション追跡の除外 |

ルールは上から下へ評価され、`-j` によるジャンプがない限り最初のマッチが適用されます。バックアップには `iptables-save` / `iptables-restore` を使います。

```bash
# View current rules
sudo iptables -L -v -n
sudo iptables -S

# Minimal allowlist INPUT (lab — adjust interfaces/ports)
sudo iptables -P INPUT DROP
sudo iptables -P FORWARD DROP
sudo iptables -P OUTPUT ACCEPT

sudo iptables -A INPUT -i lo -j ACCEPT
sudo iptables -A INPUT -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT
sudo iptables -A INPUT -p tcp --dport 22 -s 203.0.113.0/24 -j ACCEPT
sudo iptables -A INPUT -p tcp --dport 443 -j ACCEPT
sudo iptables -A INPUT -j LOG --log-prefix "IPT DROP: "
sudo iptables -A INPUT -j DROP

# Persist (Debian)
sudo apt install iptables-persistent -y
sudo netfilter-persistent save
```

| ターゲット | 動作 |
|:---|:---|
| `-j ACCEPT` | パケットを許可 |
| `-j DROP` | 無言で破棄 |
| `-j REJECT` | 破棄してICMPエラーを返す |
| `-j LOG` | ログを記録してチェーンを継続 |

## 3. nftables — 後継の構文

nftablesはIPv4/IPv6の扱いを統合しており、ルールセットは `nft -f` によってアトミックに適用されます。

デフォルトでnftを使うディストロでは、`iptables` は単なるiptables-nft互換レイヤーである場合があります。新規ルールにはネイティブの `nft` を優先してください。

```bash
sudo nft list ruleset

# Example ruleset file /etc/nftables.conf fragment
sudo tee /etc/nftables.conf << 'EOF'
#!/usr/sbin/nft -f
flush ruleset
table inet filter {
  chain input {
    type filter hook input priority 0; policy drop;
    iif "lo" accept
    ct state established,related accept
    tcp dport 22 ip saddr 203.0.113.0/24 accept
    tcp dport { 80, 443 } accept
  }
}
EOF
sudo nft -f /etc/nftables.conf
sudo systemctl enable --now nftables
```

## 4. UFW — Uncomplicated Firewall(Debian/Ubuntu)

アプリケーションプロファイルベースのフロントエンド(`OpenSSH`、`Nginx Full`)です。使いやすく、それでいてデフォルト拒否を維持します。

SSHの許可ルールを確認してから有効化してください。ロックアウトした際に復旧できるよう、コンソールアクセスを用意しておきます。

```bash
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow OpenSSH
sudo ufw allow from 203.0.113.0/24 to any port 22 proto tcp
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw limit OpenSSH    # rate-limit brute force
sudo ufw enable
sudo ufw status verbose
sudo ufw status numbered
sudo ufw delete 3         # by rule number
```

| コマンド | 効果 |
|:---|:---|
| `ufw app list` | 利用可能なプロファイル |
| `ufw allow in on eth0` | インターフェース単位のルール |
| `ufw logging on` | ブロックされたパケットをログ記録(中レベル) |

## 5. firewalld — ゾーン(RHELファミリー)

ゾーン(`public`、`internal`、`drop`)と `firewall-cmd` があり、runtimeとpermanentの2種類の変更があります。

`--permanent` の変更は再起動後も残りますが `--reload` が必要です。runtimeのみの変更は保存しない限り再起動で消えます。

```bash
sudo systemctl enable --now firewalld
sudo firewall-cmd --state
sudo firewall-cmd --get-active-zones
sudo firewall-cmd --list-all

# Allow HTTP permanently in public zone
sudo firewall-cmd --zone=public --add-service=http --permanent
sudo firewall-cmd --zone=public --add-service=https --permanent
sudo firewall-cmd --reload

# Rich rule: SSH from subnet
sudo firewall-cmd --permanent --add-rich-rule='rule family="ipv4" source address="203.0.113.0/24" service name="ssh" accept'
sudo firewall-cmd --reload
```

| ゾーン | 典型的な用途 |
|:---|:---|
| `public` | 信頼できないネットワーク |
| `internal` | 信頼できるLAN |
| `drop` | inboundをブラックホール化 |

## 6. 許可リスト設計パターン

原則: inboundは明示的に許可された範囲だけ通します。

許可される受信通信は、各サービスのポートと、そこへアクセスしてよい送信元アドレスの一覧だけです。それ以外は一切入れません。

| パターン | 使う場面 |
|:---|:---|
| 管理サブネット → SSH | 全サーバー |
| `0.0.0.0/0` → 443のみ | 公開Web |
| bastion以外のVLAN間通信を全拒否 | セグメント化されたデータセンター |
| DROPの前にLOG | 無言の失敗を避けつつ調整する |

```bash
# Verify effective posture
sudo ufw status verbose
sudo iptables -L INPUT -v -n --line-numbers
sudo nft list chain inet filter input
sudo firewall-cmd --list-all

# Map listeners vs firewall
ss -tulnp | grep LISTEN
```

## 7. セキュリティノート — ロックアウトとログ

最も高くつくミスは、リモートSSHアクセスを自分でロックアウトしてしまうことです。大きな変更を行う前にロールバックタイマーとコンソールアクセスを準備してください。

デフォルト拒否のポリシーを有効化する前にSSHを許可します。IPv6を忘れないでください。LOGはレート制限してディスクを埋め尽くさないようにします。Fail2Ban(ノート26)と認証ログ(ノート28)と組み合わせます。

| 落とし穴 | 結果 | 予防策 |
|:---|:---|:---|
| SSHを許可する前にファイアウォールを有効化 | コンソールでの復旧が必要になる | 先に `ufw allow OpenSSH`; `netfilter-persistent` でテスト |
| リモートからルールをフラッシュ | 即座にロックアウト | `at` によるロールバックタイマーかシリアルコンソール |
| 広すぎる `allow 22/tcp` | インターネットからのブルートフォース | 送信元IPの許可リスト + Fail2Ban(ノート26) |
| IPv6ルールの欠落 | v6経由でのバイパス | デュアルスタックのルール(`inet` テーブル / ip6tables) |
| すべてをログに記録 | ディスク/CPUの溢れ | LOGプレフィックスにレート制限 |

```bash
# Safe change pattern (lab)
# 1) schedule rollback
echo "sudo ufw disable" | at now + 5 minutes
# 2) apply change
sudo ufw enable
# 3) verify SSH in second session
# 4) cancel rollback: atrm JOB
```

参照: ネットワークインターフェースはノート24〜25、認証へのブルートフォースについてはノート28のログを参照してください。

## 8. クイックリファレンスチートシート

```bash
# UFW
sudo ufw default deny incoming
sudo ufw allow OpenSSH
sudo ufw enable && sudo ufw status verbose

# iptables
sudo iptables -L -v -n
sudo iptables -S
sudo netfilter-persistent save

# nftables
sudo nft list ruleset
sudo nft -f /etc/nftables.conf

# firewalld
sudo firewall-cmd --list-all
sudo firewall-cmd --add-service=https --permanent
sudo firewall-cmd --reload

# Audit
ss -tulnp | grep LISTEN
```
