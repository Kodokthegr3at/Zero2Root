## 重要な用語

この教材でよく出てくる言葉である。

| 用語 | 意味 |
|:---|:---|
| Solaris | Sun/Oracleの商用Unix。Linuxと関連はあるが別物 |
| Unix | Linuxが手本にした、より古いOSの系統 |
| SMF | Solarisのサービス管理(systemdのような役割) |
| ZFS | Solarisの高機能ファイルシステム(スナップショット、チェックサム) |
| Zones | Solaris組み込みのコンテナ/仮想化機能 |
| IPS | Solarisのパッケージシステム |
| 移植性 | 非LinuxのUnixに出会ったとき、違いを知っておくと役立つ理由 |

## 1. Oracle Solarisとは何か

Solaris(旧SunOS/Sun Solaris)はSun Microsystems発、現在はOracleによる商用Unixです。BSD/System VというDNAをLinuxと共有していますが、カーネル、ユーザーランド、initシステム、パッケージ管理、デフォルトのファイルシステムはすべて異なります。

```text
Solaris = Sun/Oracle kernel + SMF + ZFS (default) + Zones + IPS packages
```

Solarisはエンタープライズ向けSPARC/x86、通信キャリア、レガシー環境で今も現役です。ペンテスターや管理者はLinuxと並んでSolarisに遭遇することがあり、両者の違いを知ることは偵察とハードニングを速めます。

```
Timeline (simplified)
  1990s  SunOS / Solaris 2.x
  2000s  Solaris 8/9/10 — ZFS, Containers preview
  2010s  Oracle acquisition; Solaris 11 + IPS
  today  Oracle Solaris 11.x (maintenance-focused)
         Linux distros dominate cloud; Solaris in legacy/verticals
```

| 特性 | Solaris | 典型的なLinux |
|:---|:---|:---|
| ベンダー | Oracle | コミュニティ/商用の混在 |
| Init/サービス | SMF | systemd(大半のディストロ) |
| デフォルトFS | ZFS(現代的) | ext4/XFS/btrfs |
| コンテナ | Zones | cgroups/namespaces(Docker/Podman) |
| パッケージマネージャ | IPS(`pkg`) | apt/dnf/pacman |
| ライセンス | Oracleによる独占的所有 | 大半がオープンソース |

## 2. SolarisとLinuxの主な違い(管理者向け)

Linuxに慣れた管理者は、概念(ユーザー、プロセス、ネットワーク)は似ていても、異なるCLIとパスに直面します。

| 領域 | Solaris | Linux |
|:---|:---|:---|
| カーネル名 | Sun/Oracle kernel | Linux kernel |
| サービス制御 | `svcadm`、`svcs` | `systemctl` |
| ブートローダー | GRUB(x86) | GRUB/systemd-boot |
| ネットワーク設定 | `dladm`、`ipadm`、`route` | `ip`、NetworkManager |
| user/groupファイル | `/etc/passwd`、`/etc/shadow` | 同じFHSの概念 |
| プロセス一覧 | `ps`、`pgrep`、`/proc` | 概念は同じだが `ps` のフラグが異なる |
| ファイアウォール | 歴史的にはIPFilter; `pf` のパターン | iptables/nft/ufw |

Solarisでは多くのGNUツールがGNUユーザーランドパッケージ経由で利用できますが、パスやフラグが異なります。Linuxディストロ間で移植可能なスクリプトも、調整なしではSolarisで動かないことがあります。

```bash
# Linux habit          →  Solaris equivalent (illustrative — Solaris 11)
# systemctl status ssh →  svcs -xv ssh
# df -hT               →  zfs list  (when ZFS root)
# ip addr              →  ipadm show-addr
# apt install curl     →  pkg install curl
# crontab -l           →  crontab -l (similar, different paths)
```

## 3. SMF — Service Management Facility

SMFはレガシーなinitスクリプトを、FMRI(Fault Management Resource Identifier)と依存関係グラフで置き換えたものです。

```text
svc:/category/service:instance
```

例: `svc:/network/ssh:default`

SMFはサービスの状態(`online`、`offline`、`maintenance`)を追跡し、失敗時に再起動し、依存関係に基づいて起動順序を決めます。概念的にはsystemdに似ていますが、CLIとXMLマニフェストが異なります。

```bash
# List services
svcs -a
svcs -x                    # failed/maintenance
svcs -l ssh                # detailed

# Enable / start / stop
sudo svcadm enable ssh
sudo svcadm disable ssh
sudo svcadm restart ssh
sudo svcadm clear ssh      # clear maintenance state

# Inspect properties
svcprop -p all ssh
```

| SMFの状態 | 意味 |
|:---|:---|
| `online` | 実行中/満たされている |
| `offline` | 無効化/停止 |
| `maintenance` | 管理者の対応が必要 |
| `degraded` | 一部機能のみ動作 |

Linuxのsystemdとの比較についてはノート17(`systemctl`、`journalctl`)を参照してください。

## 4. IPSパッケージ管理 — `pkg`

Image Packaging System(IPS)は、Oracleのパブリッシャーと依存関係ソルバーでソフトウェアを管理します。

`apt`/`yum` ではなく `pkg` を使います。ブート環境(BE)はZFSと組み合わせて、ロールバック可能なアップグレードを実現します。

```bash
pkg publisher
pkg search curl
pkg info -r curl
sudo pkg install curl
pkg list
pkg update

# Verify package contents
pkg contents -H curl

# Create boot environment before major update (ZFS systems)
beadm list
sudo beadm create pre-update-$(date +%Y%m%d)
```

| コマンド | 動作 |
|:---|:---|
| `pkg install PKG` | パッケージをインストール |
| `pkg update` | インストール済みセットを更新 |
| `pkg verify` | ファイルの整合性を確認 |
| `beadm activate BE` | スナップショットBEへ起動 |

## 5. ZFS — Zettabyte File System

ZFSはボリュームマネージャとファイルシステムを統合したもので、copy-on-write、チェックサム、スナップショット、圧縮、重複排除(RAM使用量に注意)を備えます。

```text
tank            (pool)
 └─ tank/home
     └─ tank/home/alice
```

Linuxでも一部ディストロでOpenZFSが使えるようになりましたが、Solarisのほうがネイティブで統合が成熟しています。管理者は `/dev/sda1` のような単位ではなく、プールとデータセットという単位で考えます。

```bash
# Pool & dataset (Solaris)
zpool list
zpool status
zfs list
zfs create tank/export
zfs set compression=lz4 tank/export
zfs snapshot tank/export@backup-$(date +%F)
zfs rollback tank/export@backup-2026-08-18

# Quotas & reservations
zfs set quota=50G tank/home/alice
zfs set reservation=10G tank/home/alice
```

| ZFSの機能 | 利点 |
|:---|:---|
| チェックサム | 静かな破損を検出 |
| スナップショット | 特定時点への即座の復元 |
| 送受信(send/receive) | レプリケーション |
| 圧縮 | 容量の節約(CPUとのトレードオフ) |

LinuxのLVM/ext4の基礎についてはノート22を参照してください。

## 6. Solaris Zones — OSレベルの仮想化

Zonesは現代のコンテナに似たカーネルレベルの隔離で、global zoneとnamespaceが分離されたnon-global zoneで構成されます。

Linuxコンテナに先行する技術ですが、目的は似ています。kernel zoneとnative zoneでは隔離の強度が異なります。ZonesはDockerではありませんが、概念的にはノート23と関連があります。

```bash
# Zone management (illustrative)
zonecfg -z myzone
zoneadm -z myzone install
zoneadm -z myzone boot
zlogin myzone

# From global zone
zoneadm list -cv
```

```
Global Zone (host)
 ├─ Zone: web01   (own /etc, users, SMF subset)
 ├─ Zone: db01
 └─ Zone: dev01
Shared kernel, isolated userlands
```

## 7. セキュリティノート — Solarisのハードニングの要点

まずOSを識別してください。SolarisをLinuxと誤認すると、サービス列挙やハードニングの方針を誤った方向へ進めてしまいます。

Solarisの制御をLinuxの対応物に当てはめます。RBAC/ロールはsudoに、監査デーモンはauditdに、Trusted ExtensionsはSELinuxに対応します。パッケージは `pkg verify` で検証します。

| トピック | Solarisでのやり方 | Linuxでの対応 |
|:---|:---|:---|
| RBAC/ロール | `roleadd`、`profiles` | sudo + グループ |
| 監査 | Solarisの監査デーモン | auditd |
| MAC | Trusted Extensions(ニッチ) | SELinux/AppArmor |
| パスワードポリシー | `/etc/security/policy.conf` | `login.defs`、PAM |
| リモートアクセス | `ssh` のSMFサービス | `sshd` のsystemdユニット |
| 最小化 | `pkg` のバリアントセット | 最小構成のクラウドイメージ |

```bash
# Defensive recon (authorized Solaris host)
uname -a
cat /etc/release
svcs -x
netstat -an -f inet | grep LISTEN    # or ss equivalent if installed
pkg verify
zfs list
```

**評価時のヒント:** OSは早期に識別してください。SolarisをLinuxと取り違えると、権限昇格やサービス列挙の経路を誤ります。
