## 重要な用語

この教材でよく出てくる言葉である。

| 用語 | 意味 |
|:---|:---|
| 正規表現 | どのテキストに一致させるかを表すパターン |
| リテラル | それ自身に一致する文字(`a` は `a` に一致) |
| メタ文字 | 特別な意味を持つ文字(`.`、`*`、`^`、`$`) |
| 文字クラス | 許される文字の集合。`[a-z]` など |
| 量指定子 | 何回繰り返すか(`*`、`+`、`{2,4}`) |
| アンカー | 一致を位置に固定する(`^` 先頭、`$` 末尾) |
| キャプチャグループ | 一致の一部を覚えるかっこ `( )` |
| BRE と ERE | 基本 vs 拡張の正規表現。`grep -E` で拡張形が有効になる |

## 1. RegEx とは何か

正規表現(RegEx)は、検索パターンを形成する文字とシンボルの並びです。RegEx は非常にカスタマイズ可能なフィルターだと考えてください。テキストをふるいにかけて、必要なものを正確に見つけ出します。

RegEx の用途:
- テキストパターンを精密に検索する
- テキストを一括置換する
- 入力(メールアドレス、パスワード、電話番号)を検証する
- 他のコマンドの出力をフィルタリングする

RegEx は `grep`、`sed`、`awk`、Python、JavaScript など、多くのプログラミング言語やツールで使えます。

## 2. グループ化演算子

RegEx は3種類の括弧を使い、それぞれ検索パターンを定義するうえで異なる役割を持ちます。

| 演算子 | 記号 | 説明 |
|----------|--------|------|
| 丸括弧 | `(a)` | regex の一部をグループ化する。括弧内にさらにパターンを定義し、一緒に処理できる |
| 角括弧 | `[a-z]` | 文字クラスを定義する。括弧内に検索する文字のリストを指定する |
| 波括弧 | `{1,10}` | 量指定子(quantifier)を定義する。直前のパターンを何回繰り返すかを指定する |
| OR 演算子 | `\|` | 2つの式のいずれか一方が一致すれば結果を表示する |
| AND 演算子 | `.*` | 両方の式が指定した順序で存在し、一致した場合のみ結果を表示する |

---

## 3. OR 演算子(`|`)

`|`(OR)演算子は、指定したパターンの少なくとも一つを含む行を検索します。`grep` でこの演算子を使うには `-E`(拡張正規表現)フラグが必要です。

```bash
# Search for lines containing "my" OR "false"
$ grep -E "(my|false)" /etc/passwd

lxd:x:105:65534::/var/lib/lxd/:/bin/false
pollinate:x:109:1::/var/cache/pollinate:/bin/false
mysql:x:116:120:MySQL Server,,:/nonexistent:/bin/false
```

```
Pattern:  (my|false)
              │
     ┌────────┴────────┐
     ▼                 ▼
   "my"             "false"
  matches?          matches?
     │                 │
     └────────┬─────────┘
              ▼
     Either one = SHOW LINE
```

> 3行すべてが表示されるのは、各行が `my`(mysql)または `false`(/bin/false)のどちらか、あるいは両方を含んでいるためです。

## 4. AND 演算子(`.*`)

`.*`(AND)演算子は、両方のパターンを順番に含む行だけを表示します。`.*` は2つのパターンの間に「任意の文字が何文字でも」という意味を持つため、両方の単語が同じ行に存在する必要があります。

```bash
# Search for lines containing BOTH "my" AND "false" (in that order)
$ grep -E "(my.*false)" /etc/passwd

mysql:x:116:120:MySQL Server,,:/nonexistent:/bin/false
```

```
Pattern:  (my.*false)
            │  │   │
            │  │   └── "false" must appear AFTER "my"
            │  └────── any characters in between (.*)
            └────────── "my" must appear first

mysql:x:116:120:MySQL Server,,:/nonexistent:/bin/false
  ↑ "my" found here              ↑ "false" found here → MATCH ✓

lxd:x:105:65534::/var/lib/lxd/:/bin/false
  ↑ no "my" found → NO MATCH ✗
```

### 代替手段: grep を連結する

```bash
# Same result using two grep pipes (AND logic)
$ grep -E "my" /etc/passwd | grep -E "false"

mysql:x:116:120:MySQL Server,,:/nonexistent:/bin/false
```

> どちらの方法でも結果は同じです。`grep` を連結する方が読みやすく、`.*` の方が簡潔です。

## 5. RegEx のメタキャラクター: クイックリファレンス

メタキャラクターは、文字そのものではなく検索の構造を定義する正規表現の特殊記号です。

| メタキャラクター | 意味 | 例 |
|--------------|------|------|
| `.` | 任意の1文字(改行を除く) | `a.c` → `abc`, `a1c` |
| `*` | 直前の文字が0回以上 | `ab*` → `a`, `ab`, `abb` |
| `+` | 直前の文字が1回以上 | `ab+` → `ab`, `abb` |
| `?` | 直前の文字が0回か1回 | `ab?` → `a`, `ab` |
| `^` | 行の先頭 | `^root` |
| `$` | 行の末尾 | `bash$` |
| `[abc]` | リスト内のいずれか1文字 | `[abc]` → `a`, `b`, `c` のいずれか |
| `[^abc]` | リストにない文字 | `[^abc]` → a, b, c 以外の文字 |
| `[a-z]` | 小文字の a から z すべて | `[a-z]+` |
| `[0-9]` | 数字の 0 から 9 すべて | `[0-9]+` |
| `\d` | 数字(`[0-9]` と同じ) | `\d+` → `123` |
| `\w` | 単語文字(`[a-zA-Z0-9_]`) | `\w+` → `hello_123` |
| `\s` | 空白文字(スペース、タブ) | `\s+` |
| `{n}` | ちょうど n 回の繰り返し | `a{3}` → `aaa` |
| `{n,m}` | n 回以上 m 回以下の繰り返し | `a{2,4}` → `aa`, `aaa`, `aaaa` |
| `\` | エスケープ、次の文字をリテラルとして扱う | `\.` → リテラルなドット |

## 6. 練習問題: `/etc/ssh/sshd_config`

以下の演習では `/etc/ssh/sshd_config`、つまり Linux システム上の実際の SSH 設定ファイルを使います。このファイルはシステムセキュリティ監査でよく確認される対象なので、良い練習になります。

| # | タスク | 答え |
|---|-------|------|
| 1 | `#` 文字を含まないすべての行を表示する | 下記参照 |
| 2 | `Permit` で始まる単語を含むすべての行を検索する | 下記参照 |
| 3 | `Authentication` で終わる単語を含むすべての行を検索する | 下記参照 |
| 4 | `Key` という単語を含むすべての行を検索する | 下記参照 |
| 5 | `Password` で始まり `yes` を含むすべての行を検索する | 下記参照 |
| 6 | `yes` で終わるすべての行を検索する | 下記参照 |

### 解答

```bash
# Task 1 — Lines NOT containing "#"
grep -v "#" /etc/ssh/sshd_config

# Task 2 — Lines with a word STARTING with "Permit"
grep -E "Permit\w+" /etc/ssh/sshd_config

# Task 3 — Lines with a word ENDING with "Authentication"
grep -E "\w+Authentication" /etc/ssh/sshd_config

# Task 4 — Lines containing the word "Key"
grep "Key" /etc/ssh/sshd_config

# Task 5 — Lines BEGINNING with "Password" AND containing "yes"
grep -E "^Password.*yes" /etc/ssh/sshd_config

# Task 6 — Lines ENDING with "yes"
grep -E "yes$" /etc/ssh/sshd_config
```

### 解答の内訳

```
Task 1:  grep -v "#"
               │
               └── -v = invert match (exclude lines WITH #)

Task 2:  Permit\w+
         │      │
         │      └── \w+ = one or more word characters after "Permit"
         └── literal "Permit"

Task 3:  \w+Authentication
         │   │
         │   └── literal "Authentication" at the end
         └── \w+ = one or more word characters before it

Task 5:  ^Password.*yes
         │         │  │
         │         │  └── "yes" anywhere after
         │         └── .* = any characters in between
         └── ^ = must be at the START of line

Task 6:  yes$
         │  │
         │  └── $ = must be at the END of line
         └── literal "yes"
```

## 7. セキュリティノート: ReDoS、WAF バイパス、フォレンジック用正規表現

攻撃側・防御側どちらのサイバーセキュリティにおいても、正規表現は両刃の剣です。

1. 正規表現サービス拒否(ReDoS): `(a+)+$` や `([a-zA-Z0-9]+)*` のように、ネストされた量指定子や重複する選択肢を含む正規表現パターンは、NFA(非決定性有限オートマトン)ベースの正規表現エンジンで破滅的バックトラッキングを引き起こすことがあります。`aaaaaaaaaaaaaaaaaaaaaaaaaaaa!` のような入力を処理すると計算量が指数関数的($O(2^n)$)に増え、サーバーの CPU を固定してアプリケーションを止めてしまいます(『Mastering Regular Expressions』Friedl 参照)。
2. WAF・フィルター回避: 緩い入力検証用の正規表現は回避されることがあります。改行によるアンカー回避: マルチラインフラグなしの `^https?://.*` のようなパターンは、改行 `\n` を使って回避できます。大文字小文字の扱い: 正規表現が `-i` / `(?i)` を使っていなければ、攻撃者は大文字小文字を混ぜた表記(`<sCrIpt>`)で回避できます。不完全な選択肢: SQLi のキーワード `UNION SELECT` をブロックするブラックリストフィルターは、インラインコメント `UNION/**/SELECT` で回避できます。
3. フォレンジック用正規表現: 正規表現は SIEM の検知ルール、IDS/IPS のシグネチャ(Snort/Suricata)、マルウェアや情報持ち出しを検出する YARA ルールの基礎になっています。

```bash
# ── CYBERSECURITY REGEX PATTERNS CHEATSHEET ──────────────────

# 1. IPv4 Address Matching
grep -E -o '([0-9]{1,3}\.){3}[0-9]{1,3}' /var/log/auth.log

# 2. Extract Base64 Strings (length >= 32)
grep -E -o '[A-Za-z0-9+/]{32,}={0,2}' access.log

# 3. MD5 (32 hex) / SHA256 (64 hex) Hash Detection
grep -E -i '\b[a-f0-9]{32}\b' hashes.txt      # MD5
grep -E -i '\b[a-f0-9]{64}\b' hashes.txt      # SHA-256

# 4. Detect SQL Injection attempts in Web Server Access Logs
grep -E -i "(union.*select|select.*from|exec\(|insert.*into|drop.*table)" /var/log/apache2/access.log

# 5. Extract URLs from source text
grep -E -o 'https?://[a-zA-Z0-9./?=_-]+' input.txt
```

## `grep` + 正規表現フラグ一覧

| フラグ | 機能 |
|------|--------|
| `-E` | 拡張正規表現を有効化 |
| `-i` | 大文字小文字を区別しない検索 |
| `-v` | マッチを反転(パターンを除外) |
| `-n` | 行番号を表示 |
| `-r` | ディレクトリを再帰的に検索 |
| `-c` | 一致した行数を数える |
| `-o` | 一致した部分のみ表示 |

## クイックリファレンス

```bash
# Basic grep with regex
grep "pattern" file.txt               # literal search
grep -E "pattern" file.txt            # extended regex
grep -v "pattern" file.txt            # exclude pattern
grep -i "pattern" file.txt            # case insensitive

# OR / AND logic
grep -E "(one|two)" file.txt          # OR: contains "one" or "two"
grep -E "(one.*two)" file.txt         # AND: contains both in order
grep "one" file.txt | grep "two"      # AND: chained pipes

# Anchors
grep -E "^word" file.txt              # lines STARTING with "word"
grep -E "word$" file.txt              # lines ENDING with "word"

# Character classes
grep -E "[0-9]+" file.txt             # lines with digits
grep -E "[a-z]+" file.txt             # lines with lowercase letters
grep -E "\w+" file.txt                # lines with word characters

# Quantifiers
grep -E "a{3}" file.txt               # exactly 3 "a"s
grep -E "a{2,4}" file.txt             # 2 to 4 "a"s

# Practical sshd_config examples
grep -v "#" /etc/ssh/sshd_config              # no comments
grep -E "^Password.*yes" /etc/ssh/sshd_config # password + yes
grep -E "yes$" /etc/ssh/sshd_config           # ends with yes
grep -E "Permit\w+" /etc/ssh/sshd_config      # starts with Permit
```
