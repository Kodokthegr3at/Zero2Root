## 1. Linux ホストのネットワーキング — 層とオブジェクト

物理インタフェース、ブリッジ、VLAN、tun など、どのネットワークインタフェースも **リンク層の状態**、1つ以上の **IPアドレス**、そして出口ゲートウェイを決める **ルーティングテーブル** を持っています。

```text
app → socket → route lookup → interface → link
```

パケットがアプリケーションからソケットを経由し、ルート検索でどのインタフェースへ送るかが決まり、最後にリンク層に渡されるという流れです。現代の管理者は iproute2 に含まれる **`ip`** を使います。設定自体は **NetworkManager**、**systemd-networkd**、あるいは静的ファイル(Ubuntu の **netplan**、Debian の **`/etc/network/interfaces`**)のいずれかで管理されます。

```
┌──────────────────────────────────────────┐
│ Applications (curl, ssh, nginx)          │
├──────────────────────────────────────────┤
│ Sockets (TCP/UDP)                        │
├──────────────────────────────────────────┤
│ Routing table  ← ip route                │
├──────────────────────────────────────────┤
│ IP addresses   ← ip addr                 │
├──────────────────────────────────────────┤
│ Interfaces     ← ip link (eth0, wlan0)   │
└──────────────────────────────────────────┘
```

| オブジェクト | 表示 | 設定 |
|:---|:---|:---|
| インタフェース | `ip link` | `ip link set`, NM, netplan |
| IPv4/IPv6 | `ip addr` | `ip addr add`, DHCP |
| ルート | `ip route` | `ip route add`, default gw |
| DNS | `resolvectl`, `/etc/resolv.conf` | NM, resolved |

## 2. `ip` コマンド — リンク、アドレス、ルート

日常操作では **`ifconfig`/`route`** の代わりに **`ip`** を使います。`ip` による変更は基本的にランタイムのみ有効で、NetworkManager、netplan、interfaces のいずれかに永続化しない限り再起動で消えます。手動変更は必ず記録に残してください。

```bash
# Link layer — up/down, MTU, MAC
ip link show
ip link set eth0 up
ip link set eth0 mtu 1500

# Addresses
ip addr show dev eth0
ip addr add 10.10.14.50/24 dev eth0
ip addr del 10.10.14.50/24 dev eth0

# Routing
ip route show
ip route add default via 10.10.14.1 dev eth0
ip route add 192.168.100.0/24 via 10.10.14.254 dev eth0
ip route del 192.168.100.0/24

# Neighbor cache (ARP/NDP)
ip neigh show
```

| コマンド | 用途 |
|:---|:---|
| `ip -br a` | アドレスの簡易表示 |
| `ip -4 route get 8.8.8.8` | 宛先へのルート確認 |
| `ip link set eth0 down` | インタフェースを管理上ダウンにする |

カーネルは **最長プレフィックスマッチ(LPM)** によって最も詳細なルートを選びます。

宛先を含むすべての経路のうち、カーネルは最も具体的な、つまりプレフィックスが最も長い経路を選びます。

これは、宛先アドレス D に対してマッチするルーティングエントリ r の中から、プレフィックス長が最大のものを選ぶという意味です。より具体的なルートが常に優先されます。

## 3. 旧ツール — `ifconfig` と `route`

古いマシンや CTF の問題ではいまだに見かけます。**`net-tools`** パッケージに含まれており、自分が管理するシステムでは **`ip`** を優先してください。古いドキュメントや侵害済みホストを読むために構文は知っておくべきですが、新しい自動化スクリプトをこれらの非推奨ツールの上に構築するのはやめましょう。

```bash
ifconfig -a
ifconfig eth0 10.10.14.50 netmask 255.255.255.0 up
route -n
route add default gw 10.10.14.1
```

## 4. NetworkManager — `nmcli`

**NetworkManager**(`NetworkManager.service`)は、現代のデスクトップやサーバーで Wi-Fi、Ethernet、VPN を管理します。スクリプト化には **`nmcli`** を使います。接続プロファイルは `/etc/NetworkManager/system-connections/` に保存されており、root のみ読み取り可能です。パーミッションは厳しく保ってください。

```bash
nmcli device status
nmcli connection show
nmcli connection show "Wired connection 1"

# Static IPv4 example (lab)
nmcli con mod "Wired connection 1" \
  ipv4.method manual \
  ipv4.addresses 10.10.14.50/24 \
  ipv4.gateway 10.10.14.1 \
  ipv4.dns "10.10.14.1 1.1.1.1"
nmcli con up "Wired connection 1"

# Wi-Fi scan (authorized)
nmcli dev wifi list
nmcli dev wifi connect SSID password 'passphrase'
```

| サブコマンド | 用途 |
|:---|:---|
| `nmcli dev` | デバイスの状態 |
| `nmcli con` | 接続プロファイル |
| `nmcli networking off/on` | 全体のオンオフ切替 |

## 5. 宣言的設定 — netplan と `/etc/network/interfaces`

Ubuntu は **netplan**(YAML)を使い、旧来の Debian は **`/etc/network/interfaces`** を使います。どちらも再起動をまたいで永続化される点が、ランタイムのみの `ip` コマンドとの違いです。`netplan try` を使えば、YAML の記述ミスがあっても自動でロールバックされるので安全です。認証情報を誰でも読める YAML に書かないよう注意してください。

### Ubuntu netplan (`/etc/netplan/*.yaml`)

```yaml
# /etc/netplan/01-lab.yaml
network:
  version: 2
  ethernets:
    eth0:
      dhcp4: false
      addresses:
        - 10.10.14.50/24
      routes:
        - to: default
          via: 10.10.14.1
      nameservers:
        addresses: [10.10.14.1, 1.1.1.1]
```

```bash
sudo netplan try          # safe test with rollback
sudo netplan apply
```

### 旧来の Debian (`/etc/network/interfaces`)

```
auto eth0
iface eth0 inet static
    address 10.10.14.50
    netmask 255.255.255.0
    gateway 10.10.14.1
    dns-nameservers 10.10.14.1
```

```bash
sudo ifup eth0
sudo ifdown eth0
sudo systemctl restart networking   # distro-dependent
```

## 6. ホスト名とローカル名前表

**ホスト名** はそのホストの識別子であり、**`/etc/hosts`** はローカルで DNS を上書きします。一貫した命名規則は、ログの追跡、TLS 証明書の計画、資産管理のどれにも役立ちます。AD/LDAP 環境では名前の重複を避けてください。

```bash
hostname
hostnamectl status
sudo hostnamectl set-hostname srv01.lab.internal

cat /etc/hostname
cat /etc/hosts
```

## 7. セキュリティ上の注意点 — 防御と露出

セカンダリIP、サーバー上の Wi-Fi、設定ミスのある静的ルートは、想定外の通信経路を開いてしまうことがあります。IPv6 を有効なまま放置すると、IPv4 だけを対象にしたフィルタのバイパス経路になることがよくあります。

| 設定ミス | 影響 | 対策 |
|:---|:---|:---|
| `0.0.0.0` で待ち受けるサービスにセカンダリIP | 意図しないリスナーへのバインド | サービスを特定のIPにバインドする |
| サーバー上の弱い Wi-Fi 認証情報 | 横展開の侵入口になる | サーバーでは Wi-Fi を無効化し、有線で管理する |
| 攻撃者のゲートウェイを指す静的ルート | トラフィックの乗っ取り | ルート変更の統制と監視 |
| 外部からアクセス可能な NetworkManager の API | リモートからの再設定 | D-Bus のポリシーを localhost 限定にする |
| IPv4 だけフィルタし IPv6 を放置 | v6 経由のバイパス | デュアルスタック対応のファイアウォール(ノート27参照) |

```bash
# Defensive inventory
ip -br link
ip -br addr
ip route show table all | head
nmcli -f GENERAL.STATE,IP4.ADDRESS dev show
ss -tulnp | grep LISTEN
```

接続トラブルシューティングはノート25、DNS/DHCP サービスはノート19を参照してください。
