## 1. Linux上のネットワークサービス — デーモン層

ネットワークサービスとは、ソケット(TCP/UDP)を待ち受け、DNS、DHCP、NFS、SMB、SSH、HTTPなどのプロトコルを処理するデーモンです。Linux管理者は、誰がどのポートで listen しているか、設定がどこにあるかを把握しておく必要があります。

```text
client request --L3/L4--> listener (port) → daemon → config + data
```

Linuxホストはクライアントとサーバー両方の役割を同時に担うことがよくあります。クライアント設定は `/etc/resolv.conf`、NetworkManager、systemd-networkdにあり、サーバー役割は専用パッケージ(`bind9`、`isc-dhcp-server`、`nfs-kernel-server`、`samba`)を使います。

```
Application                Kernel network stack
     │                              │
     │                              │
  dig/curl/mount.nfs  ←→  socket bind :53/:445/:2049
                                    │
                                    ▼
                            named / smbd / nfsd
```

| サービス | デフォルトポート | パッケージ(Debian) | 設定の中心 |
|:---|:---:|:---|:---|
| DNSリゾルバ(クライアント) | なし | `systemd-resolved` | `/etc/resolv.conf`, `/etc/systemd/resolved.conf` |
| DNSサーバー | 53/tcp,udp | `bind9` | `/etc/bind/` |
| DHCPサーバー | 67/udp | `isc-dhcp-server` | `/etc/dhcp/dhcpd.conf` |
| NFS | 2049/tcp | `nfs-kernel-server` | `/etc/exports` |
| Samba(SMB) | 445/tcp | `samba` | `/etc/samba/smb.conf` |
| SSH | 22/tcp | `openssh-server` | `/etc/ssh/sshd_config` |

## 2. 名前解決 — DNSと `/etc/hosts`

外部DNSに問い合わせる前に、Linuxはまず静的な `/etc/hosts` を確認し、その後リゾルバ(通常は `systemd-resolved` または `/etc/resolv.conf`)に問い合わせます。

解決の順序はNSS(`/etc/nsswitch.conf`)で制御されます。

```text
gethostbyname → files (/etc/hosts) → dns → ...
```

解決状況の診断には `dig`、`host`、`resolvectl` を使います。DNSの設定を誤るとクエリが漏洩したり、信頼できないネットワークでスプーフィングを許してしまうため、信頼できるリゾルバを使い、ポリシーが求める場合はDNSSECを有効にします。

```bash
# Static local names (lab VMs you administer)
cat /etc/hosts
# 127.0.0.1   localhost
# 10.10.14.5  target.lab

# Resolver state
resolvectl status
cat /etc/resolv.conf

# Query DNS (authorized targets)
dig A example.com +short
dig MX example.com +short
host -t TXT example.com
nslookup example.com
```

| ファイル/ツール | 役割 |
|:---|:---|
| `/etc/hosts` | ホスト名からIPへの静的マッピング |
| `/etc/resolv.conf` | ネームサーバー一覧(しばしばsystemd-resolvedへのシンボリックリンク) |
| `/etc/systemd/resolved.conf` | スタブリスナー `127.0.0.53`、DNS over TLSのオプション |
| `dig` / `host` | 診断用クエリ |
| `systemd-resolved` | 現代的ディストロのキャッシュ付きスタブリゾルバ |

**BINDサーバーの最小構成(ラボ専用):**

```bash
sudo apt install bind9 -y
# /etc/bind/named.conf.local — zone definition for lab.internal
sudo named-checkconf
sudo systemctl reload bind9
dig @127.0.0.1 lab.internal SOA
```

## 3. DHCP — Dynamic Host Configuration

DHCPはIP、ゲートウェイ、DNS、その他のオプションをクライアントに割り当てます。Linuxのデスクトップやサーバーでは、クライアントは通常NetworkManagerか `dhclient` です。エッジでDHCPサーバーを稼働させるのはラボ環境以外では稀です。

クライアント側のリース生成サイクルは DISCOVER → OFFER → REQUEST → ACK の順に進みます。更新は T/2 のタイミングで行われます。LAN上の不正なDHCPサーバー(悪意あるゲートウェイやDNSを提示する攻撃者)を検出するため、サーバー側でリースを監視します。

```bash
# Client: view lease (NetworkManager)
nmcli dev show eth0 | grep -E 'IP4.ADDRESS|IP4.GATEWAY|IP4.DNS'

# Client: release / renew (legacy)
sudo dhclient -r eth0
sudo dhclient eth0

# Server config snippet (/etc/dhcp/dhcpd.conf) — lab
# subnet 10.10.14.0 netmask 255.255.255.0 {
#   range 10.10.14.100 10.10.14.200;
#   option routers 10.10.14.1;
#   option domain-name-servers 10.10.14.1;
# }
sudo systemctl enable --now isc-dhcp-server
```

| DHCPのリスク | 対策 |
|:---|:---|
| LAN上の不正DHCP | スイッチでのDHCPスヌーピング; 802.1X |
| 古いリース | 動的プールでのリース時間短縮 |
| ログがない | 権威サーバーで割り当てをログ記録 |

## 4. NFS — Network File System

NFSはカーネルクライアントを通じてリモートディレクトリをマウントします。サーバー側は `/etc/exports` にエクスポートを定義し、クライアント側は `mount -t nfs` を使います。

NFSv4は旧来のNFSv3(rpcbindと複数ポートが必要)に比べてポート構成が単純です(2049/tcpのみ)。強力な認証なしに誰でも書き込めるパスをエクスポートしてはいけません。本番環境ではKerberos(`sec=krb5p`)を推奨します。

```bash
# Server
sudo apt install nfs-kernel-server -y
echo '/srv/nfs/share 10.10.14.0/24(rw,sync,no_subtree_check)' | sudo tee -a /etc/exports
sudo exportfs -ra
sudo systemctl enable --now nfs-server
showmount -e localhost

# Client (authorized lab network)
sudo mkdir -p /mnt/nfs_share
sudo mount -t nfs 10.10.14.10:/srv/nfs/share /mnt/nfs_share
df -hT /mnt/nfs_share
# Persistent: add to /etc/fstab
# 10.10.14.10:/srv/nfs/share  /mnt/nfs_share  nfs  defaults  0  0
```

| エクスポートオプション | 意味 |
|:---|:---|
| `rw` / `ro` | 読み書き可 vs 読み取り専用 |
| `sync` | より安全; `async` は高速だがクラッシュ時のリスクが高い |
| `no_root_squash` | 危険、リモートのrootがローカルのrootにマッピングされる |
| `root_squash` | デフォルトの、より安全なマッピング |

## 5. Samba — SMB/CIFSファイル共有

Samba(`smbd`/`nmbd`)はWindowsのSMBプロトコルを提供し、LinuxがWindows/macOSにフォルダを共有したり、Windowsの共有をマウントしたりできるようにします。

共有の設定は `/etc/samba/smb.conf` で行います。Sambaユーザーには `smbpasswd` を使います(統合していない限りUnixパスワードとは別管理です)。再読込前には必ず `testparm` でテストします。

```bash
sudo apt install samba -y
sudo testparm -s

# Minimal share block in smb.conf:
# [shared]
#   path = /srv/samba/shared
#   browseable = yes
#   read only = no
#   valid users = alice

sudo smbpasswd -a alice
sudo systemctl enable --now smbd nmbd

# Client mount (authorized)
sudo mount -t cifs //10.10.14.10/shared /mnt/smb -o username=alice,uid=1000
smbclient -L //10.10.14.10 -U alice
```

| チェック項目 | コマンド |
|:---|:---|
| 設定の構文 | `testparm` |
| アクティブな共有 | `smbstatus` |
| 待受状態 | `ss -tlnp \| grep smbd` |

## 6. 待受中のネットワークサービスの監査

定期的な棚卸しとして、開いているポート、所有プロセス、関連するsystemdユニットを確認します。すべてのリスナーには明確な業務上の理由が必要です。各リスナーを実際の運用ニーズに対応付け、予期しない `0.0.0.0` へのバインドは優先度の高い発見として扱います。

```bash
# Modern socket audit
ss -tulnp
ss -tulnp | grep LISTEN

# Legacy (may be absent on minimal images)
netstat -tulnp 2>/dev/null

# Map to systemd units
systemctl list-units --type=service --state=running | grep -E 'ssh|nfs|samba|bind|apache|nginx'

# What owns port 445?
sudo lsof -i :445
sudo fuser -v 445/tcp
```

`0.0.0.0`(すべてのインターフェース)で待ち受けるサービスや、認証の弱いサービスが増えるほど、露出は大きくなります。

## 7. セキュリティノート — 防御とハードニング

ネットワークサービスは攻撃対象領域を広げます。基本方針は、必要がない限りインターネットに公開しない、export/shareの範囲を絞る、リスナーを定期的に監査する、の3点です。追加のデーモンはすべて追加の露出だと考えます。開放された再帰DNS、ゲスト共有、`no_root_squash` は影響の大きい典型的な誤設定です。

| 誤設定 | 影響 | 対策 |
|:---|:---|:---|
| NFS `no_root_squash` + 広いサブネット | リモートrootによるファイル書き込み | `root_squash`; exportを絞る; Kerberos |
| Sambaのゲスト書き込み許可 | 匿名でのマルウェア設置 | ゲストを無効化; 認証必須化 |
| インターネットへの再帰DNS開放 | 増幅攻撃への悪用 | 再帰を許可リストのみに限定 |
| 不正DHCP | ゲートウェイ/DNSのMITM | DHCPスヌーピング; サーバーでは静的設定 |
| 古い `/etc/hosts` の上書き | 内部アプリへの誤ったルーティング | 構成管理の徹底 |
| 信頼できないLAN上の暗号化なしNFSv3 | データの盗聴 | NFSv4 + Kerberos、またはVPN |

```bash
# Defensive audit (authorized admin)
grep -v '^#' /etc/exports 2>/dev/null
testparm -s 2>/dev/null | head -30
ss -tulnp | awk 'NR==1 || /0.0.0.0|:::/'
resolvectl dns
```

参照: ホストファイアウォールのルールはノート27、インターフェース設定はノート24〜25を参照してください。
