## 重要な用語

この教材でよく出てくる言葉である。

| 用語 | 意味 |
|:---|:---|
| バックアップ | 失ったときに復元できるよう保管しておくデータのコピー |
| リストア | バックアップからデータを戻すこと(テストを忘れがちな部分) |
| フル / 増分 | 完全なコピー / 前回からの変更分だけ |
| RPO / RTO | どれだけデータを失ってよいか / どれだけ早く復旧すべきか |
| `tar` / `rsync` | ファイルをアーカイブにまとめる / 変更分を効率よく同期する |
| 3-2-1ルール | コピー3つ、メディア2種類、1つは別の場所 |
| スナップショット | ある時点でのファイルシステムの凍結した見え方 |

## 1. バックアップの目的 — なぜ管理者はアーカイブするのか

バックアップは破損、ランサムウェア、人的ミスの後の可用性と完全性を支えます。

```text
RPO = 失っても許容できるデータの最大量      (例:「最大1時間分の作業」)
RTO = 停止していても許容できる最大時間    (例:「4時間以内に復旧」)
```

復元テストなしのバックアップは単なる仮定にすぎません。良いバックアップはRecovery Point Objective(RPO)とRecovery Time Objective(RTO)、そしてオフラインコピーの暗号学的な整合性で測られます。

```
  Live system                 Backup store
 ┌──────────┐   tar/rsync    ┌────────────┐
 │  Data    │ ─────────────► │ Encrypted  │
 │  Config  │                │ offline /  │
 │  DB dump │ ◄───────────── │ offsite    │
 └──────────┘   restore test └────────────┘
```

| 種類 | 説明 | 代表的なツール |
|:---|:---|:---|
| フル | 完全なコピー | `tar`、イメージング |
| インクリメンタル | 前回バックアップ以降の変更分 | `rsync`、borg、restic |
| 差分 | 前回フル以降の変更分 | 各種 |
| スナップショット | 特定時点のFS/ボリューム | LVM、ZFS、btrfs |

## 2. `tar` によるアーカイブ

`tar`(tape archive)は複数のパスを一つのストリームまたはファイルにまとめます。

| フラグ | 意味 |
|:---|:---|
| `-c` | 作成 |
| `-x` | 展開 |
| `-t` | 一覧表示 |
| `-v` | 詳細表示 |
| `-f` | アーカイブファイル名 |
| `-C` | 展開時のディレクトリ変更 |
| `-p` | パーミッション保持(root権限時) |

特権cronジョブでは、引用符なしのglobよりも明示的なファイルリストを優先してください(セキュリティノート参照)。

```bash
# Create / list / extract
tar -cvf etc_backup.tar /etc/
tar -tvf etc_backup.tar
tar -xvf etc_backup.tar -C /tmp/restore/

# Exclude patterns
tar -czvf home.tgz /home/alice --exclude='*/.cache/*'
```

**作成後の整合性確認:**

アーカイブのSHA-256ハッシュを計算し、バックアップ本体とは別の場所に保存しておきます。そうすれば、後でバックアップが変更されていないことを証明できます。

```bash
sha256sum backup.tar.gz | tee backup.tar.gz.sha256
```

## 3. 圧縮形式

| 形式 | `tar` フラグ | 拡張子 | トレードオフ |
|:---|:---:|:---|:---|
| gzip | `-z` | `.tar.gz` / `.tgz` | 高速、最も普及 |
| bzip2 | `-j` | `.tar.bz2` | 圧縮率は高いが遅い |
| xz | `-J` | `.tar.xz` | 最高の圧縮率、CPU負荷が大きい |
| zstd | `--zstd` | `.tar.zst` | 現代的な速度と圧縮率のバランス(新しいtarで利用可) |

```bash
tar -czvf data.tar.gz /var/www/html/
tar -cjvf data.tar.bz2 /var/www/html/
tar -cJvf data.tar.xz /var/www/html/
tar -xvf data.tar.gz          # auto-detect on GNU tar often works
```

相対的な圧縮率の目安:

```text
xz  ≤  bz2  ≤  gzip  ≤  無圧縮            (典型的な出力サイズ、小さい順)
```

(実際の比率はデータのエントロピーに依存します。)

## 4. `rsync` — インクリメンタル同期

`rsync` は変更されたブロックの差分だけを転送するため、定期バックアップに効率的です。

| フラグ | 意味 |
|:---|:---|
| `-a` | アーカイブ(パーミッション、タイムスタンプ、シンボリックリンク、再帰) |
| `-v` | 詳細表示 |
| `-z` | 転送中の圧縮 |
| `-P` | 進捗表示 + 部分再開 |
| `-e ssh` | SSHトランスポート |
| `--delete` | 削除をミラーする(方向を誤ると危険) |
| `-n` / `--dry-run` | シミュレーション |

`--delete` の前には必ず `--dry-run` を実行してください。末尾のスラッシュは重要で、`src/` は内容をコピーしますが、`src` はネストの結果が変わることがあります。

```bash
# Local
rsync -avzP /home/alice/documents/ /backup/alice/documents/

# Remote over SSH
rsync -avzP -e ssh /var/www/html/ backup@192.168.1.50:/remote/html/

# Safe mirror rehearsal
rsync -avzn --delete /data/ /backup/data/
```

差分の考え方をひと言でいうと:

rsyncは、ファイル全体ではなく、送信元と送信先で異なる部分だけを送ります。

## 5. `scp` / `sftp` — SSH経由のコピー

`scp` / `sftp` はSSHの認証と暗号化を使います。単発のコピーに向いており、繰り返す同期には `rsync` やborg/resticのような専用ツールを推奨します。

鍵ベースのSSHと制限されたバックアップアカウント(`ForceCommand`、強制chroot、パスを限定した専用鍵)を優先してください。

```bash
scp backup.tar.gz.gpg backup@server:/backups/
scp -r backup@server:/backups/2026-08-16/ ./restore-staging/
sftp backup@server
```

## 6. GnuPGによるバックアップの暗号化

アーカイブにはDBダンプ、鍵、設定ファイルなどの機密情報がしばしば含まれます。保管時に暗号化しましょう。

```text
c = Enc(k, m)      暗号化
m = Dec(k, c)      復号
```

k はパスフレーズ(対称鍵)、またはバックアップ受信者の公開鍵から導出します。

単純なオフラインディスクにはAES-256の対称暗号化を使い、バックアップチームの公開鍵への非対称暗号化を使えば、運用者が一つのパスフレーズを共有せずに済みます。

```bash
gpg --symmetric --cipher-algo AES256 backup.tar.gz
gpg --output backup.tar.gz --decrypt backup.tar.gz.gpg

# Asymmetric (recipient pubkey already imported)
gpg --encrypt --recipient backups@example.com backup.tar.gz
```

パスフレーズや秘密鍵はパスワードマネージャー、HSM、封印した封筒などに保管し、同じUSBメモリ上で暗号文の隣に置かないでください。

## 7. 戦略 — 3-2-1ルールと復元訓練

### 3-2-1ルール
```text
3  つのデータのコピー
2  種類の異なる保存メディア
1  つはオフサイト / オフラインに置く
```

| プラクティス | 詳細 |
|:---|:---|
| カタログ | 何をバックアップするか、スケジュール、所有者 |
| 暗号化 | 保管時 + 転送時(SSH/TLS) |
| 保持期間 | 法令・コンプライアンス要件を満たす |
| 復元テスト | 重要システムでは最低四半期ごと |
| アクセス制御 | バックアップアカウントは対話的な管理者権限にしない |
| 不変性 | ランサムウェアが懸念される場合はWORM/オブジェクトロック |

```
Weekly drill (sketch)
─────────────────────
1. Pick random file set from catalog
2. Restore to isolated staging host
3. Verify checksums / app smoke test
4. Record RTO observed vs target
5. Fix gaps; update runbook
```

## 8. セキュリティノート — 防御とハードニング

| リスク | 理由 | 対策 |
|:---|:---|:---|
| 暗号化されていないバックアップ | ディスク盗難がそのままデータ侵害になる | `gpg`/age/restic による暗号化; ストレージの施錠 |
| Webルート内のバックアップ | ダンプが公開ダウンロード可能になる | docroot配下に保存しない; 別ボリュームを使う |
| 誰でも読める `/var/backups` | ローカルユーザーデータの漏洩 | `750`/`640`、`backup` グループ |
| 特権cron + 書き込み可能ディレクトリでの `tar *` | 細工されたファイル名による引数インジェクション | 明示的なファイルリスト; `find … -print0` + `--files-from`; ロックされたディレクトリから実行 |
| `rsync --delete` の方向間違い | 正常なコピーの壊滅的な消失 | dry-run; pullモデル; 削除前のスナップショット |
| 認証なしの公開rsyncデーモン(873) | データの窃取や上書き | SSHを優先; 認証; ファイアウォール |
| オンラインコピーが一つだけ | ランサムウェアがバックアップも暗号化してしまう | オフライン/不変/オフサイトのコピー |
| 復元テストがない | 誤った安心感 | 定期的な訓練 + チェックサム |

### 安全な `tar` cronパターン(概念)
推奨:

```bash
# Explicit paths — no shell glob controlled by untrusted dirs
tar -czf /var/backups/etc-$(date +%F).tar.gz -C / etc
chmod 600 /var/backups/etc-*.tar.gz
```

誰でも書き込めるツリーに `cd` して `tar … *` を実行するような特権ジョブは避けてください。

### バックアップアカウントのハードニング
- 専用ユーザーとし、不要なシェルツールを持たせない。
- SSH鍵を制限する(`command=`、`from=`)。
- ネットワークセグメントやファイアウォールの許可リストを分離する。
- SSH失敗や予期しない復元先ホストを監視する。

```bash
# Permissions audit (admin)
namei -l /var/backups
find /var/backups -type f -perm -o=r -ls
```

## 9. クイックリファレンスチートシート

```bash
# tar
tar -czvf backup.tar.gz /path
tar -tvf backup.tar.gz
tar -xvf backup.tar.gz -C /restore/
sha256sum backup.tar.gz

# rsync
rsync -avzP /src/ /dst/
rsync -avzn --delete /src/ /dst/     # dry-run mirror
rsync -avzP -e ssh /src/ user@host:/dst/

# scp
scp file.gpg user@host:/backups/

# gpg
gpg -c --cipher-algo AES256 backup.tar.gz
gpg -d backup.tar.gz.gpg > backup.tar.gz
```
