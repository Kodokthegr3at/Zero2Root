## 1. Linux とは何か

Linux は Windows、macOS、iOS、Android と同じくオペレーティングシステム（OS）の一つです。OS とは、コンピュータのすべてのハードウェアリソースを管理し、アプリケーションとハードウェアの間の通信を仲立ちするソフトウェアを指します。

Linux が他の OS と違うのは、多数のディストリビューション（ディストロ）として提供される点です。ディストロとは、用途に合わせて調整された Linux の派生版のことです。Linux がサイバーセキュリティの分野で重要視される理由はいくつかあります。

- 無料かつオープンソースで、誰でもソースコードを改変できる。
- 他の OS に比べてマルウェアの被害を受けにくい。
- 安定していて、パフォーマンスも高い。
- サーバー、メインフレーム、ルーター、スマートTV、ゲーム機、そして Android にまで使われている。

### よく使われる Linux ディストリビューション

| ディストロ | 特徴 | 向いている用途 |
|-----------|------|----------------|
| Ubuntu | 使いやすさ重視 | 初心者、デスクトップ用途 |
| Debian | 安定性重視 | サーバー、開発 |
| Parrot OS | セキュリティとプライバシー重視 | ペンテスト、CTF |
| Kali Linux | 攻撃的セキュリティ向け | 侵入テスト |
| Fedora | 最新技術の採用 | 開発者 |
| Arch Linux | 高いカスタマイズ性 | 上級ユーザー |
| CentOS / RHEL | エンタープライズ向け | 本番サーバー |
| Manjaro | 使いやすさ | デスクトップユーザー |

補足: HackTheBox Academy では Parrot OS（Pwnbox）が使われている。これはセキュリティ、プライバシー、開発に重点を置いた Debian ベースのディストロである。

## 2. Linux の歴史

Linux は突然生まれたわけではない。その誕生までには長い出来事の連鎖があり、Linux の多くの概念はさらに古い Unix の哲学に根ざしているため、この歴史を理解しておく意味がある。

### 年表

```
1970  ── Unix OS released by Ken Thompson & Dennis Ritchie (AT&T)
  │
1977  ── BSD (Berkeley Software Distribution) released
  │        └── AT&T lawsuit limits BSD development
  │
1983  ── Richard Stallman starts the GNU Project
  │        └── Goal: create a free Unix-like OS
  │        └── GNU General Public License (GPL) created
  │
1991  ── Linus Torvalds (Finnish student) starts Linux kernel
  │        └── Goal: new, free OS kernel
  │        └── Written in C, originally prohibited commercial use
  │
Now   ── Linux kernel: 23+ million lines of code
           Licensed under GNU GPL v2
           600+ distributions available
           Powers most of the internet's servers
           Android (Linux-based) = most installed OS worldwide
```

| 年 | 出来事 |
|----|--------|
| 1970年 | Ken Thompson と Dennis Ritchie（AT&T）が Unix を発表 |
| 1977年 | BSD が公開されるが、AT&T の訴訟により開発が制限される |
| 1983年 | Richard Stallman が GNU プロジェクトを開始 |
| 1989年 | GNU General Public License（GPL）が作成される |
| 1991年 | 当時21歳だった Linus Torvalds が Linux カーネルを作成 |
| 現在 | 2300万行以上のコード、600以上のディストロ、世界で最も多くインストールされている OS |

Unix は AT&T のベル研究所で Ken Thompson と Dennis Ritchie によって開発された。その後 1977年に BSD（Berkeley Software Distribution）が公開されたが、AT&T の訴訟によって開発の自由度が制限された。1983年、Richard Stallman は自由に使える Unix 互換 OS を作ることを目指して GNU プロジェクトを立ち上げ、GNU GPL というライセンスを整備した。1991年、フィンランドの学生だった Linus Torvalds が C言語で新しいカーネルの開発を始めた。これが Linux カーネルである。当初は商用利用が禁止されていたが、現在では GNU GPL v2 の下でライセンスされ、2300万行を超えるコードベースを持ち、600以上のディストロが存在し、インターネットのサーバーの大部分を支え、Linux ベースの Android は世界で最も多くインストールされている OS になっている。

## 3. Linux の哲学

Linux の哲学は、シンプルさ、モジュール性、オープン性を中心にしている。Linux は、一つのことを非常にうまくこなす小さなプログラムを作り、それらを組み合わせて複雑な処理を実現するという考え方を推奨する。

### 5つの基本原則

| # | 原則 | 説明 |
|---|------|------|
| 1 | すべてはファイルである | ハードウェア、プロセス、ネットワーク接続などすべてのシステムリソースがファイルとして表現され、同じ標準ツールで読み書きできる |
| 2 | 単機能で小さいプログラム | Linux は、それぞれが一つのことを非常にうまくこなす小さなツールを数多く提供する |
| 3 | プログラムを連結できる | 小さなプログラムをパイプでつなぎ合わせることで、大きく複雑なタスクをこなせる |
| 4 | 閉じたユーザーインターフェースを避ける | Linux は主にシェル/ターミナルで操作するよう設計されており、ユーザーに OS の完全な制御権を与える |
| 5 | 設定はテキストファイルで行う | 設定データはテキストファイルに保存される。例えば `/etc/passwd` にはすべての登録ユーザーが記録されている |

これらの原則があるからこそ、Linux はサイバーセキュリティの分野で強みを発揮する。すべてが透明で、スクリプトで自動化でき、組み合わせて使うことができるからだ。

## 4. Linux のコンポーネント

Linux は、システムを動かすために連携して働くいくつかの主要なコンポーネントで構成されている。

| コンポーネント | 説明 |
|---------------|------|
| ブートローダー | OS を起動するブートプロセスを導くコード。Parrot Linux は GRUB ブートローダーを使用する |
| OS カーネル | ハードウェアレベルで I/O デバイスのリソースを管理する OS の中核コンポーネント |
| デーモン | スケジューリング、印刷、マルチメディアなどの機能が正しく動作するよう保つバックグラウンドサービス |
| OS シェル | OS とユーザーの間のインターフェース。ユーザーはここから OS にコマンドを送る。よく使われるシェルには Bash、Zsh、Fish、Ksh がある |
| グラフィックスサーバー | グラフィカルなプログラムをローカルまたはリモートで動かせるようにするグラフィカルサブシステム（"X" / Xサーバー） |
| ウィンドウマネージャー | GNOME、KDE、MATE、Unity、Cinnamon などの GUI デスクトップ環境。ファイルブラウザや Web ブラウザも含む |
| ユーティリティ | ユーザーや他のプログラムのために特定の機能を実行するアプリケーション群 |

## 5. Linux のアーキテクチャ

Linux OS は、下から上へ互いに通信し合う4つの層に分けて考えられる。

```
┌─────────────────────────────────────────────────────┐
│                  SYSTEM UTILITY                      │
│   Makes all OS functionality available to the user   │
│   (commands, programs, libraries, man pages)         │
├─────────────────────────────────────────────────────┤
│                     SHELL                            │
│   Command-line interface (CLI) — user enters         │
│   commands to interact with the kernel               │
│   Bash / Zsh / Fish / Ksh                            │
├─────────────────────────────────────────────────────┤
│                     KERNEL                           │
│   Core of Linux — virtualizes and controls hardware  │
│   CPU, RAM, I/O, process management                  │
│   Gives each process its own virtual resources       │
├─────────────────────────────────────────────────────┤
│                    HARDWARE                          │
│   Physical components: CPU, RAM, HDD/SSD,            │
│   Network card, GPU, peripherals                     │
└─────────────────────────────────────────────────────┘
          ↕ each layer communicates with adjacent layers
```

| 層 | 説明 |
|----|------|
| ハードウェア | RAM、HDD、CPU などの物理デバイス |
| カーネル | Linux の中核。ハードウェアリソースを仮想化・制御し、各プロセスに独自の仮想リソースを与える |
| シェル | CLI（コマンドラインインターフェース）。ユーザーはここからコマンドを入力し、カーネルの機能を実行する |
| システムユーティリティ | OS のすべての機能をユーザーが使えるようにする層 |

最下層のハードウェアは CPU、RAM、ストレージ、周辺機器などの物理部品を指す。その上のカーネルは Linux の中核であり、ハードウェアリソースを仮想化・制御して、プロセスごとに独立した仮想リソースを割り当てる。さらにその上のシェルは、ユーザーがコマンドを入力してカーネルの機能を呼び出すための CLI である。一番上のシステムユーティリティ層は、コマンド、プログラム、ライブラリ、man ページなど、OS のあらゆる機能をユーザーが利用できる形で提供する。

## 6. ファイルシステム階層標準（FHS）

Linux は、Filesystem Hierarchy Standard（FHS）に定義されたツリー状のディレクトリ構造を採用している。すべてのディレクトリはルート `/` から始まり、木の幹から枝分かれするように下に伸びていく。

### ディレクトリツリー

```
/ (root)
├── bin/      ← essential command binaries
├── boot/     ← bootloader, kernel
├── dev/      ← device files (hardware access)
├── etc/      ← system config files
├── home/     ← user home directories
│   └── cry0l1t3/
├── lib/      ← shared libraries for boot
├── media/    ← removable media (USB, CD)
├── mnt/      ← temporary mount points
├── opt/      ← optional / third-party software
├── proc/     ← virtual filesystem (process info)
├── root/     ← root user's home directory
├── run/      ← runtime data (PIDs, sockets)
├── sbin/     ← system admin binaries
├── sys/      ← virtual filesystem (kernel/device info)
├── tmp/      ← temporary files (cleared on boot)
├── usr/      ← user programs, libraries, man pages
└── var/      ← variable data (logs, mail, web files)
```

### ディレクトリ一覧表

| パス | 説明 |
|------|------|
| `/` | ルートディレクトリ。OS の起動に必要なすべてのファイルを含む |
| `/bin` | 基本コマンドのバイナリ（ls、cp、mv、cat など） |
| `/boot` | 静的なブートローダー、カーネル実行ファイル、起動用ファイル |
| `/dev` | ハードウェアアクセス用のデバイスファイル（ディスク、USB など） |
| `/etc` | ローカルシステムおよびアプリケーションの設定ファイル |
| `/home` | システムの各ユーザーのホームディレクトリ |
| `/lib` | システム起動に必要な共有ライブラリ |
| `/media` | 外部のリムーバブルメディア（USBドライブ、CD） |
| `/mnt` | 通常のファイルシステムを一時的にマウントする場所 |
| `/opt` | オプションのサードパーティ製ソフトウェア |
| `/root` | root ユーザーのホームディレクトリ |
| `/sbin` | システム管理用の実行ファイル |
| `/tmp` | 一時ファイル。再起動時に消去される |
| `/usr` | ユーザープログラム、ライブラリ、man ページ |
| `/var` | ログ、メール、Webファイル、cron などの可変データ |

### ペンテストで注目すべきディレクトリ

| パス | ペンテストにおける意味 |
|------|------------------------|
| `/etc/passwd` | システムの全ユーザーの一覧 |
| `/etc/shadow` | ユーザーのパスワードハッシュ（root権限が必要） |
| `/etc/crontab` | スケジュールされたジョブ。権限昇格の糸口になり得る |
| `/tmp` | 全ユーザーが書き込み可能。エクスプロイトのステージング場所としてよく使われる |
| `/var/log` | システムログ。ユーザーの活動や攻撃の痕跡が残る |
| `/home` | SSH鍵、認証情報、設定ファイルが含まれていることがある |
| `/root` | root のホームディレクトリ。権限昇格の標的になりやすい |
| `/dev` | デバイスファイル。例: `/dev/null`、`/dev/shm`（RAMベースの一時ストレージ） |

## クイックリファレンス・チートシート

```bash
# Check Linux version and distro
uname -a                    # kernel version
cat /etc/os-release         # distro information
lsb_release -a              # distro details

# Explore filesystem hierarchy
ls /                        # list root directory
ls /etc/                    # system config files
ls /home/                   # user home directories
ls /var/log/                # system log files
cat /etc/passwd             # list all users
cat /etc/os-release         # current distro info

# Check shell in use
echo $SHELL                 # current shell path
cat /etc/shells             # all available shells
```
