## 1. Linuxのストレージ階層 — ディスクからディレクトリツリーへ

データはブロックデバイス(ディスク、LV、ループ)に保存され、ファイルシステムでフォーマットされた後、単一のディレクトリツリー(`/`)内のディレクトリにマウントされます。

```text
hardware → partition / LV --mkfs--> filesystem --mount--> /mountpoint
```

管理者はトポロジー確認に `lsblk`、UUIDや種別の確認に `blkid`、起動時の永続化に `/etc/fstab` を使います。fstabの記述を誤ると起動できなくなることがあるため、必ず `mount -a` でテストします。

```
/dev/nvme0n1
 ├─ nvme0n1p1  →  /boot/efi   (vfat)
 ├─ nvme0n1p2  →  /boot       (ext4)
 └─ nvme0n1p3  →  LVM PV
                      ├─ vg0-root → /       (ext4)
                      ├─ vg0-home → /home  (ext4)
                      └─ vg0-swap → [swap]
```

| 層 | ツール | 主なファイル |
|:---|:---|:---|
| 検出 | `lsblk`, `fdisk -l`, `parted -l` | `/dev/*` |
| フォーマット | `mkfs.ext4`, `mkfs.xfs`, `mkswap` | FSスーパーブロック |
| マウント | `mount`, `umount`, `findmnt` | `/etc/fstab`, `/proc/mounts` |
| LVM | `pvcreate`, `vgcreate`, `lvcreate` | `/etc/lvm/` のメタデータ |

## 2. パーティション分割 — MBR、GPT、`fdisk`、`parted`

現行のディスクはGPT(GUID Partition Table)を使います。レガシーなMBRは古いVMでまだ見られます。`fdisk`(対話式)と `parted`(スクリプト対応)が標準ツールです。

破壊的な操作の前には必ずデバイス名(`/dev/sdb` か `/dev/sda` か)を確認します。パーティションテーブルを変更した後は `partprobe` を実行するか再起動します。

```bash
# Topology
lsblk -f
sudo fdisk -l
sudo parted -l

# GPT partition with parted (example — DESTRUCTIVE on wrong disk)
sudo parted /dev/sdb --script mklabel gpt
sudo parted /dev/sdb --script mkpart primary ext4 1MiB 100%
sudo partprobe /dev/sdb

# Interactive fdisk
sudo fdisk /dev/sdb    # n=new, p=print, w=write, q=quit
```

| 方式 | 最大パーティション数 | ブートファームウェア | 備考 |
|:---:|:---:|:---|:---|
| MBR | 基本4個(+拡張) | BIOS | レガシー |
| GPT | 非常に多い | UEFI | 現在推奨 |

## 3. ファイルシステムの種類 — ext4、XFS、swap

ワークロードに応じてFSを選びます。ext4は汎用、XFSは大きなファイルやRHELのデフォルト、vfatはESP用、swapは仮想メモリ用です。

| FS | 典型的な用途 | 作成コマンド |
|:---|:---|:---|
| ext4 | 汎用のroot/home | `mkfs.ext4` |
| XFS | 大きなファイル / RHELデフォルト | `mkfs.xfs` |
| vfat | EFIシステムパーティション | `mkfs.vfat -F 32` |
| swap | 仮想メモリ/ハイバネーション | `mkswap` |

fstab用にラベルまたはUUIDを控えておきます。デバイス名(`/dev/sda1`)はハードウェア変更後に番号が入れ替わることがあります。

```bash
sudo mkfs.ext4 -L datavol /dev/sdb1
sudo mkfs.xfs /dev/vg0/lv_data
sudo mkswap /dev/vg0/lv_swap
sudo swapon /dev/vg0/lv_swap

blkid
lsblk -f
```

## 4. マウント、アンマウント、`/etc/fstab`

`mount` はファイルシステムを空のディレクトリに接続します。`/etc/fstab` は起動時の自動マウントを定義します。

fstabの書式:

```text
device             mountpoint   type   options            dump   fsck
UUID=1234-abcd     /data        ext4   defaults,nofail    0      2
```

サーバー上の重要でないリムーバブルメディアには `nofail` を使います。`/dev/sdX` より `UUID=` を使います。fstabを編集したら毎回 `sudo mount -a` でテストします。

```bash
# Manual mount
sudo mkdir -p /mnt/data
sudo mount /dev/sdb1 /mnt/data
findmnt /mnt/data
mount | grep /mnt/data

# Umount (busy → stop processes using path)
sudo umount /mnt/data
sudo fuser -vm /mnt/data

# /etc/fstab example
# UUID=abc-123-def   /mnt/data   ext4   defaults,nofail   0   2
sudo mount -a          # apply fstab without reboot
```

| マウントオプション | 効果 |
|:---|:---|
| `defaults` | rw, suid, dev, exec, auto, nouser, async |
| `noexec` | マウント上での実行を禁止(アップロード用ディレクトリ) |
| `nosuid` | FS上のsetuidビットを無視 |
| `nodev` | FS上のデバイスファイルを無視 |
| `ro` | 読み取り専用 |
| `nofail` | マウント失敗時も起動を継続 |

## 5. LVM — 論理ボリュームマネージャ

LVMはパーティションの上位にある抽象化層です。

```text
PV (Physical Volume)  →  VG (Volume Group)  →  LV (Logical Volume)
```

利点は、オンラインでのリサイズ、スナップショット、ストライピング(上級者向け)です。

作業の流れ: パーティションタイプを `8e`(MBR)またはGPTの `8300`(Linux LVM)に設定し、`pvcreate` → `vgcreate` → `lvcreate` → `mkfs` → マウントの順で進めます。

```bash
# Create stack (lab disk /dev/sdb1 prepared)
sudo pvcreate /dev/sdb1
sudo vgcreate vg_data /dev/sdb1
sudo lvcreate -L 50G -n lv_archive vg_data
sudo mkfs.ext4 /dev/vg_data/lv_archive
sudo mkdir -p /archive
echo '/dev/vg_data/lv_archive  /archive  ext4  defaults  0  2' | sudo tee -a /etc/fstab
sudo mount -a

# Extend LV + filesystem (ext4)
sudo lvextend -L +20G /dev/vg_data/lv_archive
sudo resize2fs /dev/vg_data/lv_archive

# Inspect
pvs; vgs; lvs
sudo lvdisplay
```

| コマンド | 目的 |
|:---|:---|
| `pvcreate` | パーティションをPVとして初期化 |
| `vgcreate` | PVをまとめてVGにする |
| `lvcreate` | VGからLVを割り当てる |
| `lvextend` / `lvreduce` | LVをリサイズする |
| `resize2fs` / `xfs_growfs` | LVに合わせてFSを拡張する |

## 6. 容量、使用状況、整合性

`df -hT` はマウントごとの空き容量を表示します。`du -sh` はディレクトリのサイズを表示します。`fsck` はファイルシステムの検査と修復を行います。root以外は先にアンマウントし、rootファイルシステムは慎重な扱いが必要です。

メール/キャッシュサーバーではinodeの枯渇(`df -i`)を監視します。ファイルシステムチェックはfstabのpassフィールドかsystemdタイマーでスケジュールします。

```bash
df -hT
df -i
du -sh /var/log/* 2>/dev/null | sort -h | tail

# Offline check (FS must be unmounted)
sudo umount /dev/sdb1
sudo fsck -f /dev/sdb1

# Find large files quickly
sudo find /var -xdev -type f -size +100M -ls 2>/dev/null | head
```

## 7. セキュリティノート — 防御と権限昇格の経路

マウントオプション(`noexec`、`nosuid`、`nodev`)は装飾ではなくセキュリティ制御です。アップロード用ディレクトリとネットワーク共有は厳しく制限する必要があります。

`exec` が有効な誰でも書き込めるマウントは、典型的なwebshell設置経路です。`/etc/fstab` はroot所有の `644` に保ち、リモートのNFS/SMBコンテンツはローカルと同等には信頼しません。

| リスク | メカニズム | 対策 |
|:---|:---|:---|
| 誰でも書き込め`exec`可のマウント | `/mnt/uploads` へのwebshell設置 | `noexec,nosuid,nodev` |
| rootでのNFS/SMBマウント | リモートコンテンツをローカル同様に信頼してしまう | `nosuid,nodev`; ネットワークACL |
| ユーザーが書き込める `/etc/fstab` | 起動時のroot権限侵害 | root所有の `644`; 構成管理 |
| ディスクフル | ログ/キャッシュ肥大によるDoS | クォータ; logrotate; `df` でのアラート |
| LVMスナップショットの悪用(管理者側) | 機密データのフォレンジックコピー | LVMコマンドへのRBAC |

```bash
# Defensive mount audit
findmnt -lo TARGET,OPTIONS,SOURCE
grep -v '^#' /etc/fstab
mount | grep -E 'nosuid|noexec'
```

参照: ブロックデバイスのバックアップはノート21、コンテナボリュームはノート23を参照してください。

## 8. クイックリファレンスチートシート

```bash
# Discovery
lsblk -f
blkid
sudo fdisk -l

# Format & swap
sudo mkfs.ext4 /dev/sdb1
sudo mkswap /dev/sdb2 && sudo swapon /dev/sdb2

# Mount
sudo mount /dev/sdb1 /mnt/data
sudo umount /mnt/data
sudo mount -a

# LVM
sudo pvcreate /dev/sdb1
sudo vgcreate vg0 /dev/sdb1
sudo lvcreate -L 10G -n lv0 vg0
pvs && vgs && lvs

# Space
df -hT
du -sh /path
```
