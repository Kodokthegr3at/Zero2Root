## 重要な用語

この教材でよく出てくる言葉である。

| 用語 | 意味 |
|:---|:---|
| `which` | あるコマンド名で実際にどのプログラムが走るかを表示する |
| `whereis` | コマンドのバイナリ、ソース、manページを探す |
| `locate` | 作成済みのファイル名インデックスを検索する(非常に速い) |
| `updatedb` | `locate` が使うインデックスを更新する |
| `find` | 名前、サイズ、時刻、種類などで、実際のファイルシステムを検索する |
| 式(find) | `find` に渡す条件。`-name` や `-mtime` など |
| `-exec` | `find` が一致させた各ファイルに対してコマンドを実行する |

## 1. `which`

`which` は実行可能なプログラムのパスを検索するコマンドです。`curl`、`netcat`、`wget`、`python`、`gcc` のようなツールがシステムに存在するかどうかを確認したいときに便利です。プログラムが見つからない場合、何も出力されません。

```bash
# Check if Python is installed and where
$ which python
/usr/bin/python

# Check multiple tools at once
$ which curl wget netcat gcc
/usr/bin/curl
/usr/bin/wget
/usr/bin/netcat
/usr/bin/gcc

# Program not found = no output
$ which nonexistent
$
```

> ペンテストでの使いどころ: システムへのアクセスを獲得した直後に `which python python3 perl ruby nc wget curl` を実行すると、post-exploitation で使えるツールを手早く棚卸しできます。

## 2. `find`

`find` は非常に強力な検索ツールです。ファイルやフォルダを見つけるだけでなく、ファイルサイズ、更新日時、所有者、オブジェクトの種類といったフィルターオプションを備えており、`-exec` フラグを使えば検索結果それぞれに対してコマンドを実行することもできます。

### 構文

```bash
find <location> <options>
```

### 例: 完全なコマンド

```bash
$ find / -type f -name *.conf -user root -size +20k -newermt 2020-03-03 -exec ls -al {} \; 2>/dev/null
```

**出力:**
```
-rw-r--r-- 1 root root 136392 Apr 25 20:29 /usr/src/linux-headers-5.5.0/include/config/auto.conf
-rw-r--r-- 1 root root  82290 Apr 25 20:29 /usr/src/linux-headers-5.5.0/include/config/tristate.conf
-rw-r--r-- 1 root root  95813 May  7 14:33 /usr/share/metasploit-framework/data/jtr/repeats32.conf
-rw-r--r-- 1 root root  60346 May  7 14:33 /usr/share/metasploit-framework/data/jtr/dynamic.conf
-rw-r--r-- 1 root root  21254 May  2 11:59 /usr/share/doc/sqlmap/examples/sqlmap.conf
-rw-r--r-- 1 root root  25086 Mar  4 22:04 /etc/dnsmasq.conf
```

### `find` のオプション詳細

| オプション | 説明 |
|--------|------------|
| `-type f` | ファイルのみ検索(`f`=ファイル、`d`=ディレクトリ) |
| `-name *.conf` | `.conf` 拡張子のファイルを検索(ワイルドカード `*`) |
| `-user root` | `root` ユーザーが所有するファイルに絞り込む |
| `-size +20k` | 20 KiB より大きいファイルのみ |
| `-newermt 2020-03-03` | 指定した日付以降に更新されたファイルのみ |
| `-exec ls -al {} \;` | 各結果に対してコマンドを実行(`{}` = 結果のプレースホルダー) |
| `2>/dev/null` | エラーメッセージを非表示(null デバイスへリダイレクト) |

### サイズフィルター早見表

| サフィックス | 単位 | 例 |
|--------|------|---------|
| `c` | バイト | `-size +100c` |
| `k` | キロバイト(KiB) | `-size +20k` |
| `M` | メガバイト(MiB) | `-size +5M` |
| `G` | ギガバイト(GiB) | `-size +1G` |
| `+` プレフィックス | より大きい | `-size +20k` |
| `-` プレフィックス | より小さい | `-size -5k` |

### `find` の実践例

```bash
# Find all .conf files owned by root, larger than 20KB, modified after 2020-03-03
find / -type f -name *.conf -user root -size +20k -newermt 2020-03-03 -exec ls -al {} \; 2>/dev/null

# Find all directories named "backup"
find / -type d -name backup 2>/dev/null

# Find SUID files (critical for privilege escalation)
find / -type f -perm -4000 2>/dev/null

# Find writable files owned by current user
find / -type f -writable 2>/dev/null

# Find files modified in the last 7 days
find /home -type f -mtime -7

# Find files by exact size (exactly 1337 bytes)
find / -type f -size 1337c 2>/dev/null
```

> ペンテストの注意点: `find / -perm -4000 2>/dev/null` は SUID バイナリ、つまり所有者の権限で実行されるファイルを検索します。これらは権限昇格の主要な標的です。

## 3. `locate`

`locate` は `find` に比べてはるかに高速な検索を提供します。理由は、ファイルシステムを直接走査するのではなく、システム上の全ファイルとフォルダの情報を持つローカルデータベースを検索するためです。

弱点は、データベースを `sudo updatedb` で手動更新する必要があることです。新しく作成されたファイルは、まだデータベースに反映されていない場合があります。

`locate` と `find` の使い分け:
- 複雑なフィルターが不要な高速検索には `locate` を使う
- サイズ・日時・所有者などの特定フィルターが必要な場合は `find` を使う

```bash
# Update the locate database (run before first use or after new files added)
$ sudo updatedb

# Search for all .conf files
$ locate *.conf
/etc/GeoIP.conf
/etc/NetworkManager/NetworkManager.conf
/etc/UPower/UPower.conf
/etc/adduser.conf
...

# Search for a specific filename
$ locate shadow
/etc/shadow
/etc/shadow-
```

> 広範囲の検索では `locate` の方が `find` よりはるかに速いですが、細かいフィルターはできません。データベースを最新に保つため、まず `sudo updatedb` を実行してください。

## 4. セキュリティノート: `find` による権限昇格とフォレンジック探索

Linux のペネトレーションテストやフォレンジック調査において、`find` は権限昇格ベクトルを発見するための最も重要なローカル列挙ツールです。

1. SUID/SGID バイナリの探索: SUID ビットが設定されたバイナリ(`-perm -4000` または `-perm -u=s`)は所有者(通常は `root`)の権限で実行されます。脆弱なバイナリ(GTFOBins に掲載されている、またはパラメータインジェクションの余地があるもの)が見つかれば、攻撃者は root シェルを直接得られます。
2. 誰でも書き込み可能なファイル・ディレクトリの特定: 全ユーザーが書き込める(`-perm -2 -type f` または `-writable`)設定ファイルやスクリプト用ディレクトリがあると、攻撃者がペイロードを仕込んだり cron スクリプトの実行を乗っ取ったりできてしまいます。
3. パスワードや機密情報が入ったファイルの探索: Web ディレクトリ全体(`/var/www/`)やホームディレクトリを調べて、`.env` ファイル、データベースのバックアップ(`.sql`)、平文の認証情報を含む設定ファイルを見つけます。
4. 孤立ファイル(所有者なし)の探索: 削除済みユーザーが残したファイル(`-nouser` または `-nogroup`)は、UID/GID の乗っ取りの標的になりやすいものです。

```bash
# ── ESSENTIAL PENTESTING FIND COMMANDS ───────────────────────

# 1. SUID Binaries (Primary Linux PrivEsc vector)
$ find / -perm -u=s -type f 2>/dev/null
$ find / -perm -4000 -type f -exec ls -la {} + 2>/dev/null

# 2. SGID Binaries
$ find / -perm -g=s -type f 2>/dev/null

# 3. World-writable directories and files
$ find / -writable -type d 2>/dev/null
$ find / -perm -222 -type d 2>/dev/null
$ find / -perm -2 -type f 2>/dev/null

# 4. Search for passwords in configuration & web files
$ find /var/www /etc /opt /home -type f \( -name "*.conf" -o -name "*.php" -o -name "*.yaml" -o -name "*.env" \) -exec grep -iHn "password" {} + 2>/dev/null

# 5. Search for SSH private keys
$ find / -name "id_rsa" -o -name "id_dsa" -o -name "id_ed25519" 2>/dev/null

# 6. Files modified in the last 60 minutes (detect recent activity)
$ find / -type f -mmin -60 2>/dev/null

# 7. Linux Capabilities check (alternative to SUID)
$ getcap -r / 2>/dev/null
```

## コマンド比較: `which` vs `find` vs `locate`

| 項目 | `which` | `find` | `locate` |
|---------|---------|--------|----------|
| 目的 | 実行ファイルのパスを探す | ファイル/ディレクトリを検索 | 高速なファイル検索 |
| 速度 | 即座 | 遅い(実走査) | 速い(データベース) |
| フィルターオプション | なし | 豊富(サイズ、日付、ユーザーなど) | 最小限 |
| リアルタイム性 | あり | あり | `updatedb` の状態に依存 |
| root 権限が必要か | 不要 | 一部のパスで必要 | 不要(更新には sudo が必要) |
| 用途 | ツールの有無を確認 | 複雑な条件での検索 | 素早い広範囲検索 |

## ツールを組み合わせたワークフロー

```bash
# Step 1: Check if python3 is available
which python3

# Step 2: Find all Python scripts owned by root
find / -type f -name "*.py" -user root 2>/dev/null

# Step 3: Quick search for config files
sudo updatedb && locate *.conf

# Step 4: Find SUID files and list them in detail
find / -type f -perm -4000 -exec ls -la {} \; 2>/dev/null
```

## クイックリファレンス

```bash
# which — find executable location
which python
which curl wget netcat

# find — powerful search with filters
find / -type f -name "*.conf"              # all .conf files
find / -type d -name "backup"              # directories named backup
find / -type f -user root -size +20k       # root's files > 20KB
find / -type f -newermt 2020-01-01         # files modified after date
find / -type f -perm -4000 2>/dev/null     # SUID files
find / -type f -perm -2000 2>/dev/null     # SGID files
find / -type f -name "*.conf" -exec ls -al {} \; 2>/dev/null

# locate — fast database search
sudo updatedb                              # update database first
locate *.conf                              # find all .conf files
locate shadow                              # find files named shadow
```
