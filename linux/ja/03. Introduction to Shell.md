## 1. シェルとは何か

シェルは、ユーザーと OS のカーネルの間に立つテキストベースのインターフェースである。シェルは入力されたコマンドを受け取り、実行のためにカーネルへ渡し、その結果を私たちに表示する。

シェルは大きなオフィスビルの受付のようなものだと考えるとわかりやすい。

- サーバールーム（カーネル）: 会社のすべてのデータとコマンドを処理する。
- 受付デスク（ターミナル）: サーバールームへの通信ポイント。
- あなた: 受付に指示を渡し、サーバールームへ転送してもらう立場。

シェルは単なる GUI の代替ではない。プログラムやプロセスとやり取りし、情報をより速く取得し、スクリプトでタスクを自動化するという点で、GUI よりはるかに多くのことができる。

```
┌─────────────────────────────────────────────────────┐
│                    YOU / USER                        │
│              (type commands here)                    │
└──────────────────────┬──────────────────────────────┘
                       │ input
                       ▼
┌─────────────────────────────────────────────────────┐
│              TERMINAL / SHELL (Bash)                 │
│         text-based I/O interface (CLI)               │
└──────────────────────┬──────────────────────────────┘
                       │ system calls
                       ▼
┌─────────────────────────────────────────────────────┐
│                    KERNEL                            │
│      manages hardware, memory, processes             │
└──────────────────────┬──────────────────────────────┘
                       │ hardware access
                       ▼
┌─────────────────────────────────────────────────────┐
│                   HARDWARE                           │
│          CPU, RAM, Storage, Network...               │
└─────────────────────────────────────────────────────┘
```

上の図が示す通り、ユーザーが入力したコマンドはターミナル/シェル（Bash など）を経由し、システムコールとしてカーネルに渡される。カーネルはハードウェア、メモリ、プロセスを管理し、最終的に CPU、RAM、ストレージ、ネットワークといった物理ハードウェアにアクセスする。ユーザーからハードウェアまで、この一連の流れがシェルの役割を理解する土台になる。

## 2. ターミナル、シェル、コンソールの違い

この3つの用語はよく混同して使われるが、実際には意味が異なる。

- シェル: コマンドを解釈するプログラム（Bash、Zsh、Fish）。入力された内容を処理する「頭脳」にあたる。
- ターミナル: コマンドを入力し、出力を見るためのインターフェース。開く黒いウィンドウそのもの。
- コンソール: テキストモードのターミナル（ウィンドウではない）。GUI のウィンドウではなく、テキストモードの物理画面を指す。

| 用語 | 定義 | 例 |
|------|------|-----|
| シェル | コマンドを解釈するプログラム | Bash、Zsh、Fish |
| ターミナル | テキストインターフェースのウィンドウ | GNOME Terminal、iTerm2 |
| コンソール | 物理的なテキストモードのターミナル | `tty1`、`tty2` |
| CLI | コマンドラインインターフェース | あらゆるターミナルウィンドウ |

## 3. ターミナルエミュレーターとマルチプレクサー

ターミナルエミュレーターは、GUI 環境の中でターミナルの機能をエミュレートするソフトウェアである。コンピュータ画面上のバーチャル受付デスクのようなものと考えるとよい。物理的にマシンの前にいなくても、GUI からシェルとやり取りできるようになる。

Tmux や Screen のようなターミナルマルチプレクサーを使うと、次のようなことができる。

- 一つのウィンドウ内でターミナルを複数のペインに分割する。
- 複数のディレクトリで同時に作業する。
- 異なるタスクごとに異なるワークスペースを作る。
- セッションをデタッチする。つまりバックグラウンドでプロセスを動かしたまま離れ、あとで戻ってくる。

### よく使われるターミナルエミュレーター

| エミュレーター | プラットフォーム | 特徴 |
|----------------|-------------------|------|
| GNOME Terminal | Linux | GNOME デスクトップのデフォルト |
| Konsole | Linux | KDE デスクトップのデフォルト |
| Terminator | Linux | 複数分割パネル |
| Alacritty | クロスプラットフォーム | GPU アクセラレーション、非常に高速 |
| iTerm2 | macOS | Mac 向けの高機能ターミナル |
| Windows Terminal | Windows | WSL 向けのモダンなターミナル |

### Tmux の基本コマンド

```bash
# Start a new session
$ tmux

# Start named session
$ tmux new -s mysession

# Detach from session (keeps running in background)
Ctrl + B, then D

# List sessions
$ tmux ls

# Reattach to session
$ tmux attach -t mysession

# Split terminal horizontally
Ctrl + B, then "

# Split terminal vertically
Ctrl + B, then %

# Navigate between panes
Ctrl + B, then arrow keys

# Kill current pane
Ctrl + B, then X
```

## 4. Bash とその他のシェル

Linux で最もよく使われるシェルは Bourne-Again Shell（Bash）で、GNU プロジェクトの一部である。GUI でできることはすべて Bash でも実行できるうえ、それ以上のこともできる。Bash はスクリプトによる自動化を可能にし、何時間もの手作業を節約できる。

Bash 以外にも、好みや用途に応じて選べる複数のシェルが存在する。

### シェルの比較

| シェル | 正式名称 | 特徴 | デフォルトの環境 |
|--------|----------|------|-------------------|
| Bash | Bourne-Again Shell | 最も普遍的、スクリプト機能が強力 | 多くの Linux ディストロ |
| Zsh | Z Shell | 高度な自動補完、高いカスタマイズ性 | macOS（デフォルト） |
| Fish | Friendly Interactive Shell | リアルタイムの構文強調、使いやすい | - |
| Ksh | Korn Shell | Bash 互換、高パフォーマンス | 一部の Unix システム |
| Tcsh/Csh | TENEX C Shell | C言語に似た構文 | BSD 系システム |
| Dash | Debian Almquist Shell | 非常に軽量、スクリプト実行が高速 | Debian（/bin/sh として） |

```bash
# Check current shell
$ echo $SHELL
/bin/bash

# Check available shells on system
$ cat /etc/shells
/bin/sh
/bin/bash
/usr/bin/bash
/bin/rbash
/usr/bin/rbash
/usr/bin/sh
/bin/zsh
/usr/bin/zsh

# Switch to another shell temporarily
$ zsh
$ fish

# Change default shell permanently
$ chsh -s /bin/zsh
```

## 5. なぜシェルを学ぶべきか

シェルを学ぶことは、Linux とサイバーセキュリティの学習における重要な投資である。理由は以下の通り。

```
GUI  vs  Shell
─────────────────────────────────────────────────────
GUI:    Click → Menu → Sub-menu → Button → Confirm
Shell:  $ command -flag target   ← done in 1 line

Speed:       Shell wins always
Automation:  Shell only (scripts)
Remote:      Shell only (SSH)
Precision:   Shell wins (exact control)
Learning:    GUI easier to start
Power:       Shell has no ceiling
```

| 理由 | 説明 |
|------|------|
| 速度 | 繰り返しのタスクでは GUI よりはるかに速い |
| 自動化 | スクリプトで何千ものタスクを一度に自動化できる |
| リモートアクセス | SSH はシェルのみを使用し、GUI は不要 |
| 精度 | システムのあらゆる側面を完全に制御できる |
| サイバーセキュリティ | ほぼすべてのセキュリティツールが CLI 経由で動く |
| サーバー | Linux サーバーには GUI がないことがほとんど |

GUI ではクリックしてメニューを開き、サブメニューをたどり、ボタンを押して確認する、という手順を踏む必要がある。シェルなら `command -flag target` のように1行で完結する。速度と精度で常にシェルが勝り、自動化とリモート操作はシェルでしか実現できない。GUI は学習の取っかかりとしては簡単だが、シェルには機能面での天井がない。

## 6. セキュリティノート: シェルの悪用、制限付きシェル、環境変数汚染

ペネトレーションテストやセキュリティ評価において、シェルとのやり取りにはいくつかの重要な攻撃ベクトルが関わってくる。

1. 制限付きシェル（rbash / rzsh）からの脱出: 制限付きシェル環境では、ディレクトリの変更（`cd`）、`$PATH` / `$SHELL` 変数の変更、許可されたディレクトリ外のバイナリの実行が禁止される。よく使われる脱出手法には次のようなものがある。
   - インタラクティブなプログラム経由でサブシェルを起動する（Vim `:!/bin/sh`、Nano `^R^X`、Less `!/bin/sh`）。
   - プログラミング言語のランタイムを利用する（Python `python3 -c 'import pty; pty.spawn("/bin/bash")'`）。
   - 環境が書き込み可能であれば PATH をリセットする（`export PATH=$PATH:/bin:/usr/bin`）。
2. 環境変数汚染: `LD_PRELOAD`、`LD_LIBRARY_PATH`、`PROMPT_COMMAND` のような変数を悪用すると、悪意あるシェアードライブラリを読み込ませたり、シェルプロンプトが評価されるたびにコマンドを実行させたりできる。
3. PATH ハイジャック: 管理用スクリプトや cron ジョブが絶対パスを使わずにバイナリを実行している場合（例えば `/usr/sbin/service` ではなく `service apache2 restart` のように書かれている場合）、`$PATH` の先頭に近いディレクトリへの書き込み権限を持つ攻撃者は、そこに偽のバイナリを配置して権限昇格を達成できる。

```bash
# ── RBASH ESCAPE EXAMPLES ────────────────────────────────────

# 1. Vi / Vim escape
$ vi
:set shell=/bin/bash
:shell

# 2. Python PTY spawn
$ python3 -c 'import pty; pty.spawn("/bin/bash")'

# 3. Export PATH reset (if export is available)
$ export PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin:$PATH

# 4. SSH command execution bypass
$ ssh user@target.htb -t "bash --noprofile"

# ── CHECKING SENSITIVE SHELL VARIABLES ───────────────────────
$ env | grep -E "PATH|SHELL|LD_PRELOAD|PROMPT_COMMAND"
```

## クイックリファレンス・チートシート

```bash
# ── SHELL INFO ───────────────────────────────────────
echo $SHELL                  # current shell
echo $0                      # current shell (alternative)
cat /etc/shells              # all available shells
chsh -s /bin/zsh             # change default shell

# ── TERMINAL SHORTCUTS ───────────────────────────────
Ctrl + C                     # cancel current command
Ctrl + Z                     # suspend current process
Ctrl + D                     # logout / EOF
Ctrl + L                     # clear screen (same as clear)
Ctrl + A                     # move to beginning of line
Ctrl + E                     # move to end of line
Ctrl + R                     # search command history
Ctrl + U                     # clear current line
Tab                          # auto-complete
Tab Tab                      # show all completions
↑ / ↓                       # scroll through history

# ── TMUX QUICK START ─────────────────────────────────
tmux                         # start tmux
tmux new -s name             # named session
tmux ls                      # list sessions
tmux attach -t name          # attach to session
Ctrl+B d                     # detach session
Ctrl+B "                     # split horizontal
Ctrl+B %                     # split vertical
Ctrl+B ←→↑↓                 # navigate panes
Ctrl+B x                     # close pane
```
