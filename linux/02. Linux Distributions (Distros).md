## 1. 📦 What is a Linux Distribution?

### 🇮🇩 Bahasa Indonesia
**Linux Distribution (Distro)** adalah sistem operasi lengkap yang mengemas:

$$
\text{Distro} = \underbrace{\text{Linux Kernel}}_{\text{inti}} + \underbrace{\text{Userland}}_{\text{GNU, libs, tools}} + \underbrace{\text{Packaging}}_{\text{apt/dnf/pacman}} + \underbrace{\text{Policy}}_{\text{defaults, init, branding}}
$$

Kernel Linux sendiri **bukan** OS desktop/server siap pakai — distro menambahkan toolchain GNU, systemd (atau alternatif), repositori paket, dan kebijakan keamanan default.

### 🇬🇧 English
A distribution packages the Linux kernel with a coherent userland, package manager, init system, and configuration defaults. Think of distros as **compatible franchises** sharing the same kernel ABI philosophy but differing in release cadence, package versions, and security defaults.

### 🇯🇵 日本語
ディストリビューションはLinuxカーネルにユーザーランド、パッケージマネージャ、init、既定ポリシーを組み合わせた完成OSです。

| Layer | Examples | Role |
|:---|:---|:---|
| Kernel | `linux`, modules, firmware | Hardware + process isolation |
| C library | glibc, musl | Syscall wrappers |
| Init | systemd, OpenRC | Boot & service supervision |
| Packages | deb, rpm, pkg | Install / upgrade / remove |
| Policy | SELinux/AppArmor defaults | Confinement baseline |

## 2. 🏗️ Distro Stack Model

```
┌─────────────────────────────────────────────┐
│  Applications / Desktop / Server Roles      │
├─────────────────────────────────────────────┤
│  Package Manager (apt / dnf / pacman)       │
├─────────────────────────────────────────────┤
│  Userland (GNU coreutils, shells, libs)     │
├─────────────────────────────────────────────┤
│  Init & Logging (systemd, journald, rsyslog)│
├─────────────────────────────────────────────┤
│  Linux Kernel + modules + firmware          │
├─────────────────────────────────────────────┤
│  Hardware (CPU, disk, NIC, TPM, …)          │
└─────────────────────────────────────────────┘
```

### Formal packaging relation
Given package set $P$ and dependency graph $G=(P,E)$:

$$
\text{install}(p) \text{ succeeds} \iff \forall\, q \in \mathrm{Deps}(p):\ q \in P_{\text{installed}} \cup \{\text{to-install}\}
$$

Broken deps or unsigned packages break **integrity** of the supply chain (see Security Notes).

## 3. 📅 Release Models — Stable, Rolling, LTS

| Model | Cadence | Patch style | Best for | Risk |
|:---|:---|:---|:---|:---|
| **Stable** | ~1–2 years | Backports security fixes | Servers, compliance | Older features |
| **LTS** | 2–5+ years support | Security + selected fixes | Enterprise, prod | Slow feature lag |
| **Rolling** | Continuous | Latest upstream | Desktops, labs | Breakage / churn |
| **Point / Snapshot** | Frozen tree | Rebuild periodically | Reproducible builds | Manual upgrades |

### 🇮🇩 Bahasa Indonesia
Untuk server produksi, prefer **Debian Stable / Ubuntu LTS / RHEL / Alma / Rocky**. Rolling (Arch, Kali rolling) cocok untuk lab, bukan baseline produksi tanpa proses hardening ketat.

### 🇬🇧 English
Production servers favor **stable/LTS** channels so CVEs can be backported without wholesale package churn. Rolling releases maximize freshness at the cost of regression risk.

### 🇯🇵 日本語
本番は安定版/LTS、実験・学習はローリングが一般的です。

```
         ┌───────────────┼───────────────┐

                         CentOS Stream (upstream-ish)

                    ┌──────────┐
                    │   Arch   │
                    └────┬─────┘
                      Manjaro / EndeavourOS
                      BlackArch (security tools repo)
```

### General-purpose comparison

| Distro | Best for | PM | Init | Default MAC |
|:---|:---|:---|:---|:---|
| **Ubuntu** | Desktop, cloud images | `apt` | systemd | AppArmor |
| **Debian** | Servers, appliances | `apt` | systemd | AppArmor (optional) |
| **Fedora** | Cutting-edge desktop/dev | `dnf` | systemd | SELinux |
| **RHEL / Alma / Rocky** | Enterprise servers | `dnf` | systemd | SELinux |
| **Arch** | DIY / learning | `pacman` | systemd | (manual) |
| **openSUSE** | Enterprise + YaST | `zypper` | systemd | AppArmor |

> ⚠️ **CentOS Linux** (classic rebuild) is EOL; use **AlmaLinux**, **Rocky Linux**, or **CentOS Stream** deliberately.

## 5. 🔐 Security-Oriented Distributions

### 🇮🇩 Bahasa Indonesia
Distro “security” biasanya berarti: (1) toolset preinstalled untuk **lab/audit**, atau (2) desain privacy/hardening. Gunakan di **VM/lab terisolasi**; jangan jadikan daily driver produksi tanpa kebijakan patch & least privilege.

### 🇬🇧 English
Security-oriented images accelerate **authorized** labs and defensive tooling. Prefer disposable VMs; keep production on stable/LTS with measured hardening (note 22).

### 🇯🇵 日本語
セキュリティ向けディストロは検証・学習用VM向き。本番は安定版＋ hardening が基本です。

| Distro | Base | Focus (defense education) | Notes |
|:---|:---|:---|:---|
| **Kali Linux** | Debian | Security tool ecosystem | Rolling; not a prod server OS |
| **Parrot OS** | Debian | Security + lighter desktop | Common in training labs |
| **BlackArch** | Arch | Large security package set | Add-on repos possible |
| **Qubes OS** | Xen + Fedora templates | Strong isolation UX | Different threat model |
| **Tails** | Debian | Amnesic / privacy live | USB live sessions |

```
Why Linux dominates security workstations (defense view)
───────────────────────────────────────────────────────
Open source  → audit patches, reproduce builds
Control      → minimal services, clear attack surface
Tooling      → native packet capture, scripting, containers
Packaging    → signed updates via distro security teams
```

## 6. 🧭 Choosing a Distro — Decision Matrix

| Requirement | Prefer | Avoid as primary |
|:---|:---|:---|
| 24/7 production server | Debian Stable, Ubuntu LTS, RHEL family | Untested rolling |
| Compliance / long support | RHEL, Ubuntu LTS, Debian LTS | Short-lived spins |
| Desktop beginners | Ubuntu, Fedora Workstation, Mint | Minimal Arch (until ready) |
| Embedded / SBC | Raspberry Pi OS, Debian | Heavy desktop spins |
| Authorized security lab | Kali/Parrot **in VM** | Same image as prod gateway |
| Reproducible builds | Debian, NixOS*, Guix* | Ad-hoc binary drops |

\*NixOS/Guix are special declarative models — excellent for reproducibility, steeper learning curve.

### Formal “support window” idea
If CVE discovery rate is $\lambda$ per year and mean time-to-patch under LTS is $T$, residual exposure roughly scales with $\lambda \cdot T$ when patching is delayed — **prefer channels with fast security backports**.

## 7. 🔵 Debian — Deep Dive

### 🇮🇩 Bahasa Indonesia
**Debian** dikenal karena proses freeze yang ketat, keamanan via **Debian Security**, dan ekosistem `apt`/`dpkg`. Banyak distro (Ubuntu, Kali, Parrot) adalah turunan kebijakan Debian.

**Suites (channels):**
- `stable` — produksi
- `testing` — calon stable berikutnya
- `unstable` (`sid`) — development, bukan server

### 🇬🇧 English
Debian’s strengths: conservative package selection, long security support, and a well-documented packaging policy. Ubuntu inherits much of this while adding faster desktop/cloud cadence and Launchpad/Snap layers.

### 🇯🇵 日本語
Debianは安定性とセキュリティバックポートでサーバーに強い基盤です。

```
Debian suites (simplified)
──────────────────────────
unstable ──► testing ──► stable ──► oldstable
   (sid)      (freeze)     (prod)     (LTS/ELTS may apply)
```

### APT quick reference (Debian family)

```bash
# Refresh indices & apply security updates
sudo apt update
sudo apt upgrade                 # or: sudo apt full-upgrade when needed

sudo apt install <pkg>
sudo apt remove <pkg>
sudo apt purge <pkg>             # remove config too
apt search <keyword>
apt show <pkg>
apt list --installed
dpkg -l | less
```

### Security channels
- Install `unattended-upgrades` on Debian/Ubuntu servers for automatic security patches.
- Prefer official mirrors / HTTPS; verify release keys during install.

## 8. 🪪 Distro Identity on a Live Host

```bash
cat /etc/os-release          # ID, VERSION_ID, VARIANT
lsb_release -a               # if package installed
hostnamectl                  # pretty OS + kernel
uname -r                     # kernel release
cat /etc/debian_version      # Debian-derived
cat /etc/redhat-release      # RHEL-family
```

| Field (`os-release`) | Meaning |
|:---|:---|
| `ID` | Distro id (`debian`, `ubuntu`, `fedora`) |
| `ID_LIKE` | Family hints (`debian`, `rhel`) |
| `VERSION_CODENAME` | Suite name (`bookworm`, `noble`) |
| `SUPPORT_END` | End of support (when provided) |

## 9. 🔐 Security Notes — DEFENSE / Hardening

| Threat / gap | Why it matters | Defense |
|:---|:---|:---|
| Unsupported / EOL distro | No security backports | Upgrade to supported LTS; inventory with `os-release` |
| Mixing random PPAs / third-party RPMs | Supply-chain & trust | Prefer official repos; pin & review keys |
| Using Kali/Parrot as prod gateway | Extra attack surface | Lab VMs only; prod = minimal stable |
| Unpatched packages | Known CVEs remain open | `unattended-upgrades` / dnf-automatic; monitor DSA/USN |
| Flat container host without updates | Shared kernel risk | Patch host kernel; isolate with namespaces + MAC |
| Blind trust in “security” branding | Tools ≠ hardened defaults | Apply note 22 hardening checklist |

### Hardening baseline per family
1. Stay on **supported** release; subscribe to security mailing lists / RSS.
2. Enable automatic **security-only** updates where policy allows.
3. Keep AppArmor (Debian/Ubuntu) or SELinux (RHEL/Fedora) **enforcing**.
4. Minimize installed packages: $\text{attack surface} \propto |P_{\text{installed}}|$.
5. Separate **lab** images from **production** images.

```bash
# Quick posture checks (admin / auditor)
grep -E '^(NAME|VERSION|SUPPORT)' /etc/os-release
systemctl is-enabled unattended-upgrades 2>/dev/null || true
aa-status 2>/dev/null | head          # AppArmor hosts
getenforce 2>/dev/null                # SELinux hosts
```

## 10. 🧠 Quick Reference Cheatsheet

```bash
# Identity
cat /etc/os-release && uname -a

# Debian/Ubuntu updates
sudo apt update && sudo apt upgrade
apt-cache policy <pkg>

# Fedora / RHEL family
sudo dnf check-update
sudo dnf upgrade

# Arch
sudo pacman -Syu

# Package counts (rough surface)
dpkg -l | wc -l
rpm -qa | wc -l
```
