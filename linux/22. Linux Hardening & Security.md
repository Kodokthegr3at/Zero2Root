## 1. 🗝️ Access Control Models — DAC vs MAC vs RBAC

### 🇮🇩 Bahasa Indonesia
Linux mengimplementasikan beberapa model kontrol akses untuk mengamankan data dan resource:
1. **Discretionary Access Control (DAC)**: Model standar Unix di mana pemilik file memiliki kewenangan penuh (*discretion*) untuk mengatur izin baca/tulis/eksekusi (`chmod`, `chown`) untuk user, grup, dan others.
2. **Mandatory Access Control (MAC)**: Kebijakan keamanan terpusat yang ditegakkan oleh kernel (misal **AppArmor** atau **SELinux**). Bahkan user `root` dibatasi oleh profil keamanan yang ketat.
3. **Role-Based Access Control (RBAC)**: Hak akses diberikan berdasarkan peran atau grup fungsional user dalam organisasi (misal grup `developers`, `sysadmins`, `auditors`).

### 🇬🇧 English
Linux implements layered access control architectures to protect files, processes, and memory:
1. **Discretionary Access Control (DAC)**: The standard Unix permissions model where resource owners exert sole discretion over read, write, and execute bits (`chmod`, `chown`) for owners, groups, and global entities.
2. **Mandatory Access Control (MAC)**: Kernel-enforced security policies (such as **AppArmor** or **SELinux**) where system-wide rules override user decisions; even the `root` superuser cannot violate confined process profiles.
3. **Role-Based Access Control (RBAC)**: Permissions are assigned to distinct operational roles/groups (`sudo`, `wheel`, `developers`) rather than individual user accounts.

### 🇯🇵 日本語
Linuxは多層的なアクセス制御モデルを採用しています：
1. **任意アクセス制御（DAC / Discretionary Access Control）**: ファイル所有者が自身のファイルに対するパーミッション（r, w, x）を自由に設定できる標準Unixモデル（`chmod`、`chown`）。
2. **強制アクセス制御（MAC / Mandatory Access Control）**: カーネルレベルで一元適用されるセキュリティポリシー（**AppArmor** や **SELinux**）。rootユーザーであってもプロファイルで制限された操作は実行できません。
3. **ロールベースアクセス制御（RBAC / Role-Based Access Control）**: 組織内の役割（グループ）に基づいてアクセス権限を割り当てるモデル。

## 2. 🧱 Firewall Management — UFW & iptables

### 🇮🇩 Bahasa Indonesia
Firewall lokal melindungi sistem Linux dari port scanning dan koneksi jaringan yang tidak sah:
- **UFW (Uncomplicated Firewall)**: Frontend yang ramah pengguna untuk `iptables`/`nftables` di Ubuntu/Debian.
- **Default Policy**: Selalu terapkan *Default Deny Incoming* (tolak semua koneksi masuk secara default) dan izinkan hanya port yang diperlukan.

### 🇬🇧 English
Host-based firewalls safeguard Linux systems against port enumeration and unauthorized inbound traffic:
- **UFW (Uncomplicated Firewall)**: High-level command-line frontend managing `iptables`/`nftables` on Debian/Ubuntu systems.
- **Hardening Baseline**: Enforce *Default Deny Inbound* while permitting strictly audited service ports.

### 🇯🇵 日本語
ホスト型ファイアウォールは、不正なポートスキャンや外部からの侵入を防ぐ防壁です：
- **UFW（Uncomplicated Firewall）**: Ubuntu/Debianで `iptables`/`nftables` を直感的に操作できる管理フロントエンド。
- **基本原則**: すべての受信通信をデフォルトで拒否（`default deny incoming`）し、必要なポートのみを個別に許可。

```bash
# ── UFW FIREWALL HARDENING ───────────────────────────────────
# 1. Set default policies (Deny all incoming, allow outgoing)
$ sudo ufw default deny incoming
$ sudo ufw default allow outgoing

# 2. Allow SSH on custom port (or default 22)
$ sudo ufw allow 22/tcp

# 3. Allow HTTP and HTTPS
$ sudo ufw allow 80/tcp
$ sudo ufw allow 443/tcp

# 4. Allow traffic only from a trusted management subnet
$ sudo ufw allow from 192.168.1.0/24 to any port 22 proto tcp

# 5. Enable and verify firewall status
$ sudo ufw enable
$ sudo ufw status verbose

# ── RAW IPTABLES INSPECTION ──────────────────────────────────
$ sudo iptables -L -v -n --line-numbers
```

## 3. 🔐 SSH Service Hardening — `/etc/ssh/sshd_config`

### 🇮🇩 Bahasa Indonesia
Daemon OpenSSH (`sshd`) adalah target utama serangan brute-force. Konfigurasi pengerasan (*hardening*) pada `/etc/ssh/sshd_config`:
1. `PermitRootLogin no`: Melarang login langsung sebagai user `root`.
2. `PasswordAuthentication no`: Mematikan autentikasi password plaintext dan **mewajibkan SSH Key**.
3. `Port 2222`: Mengubah port default untuk mengurangi kebisingan bot scanner internet.
4. `MaxAuthTries 3`: Membatasi percobaan password yang salah.
5. `AllowUsers htb-student admin`: Membatasi akun mana saja yang diizinkan login remote.

### 🇬🇧 English
The OpenSSH server daemon (`sshd`) is a prime target for automated brute-force attacks. Key hardening directives in `/etc/ssh/sshd_config`:
1. `PermitRootLogin no`: Prohibits direct superuser authentication over the network.
2. `PasswordAuthentication no`: Disables passwords, enforcing **cryptographic Public Key authentication**.
3. `Port <custom_port>`: Modifies the standard listening port to mitigate automated bot scans.
4. `MaxAuthTries 3`: Restricts maximum failed credential attempts per connection.
5. `AllowUsers <user1> <user2>`: Whitelists specific authorized login accounts.

### 🇯🇵 日本語
OpenSSH（`sshd`）は総当たり攻撃の標的になりやすいため、`/etc/ssh/sshd_config` で厳格に要塞化します：
1. `PermitRootLogin no`: rootユーザーの直接SSHログインを禁止。
2. `PasswordAuthentication no`: パスワード認証を無効化し、**公開鍵認証を必須化**。
3. `Port 2222`: デフォルトポートを変更して自動スキャナーを回避。
4. `MaxAuthTries 3`: 連続認証失敗回数を制限。
5. `AllowUsers htb-student`: ログイン可能なユーザーを明示的にホワイトリスト化。

```bash
# ── AUDIT SSH CONFIGURATION ──────────────────────────────────
$ sudo grep -E -v "^#|^$" /etc/ssh/sshd_config

# Safe restart of SSH service after validation
$ sudo sshd -t && sudo systemctl restart sshd
```

## 4. 🚨 Intrusion Prevention with Fail2Ban — Automated Banning

### 🇮🇩 Bahasa Indonesia
**Fail2Ban** memantau file log sistem (`/var/log/auth.log` atau `/var/log/nginx/error.log`) secara real-time. Jika sebuah IP gagal login sebanyak $N$ kali berturut-turut, Fail2Ban akan otomatis menyisipkan aturan firewall untuk memblokir IP tersebut selama durasi tertentu (*ban time*).

### 🇬🇧 English
**Fail2Ban** actively monitors system log streams (`/var/log/auth.log`, web access logs). When an offending IP triggers $N$ authentication failures within a defined window, Fail2Ban dynamically inserts firewall drop rules to ban the attacker.

### 🇯🇵 日本語
**Fail2Ban** はシステムログ（`/var/log/auth.log` 等）を常時監視し、指定回数以上のログイン失敗を検知すると、ファイアウォールにブロックルールを自動登録して攻撃元IPを即座に遮断します。

```bash
# ── FAIL2BAN MANAGEMENT ──────────────────────────────────────
$ sudo apt install fail2ban -y

# Configure jail settings
$ sudo cp /etc/fail2ban/jail.conf /etc/fail2ban/jail.local
$ sudo systemctl enable --now fail2ban

# Check active jails and banned IPs
$ sudo fail2ban-client status sshd
Status for the jail: sshd
|- Filter
|  |- Currently failed: 2
|  `- Total failed:     45
`- Actions
   |- Currently banned: 1
   `- Banned IP list:   192.168.1.105

# Unban an IP manually
$ sudo fail2ban-client set sshd unbanip 192.168.1.105
```

## 5. ⚙️ Kernel Hardening (`sysctl`) — Network & Memory Hardening

### 🇮🇩 Bahasa Indonesia
Parameter kernel yang dikonfigurasi melalui `/etc/sysctl.conf` melindungi sistem dari serangan network spoofing, SYN floods, dan eksploitasi memori:
- `net.ipv4.tcp_syncookies = 1`: Mencegah kelumpuhan akibat serangan TCP SYN Flood (DoS).
- `net.ipv4.conf.all.accept_source_route = 0`: Menolak paket IP Source Routing yang berpotensi spoofing.
- `kernel.randomize_va_space = 2`: Mengaktifkan **Full ASLR (Address Space Layout Randomization)** untuk mencegah eksploitasi buffer overflow / memory corruption.
- `kernel.yama.ptrace_scope = 2`: Membatasi `ptrace` agar proses tidak dapat menginjeksi kode ke proses lain (mencegah credential dumping).

### 🇬🇧 English
Kernel parameters configured via `/etc/sysctl.conf` protect against network spoofing, DoS exhaustion, and memory corruption exploits:
- `net.ipv4.tcp_syncookies = 1`: Mitigates TCP SYN flood exhaustion.
- `net.ipv4.conf.all.accept_source_route = 0`: Drops source-routed packets preventing IP route spoofing.
- `kernel.randomize_va_space = 2`: Enforces **Full Address Space Layout Randomization (ASLR)**.
- `kernel.yama.ptrace_scope = 2`: Restricts `ptrace` system calls, preventing unauthorized process memory inspection.

### 🇯🇵 日本語
`/etc/sysctl.conf` を通じたカーネルパラメータの要塞化：
- `net.ipv4.tcp_syncookies = 1`: SYNフラッド攻撃（DoS）の緩和。
- `net.ipv4.conf.all.accept_source_route = 0`: 送信元ルーティングパケットの破棄（IPスプーフィング防止）。
- `kernel.randomize_va_space = 2`: 完全な **ASLR（アドレス空間配置のランダム化）** を有効化。
- `kernel.yama.ptrace_scope = 2`: 他プロセスのメモリ読み取り（`ptrace`）を制限。

```bash
# ── APPLY KERNEL HARDENING PARAMETERS ────────────────────────
$ sudo tee -a /etc/sysctl.d/99-security.conf << EOF
# Network security
net.ipv4.tcp_syncookies = 1
net.ipv4.conf.all.accept_source_route = 0
net.ipv4.conf.all.accept_redirects = 0
net.ipv4.icmp_echo_ignore_broadcasts = 1

# Memory protection (ASLR)
kernel.randomize_va_space = 2
EOF

# Reload sysctl settings immediately
$ sudo sysctl --system
```

## 6. 🛡️ Mandatory Access Control — AppArmor & SELinux

### 🇮🇩 Bahasa Indonesia
- **AppArmor (Ubuntu/Debian)**: Berbasis path file. Membatasi program (seperti Apache, Nginx, tcpdump) hanya pada file dan capability yang didefinisikan dalam profil `/etc/apparmor.d/`.
- **SELinux (RHEL/CentOS/Fedora)**: Berbasis label keamanan (*security context* / inode labels). Mengatur interaksi antara subject (proses) dan object (file/port).

### 🇬🇧 English
- **AppArmor (Ubuntu/Debian)**: Path-based MAC system confining individual binaries (e.g., Apache, Nginx) strictly to resources defined in `/etc/apparmor.d/` profiles.
- **SELinux (RHEL/CentOS/Fedora)**: Inode/label-based MAC architecture enforcing mandatory type enforcement and security contexts.

### 🇯🇵 日本語
- **AppArmor（Ubuntu/Debian系）**: ファイルパスベースの強制アクセス制御。`/etc/apparmor.d/` のプロファイルで各デーモンのアクセス先を制限。
- **SELinux（RHEL/CentOS系）**: セキュリティコンテキスト（ラベル）に基づく厳格な強制アクセス制御。

```bash
# ── CHECK APPARMOR STATUS ────────────────────────────────────
$ sudo aa-status
apparmor module is loaded.
28 profiles are in enforce mode.
  /usr/bin/evince
  /usr/sbin/cupsd
  /usr/sbin/tcpdump
0 profiles are in complain mode.
```

## 7. 🔐 Security Note — Defense Auditing, Privilege Review & Misconfiguration Hunting

### 🇮🇩 Bahasa Indonesia
Dalam penetration testing (*HTB Academy — Cry0l1t3 & knightmare Standard*):
1. **Audit Firewall Lokal**: Saat mendapatkan shell sebagai user biasa, periksa `/etc/ufw/ufw.conf` atau `/etc/iptables/` untuk melihat port internal yang dilindungi.
2. **Audit MAC Confinement**: Periksa apakah process berada di bawah AppArmor complain mode atau unconfined (`aa-unconfined`).
3. **Pemeriksaan SUID yang Tidak Perlu**: Jalankan audit binary SUID (`find / -perm -4000 2>/dev/null`) dan hapus bit SUID pada binary yang tidak membutuhkan privilege root (`chmod u-s /usr/bin/chfn`).
4. **Audit Sudoers**: Pastikan tidak ada aturan wildcard berbahaya di `/etc/sudoers` (seperti `ALL=(ALL) NOPASSWD: ALL`).

### 🇬🇧 English
In penetration testing methodology (*HTB Academy — Cry0l1t3 & knightmare Standard*):
1. **Local Defense Probing**: Inspect `/etc/ufw/` or query socket states (`ss -tulnp`) to map internally segmented networks and bypasses.
2. **MAC Profile Evaluation**: Check whether target processes run in AppArmor complain mode or entirely unconfined (`aa-unconfined`).
3. **SUID Surface Reduction**: Regularly purge unnecessary SUID binaries (`find / -perm -u=s -type f`) to minimize privilege escalation surfaces.
4. **Strict Sudoers Hygiene**: Ensure `/etc/sudoers` does not grant unrestricted `NOPASSWD` execution on dangerous binaries (GTFOBins).

### 🇯🇵 日本語
ペネトレーションテスト（HTB Academy基準）における防御監査：
1. **ローカルファイアウォール調査**: 侵入後、`ss -tulnp` や設定ファイルから内部限定ポートを特定。
2. **AppArmor状態確認**: `aa-status` でプロファイルの適用状況（Enforce / Complain）を確認。
3. **不要なSUIDバイナリの除去**: `find / -perm -4000` で検索し、不要なSUIDビットを解除して権限昇格の芽を摘む。
4. **`/etc/sudoers` の厳格な監査**: パスワードなしで実行可能な危険コマンド（GTFOBins）が存在しないか確認。

```bash
# ── SECURITY HARDENING AUDIT SCRIPT ──────────────────────────
# 1. Check ASLR status (should be 2)
cat /proc/sys/kernel/randomize_va_space

# 2. Audit unconfined network processes
sudo aa-unconfined

# 3. Check open listening ports
ss -tulnp
```

## 8. 🧠 Quick Reference Cheatsheet

```bash
# ── UFW COMMANDS ─────────────────────────────────────────────
sudo ufw enable                          # enable firewall
sudo ufw default deny incoming           # default deny policy
sudo ufw allow 22/tcp                    # allow SSH
sudo ufw allow from 192.168.1.0/24 to any port 22 proto tcp
sudo ufw status verbose                  # view detailed rules
sudo ufw delete allow 80/tcp             # delete rule

# ── SSH HARDENING ────────────────────────────────────────────
sudo vim /etc/ssh/sshd_config            # edit configuration
# PermitRootLogin no
# PasswordAuthentication no
# MaxAuthTries 3
sudo sshd -t                             # test syntax
sudo systemctl restart sshd              # restart daemon

# ── FAIL2BAN ─────────────────────────────────────────────────
sudo systemctl status fail2ban           # service status
sudo fail2ban-client status sshd         # check banned IPs
sudo fail2ban-client set sshd unbanip <IP> # unban IP

# ── KERNEL SYSCTL ────────────────────────────────────────────
sudo sysctl -p                           # reload /etc/sysctl.conf
cat /proc/sys/kernel/randomize_va_space  # check ASLR level
```
