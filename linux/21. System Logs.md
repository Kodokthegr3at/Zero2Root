## 1. 🏗️ Linux Logging Architecture — Overview

### 🇮🇩 Bahasa Indonesia
Linux mencatat hampir setiap aktivitas sistem, otentikasi user, pesan kernel, dan error aplikasi ke dalam direktori terpusat `/var/log/`. Dua sistem logging utama yang bekerja di Linux modern:
1. **Syslog Daemon (`rsyslog`)**: Menangani pesan teks log tradisional dan membaginya ke file spesifik berdasarkan *facility* (sumber) dan *priority* (tingkat keparahan).
2. **Systemd Journal (`systemd-journald`)**: Mengumpulkan log biner terstruktur dari kernel, service, dan proses boot, yang diakses melalui utility `journalctl`.

### 🇬🇧 English
Linux records granular operational activity, user authentication attempts, kernel telemetry, and application diagnostics into the centralized `/var/log/` directory. Modern Linux systems employ two parallel logging subsystems:
1. **Syslog Daemon (`rsyslog`)**: Routes plain-text log streams into designated target files based on facility (source subsystem) and priority (severity level).
2. **Systemd Journal (`systemd-journald`)**: Ingests structured binary logs covering kernel events, system services, and boot sequences, queried via `journalctl`.

### 🇯🇵 日本語
Linuxはシステムの動作、ユーザー認証、カーネルイベント、エラーログを `/var/log/` ディレクトリに一元管理します。モダンなLinuxでは主に2つのサブシステムが動作しています：
1. **Syslogデーモン（`rsyslog`）**: ファシリティ（発生元）とプライオリティ（重要度）に基づいてテキストログを各ファイルに振り分け。
2. **Systemdジャーナル（`systemd-journald`）**: カーネル、サービス、ブートログを構造化バイナリとして収集し、`journalctl` コマンドで照会。

## 2. 🗂️ Key Log Files in `/var/log` — System Telemetry Locations

### 🇮🇩 Bahasa Indonesia
Berikut adalah file-file log paling krusial yang wajib diperiksa oleh sistem administrator dan analis keamanan:
- `/var/log/auth.log` (Debian/Ubuntu) atau `/var/log/secure` (RHEL/CentOS): Mencatat semua aktivitas otentikasi (login SSH, kegagalan password, eksekusi `sudo`, pembuatan user).
- `/var/log/syslog` (atau `/var/log/messages`): Log aktivitas umum sistem dan daemon.
- `/var/log/boot.log`: Catatan pesan saat sistem melakukan booting.
- `/var/log/wtmp` & `/var/log/btmp`: File biner yang mencatat login sukses (`last`) dan login gagal (`lastb`).
- `/var/log/apache2/` / `/var/log/nginx/`: Log request web (*access.log*) dan pesan error (*error.log*).

### 🇬🇧 English
Essential log files analyzed during systems auditing and incident response:
- `/var/log/auth.log` (Debian/Ubuntu) or `/var/log/secure` (RHEL/CentOS): Captures authentication attempts, SSH sessions, `sudo` invocations, and credential validation.
- `/var/log/syslog` (or `/var/log/messages`): General operating system and service telemetry.
- `/var/log/boot.log`: System initialization and service startup logs.
- `/var/log/wtmp` & `/var/log/btmp`: Binary session history records parsed via `last` (successful logins) and `lastb` (bad login attempts).
- `/var/log/apache2/` / `/var/log/nginx/`: Web traffic access records and HTTP daemon error traces.

### 🇯🇵 日本語
システム監査やインシデント調査で確認すべき主要ログファイル：
- `/var/log/auth.log`（Debian系）または `/var/log/secure`（RHEL系）: SSHログイン、パスワード試行、`sudo`実行などの認証履歴。
- `/var/log/syslog`（または `/var/log/messages`）: システム全般のイベントログ。
- `/var/log/wtmp` & `/var/log/btmp`: ログイン成功（`last`）およびログイン失敗（`lastb`）を記録するバイナリファイル。
- `/var/log/apache2/` / `/var/log/nginx/`: Webアクセスログおよびエラーログ。

| Log File | Distribution | 🇮🇩 Deskripsi | 🇬🇧 Description | 🇯🇵 説明 |
|----------|--------------|--------------|----------------|---------|
| `auth.log` / `secure` | Debian / RHEL | Otentikasi, SSH, sudo | Authentication, SSH, sudo | 認証ログ（SSH、sudo等） |
| `syslog` / `messages` | Debian / RHEL | Log umum sistem | General system events | システム全般のログ |
| `dmesg` | All | Ring buffer kernel | Kernel ring buffer | カーネル起動・ドライバログ |

## 3. 🔍 Systemd Journal (`journalctl`) — Querying Structured Logs

### 🇮🇩 Bahasa Indonesia
`journalctl` adalah antarmuka utama untuk membaca log terstruktur yang dikelola oleh `systemd-journald`. Keunggulannya meliputi filtering berbasis waktu, unit service, dan tingkat keparahan (*priority*).

### 🇬🇧 English
`journalctl` is the command-line utility for querying structured logs maintained by `systemd-journald`, supporting rich filtering by time boundaries, service units, and severity.

### 🇯🇵 日本語
`journalctl` は `systemd-journald` が収集したバイナリログを検索・閲覧するためのコマンドです。時間指定、サービス単位、ログレベルによる高度なフィルタリングが可能です。

```bash
# ── COMMON JOURNALCTL QUERIES ────────────────────────────────
# View all logs in real-time (like tail -f)
$ journalctl -f

# Filter logs for a specific service (e.g., SSH)
$ journalctl -u ssh.service

# View logs from the current boot only
$ journalctl -b

# Filter by time range
$ journalctl --since "2026-08-01 00:00:00" --until "2026-08-16 12:00:00"

# Filter by priority (0=emerg, 1=alert, 2=crit, 3=err, 4=warning)
$ journalctl -p err..emerg

# View without pagination (clean output for scripts)
$ journalctl -u nginx --no-pager
```

## 4. ⚙️ Kernel Ring Buffer (`dmesg`) — Hardware & Kernel Diagnostics

### 🇮🇩 Bahasa Indonesia
`dmesg` (*Driver Message*) membaca pesan dari buffer memori sirkular kernel Linux. Sangat berguna untuk mendiagnosis pengenalan hardware baru, error memory, segmentations faults (segfaults), dan device driver loading.

### 🇬🇧 English
`dmesg` reads the circular memory ring buffer of the Linux kernel. It is vital for diagnosing newly attached peripheral devices, memory anomalies, segmentation faults, and kernel driver initializations.

### 🇯🇵 日本語
`dmesg` はLinuxカーネルのリングバッファからメッセージを取得します。ハードウェアの認識、メモリエラー、セグメンテーション違反（Segfault）の調査に不可欠です。

```bash
# ── DMESG COMMANDS ───────────────────────────────────────────
# Print kernel messages with human-readable timestamps
$ sudo dmesg -T

# Filter kernel errors only
$ sudo dmesg -l err,crit

# Search for hardware or network interface events
$ sudo dmesg -T | grep -iE "eth|error|segfault"
```

## 5. 🔄 Log Rotation (`logrotate`) — Managing Disk Space

### 🇮🇩 Bahasa Indonesia
File log yang terus bertambah akan menghabiskan ruang disk jika tidak dikelola. **`logrotate`** mengotomasi proses rotasi, pengarsipan terkompresi (`.gz`), dan penghapusan log lama:
- Konfigurasi Utama: `/etc/logrotate.conf`
- Konfigurasi per Aplikasi: `/etc/logrotate.d/` (misal `/etc/logrotate.d/apache2`, `/etc/logrotate.d/rsyslog`)
- Parameter Umum: `daily` / `weekly`, `rotate 4` (simpan 4 rotasi), `compress` (kompres dengan gzip), `missingok`.

### 🇬🇧 English
Unchecked log generation exhausts disk capacity. **`logrotate`** automates rotation, compression (`.gz`), and lifecycle retention policies:
- Core Configuration: `/etc/logrotate.conf`
- Application Directives: `/etc/logrotate.d/`
- Standard Directives: `daily`/`weekly`, `rotate <count>`, `compress`, `missingok`.

### 🇯🇵 日本語
**`logrotate`** はログファイルの肥大化によるディスク枯渇を防ぐため、ログの定期的なローテーション、圧縮（`.gz`）、世代管理を自動化します：
- メイン設定: `/etc/logrotate.conf`
- アプリ別設定: `/etc/logrotate.d/`
- 主なディレクティブ: `daily`、`rotate 4`（4世代保持）、`compress`（gzip圧縮）。

```bash
# ── FORCE LOG ROTATION MANUALLY ──────────────────────────────
$ sudo logrotate -f /etc/logrotate.conf

# Inspect compressed archive logs using z-commands
$ zgrep "Failed password" /var/log/auth.log.2.gz
$ zcat /var/log/syslog.2.gz | head -20
```

## 6. 🔐 Security Note — Threat Hunting, Anti-Forensics & Log Injection

### 🇮🇩 Bahasa Indonesia
Dalam cyber offensive dan defensive (*HTB Academy Module 18* & *The Hacker Playbook 3*):
1. **Threat Hunting SSH Brute Force**:
   `grep "Failed password" /var/log/auth.log | awk '{print $(NF-3)}' | sort | uniq -c | sort -nr`
2. **Audit Sudo Abuse**:
   `grep "COMMAND=" /var/log/auth.log | awk -F "COMMAND=" '{print $2}'` mengungkap perintah apa saja yang dijalankan via sudo.
3. **Log Poisoning / Log Injection to RCE**: Jika aplikasi web memiliki kerentanan Local File Inclusion (LFI), penyerang dapat mengirimkan request dengan header `User-Agent: <?php system($_GET['cmd']); ?>`. Payload PHP tersebut tercatat di `/var/log/apache2/access.log`, yang kemudian di-include melalui LFI untuk menghasilkan Remote Code Execution (RCE).
4. **Anti-Forensics & Log Evasion**:
   - Menghapus riwayat shell: `history -c; rm ~/.bash_history; unset HISTFILE`
   - Secure shredding log files: `shred -u -z -n 3 /var/log/auth.log`
   - Menyisipkan escape character terminal untuk menyamarkan baris log berbahaya.

### 🇬🇧 English
In offensive engagements and defensive digital forensics (*HTB Academy Module 18* & *The Hacker Playbook 3*):
1. **Hunting Authentication Attacks**:
   `grep "Failed password" /var/log/auth.log | awk '{print $(NF-3)}' | sort | uniq -c | sort -nr`
2. **Auditing Privileged Commands**:
   `grep "COMMAND=" /var/log/auth.log` maps all commands executed under `sudo` elevation.
3. **Log Poisoning via LFI to RCE**: Exploiting Local File Inclusion by embedding raw PHP code into HTTP headers (e.g., `User-Agent: <?php system($_GET['c']); ?>`). The payload is written into `/var/log/apache2/access.log` and subsequently executed via the LFI vector.
4. **Anti-Forensics Techniques**:
   - Shell history suppression: `unset HISTFILE; history -c`
   - Secure erasure: `shred -u -z -n 3 /var/log/auth.log`
   - Terminal control character injection to obfuscate log displays.

### 🇯🇵 日本語
サイバー攻撃およびデジタルフォレンジクスにおける重要論点：
1. **SSHブルートフォース攻撃の検知**:
   `grep "Failed password" /var/log/auth.log | awk '{print $(NF-3)}' | sort | uniq -c | sort -nr`
2. **`sudo` 実行履歴の監査**:
   `grep "COMMAND=" /var/log/auth.log` で特権実行された全コマンドを追跡。
3. **ログポイズニング（Log Poisoning）攻撃**: LFI（ローカルファイルインクルード）脆弱性を持つWebサイトに対し、`User-Agent` に `<?php system($_GET['cmd']); ?>` を含めてリクエストを送信。`/var/log/apache2/access.log` にPHPコードを混入させ、LFI経由で実行させてRCEを奪取。
4. **アンチフォレンジクス**: `history -c` や `shred` によるログ消去。

```bash
# ── LOG FORENSICS ONE-LINERS ─────────────────────────────────
# 1. Top 10 IP addresses with failed SSH attempts
$ grep "Failed password" /var/log/auth.log | awk '{print $(NF-3)}' | sort | uniq -c | sort -nr | head -10

# 2. Check all successful sudo executions
$ grep "sudo:" /var/log/auth.log | grep "COMMAND" | tail -10

# 3. Check recent logins with last & lastb
$ last -n 10
$ sudo lastb -n 10
```

## 7. 🧠 Quick Reference Cheatsheet

```bash
# ── LOG FILES VIEWING ────────────────────────────────────────
tail -f /var/log/auth.log              # follow auth logs live
tail -f /var/log/syslog                # follow system logs live
tail -f /var/log/apache2/access.log    # follow web access logs
sudo dmesg -T                          # kernel messages with timestamp

# ── JOURNALCTL COMMANDS ──────────────────────────────────────
journalctl -f                          # live systemd logs
journalctl -u ssh.service              # logs for SSH service
journalctl -b                          # logs since current boot
journalctl -p err..emerg               # filter errors only

# ── COMPRESSED ARCHIVES ──────────────────────────────────────
zgrep "keyword" /var/log/*.gz          # search in compressed logs
zcat /var/log/auth.log.1.gz            # read compressed log

# ── LOG AUDIT / USERS ────────────────────────────────────────
last -n 5                              # recent successful logins
sudo lastb -n 5                        # recent failed logins
who                                    # currently logged in users
```
