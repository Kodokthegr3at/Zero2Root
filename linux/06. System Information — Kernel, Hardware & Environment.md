## 1. 🐧 OS & Kernel Identification — Identifying the Target System

### 🇮🇩 Bahasa Indonesia
Mengumpulkan informasi sistem operasi dan kernel adalah langkah pertama yang krusial dalam administrasi sistem dan penetration testing. Perintah berikut mengungkap versi distribusi Linux, rilis kernel, dan arsitektur CPU:
- `uname -a`: Menampilkan semua informasi kernel (arsitektur, rilis kernel, nama host, tanggal build).
- `/etc/os-release` / `/etc/issue`: Berisi rilis dan nama distribusi resmi (Ubuntu, Debian, Kali, CentOS).
- `hostnamectl`: Menampilkan ringkasan hostname, kernel, dan arsitektur pada sistem modern berbasis `systemd`.

### 🇬🇧 English
Gathering operating system and kernel telemetry is the fundamental first phase in systems administration and penetration testing reconnaissance. These utilities detail the distribution release, kernel version, and CPU architecture:
- `uname -a`: Displays complete kernel telemetry (kernel version, build timestamp, architecture, hostname).
- `/etc/os-release` / `/etc/issue`: Files defining the official distribution name and version (Ubuntu, Debian, Kali, CentOS).
- `hostnamectl`: Outputs a unified summary of hostname, chassis, kernel release, and architecture on `systemd` distributions.

### 🇯🇵 日本語
OSとカーネル情報の収集は、システム管理およびペネトレーションテストの初期偵察において極めて重要です。以下のコマンドでディストリビューション、カーネルバージョン、CPUアーキテクチャを確認します：
- `uname -a`: カーネルの全情報（カーネルバージョン、ビルド日時、アーキテクチャ、ホスト名）を表示。
- `/etc/os-release` / `/etc/issue`: 公式ディストリビューション名とバージョン情報を表示。
- `hostnamectl`: `systemd` 環境でホスト名、カーネル、アーキテクチャの概要を表示。

```bash
# ── KERNEL & OS VERSION CHECK ────────────────────────────────
$ uname -a
Linux htb-target 5.15.0-78-generic #85-Ubuntu SMP Fri Jul 7 15:25:09 UTC 2023 x86_64 x86_64 x86_64 GNU/Linux

$ uname -r      # Kernel release only (e.g., 5.15.0-78-generic)
$ uname -m      # Machine architecture (e.g., x86_64 / aarch64)

# ── DISTRO INFORMATION ───────────────────────────────────────
$ cat /etc/os-release
NAME="Ubuntu"
VERSION="22.04.3 LTS (Jammy Jellyfish)"
ID=ubuntu
ID_LIKE=debian
VERSION_ID="22.04"

$ hostnamectl
```

## 2. ⚡ Hardware, CPU & Memory — Inspecting System Resources

### 🇮🇩 Bahasa Indonesia
Kernel Linux mengekspos status hardware dan konsumsi resource melalui filesystem virtual `/proc`:
- `lscpu`: Memberikan rincian mendalam tentang arsitektur prosesor, jumlah core, socket, cache L1/L2/L3, dan virtualisasi.
- `free -h`: Menampilkan total kapasitas RAM fisik dan Swap yang digunakan/tersedia dalam format yang mudah dibaca (`-h` = human-readable).
- `/proc/cpuinfo` & `/proc/meminfo`: Sumber data mentah dari kernel untuk spesifikasi prosesor dan memori.

### 🇬🇧 English
The Linux kernel exposes real-time hardware status and resource consumption metrics via the `/proc` virtual filesystem:
- `lscpu`: Gathers detailed processor architecture, core counts, threads per core, virtualization flags, and CPU cache topology.
- `free -h`: Summarizes physical RAM and Swap utilization in human-readable units (`-h`).
- `/proc/cpuinfo` & `/proc/meminfo`: Raw kernel data streams detailing hardware specifications.

### 🇯🇵 日本語
Linuxカーネルは仮想ファイルシステム `/proc` を通じてハードウェア状態とリソース使用状況を公開しています：
- `lscpu`: CPUアーキテクチャ、コア数、スレッド数、仮想化サポート、キャッシュ構成を詳細表示。
- `free -h`: 物理RAMおよびスワップメモリの使用量・空き容量を人間が読みやすい形式（`-h`）で表示。
- `/proc/cpuinfo` & `/proc/meminfo`: カーネルが保持する生データ。

```bash
# ── CPU SPECIFICATIONS ───────────────────────────────────────
$ lscpu
Architecture:            x86_64
  CPU op-mode(s):        32-bit, 64-bit
  Address sizes:         39 bits physical, 48 bits virtual
  Byte Order:            Little Endian
  CPU(s):                4
  Model name:            Intel(R) Core(TM) i7-10700K CPU @ 3.80GHz

# ── MEMORY CONSUMPTION ───────────────────────────────────────
$ free -h
               total        used        free      shared  buff/cache   available
Mem:           7.7Gi       2.1Gi       3.4Gi       120Mi       2.2Gi       5.2Gi
Swap:          2.0Gi          0B       2.0Gi
```

## 3. 💾 Disks & Filesystems — Block Devices and Partitions

### 🇮🇩 Bahasa Indonesia
- `lsblk`: Menampilkan daftar semua block device (hard disk, NVMe, USB, loop devices) dalam struktur pohon hirarkis beserta titik mount (`mountpoint`).
- `df -h`: Menampilkan penggunaan ruang disk (*Disk Free*) untuk setiap partisi yang sedang ter-mount.
- `du -sh <path>`: Menghitung total ukuran file atau direktori tertentu (*Disk Usage*).
- `fdisk -l` / `parted -l`: Menampilkan tabel partisi disk (membutuhkan akses root).

### 🇬🇧 English
- `lsblk`: Lists all block storage devices (SATA disks, NVMe, USB volumes, virtual loop devices) in an intuitive tree structure alongside their mountpoints.
- `df -h`: Reports disk space allocation and capacity across all mounted filesystems.
- `du -sh <directory>`: Summarizes the disk space consumed by a target directory or file.
- `fdisk -l` / `parted -l`: Inspects raw partition tables (requires root privileges).

### 🇯🇵 日本語
- `lsblk`: すべてのブロックデバイス（HDD、SSD、NVMe、USB等）をツリー構造とマウントポイント付きで一覧表示。
- `df -h`: マウント中の各ファイルシステムの使用量・空き容量を表示。
- `du -sh <dir>`: 指定したディレクトリの合計ディスク使用量を集計。
- `fdisk -l`: ディスクパーティションテーブルを詳細表示（root権限が必要）。

```bash
# ── BLOCK DEVICES TREE ───────────────────────────────────────
$ lsblk
NAME   MAJ:MIN RM   SIZE RO TYPE MOUNTPOINTS
sda      8:0    0    50G  0 disk 
├─sda1   8:1    0     1M  0 part 
├─sda2   8:2    0     2G  0 part /boot
└─sda3   8:3    0    48G  0 part /

# ── DISK FREE SPACE ──────────────────────────────────────────
$ df -h /
Filesystem      Size  Used Avail Use% Mounted on
/dev/sda3        48G   12G   34G  27% /

# ── DIRECTORY SIZE CALCULATION ───────────────────────────────
$ du -sh /var/log/
1.4G	/var/log/
```

## 4. 🌐 Network Interfaces & Hostname — Network Configuration

### 🇮🇩 Bahasa Indonesia
- `ip addr` / `ip a`: Menampilkan semua antarmuka jaringan (NIC) beserta alamat IPv4/IPv6 dan MAC address (menggantikan utility lama `ifconfig`).
- `ip route` / `ip r`: Menampilkan tabel routing kernel dan *default gateway*.
- `hostname -I`: Menampilkan semua alamat IP host secara ringkas.
- `/etc/resolv.conf`: Menentukan server DNS resolver yang digunakan sistem.
- `/etc/hosts`: Tabel mapping statis antara IP dan hostname lokal.

### 🇬🇧 English
- `ip addr` / `ip a`: Inspects network interfaces, assigning IPv4/IPv6 addresses and link-layer MAC identifiers (modern successor to `ifconfig`).
- `ip route` / `ip r`: Displays the kernel routing table and the default gateway address.
- `hostname -I`: Emits a concise space-separated list of all assigned host IP addresses.
- `/etc/resolv.conf`: Configures upstream DNS nameservers utilized by local resolvers.
- `/etc/hosts`: Static hostname-to-IP resolution file parsed before DNS queries.

### 🇯🇵 日本語
- `ip addr` / `ip a`: ネットワークインターフェース、IPv4/IPv6アドレス、MACアドレスを表示（`ifconfig`の後継）。
- `ip route` / `ip r`: カーネルのルーティングテーブルとデフォルトゲートウェイを表示。
- `hostname -I`: ホストに割り当てられたIPアドレス一覧を簡潔に表示。
- `/etc/resolv.conf`: システムが参照するDNSネームサーバー設定ファイル。
- `/etc/hosts`: 静的ホスト名解決テーブル。

```bash
# ── INSPECT NETWORK INTERFACES ───────────────────────────────
$ ip -br a
lo               UNKNOWN        127.0.0.1/8 ::1/128 
eth0             UP             10.10.14.25/24 fe80::250:56ff:fe9d:8b2a/64 
tun0             UP             10.10.10.50/32 

# ── ROUTING & DNS ────────────────────────────────────────────
$ ip route
default via 10.10.14.1 dev eth0 proto dhcp src 10.10.14.25 metric 100 

$ cat /etc/resolv.conf
nameserver 1.1.1.1
nameserver 8.8.8.8
```

## 5. 📂 Open Files & Sockets — `lsof` & Active Connections

### 🇮🇩 Bahasa Indonesia
Di Linux, "segalanya adalah file" (*everything is a file*). Perintah `lsof` (*List Open Files*) menampilkan semua file, pipe, device, dan socket jaringan yang sedang diakses oleh proses sistem:
- `lsof -i`: Menampilkan semua koneksi jaringan dan port terbuka.
- `lsof -i :80`: Mencari proses yang sedang menggunakan port 80.
- `lsof -u <user>`: Menampilkan file yang sedang dibuka oleh user tertentu.
- `ss -tulnp`: Menampilkan socket TCP/UDP yang sedang listening beserta nomor PID proses pemiliknya.

### 🇬🇧 English
In Unix architecture, "everything is a file". The `lsof` utility indexes all active files, anonymous pipes, character devices, and network sockets opened by executing processes:
- `lsof -i`: Lists active network sockets and established network sessions.
- `lsof -i :80`: Pinpoints which process holds binding on port 80.
- `lsof -u <username>`: Catalogs all files opened by a specific user account.
- `ss -tulnp`: Enumerates active listening TCP/UDP sockets with associated PID/program identifiers.

### 🇯🇵 日本語
Linuxの「すべてはファイルである」という哲学に基づき、`lsof`（List Open Files）コマンドはプロセスが開いているファイル、パイプ、デバイス、ネットワークソケットを一覧表示します：
- `lsof -i`: アクティブなネットワーク接続とオープンポートを表示。
- `lsof -i :80`: ポート80を使用しているプロセスを特定。
- `lsof -u <user>`: 特定ユーザーが開いているファイルを一覧表示。
- `ss -tulnp`: リッスン中のTCP/UDPポートとPIDを高速表示。

```bash
# ── LIST OPEN NETWORK CONNECTIONS ────────────────────────────
$ sudo lsof -i -P -n
COMMAND    PID     USER   FD   TYPE DEVICE SIZE/OFF NODE NAME
sshd       892     root    3u  IPv4  24110      0t0  TCP *:22 (LISTEN)
sshd       892     root    4u  IPv6  24112      0t0  TCP *:22 (LISTEN)
apache2   1245 www-data    4u  IPv4  28901      0t0  TCP *:80 (LISTEN)

# ── LISTENING PORTS USING SS ─────────────────────────────────
$ ss -tulnp
Netid State  Recv-Q Send-Q Local Address:Port  Peer Address:PortProcess
tcp   LISTEN 0      128          0.0.0.0:22         0.0.0.0:*    users:(("sshd",pid=892,fd=3))
tcp   LISTEN 0      511          0.0.0.0:80         0.0.0.0:*    users:(("apache2",pid=1245,fd=4))
```

## 6. 🌿 Environment Variables — System & User Environment

### 🇮🇩 Bahasa Indonesia
Variabel lingkungan (*Environment Variables*) adalah pasangan nilai dinamis yang digunakan oleh sistem dan aplikasi untuk menentukan konfigurasi eksekusi:
- `$PATH`: Daftar direktori tempat shell mencari file executable secara otomatis.
- `$USER` & `$HOME`: Username aktif dan path home direktori.
- `env` / `printenv`: Menampilkan semua variabel lingkungan yang aktif pada sesi saat ini.
- `export VAR="value"`: Membuat variabel baru dan mengekspornya ke semua child process yang dijalankan dari shell tersebut.

### 🇬🇧 English
Environment variables are dynamic key-value pairs influencing process execution behavior across the shell session:
- `$PATH`: Colon-separated list of directories searched when executing binaries without absolute paths.
- `$USER` & `$HOME`: Active username and home directory path.
- `env` / `printenv`: Prints all active session environment variables.
- `export KEY="VALUE"`: Sets and exports a variable to child process environments.

### 🇯🇵 日本語
環境変数は、シェルセッションやアプリケーションの動作を制御する動的な設定値です：
- `$PATH`: コマンド実行時に実行ファイルを検索するディレクトリのリスト（コロン区切り）。
- `$USER` & `$HOME`: 現在のユーザー名およびホームディレクトリのパス。
- `env` / `printenv`: 現在設定されているすべての環境変数を表示。
- `export KEY="VALUE"`: 変数を設定し、子プロセスへ引き継ぐ。

```bash
# ── INSPECT ENVIRONMENT ──────────────────────────────────────
$ echo $PATH
/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin

$ echo $USER $HOME
htb-student /home/htb-student

# Set temporary environment variable
$ export TARGET_IP="10.10.10.100"
$ ping -c 1 $TARGET_IP
```

## 7. 🔐 Security Note — Kernel Exploits, Local Recon & Environment Poisoning

### 🇮🇩 Bahasa Indonesia
Dalam penetration testing Linux (*HTB Academy Module 18* & *The Hacker Playbook 3*), informasi sistem adalah fondasi eksploitasi lokal:
1. **Pencocokan Exploit Kernel**: Versi kernel lama yang diperoleh dari `uname -r` sering kali memiliki kerentanan Local Privilege Escalation (LPE) kritis yang terdokumentasi (misal *Dirty COW* (CVE-2016-5195), *Dirty Pipe* (CVE-2022-0847), *OverlayFS* (CVE-2021-3493), atau *PwnKit* (CVE-2021-4034)). Gunakan database exploit lokal seperti `searchsploit linux kernel 5.10`.
2. **PATH Hijacking / Environment Poisoning**: Jika program SUID atau skrip cron menjalankan perintah tanpa path absolut (misal memanggil `curl` alih-alih `/usr/bin/curl`), penyerang dapat menyisipkan binary palsu di awal `$PATH` (`export PATH=/tmp:$PATH`) untuk mendapatkan eksekusi kode sebagai root.
3. **Pemeriksaan Internal Ports**: Menggunakan `ss -tulnp` atau `netstat -tlpn` dapat mengungkap service lokal yang hanya mendengarkan pada `127.0.0.1` (seperti database MySQL internal, Redis, atau web admin backend) yang dapat di-pivot atau dieksploitasi.

### 🇬🇧 English
In Linux penetration testing (*HTB Academy Module 18* & *The Hacker Playbook 3*), system telemetry drives local attack vectors:
1. **Kernel Exploit Mapping**: Kernel versions exposed via `uname -r` are cross-referenced against public Local Privilege Escalation (LPE) vulnerabilities (e.g., *Dirty COW* [CVE-2016-5195], *Dirty Pipe* [CVE-2022-0847], *OverlayFS* [CVE-2021-3493], or *PwnKit* [CVE-2021-4034]). Query offline vulnerability archives via `searchsploit linux kernel <version>`.
2. **`$PATH` Hijacking & Environment Poisoning**: When SUID binaries or cron jobs invoke utilities using relative names (e.g., `tar` instead of `/usr/bin/tar`), prepending a malicious directory to `$PATH` (`export PATH=/tmp:$PATH`) allows hijacking execution flow with elevated privileges.
3. **Local Loopback Enumeration**: `ss -tulnp` uncovers internal daemons bound exclusively to `127.0.0.1` (e.g., unfiltered Redis, database sockets, local metrics daemons) accessible for internal privilege escalation.

### 🇯🇵 日本語
Linuxペネトレーションテスト（HTB Academy Module 18）において、システム情報は権限昇格攻撃の成否を分ける重要要素です：
1. **カーネル脆弱性の特定（LPE）**: `uname -r` で取得したカーネルバージョンを照合し、*Dirty COW*（CVE-2016-5195）、*Dirty Pipe*（CVE-2022-0847）、*PwnKit*（CVE-2021-4034）等の既知のローカル権限昇格エクスプロイトを調査（`searchsploit linux kernel 5.x`）。
2. **`$PATH` ハイジャック**: SUIDバイナリやCronタスクが絶対パスを指定せずに外部コマンドを実行している場合、`PATH=/tmp:$PATH` のように悪意あるディレクトリを先頭に追加してroot権限で不正スクリプトを実行。
3. **ループバック通信（127.0.0.1）のポート調査**: `ss -tulnp` でローカルホスト限定で動作している内部サービス（Redis、MySQL、内部管理WebUI）を発見し、横展開の足がかりとします。

```bash
# ── PENTESTING SYSTEM RECONNAISSANCE SCRIPT ──────────────────
# 1. OS & Architecture check
uname -a; cat /etc/*release 2>/dev/null

# 2. Search for kernel exploits with searchsploit
searchsploit "Linux Kernel $(uname -r | cut -d'-' -f1)"

# 3. Check internal listening services
ss -tulnp | grep -E "127.0.0.1|::1"

# 4. Check for writable directories in PATH
echo $PATH | tr ":" "\n" | while read dir; do [ -w "$dir" ] && echo "[!] Writable PATH: $dir"; done
```

## 8. 🧠 Quick Reference Cheatsheet

```bash
# ── SYSTEM & KERNEL ──────────────────────────────────────────
uname -a                               # full kernel & architecture
uname -r                               # kernel release version
cat /etc/os-release                    # Linux distribution details
hostname -I                            # all host IP addresses

# ── HARDWARE & RESOURCES ─────────────────────────────────────
lscpu                                  # CPU architecture details
free -h                                # RAM & Swap memory usage
lsblk                                  # list block devices & mounts
df -h                                  # free disk space per partition
du -sh /path/dir                       # directory disk usage

# ── NETWORK & SOCKETS ────────────────────────────────────────
ip -br a                               # brief network interfaces list
ip route                               # routing table & default gateway
ss -tulnp                              # listening TCP/UDP ports with PID
sudo lsof -i -P -n                     # active network connections & files

# ── ENVIRONMENT ──────────────────────────────────────────────
env                                    # print all environment variables
echo $PATH                             # print execution search path
export VAR="value"                     # set environment variable
```
