## 1. 🧱 Linux Host Networking — Layers & Objects

### 🇮🇩 Bahasa Indonesia
Setiap interface jaringan (fisik, bridge, VLAN, tun) memiliki **link layer** state, **IP address(es)**, dan **routing table** yang menentukan gateway keluar.

$$
\text{Packet egress: } \text{app} \rightarrow \text{socket} \rightarrow \text{route lookup} \rightarrow \text{interface} \rightarrow \text{link}
$$

### 🇬🇧 English
Modern admin uses **`ip`** from iproute2. Configuration may be managed by **NetworkManager**, **systemd-networkd**, or static files (**netplan** on Ubuntu, **`/etc/network/interfaces`** on Debian).

### 日本語
各インタフェースはリンク状態・IP アドレス・L3 経路を持ちます。日常操作は `ip`、永続化は NetworkManager / netplan / interfaces です。

```
┌──────────────────────────────────────────┐
│ Applications (curl, ssh, nginx)          │
├──────────────────────────────────────────┤
│ Sockets (TCP/UDP)                        │
├──────────────────────────────────────────┤
│ Routing table  ← ip route                │
├──────────────────────────────────────────┤
│ IP addresses   ← ip addr                 │
├──────────────────────────────────────────┤
│ Interfaces     ← ip link (eth0, wlan0)   │
└──────────────────────────────────────────┘
```

| Object | Show | Configure |
|:---|:---|:---|
| Interface | `ip link` | `ip link set`, NM, netplan |
| IPv4/IPv6 | `ip addr` | `ip addr add`, DHCP |
| Routes | `ip route` | `ip route add`, default gw |
| DNS | `resolvectl`, `/etc/resolv.conf` | NM, resolved |

## 2. 🛠️ The `ip` Command — Link, Address, Route

### 🇮🇩 Bahasa Indonesia
Ganti **`ifconfig`/`route`** dengan **`ip`** untuk operasi harian.

### 🇬🇧 English
Changes via `ip` are often **runtime-only** unless persisted in NM/netplan/interfaces. Document every manual change.

### 日本語
日常は `ip link` / `ip addr` / `ip route` です。`ip` だけの変更は再起動で消えることが多いので、永続設定に落とします。

```bash
# Link layer — up/down, MTU, MAC
ip link show
ip link set eth0 up
ip link set eth0 mtu 1500

# Addresses
ip addr show dev eth0
ip addr add 10.10.14.50/24 dev eth0
ip addr del 10.10.14.50/24 dev eth0

# Routing
ip route show
ip route add default via 10.10.14.1 dev eth0
ip route add 192.168.100.0/24 via 10.10.14.254 dev eth0
ip route del 192.168.100.0/24

# Neighbor cache (ARP/NDP)
ip neigh show
```

| Command | Purpose |
|:---|:---|
| `ip -br a` | Brief address summary |
| `ip -4 route get 8.8.8.8` | Which path to destination |
| `ip link set eth0 down` | Admin down interface |

**Longest Prefix Match (LPM)** — kernel picks the most specific route:

$$
\text{match}(D) = \arg\max_{r \in R} \{\text{prefix\_len}(r) : r.\text{network} \subseteq D\}
$$

## 3. 📜 Legacy Tools — `ifconfig` & `route`

### 🇮🇩 Bahasa Indonesia
Masih muncul di mesin/CTF lama. Paket **`net-tools`**; prefer **`ip`** pada sistem yang Anda kelola.

### 🇬🇧 English
Know the syntax for reading old docs and compromised hosts — do not build new automation on deprecated tools.

### 日本語
古いドキュメントやレガシーホストでは ifconfig/route が残ります。新規自動化には使いません。

```bash
ifconfig -a
ifconfig eth0 10.10.14.50 netmask 255.255.255.0 up
route -n
route add default gw 10.10.14.1
```

## 4. 📶 NetworkManager — `nmcli`

### 🇮🇩 Bahasa Indonesia
**NetworkManager** (`NetworkManager.service`) mengelola Wi-Fi, Ethernet, VPN di desktop/server modern.

### 🇬🇧 English
Use **`nmcli`** for scripting. Connection profiles are stored under `/etc/NetworkManager/system-connections/` (root-readable — protect permissions).

### 日本語
NetworkManager は nmcli で操作します。プロファイルは `/etc/NetworkManager/system-connections/` にあり、権限を厳しく保ちます。

```bash
nmcli device status
nmcli connection show
nmcli connection show "Wired connection 1"

# Static IPv4 example (lab)
nmcli con mod "Wired connection 1" \
  ipv4.method manual \
  ipv4.addresses 10.10.14.50/24 \
  ipv4.gateway 10.10.14.1 \
  ipv4.dns "10.10.14.1 1.1.1.1"
nmcli con up "Wired connection 1"

# Wi-Fi scan (authorized)
nmcli dev wifi list
nmcli dev wifi connect SSID password 'passphrase'
```

| Subcommand | Use |
|:---|:---|
| `nmcli dev` | Device state |
| `nmcli con` | Connection profiles |
| `nmcli networking off/on` | Global toggle |

## 5. 📄 Declarative Config — netplan & `/etc/network/interfaces`

### 🇮🇩 Bahasa Indonesia
Ubuntu memakai **netplan** (YAML); Debian klasik memakai **`/etc/network/interfaces`**. Keduanya persistensi boot, bukan hanya runtime `ip`.

### 🇬🇧 English
Prefer `netplan try` so a bad YAML rolls back. Keep secrets out of world-readable YAML.

### 日本語
永続設定は distro 依存です。Ubuntu は netplan、Debian クラシックは interfaces。`netplan try` で失敗時にロールバックできます。

### Ubuntu netplan (`/etc/netplan/*.yaml`)

```yaml
# /etc/netplan/01-lab.yaml
network:
  version: 2
  ethernets:
    eth0:
      dhcp4: false
      addresses:
        - 10.10.14.50/24
      routes:
        - to: default
          via: 10.10.14.1
      nameservers:
        addresses: [10.10.14.1, 1.1.1.1]
```

```bash
sudo netplan try          # safe test with rollback
sudo netplan apply
```

### Debian classic (`/etc/network/interfaces`)

```
auto eth0
iface eth0 inet static
    address 10.10.14.50
    netmask 255.255.255.0
    gateway 10.10.14.1
    dns-nameservers 10.10.14.1
```

```bash
sudo ifup eth0
sudo ifdown eth0
sudo systemctl restart networking   # distro-dependent
```

## 6. 🏷️ Hostname & Local Name Table

### 🇮🇩 Bahasa Indonesia
**Hostname** adalah identitas host; **`/etc/hosts`** override DNS lokal.

### 🇬🇧 English
Consistent naming aids logging, TLS cert planning, and inventory. Avoid duplicate names in AD/LDAP environments.

### 日本語
hostname と `/etc/hosts` はローカル識別と DNS 上書きです。ログ・証明書・在庫管理のため一貫した命名が重要です。

```bash
hostname
hostnamectl status
sudo hostnamectl set-hostname srv01.lab.internal

cat /etc/hostname
cat /etc/hosts
```

## 7. 🔐 Security Notes — DEFENSE / Exposure

### 🇮🇩 Bahasa Indonesia
IP sekunder, Wi-Fi di server, dan rute statis yang salah bisa membuka jalur tak terduga. IPv6 yang diabaikan sering jadi bypass filter IPv4.

### 🇬🇧 English
Bind services to specific addresses. Disable Wi-Fi on servers. Watch route changes. Apply dual-stack firewalls (note 27).

### 日本語
サービスは特定 IP に bind し、サーバの Wi-Fi は無効化、経路変更を監視し、IPv6 もファイアウォール対象にします。

| Misconfiguration | Impact | Defense |
|:---|:---|:---|
| Secondary IP on `0.0.0.0` services | Unexpected listener binding | Bind services to specific IPs |
| Weak Wi-Fi creds on server | Lateral entry | Disable Wi-Fi on servers; wired mgmt |
| Static routes to attacker GW | Traffic hijack | Route change control; monitoring |
| World-accessible NM APIs | Remote reconfiguration | Localhost-only D-Bus policies |
| IPv6 left enabled, IPv4 filtered | Bypass via v6 | Dual-stack firewall (note 27) |

```bash
# Defensive inventory
ip -br link
ip -br addr
ip route show table all | head
nmcli -f GENERAL.STATE,IP4.ADDRESS dev show
ss -tulnp | grep LISTEN
```

Troubleshooting connectivity → **note 25**. DNS/DHCP services → **note 19**.
