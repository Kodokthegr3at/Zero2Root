## Why Getting Help Matters

We don't need to memorize every command and its options. What matters more is knowing how to get help when we run into an unfamiliar tool or forget a specific option. That ability is a sign of a good engineer, not memorization, but adaptability.

Every tool has hundreds of options. Memorizing all of them is neither possible nor necessary. What we need to master is finding the right information quickly.

## 1. `man`, Manual Pages

`man` (manual) displays the complete documentation for a command or tool. Manual pages contain in-depth explanations of all options, arguments, usage examples, and tool behavior. This is the most comprehensive reference source available directly on the system.

```bash
# Syntax
man <tool>

# Example: manual for ls
$ man ls
```

**Output:**
```
LS(1)                    User Commands                    LS(1)

NAME
       ls - list directory contents

SYNOPSIS
       ls [OPTION]... [FILE]...

DESCRIPTION
       List information about the FILEs (the current directory
       by default). Sort entries alphabetically if none of
       -cftuvSUX nor --sort is specified.

       -a, --all
              do not ignore entries starting with .

       -A, --almost-all
              do not list implied . and ..
...
Manual page ls(1) line 1 (press h for help or q to quit)
```

### Navigating the `man` page

| Key | Function |
|-----|----------|
| `↑` / `↓` | Scroll line by line |
| `Space` | Scroll one page down |
| `b` | Go back one page |
| `/keyword` | Search for keyword |
| `n` | Next search result |
| `N` | Previous search result |
| `g` | Go to beginning |
| `G` | Go to end |
| `h` | Show navigation help |
| `q` | Quit man page |

### Man Page Section Numbers

```bash
# Format: man <section> <command>
$ man 1 ls      # user commands
$ man 5 passwd  # file formats (e.g. /etc/passwd structure)
$ man 8 sudo    # system admin commands
```

| Section | Content |
|---------|---------|
| `1` | General user commands |
| `2` | System calls |
| `3` | Library functions |
| `4` | Special device files |
| `5` | File formats and configurations |
| `6` | Games |
| `7` | Miscellaneous |
| `8` | System admin commands |

## 2. `--help`, the Quick Help Flag

`--help` is a quick, concise way to see available options without opening the full manual page. Its output is shorter and shows a list of flags with brief explanations directly. It's ideal when we only need to recall one or two options.

```bash
# Syntax
<tool> --help

# Example
$ ls --help
```

**Output:**
```
Usage: ls [OPTION]... [FILE]...
List information about the FILEs (the current directory by default).
Sort entries alphabetically if none of -cftuvSUX nor --sort is specified.

  -a, --all                  do not ignore entries starting with .
  -A, --almost-all           do not list implied . and ..
      --author               with -l, print the author of each file
  -b, --escape               print C-style escapes for nongraphic characters
  -B, --ignore-backups       do not list implied entries ending with ~
  -c                         with -lt: sort by, and show, ctime
  -C                         list entries by columns
<SNIP>
```

## 3. `-h`, the Short Help Flag

Some tools use `-h` (instead of `--help`) as the short version of the help flag. Its output is usually more compact than `--help`. Not every tool supports `-h`: some only offer `--help`, some support both.

```bash
# Syntax
<tool> -h

# Example: curl short help
$ curl -h
```

**Output:**
```
Usage: curl [options...] <url>
     --abstract-unix-socket <path> Connect via abstract Unix domain socket
     --anyauth       Pick any authentication method
 -a, --append        Append to target file when uploading
     --basic         Use HTTP Basic Authentication
     --cacert <file> CA certificate to verify peer against
 -E, --cert <certificate[:password]> Client certificate file and password
<SNIP>
```

### Which One Should You Use?

```
Tool unknown?         → man <tool>          (full documentation)
Need a quick flag?    → <tool> --help       (most tools)
Tool uses short help? → <tool> -h           (curl, nmap, etc.)
Not sure?             → try --help first, then -h
```

## 4. `apropos`, Searching by Keyword

`apropos` searches for a keyword within the short descriptions of all manual pages. It's useful when we know what we want to do but don't know the command name, for example, finding all tools related to `sudo`.

```bash
# Syntax
apropos <keyword>

# Example: find everything related to sudo
$ apropos sudo
```

**Output:**
```
sudo (8)             - execute a command as another user
sudo.conf (5)        - configuration for sudo front end
sudo_plugin (8)      - Sudo Plugin API
sudo_root (8)        - How to run administrative commands
sudoedit (8)         - execute a command as another user
sudoers (5)          - default sudo security policy plugin
sudoreplay (8)       - replay sudo session logs
visudo (8)           - edit the sudoers file
```

```bash
# More examples
$ apropos password       # find password-related commands
$ apropos network        # find networking commands
$ apropos compress       # find compression tools
$ apropos "file system"  # search multi-word keyword
```

If `apropos` returns nothing, run `sudo mandb` first to update the manual database.

## 5. ExplainShell, an Online Command Explainer

ExplainShell (https://explainshell.com) is an online tool that breaks down and explains every part of a long command. It's useful when we run into a complex command we've never seen before and want to understand what each part does.

```bash
# Example: paste this complex command into explainshell.com
find /etc/ -name *.conf -user root -size +20k -newermt 2020-03-03 -exec ls -al {} \; 2>/dev/null

# ExplainShell will break it down:
# find        → search for files
# /etc/       → starting directory
# -name *.conf → match files ending in .conf
# -user root  → owned by root
# -size +20k  → larger than 20 kilobytes
# -newermt    → modified after specified date
# -exec ls -al {} \; → run ls -al on each result
# 2>/dev/null → suppress errors
```

## Help Methods Comparison

| Method | When to use | Detail level |
|--------|-------------|---------------|
| `man <tool>` | Need full documentation | Full |
| `<tool> --help` | Need a quick option list | Medium |
| `<tool> -h` | Tool uses a short flag | Short |
| `apropos <keyword>` | Don't know the command name | Names only |
| `explainshell.com` | Long or complex commands | Visual |

## 6. Security Note: GTFOBins Pager Breakout and Offline Recon

In penetration testing and security assessments, Linux's built-in help system carries a few important security implications.

1. GTFOBins / pager privilege escalation: `man` defaults to using pagers like `less` or `more`. If a low-privileged user has `sudo` rights to run `man` (e.g. `sudo man ls` or `sudo man 1 intro`), typing `!/bin/sh` or `!bash` inside the pager drops straight into an interactive root shell.
2. Offline reconnaissance: on air-gapped systems or restrictive CTF labs without internet access, `man` and `apropos` are primary recon tools for discovering installed utilities (such as `nc`, `socat`, `python`, `gcc`, `openssl`, `base64`) that can be weaponized for privilege escalation or data exfiltration.
3. Configuration schema analysis (man section 5): reading local configuration documentation through `man 5` (e.g. `man 5 sudoers`, `man 5 sshd_config`, `man 5 shadow`) lets auditors quickly parse syntax and spot security misconfigurations in system config files.

```bash
# ── GTFOBINS PAGER ESCAPE EXAMPLES ───────────────────────────

# 1. Sudo man privilege escalation
$ sudo man ls
# Inside man / less pager, type:
!/bin/sh
# Result: # (root shell!)

# 2. Offline tool discovery for reverse shell payloads
$ apropos "network" | grep -E "transfer|client|listen"
$ apropos "compiler" # check if gcc/clang is installed

# 3. Read security configuration documentation
$ man 5 sudoers     # syntax for /etc/sudoers (e.g. NOPASSWD, wildcards)
$ man 5 shadow      # password hash field formats
```

## Quick Reference Cheatsheet

```bash
# ── FULL DOCUMENTATION ───────────────────────────────
man ls                      # manual for ls
man 5 /etc/passwd           # manual for passwd file format
man -k keyword              # same as apropos

# ── QUICK HELP ───────────────────────────────────────
ls --help                   # long help flag
curl -h                     # short help flag (some tools)
nmap -h                     # short help (nmap style)

# ── SEARCH MANUALS ───────────────────────────────────
apropos sudo                # find commands related to sudo
apropos password            # find password-related commands
sudo mandb                  # update man page database

# ── NAVIGATING man PAGES ─────────────────────────────
/keyword    # search inside man page
n           # next match
N           # previous match
q           # quit
Space       # next page
b           # previous page
g           # go to top
G           # go to bottom

# ── ONLINE RESOURCES ─────────────────────────────────
# https://explainshell.com  → visual command breakdown
# https://tldr.sh           → simplified man pages (community)
# https://gtfobins.github.io → unix binaries bypass list
# https://cheat.sh          → cheatsheets from terminal:
curl cheat.sh/ls            # get ls cheatsheet from terminal
```
