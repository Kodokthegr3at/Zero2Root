## 1. What Is Oracle Solaris?

Solaris (formerly SunOS/Sun Solaris) is a commercial Unix from Sun Microsystems, now Oracle. It shares BSD/System V DNA with Linux, but the kernel, userland, init system, packaging, and default filesystem all differ.

$$
\text{Solaris stack} = \text{Sun/Oracle kernel} + \text{SMF} + \text{ZFS default} + \text{Zones} + \text{IPS pkg}
$$

Solaris remains relevant in enterprise SPARC/x86, telco, and legacy estates. Pentesters and admins encounter it alongside Linux; knowing the differences speeds up recon and hardening.

```
Timeline (simplified)
  1990s  SunOS / Solaris 2.x
  2000s  Solaris 8/9/10 — ZFS, Containers preview
  2010s  Oracle acquisition; Solaris 11 + IPS
  today  Oracle Solaris 11.x (maintenance-focused)
         Linux distros dominate cloud; Solaris in legacy/verticals
```

| Property | Solaris | Typical Linux |
|:---|:---|:---|
| Vendor | Oracle | Community/commercial mix |
| Init / services | SMF | systemd (most distros) |
| Default FS | ZFS (modern) | ext4/XFS/btrfs |
| Containers | Zones | cgroups/namespaces (Docker/Podman) |
| Package manager | IPS (`pkg`) | apt/dnf/pacman |
| License | Proprietary (Oracle) | Mostly open source |

## 2. Solaris vs Linux — Key Differences for Admins

An admin used to Linux will run into different CLIs and paths, even though the concepts (users, processes, networking) are similar.

| Area | Solaris | Linux |
|:---|:---|:---|
| Kernel name | Sun/Oracle kernel | Linux kernel |
| Service control | `svcadm`, `svcs` | `systemctl` |
| Boot loader | GRUB (x86) | GRUB/systemd-boot |
| Network config | `dladm`, `ipadm`, `route` | `ip`, NetworkManager |
| User/group files | `/etc/passwd`, `/etc/shadow` | Same FHS concept |
| Process list | `ps`, `pgrep`, `/proc` | Same ideas, different `ps` flags |
| Firewall | IPFilter historically; `pf` patterns | iptables/nft/ufw |

Many GNU tools exist on Solaris via GNU userland packages, but the paths and flags differ. A script portable across Linux distros can fail on Solaris without adjustment.

```bash
# Linux habit          →  Solaris equivalent (illustrative — Solaris 11)
# systemctl status ssh →  svcs -xv ssh
# df -hT               →  zfs list  (when ZFS root)
# ip addr              →  ipadm show-addr
# apt install curl     →  pkg install curl
# crontab -l           →  crontab -l (similar, different paths)
```

## 3. SMF — Service Management Facility

SMF replaces legacy init scripts with an FMRI (Fault Management Resource Identifier) and a dependency graph.

$$
\text{FMRI} = \texttt{svc:/category/service:instance}
$$

Example: `svc:/network/ssh:default`

SMF tracks service state (`online`, `offline`, `maintenance`), restarts on failure, and orders startup by dependency, conceptually similar to systemd but with a different CLI and XML manifests.

```bash
# List services
svcs -a
svcs -x                    # failed/maintenance
svcs -l ssh                # detailed

# Enable / start / stop
sudo svcadm enable ssh
sudo svcadm disable ssh
sudo svcadm restart ssh
sudo svcadm clear ssh      # clear maintenance state

# Inspect properties
svcprop -p all ssh
```

| SMF state | Meaning |
|:---|:---|
| `online` | Running / satisfied |
| `offline` | Disabled/stopped |
| `maintenance` | Admin intervention needed |
| `degraded` | Partial function |

Compare with Linux systemd, see note 17 (`systemctl`, `journalctl`).

## 4. IPS Packaging — `pkg`

The Image Packaging System (IPS) manages software with Oracle publishers and a dependency solver.

Use `pkg`, not `apt`/`yum`. Boot environments (BE) pair with ZFS for rollback-friendly upgrades.

```bash
pkg publisher
pkg search curl
pkg info -r curl
sudo pkg install curl
pkg list
pkg update

# Verify package contents
pkg contents -H curl

# Create boot environment before major update (ZFS systems)
beadm list
sudo beadm create pre-update-$(date +%Y%m%d)
```

| Command | Action |
|:---|:---|
| `pkg install PKG` | Install a package |
| `pkg update` | Update the installed set |
| `pkg verify` | Check file integrity |
| `beadm activate BE` | Boot into a snapshot BE |

## 5. ZFS — Zettabyte File System

ZFS combines a volume manager and a filesystem: copy-on-write, checksums, snapshots, compression, and dedup (be careful with RAM usage).

$$
\text{Dataset path: } \texttt{tank/home/alice} \subset \texttt{tank/home} \subset \texttt{tank (pool)}
$$

Linux now has OpenZFS on some distros, but Solaris integration is native and more mature. Admins think in terms of pools and datasets, not just `/dev/sda1`.

```bash
# Pool & dataset (Solaris)
zpool list
zpool status
zfs list
zfs create tank/export
zfs set compression=lz4 tank/export
zfs snapshot tank/export@backup-$(date +%F)
zfs rollback tank/export@backup-2026-08-18

# Quotas & reservations
zfs set quota=50G tank/home/alice
zfs set reservation=10G tank/home/alice
```

| ZFS feature | Benefit |
|:---|:---|
| Checksumming | Detects silent corruption |
| Snapshots | Instant point-in-time copies |
| Send/receive | Replication |
| Compression | Space savings (CPU tradeoff) |

Linux LVM/ext4 basics, see note 22.

## 6. Solaris Zones — OS-Level Virtualization

Zones are kernel-level isolation, similar to modern containers: a global zone plus non-global zones with separate namespaces.

They predate Linux containers but share similar goals. Kernel zones and native zones differ in isolation strength. Zones are not Docker, but they are conceptually related to note 23.

```bash
# Zone management (illustrative)
zonecfg -z myzone
zoneadm -z myzone install
zoneadm -z myzone boot
zlogin myzone

# From global zone
zoneadm list -cv
```

```
Global Zone (host)
 ├─ Zone: web01   (own /etc, users, SMF subset)
 ├─ Zone: db01
 └─ Zone: dev01
Shared kernel, isolated userlands
```

## 7. Security Notes — Solaris Hardening Highlights

Identify the OS first; mistaking Solaris for Linux leads to wrong assumptions in service enumeration and hardening paths.

Map Solaris controls to their Linux analogues: RBAC/roles vs sudo, the audit daemon vs auditd, Trusted Extensions vs SELinux. Verify packages with `pkg verify`.

| Topic | Solaris practice | Linux analogue |
|:---|:---|:---|
| RBAC / roles | `roleadd`, `profiles` | sudo + groups |
| Auditing | Solaris audit daemon | auditd |
| MAC | Trusted Extensions (niche) | SELinux/AppArmor |
| Password policy | `/etc/security/policy.conf` | `login.defs`, PAM |
| Remote access | `ssh` SMF service | `sshd` systemd unit |
| Minimization | `pkg` variant sets | minimal cloud images |

```bash
# Defensive recon (authorized Solaris host)
uname -a
cat /etc/release
svcs -x
netstat -an -f inet | grep LISTEN    # or ss equivalent if installed
pkg verify
zfs list
```

**Assessment tip:** identify the OS early. Mistaking Solaris for Linux leads to the wrong privilege-escalation and service-enumeration paths.
