## Key Terms

You'll see these words throughout the lesson.

| Term | Plain meaning |
|:---|:---|
| Shell | The program that reads commands and runs them (Bash is the common one) |
| Terminal | The window the shell runs inside |
| Prompt | The text the shell shows when it's waiting for input |
| Command | The program you ask the shell to run |
| Argument / flag | Extra input to a command; flags start with `-` (`ls -l`) |
| Built-in | A command the shell runs itself, not a separate program |
| PATH | The list of folders the shell searches to find a command |
| Script | A saved file of shell commands run as one program |

## 1. What is a Shell?

The shell is a text-based interface between the user and the operating system kernel. The shell receives commands we type, passes them to the kernel for execution, then displays the results back to us.

Think of the shell like a receptionist at a large office building.

- Server room (kernel): processes all company data and commands.
- Receptionist's desk (terminal): the communication point to the server room.
- You: deliver instructions to the receptionist to forward to the server room.

The shell is not just a GUI replacement. It gives far more capability to interact with programs and processes, get information faster, and automate tasks with scripts.

```
┌─────────────────────────────────────────────────────┐
│                    YOU / USER                        │
│              (type commands here)                    │
└──────────────────────┬──────────────────────────────┘
                       │ input
                       ▼
┌─────────────────────────────────────────────────────┐
│              TERMINAL / SHELL (Bash)                 │
│         text-based I/O interface (CLI)               │
└──────────────────────┬──────────────────────────────┘
                       │ system calls
                       ▼
┌─────────────────────────────────────────────────────┐
│                    KERNEL                            │
│      manages hardware, memory, processes             │
└──────────────────────┬──────────────────────────────┘
                       │ hardware access
                       ▼
┌─────────────────────────────────────────────────────┐
│                   HARDWARE                           │
│          CPU, RAM, Storage, Network...               │
└─────────────────────────────────────────────────────┘
```

## 2. Terminal vs Shell vs Console

These three terms are often used interchangeably, but they have distinct meanings.

- Shell: the program that interprets commands (Bash, Zsh, Fish). This is the "brain" that processes what you type.
- Terminal: the interface where you type commands and see output. The black window you open.
- Console: a terminal in text mode (not a window). Refers to a physical screen in text mode, not a GUI window.

| Term | Definition | Example |
|------|------------|---------|
| Shell | Command interpreter program | Bash, Zsh, Fish |
| Terminal | Text interface window | GNOME Terminal, iTerm2 |
| Console | Physical text-mode terminal | `tty1`, `tty2` |
| CLI | Command-Line Interface | Any terminal window |

## 3. Terminal Emulators & Multiplexers

A terminal emulator is software that emulates the function of a terminal within a GUI environment. Think of it as a virtual receptionist's desk on your computer screen, letting you interact with the shell remotely or from within a GUI without being physically present at the machine.

A terminal multiplexer like Tmux or Screen lets you:

- split the terminal into multiple panes within one window,
- work in multiple directories simultaneously,
- create different workspaces for different tasks,
- detach sessions, leaving processes running in the background and returning to them later.

### Popular Terminal Emulators

| Emulator | Platform | Strength |
|----------|----------|----------|
| GNOME Terminal | Linux | Default on GNOME desktop |
| Konsole | Linux | Default on KDE desktop |
| Terminator | Linux | Multi-split panels |
| Alacritty | Cross-platform | GPU-accelerated, very fast |
| iTerm2 | macOS | Feature-rich for Mac |
| Windows Terminal | Windows | Modern terminal for WSL |

### Tmux: Essential Commands

```bash
# Start a new session
$ tmux

# Start named session
$ tmux new -s mysession

# Detach from session (keeps running in background)
Ctrl + B, then D

# List sessions
$ tmux ls

# Reattach to session
$ tmux attach -t mysession

# Split terminal horizontally
Ctrl + B, then "

# Split terminal vertically
Ctrl + B, then %

# Navigate between panes
Ctrl + B, then arrow keys

# Kill current pane
Ctrl + B, then X
```

## 4. Bash & Other Shells

The most commonly used shell in Linux is the Bourne-Again Shell (Bash), part of the GNU Project. Everything done through the GUI can be done with Bash, and much more. Bash enables automation through scripting that can save hours of manual work.

Besides Bash, other shells are available to suit different preferences and needs.

### Shell Comparison

| Shell | Full Name | Strength | Default On |
|-------|-----------|----------|------------|
| Bash | Bourne-Again Shell | Most universal, powerful scripting | Most Linux distros |
| Zsh | Z Shell | Advanced auto-complete, highly customizable | macOS (default) |
| Fish | Friendly Interactive Shell | Real-time syntax highlighting, user-friendly | - |
| Ksh | Korn Shell | Compatible with Bash, high performance | Some Unix systems |
| Tcsh/Csh | TENEX C Shell | C language-like syntax | BSD systems |
| Dash | Debian Almquist Shell | Very lightweight, fast for scripting | Debian (as /bin/sh) |

```bash
# Check current shell
$ echo $SHELL
/bin/bash

# Check available shells on system
$ cat /etc/shells
/bin/sh
/bin/bash
/usr/bin/bash
/bin/rbash
/usr/bin/rbash
/usr/bin/sh
/bin/zsh
/usr/bin/zsh

# Switch to another shell temporarily
$ zsh
$ fish

# Change default shell permanently
$ chsh -s /bin/zsh
```

## 5. Why Learn the Shell?

Learning the shell is an important investment in your Linux and cybersecurity learning journey, for the reasons below.

```
GUI  vs  Shell
─────────────────────────────────────────────────────
GUI:    Click → Menu → Sub-menu → Button → Confirm
Shell:  $ command -flag target   ← done in 1 line

Speed:       Shell wins always
Automation:  Shell only (scripts)
Remote:      Shell only (SSH)
Precision:   Shell wins (exact control)
Learning:    GUI easier to start
Power:       Shell has no ceiling
```

| Reason | Explanation |
|--------|-------------|
| Speed | Much faster than the GUI for repetitive tasks |
| Automation | Scripts can automate thousands of tasks at once |
| Remote access | SSH only uses the shell, no GUI needed |
| Precision | Full control over every aspect of the system |
| Cybersecurity | Almost all security tools run via CLI |
| Servers | Linux servers rarely have a GUI |

## 6. Security Note: Shell Exploitation, Restricted Shells, and Environment Poisoning

In penetration testing and security assessments, shell interactions involve several important attack vectors.

1. Restricted Shell (rbash / rzsh) Escape: restricted shells prevent users from changing directories (`cd`), modifying `$PATH` / `$SHELL` variables, or executing binaries outside allowed directories. Common escape techniques include:
   - spawning subshells via interactive programs (Vim `:!/bin/sh`, Nano `^R^X`, Less `!/bin/sh`),
   - leveraging programming language runtimes (Python `python3 -c 'import pty; pty.spawn("/bin/bash")'`),
   - resetting the PATH variable if the environment is writable (`export PATH=$PATH:/bin:/usr/bin`).
2. Environment Variable Poisoning: variables such as `LD_PRELOAD`, `LD_LIBRARY_PATH`, and `PROMPT_COMMAND` can be abused to load malicious shared libraries or trigger command execution every time the shell prompt is evaluated.
3. PATH Hijacking: when administrative scripts or cron jobs execute a binary without an absolute path (for example `service apache2 restart` instead of `/usr/sbin/service`), an attacker with write access to a directory early in `$PATH` can plant a fake binary to achieve privilege escalation.

```bash
# ── RBASH ESCAPE EXAMPLES ────────────────────────────────────

# 1. Vi / Vim escape
$ vi
:set shell=/bin/bash
:shell

# 2. Python PTY spawn
$ python3 -c 'import pty; pty.spawn("/bin/bash")'

# 3. Export PATH reset (if export is available)
$ export PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin:$PATH

# 4. SSH command execution bypass
$ ssh user@target.htb -t "bash --noprofile"

# ── CHECKING SENSITIVE SHELL VARIABLES ───────────────────────
$ env | grep -E "PATH|SHELL|LD_PRELOAD|PROMPT_COMMAND"
```

## Quick Reference Cheatsheet

```bash
# ── SHELL INFO ───────────────────────────────────────
echo $SHELL                  # current shell
echo $0                      # current shell (alternative)
cat /etc/shells              # all available shells
chsh -s /bin/zsh             # change default shell

# ── TERMINAL SHORTCUTS ───────────────────────────────
Ctrl + C                     # cancel current command
Ctrl + Z                     # suspend current process
Ctrl + D                     # logout / EOF
Ctrl + L                     # clear screen (same as clear)
Ctrl + A                     # move to beginning of line
Ctrl + E                     # move to end of line
Ctrl + R                     # search command history
Ctrl + U                     # clear current line
Tab                          # auto-complete
Tab Tab                      # show all completions
↑ / ↓                       # scroll through history

# ── TMUX QUICK START ─────────────────────────────────
tmux                         # start tmux
tmux new -s name             # named session
tmux ls                      # list sessions
tmux attach -t name          # attach to session
Ctrl+B d                     # detach session
Ctrl+B "                     # split horizontal
Ctrl+B %                     # split vertical
Ctrl+B ←→↑↓                 # navigate panes
Ctrl+B x                     # close pane
```
