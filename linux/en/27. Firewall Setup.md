## Key Terms

You'll see these words throughout the lesson.

| Term | Plain meaning |
|:---|:---|
| Firewall | Rules that allow or block network traffic |
| Netfilter | The kernel subsystem that actually filters packets |
| iptables / nftables | The older / newer tools to write firewall rules |
| `ufw` / `firewalld` | Friendlier front-ends over nftables |
| Chain | A list of rules traffic is checked against (INPUT, OUTPUT, FORWARD) |
| Default deny | Block everything, then allow only what's needed |
| Stateful | The firewall tracks connections, not just single packets |

## 1. Linux Netfilter — Where Filtering Happens

The Netfilter kernel subsystem evaluates packets against iptables/nftables rules before forwarding, accepting, or dropping them.

```text
ACCEPT  |  DROP  |  REJECT  |  LOG  |  NAT
```

A host firewall is defense-in-depth after network edge filters. The default posture for servers: deny inbound, allow established connections, and add an explicit allowlist only for the services that need it.

```
Inbound packet
      │
      ▼
 PREROUTING (nat)
      │
      ▼
 INPUT (filter)  → ACCEPT / DROP
      │
      ▼
 Local process OR forward path
```

| Framework | Distros | Backend |
|:---|:---|:---|
| UFW | Ubuntu/Debian | iptables/nft backend |
| firewalld | Fedora/RHEL/Alma | nftables |
| iptables | Universal low-level | legacy CLI |
| nftables | Modern default | `nft` CLI |

Theory context (DAC, MAC, hardening pillars), see note 26.

## 2. iptables — Tables, Chains & Rules

iptables organizes rules into tables (filter/nat/...) and chains (INPUT/FORWARD/OUTPUT). Rules are evaluated top to bottom; the first match wins.

| Table | Purpose |
|:---|:---|
| `filter` | Allow/deny (INPUT, FORWARD, OUTPUT) |
| `nat` | SNAT/DNAT/MASQUERADE |
| `mangle` | TTL/TOS/mark |
| `raw` | Connection tracking exemptions |

Rules are evaluated top to bottom; the first match wins unless a `-j` jump changes flow. Use `iptables-save` / `iptables-restore` for backups.

```bash
# View current rules
sudo iptables -L -v -n
sudo iptables -S

# Minimal allowlist INPUT (lab — adjust interfaces/ports)
sudo iptables -P INPUT DROP
sudo iptables -P FORWARD DROP
sudo iptables -P OUTPUT ACCEPT

sudo iptables -A INPUT -i lo -j ACCEPT
sudo iptables -A INPUT -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT
sudo iptables -A INPUT -p tcp --dport 22 -s 203.0.113.0/24 -j ACCEPT
sudo iptables -A INPUT -p tcp --dport 443 -j ACCEPT
sudo iptables -A INPUT -j LOG --log-prefix "IPT DROP: "
sudo iptables -A INPUT -j DROP

# Persist (Debian)
sudo apt install iptables-persistent -y
sudo netfilter-persistent save
```

| Target | Behavior |
|:---|:---|
| `-j ACCEPT` | Allow the packet |
| `-j DROP` | Silent discard |
| `-j REJECT` | Discard + ICMP error |
| `-j LOG` | Log then continue the chain |

## 3. nftables — Successor Syntax

nftables merges IPv4/IPv6 handling; the ruleset is applied atomically via `nft -f`.

On distros that default to nft, `iptables` may just be an iptables-nft compatibility layer; prefer native `nft` for new rules.

```bash
sudo nft list ruleset

# Example ruleset file /etc/nftables.conf fragment
sudo tee /etc/nftables.conf << 'EOF'
#!/usr/sbin/nft -f
flush ruleset
table inet filter {
  chain input {
    type filter hook input priority 0; policy drop;
    iif "lo" accept
    ct state established,related accept
    tcp dport 22 ip saddr 203.0.113.0/24 accept
    tcp dport { 80, 443 } accept
  }
}
EOF
sudo nft -f /etc/nftables.conf
sudo systemctl enable --now nftables
```

## 4. UFW — Uncomplicated Firewall (Debian/Ubuntu)

An application-profile frontend (`OpenSSH`, `Nginx Full`). It is easy to use while staying default-deny.

Enable it only after confirming the SSH allow rule; keep console access ready in case you need to recover from a lockout.

```bash
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow OpenSSH
sudo ufw allow from 203.0.113.0/24 to any port 22 proto tcp
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw limit OpenSSH    # rate-limit brute force
sudo ufw enable
sudo ufw status verbose
sudo ufw status numbered
sudo ufw delete 3         # by rule number
```

| Command | Effect |
|:---|:---|
| `ufw app list` | Available profiles |
| `ufw allow in on eth0` | Interface-scoped rule |
| `ufw logging on` | Log blocked packets (medium level) |

## 5. firewalld — Zones (RHEL Family)

Zones (`public`, `internal`, `drop`) plus `firewall-cmd`: runtime versus permanent.

`--permanent` changes survive reboot but need `--reload`; runtime-only changes are lost on reboot unless saved.

```bash
sudo systemctl enable --now firewalld
sudo firewall-cmd --state
sudo firewall-cmd --get-active-zones
sudo firewall-cmd --list-all

# Allow HTTP permanently in public zone
sudo firewall-cmd --zone=public --add-service=http --permanent
sudo firewall-cmd --zone=public --add-service=https --permanent
sudo firewall-cmd --reload

# Rich rule: SSH from subnet
sudo firewall-cmd --permanent --add-rich-rule='rule family="ipv4" source address="203.0.113.0/24" service name="ssh" accept'
sudo firewall-cmd --reload
```

| Zone | Typical use |
|:---|:---|
| `public` | Untrusted networks |
| `internal` | Trusted LAN |
| `drop` | Blackhole inbound |

## 6. Allowlist Design Patterns

Principle: inbound traffic is permitted only where explicitly allowed.

Allowed inbound traffic is simply the list of each service's port plus the source addresses allowed to reach it. Nothing else gets in.

| Pattern | When |
|:---|:---|
| Management subnet → SSH | All servers |
| `0.0.0.0/0` → 443 only | Public web |
| Deny all inter-VLAN except bastion | Segmented data center |
| LOG before DROP | Tuning without silent failure |

```bash
# Verify effective posture
sudo ufw status verbose
sudo iptables -L INPUT -v -n --line-numbers
sudo nft list chain inet filter input
sudo firewall-cmd --list-all

# Map listeners vs firewall
ss -tulnp | grep LISTEN
```

## 7. Security Notes — Lockout & Logging

The most expensive mistake: locking out remote SSH access. Prepare a rollback timer and console access before making a major change.

Allow SSH before enabling a default-deny policy. Do not forget IPv6. Rate-limit LOG to avoid filling the disk. Pair this with Fail2Ban (note 26) and auth logs (note 28).

| Pitfall | Consequence | Prevention |
|:---|:---|:---|
| Enabling the firewall before allowing SSH | Console recovery needed | `ufw allow OpenSSH` first; test with `netfilter-persistent` |
| Flushing rules remotely | Instant lockout | An `at` rollback timer or a serial console |
| Over-broad `allow 22/tcp` | Internet brute force | Source IP allowlist + Fail2Ban (note 26) |
| No IPv6 rules | v6 bypass | Dual-stack rules (`inet` table / ip6tables) |
| Logging everything | Disk/CPU flood | Rate-limited LOG prefix |

```bash
# Safe change pattern (lab)
# 1) schedule rollback
echo "sudo ufw disable" | at now + 5 minutes
# 2) apply change
sudo ufw enable
# 3) verify SSH in second session
# 4) cancel rollback: atrm JOB
```

Cross-reference: network interfaces, see notes 24-25; auth brute force, see the logs in note 28.

## 8. Quick Reference Cheatsheet

```bash
# UFW
sudo ufw default deny incoming
sudo ufw allow OpenSSH
sudo ufw enable && sudo ufw status verbose

# iptables
sudo iptables -L -v -n
sudo iptables -S
sudo netfilter-persistent save

# nftables
sudo nft list ruleset
sudo nft -f /etc/nftables.conf

# firewalld
sudo firewall-cmd --list-all
sudo firewall-cmd --add-service=https --permanent
sudo firewall-cmd --reload

# Audit
ss -tulnp | grep LISTEN
```
