## Key Terms

You'll see these words throughout the lesson.

| Term | Plain meaning |
|:---|:---|
| Attack surface | Everything an attacker could try: open ports, users, software |
| Hardening | Reducing the attack surface and tightening configuration |
| Least privilege | Give each user/process only the access it truly needs |
| Defense in depth | Layering several independent controls |
| DAC vs MAC | Normal owner-based permissions vs enforced policy (SELinux, AppArmor) |
| CVE | A publicly catalogued known vulnerability |
| Patching | Installing updates that fix known vulnerabilities |

## 1. Linux Security Goals — Shrink the Attack Surface

Hardening means lowering exposure without breaking the business function:

Risk grows with how valuable the assets are, how many threats exist, how many weaknesses the system has, and how exposed it is.

We reduce **Exposure** (ports, packages, users, privilege) and **Vulnerabilities** (patching, safe configuration). A hardened host has few listeners, few installed packages, least privilege throughout, MAC actually enforcing, encrypted admin channels, and monitored auth logs.

```
          Before                         After (sketch)
   ┌─────────────────┐              ┌─────────────────┐
   │ Many packages   │              │ Minimal packages│
   │ Open ports **** │     ───►     │ Only 22/443     │
   │ Password SSH    │              │ Keys only SSH   │
   │ MAC complain    │              │ MAC enforcing   │
   └─────────────────┘              └─────────────────┘
```

| Pillar | Example controls |
|:---|:---|
| Identity | Strong auth, no shared root SSH |
| Network | Default-deny firewall |
| Software | Signed updates, minimal set |
| Privilege | sudo scoped, no NOPASSWD:ALL |
| Detection | journal/auth forwarded to alerts |
| Recovery | Tested backups (note 21) |

## 2. Access Control — DAC, MAC, RBAC

| Model | Who decides? | Linux mechanism |
|:---|:---|:---|
| **DAC** | Resource owner | `chmod`/`chown` mode bits |
| **MAC** | System policy | SELinux, AppArmor |
| **RBAC** | Role assignment | groups + `sudo` + policy |

Unix mode bits, as a reminder:

```text
  s       rwx     rwx     rwx
special   user    group   other

chmod 750 file   →   rwx r-x ---
```

Even correct DAC can be bypassed by a compromised `root`, unless **MAC** confines the process.

## 3. Defense-in-Depth — Layered Controls

Effective Linux security stacks independent controls, so a failure in one layer does not leave the host wide open.

| Layer | Linux examples | Deep-dive note |
|:---|:---|:---|
| Network edge | Router ACL, VPN | `networking/` module |
| **Host firewall** | iptables, UFW, firewalld | **note 27** |
| Transport/admin | SSH keys, TLS | This note, §4 |
| OS identity | PAM, sudo, shadow | **note 15** |
| Object permissions | chmod, SUID audit | **note 14** |
| MAC | SELinux, AppArmor | §7 below |
| Monitoring | auth logs, journal | **note 28** |

Design the layers as network, then host firewall, then authentication, then MAC, then logging.

```
Internet
   │
   ▼
Edge firewall / WAF
   │
   ▼
Host firewall (note 27) ── default deny inbound
   │
   ▼
SSH/TLS hardened admin path (§4)
   │
   ▼
DAC + sudo RBAC + MAC (§2, §7)
   │
   ▼
Logging & alerting (note 28)
```

**Principle:** default-deny at network boundaries, least privilege everywhere, and assume breach so the blast radius stays limited.

## 4. OpenSSH Hardening — `/etc/ssh/sshd_config`

### Baseline directives

| Directive | Hardened value | Purpose |
|:---|:---|:---|
| `PermitRootLogin` | `no` | No direct root sessions |
| `PasswordAuthentication` | `no` | Keys only |
| `PubkeyAuthentication` | `yes` | Enable keys |
| `KbdInteractiveAuthentication` | `no` | Reduce auth surfaces |
| `MaxAuthTries` | `3` | Slow guessing |
| `AllowUsers` / `AllowGroups` | explicit | Account allowlist |
| `X11Forwarding` | `no` (if unused) | Less attack surface |
| `ClientAliveInterval` | e.g. `300` | Drop stale sessions |

```bash
# Audit effective non-comment config
sudo sshd -T | egrep 'permitrootlogin|passwordauthentication|pubkeyauthentication|maxauthtries'

# Validate before restart
sudo sshd -t && sudo systemctl reload ssh
```

**Rollout tip:** keep a second session open while testing, and use console or cloud serial access if you're remote.

Generate admin keys (on the admin workstation):

```bash
ssh-keygen -t ed25519 -a 100 -f ~/.ssh/id_ed25519_admin
# install public key to ~/.ssh/authorized_keys on server (mode 600)
```

## 5. Fail2Ban — Automated Response

Fail2Ban watches logs. After N failures inside a time window, the offending IP is banned in the firewall for T seconds.

Fail2Ban complements, and doesn't replace, key-only SSH and firewall allowlists.

```bash
sudo apt install fail2ban -y
sudo cp /etc/fail2ban/jail.conf /etc/fail2ban/jail.local
sudo systemctl enable --now fail2ban
sudo fail2ban-client status sshd
sudo fail2ban-client set sshd unbanip 203.0.113.50
```

Tune `findtime`, `maxretry`, and `bantime` in jail.local, and whitelist admin NATs carefully.

## 6. Kernel Hardening via `sysctl`

Useful defensive parameters (verify against your own workload before applying):

| Parameter | Value | Intent |
|:---|:---:|:---|
| `net.ipv4.tcp_syncookies` | `1` | SYN flood resilience |
| `net.ipv4.conf.all.accept_redirects` | `0` | Resist evil ICMP redirects |
| `net.ipv4.conf.all.accept_source_route` | `0` | Drop source-routed packets |
| `net.ipv4.conf.all.log_martians` | `1` | Log impossible addresses |
| `net.ipv4.icmp_echo_ignore_broadcasts` | `1` | Cut smurf-style noise |
| `kernel.randomize_va_space` | `2` | Full ASLR |
| `fs.protected_hardlinks` | `1` | Hardlink safety |
| `fs.protected_symlinks` | `1` | Symlink safety |
| `kernel.yama.ptrace_scope` | `1` or `2` | Limit process tracing |

```bash
sudo tee /etc/sysctl.d/99-hardening.conf << 'EOF'
net.ipv4.tcp_syncookies = 1
net.ipv4.conf.all.accept_redirects = 0
net.ipv4.conf.all.accept_source_route = 0
net.ipv4.icmp_echo_ignore_broadcasts = 1
kernel.randomize_va_space = 2
fs.protected_hardlinks = 1
fs.protected_symlinks = 1
EOF
sudo sysctl --system
cat /proc/sys/kernel/randomize_va_space   # expect 2
```

ASLR intuition: randomize base addresses so a naive fixed-offset memory corruption exploit becomes unreliable:

With `randomize_va_space=2`, the chance of guessing the right addresses is tiny.

## 7. Mandatory Access Control — AppArmor & SELinux

| Framework | Distros | Model |
|:---|:---|:---|
| **AppArmor** | Ubuntu/Debian | Path-based profiles |
| **SELinux** | Fedora/RHEL/Alma/Rocky | Label/type enforcement |

```bash
# AppArmor
sudo aa-status
sudo aa-enforce /etc/apparmor.d/usr.sbin.nginx   # example

# SELinux
getenforce
sudo setenforce 1                                # enforcing until reboot policy
# persistent: SELINUX=enforcing in /etc/selinux/config
```

**Policy:** prefer **enforcing** in production; use complain/permissive only while developing profiles, then tighten.

## 8. Patch Quickly, Install Little

Every extra installed package and every extra listening port adds to the attack surface.

```bash
# Debian/Ubuntu
sudo apt update && sudo apt upgrade
sudo apt install unattended-upgrades
sudo dpkg-query -f '${binary:Package}\n' -W | wc -l

# RHEL family
sudo dnf upgrade
sudo dnf install dnf-automatic

# Listeners audit
ss -tulnp
systemctl list-units --type=service --state=running
```

Disable unused services (`systemctl disable --now …`). Remove compilers and extra interpreters from production edge hosts if policy allows it.

## 9. Security Notes — Defense Checklist

| Control area | Verify | Remediate |
|:---|:---|:---|
| Updates | Supported release; recent security upgrades | Enable auto security updates |
| SSH | `sshd -T` shows no password/root login | Keys + AllowUsers + firewall |
| Firewall | Default deny; minimal allows | UFW/nft rules reviewed |
| MAC | Enforcing profiles/labels | Fix denials properly, don't disable MAC |
| Sudo | No broad `NOPASSWD: ALL` | Scope commands, use groups |
| SUID/SGID inventory | Periodic review of special bits | Remove unnecessary setuid |
| World-writable dirs | Especially cron/backup paths | Fix ownership & modes |
| Logs | auth + journal retained/forwarded | Note 28 practices |
| Backups | Encrypted + restore-tested | Note 21 practices |
| Firewall | Default deny; documented allows | Note 27 rules |
| Secrets | No keys in web roots or world-readable homes | `600` keys, vault/HSM |

```bash
# Defensive audit snippets (authorized admin)
sshd -T | egrep 'permitrootlogin|passwordauthentication'
sudo ufw status verbose
getenforce 2>/dev/null; sudo aa-status 2>/dev/null | head
find /usr -perm -4000 -type f 2>/dev/null | head   # inventory only
sudo grep -R "NOPASSWD" /etc/sudoers /etc/sudoers.d 2>/dev/null
```

This SUID binary inventory is for **reduction and monitoring** on systems you administer, not a recipe list for abuse.

### Defense-in-depth stack
```
Users/Apps
   │  DAC (chmod) + sudo RBAC
   ▼
MAC (AppArmor/SELinux)
   │
   ▼
Kernel hardening (ASLR, sysctl)
   │
   ▼
Host firewall (note 27) + Fail2Ban
   │
   ▼
Network edge / WAF / VPN
```
