## Key Terms

You'll see these words throughout the lesson.

| Term | Plain meaning |
|:---|:---|
| Block device | A disk or partition the system reads/writes (`/dev/sda`) |
| Partition | A slice of a disk treated as a unit |
| File system | The format that organizes files on a partition (ext4, xfs) |
| Mount | Attaching a filesystem into the directory tree |
| `/etc/fstab` | The table of filesystems to mount at boot |
| LVM | Logical Volume Manager: flexible, resizable volumes over disks |
| `lsblk` / `df` / `du` | List block devices / free space / space used |

## 1. Linux Storage Stack — From Disk to Directory Tree

Data is stored on a block device (disk, LV, loop), formatted with a file system, then mounted into a directory within the single tree (`/`).

```text
hardware → partition / LV --mkfs--> filesystem --mount--> /mountpoint
```

Administrators work with `lsblk` for topology, `blkid` for UUIDs and types, and `/etc/fstab` for boot persistence. Wrong fstab entries can prevent boot; always test with `mount -a`.

```
/dev/nvme0n1
 ├─ nvme0n1p1  →  /boot/efi   (vfat)
 ├─ nvme0n1p2  →  /boot       (ext4)
 └─ nvme0n1p3  →  LVM PV
                      ├─ vg0-root → /       (ext4)
                      ├─ vg0-home → /home  (ext4)
                      └─ vg0-swap → [swap]
```

| Layer | Tools | Key files |
|:---|:---|:---|
| Discovery | `lsblk`, `fdisk -l`, `parted -l` | `/dev/*` |
| Format | `mkfs.ext4`, `mkfs.xfs`, `mkswap` | FS superblock |
| Mount | `mount`, `umount`, `findmnt` | `/etc/fstab`, `/proc/mounts` |
| LVM | `pvcreate`, `vgcreate`, `lvcreate` | `/etc/lvm/` metadata |

## 2. Partitioning — MBR, GPT, `fdisk` & `parted`

Modern disks use GPT (GUID Partition Table); legacy MBR still shows up on old VMs. `fdisk` (interactive) and `parted` (scriptable) are the standard tools.

Always confirm the device name (`/dev/sdb` vs `/dev/sda`) before a destructive operation. Use `partprobe` or reboot after partition table changes.

```bash
# Topology
lsblk -f
sudo fdisk -l
sudo parted -l

# GPT partition with parted (example — DESTRUCTIVE on wrong disk)
sudo parted /dev/sdb --script mklabel gpt
sudo parted /dev/sdb --script mkpart primary ext4 1MiB 100%
sudo partprobe /dev/sdb

# Interactive fdisk
sudo fdisk /dev/sdb    # n=new, p=print, w=write, q=quit
```

| Scheme | Max partitions | Boot firmware | Notes |
|:---:|:---:|:---|:---|
| MBR | 4 primary (+ extended) | BIOS | Legacy |
| GPT | Very large | UEFI | Preferred today |

## 3. File System Types — ext4, XFS & swap

Choose a filesystem based on the workload: ext4 for general purpose, XFS for large files or the RHEL default, vfat for the ESP, and swap for virtual memory.

| FS | Typical use | Create |
|:---|:---|:---|
| ext4 | General purpose root/home | `mkfs.ext4` |
| XFS | Large files / RHEL default | `mkfs.xfs` |
| vfat | EFI System Partition | `mkfs.vfat -F 32` |
| swap | Virtual memory / hibernation | `mkswap` |

Note the label or UUID for fstab: device names (`/dev/sda1`) can reorder after hardware changes.

```bash
sudo mkfs.ext4 -L datavol /dev/sdb1
sudo mkfs.xfs /dev/vg0/lv_data
sudo mkswap /dev/vg0/lv_swap
sudo swapon /dev/vg0/lv_swap

blkid
lsblk -f
```

## 4. Mount, Umount & `/etc/fstab`

`mount` attaches a filesystem to an empty directory. `/etc/fstab` defines automatic mounts at boot.

The fstab format:

```text
device             mountpoint   type   options            dump   fsck
UUID=1234-abcd     /data        ext4   defaults,nofail    0      2
```

Use `nofail` for non-critical removable media on servers. Use `UUID=` over `/dev/sdX`. Test with `sudo mount -a` after every fstab edit.

```bash
# Manual mount
sudo mkdir -p /mnt/data
sudo mount /dev/sdb1 /mnt/data
findmnt /mnt/data
mount | grep /mnt/data

# Umount (busy → stop processes using path)
sudo umount /mnt/data
sudo fuser -vm /mnt/data

# /etc/fstab example
# UUID=abc-123-def   /mnt/data   ext4   defaults,nofail   0   2
sudo mount -a          # apply fstab without reboot
```

| Mount option | Effect |
|:---|:---|
| `defaults` | rw, suid, dev, exec, auto, nouser, async |
| `noexec` | Block execution from the mount (upload dirs) |
| `nosuid` | Ignore setuid bits on the FS |
| `nodev` | Ignore device files on the FS |
| `ro` | Read-only |
| `nofail` | Boot continues if the mount fails |

## 5. LVM — Logical Volume Manager

LVM is an abstraction layer above partitions:

```text
PV (Physical Volume)  →  VG (Volume Group)  →  LV (Logical Volume)
```

Its advantages: online resize, snapshots, and striping (advanced).

Workflow: partition type `8e` (MBR) or GPT `8300` Linux LVM, then `pvcreate` → `vgcreate` → `lvcreate` → `mkfs` → mount.

```bash
# Create stack (lab disk /dev/sdb1 prepared)
sudo pvcreate /dev/sdb1
sudo vgcreate vg_data /dev/sdb1
sudo lvcreate -L 50G -n lv_archive vg_data
sudo mkfs.ext4 /dev/vg_data/lv_archive
sudo mkdir -p /archive
echo '/dev/vg_data/lv_archive  /archive  ext4  defaults  0  2' | sudo tee -a /etc/fstab
sudo mount -a

# Extend LV + filesystem (ext4)
sudo lvextend -L +20G /dev/vg_data/lv_archive
sudo resize2fs /dev/vg_data/lv_archive

# Inspect
pvs; vgs; lvs
sudo lvdisplay
```

| Command | Purpose |
|:---|:---|
| `pvcreate` | Init a partition as a PV |
| `vgcreate` | Group PVs into a VG |
| `lvcreate` | Allocate an LV from a VG |
| `lvextend` / `lvreduce` | Resize an LV |
| `resize2fs` / `xfs_growfs` | Grow the FS to fill the LV |

## 6. Capacity, Usage & Integrity

`df -hT` shows free space per mount. `du -sh` shows directory size. `fsck` checks and repairs a filesystem; unmount it first, except for a root filesystem that needs careful handling.

Monitor inode exhaustion (`df -i`) on mail/cache servers. Schedule filesystem checks via the fstab pass field or systemd timers.

```bash
df -hT
df -i
du -sh /var/log/* 2>/dev/null | sort -h | tail

# Offline check (FS must be unmounted)
sudo umount /dev/sdb1
sudo fsck -f /dev/sdb1

# Find large files quickly
sudo find /var -xdev -type f -size +100M -ls 2>/dev/null | head
```

## 7. Security Notes — Defense / Privilege Paths

Mount options (`noexec`, `nosuid`, `nodev`) are security controls, not cosmetic flags. Upload directories and network shares should be locked down.

World-writable mounts with `exec` are a classic webshell drop path. Keep `/etc/fstab` root-owned `644` and treat remote NFS/SMB content as untrusted.

| Risk | Mechanism | Defense |
|:---|:---|:---|
| World-writable mount + `exec` | Drop webshells on `/mnt/uploads` | `noexec,nosuid,nodev` |
| NFS/SMB mount as root | Remote content trusted like local | `nosuid,nodev`; network ACLs |
| `/etc/fstab` writable by users | Boot-time root compromise | root-owned `644`; configuration management |
| Full disk | Log/cache fill causes a DoS | Quotas; logrotate; alerts on `df` |
| LVM snapshot abuse (admin) | Forensic copies of sensitive LV | RBAC on LVM commands |

```bash
# Defensive mount audit
findmnt -lo TARGET,OPTIONS,SOURCE
grep -v '^#' /etc/fstab
mount | grep -E 'nosuid|noexec'
```

## 8. Quick Reference Cheatsheet

```bash
# Discovery
lsblk -f
blkid
sudo fdisk -l

# Format & swap
sudo mkfs.ext4 /dev/sdb1
sudo mkswap /dev/sdb2 && sudo swapon /dev/sdb2

# Mount
sudo mount /dev/sdb1 /mnt/data
sudo umount /mnt/data
sudo mount -a

# LVM
sudo pvcreate /dev/sdb1
sudo vgcreate vg0 /dev/sdb1
sudo lvcreate -L 10G -n lv0 vg0
pvs && vgs && lvs

# Space
df -hT
du -sh /path
```
