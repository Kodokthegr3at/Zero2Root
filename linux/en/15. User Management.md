## 1. Overview: Why User Management Matters

User management is a fundamental part of Linux system administration. Administrators frequently need to create new user accounts for team members, add users to specific groups to enforce access controls, and run commands as a different user for tasks that need different privileges.

From a cybersecurity standpoint, understanding user management matters for identifying privilege escalation opportunities, finding misconfigured permissions, and performing system auditing and troubleshooting.

### The `/etc/shadow` File

```bash
# Regular user — CANNOT read /etc/shadow
$ cat /etc/shadow
cat: /etc/shadow: Permission denied

# With sudo — CAN read /etc/shadow
$ sudo cat /etc/shadow
root:<SNIP>:18395:0:99999:7:::
daemon:*:17737:0:99999:7:::
bin:*:17737:0:99999:7:::
```

> `/etc/shadow` stores encrypted password hashes for every user account. It is readable and writable only by root, to prevent unauthorized access to authentication data.

## 2. `sudo`, Execute as Another User

`sudo` (superuser do) lets permitted users run commands with another user's privileges, typically root's. It's the safe way to perform administrative tasks without logging in as root directly, and it's considered a security best practice.

```bash
# Run a single command as root
$ sudo cat /etc/shadow

# Run command as specific user
$ sudo -u alex cat /home/alex/secret.txt

# Open a root shell
$ sudo -s
$ sudo su

# Check what sudo privileges current user has
$ sudo -l

# Run with environment preserved
$ sudo -E command
```

> Pentesting note: `sudo -l` is one of the first commands to run after gaining access to a system. It shows which commands you can run with elevated privileges without needing to know the root password.

## 3. `su`, Switch User

`su` (switch user) fully switches to another user's session. Unlike `sudo`, which runs a single command, `su` opens a new shell as the target user. It requires the target user's password, unless run by root.

```bash
# Switch to root (requires root password)
$ su
Password:
root@hostname#

# Switch to specific user
$ su alex
Password:
alex@hostname$

# Switch with full login environment (recommended)
$ su - alex

# Switch to root with login environment
$ su -
```

### `su` vs `sudo`: Key Difference

```
sudo command          →  runs ONE command as root, then back to your user
su                    →  opens a NEW SHELL as another user (stays until exit)
su -                  →  full login shell (loads target user's env variables)
sudo su               →  switch to root shell using sudo privileges
```

## 4. `useradd`, Create a New User

`useradd` creates a new user account. When a user is created, the system automatically creates a home directory, assigns a UID, and applies default settings from `/etc/default/useradd`.

```bash
# Create a basic new user
$ sudo useradd alex

# Create user WITH home directory (-m) and default shell (-s)
$ sudo useradd -m -s /bin/bash alex

# Create user with specific UID (-u) and GID (-g)
$ sudo useradd -m -u 1500 -g developers alex

# Create user with comment/description (-c)
$ sudo useradd -m -c "Alex - Developer" alex

# Create user and add to supplementary groups (-G)
$ sudo useradd -m -G sudo,docker alex

# Create system user (no home dir, for services)
$ sudo useradd --system --no-create-home serviceaccount
```

| Flag | Function |
|------|----------|
| `-m` | Create home directory |
| `-s` | Set default shell |
| `-u` | Set specific UID |
| `-g` | Set primary group |
| `-G` | Add to supplementary groups |
| `-c` | Add comment/description |
| `-e` | Set account expiry date |

## 5. `userdel`, Delete a User

`userdel` deletes a user account from the system. Use the `-r` flag to also remove the home directory and mail spool. Without `-r`, the user's files remain on the filesystem.

```bash
# Delete user only (home directory remains)
$ sudo userdel alex

# Delete user AND their home directory + mail spool
$ sudo userdel -r alex

# Force delete even if user is logged in
$ sudo userdel -f alex
```

> Always use `userdel -r` carefully. It permanently deletes the user's home directory and every file inside it.

## 6. `usermod`, Modify a User

`usermod` modifies an existing user account. It's the most flexible tool for managing users: it can change a username, shell, groups, home directory, and more.

```bash
# Add user to a supplementary group
$ sudo usermod -aG docker alex
#                  ↑
#                  -a = append (IMPORTANT: without -a, existing groups are REPLACED)

# Add user to multiple groups
$ sudo usermod -aG sudo,docker,developers alex

# Change user's primary group
$ sudo usermod -g developers alex

# Change username
$ sudo usermod -l newname alex

# Change home directory
$ sudo usermod -d /new/home alex

# Change default shell
$ sudo usermod -s /bin/zsh alex

# Lock a user account
$ sudo usermod -L alex

# Unlock a user account
$ sudo usermod -U alex

# Set account expiry date
$ sudo usermod -e 2025-12-31 alex
```

> Critical: always use `-aG` (append + group), never just `-G` alone. Using `-G` without `-a` removes the user from all other groups first.

---

## 7. `addgroup`, Add a Group

`addgroup` creates a new group on the system. Groups manage access to files and directories collectively, since every group member shares the same permissions.

```bash
# Create a new group
$ sudo addgroup developers

# Create group with specific GID
$ sudo addgroup --gid 1500 developers

# Add existing user to existing group
$ sudo addgroup alex developers
```

---

## 8. `delgroup`, Remove a Group

`delgroup` removes a group from the system. A group cannot be deleted while it's still the primary group of any user.

```bash
# Remove a group
$ sudo delgroup developers

# Remove user from a group (without deleting the group)
$ sudo delgroup alex developers
```

---

## 9. `passwd`, Change a Password

`passwd` changes a user's password. Regular users can only change their own password, while root can change anyone's password without knowing the old one.

```bash
# Change YOUR OWN password
$ passwd

# Change another user's password (requires root)
$ sudo passwd alex

# Lock a user's password (disable login)
$ sudo passwd -l alex

# Unlock a user's password
$ sudo passwd -u alex

# Force user to change password on next login
$ sudo passwd -e alex

# Check password status
$ sudo passwd -S alex
```

## Key System Files

| File | Contents |
|------|----------|
| `/etc/passwd` | List of all users (username, UID, GID, home, shell) |
| `/etc/shadow` | Encrypted password hashes (root only) |
| `/etc/group` | List of all groups and their members |
| `/etc/sudoers` | Sudo privilege configuration per user/group |

## Practical Workflow Example

```bash
# Create new employee "alex" with full setup
$ sudo useradd -m -s /bin/bash -c "Alex - Developer" alex

# Set password
$ sudo passwd alex

# Add to necessary groups
$ sudo usermod -aG sudo,docker,developers alex

# Verify
$ id alex
uid=1001(alex) gid=1001(alex) groups=1001(alex),27(sudo),998(docker),1500(developers)

# Check home directory was created
$ ls -la /home/alex/

# Later: lock account if employee leaves
$ sudo passwd -l alex
$ sudo usermod -e 2025-01-01 alex
```

## Quick Reference Cheatsheet

```bash
# ── CREATE ──────────────────────────────────────────────
sudo useradd -m -s /bin/bash username    # create user + home
sudo passwd username                      # set password
sudo addgroup groupname                   # create group
sudo usermod -aG groupname username       # add user to group

# ── READ / CHECK ────────────────────────────────────────
id username                               # show UID, GID, groups
whoami                                    # current user
groups username                           # show user's groups
cat /etc/passwd | grep username           # user info
sudo cat /etc/shadow | grep username      # password hash
sudo -l                                   # check sudo privileges

# ── MODIFY ──────────────────────────────────────────────
sudo usermod -aG group user               # add to group (SAFE)
sudo usermod -s /bin/zsh username         # change shell
sudo usermod -L username                  # lock account
sudo usermod -U username                  # unlock account
sudo passwd -e username                   # force pw change on login

# ── DELETE ──────────────────────────────────────────────
sudo userdel -r username                  # delete user + home
sudo delgroup groupname                   # delete group

# ── PRIVILEGE ESCALATION CHECK (pentesting) ─────────────
sudo -l                                   # what can I sudo?
cat /etc/passwd                           # list all users
cat /etc/group                            # list all groups
find / -perm -4000 2>/dev/null            # find SUID files
```
