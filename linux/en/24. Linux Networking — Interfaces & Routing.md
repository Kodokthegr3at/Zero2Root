## Key Terms

You'll see these words throughout the lesson.

| Term | Plain meaning |
|:---|:---|
| Interface | A network connection point (`eth0`, `wlan0`, `lo`) |
| IP address | The host's address on a network |
| Routing table | The rules deciding where each packet goes |
| Default gateway | The router used for anything not on the local network |
| `ip` command | The modern tool to view/configure addresses and routes |
| NetworkManager | A service that manages connections on desktops/servers |
| Loopback (`lo`) | The virtual interface a machine uses to talk to itself |

## 1. Linux Host Networking — Layers & Objects

Every network interface (physical, bridge, VLAN, tun) carries **link layer** state, one or more **IP addresses**, and a **routing table** that determines the outbound gateway.

```text
app → socket → route lookup → interface → link
```

Modern admins use **`ip`** from iproute2. Configuration may be managed by **NetworkManager**, **systemd-networkd**, or static files (**netplan** on Ubuntu, **`/etc/network/interfaces`** on Debian).

```
┌──────────────────────────────────────────┐
│ Applications (curl, ssh, nginx)          │
├──────────────────────────────────────────┤
│ Sockets (TCP/UDP)                        │
├──────────────────────────────────────────┤
│ Routing table  ← ip route                │
├──────────────────────────────────────────┤
│ IP addresses   ← ip addr                 │
├──────────────────────────────────────────┤
│ Interfaces     ← ip link (eth0, wlan0)   │
└──────────────────────────────────────────┘
```

| Object | Show | Configure |
|:---|:---|:---|
| Interface | `ip link` | `ip link set`, NM, netplan |
| IPv4/IPv6 | `ip addr` | `ip addr add`, DHCP |
| Routes | `ip route` | `ip route add`, default gw |
| DNS | `resolvectl`, `/etc/resolv.conf` | NM, resolved |

## 2. The `ip` Command — Link, Address, Route

Replace **`ifconfig`/`route`** with **`ip`** for day-to-day work. Changes made through `ip` are usually runtime-only unless persisted in NM, netplan, or interfaces. Document every manual change.

```bash
# Link layer — up/down, MTU, MAC
ip link show
ip link set eth0 up
ip link set eth0 mtu 1500

# Addresses
ip addr show dev eth0
ip addr add 10.10.14.50/24 dev eth0
ip addr del 10.10.14.50/24 dev eth0

# Routing
ip route show
ip route add default via 10.10.14.1 dev eth0
ip route add 192.168.100.0/24 via 10.10.14.254 dev eth0
ip route del 192.168.100.0/24

# Neighbor cache (ARP/NDP)
ip neigh show
```

| Command | Purpose |
|:---|:---|
| `ip -br a` | Brief address summary |
| `ip -4 route get 8.8.8.8` | Which path to a destination |
| `ip link set eth0 down` | Admin-down an interface |

The kernel picks the most specific route through **Longest Prefix Match (LPM)**:

Out of all routes that contain the destination, the kernel picks the one with the longest prefix, because it is the most specific.

## 3. Legacy Tools — `ifconfig` & `route`

Still shows up on older machines and in CTF boxes. Part of the **`net-tools`** package; prefer **`ip`** on systems you manage yourself. Know the syntax so you can read old documentation and compromised hosts, but do not build new automation on deprecated tools.

```bash
ifconfig -a
ifconfig eth0 10.10.14.50 netmask 255.255.255.0 up
route -n
route add default gw 10.10.14.1
```

## 4. NetworkManager — `nmcli`

**NetworkManager** (`NetworkManager.service`) manages Wi-Fi, Ethernet, and VPN on modern desktops and servers. Use **`nmcli`** for scripting. Connection profiles are stored under `/etc/NetworkManager/system-connections/` (root-readable, keep the permissions tight).

```bash
nmcli device status
nmcli connection show
nmcli connection show "Wired connection 1"

# Static IPv4 example (lab)
nmcli con mod "Wired connection 1" \
  ipv4.method manual \
  ipv4.addresses 10.10.14.50/24 \
  ipv4.gateway 10.10.14.1 \
  ipv4.dns "10.10.14.1 1.1.1.1"
nmcli con up "Wired connection 1"

# Wi-Fi scan (authorized)
nmcli dev wifi list
nmcli dev wifi connect SSID password 'passphrase'
```

| Subcommand | Use |
|:---|:---|
| `nmcli dev` | Device state |
| `nmcli con` | Connection profiles |
| `nmcli networking off/on` | Global toggle |

## 5. Declarative Config — netplan & `/etc/network/interfaces`

Ubuntu uses **netplan** (YAML); classic Debian uses **`/etc/network/interfaces`**. Both persist across reboots, unlike plain `ip` runtime changes. Prefer `netplan try` so a bad YAML file rolls back automatically. Keep secrets out of world-readable YAML.

### Ubuntu netplan (`/etc/netplan/*.yaml`)

```yaml
# /etc/netplan/01-lab.yaml
network:
  version: 2
  ethernets:
    eth0:
      dhcp4: false
      addresses:
        - 10.10.14.50/24
      routes:
        - to: default
          via: 10.10.14.1
      nameservers:
        addresses: [10.10.14.1, 1.1.1.1]
```

```bash
sudo netplan try          # safe test with rollback
sudo netplan apply
```

### Debian classic (`/etc/network/interfaces`)

```
auto eth0
iface eth0 inet static
    address 10.10.14.50
    netmask 255.255.255.0
    gateway 10.10.14.1
    dns-nameservers 10.10.14.1
```

```bash
sudo ifup eth0
sudo ifdown eth0
sudo systemctl restart networking   # distro-dependent
```

## 6. Hostname & Local Name Table

**Hostname** is the host's identity; **`/etc/hosts`** overrides DNS locally. Consistent naming helps logging, TLS certificate planning, and inventory. Avoid duplicate names in AD/LDAP environments.

```bash
hostname
hostnamectl status
sudo hostnamectl set-hostname srv01.lab.internal

cat /etc/hostname
cat /etc/hosts
```

## 7. Security Notes — Defense & Exposure

Secondary IPs, Wi-Fi on servers, and misconfigured static routes can open unexpected paths. IPv6 left enabled often becomes a bypass for IPv4-only filters.

| Misconfiguration | Impact | Defense |
|:---|:---|:---|
| Secondary IP on `0.0.0.0` services | Unexpected listener binding | Bind services to specific IPs |
| Weak Wi-Fi credentials on a server | Lateral entry point | Disable Wi-Fi on servers, use wired management |
| Static routes pointing at an attacker gateway | Traffic hijack | Route change control, monitoring |
| World-accessible NetworkManager APIs | Remote reconfiguration | Localhost-only D-Bus policies |
| IPv6 left enabled while IPv4 is filtered | Bypass via v6 | Dual-stack firewall (see note 27) |

```bash
# Defensive inventory
ip -br link
ip -br addr
ip route show table all | head
nmcli -f GENERAL.STATE,IP4.ADDRESS dev show
ss -tulnp | grep LISTEN
```

Connectivity troubleshooting is covered in note 25. DNS/DHCP services are covered in note 19.
