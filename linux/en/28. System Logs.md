## 1. Linux Logging Architecture

Modern Linux typically runs two telemetry paths in parallel:

1. `systemd-journald`, structured binary logs queried through `journalctl`.
2. `rsyslog` / `syslog-ng`, classic text files under `/var/log/`.

Together they record authentication, kernel events, service stdout/stderr, and application messages. Defenders treat logs as evidence; integrity and retention matter as much as content.

```
 Kernel / services / apps
            │
            ▼
     ┌──────────────┐
     │ journald     │────► journalctl queries
     └──────┬───────┘
            │ (forward)
            ▼
     ┌──────────────┐
     │ rsyslog      │────► /var/log/*.log
     └──────┬───────┘
            │
            ▼
     SIEM / remote syslog (optional)
```

## 2. Syslog Facility & Severity (Formal)

Classic syslog labels each message with a facility f and severity p:

```text
priority = 8 × facility + severity

Example: facility 4 (auth), severity 2 (crit)  →  8 × 4 + 2 = 34
```

| Severity p | Name | Meaning |
|:---:|:---|:---|
| 0 | emerg | System unusable |
| 1 | alert | Immediate action required |
| 2 | crit | Critical conditions |
| 3 | err | Errors |
| 4 | warning | Warnings |
| 5 | notice | Normal but significant |
| 6 | info | Informational |
| 7 | debug | Debug |

Common facilities: `auth`/`authpriv`, `kern`, `daemon`, `cron`, `local0-7`.

```bash
# Emit a test message (lab)
logger -p auth.notice "lab test auth notice from $(whoami)"
```

## 3. Key Files under `/var/log`

| File | Distro family | Contents |
|:---|:---|:---|
| `auth.log` | Debian/Ubuntu | SSH, sudo, pam, user auth |
| `secure` | RHEL family | Same role as `auth.log` |
| `syslog` / `messages` | Debian / RHEL | General system events |
| `kern.log` | Debian | Kernel messages (text) |
| `wtmp` / `btmp` | All | Login success / failure (binary) |
| `lastlog` | All | Per-user last login |
| `apache2/` / `nginx/` | Web stacks | Access + error |
| `audit/` | auditd hosts | SELinux/audit trails |

```bash
ls -lah /var/log
sudo tail -n 50 /var/log/auth.log     # Debian family
sudo tail -n 50 /var/log/secure       # RHEL family
```

| Tool | Reads | Use |
|:---|:---|:---|
| `last` | `wtmp` | Successful logins |
| `lastb` | `btmp` | Failed logins (root) |
| `who` / `w` | `utmp` | Current sessions |
| `zgrep` | `*.gz` | Search rotated logs |

## 4. `journalctl` — Querying the Journal

`journalctl` filters by unit, time, priority, and boot session.

Prefer time-bounded queries during incidents to avoid drowning in noise.

```bash
journalctl -f                              # follow
journalctl -b                              # current boot
journalctl -u ssh.service                  # one unit
journalctl -u nginx --since "1 hour ago"
journalctl --since "2026-08-01" --until "2026-08-16"
journalctl -p err..emerg                   # severities
journalctl -k                              # kernel via journal
journalctl --disk-usage
journalctl --no-pager -o short-iso
```

Persistent journals: enable storage under `/var/log/journal/` and set retention in `/etc/systemd/journald.conf` (`SystemMaxUse=`, `MaxRetentionSec=`).

## 5. `dmesg` — Kernel Ring Buffer

`dmesg` reads the kernel's circular buffer: hardware probes, OOM events, driver errors, segfault notices.

Ring buffers are finite and volatile; critical kernel events should also land in the journal or syslog for longer retention.

```bash
sudo dmesg -T
sudo dmesg -l err,crit
sudo dmesg -T | grep -iE 'error|fail|oom|segfault'
```

## 6. `logrotate` — Retention Without Filling Disks

Without rotation, logs fill the disk and cause an availability DoS. `logrotate` archives, compresses, and discards old generations.

Balance forensic need (longer retention) against disk cost. Ship copies off-box before aggressive deletion.

| Directive | Meaning |
|:---|:---|
| `daily` / `weekly` | Cadence |
| `rotate N` | Keep N generations |
| `compress` | gzip old logs |
| `delaycompress` | Compress starting next cycle |
| `missingok` | Skip if the file is absent |
| `notifempty` | Skip empty files |

Paths: `/etc/logrotate.conf`, `/etc/logrotate.d/*`.

```bash
sudo logrotate -d /etc/logrotate.conf     # debug / dry
sudo logrotate -f /etc/logrotate.conf     # force (careful)
zgrep "Failed password" /var/log/auth.log.*.gz
```

## 7. Defensive Hunting — Auth & Privilege Telemetry

Detection examples, not anti-forensics: SSH brute force, sudo abuse, off-hours logins.

These one-liners help administrators and blue teams on systems they own. Correlate them with firewall/Fail2Ban data and ticket timelines.

```bash
# Top sources of failed SSH passwords (Debian auth.log)
sudo grep "Failed password" /var/log/auth.log \
  | awk '{print $(NF-3)}' | sort | uniq -c | sort -nr | head

# Successful sudo commands (audit trail)
sudo grep "COMMAND=" /var/log/auth.log | tail -n 30

# Session history
last -n 20
sudo lastb -n 20

# Journal view of ssh
journalctl -u ssh --since "24 hours ago" | grep -i fail
```

Web defenders also watch for spikes of `404`/`401`/`500` in access logs, which indicate scanning or app faults, without treating logs as an exploit channel.

## 8. Security Notes — Defense / Hardening

| Risk | Impact | Defense |
|:---|:---|:---|
| Logs only on the host | An attacker with root can alter local files | Remote syslog/SIEM; append-only / WORM where possible |
| World-readable auth logs | Credential-adjacent leakage | Restrict `/var/log` permissions; separate `authpriv` |
| No time sync | Broken timelines | NTP/chrony; store timestamps in UTC |
| Overly short retention | Blind investigations | Align with policy; keep offsite copies |
| Untrusted apps write user-controlled strings into logs | Confusion or secondary bugs if logs are mishandled | Never `include` log files in app code; sanitize displays; treat logs as data, not code |
| Disk full from verbose debug | Availability outage | `logrotate`, journal size caps, rate limits |
| Ignoring `btmp`/`lastb` | Missed brute force | Alert on thresholds; Fail2Ban |

### Integrity practices
1. Forward `auth` and critical units to a collector over TLS.
2. Restrict who can run `journalctl` as non-root (systemd ACLs/groups, carefully).
3. Monitor abrupt journal gaps (time jumps, wiped ranges) as incident signals; investigate via backups/SIEM rather than "practicing" a wipe.
4. Protect `auditd` rules on high-assurance hosts.
5. Document chain-of-custody for exported evidence files (hashes).

```bash
# Health / posture
journalctl --disk-usage
timedatectl status
sudo ss -tulnp | grep -E 'syslog|514'
```

## 9. Quick Reference Cheatsheet

```bash
# Live tails
sudo tail -f /var/log/auth.log
sudo tail -f /var/log/syslog
journalctl -f

# Journal filters
journalctl -u ssh.service -p err..warning
journalctl -b -p err

# Kernel
sudo dmesg -T | tail

# Sessions
who; w; last -n 10

# Compressed search
zgrep -H "error" /var/log/syslog.*.gz
```
