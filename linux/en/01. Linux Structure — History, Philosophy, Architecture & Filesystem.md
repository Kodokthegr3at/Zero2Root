## 1. What is Linux?

Linux is an operating system, just like Windows, macOS, iOS, or Android. An OS is software that manages all the hardware resources of a computer and handles communication between applications and hardware.

What makes Linux different is that it comes in many distributions (distros), versions of Linux tailored to different needs. Linux matters in cybersecurity for a few reasons.

- It's free and open source, and anyone can modify the source code.
- It's rarely affected by malware compared to other operating systems.
- It's stable and performs well.
- It runs on servers, mainframes, routers, smart TVs, game consoles, and Android.

### Popular Linux Distributions

| Distro | Focus | Best for |
|--------|-------|----------|
| Ubuntu | User-friendly | Beginners, desktops |
| Debian | Stability | Servers, development |
| Parrot OS | Security & privacy | Pentesting, CTF |
| Kali Linux | Offensive security | Penetration testing |
| Fedora | Cutting-edge | Developers |
| Arch Linux | Customization | Advanced users |
| CentOS / RHEL | Enterprise | Production servers |
| Manjaro | Ease of use | Desktop users |

Note: HackTheBox Academy uses Parrot OS (Pwnbox), a Debian-based distro focused on security, privacy, and development.

## 2. History of Linux

Linux didn't appear out of nowhere. A long chain of events led up to it, and understanding that history matters because many Linux concepts are rooted in the much older Unix philosophy.

### Timeline

```
1970  ── Unix OS released by Ken Thompson & Dennis Ritchie (AT&T)
  │
1977  ── BSD (Berkeley Software Distribution) released
  │        └── AT&T lawsuit limits BSD development
  │
1983  ── Richard Stallman starts the GNU Project
  │        └── Goal: create a free Unix-like OS
  │        └── GNU General Public License (GPL) created
  │
1991  ── Linus Torvalds (Finnish student) starts Linux kernel
  │        └── Goal: new, free OS kernel
  │        └── Written in C, originally prohibited commercial use
  │
Now   ── Linux kernel: 23+ million lines of code
           Licensed under GNU GPL v2
           600+ distributions available
           Powers most of the internet's servers
           Android (Linux-based) = most installed OS worldwide
```

| Year | Event |
|------|-------|
| 1970 | Unix released by Ken Thompson & Dennis Ritchie at AT&T |
| 1977 | BSD released, its development limited by an AT&T lawsuit |
| 1983 | GNU Project started by Richard Stallman |
| 1989 | GNU General Public License (GPL) created |
| 1991 | Linux kernel created by Linus Torvalds, then 21 years old |
| Present | 23+ million lines of code, 600+ distros, the most installed OS globally |

## 3. Linux Philosophy

The Linux philosophy centers on simplicity, modularity, and openness. Linux favors building small programs that do one task very well, then combining them to handle complex operations.

### 5 Core Principles

| # | Principle | Description |
|---|-----------|-------------|
| 1 | Everything is a file | All system resources (hardware, processes, network connections) are represented as files, readable and writable with the same standard tools |
| 2 | Small, single-purpose programs | Linux provides many small tools that each do one thing very well |
| 3 | Ability to chain programs | Small programs can be chained together with pipes to handle large, complex tasks |
| 4 | Avoid captive user interfaces | Linux is designed to work primarily through the shell/terminal, giving the user full control over the OS |
| 5 | Configuration in text files | Configuration data is stored in text files, for example `/etc/passwd` holds all registered users |

These principles are why Linux works so well for cybersecurity: everything is transparent, scriptable, and composable.

## 4. Linux Components

Linux consists of several key components that work together to run the system.

| Component | Description |
|-----------|-------------|
| Bootloader | Code that guides the booting process to start the OS. Parrot Linux uses the GRUB bootloader |
| OS Kernel | The main OS component that manages I/O device resources at the hardware level |
| Daemons | Background services that keep functions like scheduling, printing, and multimedia working correctly |
| OS Shell | The interface between the OS and the user, where the user issues commands to the OS. Popular shells: Bash, Zsh, Fish, Ksh |
| Graphics Server | The graphical subsystem ("X" / X server) that lets graphical programs run locally or remotely |
| Window Manager | GUI desktop environments such as GNOME, KDE, MATE, Unity, Cinnamon, including file and web browsers |
| Utilities | Applications that perform specific functions for the user or for other programs |

## 5. Linux Architecture

The Linux OS can be broken down into 4 layers that communicate with each other from bottom to top.

```
┌─────────────────────────────────────────────────────┐
│                  SYSTEM UTILITY                      │
│   Makes all OS functionality available to the user   │
│   (commands, programs, libraries, man pages)         │
├─────────────────────────────────────────────────────┤
│                     SHELL                            │
│   Command-line interface (CLI) — user enters         │
│   commands to interact with the kernel               │
│   Bash / Zsh / Fish / Ksh                            │
├─────────────────────────────────────────────────────┤
│                     KERNEL                           │
│   Core of Linux — virtualizes and controls hardware  │
│   CPU, RAM, I/O, process management                  │
│   Gives each process its own virtual resources       │
├─────────────────────────────────────────────────────┤
│                    HARDWARE                          │
│   Physical components: CPU, RAM, HDD/SSD,            │
│   Network card, GPU, peripherals                     │
└─────────────────────────────────────────────────────┘
          ↕ each layer communicates with adjacent layers
```

| Layer | Description |
|-------|-------------|
| Hardware | Physical devices: RAM, hard drive, CPU, etc. |
| Kernel | The core of Linux; virtualizes and controls hardware resources, giving each process its own virtual resources |
| Shell | CLI (command-line interface), where the user enters commands to run kernel functions |
| System Utility | Makes all OS functionality available to the user |

## 6. Filesystem Hierarchy Standard (FHS)

Linux uses a tree-like directory structure documented in the Filesystem Hierarchy Standard (FHS). All directories start from the root `/`, like the trunk of a tree branching downward.

### Directory Tree

```
/ (root)
├── bin/      ← essential command binaries
├── boot/     ← bootloader, kernel
├── dev/      ← device files (hardware access)
├── etc/      ← system config files
├── home/     ← user home directories
│   └── cry0l1t3/
├── lib/      ← shared libraries for boot
├── media/    ← removable media (USB, CD)
├── mnt/      ← temporary mount points
├── opt/      ← optional / third-party software
├── proc/     ← virtual filesystem (process info)
├── root/     ← root user's home directory
├── run/      ← runtime data (PIDs, sockets)
├── sbin/     ← system admin binaries
├── sys/      ← virtual filesystem (kernel/device info)
├── tmp/      ← temporary files (cleared on boot)
├── usr/      ← user programs, libraries, man pages
└── var/      ← variable data (logs, mail, web files)
```

### Directory Reference Table

| Path | Description |
|------|-------------|
| `/` | Top-level root directory, contains all files needed to boot the OS |
| `/bin` | Essential command binaries (ls, cp, mv, cat, etc.) |
| `/boot` | Static bootloader, kernel executable, boot files |
| `/dev` | Device files for hardware access (disk, USB, etc.) |
| `/etc` | Local system and application configuration files |
| `/home` | Home directory for each user on the system |
| `/lib` | Shared library files required for system boot |
| `/media` | External removable media (USB drives, CDs) |
| `/mnt` | Temporary mount point for regular filesystems |
| `/opt` | Optional / third-party software |
| `/root` | Home directory for the root user |
| `/sbin` | System administration executables |
| `/tmp` | Temporary files, cleared on reboot |
| `/usr` | User programs, libraries, man pages |
| `/var` | Variable data: logs, emails, web files, cron |

### Pentesting-Relevant Directories

| Path | Pentesting Relevance |
|------|-----------------------|
| `/etc/passwd` | List of all users on the system |
| `/etc/shadow` | User password hashes (requires root) |
| `/etc/crontab` | Scheduled jobs, a potential privilege escalation path |
| `/tmp` | Writable by all users, often used for exploit staging |
| `/var/log` | System logs, traces of user activity and attacks |
| `/home` | May contain SSH keys, credentials, config files |
| `/root` | The root user's home, a target for privilege escalation |
| `/dev` | Device files, e.g. `/dev/null`, `/dev/shm` (RAM-based temp storage) |

## Quick Reference Cheatsheet

```bash
# Check Linux version and distro
uname -a                    # kernel version
cat /etc/os-release         # distro information
lsb_release -a              # distro details

# Explore filesystem hierarchy
ls /                        # list root directory
ls /etc/                    # system config files
ls /home/                   # user home directories
ls /var/log/                # system log files
cat /etc/passwd             # list all users
cat /etc/os-release         # current distro info

# Check shell in use
echo $SHELL                 # current shell path
cat /etc/shells             # all available shells
```
