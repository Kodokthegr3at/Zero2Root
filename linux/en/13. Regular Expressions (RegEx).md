## Key Terms

You'll see these words throughout the lesson.

| Term | Plain meaning |
|:---|:---|
| Regular expression | A pattern that describes which text to match |
| Literal | A character that matches itself (`a` matches `a`) |
| Metacharacter | A character with special meaning (`.`, `*`, `^`, `$`) |
| Character class | A set of allowed characters, like `[a-z]` |
| Quantifier | How many times something repeats (`*`, `+`, `{2,4}`) |
| Anchor | Ties a match to a position (`^` start, `$` end) |
| Capture group | Parentheses `( )` that remember part of a match |
| BRE vs ERE | Basic vs extended regex; `grep -E` enables the extended form |

## 1. What is RegEx?

A Regular Expression (RegEx) is a sequence of characters and symbols that form a search pattern. Think of RegEx as a highly customizable filter: it sifts through text to find exactly what you need.

RegEx can be used to:
- Search for text patterns with precision
- Replace text in bulk
- Validate input (emails, passwords, phone numbers)
- Filter output from other commands

RegEx is available across many programming languages and tools, including `grep`, `sed`, `awk`, Python, and JavaScript.

## 2. Grouping Operators

RegEx uses three types of brackets, each with a different job in defining a search pattern.

| Operator | Symbol | Description |
|----------|--------|-------------|
| Round brackets | `(a)` | Group parts of a regex. Inside them you can define further patterns to be processed together |
| Square brackets | `[a-z]` | Define a character class. Inside them, specify the list of characters to search for |
| Curly brackets | `{1,10}` | Define a quantifier. Specify how many times the previous pattern should repeat |
| OR operator | `\|` | Shows results when one of two expressions matches |
| AND operator | `.*` | Shows results only when both expressions are present and match in the specified order |

---

## 3. OR Operator (`|`)

The `|` (OR) operator searches for lines containing at least one of the given patterns. Using this with `grep` requires the `-E` (extended regex) flag.

```bash
# Search for lines containing "my" OR "false"
$ grep -E "(my|false)" /etc/passwd

lxd:x:105:65534::/var/lib/lxd/:/bin/false
pollinate:x:109:1::/var/cache/pollinate:/bin/false
mysql:x:116:120:MySQL Server,,:/nonexistent:/bin/false
```

```
Pattern:  (my|false)
              │
     ┌────────┴────────┐
     ▼                 ▼
   "my"             "false"
  matches?          matches?
     │                 │
     └────────┬─────────┘
              ▼
     Either one = SHOW LINE
```

> All 3 lines are shown because each line contains either `my` (mysql) or `false` (/bin/false), or both.

## 4. AND Operator (`.*`)

The `.*` (AND) operator only shows lines that contain both patterns in order. `.*` means "any character, any number of times" between the two patterns, so both words must exist in the same line.

```bash
# Search for lines containing BOTH "my" AND "false" (in that order)
$ grep -E "(my.*false)" /etc/passwd

mysql:x:116:120:MySQL Server,,:/nonexistent:/bin/false
```

```
Pattern:  (my.*false)
            │  │   │
            │  │   └── "false" must appear AFTER "my"
            │  └────── any characters in between (.*)
            └────────── "my" must appear first

mysql:x:116:120:MySQL Server,,:/nonexistent:/bin/false
  ↑ "my" found here              ↑ "false" found here → MATCH ✓

lxd:x:105:65534::/var/lib/lxd/:/bin/false
  ↑ no "my" found → NO MATCH ✗
```

### Alternative: Chained grep

```bash
# Same result using two grep pipes (AND logic)
$ grep -E "my" /etc/passwd | grep -E "false"

mysql:x:116:120:MySQL Server,,:/nonexistent:/bin/false
```

> Both approaches produce the same result. Chained `grep` is more readable, `.*` is more compact.

## 5. RegEx Metacharacters: Quick Reference

Metacharacters are special symbols in regex that define the structure of a search rather than acting as literal characters.

| Metacharacter | Meaning | Example |
|--------------|---------|---------|
| `.` | Any character (except newline) | `a.c` → `abc`, `a1c` |
| `*` | 0 or more of the previous character | `ab*` → `a`, `ab`, `abb` |
| `+` | 1 or more of the previous character | `ab+` → `ab`, `abb` |
| `?` | 0 or 1 of the previous character | `ab?` → `a`, `ab` |
| `^` | Beginning of line | `^root` |
| `$` | End of line | `bash$` |
| `[abc]` | One of the listed characters | `[abc]` → `a`, `b`, or `c` |
| `[^abc]` | A character not in the list | `[^abc]` → anything except a, b, c |
| `[a-z]` | All lowercase letters a to z | `[a-z]+` |
| `[0-9]` | All digits 0 to 9 | `[0-9]+` |
| `\d` | Digit (same as `[0-9]`) | `\d+` → `123` |
| `\w` | Word character (`[a-zA-Z0-9_]`) | `\w+` → `hello_123` |
| `\s` | Whitespace (space, tab) | `\s+` |
| `{n}` | Exactly n repetitions | `a{3}` → `aaa` |
| `{n,m}` | Between n and m repetitions | `a{2,4}` → `aa`, `aaa`, `aaaa` |
| `\` | Escape, next character is literal | `\.` → literal dot |

## 6. Practice Tasks: `/etc/ssh/sshd_config`

These exercises use `/etc/ssh/sshd_config`, a real SSH configuration file on Linux systems. It's good practice because this file is one of the ones most often reviewed during a system security audit.

| # | Task | Answer |
|---|------|--------|
| 1 | Show all lines that do not contain the `#` character | See below |
| 2 | Find all lines containing a word that starts with `Permit` | See below |
| 3 | Find all lines containing a word ending with `Authentication` | See below |
| 4 | Find all lines containing the word `Key` | See below |
| 5 | Find all lines beginning with `Password` and containing `yes` | See below |
| 6 | Find all lines ending with `yes` | See below |

### Solutions

```bash
# Task 1 — Lines NOT containing "#"
grep -v "#" /etc/ssh/sshd_config

# Task 2 — Lines with a word STARTING with "Permit"
grep -E "Permit\w+" /etc/ssh/sshd_config

# Task 3 — Lines with a word ENDING with "Authentication"
grep -E "\w+Authentication" /etc/ssh/sshd_config

# Task 4 — Lines containing the word "Key"
grep "Key" /etc/ssh/sshd_config

# Task 5 — Lines BEGINNING with "Password" AND containing "yes"
grep -E "^Password.*yes" /etc/ssh/sshd_config

# Task 6 — Lines ENDING with "yes"
grep -E "yes$" /etc/ssh/sshd_config
```

### Solution Breakdown

```
Task 1:  grep -v "#"
               │
               └── -v = invert match (exclude lines WITH #)

Task 2:  Permit\w+
         │      │
         │      └── \w+ = one or more word characters after "Permit"
         └── literal "Permit"

Task 3:  \w+Authentication
         │   │
         │   └── literal "Authentication" at the end
         └── \w+ = one or more word characters before it

Task 5:  ^Password.*yes
         │         │  │
         │         │  └── "yes" anywhere after
         │         └── .* = any characters in between
         └── ^ = must be at the START of line

Task 6:  yes$
         │  │
         │  └── $ = must be at the END of line
         └── literal "yes"
```

## 7. Security Note: ReDoS, WAF Bypasses & Forensic Regex

In both offensive and defensive cybersecurity work, regular expressions cut both ways.

1. Regular Expression Denial of Service (ReDoS): when a regex pattern contains nested quantifiers or overlapping alternations, like `(a+)+$` or `([a-zA-Z0-9]+)*`, an NFA-based (Nondeterministic Finite Automaton) regex engine can hit catastrophic backtracking. Processing an input like `aaaaaaaaaaaaaaaaaaaaaaaaaaaa!` then takes exponential time ($O(2^n)$), pinning the server's CPU and stalling the application (see *Mastering Regular Expressions*, Friedl).
2. WAF and filter evasion: loose input-validation regex can be bypassed. Newline anchors: a pattern like `^https?://.*` without the multiline flag can be bypassed with a newline `\n`. Case sensitivity: an attacker mixes letter case (`<sCrIpt>`) if the regex doesn't use `-i` / `(?i)`. Incomplete alternation: a blacklist filter for the SQLi keyword `UNION SELECT` can be bypassed with an inline comment, `UNION/**/SELECT`.
3. Forensic regex: regex patterns underpin SIEM detection rules, IDS/IPS signatures (Snort/Suricata), and YARA rules used to detect malware and exfiltration.

```bash
# ── CYBERSECURITY REGEX PATTERNS CHEATSHEET ──────────────────

# 1. IPv4 Address Matching
grep -E -o '([0-9]{1,3}\.){3}[0-9]{1,3}' /var/log/auth.log

# 2. Extract Base64 Strings (length >= 32)
grep -E -o '[A-Za-z0-9+/]{32,}={0,2}' access.log

# 3. MD5 (32 hex) / SHA256 (64 hex) Hash Detection
grep -E -i '\b[a-f0-9]{32}\b' hashes.txt      # MD5
grep -E -i '\b[a-f0-9]{64}\b' hashes.txt      # SHA-256

# 4. Detect SQL Injection attempts in Web Server Access Logs
grep -E -i "(union.*select|select.*from|exec\(|insert.*into|drop.*table)" /var/log/apache2/access.log

# 5. Extract URLs from source text
grep -E -o 'https?://[a-zA-Z0-9./?=_-]+' input.txt
```

## Quick Reference Cheatsheet

```bash
# Basic grep with regex
grep "pattern" file.txt               # literal search
grep -E "pattern" file.txt            # extended regex
grep -v "pattern" file.txt            # exclude pattern
grep -i "pattern" file.txt            # case insensitive

# OR / AND logic
grep -E "(one|two)" file.txt          # OR: contains "one" or "two"
grep -E "(one.*two)" file.txt         # AND: contains both in order
grep "one" file.txt | grep "two"      # AND: chained pipes

# Anchors
grep -E "^word" file.txt              # lines STARTING with "word"
grep -E "word$" file.txt              # lines ENDING with "word"

# Character classes
grep -E "[0-9]+" file.txt             # lines with digits
grep -E "[a-z]+" file.txt             # lines with lowercase letters
grep -E "\w+" file.txt                # lines with word characters

# Quantifiers
grep -E "a{3}" file.txt               # exactly 3 "a"s
grep -E "a{2,4}" file.txt             # 2 to 4 "a"s

# Practical sshd_config examples
grep -v "#" /etc/ssh/sshd_config              # no comments
grep -E "^Password.*yes" /etc/ssh/sshd_config # password + yes
grep -E "yes$" /etc/ssh/sshd_config           # ends with yes
grep -E "Permit\w+" /etc/ssh/sshd_config      # starts with Permit
```
