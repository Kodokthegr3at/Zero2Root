## 1. Layered Troubleshooting Methodology

Use a **bottom-up** or **top-down** approach, and record the hypothesis and evidence at each layer.

```text
App → DNS → TCP/UDP → Routing → Interface → Physical
```

On Linux servers the typical flow is: verify **link/up**, **IP**, **default route**, **DNS**, then check that the **remote port is reachable** (`nc`/`curl`), and only then **capture** if the problem still isn't clear.

```
Symptom: "curl https://app.internal fails"
  │
  ├─ ip link / ip addr        → interface up? correct IP?
  ├─ ip route                 → default gw present?
  ├─ ping gw                  → L2/L3 local OK?
  ├─ dig app.internal         → DNS resolves?
  ├─ curl -v / nc -vz         → TCP 443 reachable?
  └─ tcpdump on interface     → where packets die?
```

| Layer | Questions | Tools |
|:---|:---|:---|
| L1/L2 | Cable/VLAN/bridge? | `ip link`, `ethtool` |
| L3 | IP & routes correct? | `ip addr`, `ip route`, `ping` |
| L4 | Port open/filtered? | `ss`, `nc` (authorized) |
| L7 | App/TLS/HTTP OK? | `curl -v`, `openssl s_client` |

## 2. Reachability — `ping`, `traceroute`, `mtr`

**ICMP echo** (`ping`) tests round-trip time; **traceroute**, `tracepath`, and `mtr` show delay and loss hop by hop. Firewalls often block ICMP, so a failed ping does not prove TCP is down too. Combine it with TCP probes.

```bash
ping -c 4 10.10.14.1
ping -6 -c 4 2001:db8::1

traceroute 8.8.8.8
tracepath example.com
mtr -rwzc 50 example.com    # report mode, 50 cycles

# TCP-based traceroute alternative when ICMP blocked
sudo traceroute -T -p 443 example.com
```

| Tool | Shows |
|:---|:---|
| `ping` | RTT, loss to a single host |
| `traceroute` | Per-hop routers (ICMP/UDP/TCP variants) |
| `mtr` | Combined ping and traceroute statistics |

## 3. Sockets & Connections — `ss` & `netstat`

**`ss`** replaces **`netstat`**. Use it to see listening ports, established connections, and queue backlog. During incident response on hosts you own, map suspicious outbound connections to processes with `-p`.

```bash
ss -tulnp                    # listening TCP/UDP + process
ss -tan state established    # active TCP
ss -o state established '( dport = :443 )'

# Legacy
netstat -tulnp 2>/dev/null

# Bandwidth per socket (if installed)
sudo ss -ti
```

| State | Meaning |
|:---|:---|
| `LISTEN` | Awaiting inbound connections |
| `ESTAB` | Active session |
| `TIME-WAIT` | Closed side waiting out 2MSL |
| `SYN-RECV` | Possible SYN flood or half-open connection |

## 4. Packet Capture — `tcpdump`

**`tcpdump`** captures frames/packets on the wire from an interface. It needs **`CAP_NET_RAW`** or root. Capture only on networks and systems you are **authorized** to monitor. Store pcaps encrypted, since they can contain credentials if the traffic is cleartext HTTP.

```bash
# List interfaces
tcpdump -D

# Basic capture (lab)
sudo tcpdump -i eth0 -nn -c 20
sudo tcpdump -i eth0 -nn host 10.10.14.5 and port 443

# Write pcap for Wireshark
sudo tcpdump -i eth0 -w /tmp/capture.pcap -c 500
tcpdump -r /tmp/capture.pcap -nn | head

# Common filters
# tcp port 80
# icmp
# net 10.10.14.0/24
# not port 22
```

| Filter expression | Matches |
|:---|:---|
| `host X` | Src or dst X |
| `port 53` | TCP or UDP 53 |
| `tcp[tcpflags] & tcp-syn != 0` | SYN packets |
| `vlan 100` | VLAN tag (if present) |

The **Berkeley Packet Filter (BPF)** runs in-kernel for efficiency before packets are copied to userspace.

## 5. ARP & Neighbor Discovery — `ip neigh`, `arp`

IPv4 **ARP** maps IP to MAC on the local segment. The neighbor table is read with **`ip neigh`**. Stale or poisoned ARP entries cause subtle connectivity issues, or MITM on untrusted LANs. Use DAI/802.1X on switches where it's available.

```bash
ip neigh show
arp -n

# Clear single stale entry (careful on production)
sudo ip neigh del 10.10.14.1 dev eth0
sudo ip neigh flush dev eth0

# Link diagnostics
ethtool eth0
ethtool -S eth0 | head
```

## 6. Application-Layer Probes — DNS & HTTP

Once L3/L4 look fine, verify **DNS** and **HTTP/TLS** with `dig`, `curl`, and `openssl`. `curl -v` exposes redirects, cert errors, and SNI behavior, which is invaluable for vHost and TLS debugging.

```bash
dig +trace example.com A
dig @10.10.14.1 internal.lab A

curl -v http://127.0.0.1:8080/
curl -vk https://app.lab/health
curl -o /dev/null -w '%{http_code} time=%{time_total}\n' -s https://example.com/

# TLS handshake inspect
echo | openssl s_client -connect example.com:443 -servername example.com 2>/dev/null | openssl x509 -noout -subject -dates

# TCP port probe
nc -vz 10.10.14.10 22
nc -vz -w 3 example.com 443
```

## 7. Security Notes — Ethics & Defense

Capture and ARP inspection only on systems or networks **you are authorized** to manage. pcaps are sensitive data. Promiscuous mode and packet dumps are high-privacy operations. Correlate listeners with auth logs (note 28) during IR on owned hosts.

| Activity | Authorized context | Abuse risk |
|:---|:---|:---|
| `tcpdump` on a LAN | SOC/NOC with policy | Credential theft, privacy violation |
| ARP inspection | Troubleshooting your own subnet | MITM if combined with forwarding |
| `ss` process mapping | IR on an owned host | Recon on a compromised shared host |
| Promiscuous mode | IDS sensor | Covert channel if misused |

**Defensive monitoring:**

```bash
# Unexpected promiscuous interface?
ip link | grep PROMISC

# New listeners after change window
ss -tulnp | grep LISTEN

# Auth + network correlation (see note 28)
journalctl -u ssh --since "1 hour ago" | tail
```

```bash
# Reachability

sudo tcpdump -i eth0 -nn -c 50

# App layer
dig A HOST +short

```
