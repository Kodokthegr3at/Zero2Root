## 1. 🧱 Linux Netfilter — Where Filtering Happens

### 🇮🇩 Bahasa Indonesia
Kernel **Netfilter** mengevaluasi paket di rules **iptables/nftables** sebelum forward/accept/drop.

$$
\text{Decision} \in \{\text{ACCEPT}, \text{DROP}, \text{REJECT}, \text{LOG}, \text{NAT}\}
$$

### 🇬🇧 English
A host firewall is **defense-in-depth** after network edge filters. Default stance for servers: **deny inbound**, allow established, explicit allowlist for services.

### 日本語
Netfilter が INPUT/FORWARD で ACCEPT/DROP を決めます。サーバの基本姿勢は inbound 拒否、確立済み許可、サービスだけ明示許可です。

```
Inbound packet
      │
      ▼
 PREROUTING (nat)
      │
      ▼
 INPUT (filter)  → ACCEPT / DROP
      │
      ▼
 Local process OR forward path
```

| Framework | Distros | Backend |
|:---|:---|:---|
| **UFW** | Ubuntu/Debian | iptables/nft backend |
| **firewalld** | Fedora/RHEL/Alma | nftables |
| **iptables** | Universal low-level | legacy CLI |
| **nftables** | Modern default | `nft` CLI |

Theory context (DAC, MAC, hardening pillars) → **note 26**.

## 2. 📜 iptables — Tables, Chains & Rules

### 🇮🇩 Bahasa Indonesia
iptables mengatur **table** (filter/nat/…) dan **chain** (INPUT/FORWARD/OUTPUT). Rule dievaluasi dari atas; match pertama yang menang.

| Table | Purpose |
|:---|:---|
| `filter` | Allow/deny (INPUT, FORWARD, OUTPUT) |
| `nat` | SNAT/DNAT/MASQUERADE |
| `mangle` | TTL/TOS/mark |
| `raw` | Connection tracking exemptions |

### 🇬🇧 English
Rules are evaluated **top to bottom**; first match wins unless `-j` jumps. Use **`iptables-save`** / **`iptables-restore`** for backup.

### 日本語
filter 表の INPUT/FORWARD/OUTPUT が許可・拒否の中心です。変更前に `iptables-save` でバックアップします。

```bash
# View current rules
sudo iptables -L -v -n
sudo iptables -S

# Minimal allowlist INPUT (lab — adjust interfaces/ports)
sudo iptables -P INPUT DROP
sudo iptables -P FORWARD DROP
sudo iptables -P OUTPUT ACCEPT

sudo iptables -A INPUT -i lo -j ACCEPT
sudo iptables -A INPUT -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT
sudo iptables -A INPUT -p tcp --dport 22 -s 203.0.113.0/24 -j ACCEPT
sudo iptables -A INPUT -p tcp --dport 443 -j ACCEPT
sudo iptables -A INPUT -j LOG --log-prefix "IPT DROP: "
sudo iptables -A INPUT -j DROP

# Persist (Debian)
sudo apt install iptables-persistent -y
sudo netfilter-persistent save
```

| Target | Behavior |
|:---|:---|
| `-j ACCEPT` | Allow packet |
| `-j DROP` | Silent discard |
| `-j REJECT` | Discard + ICMP error |
| `-j LOG` | Log then continue chain |

## 3. 🆕 nftables — Successor Syntax

### 🇮🇩 Bahasa Indonesia
**nftables** menggabungkan IPv4/IPv6; ruleset atomik via **`nft -f`**.

### 🇬🇧 English
On distros defaulting to nft, `iptables` may be an iptables-nft compatibility layer — prefer native `nft` for new rules.

### 日本語
nftables は IPv4/IPv6 を一つの `inet` 表で扱えます。新規ルールは互換ラッパよりネイティブ `nft` を推奨します。

```bash
sudo nft list ruleset

# Example ruleset file /etc/nftables.conf fragment
sudo tee /etc/nftables.conf << 'EOF'
#!/usr/sbin/nft -f
flush ruleset
table inet filter {
  chain input {
    type filter hook input priority 0; policy drop;
    iif "lo" accept
    ct state established,related accept
    tcp dport 22 ip saddr 203.0.113.0/24 accept
    tcp dport { 80, 443 } accept
  }
}
EOF
sudo nft -f /etc/nftables.conf
sudo systemctl enable --now nftables
```

## 4. 🛡️ UFW — Uncomplicated Firewall (Debian/Ubuntu)

### 🇮🇩 Bahasa Indonesia
Frontend berbasis profil aplikasi (`OpenSSH`, `Nginx Full`). Mudah, tetap default-deny.

### 🇬🇧 English
Enable only after confirming the SSH allow rule — keep **console access** ready to recover lockouts.

### 日本語
UFW は iptables/nft の薄い CLI です。有効化の前に SSH 許可を確認し、コンソール復旧手段を用意します。

```bash
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow OpenSSH
sudo ufw allow from 203.0.113.0/24 to any port 22 proto tcp
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw limit OpenSSH    # rate-limit brute force
sudo ufw enable
sudo ufw status verbose
sudo ufw status numbered
sudo ufw delete 3         # by rule number
```

| Command | Effect |
|:---|:---|
| `ufw app list` | Available profiles |
| `ufw allow in on eth0` | Interface-scoped rule |
| `ufw logging on` | Log blocked packets (medium) |

## 5. 🗺️ firewalld — Zones (RHEL Family)

### 🇮🇩 Bahasa Indonesia
**Zones** (`public`, `internal`, `drop`) plus **`firewall-cmd`**: runtime vs permanent.

### 🇬🇧 English
`--permanent` changes survive reboot but need **`--reload`**; runtime `--add-service` is lost on reboot unless saved.

### 日本語
firewalld はゾーンモデルです。`--permanent` のあと `--reload` が必要です。runtime だけの変更は再起動で消えます。

```bash
sudo systemctl enable --now firewalld
sudo firewall-cmd --state
sudo firewall-cmd --get-active-zones
sudo firewall-cmd --list-all

# Allow HTTP permanently in public zone
sudo firewall-cmd --zone=public --add-service=http --permanent
sudo firewall-cmd --zone=public --add-service=https --permanent
sudo firewall-cmd --reload

# Rich rule: SSH from subnet
sudo firewall-cmd --permanent --add-rich-rule='rule family="ipv4" source address="203.0.113.0/24" service name="ssh" accept'
sudo firewall-cmd --reload
```

| Zone | Typical use |
|:---|:---|
| `public` | Untrusted networks |
| `internal` | Trusted LAN |
| `drop` | Blackhole inbound |

## 6. ✅ Allowlist Design Patterns

### 🇮🇩 Bahasa Indonesia
Prinsip: inbound hanya yang **eksplisit** diizinkan.

$$
\text{Permitted inbound} = \bigcup_{\text{service } s} \{(s.\text{port}, s.\text{src allowlist})\}
$$

### 🇬🇧 English
| Pattern | When |
|:---|:---|
| Mgmt subnet → SSH | All servers |
| `0.0.0.0/0` → 443 only | Public web |
| Deny all inter-VLAN except bastion | Segmented DC |
| LOG before DROP | Tuning without silent failure |

### 日本語
インバウンドは許可リストだけ。管理網→SSH、公開は 443、VLAN 間は bastion 以外拒否、DROP の前に LOG で調整します。

```bash
# Verify effective posture
sudo ufw status verbose
sudo iptables -L INPUT -v -n --line-numbers
sudo nft list chain inet filter input
sudo firewall-cmd --list-all

# Map listeners vs firewall
ss -tulnp | grep LISTEN
```

## 7. 🔐 Security Notes — Lockout & Logging

### 🇮🇩 Bahasa Indonesia
Kesalahan paling mahal: mengunci SSH dari jarak jauh. Siapkan rollback timer dan akses konsol.

### 🇬🇧 English
Allow SSH **before** enabling a default-deny policy. Cover IPv6. Rate-limit LOG to avoid disk floods. Pair with Fail2Ban (note 26) and auth logs (note 28).

### 日本語
SSH 許可の前に FW を有効化しない。IPv6 ルール漏れ、過剰 LOG、広すぎる `22/tcp` 公開を避けます。

| Pitfall | Consequence | Prevention |
|:---|:---|:---|
| Enable firewall before SSH allow | Console recovery needed | `ufw allow OpenSSH` first; `netfilter-persistent` test |
| Flush rules remotely | Instant lockout | `at` rollback timer or serial console |
| Over-broad `allow 22/tcp` | Internet brute force | Source IP allowlist + Fail2Ban (note 26) |
| No IPv6 rules | v6 bypass | Dual-stack rules (`inet` table / ip6tables) |
| LOG everything | Disk/CPU flood | Rate-limited LOG prefix |

```bash
# Safe change pattern (lab)
# 1) schedule rollback
echo "sudo ufw disable" | at now + 5 minutes
# 2) apply change
sudo ufw enable
# 3) verify SSH in second session
# 4) cancel rollback: atrm JOB
```

Cross-reference: network interfaces → **notes 24–25**; auth brute force → **note 28** logs.
