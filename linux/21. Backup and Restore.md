## 1. 🎯 Backup Goals — Why Admins Archive

### 🇮🇩 Bahasa Indonesia
Backup mendukung **availability** dan **integrity** setelah kerusakan, ransomware, atau kesalahan manusia:

$$
\text{RPO} = \text{max data loss tolerated},\quad
\text{RTO} = \text{max downtime tolerated}
$$

Tanpa uji restore, backup hanya **asumsi**.

### 🇬🇧 English
Good backups are measured by **Recovery Point Objective (RPO)** and **Recovery Time Objective (RTO)**, plus cryptographic integrity of offline copies.

### 日本語
RPO/RTOを定義し、復元テストで実効性を確認します。

```
  Live system                 Backup store
 ┌──────────┐   tar/rsync    ┌────────────┐
 │  Data    │ ─────────────► │ Encrypted  │
 │  Config  │                │ offline /  │
 │  DB dump │ ◄───────────── │ offsite    │
 └──────────┘   restore test └────────────┘
```

| Type | Description | Example tools |
|:---|:---|:---|
| Full | Complete copy | `tar`, imaging |
| Incremental | Changes since last backup | `rsync`, borg, restic |
| Differential | Changes since last full | Various |
| Snapshot | Point-in-time FS/volume | LVM, ZFS, btrfs |

## 2. 📦 Archiving with `tar`

### 🇮🇩 Bahasa Indonesia
`tar` (*tape archive*) menggabungkan banyak path menjadi satu stream/file.

| Flag | Meaning |
|:---|:---|
| `-c` | Create |
| `-x` | Extract |
| `-t` | List |
| `-v` | Verbose |
| `-f` | Archive file name |
| `-C` | Change directory on extract |
| `-p` | Preserve permissions (as root) |

### 🇬🇧 English
Prefer explicit file lists over unquoted globs in privileged cron jobs (see Security Notes).

### 日本語
特権cronではワイルドカードより明示リストを推奨します。

```bash
# Create / list / extract
tar -cvf etc_backup.tar /etc/
tar -tvf etc_backup.tar
tar -xvf etc_backup.tar -C /tmp/restore/

# Exclude patterns
tar -czvf home.tgz /home/alice --exclude='*/.cache/*'
```

**Integrity after create:**

$$
h = \mathrm{SHA256}(\text{archive}),\quad
\text{store } h \text{ separately from the blob}
$$

```bash
sha256sum backup.tar.gz | tee backup.tar.gz.sha256
```

## 3. 🗜️ Compression Formats

| Format | `tar` flag | Extension | Trade-off |
|:---|:---:|:---|:---|
| gzip | `-z` | `.tar.gz` / `.tgz` | Fast, ubiquitous |
| bzip2 | `-j` | `.tar.bz2` | Higher ratio, slower |
| xz | `-J` | `.tar.xz` | Best ratio, CPU-heavy |
| zstd | `--zstd` | `.tar.zst` | Modern speed/ratio (newer tar) |

```bash
tar -czvf data.tar.gz /var/www/html/
tar -cjvf data.tar.bz2 /var/www/html/
tar -cJvf data.tar.xz /var/www/html/
tar -xvf data.tar.gz          # auto-detect on GNU tar often works
```

Relative compression (intuition):

$$
\text{size}_{\text{xz}} \lesssim \text{size}_{\text{bz2}} \lesssim \text{size}_{\text{gz}} \le \text{size}_{\text{raw}}
$$

(Actual ratios depend on data entropy.)

## 4. 🔄 `rsync` — Incremental Synchronization

### 🇮🇩 Bahasa Indonesia
`rsync` hanya mentransfer **delta** blok yang berubah — efisien untuk backup berkala.

| Flag | Meaning |
|:---|:---|
| `-a` | Archive (perms, times, symlinks, recursive) |
| `-v` | Verbose |
| `-z` | Compress in transit |
| `-P` | Progress + partial resume |
| `-e ssh` | SSH transport |
| `--delete` | Mirror deletions (dangerous if mis-aimed) |
| `-n` / `--dry-run` | Simulate |

### 🇬🇧 English
Always `--dry-run` before `--delete`. Trailing slashes matter: `src/` copies *contents*; `src` can nest differently.

### 日本語
`--delete` の前に必ず dry-run。末尾の `/` に注意。

```bash
# Local
rsync -avzP /home/alice/documents/ /backup/alice/documents/

# Remote over SSH
rsync -avzP -e ssh /var/www/html/ backup@192.168.1.50:/remote/html/

# Safe mirror rehearsal
rsync -avzn --delete /data/ /backup/data/
```

Formal delta idea:

$$
\text{transfer} \approx \Delta\big(\text{src}, \text{dst}\big)
\quad\text{instead of}\quad
|\text{src}|
$$

## 5. 🔐 `scp` / `sftp` — Copy over SSH

### 🇮🇩 Bahasa Indonesia
`scp` / `sftp` memakai autentikasi & enkripsi SSH. Cocok untuk salinan ad-hoc; untuk sync berulang prefer `rsync` atau tool dedikasi (borg/restic).

### 🇬🇧 English
Prefer key-based SSH, restricted backup accounts (`ForceCommand`, forced chroot, or dedicated keys with limited paths).

### 日本語
定期同期は `rsync` 等、単発転送は `scp`/`sftp`。

```bash
scp backup.tar.gz.gpg backup@server:/backups/
scp -r backup@server:/backups/2026-08-16/ ./restore-staging/
sftp backup@server
```

## 6. 🔏 Encrypting Backups with GnuPG

### 🇮🇩 Bahasa Indonesia
Arsip sering berisi rahasia (DB dumps, keys, configs). Enkripsi at-rest:

$$
c = \mathsf{Enc}_k(m),\quad
m = \mathsf{Dec}_k(c)
$$

dengan $k$ dari passphrase (simetris) atau public key penerima backup.

### 🇬🇧 English
Use AES-256 symmetric encryption for simple offline disks, or asymmetric encryption to a backup team’s public key so operators never share one passphrase.

### 日本語
保管時はGPG等で暗号化し、鍵/パスフレーズをバックアップ本体と分離します。

```bash
gpg --symmetric --cipher-algo AES256 backup.tar.gz
gpg --output backup.tar.gz --decrypt backup.tar.gz.gpg

# Asymmetric (recipient pubkey already imported)
gpg --encrypt --recipient backups@example.com backup.tar.gz
```

Store passphrase / private key in a **password manager / HSM / sealed envelope** — not next to the ciphertext on the same USB stick alone.

## 7. 📐 Strategy — 3-2-1 and Restore Drills

### 3-2-1 rule
$$
3\ \text{copies},\quad
2\ \text{media types},\quad
1\ \text{offsite / offline}
$$

| Practice | Detail |
|:---|:---|
| Catalog | What is backed up, schedule, owner |
| Encryption | At rest + in transit (SSH/TLS) |
| Retention | Meet legal/compliance windows |
| Restore test | Quarterly minimum for critical systems |
| Access control | Backup account ≠ interactive admin |
| Immutability | WORM / object-lock where ransomware is a concern |

```
Weekly drill (sketch)
─────────────────────
1. Pick random file set from catalog
2. Restore to isolated staging host
3. Verify checksums / app smoke test
4. Record RTO observed vs target
5. Fix gaps; update runbook
```

## 8. 🔐 Security Notes — DEFENSE / Hardening

| Risk | Why | Defense |
|:---|:---|:---|
| Unencrypted backups | Theft of disk = data breach | `gpg`/age/restic encryption; lock storage |
| Backups in web root | Public download of dumps | Never store under docroot; separate volume |
| World-readable `/var/backups` | Local user data leak | `750`/`640`, group `backup` |
| Privileged cron + `tar *` in writable dirs | Argument injection via crafted filenames | Explicit file lists; `find … -print0` + `--files-from`; run from locked dirs |
| `rsync --delete` mis-aimed | Catastrophic wipe of good copy | Dry-run; pull model; snapshots before delete |
| Open rsync daemon (873) without auth | Data exfil / overwrite | Prefer SSH; authenticate; firewall |
| Single online copy | Ransomware encrypts backups too | Offline / immutable / offsite copy |
| No restore tests | False confidence | Scheduled drills + checksums |

### Safe `tar` cron pattern (concept)
Prefer:

```bash
# Explicit paths — no shell glob controlled by untrusted dirs
tar -czf /var/backups/etc-$(date +%F).tar.gz -C / etc
chmod 600 /var/backups/etc-*.tar.gz
```

Avoid privileged jobs that `cd` into world-writable trees and run `tar … *`.

### Backup account hardening
- Dedicated user, no unnecessary shell tools.
- SSH key restricted (`command=`, `from=`).
- Separate network segment / firewall allowlist.
- Monitor failed SSH and unexpected restore hosts.

```bash
# Permissions audit (admin)
namei -l /var/backups
find /var/backups -type f -perm -o=r -ls
```

## 9. 🧠 Quick Reference Cheatsheet

```bash
# tar
tar -czvf backup.tar.gz /path
tar -tvf backup.tar.gz
tar -xvf backup.tar.gz -C /restore/
sha256sum backup.tar.gz

# rsync
rsync -avzP /src/ /dst/
rsync -avzn --delete /src/ /dst/     # dry-run mirror
rsync -avzP -e ssh /src/ user@host:/dst/

# scp
scp file.gpg user@host:/backups/

# gpg
gpg -c --cipher-algo AES256 backup.tar.gz
gpg -d backup.tar.gz.gpg > backup.tar.gz
```
