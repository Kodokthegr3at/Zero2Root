## 1. Tujuan Keamanan Linux — Mengecilkan Attack Surface

Hardening berarti menurunkan eksposur tanpa merusak fungsi bisnis:

$$
\text{Risk} \propto \text{Assets} \times \text{Threats} \times \text{Vulnerabilities} \times \text{Exposure}
$$

Kita mengurangi **Exposure** (port, paket, user, privilege) dan **Vulnerabilities** (patch, konfigurasi aman). Host yang sudah di-hardening punya sedikit listener, sedikit paket terpasang, prinsip least privilege, MAC yang aktif menegakkan aturan, jalur admin terenkripsi, dan log auth yang dipantau.

```
          Before                         After (sketch)
   ┌─────────────────┐              ┌─────────────────┐
   │ Many packages   │              │ Minimal packages│
   │ Open ports **** │     ───►     │ Only 22/443     │
   │ Password SSH    │              │ Keys only SSH   │
   │ MAC complain    │              │ MAC enforcing   │
   └─────────────────┘              └─────────────────┘
```

| Pilar | Contoh kontrol |
|:---|:---|
| Identitas | Auth kuat, tidak ada root SSH bersama |
| Jaringan | Firewall default-deny |
| Software | Update tertandatangani, paket minimal |
| Privilege | sudo dibatasi scope-nya, tidak ada NOPASSWD:ALL |
| Deteksi | journal/auth diteruskan ke alert |
| Recovery | Backup yang sudah diuji (catatan 21) |

## 2. Access Control — DAC, MAC, RBAC

| Model | Siapa yang menentukan? | Mekanisme di Linux |
|:---|:---|:---|
| **DAC** | Pemilik resource | Mode bit `chmod`/`chown` |
| **MAC** | Kebijakan sistem | SELinux, AppArmor |
| **RBAC** | Penugasan role | groups + `sudo` + kebijakan |

Pengingat mode bit Unix:

$$
\text{mode} = \underbrace{s}_{\text{special}} \underbrace{rwx}_{\text{user}} \underbrace{rwx}_{\text{group}} \underbrace{rwx}_{\text{other}}
\quad\text{octal } 0\ldots777\ (+\, special\, 4/2/1\,000)
$$

DAC yang sudah benar sekalipun tetap bisa dilewati oleh `root` yang sudah dikuasai penyerang, kecuali **MAC** membatasi proses tersebut.

## 3. Defense-in-Depth — Kontrol Berlapis

Keamanan Linux yang efektif menumpuk kontrol yang independen satu sama lain. Kegagalan di satu lapisan tidak membuat host langsung terbuka.

$$
\text{Effective security} = f(\text{Identity}, \text{Network}, \text{Host}, \text{App}, \text{Data}, \text{Detection})
$$

| Layer | Contoh di Linux | Catatan detail |
|:---|:---|:---|
| Tepi jaringan | Router ACL, VPN | Modul `networking/` |
| **Firewall host** | iptables, UFW, firewalld | **catatan 27** |
| Transport/admin | SSH keys, TLS | Bagian §4 di sini |
| Identitas OS | PAM, sudo, shadow | **catatan 15** |
| Izin objek | chmod, audit SUID | **catatan 14** |
| MAC | SELinux, AppArmor | §7 di bawah |
| Monitoring | log auth, journal | **catatan 28** |

Rancang pertahanan berlapis: jaringan → firewall host → autentikasi → MAC → log.

```
Internet
   │
   ▼
Edge firewall / WAF
   │
   ▼
Host firewall (note 27) ── default deny inbound
   │
   ▼
SSH/TLS hardened admin path (§4)
   │
   ▼
DAC + sudo RBAC + MAC (§2, §7)
   │
   ▼
Logging & alerting (note 28)
```

**Prinsip:** default-deny di batas jaringan, least privilege di mana pun, dan asumsikan sistem bisa dibobol sehingga batasi radius dampaknya.

## 4. OpenSSH Hardening — `/etc/ssh/sshd_config`

### Direktif dasar

| Direktif | Nilai hardened | Tujuan |
|:---|:---|:---|
| `PermitRootLogin` | `no` | Tidak ada sesi root langsung |
| `PasswordAuthentication` | `no` | Hanya key-based |
| `PubkeyAuthentication` | `yes` | Aktifkan autentikasi key |
| `KbdInteractiveAuthentication` | `no` | Kurangi permukaan auth |
| `MaxAuthTries` | `3` | Perlambat percobaan tebak password |
| `AllowUsers` / `AllowGroups` | eksplisit | Allowlist akun |
| `X11Forwarding` | `no` (kalau tidak dipakai) | Kurangi attack surface |
| `ClientAliveInterval` | misal `300` | Putuskan sesi yang basi |

```bash
# Audit effective non-comment config
sudo sshd -T | egrep 'permitrootlogin|passwordauthentication|pubkeyauthentication|maxauthtries'

# Validate before restart
sudo sshd -t && sudo systemctl reload ssh
```

**Tips rollout:** biarkan satu sesi lain tetap terbuka saat menguji perubahan; pakai console/serial cloud kalau aksesnya remote.

Generate key admin (di workstation admin):

```bash
ssh-keygen -t ed25519 -a 100 -f ~/.ssh/id_ed25519_admin
# install public key to ~/.ssh/authorized_keys on server (mode 600)
```

## 5. Fail2Ban — Respons Otomatis

Fail2Ban mengamati log; setelah $N$ kegagalan dalam jendela waktu tertentu, IP tersebut di-ban di firewall selama $T$ detik.

$$
\text{ban}(ip) \iff \#\{\text{failures in window } W\} \ge N
$$

Fail2Ban melengkapi, bukan menggantikan, SSH key-only dan allowlist firewall.

```bash
sudo apt install fail2ban -y
sudo cp /etc/fail2ban/jail.conf /etc/fail2ban/jail.local
sudo systemctl enable --now fail2ban
sudo fail2ban-client status sshd
sudo fail2ban-client set sshd unbanip 203.0.113.50
```

Atur `findtime`, `maxretry`, `bantime` di jail.local; whitelist NAT admin dengan hati-hati.

## 6. Kernel Hardening lewat `sysctl`

Parameter defensif yang berguna (verifikasi dulu terhadap beban kerja Anda):

| Parameter | Nilai | Tujuan |
|:---|:---:|:---|
| `net.ipv4.tcp_syncookies` | `1` | Tahan terhadap SYN flood |
| `net.ipv4.conf.all.accept_redirects` | `0` | Tolak ICMP redirect jahat |
| `net.ipv4.conf.all.accept_source_route` | `0` | Buang paket source-routed |
| `net.ipv4.conf.all.log_martians` | `1` | Catat alamat yang mustahil |
| `net.ipv4.icmp_echo_ignore_broadcasts` | `1` | Redam noise gaya smurf |
| `kernel.randomize_va_space` | `2` | ASLR penuh |
| `fs.protected_hardlinks` | `1` | Keamanan hardlink |
| `fs.protected_symlinks` | `1` | Keamanan symlink |
| `kernel.yama.ptrace_scope` | `1` atau `2` | Batasi process tracing |

```bash
sudo tee /etc/sysctl.d/99-hardening.conf << 'EOF'
net.ipv4.tcp_syncookies = 1
net.ipv4.conf.all.accept_redirects = 0
net.ipv4.conf.all.accept_source_route = 0
net.ipv4.icmp_echo_ignore_broadcasts = 1
kernel.randomize_va_space = 2
fs.protected_hardlinks = 1
fs.protected_symlinks = 1
EOF
sudo sysctl --system
cat /proc/sys/kernel/randomize_va_space   # expect 2
```

Intuisi ASLR: acak alamat dasar supaya memory corruption dengan offset tetap jadi tidak bisa diandalkan penyerang:

$$
\mathrm{P}(\text{guess correct slide}) \ll 1 \text{ under } \texttt{randomize\_va\_space}=2
$$

## 7. Mandatory Access Control — AppArmor & SELinux

| Framework | Distro | Model |
|:---|:---|:---|
| **AppArmor** | Ubuntu/Debian | Profil berbasis path |
| **SELinux** | Fedora/RHEL/Alma/Rocky | Penegakan label/type |

```bash
# AppArmor
sudo aa-status
sudo aa-enforce /etc/apparmor.d/usr.sbin.nginx   # example

# SELinux
getenforce
sudo setenforce 1                                # enforcing until reboot policy
# persistent: SELINUX=enforcing in /etc/selinux/config
```

**Kebijakan:** utamakan mode **enforcing** di production; pakai complain/permissive hanya saat mengembangkan profil, lalu ketatkan lagi.

## 8. Patch Cepat, Install Sedikit

$$
\text{Attack surface} \uparrow \text{ with } |P_{\text{installed}}| \text{ and open listeners}
$$

```bash
# Debian/Ubuntu
sudo apt update && sudo apt upgrade
sudo apt install unattended-upgrades
sudo dpkg-query -f '${binary:Package}\n' -W | wc -l

# RHEL family
sudo dnf upgrade
sudo dnf install dnf-automatic

# Listeners audit
ss -tulnp
systemctl list-units --type=service --state=running
```

Matikan service yang tidak dipakai (`systemctl disable --now …`). Hapus compiler dan interpreter tambahan dari host edge production kalau kebijakan mengizinkan.

## 9. Catatan Keamanan — Checklist Pertahanan

| Area kontrol | Verifikasi | Perbaikan |
|:---|:---|:---|
| Update | Rilis masih didukung; update security terbaru terpasang | Aktifkan auto security update |
| SSH | `sshd -T` tidak menunjukkan login password/root | Key + AllowUsers + firewall |
| Firewall | Default deny; allow seminimal mungkin | Review aturan UFW/nft |
| MAC | Profil/label dalam mode enforcing | Perbaiki denial dengan benar, jangan matikan MAC |
| Sudo | Tidak ada `NOPASSWD: ALL` yang terlalu luas | Batasi command per scope; pakai group |
| Inventaris SUID/SGID | Review berkala bit khusus | Hapus setuid yang tidak perlu |
| Direktori world-writable | Terutama path cron/backup | Perbaiki ownership & mode |
| Log | auth + journal disimpan/diteruskan | Praktik di catatan 28 |
| Backup | Terenkripsi + sudah diuji restore | Praktik di catatan 21 |
| Firewall | Default deny; allow terdokumentasi | Aturan di catatan 27 |
| Secrets | Tidak ada key di web root / home yang bisa dibaca semua orang | Key `600`; vault/HSM |

```bash
# Defensive audit snippets (authorized admin)
sshd -T | egrep 'permitrootlogin|passwordauthentication'
sudo ufw status verbose
getenforce 2>/dev/null; sudo aa-status 2>/dev/null | head
find /usr -perm -4000 -type f 2>/dev/null | head   # inventory only
sudo grep -R "NOPASSWD" /etc/sudoers /etc/sudoers.d 2>/dev/null
```

Inventaris binary SUID di sini untuk keperluan **pengurangan dan monitoring** pada sistem yang Anda administrasikan, bukan daftar resep untuk disalahgunakan.

### Susunan defense-in-depth
```
Users/Apps
   │  DAC (chmod) + sudo RBAC
   ▼
MAC (AppArmor/SELinux)
   │
   ▼
Kernel hardening (ASLR, sysctl)
   │
   ▼
Host firewall (note 27) + Fail2Ban
   │
   ▼
Network edge / WAF / VPN
```
