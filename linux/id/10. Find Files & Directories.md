## 1. `which`

`which` digunakan untuk mencari lokasi (path) dari sebuah program yang dapat dieksekusi. Sangat berguna saat kita ingin tahu apakah sebuah tool seperti `curl`, `netcat`, `wget`, `python`, atau `gcc` tersedia di sistem. Jika program tidak ditemukan, tidak ada output yang ditampilkan.

```bash
# Check if Python is installed and where
$ which python
/usr/bin/python

# Check multiple tools at once
$ which curl wget netcat gcc
/usr/bin/curl
/usr/bin/wget
/usr/bin/netcat
/usr/bin/gcc

# Program not found = no output
$ which nonexistent
$
```

> Kegunaan saat pentest: setelah berhasil mendapat akses ke sebuah sistem, jalankan `which python python3 perl ruby nc wget curl` untuk cepat menginventarisasi tool yang tersedia untuk post-exploitation.

## 2. `find`

`find` adalah tool pencarian yang sangat powerful. Selain menemukan file dan folder, ia juga memiliki berbagai opsi filter seperti ukuran file, tanggal modifikasi, pemilik file, tipe objek, dan bahkan bisa menjalankan perintah pada setiap hasil yang ditemukan dengan flag `-exec`.

### Sintaks

```bash
find <location> <options>
```

### Contoh: Perintah Lengkap

```bash
$ find / -type f -name *.conf -user root -size +20k -newermt 2020-03-03 -exec ls -al {} \; 2>/dev/null
```

**Output:**
```
-rw-r--r-- 1 root root 136392 Apr 25 20:29 /usr/src/linux-headers-5.5.0/include/config/auto.conf
-rw-r--r-- 1 root root  82290 Apr 25 20:29 /usr/src/linux-headers-5.5.0/include/config/tristate.conf
-rw-r--r-- 1 root root  95813 May  7 14:33 /usr/share/metasploit-framework/data/jtr/repeats32.conf
-rw-r--r-- 1 root root  60346 May  7 14:33 /usr/share/metasploit-framework/data/jtr/dynamic.conf
-rw-r--r-- 1 root root  21254 May  2 11:59 /usr/share/doc/sqlmap/examples/sqlmap.conf
-rw-r--r-- 1 root root  25086 Mar  4 22:04 /etc/dnsmasq.conf
```

### Rincian Opsi `find`

| Opsi | Keterangan |
|--------|----------------------|
| `-type f` | Cari hanya file (`f`=file, `d`=direktori) |
| `-name *.conf` | Cari file berekstensi `.conf` (wildcard `*`) |
| `-user root` | Filter file milik user `root` |
| `-size +20k` | Hanya file lebih besar dari 20 KiB |
| `-newermt 2020-03-03` | Hanya file yang dimodifikasi setelah tanggal tersebut |
| `-exec ls -al {} \;` | Jalankan perintah pada setiap hasil (`{}` = placeholder hasil) |
| `2>/dev/null` | Sembunyikan pesan error (redirect ke null device) |

### Referensi Filter Ukuran

| Suffix | Satuan | Contoh |
|--------|------|---------|
| `c` | Byte | `-size +100c` |
| `k` | Kilobyte (KiB) | `-size +20k` |
| `M` | Megabyte (MiB) | `-size +5M` |
| `G` | Gigabyte (GiB) | `-size +1G` |
| Prefix `+` | Lebih besar dari | `-size +20k` |
| Prefix `-` | Lebih kecil dari | `-size -5k` |

### Contoh Praktis `find`

```bash
# Find all .conf files owned by root, larger than 20KB, modified after 2020-03-03
find / -type f -name *.conf -user root -size +20k -newermt 2020-03-03 -exec ls -al {} \; 2>/dev/null

# Find all directories named "backup"
find / -type d -name backup 2>/dev/null

# Find SUID files (critical for privilege escalation)
find / -type f -perm -4000 2>/dev/null

# Find writable files owned by current user
find / -type f -writable 2>/dev/null

# Find files modified in the last 7 days
find /home -type f -mtime -7

# Find files by exact size (exactly 1337 bytes)
find / -type f -size 1337c 2>/dev/null
```

> Catatan pentesting: `find / -perm -4000 2>/dev/null` mencari binary SUID, yaitu file yang berjalan dengan hak akses pemiliknya. Binary jenis ini adalah target utama untuk eskalasi hak akses.

## 3. `locate`

`locate` menawarkan cara pencarian yang jauh lebih cepat dibanding `find`. Alasannya, `locate` tidak menelusuri filesystem secara langsung, melainkan mencari dari database lokal yang berisi informasi semua file dan folder di sistem.

Kelemahannya, database perlu diperbarui secara manual dengan `sudo updatedb`. File yang baru dibuat mungkin belum masuk database.

Kapan pakai `locate` dibanding `find`:
- Gunakan `locate` untuk pencarian cepat tanpa filter kompleks
- Gunakan `find` ketika butuh filter spesifik (ukuran, tanggal, pemilik, dll.)

```bash
# Update the locate database (run before first use or after new files added)
$ sudo updatedb

# Search for all .conf files
$ locate *.conf
/etc/GeoIP.conf
/etc/NetworkManager/NetworkManager.conf
/etc/UPower/UPower.conf
/etc/adduser.conf
...

# Search for a specific filename
$ locate shadow
/etc/shadow
/etc/shadow-
```

> `locate` jauh lebih cepat dari `find` untuk pencarian luas, tapi tidak punya filter serinci `find`. Selalu jalankan `sudo updatedb` lebih dulu agar database up to date.

## 4. Catatan Keamanan: Eskalasi Hak Akses & Rekon Forensik dengan `find`

Dalam penetration testing Linux dan audit forensik, perintah `find` adalah alat reconnaissance lokal paling penting untuk menemukan vektor eskalasi hak akses (local privilege escalation):

1. Mencari binary SUID/SGID: binary dengan bit SUID (`-perm -4000` atau `-perm -u=s`) berjalan dengan hak akses pemiliknya (biasanya `root`). Jika binary tersebut rentan (terdaftar di GTFOBins atau memiliki celah injeksi parameter), penyerang bisa memperoleh root shell.
2. Mencari direktori & file world-writable: file konfigurasi atau direktori script yang dapat ditulis oleh siapa saja (`-perm -2 -type f` atau `-writable`) memungkinkan penyerang menyisipkan payload atau membajak eksekusi script cron.
3. Mencari file password / kredensial sensitif: menelusuri seluruh direktori web (`/var/www/`) atau direktori home untuk menemukan file `.env`, backup database (`.sql`), atau file konfigurasi yang memuat kredensial plaintext.
4. Mencari file orphan (tanpa pemilik): file yang ditinggalkan user yang sudah dihapus (`-nouser` atau `-nogroup`) sering menjadi target pengambilalihan UID/GID.

```bash
# ── ESSENTIAL PENTESTING FIND COMMANDS ───────────────────────

# 1. SUID Binaries (Primary Linux PrivEsc vector)
$ find / -perm -u=s -type f 2>/dev/null
$ find / -perm -4000 -type f -exec ls -la {} + 2>/dev/null

# 2. SGID Binaries
$ find / -perm -g=s -type f 2>/dev/null

# 3. World-writable directories and files
$ find / -writable -type d 2>/dev/null
$ find / -perm -222 -type d 2>/dev/null
$ find / -perm -2 -type f 2>/dev/null

# 4. Search for passwords in configuration & web files
$ find /var/www /etc /opt /home -type f \( -name "*.conf" -o -name "*.php" -o -name "*.yaml" -o -name "*.env" \) -exec grep -iHn "password" {} + 2>/dev/null

# 5. Search for SSH private keys
$ find / -name "id_rsa" -o -name "id_dsa" -o -name "id_ed25519" 2>/dev/null

# 6. Files modified in the last 60 minutes (detect recent activity)
$ find / -type f -mmin -60 2>/dev/null

# 7. Linux Capabilities check (alternative to SUID)
$ getcap -r / 2>/dev/null
```

## Perbandingan Perintah: `which` vs `find` vs `locate`

| Aspek | `which` | `find` | `locate` |
|---------|---------|--------|----------|
| Tujuan | Cari path executable | Cari file/direktori | Pencarian file cepat |
| Kecepatan | Instan | Lambat (scan langsung) | Cepat (database) |
| Opsi filter | Tidak ada | Banyak (ukuran, tanggal, user, dll.) | Minimal |
| Hasil real-time | Ya | Ya | Tergantung `updatedb` |
| Butuh root | Tidak | Untuk sebagian path | Tidak (update butuh sudo) |
| Kasus penggunaan | Cek apakah tool ada | Pencarian spesifik yang kompleks | Pencarian luas yang cepat |

## Menggabungkan Tool dalam Satu Alur Kerja

```bash
# Step 1: Check if python3 is available
which python3

# Step 2: Find all Python scripts owned by root
find / -type f -name "*.py" -user root 2>/dev/null

# Step 3: Quick search for config files
sudo updatedb && locate *.conf

# Step 4: Find SUID files and list them in detail
find / -type f -perm -4000 -exec ls -la {} \; 2>/dev/null
```

## Cheatsheet Referensi Cepat

```bash
# which — find executable location
which python
which curl wget netcat

# find — powerful search with filters
find / -type f -name "*.conf"              # all .conf files
find / -type d -name "backup"              # directories named backup
find / -type f -user root -size +20k       # root's files > 20KB
find / -type f -newermt 2020-01-01         # files modified after date
find / -type f -perm -4000 2>/dev/null     # SUID files
find / -type f -perm -2000 2>/dev/null     # SGID files
find / -type f -name "*.conf" -exec ls -al {} \; 2>/dev/null

# locate — fast database search
sudo updatedb                              # update database first
locate *.conf                              # find all .conf files
locate shadow                              # find files named shadow
```
