## Istilah penting

Istilah-istilah ini akan sering muncul di materi.

| Istilah | Artinya |
|:---|:---|
| Regular expression | Pola yang menjelaskan teks mana yang harus dicocokkan |
| Literal | Karakter yang mencocokkan dirinya sendiri (`a` cocok dengan `a`) |
| Metacharacter | Karakter dengan makna khusus (`.`, `*`, `^`, `$`) |
| Character class | Himpunan karakter yang dibolehkan, seperti `[a-z]` |
| Quantifier | Berapa kali sesuatu berulang (`*`, `+`, `{2,4}`) |
| Anchor | Mengikat kecocokan ke posisi (`^` awal, `$` akhir) |
| Capture group | Tanda kurung `( )` yang mengingat bagian dari kecocokan |
| BRE vs ERE | Regex basic vs extended; `grep -E` mengaktifkan bentuk extended |

## 1. Apa itu RegEx?

Regular Expression (RegEx) adalah urutan karakter dan simbol yang membentuk pola pencarian. Bayangkan RegEx sebagai filter yang sangat bisa dikustomisasi, ia menyaring teks untuk menemukan tepat apa yang kita butuhkan.

RegEx bisa dipakai untuk:
- Mencari pola teks secara presisi
- Mengganti teks secara massal
- Memvalidasi input (email, password, nomor telepon)
- Memfilter output dari perintah lain

RegEx tersedia di banyak bahasa pemrograman dan tools seperti `grep`, `sed`, `awk`, Python, JavaScript, dan lainnya.

## 2. Operator Pengelompokan

RegEx memakai tiga jenis tanda kurung yang masing-masing punya fungsi berbeda untuk mendefinisikan pola pencarian.

| Operator | Simbol | Deskripsi |
|----------|--------|-----------|
| Round brackets | `(a)` | Mengelompokkan bagian dari regex. Di dalam kurung bisa didefinisikan pola lebih lanjut yang diproses bersama |
| Square brackets | `[a-z]` | Mendefinisikan kelas karakter. Di dalam kurung, tentukan daftar karakter yang dicari |
| Curly brackets | `{1,10}` | Mendefinisikan quantifier. Menentukan berapa kali pola sebelumnya harus diulang |
| OR operator | `\|` | Menampilkan hasil jika salah satu dari dua ekspresi cocok |
| AND operator | `.*` | Menampilkan hasil hanya jika kedua ekspresi ada dan cocok sesuai urutan |

---

## 3. Operator OR (`|`)

Operator `|` (OR) mencari baris yang mengandung salah satu dari pola yang diberikan. Untuk menggunakan operator ini dengan `grep`, diperlukan flag `-E` (extended regex).

```bash
# Search for lines containing "my" OR "false"
$ grep -E "(my|false)" /etc/passwd

lxd:x:105:65534::/var/lib/lxd/:/bin/false
pollinate:x:109:1::/var/cache/pollinate:/bin/false
mysql:x:116:120:MySQL Server,,:/nonexistent:/bin/false
```

```
Pattern:  (my|false)
              │
     ┌────────┴────────┐
     ▼                 ▼
   "my"             "false"
  matches?          matches?
     │                 │
     └────────┬─────────┘
              ▼
     Either one = SHOW LINE
```

> Ketiga baris ditampilkan karena masing-masing mengandung `my` (mysql) atau `false` (/bin/false), atau keduanya.

## 4. Operator AND (`.*`)

Operator `.*` (AND) hanya menampilkan baris yang mengandung kedua pola secara berurutan. `.*` berarti "karakter apa pun, berapa pun banyaknya" di antara dua pola, sehingga kedua kata harus ada dalam satu baris.

```bash
# Search for lines containing BOTH "my" AND "false" (in that order)
$ grep -E "(my.*false)" /etc/passwd

mysql:x:116:120:MySQL Server,,:/nonexistent:/bin/false
```

```
Pattern:  (my.*false)
            │  │   │
            │  │   └── "false" must appear AFTER "my"
            │  └────── any characters in between (.*)
            └────────── "my" must appear first

mysql:x:116:120:MySQL Server,,:/nonexistent:/bin/false
  ↑ "my" found here              ↑ "false" found here → MATCH ✓

lxd:x:105:65534::/var/lib/lxd/:/bin/false
  ↑ no "my" found → NO MATCH ✗
```

### Alternatif: Chained grep

```bash
# Same result using two grep pipes (AND logic)
$ grep -E "my" /etc/passwd | grep -E "false"

mysql:x:116:120:MySQL Server,,:/nonexistent:/bin/false
```

> Kedua pendekatan menghasilkan hasil yang sama. Chained `grep` lebih mudah dibaca, `.*` lebih ringkas.

## 5. Metacharacter RegEx: Referensi Cepat

Metacharacter adalah simbol spesial dalam regex yang mendefinisikan struktur pencarian, bukan karakter literal.

| Metacharacter | Arti | Contoh |
|--------------|------|--------|
| `.` | Karakter apa pun (kecuali newline) | `a.c` → `abc`, `a1c` |
| `*` | 0 atau lebih dari karakter sebelumnya | `ab*` → `a`, `ab`, `abb` |
| `+` | 1 atau lebih dari karakter sebelumnya | `ab+` → `ab`, `abb` |
| `?` | 0 atau 1 dari karakter sebelumnya | `ab?` → `a`, `ab` |
| `^` | Awal dari baris | `^root` |
| `$` | Akhir dari baris | `bash$` |
| `[abc]` | Salah satu karakter dalam list | `[abc]` → `a`, `b`, atau `c` |
| `[^abc]` | Karakter yang tidak ada dalam list | `[^abc]` → apa pun kecuali a, b, c |
| `[a-z]` | Semua huruf kecil a sampai z | `[a-z]+` |
| `[0-9]` | Semua digit 0 sampai 9 | `[0-9]+` |
| `\d` | Digit (sama dengan `[0-9]`) | `\d+` → `123` |
| `\w` | Word character (`[a-zA-Z0-9_]`) | `\w+` → `hello_123` |
| `\s` | Whitespace (spasi, tab) | `\s+` |
| `{n}` | Tepat n kali pengulangan | `a{3}` → `aaa` |
| `{n,m}` | Antara n dan m kali pengulangan | `a{2,4}` → `aa`, `aaa`, `aaaa` |
| `\` | Escape, karakter berikutnya jadi literal | `\.` → titik literal |

## 6. Latihan Soal: `/etc/ssh/sshd_config`

Latihan berikut memakai file `/etc/ssh/sshd_config`, file konfigurasi SSH yang nyata di sistem Linux. Ini latihan penting karena file ini sering dianalisis saat audit keamanan sistem.

| # | Tugas | Jawaban |
|---|-------|---------|
| 1 | Tampilkan semua baris yang tidak mengandung karakter `#` | Lihat di bawah |
| 2 | Cari semua baris yang mengandung kata yang dimulai dengan `Permit` | Lihat di bawah |
| 3 | Cari semua baris yang mengandung kata yang diakhiri dengan `Authentication` | Lihat di bawah |
| 4 | Cari semua baris yang mengandung kata `Key` | Lihat di bawah |
| 5 | Cari semua baris yang dimulai dengan `Password` dan mengandung `yes` | Lihat di bawah |
| 6 | Cari semua baris yang diakhiri dengan `yes` | Lihat di bawah |

### Solusi

```bash
# Task 1 — Lines NOT containing "#"
grep -v "#" /etc/ssh/sshd_config

# Task 2 — Lines with a word STARTING with "Permit"
grep -E "Permit\w+" /etc/ssh/sshd_config

# Task 3 — Lines with a word ENDING with "Authentication"
grep -E "\w+Authentication" /etc/ssh/sshd_config

# Task 4 — Lines containing the word "Key"
grep "Key" /etc/ssh/sshd_config

# Task 5 — Lines BEGINNING with "Password" AND containing "yes"
grep -E "^Password.*yes" /etc/ssh/sshd_config

# Task 6 — Lines ENDING with "yes"
grep -E "yes$" /etc/ssh/sshd_config
```

### Penjelasan Solusi

```
Task 1:  grep -v "#"
               │
               └── -v = invert match (exclude lines WITH #)

Task 2:  Permit\w+
         │      │
         │      └── \w+ = one or more word characters after "Permit"
         └── literal "Permit"

Task 3:  \w+Authentication
         │   │
         │   └── literal "Authentication" at the end
         └── \w+ = one or more word characters before it

Task 5:  ^Password.*yes
         │         │  │
         │         │  └── "yes" anywhere after
         │         └── .* = any characters in between
         └── ^ = must be at the START of line

Task 6:  yes$
         │  │
         │  └── $ = must be at the END of line
         └── literal "yes"
```

## 7. Catatan Keamanan: ReDoS, Bypass WAF & Regex Forensik

Dalam cybersecurity ofensif maupun defensif, regular expression adalah pedang bermata dua.

1. Regular Expression Denial of Service (ReDoS): ketika pola regex mengandung quantifier bertingkat (nested quantifiers) atau alternasi yang saling overlap, seperti `(a+)+$` atau `([a-zA-Z0-9]+)*`, regex engine berbasis NFA (Nondeterministic Finite Automaton) akan mengalami catastrophic backtracking. Memproses input seperti `aaaaaaaaaaaaaaaaaaaaaaaaaaaa!` membutuhkan waktu eksponensial ($O(2^n)$), membekukan CPU server dan melumpuhkan aplikasi (lihat *Mastering Regular Expressions*, Friedl).
2. WAF & filter evasion: input validation regex yang tidak ketat bisa dibypass. Anchor newline: pola `^https?://.*` tanpa flag multiline bisa dibypass dengan newline `\n`. Case sensitivity: penyerang memakai variasi huruf besar-kecil (`<sCrIpt>`) jika regex tidak memakai flag `-i` / `(?i)`. Alternasi tidak lengkap: filter blacklist kata kunci SQLi `UNION SELECT` bisa dibypass dengan inline comment `UNION/**/SELECT`.
3. Regex forensik: regex adalah fondasi aturan deteksi SIEM, IDS/IPS (Snort/Suricata), dan YARA rules untuk mendeteksi malware dan exfiltration.

```bash
# ── CYBERSECURITY REGEX PATTERNS CHEATSHEET ──────────────────

# 1. IPv4 Address Matching
grep -E -o '([0-9]{1,3}\.){3}[0-9]{1,3}' /var/log/auth.log

# 2. Extract Base64 Strings (length >= 32)
grep -E -o '[A-Za-z0-9+/]{32,}={0,2}' access.log

# 3. MD5 (32 hex) / SHA256 (64 hex) Hash Detection
grep -E -i '\b[a-f0-9]{32}\b' hashes.txt      # MD5
grep -E -i '\b[a-f0-9]{64}\b' hashes.txt      # SHA-256

# 4. Detect SQL Injection attempts in Web Server Access Logs
grep -E -i "(union.*select|select.*from|exec\(|insert.*into|drop.*table)" /var/log/apache2/access.log

# 5. Extract URLs from source text
grep -E -o 'https?://[a-zA-Z0-9./?=_-]+' input.txt
```

## Cheatsheet Referensi Cepat

```bash
# Basic grep with regex
grep "pattern" file.txt               # literal search
grep -E "pattern" file.txt            # extended regex
grep -v "pattern" file.txt            # exclude pattern
grep -i "pattern" file.txt            # case insensitive

# OR / AND logic
grep -E "(one|two)" file.txt          # OR: contains "one" or "two"
grep -E "(one.*two)" file.txt         # AND: contains both in order
grep "one" file.txt | grep "two"      # AND: chained pipes

# Anchors
grep -E "^word" file.txt              # lines STARTING with "word"
grep -E "word$" file.txt              # lines ENDING with "word"

# Character classes
grep -E "[0-9]+" file.txt             # lines with digits
grep -E "[a-z]+" file.txt             # lines with lowercase letters
grep -E "\w+" file.txt                # lines with word characters

# Quantifiers
grep -E "a{3}" file.txt               # exactly 3 "a"s
grep -E "a{2,4}" file.txt             # 2 to 4 "a"s

# Practical sshd_config examples
grep -v "#" /etc/ssh/sshd_config              # no comments
grep -E "^Password.*yes" /etc/ssh/sshd_config # password + yes
grep -E "yes$" /etc/ssh/sshd_config           # ends with yes
grep -E "Permit\w+" /etc/ssh/sshd_config      # starts with Permit
```
