## 1. Layanan Jaringan di Linux — Lapisan Daemon

**Network service** adalah daemon yang mendengarkan socket (TCP/UDP) dan melayani protokol jaringan: DNS, DHCP, NFS, SMB, SSH, HTTP, dan sejenisnya. Administrator Linux harus tahu siapa yang listen, di port berapa, dan konfigurasinya ada di mana.

```text
client request --L3/L4--> listener (port) → daemon → config + data
```

Linux sering menjalankan peran client sekaligus server pada jaringan. Konfigurasi client ada di `/etc/resolv.conf`, NetworkManager, atau systemd-networkd; peran server memakai paket khusus (`bind9`, `isc-dhcp-server`, `nfs-kernel-server`, `samba`).

```
Application                Kernel network stack
     │                              │
     │                              │
  dig/curl/mount.nfs  ←→  socket bind :53/:445/:2049
                                    │
                                    ▼
                            named / smbd / nfsd
```

| Service | Port default | Package (Debian) | Config hub |
|:---|:---:|:---|:---|
| DNS resolver (client) | (tidak ada) | `systemd-resolved` | `/etc/resolv.conf`, `/etc/systemd/resolved.conf` |
| DNS server | 53/tcp,udp | `bind9` | `/etc/bind/` |
| DHCP server | 67/udp | `isc-dhcp-server` | `/etc/dhcp/dhcpd.conf` |
| NFS | 2049/tcp | `nfs-kernel-server` | `/etc/exports` |
| Samba (SMB) | 445/tcp | `samba` | `/etc/samba/smb.conf` |
| SSH | 22/tcp | `openssh-server` | `/etc/ssh/sshd_config` |

## 2. Name Resolution — DNS & `/etc/hosts`

Sebelum melakukan query DNS eksternal, Linux memeriksa `/etc/hosts` (statis) terlebih dulu, baru kemudian resolver, biasanya `systemd-resolved` atau `/etc/resolv.conf`.

Urutan resolusi diatur oleh NSS (`/etc/nsswitch.conf`):

```text
gethostbyname → files (/etc/hosts) → dns → ...
```

Gunakan `dig`, `host`, atau `resolvectl` untuk mendiagnosis resolusi nama. DNS yang salah konfigurasi bisa membocorkan query atau membuka celah spoofing di jaringan tidak tepercaya; pilih resolver tepercaya dan aktifkan DNSSEC bila kebijakan mengharuskannya.

```bash
# Static local names (lab VMs you administer)
cat /etc/hosts
# 127.0.0.1   localhost
# 10.10.14.5  target.lab

# Resolver state
resolvectl status
cat /etc/resolv.conf

# Query DNS (authorized targets)
dig A example.com +short
dig MX example.com +short
host -t TXT example.com
nslookup example.com
```

| File / tool | Peran |
|:---|:---|
| `/etc/hosts` | Pemetaan hostname statis ke IP |
| `/etc/resolv.conf` | Daftar nameserver (sering symlink ke systemd-resolved) |
| `/etc/systemd/resolved.conf` | Stub listener `127.0.0.53`, opsi DNS over TLS |
| `dig` / `host` | Query diagnostik |
| `systemd-resolved` | Resolver stub dengan cache di distro modern |

**Sketsa server BIND minimal (khusus lab):**

```bash
sudo apt install bind9 -y
# /etc/bind/named.conf.local — zone definition for lab.internal
sudo named-checkconf
sudo systemctl reload bind9
dig @127.0.0.1 lab.internal SOA
```

## 3. DHCP — Dynamic Host Configuration

DHCP memberikan IP, gateway, DNS, dan opsi lain ke klien. Di desktop atau server Linux, klien biasanya memakai NetworkManager atau `dhclient`; server DHCP jarang ditemukan di edge kecuali di lingkungan lab.

Siklus lease pada sisi klien mengikuti urutan DISCOVER → OFFER → REQUEST → ACK. Renewal terjadi pada waktu T/2. Pantau lease di sisi server untuk mendeteksi DHCP nakal (penyerang di LAN yang menawarkan gateway atau DNS palsu).

```bash
# Client: view lease (NetworkManager)
nmcli dev show eth0 | grep -E 'IP4.ADDRESS|IP4.GATEWAY|IP4.DNS'

# Client: release / renew (legacy)
sudo dhclient -r eth0
sudo dhclient eth0

# Server config snippet (/etc/dhcp/dhcpd.conf) — lab
# subnet 10.10.14.0 netmask 255.255.255.0 {
#   range 10.10.14.100 10.10.14.200;
#   option routers 10.10.14.1;
#   option domain-name-servers 10.10.14.1;
# }
sudo systemctl enable --now isc-dhcp-server
```

| Risiko DHCP | Mitigasi |
|:---|:---|
| DHCP nakal di LAN | DHCP snooping di switch; 802.1X |
| Lease usang | Waktu lease pendek di pool dinamis |
| Tanpa logging | Log setiap assignment di server otoritatif |

## 4. NFS — Network File System

NFS mem-mount direktori remote lewat kernel client. Server mendefinisikan export di `/etc/exports`; klien memakai `mount -t nfs`.

NFSv4 menyederhanakan port (2049/tcp) dibanding NFSv3 lama (rpcbind plus beberapa port). Jangan pernah mengekspor path yang bisa ditulis oleh semua orang tanpa autentikasi kuat; gunakan Kerberos (`sec=krb5p`) di lingkungan produksi.

```bash
# Server
sudo apt install nfs-kernel-server -y
echo '/srv/nfs/share 10.10.14.0/24(rw,sync,no_subtree_check)' | sudo tee -a /etc/exports
sudo exportfs -ra
sudo systemctl enable --now nfs-server
showmount -e localhost

# Client (authorized lab network)
sudo mkdir -p /mnt/nfs_share
sudo mount -t nfs 10.10.14.10:/srv/nfs/share /mnt/nfs_share
df -hT /mnt/nfs_share
# Persistent: add to /etc/fstab
# 10.10.14.10:/srv/nfs/share  /mnt/nfs_share  nfs  defaults  0  0
```

| Opsi export | Arti |
|:---|:---|
| `rw` / `ro` | Baca-tulis vs baca saja |
| `sync` | Lebih aman; `async` lebih cepat tapi lebih berisiko saat crash |
| `no_root_squash` | Berbahaya, root remote dipetakan ke root lokal |
| `root_squash` | Pemetaan default yang lebih aman |

## 5. Samba — Berbagi File SMB/CIFS

Samba (`smbd`/`nmbd`) melayani protokol SMB milik Windows sehingga Linux bisa berbagi folder ke Windows/macOS atau mount share Windows.

Konfigurasi share ada di `/etc/samba/smb.conf`. Gunakan `smbpasswd` untuk membuat user Samba (terpisah dari password Unix kecuali diintegrasikan). Selalu uji dengan `testparm` sebelum reload.

```bash
sudo apt install samba -y
sudo testparm -s

# Minimal share block in smb.conf:
# [shared]
#   path = /srv/samba/shared
#   browseable = yes
#   read only = no
#   valid users = alice

sudo smbpasswd -a alice
sudo systemctl enable --now smbd nmbd

# Client mount (authorized)
sudo mount -t cifs //10.10.14.10/shared /mnt/smb -o username=alice,uid=1000
smbclient -L //10.10.14.10 -U alice
```

| Pemeriksaan | Perintah |
|:---|:---|
| Sintaks config | `testparm` |
| Share aktif | `smbstatus` |
| Status listen | `ss -tlnp \| grep smbd` |

## 6. Audit Layanan Jaringan yang Listen

Lakukan inventarisasi rutin: port terbuka, proses pemilik, dan unit systemd terkait. Setiap listener harus punya alasan bisnis yang jelas; petakan setiap listener ke kebutuhan operasional dan tandai bind `0.0.0.0` yang tidak diharapkan sebagai temuan prioritas tinggi.

```bash
# Modern socket audit
ss -tulnp
ss -tulnp | grep LISTEN

# Legacy (may be absent on minimal images)
netstat -tulnp 2>/dev/null

# Map to systemd units
systemctl list-units --type=service --state=running | grep -E 'ssh|nfs|samba|bind|apache|nginx'

# What owns port 445?
sudo lsof -i :445
sudo fuser -v 445/tcp
```

Keterpaparan makin besar untuk setiap layanan yang listening di `0.0.0.0` (semua interface) dan setiap layanan dengan autentikasi lemah.

## 7. Security Notes — Defense / Hardening

Layanan jaringan memperbesar permukaan serangan. Aturan default: jangan expose ke internet kecuali memang perlu, persempit export/share, dan audit listener secara berkala. Perlakukan setiap daemon tambahan sebagai eksposur tambahan; recursive DNS terbuka, guest share, dan `no_root_squash` adalah kesalahan konfigurasi klasik dengan dampak besar.

| Kesalahan konfigurasi | Dampak | Pertahanan |
|:---|:---|:---|
| NFS `no_root_squash` + subnet luas | Root remote bisa menulis file | `root_squash`; persempit export; Kerberos |
| Samba guest write | Malware bisa di-drop anonim | Nonaktifkan guest; wajib auth |
| DNS recursion terbuka ke internet | Disalahgunakan untuk amplifikasi | Allowlist recursion saja |
| DHCP nakal | MITM gateway/DNS | DHCP snooping; statis di server |
| Override `/etc/hosts` yang usang | Routing salah ke app internal | Configuration management |
| NFSv3 tanpa enkripsi di LAN tidak tepercaya | Sniffing data | NFSv4 + Kerberos atau VPN |

```bash
# Defensive audit (authorized admin)
grep -v '^#' /etc/exports 2>/dev/null
testparm -s 2>/dev/null | head -30
ss -tulnp | awk 'NR==1 || /0.0.0.0|:::/'
resolvectl dns
```
