## 1. Tujuan Backup — Kenapa Admin Melakukan Arsip

Backup mendukung availability dan integrity setelah kerusakan, ransomware, atau kesalahan manusia:

$$
\text{RPO} = \text{max data loss tolerated},\quad
\text{RTO} = \text{max downtime tolerated}
$$

Tanpa uji restore, backup hanyalah asumsi. Backup yang baik diukur dari Recovery Point Objective (RPO) dan Recovery Time Objective (RTO), ditambah integritas kriptografis salinan offline.

```
  Live system                 Backup store
 ┌──────────┐   tar/rsync    ┌────────────┐
 │  Data    │ ─────────────► │ Encrypted  │
 │  Config  │                │ offline /  │
 │  DB dump │ ◄───────────── │ offsite    │
 └──────────┘   restore test └────────────┘
```

| Tipe | Deskripsi | Contoh tool |
|:---|:---|:---|
| Full | Salinan lengkap | `tar`, imaging |
| Incremental | Perubahan sejak backup terakhir | `rsync`, borg, restic |
| Differential | Perubahan sejak full terakhir | Beragam |
| Snapshot | Point-in-time FS/volume | LVM, ZFS, btrfs |

## 2. Archiving dengan `tar`

`tar` (*tape archive*) menggabungkan banyak path menjadi satu stream/file.

| Flag | Arti |
|:---|:---|
| `-c` | Create |
| `-x` | Extract |
| `-t` | List |
| `-v` | Verbose |
| `-f` | Nama file arsip |
| `-C` | Ganti direktori saat extract |
| `-p` | Preserve permission (sebagai root) |

Untuk cron job privileged, utamakan daftar file eksplisit daripada glob yang tidak dikutip (lihat Security Notes).

```bash
# Create / list / extract
tar -cvf etc_backup.tar /etc/
tar -tvf etc_backup.tar
tar -xvf etc_backup.tar -C /tmp/restore/

# Exclude patterns
tar -czvf home.tgz /home/alice --exclude='*/.cache/*'
```

**Integritas setelah create:**

$$
h = \mathrm{SHA256}(\text{archive}),\quad
\text{store } h \text{ separately from the blob}
$$

```bash
sha256sum backup.tar.gz | tee backup.tar.gz.sha256
```

## 3. Format Kompresi

| Format | Flag `tar` | Ekstensi | Trade-off |
|:---|:---:|:---|:---|
| gzip | `-z` | `.tar.gz` / `.tgz` | Cepat, paling umum |
| bzip2 | `-j` | `.tar.bz2` | Rasio lebih tinggi, lebih lambat |
| xz | `-J` | `.tar.xz` | Rasio terbaik, berat di CPU |
| zstd | `--zstd` | `.tar.zst` | Kecepatan/rasio modern (tar versi baru) |

```bash
tar -czvf data.tar.gz /var/www/html/
tar -cjvf data.tar.bz2 /var/www/html/
tar -cJvf data.tar.xz /var/www/html/
tar -xvf data.tar.gz          # auto-detect on GNU tar often works
```

Intuisi rasio kompresi relatif:

$$
\text{size}_{\text{xz}} \lesssim \text{size}_{\text{bz2}} \lesssim \text{size}_{\text{gz}} \le \text{size}_{\text{raw}}
$$

(Rasio aktual bergantung pada entropi data.)

## 4. `rsync` — Sinkronisasi Incremental

`rsync` hanya mentransfer delta blok yang berubah, sehingga efisien untuk backup berkala.

| Flag | Arti |
|:---|:---|
| `-a` | Archive (permission, timestamp, symlink, rekursif) |
| `-v` | Verbose |
| `-z` | Compress saat transit |
| `-P` | Progress + resume partial |
| `-e ssh` | Transport SSH |
| `--delete` | Mirror penghapusan (berbahaya kalau salah arah) |
| `-n` / `--dry-run` | Simulasi |

Selalu jalankan `--dry-run` sebelum `--delete`. Trailing slash penting: `src/` menyalin isi, sedangkan `src` bisa menghasilkan nesting berbeda.

```bash
# Local
rsync -avzP /home/alice/documents/ /backup/alice/documents/

# Remote over SSH
rsync -avzP -e ssh /var/www/html/ backup@192.168.1.50:/remote/html/

# Safe mirror rehearsal
rsync -avzn --delete /data/ /backup/data/
```

Ide delta secara formal:

$$
\text{transfer} \approx \Delta\big(\text{src}, \text{dst}\big)
\quad\text{instead of}\quad
|\text{src}|
$$

## 5. `scp` / `sftp` — Salin lewat SSH

`scp` / `sftp` memakai autentikasi dan enkripsi SSH. Cocok untuk salinan ad-hoc; untuk sync berulang lebih baik gunakan `rsync` atau tool dedikasi seperti borg/restic.

Utamakan SSH berbasis key dan akun backup yang dibatasi (`ForceCommand`, chroot paksa, atau key khusus dengan path terbatas).

```bash
scp backup.tar.gz.gpg backup@server:/backups/
scp -r backup@server:/backups/2026-08-16/ ./restore-staging/
sftp backup@server
```

## 6. Enkripsi Backup dengan GnuPG

Arsip sering berisi rahasia (DB dump, key, config). Enkripsi at-rest:

$$
c = \mathsf{Enc}_k(m),\quad
m = \mathsf{Dec}_k(c)
$$

dengan $k$ berasal dari passphrase (simetris) atau public key penerima backup.

Gunakan enkripsi simetris AES-256 untuk disk offline sederhana, atau enkripsi asimetris ke public key tim backup sehingga operator tidak perlu berbagi satu passphrase.

```bash
gpg --symmetric --cipher-algo AES256 backup.tar.gz
gpg --output backup.tar.gz --decrypt backup.tar.gz.gpg

# Asymmetric (recipient pubkey already imported)
gpg --encrypt --recipient backups@example.com backup.tar.gz
```

Simpan passphrase / private key di password manager, HSM, atau amplop tersegel, jangan diletakkan di samping ciphertext pada USB stick yang sama.

## 7. Strategi — 3-2-1 dan Restore Drill

### Aturan 3-2-1
$$
3\ \text{copies},\quad
2\ \text{media types},\quad
1\ \text{offsite / offline}
$$

| Praktik | Detail |
|:---|:---|
| Katalog | Apa yang di-backup, jadwal, pemilik |
| Enkripsi | At-rest + in-transit (SSH/TLS) |
| Retensi | Memenuhi jendela legal/kepatuhan |
| Restore test | Minimal triwulanan untuk sistem kritikal |
| Access control | Akun backup bukan admin interaktif |
| Immutability | WORM / object-lock saat ransomware jadi perhatian |

```
Weekly drill (sketch)
─────────────────────
1. Pick random file set from catalog
2. Restore to isolated staging host
3. Verify checksums / app smoke test
4. Record RTO observed vs target
5. Fix gaps; update runbook
```

## 8. Security Notes — Defense / Hardening

| Risiko | Alasan | Pertahanan |
|:---|:---|:---|
| Backup tidak terenkripsi | Pencurian disk = kebocoran data | Enkripsi `gpg`/age/restic; kunci storage |
| Backup di web root | Dump bisa diunduh publik | Jangan simpan di bawah docroot; volume terpisah |
| `/var/backups` world-readable | Kebocoran data pengguna lokal | `750`/`640`, grup `backup` |
| Cron privileged + `tar *` di direktori writable | Argument injection lewat nama file yang dibuat khusus | Daftar file eksplisit; `find … -print0` + `--files-from`; jalankan dari direktori terkunci |
| `rsync --delete` salah arah | Penghapusan katastrofik salinan baik | Dry-run; model pull; snapshot sebelum delete |
| Daemon rsync terbuka (873) tanpa auth | Eksfiltrasi/overwrite data | Utamakan SSH; autentikasi; firewall |
| Hanya satu salinan online | Ransomware ikut mengenkripsi backup | Salinan offline/immutable/offsite |
| Tidak ada uji restore | Kepercayaan palsu | Drill terjadwal + checksum |

### Pola cron `tar` yang aman (konsep)
Utamakan:

```bash
# Explicit paths — no shell glob controlled by untrusted dirs
tar -czf /var/backups/etc-$(date +%F).tar.gz -C / etc
chmod 600 /var/backups/etc-*.tar.gz
```

Hindari job privileged yang `cd` ke tree world-writable dan menjalankan `tar … *`.

### Hardening akun backup
- User khusus, tanpa tool shell yang tidak perlu.
- SSH key dibatasi (`command=`, `from=`).
- Segmen jaringan/allowlist firewall terpisah.
- Pantau SSH gagal dan host restore yang tidak terduga.

```bash
# Permissions audit (admin)
namei -l /var/backups
find /var/backups -type f -perm -o=r -ls
```

## 9. Cheatsheet Referensi Cepat

```bash
# tar
tar -czvf backup.tar.gz /path
tar -tvf backup.tar.gz
tar -xvf backup.tar.gz -C /restore/
sha256sum backup.tar.gz

# rsync
rsync -avzP /src/ /dst/
rsync -avzn --delete /src/ /dst/     # dry-run mirror
rsync -avzP -e ssh /src/ user@host:/dst/

# scp
scp file.gpg user@host:/backups/

# gpg
gpg -c --cipher-algo AES256 backup.tar.gz
gpg -d backup.tar.gz.gpg > backup.tar.gz
```
