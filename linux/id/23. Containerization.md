## 1. Container vs Virtual Machine

Container membagikan kernel host; isolasi dicapai lewat namespaces dan cgroups, bukan hypervisor dengan guest kernel penuh.

$$
\text{VM} = \text{Guest OS} + \text{App},\quad
\text{Container} = \text{App + libs} \text{ on shared kernel}
$$

Container start cepat dan padat kepadatannya, tetapi container bukan VM. Kernel escape atau container `--privileged` yang berlebihan bisa mengompromikan host. Gunakan container dengan defense-in-depth: non-root, capability dikurangi, rootfs read-only.

```
┌─────────────────────────────────────────────┐
│ Host Linux Kernel                           │
│  ┌─────────────┐  ┌─────────────┐           │
│  │ Container A │  │ Container B │           │
│  │ PID/NET/MNT │  │ PID/NET/MNT │  (namespaces)
│  │ cgroups     │  │ cgroups     │           │
│  └─────────────┘  └─────────────┘           │
│         dockerd / containerd / podman       │
└─────────────────────────────────────────────┘

vs VM: each guest has its own kernel under a hypervisor
```

| Aspek | VM | Container |
|:---|:---|:---|
| Isolasi | Hardware/virtual HW | Kernel namespaces |
| Waktu boot | Menit | Detik |
| Densitas | Lebih rendah | Lebih tinggi |
| Kernel | Per guest | Dibagikan |
| Tool umum | KVM, VMware | Docker, Podman |

## 2. Primitif Linux — Namespaces & cgroups

Kernel menyediakan blok isolasi: namespaces memisahkan tampilan (PID, net, mount, dst.) dan cgroups membatasi resource.

| Namespace | Yang diisolasi |
|:---|:---|
| `pid` | Process ID |
| `net` | Interface, route, port |
| `mnt` | Mount tree |
| `uts` | Hostname |
| `ipc` | Objek IPC |
| `user` | Pemetaan UID/GID (rootless) |

cgroups membatasi CPU, memory, I/O, dan jumlah PID.

Capability memecah kekuatan root (`CAP_NET_BIND_SERVICE`, dan lainnya). Docker secara default menjatuhkan banyak capability; `--cap-add` memperluas permukaan serangan.

```bash
# Peek at container namespaces (host admin, container ID from docker ps)
pid=$(docker inspect -f '{{.State.Pid}}' mycontainer)
sudo ls -l /proc/$pid/ns/
sudo cat /proc/$pid/cgroup
```

## 3. Workflow Inti Docker

Instal `docker.io` (Debian) atau `docker-ce`. Daemon `dockerd` mengelola image dan container.

Image adalah FS read-only berlapis plus metadata; container adalah writable layer di atasnya. Registry default adalah Docker Hub; pin digest di produksi.

```bash
# Install (Debian/Ubuntu lab)
sudo apt update && sudo apt install docker.io -y
sudo systemctl enable --now docker
sudo usermod -aG docker $USER   # re-login for group

# Pull & run
docker pull nginx:1.25-alpine
docker run -d --name web -p 8080:80 nginx:1.25-alpine
docker ps
docker logs web
docker stop web && docker rm web

# Inspect
docker inspect web
docker image ls
docker system df
```

| Perintah | Aksi |
|:---|:---|
| `docker pull` | Download image |
| `docker run` | Buat + start container |
| `docker ps -a` | List container |
| `docker exec -it` | Shell di dalam container yang berjalan |
| `docker rm` / `docker rmi` | Hapus container / image |

## 4. Dockerfile & Docker Compose

Dockerfile mendefinisikan build image; Compose mengorkestrasi multi-container di lab/dev.

Multi-stage build memperkecil image akhir. Jangan pernah menyematkan secret di dalam layer; gunakan build secret atau env runtime dari vault.

**Dockerfile minimal:**

```dockerfile
FROM python:3.12-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
USER 1000:1000
EXPOSE 8000
CMD ["python", "-m", "http.server", "8000", "--bind", "0.0.0.0"]
```

```bash
docker build -t myapp:lab .
docker run -d -p 8000:8000 --read-only --tmpfs /tmp myapp:lab
```

**Sketsa docker-compose.yml:**

```yaml
services:
  web:
    image: nginx:alpine
    ports:
      - "127.0.0.1:8080:80"
    read_only: true
  db:
    image: postgres:16-alpine
    environment:
      POSTGRES_PASSWORD: changeme
    volumes:
      - pgdata:/var/lib/postgresql/data
volumes:
  pgdata:
```

```bash
docker compose up -d
docker compose ps
docker compose logs -f web
docker compose down
```

## 5. Podman — Alternatif Rootless-First

Podman bersifat daemonless (model fork-exec), cocok untuk container rootless tanpa grup `docker`.

CLI-nya sebagian besar kompatibel dengan Docker: `podman run`, `podman build`. Integrasi systemd lewat `podman generate systemd`.

```bash
sudo apt install podman -y
podman run -d --name web -p 8080:80 docker.io/library/nginx:alpine
podman ps
podman exec -it web sh

# Rootless (unprivileged user)
podman run --rm -it alpine id
```

| Docker | Ekuivalen Podman |
|:---|:---|
| `docker` | `podman` |
| `docker compose` | `podman compose` |
| daemon socket | tanpa daemon sentral |

## 6. Operasi Day-2

Monitoring resource, restart policy, backup volume, dan rotasi log adalah pekerjaan rutin setelah container berjalan.

Bind-mounting `/` host atau socket Docker ke dalam container memberi kekuatan setara host; ini dilarang dalam pola produksi.

```bash
# Resource stats
docker stats --no-stream

# Restart policies
docker run -d --restart unless-stopped nginx:alpine

# Volumes
docker volume create appdata
docker run -v appdata:/data alpine sh -c 'echo test > /data/file'

# Interactive debug (authorized)
docker exec -it mycontainer sh
docker cp mycontainer:/etc/nginx/nginx.conf ./nginx.conf.bak
```

## 7. Security Notes — Defense / Breakout Awareness

Postur aman: non-root, tanpa `--privileged`, tanpa socket Docker di-mount, pin image, dan scan lewat registry tepercaya.

Riset container escape hanya boleh dilakukan di lingkungan lab berizin. Defender fokus pada pengurangan capability, profil seccomp/AppArmor, dan patching kernel.

| Kesalahan konfigurasi | Dampak | Pertahanan |
|:---|:---|:---|
| `--privileged` | Hampir setara root di host | Hindari; capability minimal |
| Mount `/var/run/docker.sock` | Kontrol atas semua container | Jangan pernah di workload tidak tepercaya |
| Jalankan sebagai root di container | Rantai escape lebih mudah | `USER` non-root di Dockerfile |
| `:latest` di produksi | Drift supply-chain | Pin digest/versi |
| Image dari registry publik | Malware/backdoor | Scan (Trivy/Grype); registry tepercaya |
| Secret di env/build args | Bocor lewat `docker inspect`/history | Secrets manager, inject saat runtime |
| Mode network host `--network host` | Berbagi network stack host | Default bridge kecuali memang perlu |

```bash
# Defensive posture checks (authorized)
docker info 2>/dev/null | grep -i root
docker ps --quiet | xargs -r docker inspect -f '{{.Name}} privileged={{.HostConfig.Privileged}} caps={{.HostConfig.CapAdd}}'
# podman
podman ps --format '{{.Names}} {{.Privileged}}'
```
