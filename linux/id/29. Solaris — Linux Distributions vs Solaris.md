## 1. Apa Itu Oracle Solaris?

Solaris (dulu SunOS/Sun Solaris) adalah Unix komersial dari Sun Microsystems (sekarang Oracle). Solaris berbagi DNA BSD/System V dengan Linux, tetapi kernel, userland, init, packaging, dan FS default-nya berbeda.

$$
\text{Solaris stack} = \text{Sun/Oracle kernel} + \text{SMF} + \text{ZFS default} + \text{Zones} + \text{IPS pkg}
$$

Solaris tetap relevan di lingkungan enterprise SPARC/x86, telco, dan estate legacy. Pentester dan admin akan bertemu Solaris berdampingan dengan Linux; memahami perbedaannya mempercepat recon dan hardening.

```
Timeline (simplified)
  1990s  SunOS / Solaris 2.x
  2000s  Solaris 8/9/10 — ZFS, Containers preview
  2010s  Oracle acquisition; Solaris 11 + IPS
  today  Oracle Solaris 11.x (maintenance-focused)
         Linux distros dominate cloud; Solaris in legacy/verticals
```

| Properti | Solaris | Linux umum |
|:---|:---|:---|
| Vendor | Oracle | Campuran komunitas/komersial |
| Init / service | SMF | systemd (mayoritas distro) |
| FS default | ZFS (modern) | ext4/XFS/btrfs |
| Container | Zones | cgroups/namespaces (Docker/Podman) |
| Package manager | IPS (`pkg`) | apt/dnf/pacman |
| Lisensi | Proprietary (Oracle) | Mayoritas open source |

## 2. Solaris vs Linux — Perbedaan Kunci bagi Admin

Admin yang terbiasa dengan Linux akan menemui CLI dan path yang berbeda, meski konsep (user, proses, jaringan) mirip.

| Area | Solaris | Linux |
|:---|:---|:---|
| Nama kernel | Sun/Oracle kernel | Linux kernel |
| Kontrol service | `svcadm`, `svcs` | `systemctl` |
| Boot loader | GRUB (x86) | GRUB/systemd-boot |
| Konfigurasi jaringan | `dladm`, `ipadm`, `route` | `ip`, NetworkManager |
| File user/group | `/etc/passwd`, `/etc/shadow` | Konsep FHS yang sama |
| Daftar proses | `ps`, `pgrep`, `/proc` | Ide sama, flag `ps` berbeda |
| Firewall | IPFilter secara historis; pola `pf` | iptables/nft/ufw |

Banyak tool GNU tersedia di Solaris lewat paket GNU userland, tetapi path dan flag-nya berbeda. Script yang portable di Linux bisa gagal di Solaris tanpa penyesuaian.

```bash
# Linux habit          →  Solaris equivalent (illustrative — Solaris 11)
# systemctl status ssh →  svcs -xv ssh
# df -hT               →  zfs list  (when ZFS root)
# ip addr              →  ipadm show-addr
# apt install curl     →  pkg install curl
# crontab -l           →  crontab -l (similar, different paths)
```

## 3. SMF — Service Management Facility

SMF menggantikan skrip init legacy dengan FMRI (Fault Management Resource Identifier) dan graf ketergantungan.

$$
\text{FMRI} = \texttt{svc:/category/service:instance}
$$

Contoh: `svc:/network/ssh:default`

SMF melacak state service (`online`, `offline`, `maintenance`), me-restart saat gagal, dan mengurutkan startup berdasarkan dependency; secara konsep mirip systemd tapi dengan CLI dan manifest XML yang berbeda.

```bash
# List services
svcs -a
svcs -x                    # failed/maintenance
svcs -l ssh                # detailed

# Enable / start / stop
sudo svcadm enable ssh
sudo svcadm disable ssh
sudo svcadm restart ssh
sudo svcadm clear ssh      # clear maintenance state

# Inspect properties
svcprop -p all ssh
```

| State SMF | Arti |
|:---|:---|
| `online` | Berjalan / terpenuhi |
| `offline` | Dinonaktifkan/dihentikan |
| `maintenance` | Butuh intervensi admin |
| `degraded` | Fungsi sebagian |

Bandingkan dengan systemd Linux, lihat catatan 17 (`systemctl`, `journalctl`).

## 4. Packaging IPS — `pkg`

Image Packaging System (IPS) mengelola software dengan publisher Oracle dan dependency solver.

Gunakan `pkg`, bukan `apt`/`yum`. Boot environment (BE) dipasangkan dengan ZFS untuk upgrade yang bisa di-rollback.

```bash
pkg publisher
pkg search curl
pkg info -r curl
sudo pkg install curl
pkg list
pkg update

# Verify package contents
pkg contents -H curl

# Create boot environment before major update (ZFS systems)
beadm list
sudo beadm create pre-update-$(date +%Y%m%d)
```

| Perintah | Aksi |
|:---|:---|
| `pkg install PKG` | Install paket |
| `pkg update` | Update set yang terpasang |
| `pkg verify` | Cek integritas file |
| `beadm activate BE` | Boot ke snapshot BE |

## 5. ZFS — Zettabyte File System

ZFS menggabungkan volume manager dan file system: copy-on-write, checksum, snapshot, kompresi, dan dedup (hati-hati dengan konsumsi RAM).

$$
\text{Dataset path: } \texttt{tank/home/alice} \subset \texttt{tank/home} \subset \texttt{tank (pool)}
$$

Linux kini punya OpenZFS di beberapa distro, tetapi integrasi di Solaris bersifat native dan lebih matang. Admin berpikir dalam istilah pool dan dataset, bukan hanya `/dev/sda1`.

```bash
# Pool & dataset (Solaris)
zpool list
zpool status
zfs list
zfs create tank/export
zfs set compression=lz4 tank/export
zfs snapshot tank/export@backup-$(date +%F)
zfs rollback tank/export@backup-2026-08-18

# Quotas & reservations
zfs set quota=50G tank/home/alice
zfs set reservation=10G tank/home/alice
```

| Fitur ZFS | Manfaat |
|:---|:---|
| Checksumming | Deteksi korupsi diam-diam |
| Snapshot | Point-in-time instan |
| Send/receive | Replikasi |
| Kompresi | Hemat ruang (trade-off CPU) |

Dasar LVM/ext4 di Linux, lihat catatan 22.

## 6. Solaris Zones — Virtualisasi Level OS

Zones adalah isolasi level kernel (seperti container modern): global zone plus non-global zone dengan namespace terpisah.

Konsep ini mendahului container Linux tapi punya tujuan serupa. Kernel zone vs native zone berbeda kekuatan isolasinya. Zones bukan Docker, tapi secara konsep berkaitan dengan catatan 23.

```bash
# Zone management (illustrative)
zonecfg -z myzone
zoneadm -z myzone install
zoneadm -z myzone boot
zlogin myzone

# From global zone
zoneadm list -cv
```

```
Global Zone (host)
 ├─ Zone: web01   (own /etc, users, SMF subset)
 ├─ Zone: db01
 └─ Zone: dev01
Shared kernel, isolated userlands
```

## 7. Security Notes — Sorotan Hardening Solaris

Identifikasi OS terlebih dahulu; mengira Solaris sebagai Linux membuat enumerasi service dan jalur hardening jadi salah arah.

Petakan kontrol Solaris ke analognya di Linux: RBAC/role vs sudo, audit daemon vs auditd, Trusted Extensions vs SELinux. Verifikasi paket dengan `pkg verify`.

| Topik | Praktik Solaris | Analog Linux |
|:---|:---|:---|
| RBAC / role | `roleadd`, `profiles` | sudo + grup |
| Audit | Solaris audit daemon | auditd |
| MAC | Trusted Extensions (niche) | SELinux/AppArmor |
| Kebijakan password | `/etc/security/policy.conf` | `login.defs`, PAM |
| Akses remote | Service SMF `ssh` | Unit systemd `sshd` |
| Minimisasi | Variant set `pkg` | Image cloud minimal |

```bash
# Defensive recon (authorized Solaris host)
uname -a
cat /etc/release
svcs -x
netstat -an -f inet | grep LISTEN    # or ss equivalent if installed
pkg verify
zfs list
```

**Tips asesmen:** identifikasi OS sejak awal; mengira Solaris sebagai Linux membawa ke jalur privilege escalation dan enumerasi service yang salah.
