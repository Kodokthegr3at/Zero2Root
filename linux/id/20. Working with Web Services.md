## 1. Layanan HTTP di Linux — Peran Web Stack

Web service di Linux biasanya terdiri dari alur berikut:

```text
Client --HTTP/HTTPS--> Listener (80/443) → Daemon → DocRoot + App
```

Daemon yang umum dipakai: Apache (`httpd`/`apache2`), Nginx, dan kadang Caddy. Di belakangnya bisa ada PHP-FPM, uWSGI, atau reverse proxy menuju aplikasi kontainer. Administrator harus memahami document root, listener socket, log, dan sertifikat TLS.

```
Internet / LAN
      │
      ▼
 ┌────────────┐     ┌──────────────┐
 │ Firewall   │────►│ nginx/apache │
 │ (ufw/nft)  │     │ :80 / :443   │
 └────────────┘     └──────┬───────┘
                           │
              ┌────────────┼────────────┐
              ▼            ▼            ▼
           DocRoot      PHP-FPM      Upstream app
         /var/www/…                 127.0.0.1:8000
```

| Port | Protokol | Kegunaan umum |
|:---:|:---|:---|
| 80 | HTTP | Redirect ke HTTPS atau ACME |
| 443 | HTTPS | Traffic produksi |
| 8080/8000 | HTTP | Bind lokal/dev (utamakan loopback) |

## 2. Apache HTTP Server

Pada Debian/Ubuntu, paket `apache2` memakai layout berikut:

| Path | Peran |
|:---|:---|
| `/var/www/html/` | Document root default |
| `/etc/apache2/apache2.conf` | Config utama |
| `/etc/apache2/ports.conf` | Direktif listen |
| `/etc/apache2/sites-available/` | Definisi site |
| `/etc/apache2/sites-enabled/` | Symlink site yang aktif |
| `/etc/apache2/mods-enabled/` | Modul yang aktif |
| `/var/log/apache2/` | `access.log`, `error.log` |

Aktifkan site dengan `a2ensite`, modul dengan `a2enmod`, lalu jalankan `apache2ctl configtest` sebelum reload.

```bash
sudo apt install apache2 -y
sudo systemctl enable --now apache2
sudo apache2ctl configtest
sudo a2enmod headers ssl rewrite
sudo a2ensite 000-default.conf
sudo systemctl reload apache2
systemctl status apache2 --no-pager
```

**Ide hardening minimal (Apache):**
- Nonaktifkan modul yang tidak dipakai (`a2dismod`).
- Set opsi `Directory` yang ketat (tanpa Indexes kecuali diperlukan).
- Gunakan user service khusus; jangan pernah `chmod -R 777` pada docroot.

## 3. Nginx — Server Event-Driven & Reverse Proxy

Nginx unggul sebagai reverse proxy dan static file server. Konfigurasinya:

| Path | Peran |
|:---|:---|
| `/etc/nginx/nginx.conf` | Setting global |
| `/etc/nginx/sites-available/` | Server block |
| `/etc/nginx/sites-enabled/` | Link yang aktif |
| `/var/log/nginx/access.log` | Telemetri akses |
| `/var/log/nginx/error.log` | Error |

Selalu jalankan `nginx -t` sebelum `reload`. Aplikasi upstream sebaiknya listen di localhost bila memungkinkan; hanya proxy yang diekspos.

```bash
sudo apt install nginx -y
sudo nginx -t
sudo systemctl enable --now nginx
sudo systemctl reload nginx
```

Contoh sketsa reverse proxy (untuk edukasi admin):

```nginx
server {
    listen 443 ssl http2;
    server_name app.example.com;
    # ssl_certificate     /etc/ssl/...;
    # ssl_certificate_key /etc/ssl/...;

    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

## 4. TLS Termination — Hal Penting bagi Admin

TLS menyediakan kerahasiaan dan integritas untuk record layer HTTP:

HTTPS hanyalah HTTP yang dikirim di dalam koneksi TLS, dan klien memeriksa rantai sertifikat server sampai ke root yang dipercaya.

| Praktik | Alasan |
|:---|:---|
| Utamakan TLS 1.2+ (idealnya 1.3) | Hindari protokol usang |
| HSTS setelah HTTPS terbukti stabil | Kurangi risiko SSL-strip |
| Permission private key terpisah `600` root | Tahan terhadap kebocoran kunci |
| Otomasi renewal (misalnya ACME) | Hindari sertifikat kedaluwarsa |
| Redirect 80→443 | UX keamanan yang konsisten |

```bash
# Inspect remote cert (ops / monitoring)
echo | openssl s_client -connect example.com:443 -servername example.com 2>/dev/null \
  | openssl x509 -noout -dates -subject -issuer
```

## 5. Server HTTP Ringan — Khusus Lab Lokal

Server HTTP satu baris berguna untuk prototipe lokal: dokumentasi atau file statis di loopback. Jangan mengekspos ke jaringan yang tidak tepercaya tanpa autentikasi/TLS. Server bawaan ini ditujukan untuk pengembangan lokal berizin; bind ke `127.0.0.1` secara default, dan perlakukan bind ke `0.0.0.0` sebagai eksposur yang disengaja dan memerlukan aturan firewall.

```bash
# Prefer loopback for labs
python3 -m http.server 8000 --bind 127.0.0.1
php -S 127.0.0.1:8080
```

| Tool | Cocok untuk | Perhatian |
|:---|:---|:---|
| `python3 -m http.server` | File statis | Tanpa auth; listing direktori |
| `php -S` | Uji cepat PHP | Bukan untuk produksi |
| `npx http-server` | Preview SPA statis | Cek bind jaringan |

## 6. Klien Terminal — `curl` & `wget`

`curl` cocok untuk inspeksi header, metode HTTP, dan debugging API. `wget` cocok untuk unduhan file atau mirroring terkontrol.

Gunakan klien ini untuk memverifikasi service milik sendiri: status code, redirect, TLS, dan response header. Hindari mem-pipe konten remote langsung ke shell pada host produksi.

```bash
curl -I https://localhost/                 # headers only
curl -v https://app.example.com/health     # verbose trace
curl -o /tmp/file.tgz https://example.com/file.tgz

wget -c https://example.com/large.iso      # resume
wget --spider https://example.com/         # reachability check
```

**Pola operasional aman:** unduh, hitung checksum, inspeksi, baru install.

```text
sha256sum file    →  harus sama dengan hash yang dipublikasikan vendor
```

## 7. Virtual Host (Hosting Berbasis Nama)

Satu IP dapat melayani banyak nama domain. Server memilih vHost berdasarkan header HTTP `Host:` (atau SNI pada TLS).

Name-based virtual hosting memungkinkan banyak situs dilayani oleh satu listener. vHost default yang salah konfigurasi sering membocorkan situs staging; set default eksplisit yang mengembalikan `404`/`444`.

```
Client request: GET / HTTP/1.1
Host: admin.example.com
        │
        ▼
   Match server_name / ServerName
        │
        ▼
   DocRoot or proxy for that site
```

```bash
# Test Host routing against your lab IP (authorized hosts only)
curl -H "Host: app.lab.local" http://127.0.0.1/

# Local name resolution for lab VMs you control
# (edit /etc/hosts only on machines you administer)
```

Apache memisahkan file di bawah `sites-available/`. Nginx memisahkan blok `server { server_name … }`.

## 8. Security Notes — Defense / Hardening

| Kesalahan konfigurasi | Dampak | Pertahanan |
|:---|:---|:---|
| Directory indexing aktif | Bocornya backup, `.env`, dump | `Options -Indexes` / `autoindex off` |
| Docroot world-writable (`777`) | Perubahan konten tak sah | `755` untuk direktori, `644` untuk file; deploy via user CI |
| `phpinfo` / `server-status` default publik | Kebocoran informasi | Hapus atau batasi per IP + auth |
| App listen di `0.0.0.0` tanpa firewall | Permukaan serangan remote | Bind ke localhost; proxy; allowlist UFW/nft |
| Panel admin HTTP-only | Sniffing kredensial | Paksa HTTPS, HSTS, auth kuat |
| Pipe script remote langsung ke shell | Risiko supply-chain | Verifikasi checksum; gunakan package manager |
| Halaman error verbose di produksi | Kebocoran path/stack | Error generik; log detail hanya di sisi server |

### Checklist hardening
1. TLS di semua traffic non-lab, dengan cipher modern.
2. Least privilege untuk user `www-data`/`nginx`, tanpa akses shell login.
3. Pisahkan direktori upload yang bisa ditulis dari direktori script yang bisa dieksekusi.
4. Kirim log access/error ke central store; pantau lonjakan 4xx/5xx.
5. Selalu update paket (`apt`/`dnf`); hapus modul yang tidak dipakai.
6. Pasang WAF/rate-limit di edge saat menghadap internet.

```bash
# Posture snippets (admin)
namei -l /var/www/html | head
sudo apache2ctl -M 2>/dev/null | head
sudo nginx -T 2>/dev/null | grep -E 'listen|server_name|root' | head
ss -tulnp | grep -E ':80|:443'
```
