## Istilah penting

Istilah-istilah ini akan sering muncul di materi.

| Istilah | Artinya |
|:---|:---|
| Distribusi (distro) | OS siap pakai yang dibangun dari kernel Linux plus tool |
| Package manager | Tool yang menginstal/memperbarui software (`apt`, `dnf`, `pacman`) |
| Repository | Gudang online paket tempat distro menginstal |
| Base distro | Distro yang jadi dasar distro lain (Debian → Ubuntu → Mint) |
| Rolling vs fixed release | Selalu update terbaru vs. versi bernomor berkala |
| LTS | Long-Term Support: rilis yang di-patch bertahun-tahun |
| Desktop environment | Antarmuka grafis (GNOME, KDE) |
| Init system | Yang memulai dan mengawasi service saat boot (biasanya systemd) |

## 1. Apa itu Distribusi Linux?

Linux Distribution (Distro) adalah sistem operasi lengkap yang mengemas:

```text
Distro = kernel Linux        (inti)
       + userland            (tool GNU, library)
       + package manager     (apt / dnf / pacman)
       + kebijakan           (default, init system, branding)
```

Kernel Linux sendiri bukan OS desktop/server yang siap pakai. Distro menambahkan toolchain GNU, systemd (atau alternatifnya), repositori paket, dan kebijakan keamanan default.

Bisa dibilang setiap distro adalah "cabang" yang kompatibel satu sama lain karena berbagi filosofi ABI kernel yang sama, tapi berbeda dalam siklus rilis, versi paket, dan default keamanan.

| Layer | Contoh | Peran |
|-------|--------|-------|
| Kernel | `linux`, modules, firmware | Isolasi hardware + proses |
| C library | glibc, musl | Wrapper syscall |
| Init | systemd, OpenRC | Boot & supervisi service |
| Packages | deb, rpm, pkg | Install / upgrade / remove |
| Policy | Default SELinux/AppArmor | Baseline confinement |

## 3. Model Rilis: Stable, Rolling, LTS

| Model | Siklus | Gaya patch | Cocok untuk | Risiko |
|-------|--------|------------|--------------|--------|
| Stable | ~1-2 tahun | Backport fix keamanan | Server, kepatuhan (compliance) | Fitur lebih lama |
| LTS | Dukungan 2-5+ tahun | Keamanan + fix terpilih | Enterprise, produksi | Fitur baru lebih lambat |
| Rolling | Berkelanjutan | Upstream terbaru | Desktop, lab | Rawan breakage / churn |
| Point / Snapshot | Tree beku | Rebuild berkala | Build yang reproducible | Upgrade manual |

Untuk server produksi, prioritaskan Debian Stable, Ubuntu LTS, RHEL, Alma, atau Rocky. Rolling (Arch, Kali rolling) cocok untuk lab, bukan baseline produksi tanpa proses hardening yang ketat.

### Perbandingan umum

| Distro | Cocok untuk | PM | Init | MAC default |
|--------|-------------|----|----|-------------|
| Ubuntu | Desktop, cloud images | `apt` | systemd | AppArmor |
| Debian | Server, appliance | `apt` | systemd | AppArmor (opsional) |
| Fedora | Desktop/dev teknologi terbaru | `dnf` | systemd | SELinux |
| RHEL / Alma / Rocky | Server enterprise | `dnf` | systemd | SELinux |
| Arch | DIY / belajar | `pacman` | systemd | (manual) |
| openSUSE | Enterprise + YaST | `zypper` | systemd | AppArmor |

Catatan: CentOS Linux versi klasik (rebuild) sudah EOL (end of life). Gunakan AlmaLinux, Rocky Linux, atau CentOS Stream secara sadar sesuai kebutuhan.

## 5. Distro Berorientasi Keamanan

Distro "security" biasanya berarti dua hal: (1) toolset yang sudah terpasang untuk lab/audit, atau (2) desain yang mengutamakan privasi/hardening. Gunakan di VM/lab terisolasi. Jangan jadikan daily driver produksi tanpa kebijakan patch dan least privilege.

| Distro | Basis | Fokus (edukasi defense) | Catatan |
|--------|-------|--------------------------|---------|
| Kali Linux | Debian | Ekosistem tool security | Rolling; bukan OS server produksi |
| Parrot OS | Debian | Security + desktop lebih ringan | Umum dipakai di lab training |
| BlackArch | Arch | Kumpulan paket security yang besar | Repo tambahan tersedia |
| Qubes OS | Xen + template Fedora | UX isolasi yang kuat | Threat model berbeda |
| Tails | Debian | Live amnesic / privasi | Sesi live via USB |

```
Why Linux dominates security workstations (defense view)
───────────────────────────────────────────────────────
Open source  → audit patches, reproduce builds
Control      → minimal services, clear attack surface
Tooling      → native packet capture, scripting, containers
Packaging    → signed updates via distro security teams
```

## 6. Memilih Distro: Matriks Keputusan

| Kebutuhan | Pilih | Hindari sebagai utama |
|-----------|-------|------------------------|
| Server produksi 24/7 | Debian Stable, Ubuntu LTS, keluarga RHEL | Rolling yang belum teruji |
| Compliance / dukungan jangka panjang | RHEL, Ubuntu LTS, Debian LTS | Spin berumur pendek |
| Desktop untuk pemula | Ubuntu, Fedora Workstation, Mint | Arch minimal (sebelum siap) |
| Embedded / SBC | Raspberry Pi OS, Debian | Spin desktop yang berat |
| Lab security berizin | Kali/Parrot di dalam VM | Image yang sama dengan gateway produksi |
| Build reproducible | Debian, NixOS*, Guix* | Binary ad-hoc tanpa kontrol |

\*NixOS/Guix memakai model deklaratif khusus, unggul untuk reproducibility, tapi kurva belajarnya lebih curam.

### Gagasan formal "jendela dukungan"

Jika laju penemuan CVE adalah λ per tahun dan rata-rata waktu-ke-patch di bawah LTS adalah T, paparan residual kurang lebih berskala dengan λ·T ketika patching tertunda. Prioritaskan channel dengan backport keamanan yang cepat.

## 7. Debian Secara Mendalam

Debian dikenal karena proses freeze yang ketat, keamanan lewat Debian Security, dan ekosistem apt/dpkg. Banyak distro (Ubuntu, Kali, Parrot) adalah turunan dari kebijakan Debian.

Suites (channel):
- `stable`, untuk produksi.
- `testing`, calon stable berikutnya.
- `unstable` (`sid`), untuk development, bukan untuk server.

Kekuatan Debian ada pada pemilihan paket yang konservatif, dukungan keamanan jangka panjang, dan kebijakan packaging yang terdokumentasi dengan baik. Ubuntu mewarisi banyak dari ini sambil menambahkan siklus desktop/cloud yang lebih cepat serta layer Launchpad/Snap.

```
Debian suites (simplified)
──────────────────────────
unstable ──► testing ──► stable ──► oldstable
   (sid)      (freeze)     (prod)     (LTS/ELTS may apply)
```

### Referensi cepat APT (keluarga Debian)

```bash
# Refresh indices & apply security updates
sudo apt update
sudo apt upgrade                 # or: sudo apt full-upgrade when needed

sudo apt install <pkg>
sudo apt remove <pkg>
sudo apt purge <pkg>             # remove config too
apt search <keyword>
apt show <pkg>
apt list --installed
dpkg -l | less
```

### Channel keamanan

- Install `unattended-upgrades` di server Debian/Ubuntu untuk patch keamanan otomatis.
- Prioritaskan mirror resmi / HTTPS, dan verifikasi release key saat instalasi.

## 8. Identitas Distro di Host Live

```bash
cat /etc/os-release          # ID, VERSION_ID, VARIANT
lsb_release -a               # if package installed
hostnamectl                  # pretty OS + kernel
uname -r                     # kernel release
cat /etc/debian_version      # Debian-derived
cat /etc/redhat-release      # RHEL-family
```

| Field (`os-release`) | Arti |
|-----------------------|------|
| `ID` | ID distro (`debian`, `ubuntu`, `fedora`) |
| `ID_LIKE` | Petunjuk keluarga (`debian`, `rhel`) |
| `VERSION_CODENAME` | Nama suite (`bookworm`, `noble`) |
| `SUPPORT_END` | Akhir dukungan (jika tersedia) |

## 9. Catatan Keamanan: Defense / Hardening

| Ancaman / celah | Kenapa penting | Defense |
|------------------|-----------------|---------|
| Distro tidak didukung / EOL | Tidak ada backport keamanan | Upgrade ke LTS yang didukung; inventarisasi dengan `os-release` |
| Mencampur PPA acak / RPM pihak ketiga | Risiko supply-chain & trust | Prioritaskan repo resmi; pin & review key |
| Memakai Kali/Parrot sebagai gateway produksi | Attack surface tambahan | Hanya untuk VM lab; produksi pakai stable minimal |
| Paket belum di-patch | CVE yang sudah diketahui tetap terbuka | `unattended-upgrades` / dnf-automatic; pantau DSA/USN |
| Container host yang flat tanpa update | Risiko kernel yang dibagi bersama | Patch kernel host; isolasi dengan namespace + MAC |
| Percaya buta pada branding "security" | Tools bukan berarti default sudah hardened | Terapkan checklist hardening (lihat catatan LC-026) |

### Baseline hardening per keluarga

1. Tetap di rilis yang didukung; berlangganan mailing list/RSS keamanan.
2. Aktifkan update keamanan otomatis (security-only) bila kebijakan mengizinkan.
3. Jaga AppArmor (Debian/Ubuntu) atau SELinux (RHEL/Fedora) tetap enforcing.
4. Minimalkan paket terinstal: makin banyak paket, makin luas attack surface.
5. Pisahkan image lab dari image produksi.

```bash
# Quick posture checks (admin / auditor)
grep -E '^(NAME|VERSION|SUPPORT)' /etc/os-release
systemctl is-enabled unattended-upgrades 2>/dev/null || true
aa-status 2>/dev/null | head          # AppArmor hosts
getenforce 2>/dev/null                # SELinux hosts
```

## 10. Cheatsheet Referensi Cepat

```bash
# Identity
cat /etc/os-release && uname -a

# Debian/Ubuntu updates
sudo apt update && sudo apt upgrade
apt-cache policy <pkg>

# Fedora / RHEL family
sudo dnf check-update
sudo dnf upgrade

# Arch
sudo pacman -Syu

# Package counts (rough surface)
dpkg -l | wc -l
rpm -qa | wc -l
```

| Fitur | Ubuntu LTS | Debian Stable | Fedora | RHEL/Alma/Rocky | Arch | Kali (lab) |
|-------|------------|----------------|--------|------------------|------|------------|
| Siklus | LTS 2 tahun | ~2 tahun | ~6 bulan | Dukungan panjang | Rolling | Rolling |
| MAC default | AppArmor | AppArmor* | SELinux | SELinux | Manual | AppArmor |
| Server produksi | Ya | Ya | Sebagian | Ya | Sebagian | Tidak |
| Desktop belajar | Ya | Ya | Ya | Sebagian | Ya | VM lab |

\*Mungkin perlu diaktifkan tergantung set paket.
