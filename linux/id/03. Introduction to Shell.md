## 1. Apa itu Shell?

Shell adalah antarmuka berbasis teks antara user dan kernel sistem operasi. Shell menerima perintah yang kita ketik, meneruskannya ke kernel untuk dieksekusi, lalu menampilkan hasilnya kembali ke kita.

Bayangkan shell seperti resepsionis di gedung kantor besar.

- Server room (kernel): memproses semua data dan perintah perusahaan.
- Meja resepsionis (terminal): titik komunikasi ke server room.
- Kamu: mengantar instruksi ke resepsionis untuk diteruskan ke server room.

Shell bukan cuma pengganti GUI. Shell memberi kemampuan jauh lebih luas untuk berinteraksi dengan program dan proses, mendapatkan informasi lebih cepat, dan mengotomasi tugas lewat skrip.

```
┌─────────────────────────────────────────────────────┐
│                    YOU / USER                        │
│              (type commands here)                    │
└──────────────────────┬──────────────────────────────┘
                       │ input
                       ▼
┌─────────────────────────────────────────────────────┐
│              TERMINAL / SHELL (Bash)                 │
│         text-based I/O interface (CLI)               │
└──────────────────────┬──────────────────────────────┘
                       │ system calls
                       ▼
┌─────────────────────────────────────────────────────┐
│                    KERNEL                            │
│      manages hardware, memory, processes             │
└──────────────────────┬──────────────────────────────┘
                       │ hardware access
                       ▼
┌─────────────────────────────────────────────────────┐
│                   HARDWARE                           │
│          CPU, RAM, Storage, Network...               │
└─────────────────────────────────────────────────────┘
```

## 2. Terminal vs Shell vs Console

Ketiga istilah ini sering dipakai bergantian, padahal artinya berbeda.

- Shell: program yang menginterpretasikan perintah (Bash, Zsh, Fish). Ini "otak" yang memproses apa yang kamu ketik.
- Terminal: antarmuka tempat kamu mengetik perintah dan melihat output. Jendela hitam yang kamu buka.
- Console: terminal dalam mode teks (bukan window). Merujuk ke layar fisik dalam mode teks, bukan jendela GUI.

| Istilah | Definisi | Contoh |
|---------|----------|--------|
| Shell | Program interpreter perintah | Bash, Zsh, Fish |
| Terminal | Jendela antarmuka teks | GNOME Terminal, iTerm2 |
| Console | Terminal mode teks fisik | `tty1`, `tty2` |
| CLI | Command-Line Interface | Jendela terminal mana pun |

## 3. Terminal Emulator & Multiplexer

Terminal emulator adalah software yang mengemulasi fungsi terminal di dalam lingkungan GUI. Bayangkan ini seperti meja resepsionis virtual di layar komputermu, yang memungkinkan kamu berinteraksi dengan shell dari jarak jauh atau dari dalam GUI tanpa harus berada di depan mesin secara fisik.

Terminal multiplexer seperti Tmux atau Screen memungkinkan kamu untuk:

- split terminal menjadi beberapa panel dalam satu window,
- bekerja di beberapa direktori secara bersamaan,
- membuat workspace berbeda untuk task yang berbeda,
- detach session, yaitu meninggalkan proses berjalan di background dan kembali lagi nanti.

### Terminal Emulator Populer

| Emulator | Platform | Keunggulan |
|----------|----------|------------|
| GNOME Terminal | Linux | Default di GNOME desktop |
| Konsole | Linux | Default di KDE desktop |
| Terminator | Linux | Multi-split panel |
| Alacritty | Cross-platform | GPU-accelerated, sangat cepat |
| iTerm2 | macOS | Fitur lengkap untuk Mac |
| Windows Terminal | Windows | Terminal modern untuk WSL |

### Tmux: Perintah Penting

```bash
# Start a new session
$ tmux

# Start named session
$ tmux new -s mysession

# Detach from session (keeps running in background)
Ctrl + B, then D

# List sessions
$ tmux ls

# Reattach to session
$ tmux attach -t mysession

# Split terminal horizontally
Ctrl + B, then "

# Split terminal vertically
Ctrl + B, then %

# Navigate between panes
Ctrl + B, then arrow keys

# Kill current pane
Ctrl + B, then X
```

## 4. Bash & Shell Lainnya

Shell paling umum di Linux adalah Bourne-Again Shell (Bash), bagian dari GNU Project. Semua yang bisa dilakukan lewat GUI bisa dilakukan dengan Bash, bahkan lebih banyak lagi. Bash memungkinkan otomasi lewat scripting yang bisa menghemat berjam-jam pekerjaan manual.

Selain Bash, ada shell lain yang bisa dipakai sesuai preferensi dan kebutuhan.

### Perbandingan Shell

| Shell | Nama Lengkap | Keunggulan | Default Pada |
|-------|--------------|------------|---------------|
| Bash | Bourne-Again Shell | Paling universal, scripting kuat | Sebagian besar distro Linux |
| Zsh | Z Shell | Auto-complete canggih, sangat bisa dikustomisasi | macOS (default) |
| Fish | Friendly Interactive Shell | Syntax highlighting real-time, ramah pengguna | - |
| Ksh | Korn Shell | Kompatibel dengan Bash, performa tinggi | Beberapa sistem Unix |
| Tcsh/Csh | TENEX C Shell | Sintaks mirip bahasa C | Sistem BSD |
| Dash | Debian Almquist Shell | Sangat ringan, cepat untuk scripting | Debian (sebagai /bin/sh) |

```bash
# Check current shell
$ echo $SHELL
/bin/bash

# Check available shells on system
$ cat /etc/shells
/bin/sh
/bin/bash
/usr/bin/bash
/bin/rbash
/usr/bin/rbash
/usr/bin/sh
/bin/zsh
/usr/bin/zsh

# Switch to another shell temporarily
$ zsh
$ fish

# Change default shell permanently
$ chsh -s /bin/zsh
```

## 5. Mengapa Harus Belajar Shell?

Mempelajari shell adalah investasi penting dalam perjalanan belajar Linux dan cybersecurity, dengan alasan berikut.

```
GUI  vs  Shell
─────────────────────────────────────────────────────
GUI:    Click → Menu → Sub-menu → Button → Confirm
Shell:  $ command -flag target   ← done in 1 line

Speed:       Shell wins always
Automation:  Shell only (scripts)
Remote:      Shell only (SSH)
Precision:   Shell wins (exact control)
Learning:    GUI easier to start
Power:       Shell has no ceiling
```

| Alasan | Penjelasan |
|--------|------------|
| Kecepatan | Jauh lebih cepat dari GUI untuk task berulang |
| Otomasi | Script bisa mengotomasi ribuan task sekaligus |
| Akses remote | SSH hanya menggunakan shell, tidak butuh GUI |
| Presisi | Kontrol penuh atas setiap aspek sistem |
| Cybersecurity | Hampir semua security tool berjalan lewat CLI |
| Server | Server Linux jarang punya GUI |

## 6. Catatan Keamanan: Eksploitasi Shell, Restricted Shell, dan Environment Poisoning

Dalam penetration testing dan security assessment, interaksi dengan shell mencakup beberapa vektor serangan penting.

1. Restricted Shell (rbash / rzsh) Escape: lingkungan restricted shell membatasi user dari mengubah direktori (`cd`), mengubah variabel `$PATH` / `$SHELL`, atau mengeksekusi binary di luar path yang ditentukan. Teknik breakout umum meliputi:
   - spawn subshell lewat program internal (Vim `:!/bin/sh`, Nano `^R^X`, Less `!/bin/sh`),
   - memakai runtime bahasa pemrograman (Python `python3 -c 'import pty; pty.spawn("/bin/bash")'`),
   - mengatur ulang PATH kalau environment writable (`export PATH=$PATH:/bin:/usr/bin`).
2. Environment Variable Poisoning: variabel lingkungan seperti `LD_PRELOAD`, `LD_LIBRARY_PATH`, dan `PROMPT_COMMAND` bisa dimanipulasi untuk memuat shared library berbahaya atau menjalankan perintah setiap kali prompt shell dievaluasi.
3. PATH Hijacking: kalau script administrasi atau cron job mengeksekusi binary tanpa absolute path (misalnya `service apache2 restart`, bukan `/usr/sbin/service`), penyerang yang punya akses tulis ke direktori di awal `$PATH` bisa menempatkan binary palsu untuk eskalasi hak akses (privilege escalation).

```bash
# ── RBASH ESCAPE EXAMPLES ────────────────────────────────────

# 1. Vi / Vim escape
$ vi
:set shell=/bin/bash
:shell

# 2. Python PTY spawn
$ python3 -c 'import pty; pty.spawn("/bin/bash")'

# 3. Export PATH reset (if export is available)
$ export PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin:$PATH

# 4. SSH command execution bypass
$ ssh user@target.lab -t "bash --noprofile"

# ── CHECKING SENSITIVE SHELL VARIABLES ───────────────────────
$ env | grep -E "PATH|SHELL|LD_PRELOAD|PROMPT_COMMAND"
```

## Cheatsheet Referensi Cepat

```bash
# ── SHELL INFO ───────────────────────────────────────
echo $SHELL                  # current shell
echo $0                      # current shell (alternative)
cat /etc/shells              # all available shells
chsh -s /bin/zsh             # change default shell

# ── TERMINAL SHORTCUTS ───────────────────────────────
Ctrl + C                     # cancel current command
Ctrl + Z                     # suspend current process
Ctrl + D                     # logout / EOF
Ctrl + L                     # clear screen (same as clear)
Ctrl + A                     # move to beginning of line
Ctrl + E                     # move to end of line
Ctrl + R                     # search command history
Ctrl + U                     # clear current line
Tab                          # auto-complete
Tab Tab                      # show all completions
↑ / ↓                       # scroll through history

# ── TMUX QUICK START ─────────────────────────────────
tmux                         # start tmux
tmux new -s name             # named session
tmux ls                      # list sessions
tmux attach -t name          # attach to session
Ctrl+B d                     # detach session
Ctrl+B "                     # split horizontal
Ctrl+B %                     # split vertical
Ctrl+B ←→↑↓                 # navigate panes
Ctrl+B x                     # close pane
```
