## Istilah penting

Istilah-istilah ini akan sering muncul di materi.

| Istilah | Artinya |
|:---|:---|
| Log | Catatan kejadian di sistem dengan cap waktu |
| syslog | Standar logging klasik; log masuk ke `/var/log` |
| journald | Service logging systemd, dibaca dengan `journalctl` |

## 1. Arsitektur Logging Linux

Linux modern biasanya menjalankan dua jalur telemetri secara paralel:

1. `systemd-journald`, log terstruktur biner yang diquery lewat `journalctl`.
2. `rsyslog` / `syslog-ng`, file teks klasik di `/var/log/`.

Keduanya bersama-sama mencatat autentikasi, event kernel, stdout/stderr service, dan pesan aplikasi. Defender memperlakukan log sebagai bukti; integritas dan retensi sama pentingnya dengan isinya.

```
 Kernel / services / apps
            │
            ▼
     ┌──────────────┐
     │ journald     │────► journalctl queries
     └──────┬───────┘
            │ (forward)
            ▼
     ┌──────────────┐
     │ rsyslog      │────► /var/log/*.log
     └──────┬───────┘
            │
            ▼
     SIEM / remote syslog (optional)
```

## 2. Facility & Severity Syslog (Formal)

Syslog klasik memberi label pada setiap pesan dengan facility f dan severity p:

```text
priority = 8 × facility + severity

Contoh: facility 4 (auth), severity 2 (crit)  →  8 × 4 + 2 = 34
```

| Severity p | Nama | Arti |
|:---:|:---|:---|
| 0 | emerg | Sistem tidak bisa dipakai |
| 1 | alert | Butuh tindakan segera |
| 2 | crit | Kondisi kritis |
| 3 | err | Error |
| 4 | warning | Peringatan |
| 5 | notice | Normal tapi signifikan |
| 6 | info | Informasional |
| 7 | debug | Debug |

Facility umum: `auth`/`authpriv`, `kern`, `daemon`, `cron`, `local0-7`.

```bash
# Emit a test message (lab)
logger -p auth.notice "lab test auth notice from $(whoami)"
```

## 3. File Kunci di `/var/log`

|:---|:---|:---|

| `secure` | Keluarga RHEL | Peran sama dengan `auth.log` |

| Tool | Membaca | Kegunaan |
|:---|:---|:---|
| `last` | `wtmp` | Login sukses |
| `lastb` | `btmp` | Login gagal (root) |
| `who` / `w` | `utmp` | Sesi aktif saat ini |
| `zgrep` | `*.gz` | Cari di log yang sudah dirotasi |

## 4. `journalctl` — Query Journal

`journalctl` memfilter berdasarkan unit, waktu, prioritas, dan sesi boot.

Utamakan query dengan batas waktu saat incident agar tidak tenggelam dalam noise.

```bash
journalctl -f                              # follow
journalctl -b                              # current boot
journalctl -u ssh.service                  # one unit
journalctl -u nginx --since "1 hour ago"
journalctl --since "2026-08-01" --until "2026-08-16"
journalctl -p err..emerg                   # severities
journalctl -k                              # kernel via journal
journalctl --disk-usage
journalctl --no-pager -o short-iso
```

Journal persisten: aktifkan storage di `/var/log/journal/` dan atur retensi di `/etc/systemd/journald.conf` (`SystemMaxUse=`, `MaxRetentionSec=`).

## 5. `dmesg` — Ring Buffer Kernel

`dmesg` membaca buffer sirkular kernel: probe hardware, OOM, error driver, notifikasi segfault.

Ring buffer bersifat terbatas dan sementara; event kernel kritis sebaiknya juga masuk ke journal/syslog untuk retensi jangka panjang.

```bash
sudo dmesg -T
sudo dmesg -l err,crit
sudo dmesg -T | grep -iE 'error|fail|oom|segfault'
```

## 6. `logrotate` — Retensi Tanpa Memenuhi Disk

Tanpa rotasi, log akan memenuhi disk dan menyebabkan DoS ketersediaan. `logrotate` mengarsipkan, mengompres, dan membuang generasi lama.

Seimbangkan kebutuhan forensik (retensi lebih panjang) dengan biaya disk. Kirim salinan keluar host sebelum penghapusan agresif.

| Direktif | Arti |
|:---|:---|
| `daily` / `weekly` | Cadence |
| `rotate N` | Simpan N generasi |
| `compress` | gzip log lama |
| `delaycompress` | Kompres mulai siklus berikutnya |
| `missingok` | Lewati kalau file tidak ada |
| `notifempty` | Lewati file kosong |

Path: `/etc/logrotate.conf`, `/etc/logrotate.d/*`.

```bash
sudo logrotate -d /etc/logrotate.conf     # debug / dry
sudo logrotate -f /etc/logrotate.conf     # force (careful)
zgrep "Failed password" /var/log/auth.log.*.gz
```

## 7. Defensive Hunting — Telemetri Auth & Privilege

Contoh deteksi (bukan anti-forensik): brute force SSH, penyalahgunaan sudo, login di luar jam kerja.

One-liner berikut membantu administrator dan blue team di sistem milik mereka sendiri. Korelasikan dengan firewall/Fail2Ban dan timeline tiket.

```bash
# Top sources of failed SSH passwords (Debian auth.log)
sudo grep "Failed password" /var/log/auth.log \
  | awk '{print $(NF-3)}' | sort | uniq -c | sort -nr | head

# Successful sudo commands (audit trail)
sudo grep "COMMAND=" /var/log/auth.log | tail -n 30

# Session history
last -n 20
sudo lastb -n 20

# Journal view of ssh
journalctl -u ssh --since "24 hours ago" | grep -i fail
```

Defender web juga memantau lonjakan `404`/`401`/`500` di access log sebagai indikator scanning atau bug aplikasi, tanpa memperlakukan log sebagai kanal eksploitasi.

## 8. Security Notes — Defense / Hardening

| Risiko | Dampak | Pertahanan |
|:---|:---|:---|
| Log hanya di host | Root yang kompromi bisa mengubah file lokal | Remote syslog/SIEM; append-only / WORM bila memungkinkan |
| Auth log world-readable | Kebocoran yang berdekatan dengan kredensial | Batasi permission `/var/log`; pisahkan `authpriv` |
| Tidak ada sinkronisasi waktu | Timeline rusak | NTP/chrony; simpan dalam UTC |
| Retensi terlalu pendek | Investigasi buta | Selaraskan dengan kebijakan; salinan offsite |
| Aplikasi tidak tepercaya menulis string user-controlled ke log | Kebingungan / bug sekunder jika log salah ditangani | Jangan `include` file log ke kode aplikasi; sanitasi tampilan; perlakukan log sebagai data, bukan kode |
| Disk penuh karena debug verbose | Outage ketersediaan | `logrotate`, batas ukuran journal, rate limit |
| Mengabaikan `btmp`/`lastb` | Brute force terlewat | Alert berdasarkan threshold; Fail2Ban |

### Praktik integritas
1. Forward `auth` dan unit kritis ke collector lewat TLS.
2. Batasi siapa yang bisa `journalctl` sebagai non-root (ACL/grup systemd secara hati-hati).
3. Pantau gap journal yang tiba-tiba (lompatan waktu, rentang yang terhapus) sebagai sinyal insiden; investigasi lewat backup/SIEM, jangan "berlatih menghapus jejak".
4. Lindungi rule `auditd` di host berassurance tinggi.
5. Dokumentasikan chain-of-custody untuk file bukti yang diekspor (hash).

```bash
# Health / posture
journalctl --disk-usage
timedatectl status
sudo ss -tulnp | grep -E 'syslog|514'
```
