## Istilah penting

Istilah-istilah ini akan sering muncul di materi.

| Istilah | Artinya |
|:---|:---|
| Firewall | Aturan yang mengizinkan atau memblokir traffic jaringan |
| Netfilter | Subsistem kernel yang benar-benar memfilter paket |
| iptables / nftables | Tool lama / baru untuk menulis aturan firewall |
| `ufw` / `firewalld` | Front-end yang lebih ramah di atas nftables |
| Chain | Daftar aturan tempat traffic dicek (INPUT, OUTPUT, FORWARD) |
| Default deny | Blokir semuanya, lalu izinkan hanya yang dibutuhkan |
| Stateful | Firewall melacak koneksi, bukan sekadar paket tunggal |

## 1. Linux Netfilter — Tempat Filtering Terjadi

Kernel Netfilter mengevaluasi paket lewat rule iptables/nftables sebelum forward/accept/drop.

```text
ACCEPT  |  DROP  |  REJECT  |  LOG  |  NAT
```

Firewall host adalah defense-in-depth setelah filter di edge jaringan. Sikap default untuk server: tolak inbound, izinkan koneksi established, allowlist eksplisit hanya untuk service yang diperlukan.

```
Inbound packet
      │
      ▼
 PREROUTING (nat)
      │
      ▼
 INPUT (filter)  → ACCEPT / DROP
      │
      ▼
 Local process OR forward path
```

| Framework | Distro | Backend |
|:---|:---|:---|
| UFW | Ubuntu/Debian | Backend iptables/nft |
| firewalld | Fedora/RHEL/Alma | nftables |
| iptables | Universal, low-level | CLI legacy |
| nftables | Default modern | CLI `nft` |

Konteks teori (DAC, MAC, pilar hardening) lihat catatan 26.

## 2. iptables — Table, Chain & Rule

iptables mengatur table (filter/nat/…) dan chain (INPUT/FORWARD/OUTPUT). Rule dievaluasi dari atas ke bawah; match pertama yang menang.

| Table | Kegunaan |
|:---|:---|
| `filter` | Allow/deny (INPUT, FORWARD, OUTPUT) |
| `nat` | SNAT/DNAT/MASQUERADE |
| `mangle` | TTL/TOS/mark |
| `raw` | Pengecualian connection tracking |

Rule dievaluasi dari atas ke bawah; match pertama menang kecuali ada `-j` yang melompat. Gunakan `iptables-save` / `iptables-restore` untuk backup.

```bash
# View current rules
sudo iptables -L -v -n
sudo iptables -S

# Minimal allowlist INPUT (lab — adjust interfaces/ports)
sudo iptables -P INPUT DROP
sudo iptables -P FORWARD DROP
sudo iptables -P OUTPUT ACCEPT

sudo iptables -A INPUT -i lo -j ACCEPT
sudo iptables -A INPUT -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT
sudo iptables -A INPUT -p tcp --dport 22 -s 203.0.113.0/24 -j ACCEPT
sudo iptables -A INPUT -p tcp --dport 443 -j ACCEPT
sudo iptables -A INPUT -j LOG --log-prefix "IPT DROP: "
sudo iptables -A INPUT -j DROP

# Persist (Debian)
sudo apt install iptables-persistent -y
sudo netfilter-persistent save
```

| Target | Perilaku |
|:---|:---|
| `-j ACCEPT` | Izinkan paket |
| `-j DROP` | Buang secara diam-diam |
| `-j REJECT` | Buang + kirim error ICMP |
| `-j LOG` | Log lalu lanjutkan chain |

## 3. nftables — Sintaks Penerus

nftables menggabungkan IPv4/IPv6; ruleset bersifat atomik lewat `nft -f`.

Pada distro yang defaultnya nft, `iptables` bisa jadi hanya layer kompatibilitas iptables-nft; utamakan `nft` native untuk rule baru.

```bash
sudo nft list ruleset

# Example ruleset file /etc/nftables.conf fragment
sudo tee /etc/nftables.conf << 'EOF'
#!/usr/sbin/nft -f
flush ruleset
table inet filter {
  chain input {
    type filter hook input priority 0; policy drop;
    iif "lo" accept
    ct state established,related accept
    tcp dport 22 ip saddr 203.0.113.0/24 accept
    tcp dport { 80, 443 } accept
  }
}
EOF
sudo nft -f /etc/nftables.conf
sudo systemctl enable --now nftables
```

## 4. UFW — Uncomplicated Firewall (Debian/Ubuntu)

Frontend berbasis profil aplikasi (`OpenSSH`, `Nginx Full`). Mudah dipakai, tetap default-deny.

Aktifkan hanya setelah memastikan rule allow SSH sudah ada; siapkan akses konsol untuk memulihkan bila terjadi lockout.

```bash
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow OpenSSH
sudo ufw allow from 203.0.113.0/24 to any port 22 proto tcp
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw limit OpenSSH    # rate-limit brute force
sudo ufw enable
sudo ufw status verbose
sudo ufw status numbered
sudo ufw delete 3         # by rule number
```

| Perintah | Efek |
|:---|:---|
| `ufw app list` | Profil yang tersedia |
| `ufw allow in on eth0` | Rule per-interface |
| `ufw logging on` | Log paket yang diblokir (level medium) |

## 5. firewalld — Zone (Keluarga RHEL)

Zone (`public`, `internal`, `drop`) plus `firewall-cmd`: runtime vs permanent.

Perubahan `--permanent` bertahan setelah reboot tapi butuh `--reload`; perubahan runtime saja hilang saat reboot kecuali disimpan.

```bash
sudo systemctl enable --now firewalld
sudo firewall-cmd --state
sudo firewall-cmd --get-active-zones
sudo firewall-cmd --list-all

# Allow HTTP permanently in public zone
sudo firewall-cmd --zone=public --add-service=http --permanent
sudo firewall-cmd --zone=public --add-service=https --permanent
sudo firewall-cmd --reload

# Rich rule: SSH from subnet
sudo firewall-cmd --permanent --add-rich-rule='rule family="ipv4" source address="203.0.113.0/24" service name="ssh" accept'
sudo firewall-cmd --reload
```

| Zone | Kegunaan umum |
|:---|:---|
| `public` | Jaringan tidak tepercaya |
| `internal` | LAN tepercaya |
| `drop` | Blackhole inbound |

## 6. Pola Desain Allowlist

Prinsip: inbound hanya yang eksplisit diizinkan.

Traffic masuk yang diizinkan hanyalah daftar port tiap layanan beserta alamat sumber yang boleh mengaksesnya. Selain itu tidak boleh masuk.

| Pola | Kapan dipakai |
|:---|:---|
| Subnet manajemen → SSH | Semua server |
| `0.0.0.0/0` → 443 saja | Web publik |
| Deny semua antar-VLAN kecuali bastion | Datacenter tersegmentasi |
| LOG sebelum DROP | Tuning tanpa kegagalan diam-diam |

```bash
# Verify effective posture
sudo ufw status verbose
sudo iptables -L INPUT -v -n --line-numbers
sudo nft list chain inet filter input
sudo firewall-cmd --list-all

# Map listeners vs firewall
ss -tulnp | grep LISTEN
```

## 7. Security Notes — Lockout & Logging

Kesalahan paling mahal: mengunci akses SSH dari jarak jauh. Siapkan rollback timer dan akses konsol sebelum melakukan perubahan besar.

Izinkan SSH sebelum mengaktifkan policy default-deny. Jangan lupakan IPv6. Rate-limit LOG untuk menghindari disk penuh. Pasangkan dengan Fail2Ban (catatan 26) dan auth log (catatan 28).

| Jebakan | Konsekuensi | Pencegahan |
|:---|:---|:---|
| Aktifkan firewall sebelum SSH diizinkan | Perlu pemulihan lewat konsol | `ufw allow OpenSSH` dulu; uji `netfilter-persistent` |
| Flush rule dari jarak jauh | Lockout instan | Rollback timer `at` atau serial console |
| Rule `allow 22/tcp` terlalu luas | Brute force dari internet | Allowlist source IP + Fail2Ban (catatan 26) |
| Tidak ada rule IPv6 | Bypass lewat v6 | Rule dual-stack (table `inet` / ip6tables) |
| LOG semua hal | Disk/CPU banjir | Prefix LOG dengan rate-limit |

```bash
# Safe change pattern (lab)
# 1) schedule rollback
echo "sudo ufw disable" | at now + 5 minutes
# 2) apply change
sudo ufw enable
# 3) verify SSH in second session
# 4) cancel rollback: atrm JOB
```

Referensi silang: interface jaringan lihat catatan 24-25; brute force auth lihat log di catatan 28.
