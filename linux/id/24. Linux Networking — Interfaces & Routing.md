## 1. Jaringan Host Linux — Layer & Objek

Setiap interface jaringan (fisik, bridge, VLAN, tun) punya state **link layer**, satu atau lebih **alamat IP**, dan **routing table** yang menentukan gateway keluar.

```text
app → socket → route lookup → interface → link
```

Admin modern memakai **`ip`** dari paket iproute2. Konfigurasi bisa dikelola oleh **NetworkManager**, **systemd-networkd**, atau file statis (**netplan** di Ubuntu, **`/etc/network/interfaces`** di Debian).

```
┌──────────────────────────────────────────┐
│ Applications (curl, ssh, nginx)          │
├──────────────────────────────────────────┤
│ Sockets (TCP/UDP)                        │
├──────────────────────────────────────────┤
│ Routing table  ← ip route                │
├──────────────────────────────────────────┤
│ IP addresses   ← ip addr                 │
├──────────────────────────────────────────┤
│ Interfaces     ← ip link (eth0, wlan0)   │
└──────────────────────────────────────────┘
```

| Objek | Lihat | Konfigurasi |
|:---|:---|:---|
| Interface | `ip link` | `ip link set`, NM, netplan |
| IPv4/IPv6 | `ip addr` | `ip addr add`, DHCP |
| Routes | `ip route` | `ip route add`, default gw |
| DNS | `resolvectl`, `/etc/resolv.conf` | NM, resolved |

## 2. Perintah `ip` — Link, Address, Route

Ganti **`ifconfig`/`route`** dengan **`ip`** untuk operasi harian. Perubahan lewat `ip` biasanya hanya berlaku saat runtime, kecuali dipersiskan di NM, netplan, atau interfaces. Catat setiap perubahan manual.

```bash
# Link layer — up/down, MTU, MAC
ip link show
ip link set eth0 up
ip link set eth0 mtu 1500

# Addresses
ip addr show dev eth0
ip addr add 10.10.14.50/24 dev eth0
ip addr del 10.10.14.50/24 dev eth0

# Routing
ip route show
ip route add default via 10.10.14.1 dev eth0
ip route add 192.168.100.0/24 via 10.10.14.254 dev eth0
ip route del 192.168.100.0/24

# Neighbor cache (ARP/NDP)
ip neigh show
```

| Perintah | Fungsi |
|:---|:---|
| `ip -br a` | Ringkasan alamat |
| `ip -4 route get 8.8.8.8` | Jalur mana ke tujuan |
| `ip link set eth0 down` | Matikan interface secara admin |

Kernel memilih rute paling spesifik lewat **Longest Prefix Match (LPM)**:

Dari semua rute yang mencakup alamat tujuan, kernel memilih yang prefix-nya paling panjang, karena itulah yang paling spesifik.

## 3. Tools Lama — `ifconfig` & `route`

Masih muncul di mesin lama atau soal CTF. Paket **`net-tools`**; pakai **`ip`** pada sistem yang Anda kelola sendiri. Kenali sintaksnya untuk membaca dokumentasi lama dan host yang sudah diretas, tapi jangan bangun automasi baru di atas tools yang sudah deprecated.

```bash
ifconfig -a
ifconfig eth0 10.10.14.50 netmask 255.255.255.0 up
route -n
route add default gw 10.10.14.1
```

## 4. NetworkManager — `nmcli`

**NetworkManager** (`NetworkManager.service`) mengelola Wi-Fi, Ethernet, dan VPN di desktop maupun server modern. Pakai **`nmcli`** untuk scripting. Profil koneksi disimpan di `/etc/NetworkManager/system-connections/` (hanya root yang bisa baca, jaga izinnya).

```bash
nmcli device status
nmcli connection show
nmcli connection show "Wired connection 1"

# Static IPv4 example (lab)
nmcli con mod "Wired connection 1" \
  ipv4.method manual \
  ipv4.addresses 10.10.14.50/24 \
  ipv4.gateway 10.10.14.1 \
  ipv4.dns "10.10.14.1 1.1.1.1"
nmcli con up "Wired connection 1"

# Wi-Fi scan (authorized)
nmcli dev wifi list
nmcli dev wifi connect SSID password 'passphrase'
```

| Subcommand | Kegunaan |
|:---|:---|
| `nmcli dev` | State device |
| `nmcli con` | Profil koneksi |
| `nmcli networking off/on` | Toggle global |

## 5. Konfigurasi Deklaratif — netplan & `/etc/network/interfaces`

Ubuntu memakai **netplan** (YAML); Debian klasik memakai **`/etc/network/interfaces`**. Keduanya persisten setelah reboot, tidak seperti perubahan `ip` yang hanya runtime. Pakai `netplan try` supaya YAML yang salah otomatis rollback. Jangan simpan kredensial di YAML yang bisa dibaca semua orang.

### Ubuntu netplan (`/etc/netplan/*.yaml`)

```yaml
# /etc/netplan/01-lab.yaml
network:
  version: 2
  ethernets:
    eth0:
      dhcp4: false
      addresses:
        - 10.10.14.50/24
      routes:
        - to: default
          via: 10.10.14.1
      nameservers:
        addresses: [10.10.14.1, 1.1.1.1]
```

```bash
sudo netplan try          # safe test with rollback
sudo netplan apply
```

### Debian klasik (`/etc/network/interfaces`)

```
auto eth0
iface eth0 inet static
    address 10.10.14.50
    netmask 255.255.255.0
    gateway 10.10.14.1
    dns-nameservers 10.10.14.1
```

```bash
sudo ifup eth0
sudo ifdown eth0
sudo systemctl restart networking   # distro-dependent
```

## 6. Hostname & Tabel Nama Lokal

**Hostname** adalah identitas host; **`/etc/hosts`** meng-override DNS secara lokal. Penamaan yang konsisten membantu logging, perencanaan sertifikat TLS, dan inventaris. Hindari nama ganda di lingkungan AD/LDAP.

```bash
hostname
hostnamectl status
sudo hostnamectl set-hostname srv01.lab.internal

cat /etc/hostname
cat /etc/hosts
```

## 7. Catatan Keamanan — Pertahanan & Eksposur

IP sekunder, Wi-Fi di server, dan rute statis yang salah bisa membuka jalur tak terduga. IPv6 yang dibiarkan aktif sering jadi jalan bypass filter IPv4.

| Kesalahan Konfigurasi | Dampak | Pertahanan |
|:---|:---|:---|
| IP sekunder pada layanan `0.0.0.0` | Listener terbuka tak terduga | Bind layanan ke IP spesifik |
| Kredensial Wi-Fi lemah di server | Jalur masuk lateral | Matikan Wi-Fi di server, kelola lewat kabel |
| Rute statis ke gateway penyerang | Traffic hijack | Kontrol perubahan rute, monitoring |
| API NetworkManager bisa diakses dari luar | Rekonfigurasi jarak jauh | Kebijakan D-Bus hanya localhost |
| IPv6 aktif, IPv4 difilter | Bypass lewat v6 | Firewall dual-stack (catatan 27) |

```bash
# Defensive inventory
ip -br link
ip -br addr
ip route show table all | head
nmcli -f GENERAL.STATE,IP4.ADDRESS dev show
ss -tulnp | grep LISTEN
```

Troubleshooting konektivitas ada di catatan 25. Layanan DNS/DHCP ada di catatan 19.
