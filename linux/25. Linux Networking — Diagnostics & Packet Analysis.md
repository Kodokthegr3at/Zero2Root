## 1. 🧭 Layered Troubleshooting Methodology

### 🇮🇩 Bahasa Indonesia
Gunakan **bottom-up** atau **top-down**; catat hipotesis dan bukti di setiap lapisan.

$$
\text{App} \rightarrow \text{DNS} \rightarrow \text{TCP/UDP} \rightarrow \text{Routing} \rightarrow \text{Interface} \rightarrow \text{Physical}
$$

### 🇬🇧 English
On Linux servers, typical flow: verify **link/up**, **IP**, **default route**, **DNS**, **remote port reachable** (`nc`/`curl`), then **capture** if still failing.

### 日本語
リンク → IP → 経路 → DNS → L4 到達 → キャプチャの順で仮説を検証します。ICMP だけに頼らないでください。

```
Symptom: "curl https://app.internal fails"
  │
  ├─ ip link / ip addr        → interface up? correct IP?
  ├─ ip route                 → default gw present?
  ├─ ping gw                  → L2/L3 local OK?
  ├─ dig app.internal         → DNS resolves?
  ├─ curl -v / nc -vz         → TCP 443 reachable?
  └─ tcpdump on interface     → where packets die?
```

| Layer | Questions | Tools |
|:---|:---|:---|
| L1/L2 | Cable/VLAN/bridge? | `ip link`, `ethtool` |
| L3 | IP & routes correct? | `ip addr`, `ip route`, `ping` |
| L4 | Port open/filtered? | `ss`, `nc` (authorized) |
| L7 | App/TLS/HTTP OK? | `curl -v`, `openssl s_client` |

## 2. 📡 Reachability — `ping`, `traceroute`, `mtr`

### 🇮🇩 Bahasa Indonesia
**ICMP echo** (`ping`) menguji round-trip; **traceroute** / `tracepath` / `mtr` menunjukkan delay dan loss hop-by-hop.

### 🇬🇧 English
Firewalls often block ICMP — absence of ping does **not** prove TCP failure. Combine with TCP probes.

### 日本語
ICMP が落ちても TCP が生きていることがあります。到達性は ping と TCP プローブを併用します。

```bash
ping -c 4 10.10.14.1
ping -6 -c 4 2001:db8::1

traceroute 8.8.8.8
tracepath example.com
mtr -rwzc 50 example.com    # report mode, 50 cycles

# TCP-based traceroute alternative when ICMP blocked
sudo traceroute -T -p 443 example.com
```

| Tool | Shows |
|:---|:---|
| `ping` | RTT, loss to single host |
| `traceroute` | Per-hop routers (ICMP/UDP/TCP variants) |
| `mtr` | Combined ping + traceroute statistics |

## 3. 🔌 Sockets & Connections — `ss` & `netstat`

### 🇮🇩 Bahasa Indonesia
**`ss`** menggantikan **`netstat`** — lihat listening ports, koneksi established, dan backlog antrian.

### 🇬🇧 English
Map suspicious outbound connections to processes (`-p`) during incident response on hosts you own.

### 日本語
ss で listen / 確立済み接続を見ます。インシデント時は `-p` でプロセスに紐づけます。

```bash
ss -tulnp                    # listening TCP/UDP + process
ss -tan state established    # active TCP
ss -o state established '( dport = :443 )'

# Legacy
netstat -tulnp 2>/dev/null

# Bandwidth per socket (if installed)
sudo ss -ti
```

| State | Meaning |
|:---|:---|
| `LISTEN` | Awaiting inbound connections |
| `ESTAB` | Active session |
| `TIME-WAIT` | Closed side waiting 2MSL |
| `SYN-RECV` | Possible SYN flood or half-open |

## 4. 📦 Packet Capture — `tcpdump`

### 🇮🇩 Bahasa Indonesia
**`tcpdump`** menangkap frame/packet on-the-wire dari interface. Butuh **`CAP_NET_RAW`** atau root.

### 🇬🇧 English
Capture only on networks/systems you are **authorized** to monitor. Store pcaps encrypted; they contain credentials if HTTP is cleartext.

### 日本語
許可されたホスト/網でのみキャプチャします。pcap には平文資格情報が入り得るので暗号化保管します。

```bash
# List interfaces
tcpdump -D

# Basic capture (lab)
sudo tcpdump -i eth0 -nn -c 20
sudo tcpdump -i eth0 -nn host 10.10.14.5 and port 443

# Write pcap for Wireshark
sudo tcpdump -i eth0 -w /tmp/capture.pcap -c 500
tcpdump -r /tmp/capture.pcap -nn | head

# Common filters
# tcp port 80
# icmp
# net 10.10.14.0/24
# not port 22
```

| Filter expr | Matches |
|:---|:---|
| `host X` | Src or dst X |
| `port 53` | TCP or UDP 53 |
| `tcp[tcpflags] & tcp-syn != 0` | SYN packets |
| `vlan 100` | VLAN tag (if present) |

**Berkeley Packet Filter (BPF)** runs in-kernel for efficiency before copying to userspace.

## 5. 🔗 ARP & Neighbor Discovery — `ip neigh`, `arp`

### 🇮🇩 Bahasa Indonesia
IPv4 **ARP** memetakan IP → MAC di segmen lokal. Tabel neighbor: **`ip neigh`**.

### 🇬🇧 English
Stale or poisoned ARP entries cause subtle connectivity issues or MITM on untrusted LANs — use DAI/802.1X on switches where possible.

### 日本語
同一セグメントの ARP/NDP を `ip neigh` で確認します。古いエントリや汚染は通信障害や MITM の原因になります。

```bash
ip neigh show
arp -n

# Clear single stale entry (careful on production)
sudo ip neigh del 10.10.14.1 dev eth0
sudo ip neigh flush dev eth0

# Link diagnostics
ethtool eth0
ethtool -S eth0 | head
```

## 6. 🌍 Application-Layer Probes — DNS & HTTP

### 🇮🇩 Bahasa Indonesia
Setelah L3/L4 OK, verifikasi **DNS** dan **HTTP/TLS** dengan `dig`, `curl`, `openssl`.

### 🇬🇧 English
`curl -v` exposes redirects, cert errors, and SNI behavior — invaluable for vHost and TLS debugging.

### 日本語
dig と curl で名前解決と HTTP/TLS を確認します。`curl -v` はリダイレクト・証明書・SNI の切り分けに有効です。

```bash
dig +trace example.com A
dig @10.10.14.1 internal.lab A

curl -v http://127.0.0.1:8080/
curl -vk https://app.lab/health
curl -o /dev/null -w '%{http_code} time=%{time_total}\n' -s https://example.com/

# TLS handshake inspect
echo | openssl s_client -connect example.com:443 -servername example.com 2>/dev/null | openssl x509 -noout -subject -dates

# TCP port probe
nc -vz 10.10.14.10 22
nc -vz -w 3 example.com 443
```

## 7. 🔐 Security Notes — Ethics & Defense

### 🇮🇩 Bahasa Indonesia
Capture dan inspeksi ARP hanya pada sistem/jaringan yang **Anda izinkan** mengelolanya. pcap adalah data sensitif.

### 🇬🇧 English
Promiscuous mode and packet dumps are high-privacy operations. Correlate listeners and auth logs (note 28) during IR on owned hosts.

### 日本語
キャプチャは許可された範囲のみ。PROMISC の予期しない有効化と新規 listener を監視します。

| Activity | Authorized context | Abuse risk |
|:---|:---|:---|
| `tcpdump` on LAN | SOC/NOC with policy | Credential theft, privacy violation |
| ARP inspection | Own subnet troubleshooting | MITM if combined with forwarding |
| `ss` process mapping | IR on owned host | Recon on compromised shared host |
| Promiscuous mode | IDS sensor | Covert channel if misused |

**Defensive monitoring:**

```bash
# Unexpected promiscuous interface?
ip link | grep PROMISC

# New listeners after change window
ss -tulnp | grep LISTEN

# Auth + network correlation (see note 28)
journalctl -u ssh --since "1 hour ago" | tail
```
