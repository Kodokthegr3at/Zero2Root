## 1. 📦 Containers vs Virtual Machines

### 🇮🇩 Bahasa Indonesia
**Container** membagikan kernel host; isolasi via **namespaces** + **cgroups**, bukan hypervisor guest kernel penuh.

$$
\text{VM} = \text{Guest OS} + \text{App},\quad
\text{Container} = \text{App + libs} \text{ on shared kernel}
$$

### 🇬🇧 English
Containers start fast and pack densely, but **they are not VMs** — a kernel escape or excessive `--privileged` container can compromise the host. Use them with defense-in-depth (non-root, dropped caps, read-only rootfs).

### 日本語
コンテナはホストカーネルを共有し、名前空間と cgroup で隔離します。VM ではないため、`--privileged` やカーネル脱出はホスト全体を危険にします。非 root・capability 削減・読み取り専用 rootfs を基本にします。

```
┌─────────────────────────────────────────────┐
│ Host Linux Kernel                           │
│  ┌─────────────┐  ┌─────────────┐           │
│  │ Container A │  │ Container B │           │
│  │ PID/NET/MNT │  │ PID/NET/MNT │  (namespaces)
│  │ cgroups     │  │ cgroups     │           │
│  └─────────────┘  └─────────────┘           │
│         dockerd / containerd / podman       │
└─────────────────────────────────────────────┘

vs VM: each guest has its own kernel under a hypervisor
```

| Aspect | VM | Container |
|:---|:---|:---|
| Isolation | Hardware/virtual HW | Kernel namespaces |
| Boot time | Minutes | Seconds |
| Density | Lower | Higher |
| Kernel | Per guest | Shared |
| Typical tool | KVM, VMware | Docker, Podman |

## 2. 🧩 Linux Primitives — Namespaces & cgroups

### 🇮🇩 Bahasa Indonesia
Kernel menyediakan blok isolasi: **namespaces** memisahkan tampilan (PID, net, mount, …) dan **cgroups** membatasi resource.

| Namespace | Isolates |
|:---|:---|
| `pid` | Process IDs |
| `net` | Interfaces, routes, ports |
| `mnt` | Mount tree |
| `uts` | Hostname |
| `ipc` | IPC objects |
| `user` | UID/GID mapping (rootless) |

**cgroups** membatasi CPU, memory, I/O, PIDs.

### 🇬🇧 English
Capabilities split root powers (`CAP_NET_BIND_SERVICE`, and others). Default Docker drops many caps; `--cap-add` widens the attack surface.

### 日本語
namespaces が視界を分離し、cgroups が資源を制限します。capability は root 権限の分割です。`--cap-add` は攻撃面を広げます。

```bash
# Peek at container namespaces (host admin, container ID from docker ps)
pid=$(docker inspect -f '{{.State.Pid}}' mycontainer)
sudo ls -l /proc/$pid/ns/
sudo cat /proc/$pid/cgroup
```

## 3. 🐳 Docker Core Workflow

### 🇮🇩 Bahasa Indonesia
Instal **`docker.io`** (Debian) atau **`docker-ce`**. Daemon **`dockerd`** mengelola image & container.

### 🇬🇧 English
Images are a layered read-only FS plus metadata; containers are a writable layer on top. Registry default: Docker Hub — pin digests in production.

### 日本語
イメージを pull し、コンテナを run します。本番では `:latest` ではなくバージョンまたは digest を固定します。

```bash
# Install (Debian/Ubuntu lab)
sudo apt update && sudo apt install docker.io -y
sudo systemctl enable --now docker
sudo usermod -aG docker $USER   # re-login for group

# Pull & run
docker pull nginx:1.25-alpine
docker run -d --name web -p 8080:80 nginx:1.25-alpine
docker ps
docker logs web
docker stop web && docker rm web

# Inspect
docker inspect web
docker image ls
docker system df
```

| Command | Action |
|:---|:---|
| `docker pull` | Download image |
| `docker run` | Create + start container |
| `docker ps -a` | List containers |
| `docker exec -it` | Shell inside running container |
| `docker rm` / `docker rmi` | Remove container / image |

## 4. 📝 Dockerfile & Docker Compose

### 🇮🇩 Bahasa Indonesia
**Dockerfile** mendefinisikan build image; **Compose** mengorkestrasi multi-container di lab/dev.

### 🇬🇧 English
Multi-stage builds shrink final images. Never embed secrets in layers — use build secrets or runtime env from a vault.

### 日本語
Dockerfile でイメージを定義し、Compose で複数コンテナを起動します。秘密情報をレイヤに埋め込まないでください。

**Minimal Dockerfile:**

```dockerfile
FROM python:3.12-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
USER 1000:1000
EXPOSE 8000
CMD ["python", "-m", "http.server", "8000", "--bind", "0.0.0.0"]
```

```bash
docker build -t myapp:lab .
docker run -d -p 8000:8000 --read-only --tmpfs /tmp myapp:lab
```

**docker-compose.yml sketch:**

```yaml
services:
  web:
    image: nginx:alpine
    ports:
      - "127.0.0.1:8080:80"
    read_only: true
  db:
    image: postgres:16-alpine
    environment:
      POSTGRES_PASSWORD: changeme
    volumes:
      - pgdata:/var/lib/postgresql/data
volumes:
  pgdata:
```

```bash
docker compose up -d
docker compose ps
docker compose logs -f web
docker compose down
```

## 5. 🦭 Podman — Rootless-First Alternative

### 🇮🇩 Bahasa Indonesia
**Podman** daemonless (model fork-exec), cocok untuk **rootless** containers tanpa group `docker`.

### 🇬🇧 English
CLI is largely Docker-compatible: `podman run`, `podman build`. systemd integration via **`podman generate systemd`**.

### 日本語
Podman は中央デーモンなしで、一般ユーザーの rootless コンテナに向きます。CLI は Docker とほぼ互換です。

```bash
sudo apt install podman -y
podman run -d --name web -p 8080:80 docker.io/library/nginx:alpine
podman ps
podman exec -it web sh

# Rootless (unprivileged user)
podman run --rm -it alpine id
```

| Docker | Podman equivalent |
|:---|:---|
| `docker` | `podman` |
| `docker compose` | `podman compose` |
| daemon socket | no central daemon |

## 6. 🛠️ Day-2 Operations

### 🇮🇩 Bahasa Indonesia
Monitoring resource, restart policy, volume backup, dan rotasi log adalah pekerjaan harian setelah container hidup.

### 🇬🇧 English
Bind-mounting host `/` or the Docker socket into a container grants host-level power — forbidden in production patterns.

### 日本語
統計・再起動ポリシー・ボリューム・ログが日常運用です。ホストの `/` や Docker ソケットの bind-mount は本番では禁止です。

```bash
# Resource stats
docker stats --no-stream

# Restart policies
docker run -d --restart unless-stopped nginx:alpine

# Volumes
docker volume create appdata
docker run -v appdata:/data alpine sh -c 'echo test > /data/file'

# Interactive debug (authorized)
docker exec -it mycontainer sh
docker cp mycontainer:/etc/nginx/nginx.conf ./nginx.conf.bak
```

## 7. 🔐 Security Notes — DEFENSE / Breakout Awareness

### 🇮🇩 Bahasa Indonesia
Postur aman: non-root, tanpa `--privileged`, tanpa socket Docker, pin image, scan registry tepercaya.

### 🇬🇧 English
Container escape research belongs in **authorized lab** environments only. Defenders focus on **capability reduction**, **seccomp/AppArmor profiles**, and **kernel patching**.

### 日本語
防御側は capability 削減、seccomp/AppArmor、カーネルパッチに集中します。`--privileged` と Docker ソケットのマウントはほぼホスト権限です。

| Misconfiguration | Impact | Defense |
|:---|:---|:---|
| `--privileged` | Near-root on host | Avoid; minimal caps |
| Mount `/var/run/docker.sock` | Control all containers | Never in untrusted workloads |
| Run as root in container | Easier escape chains | `USER` non-root in Dockerfile |
| `:latest` in prod | Supply-chain drift | Pin digest/version |
| Public registry images | Malware/backdoors | Scan (Trivy/Grype); trusted registries |
| Secrets in env/build args | Leak via `docker inspect`/history | Secrets manager, runtime inject |
| Host network mode `--network host` | Shares host stack | Default bridge unless required |

```bash
# Defensive posture checks (authorized)
docker info 2>/dev/null | grep -i root
docker ps --quiet | xargs -r docker inspect -f '{{.Name}} privileged={{.HostConfig.Privileged}} caps={{.HostConfig.CapAdd}}'
# podman
podman ps --format '{{.Names}} {{.Privileged}}'
```
