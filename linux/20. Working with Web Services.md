## 1. 🌐 HTTP Services on Linux — Role of the Web Stack

### 🇮🇩 Bahasa Indonesia
Web service di Linux biasanya terdiri dari:

$$
\text{Client} \xrightarrow{\text{HTTP/HTTPS}} \text{Listener (80/443)} \rightarrow \text{Daemon} \rightarrow \text{DocRoot} + \text{App}
$$

Daemon umum: **Apache `httpd`/`apache2`**, **Nginx**, kadang **Caddy**. Di belakangnya bisa ada PHP-FPM, uWSGI, atau reverse-proxy ke aplikasi kontainer.

### 🇬🇧 English
Linux hosts terminate HTTP(S), apply access controls, serve static files or proxy to application runtimes. Administrators must understand **document roots**, **listener sockets**, **logs**, and **TLS certificates**.

### 日本語
Webサーバーはリクエストを受け、静的ファイル配信またはアプリへのプロキシを行います。

```
Internet / LAN
      │
      ▼
 ┌────────────┐     ┌──────────────┐
 │ Firewall   │────►│ nginx/apache │
 │ (ufw/nft)  │     │ :80 / :443   │
 └────────────┘     └──────┬───────┘
                           │
              ┌────────────┼────────────┐
              ▼            ▼            ▼
           DocRoot      PHP-FPM      Upstream app
         /var/www/…                 127.0.0.1:8000
```

| Port | Protocol | Typical use |
|:---:|:---|:---|
| 80 | HTTP | Redirect to HTTPS or ACME |
| 443 | HTTPS | Production traffic |
| 8080/8000 | HTTP | Local/dev bind (prefer loopback) |

## 2. 🏛️ Apache HTTP Server

### 🇮🇩 Bahasa Indonesia
Pada Debian/Ubuntu, paket `apache2` memakai layout:

| Path | Role |
|:---|:---|
| `/var/www/html/` | Default document root |
| `/etc/apache2/apache2.conf` | Main config |
| `/etc/apache2/ports.conf` | Listen directives |
| `/etc/apache2/sites-available/` | Site definitions |
| `/etc/apache2/sites-enabled/` | Enabled symlinks |
| `/etc/apache2/mods-enabled/` | Active modules |
| `/var/log/apache2/` | `access.log`, `error.log` |

### 🇬🇧 English
Enable sites with `a2ensite`, modules with `a2enmod`, then `apache2ctl configtest` before reload.

### 日本語
サイトとモジュールは `a2ensite` / `a2enmod` で有効化し、再読込前に構文チェックします。

```bash
sudo apt install apache2 -y
sudo systemctl enable --now apache2
sudo apache2ctl configtest
sudo a2enmod headers ssl rewrite
sudo a2ensite 000-default.conf
sudo systemctl reload apache2
systemctl status apache2 --no-pager
```

**Minimal hardening ideas (Apache):**
- Disable unused modules (`a2dismod`).
- Set restrictive `Directory` options (no Indexes unless required).
- Prefer dedicated service user; never `chmod -R 777` on docroot.

## 3. ⚡ Nginx — Event-Driven Server & Reverse Proxy

### 🇮🇩 Bahasa Indonesia
Nginx unggul sebagai reverse proxy dan static file server. Konfigurasi:

| Path | Role |
|:---|:---|
| `/etc/nginx/nginx.conf` | Global settings |
| `/etc/nginx/sites-available/` | Server blocks |
| `/etc/nginx/sites-enabled/` | Enabled links |
| `/var/log/nginx/access.log` | Access telemetry |
| `/var/log/nginx/error.log` | Errors |

### 🇬🇧 English
Always `nginx -t` before `reload`. Upstream apps should listen on **localhost** when possible; expose only the proxy.

### 日本語
変更後は必ず `nginx -t`。アップストリームは可能なら localhost に閉じます。

```bash
sudo apt install nginx -y
sudo nginx -t
sudo systemctl enable --now nginx
sudo systemctl reload nginx
```

Example **reverse proxy** sketch (admin education):

```nginx
server {
    listen 443 ssl http2;
    server_name app.example.com;
    # ssl_certificate     /etc/ssl/...;
    # ssl_certificate_key /etc/ssl/...;

    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

## 4. 🔒 TLS Termination — Admin Essentials

### Formal view
TLS provides confidentiality + integrity for the HTTP record layer:

$$
\text{HTTPS} = \mathsf{TLS}(\text{HTTP bytes}),\quad
\text{verify cert chain to trust anchor}
$$

| Practice | Why |
|:---|:---|
| Prefer TLS 1.2+ (ideally 1.3) | Drop obsolete protocols |
| HSTS after HTTPS proven | Reduce SSL-strip risk |
| Separate privkey perms `600` root | Key leakage resistance |
| Automate renew (e.g. ACME) | Avoid expired certs |
| Redirect 80→443 | Consistent security UX |

```bash
# Inspect remote cert (ops / monitoring)
echo | openssl s_client -connect example.com:443 -servername example.com 2>/dev/null \
  | openssl x509 -noout -dates -subject -issuer
```

## 5. 🚀 Lightweight HTTP Servers — Local Lab Only

### 🇮🇩 Bahasa Indonesia
One-liner HTTP berguna untuk **prototipe lokal** (dokumentasi, file statis di loopback). **Jangan** mengekspos ke jaringan tidak tepercaya tanpa autentikasi/TLS.

### 🇬🇧 English
Built-in servers are for **authorized local development**. Bind to `127.0.0.1` by default; treat anything bound to `0.0.0.0` as an intentional exposure requiring firewall rules.

### 日本語
軽量サーバーはローカル検証用。外部公開はファイアウォールと認証を前提にします。

```bash
# Prefer loopback for labs
python3 -m http.server 8000 --bind 127.0.0.1
php -S 127.0.0.1:8080
```

| Tool | Good for | Caution |
|:---|:---|:---|
| `python3 -m http.server` | Static files | No auth; directory listing |
| `php -S` | Quick PHP smoke tests | Not production |
| `npx http-server` | Static SPA previews | Review network bind |

## 6. 📟 Terminal Clients — `curl` & `wget`

### 🇮🇩 Bahasa Indonesia
- **`curl`**: inspeksi header, metode HTTP, debugging API.
- **`wget`**: unduhan file / mirroring terkontrol.

### 🇬🇧 English
Use clients to **verify** your own services: status codes, redirects, TLS, and response headers. Avoid piping remote content into a shell on production hosts.

### 日本語
自ホストの疎通・ヘッダー確認に使います。リモート出力をシェルへ直接パイプしないでください。

```bash
curl -I https://localhost/                 # headers only
curl -v https://app.example.com/health     # verbose trace
curl -o /tmp/file.tgz https://example.com/file.tgz

wget -c https://example.com/large.iso      # resume
wget --spider https://example.com/         # reachability check
```

**Safe ops pattern:** download → checksum → inspect → then install.

$$
\mathsf{Verify}(file) = \big(\mathrm{SHA256}(file) = \mathrm{SHA256}_{\text{published}}\big)
$$

## 7. 🏷️ Virtual Hosts (Name-Based Hosting)

### 🇮🇩 Bahasa Indonesia
Satu IP dapat melayani banyak nama domain. Server memilih *vHost* berdasarkan header HTTP **`Host:`** (atau SNI pada TLS).

### 🇬🇧 English
Name-based virtual hosting multiplexes sites on one listener. Misconfigured default vHosts often leak staging sites — set an explicit default that returns `404`/`444`.

### 日本語
`Host:` / SNI でサイトを振り分けます。デフォルトvHostの漏洩に注意。

```
Client request: GET / HTTP/1.1
Host: admin.example.com
        │
        ▼
   Match server_name / ServerName
        │
        ▼
   DocRoot or proxy for that site
```

```bash
# Test Host routing against your lab IP (authorized hosts only)
curl -H "Host: app.lab.local" http://127.0.0.1/

# Local name resolution for lab VMs you control
# (edit /etc/hosts only on machines you administer)
```

Apache: separate files under `sites-available/`.  
Nginx: separate `server { server_name … }` blocks.

## 8. 🔐 Security Notes — DEFENSE / Hardening

| Misconfiguration | Impact | Defense |
|:---|:---|:---|
| Directory indexing enabled | Leak backups, `.env`, dumps | `Options -Indexes` / `autoindex off` |
| Docroot world-writable (`777`) | Unauthorized content change | `755` dirs, `644` files; deploy via CI user |
| Default `phpinfo` / `server-status` public | Info disclosure | Remove or restrict by IP + auth |
| App listens on `0.0.0.0` without firewall | Remote attack surface | Bind localhost; proxy; UFW/nft allowlist |
| HTTP-only admin panels | Credential sniffing | Force HTTPS, HSTS, strong auth |
| Piping remote scripts to shell | Supply-chain risk | Verify checksums; use package managers |
| Verbose error pages in prod | Path/stack leaks | Generic errors; detailed logs server-side only |

### Hardening checklist
1. TLS everywhere for non-lab traffic; modern ciphers.
2. Least privilege for `www-data`/`nginx` users — no shell login.
3. Separate writeable upload dirs from executable script dirs.
4. Ship access/error logs to central store; monitor 4xx/5xx spikes.
5. Keep packages updated (`apt`/`dnf`); remove unused modules.
6. WAF/rate-limit at edge when facing the internet.

```bash
# Posture snippets (admin)
namei -l /var/www/html | head
sudo apache2ctl -M 2>/dev/null | head
sudo nginx -T 2>/dev/null | grep -E 'listen|server_name|root' | head
ss -tulnp | grep -E ':80|:443'
```
