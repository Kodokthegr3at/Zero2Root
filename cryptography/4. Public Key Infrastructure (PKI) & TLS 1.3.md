## 1. 🏢 PKI Architecture & Chain of Trust

### 🇮🇩 Bahasa Indonesia
**Public Key Infrastructure (PKI)** adalah ekosistem yang terdiri dari perangkat keras, perangkat lunak, kebijakan, dan prosedur untuk membuat, mengelola, mendistribusikan, dan mencabut **sertifikat digital X.509**.

```
[ Root CA (Offline, Self-Signed, Ultra Secure) ]
                      │
           (Signs Intermediate CA)
                      ▼
[ Intermediate CA (Issuing Authority) ]
                      │
              (Signs End-Entity)
                      ▼
[ Server Certificate: example.com ] ─── Validated by Browser Trust Store
```

## 2. ⚡ TLS 1.3 vs TLS 1.2 Handshake Dynamics

TLS 1.3 (RFC 8446) menghapus algoritma kriptografi warisan yang tidak aman (RSA key transport, CBC ciphers, SHA-1, RC4) dan memangkas latensi handshake dari **2 RTT menjadi hanya 1 RTT (atau 0-RTT via PSK)**!

```
                    TLS 1.3 FULL HANDSHAKE (1-RTT)
Client                                                              Server
  │                                                                   │
  │─── 1. ClientHello + Supported Groups + KeyShare (ECDH Public) ───>│
  │                                                                   │
  │<── 2. ServerHello + KeyShare (ECDH Public) ───────────────────────│
  │       {EncryptedExtensions}                                       │
  │       {Certificate}                                               │
  │       {CertificateVerify}                                         │
  │       {Finished}                                                  │
  │                                                                   │
  │─── 3. {Finished} ────────────────────────────────────────────────>│
  │                                                                   │
  │══════════════════════ 1-RTT APPLICATION DATA ═════════════════════│
```

## 3. 🛡️ Perfect Forward Secrecy (PFS)

### 🇮🇩 Bahasa Indonesia
**Perfect Forward Secrecy (PFS)** memastikan bahwa jika kunci privat jangka panjang milik server (*long-term private key*) bocor atau dicuri di masa depan, **seluruh rekaman sesi komunikasi terenkripsi di masa lalu tetap aman dan tidak dapat didekripsi**.
- Diimplementasikan menggunakan pertukaran kunci ephemeral: **ECDHE (Elliptic Curve Diffie-Hellman Ephemeral)** atau **DHE**.
- Diwajibkan secara mutlak pada **TLS 1.3** (pertukaran kunci statis RSA dihapus sepenuhnya).

## 4. 🛠️ Practical OpenSSL PKI Management Workflows

```bash
# ── 1. GENERATE PRIVATE KEY & CSR (CERTIFICATE SIGNING REQUEST) ──
openssl req -new -newkey rsa:4096 -nodes \
    -keyout example.com.key \
    -out example.com.csr \
    -subj "/C=ID/ST=Jakarta/L=Jakarta/O=LearnCyber/CN=example.com"

# ── 2. GENERATE SELF-SIGNED CERTIFICATE (VALID FOR 365 DAYS) ─────
openssl req -x509 -newkey ec -pkeyopt ec_paramgen_curve:prime256v1 \
    -days 365 -nodes \
    -keyout server.key -out server.crt \
    -subj "/CN=localhost"

# ── 3. INSPECT REMOTE SSL/TLS CERTIFICATE ────────────────────
openssl s_client -connect example.com:443 -servername example.com -showcerts

# ── 4. VERIFY CERTIFICATE AGAINST CA CHAIN ───────────────────
openssl verify -CAfile ca_chain.pem example.com.crt
```
