## 1. 📐 Three Fundamental Properties of Cryptographic Hashes

1. **Pre-image Resistance (One-Way Property)**: Diberikan nilai hash $h$, secara komputasi tidak mungkin menemukan pesan $m$ sedemikian rupa sehingga $\text{Hash}(m) = h$.
2. **Second Pre-image Resistance (Weak Collision Resistance)**: Diberikan pesan $m_1$, secara komputasi tidak mungkin menemukan pesan berbeda $m_2$ ($m_1 \neq m_2$) sedemikian rupa sehingga $\text{Hash}(m_1) = \text{Hash}(m_2)$.
3. **Collision Resistance (Strong Collision Resistance)**: Secara komputasi tidak mungkin menemukan **dua pesan acak mana pun** $m_1$ dan $m_2$ yang menghasilkan nilai hash yang sama $\text{Hash}(m_1) = \text{Hash}(m_2)$.
4. **Avalanche Effect (Efek Longsoran Salju)**: Mengubah 1 bit tunggal pada input akan mengubah lebih dari 50% bit pada output hash.

## 2. 🧬 Hash Families & Security Status

| Hash Function | Digest Size | Security Status | Vulnerabilities / Notes |
|:---|:---|:---|:---|
| **MD5** | 128-bit | 🔴 Completely Broken | Practical collision generation in < 1 second |
| **SHA-1** | 160-bit | 🔴 Broken (SHAttered) | Practical collision attacks proven by Google (2017) |
| **SHA-256 (SHA-2)**| 256-bit | 🟢 Secure Standard | Merkle-Damgård construction; Length extension possible |
| **SHA-512 (SHA-2)**| 512-bit | 🟢 Very High Security | Merkle-Damgård construction; 64-bit word optimized |
| **SHA-3 (Keccak)**| 256/512-bit| 🟢 Next-Gen Standard | Sponge construction; immune to length extension |
| **BLAKE3** | 256-bit | 🟢 Ultra High Speed | Tree hashing; multi-threaded SIMD optimized |

## 3. 🔐 Message Authentication Codes (HMAC)

Untuk memverifikasi **integritas sekaligus keaslian sumber data**, digunakan **HMAC (Hash-based Message Authentication Code)** yang menggabungkan kunci rahasia dengan fungsi hash:

$$\text{HMAC}(K, m) = \text{Hash}\Big((K' \oplus \text{opad}) \parallel \text{Hash}\big((K' \oplus \text{ipad}) \parallel m\big)\Big)$$

- Mencegah serangan **Length Extension Attack** yang rentan terjadi pada konstruksi naive `Hash(Key || Message)`.

## 4. 🛡️ Password Storage: Why Fast Hashes Fail

### 🇮🇩 Bahasa Indonesia
Fungsi hash kriptografi umum (seperti SHA-256 atau MD5) sengaja didesain untuk **sangat cepat**. Namun, untuk penyimpanan password, kecepatan adalah **kelemahan fatal** karena penyerang dengan GPU modern dapat mencoba **miliaran hash per detik (Hashcat)**!

Penyimpanan password wajib menggunakan **Slow / Memory-Hard Key Derivation Functions (KDF)**:
1. **Argon2id (Pemenang Password Hashing Competition - Standard Terbaik)**: Menggabungkan resistensi terhadap serangan GPU memory-hard (Argon2d) dan serangan side-channel timing (Argon2i).
2. **bcrypt (OpenBSD)**: Berbasis cipher Blowfish dengan cost parameter terkonfigurasi.
3. **scrypt**: Memory-hard KDF yang dirancang untuk mencegah cracking berbasis hardware ASIC/FPGA.

## 5. 🛠️ Practical Linux & OpenSSL Hash Workflows

```bash
# ── INTEGRITY VERIFICATION ────────────────────────────────────
sha256sum software.iso                        # Compute SHA-256
sha256sum -c checksums.txt                    # Verify against checksum list
b2sum largefile.tar                           # Compute ultra-fast BLAKE2b

# ── HMAC COMPUTATION WITH OPENSSL ────────────────────────────
echo -n "Critical Financial Payload" | openssl dgst -sha256 -hmac "SecretKey123"

# ── GENERATE SECURE ARGON2 / BCRYPT HASH (PYTHON) ────────────
python3 -c "
import argon2
ph = argon2.PasswordHasher()
hash = ph.hash('MySuperSecretPassword!')
print(hash)
"
```
