## 1. 📐 Formal Definition

### 🇮🇩 Bahasa Indonesia
Fungsi hash kriptografi adalah pemetaan efisien:

$$
H: \{0,1\}^{*} \rightarrow \{0,1\}^{n}
$$

yang mengompresi input berukuran arbitrer menjadi **digest** tetap $n$-bit (mis. $n=256$ untuk SHA-256).

Sifat operasional yang diinginkan (Wong Ch.2):
- **Deterministik:** $H(m)$ selalu sama untuk $m$ sama.
- **Avalanche:** ubah 1 bit input ⇒ ~50% bit output berubah.
- **Efisien:** evaluasi cepat di CPU umum (kebalikan dari password KDF).

### 🇬🇧 English
Hashes create fixed-length fingerprints for integrity checks, commitments, Merkle trees, digital signatures (hash-then-sign), and KDFs — but a bare hash is **not** authentication without a secret key (use MAC/HMAC/AEAD).

### 日本語
ハッシュは完全性確認や署名前処理に使いますが、**秘密鍵なしのハッシュだけでは認証になりません**（MAC/HMAC/AEADを使う）。

## 2. 🛡️ Classical Security Properties

Misalkan lawan $\mathcal{A}$ dengan bound komputasi praktis.

### 2.1 Preimage resistance (one-way)
Diberikan $h$, sulit menemukan $m$ dengan $H(m)=h$:

$$
\Pr\big[H(\mathcal{A}(h))=h\big] \approx \mathsf{negl}
$$

Kompleksitas generik $\sim 2^{n}$ trial.

### 2.2 Second-preimage resistance
Diberikan $m_1$, sulit mencari $m_2\neq m_1$ dengan $H(m_1)=H(m_2)$. Generik $\sim 2^{n}$.

### 2.3 Collision resistance
Sulit mencari sembarang pasangan $m_1\neq m_2$ dengan $H(m_1)=H(m_2)$.  
Karena birthday bound, generik $\sim 2^{n/2}$.

### 2.4 Hubungan kekuatan
Collision resistance $\Rightarrow$ second-preimage (secara asimptotik dalam banyak formalisasi). Sebaliknya tidak selalu. Desain modern menargetkan **collision security $\approx 2^{n/2}$** dengan $n\ge 256$ untuk level ~128-bit.

## 3. 🎂 Birthday Bound — Rumus Probabilitas

### 🇮🇩 Bahasa Indonesia
**Masalah ulang tahun:** berapa orang agar peluang ≥ 50% dua orang berulang tahun sama? Jawabannya $\approx 23$, bukan $\sqrt{365}$ secara naif tanpa deret.

Untuk $k$ sampel seragam dari ruang berukuran $N=2^{n}$:

$$
\Pr[\text{collision}] \approx 1 - \exp\!\left(-\frac{k(k-1)}{2N}\right)
$$

Untuk peluang $\approx 1/2$:

$$
k \approx \sqrt{2\ln 2}\cdot\sqrt{N} \approx 1.177\sqrt{N} = \Theta\!\big(2^{n/2}\big)
$$

Implikasi (Wong, “The birthday bound”):
- SHA-256 ($n=256$) ⇒ collision generik $\sim 2^{128}$ — target level keamanan 128-bit.
- Truncation berbahaya: untuk menjaga collision ~128-bit, digest ≥ **256-bit**; untuk preimage saja, ≥ **128-bit**.

### 🇬🇧 English
Always size digests for the **property you need**. Collision-sensitive apps (certificates, git-like content addressing under adversarial choice) need the full birthday margin.

### 日本語
必要な性質に応じてダイジェスト長を選びます。衝突が重要な用途では誕生日バウンドを満たす長さが必要です。

## 4. 🧱 Constructions: Merkle–Damgård vs Sponge

### 4.1 Merkle–Damgård (SHA-1, SHA-2)
1. Pad pesan (panjang pesan dikodekan di akhir padding).
2. Pecah jadi blok $M_1,\ldots,M_L$ selebar compression function.
3. Iterasi:

$$
\begin{aligned}
IV &= H_0 \\
H_i &= f(H_{i-1}, M_i),\quad i=1,\ldots,L \\
H(M) &= H_L
\end{aligned}
$$

di mana $f$ adalah **compression function** (SHA-256: berbasis SHA family round).

**Konsekuensi:** length-extension (lihat §7) jika dipakai naif sebagai MAC `H(K‖M)`.

### 4.2 Sponge (SHA-3 / Keccak)
State $b$-bit = rate $r$ + capacity $c$ ($b=r+c$). Absorb input ke rate, permute $\pi$, lalu squeeze output:

$$
\text{security ~ related to }c/2\text{ against generic attacks}
$$

SHA-3 kebal length-extension ala MD. Juga menyediakan **XOF** (SHAKE128/256) dengan keluaran panjang fleksibel.

```
 Merkle–Damgård                 Sponge (SHA-3)
 M1  M2  M3                     absorb → squeeze
  │   │   │                     ┌──────────────┐
  ▼   ▼   ▼                     │ rate r       │
 IV→f→f→f→ digest               │ capacity c   │──→ digest/XOF
                                └──────────────┘
```

## 5. 🧬 Hash Algorithm Zoo & Status

| Function | Digest | Construction | Status | Notes |
|:---|:---:|:---|:---|:---|
| MD5 | 128 | MD | 🔴 Broken | Collision praktis |
| SHA-1 | 160 | MD | 🔴 Broken | SHAttered (2017) |
| SHA-256 | 256 | MD | 🟢 OK | Length-ext. jika disalahgunakan |
| SHA-512 | 512 | MD | 🟢 OK | Baik di CPU 64-bit |
| SHA-3-256 | 256 | Sponge | 🟢 OK | Alternatif struktural |
| SHAKE256 | var | XOF | 🟢 OK | Output fleksibel |
| BLAKE3 | 256 | Tree | 🟢 Fast | Paralel / SIMD |

**Aturan praktis:** integritas file → SHA-256/BLAKE3; protokol baru → SHA-256 atau SHA-3/BLAKE3; **jangan** MD5/SHA-1 untuk keamanan.

## 6. 🔐 Message Authentication Codes (MAC) & HMAC

### 🇮🇩 Bahasa Indonesia
MAC memakai **kunci rahasia** untuk otentikasi + integritas:

$$
t = \mathsf{MAC}_K(m),\qquad \mathsf{Verify}_K(m,t)\in\{0,1\}
$$

#### HMAC (RFC 2104)
$$
\mathsf{HMAC}(K,m)=H\Big((K' \oplus \mathsf{opad}) \,\|\, H\big((K' \oplus \mathsf{ipad}) \,\|\, m\big)\Big)
$$

- $K'$ = kunci dipad/dipotong ke ukuran blok hash.
- $\mathsf{ipad}=0x36\ldots$, $\mathsf{opad}=0x5c\ldots$

HMAC tetap aman dengan SHA-256 meski MD rentan length-extension pada konstruksi naif.

#### Poly1305
MAC cepat berbasis polinomial modulo $2^{130}-5$; dipasangkan ChaCha20 sebagai AEAD (**ChaCha20-Poly1305**).

### 🇬🇧 English
Never invent `H(K‖m)` or `H(m‖K)` as a MAC. Use HMAC, KMAC, Poly1305, or AEAD tags. Compare tags in **constant time**.

### 日本語
`H(K‖m)` のような自作MACは避け、HMAC/KMAC/Poly1305/AEADを使い、タグ比較は定数時間で行います。

## 7. 📏 Length-Extension Attack (Konsep)

Untuk hash Merkle–Damgård, jika diketahui $H(M)$ dan panjang $|M|$, lawan dapat menghitung $H(M \,\|\, \mathsf{pad} \,\|\, M')$ **tanpa** mengetahui $M$, dengan meneruskan state internal.

Implikasi: `auth = SHA256(secret ‖ message)` **bukan** MAC yang aman. Mitigasi: **HMAC**, SHA-3/BLAKE3, atau AEAD.

> Fokus catatan ini: memahami mengapa desain naif gagal dan bagaimana memilih konstruksi yang benar — bukan prosedur eksploitasi terhadap sistem pihak ketiga.

## 8. 🔑 Password Hashing & Memory-Hard KDFs

### 🇮🇩 Bahasa Indonesia
SHA-256 **sengaja cepat** → GPU/ASIC dapat menguji miliaran kandidat/detik. Password **wajib** memakai KDF lambat / memory-hard.

Misalkan cost parameter $t$ (iterasi / waktu), memori $m$, paralelisme $p$:

$$
\mathsf{Hash}_{pwd} = \mathsf{KDF}(\mathsf{password},\;\mathsf{salt};\; t,m,p)
$$

| KDF | Sifat | Catatan |
|:---|:---|:---|
| **Argon2id** | Memory-hard + side-channel balanced | Pemenang PHC; pilihan default modern (Wong) |
| **scrypt** | Memory-hard | Baik; parameter harus hati-hati |
| **bcrypt** | CPU-hard (Blowfish) | Masih umum; batas panjang password |
| **PBKDF2** | Iterasi HMAC | Bukan memory-hard; butuh iterasi sangat tinggi |

**Salt** unik per user (16+ bytes random) mencegah rainbow table. **Pepper** (rahasia server) opsional tambahan.

### 🇬🇧 English
Store only the KDF output + salt + parameters. On login, recompute and compare in constant time. Prefer Argon2id for new systems.

### 日本語
保存するのはKDF出力・ソルト・パラメータのみ。照合は定数時間。新規はArgon2idを推奨します。

## 9. 🌱 HKDF — Extract-then-Expand

Dari shared secret mentah (mis. ECDH) yang **belum** seragam sempurna:

$$
\begin{aligned}
PRK &\leftarrow \mathsf{HKDF\text{-}Extract}(salt,\, IKM) = \mathsf{HMAC}(salt,\, IKM) \\
OKM &\leftarrow \mathsf{HKDF\text{-}Expand}(PRK,\, info,\, L)
\end{aligned}
$$

- **Extract:** menyeragamkan entropi.
- **Expand:** menghasilkan $L$ byte kunci aplikasi (traffic keys, IV keys, …).

Dipakai luas di TLS 1.3, Signal, Noise.

## 10. 🛠️ Cheatsheet

```bash
# ── Integrity ────────────────────────────────────────────────
sha256sum file.iso
sha256sum -c SHA256SUMS
b2sum file.tar                 # BLAKE2b (util-linux)

# ── OpenSSL digest / HMAC ────────────────────────────────────
openssl dgst -sha256 file.bin
echo -n 'payload' | openssl dgst -sha256 -hmac 'secret-key'

# ── Argon2 example (Python) ──────────────────────────────────
python3 -c "
from argon2 import PasswordHasher
ph = PasswordHasher()          # Argon2id defaults
h = ph.hash('correct horse battery staple')
print(h)
print(ph.verify(h, 'correct horse battery staple'))
"
```

## 🔐 Security Notes

| Anti-pattern | Risiko | Ganti dengan |
|:---|:---|:---|
| MD5/SHA-1 for security | Collision | SHA-256+ |
| `H(secret‖msg)` as MAC | Length extension | HMAC / AEAD |
| Fast hash for passwords | GPU cracking | Argon2id |
| Truncate to 64-bit | Birthday break cepat | ≥128-bit (preimage) / ≥256 (collision) |
| Non-constant tag compare | Timing leak | `hmac.compare_digest` / `CRYPTO_memcmp` |
