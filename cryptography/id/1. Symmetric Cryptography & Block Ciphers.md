## 1. Tujuan Kriptografi: Empat Pilar

Kriptografi modern memperkuat protokol agar tetap aman di lingkungan adversarial (David Wong, *Real-World Cryptography*, Ch.1). Empat tujuan klasik:

1. Confidentiality: hanya pihak berwenang yang membaca plaintext.
2. Integrity: perubahan data terdeteksi, biasanya lewat MAC atau tag AEAD.
3. Authentication: identitas pengirim atau sumber dapat diverifikasi.
4. Non-repudiation: pengirim sulit menyangkal pesan yang ditandatangani, biasanya dengan tanda tangan digital, bukan cipher simetris murni.

Cipher simetris terutama memberi confidentiality. Integrity dan authenticity butuh MAC atau konstruksi AEAD seperti AES-GCM atau ChaCha20-Poly1305.

## 2. Model Formal Enkripsi Simetris

Sistem enkripsi simetris terdiri dari tiga algoritma:

```text
KeyGen()   → k     buat kunci rahasia
Enc(k, m)  → c     enkripsi pesan m menjadi ciphertext c
Dec(k, c)  → m     dekripsi c kembali menjadi m
```

Kedua pihak memakai kunci k yang sama: satu untuk mengunci pesan, satunya untuk membukanya.

**Correctness (kelengkapan):**

```text
Dec(k, Enc(k, m)) = m
```

Artinya: kalau pesan dienkripsi lalu didekripsi dengan kunci yang sama, hasilnya selalu pesan aslinya.

**Semantic security (intuisi IND-CPA):** musuh yang melihat ciphertext tidak memperoleh keuntungan berarti untuk membedakan dua pesan yang dipilihnya, kecuali panjang pesan, yang biasanya bocor.

Kunci rahasia k yang sama dipakai untuk enkripsi dan dekripsi. Keamanan bergantung pada kerahasiaan kunci, bukan kerahasiaan algoritma (prinsip Kerckhoffs): sistem harus tetap aman walaupun semua hal selain kunci diketahui publik.

| Parameter | Simetris | Asimetris |
|:---|:---|:---|
| Kunci | 1 rahasia bersama | Pasangan kunci publik + privat |
| Kecepatan | Sangat cepat (AES-NI) | Lebih lambat (matematika modular / ECC) |
| Ukuran umum | AES-128 / AES-256 | RSA-2048+ / ECC-256+ |
| Kegunaan utama | Data massal, disk, TLS record | Key exchange, tanda tangan |
| Masalah sulit | Pencarian kunci brute-force 2^(key length) | Faktorisasi / DLOG / ECDLP |

## 3. Cipher Blok vs Cipher Stream

Cipher blok memetakan blok tetap n-bit ke blok n-bit dengan kunci k:

```text
C = E(k, P)
```

Cipher menerima satu blok plaintext P berukuran tetap dan kunci k, lalu mengeluarkan satu blok ciphertext C dengan ukuran yang sama.

AES memakai n = 128. Pesan lebih panjang dari satu blok harus dipotong dan digabung lewat mode operasi.

Cipher stream menghasilkan keystream s = s₁ s₂ ... lalu:

```text
cᵢ = mᵢ XOR sᵢ
```

Setiap bit pesan di-XOR dengan bit keystream berikutnya.

Contoh modern: ChaCha20, sering dipasangkan Poly1305 sebagai AEAD.

Cipher blok saja tidak cukup untuk pesan panjang variabel; mode (ECB/CBC/CTR/GCM) menentukan cara blok dirangkai. Mode CTR pada dasarnya mengubah cipher blok menjadi cipher stream dengan mengenkripsi sebuah counter.

## 4. Struktur AES: Substitution-Permutation Network

AES (Advanced Encryption Standard / Rijndael) dipilih lewat kompetisi NIST (Wong, Ch.4). Parameter:

| Varian | Bit kunci κ | Jumlah round Nᵣ | Ukuran blok |
|:---|:---:|:---:|:---:|
| AES-128 | 128 | 10 | 128 |
| AES-192 | 192 | 12 | 128 |
| AES-256 | 256 | 14 | 128 |

State AES dipandang sebagai matriks 4 × 4 byte (kolom-mayor). Setiap round, kecuali yang terakhir, adalah komposisi:

```text
SubBytes → ShiftRows → MixColumns → AddRoundKey
```

Round terakhir tanpa `MixColumns`.

### 4.1 AddRoundKey
```text
state = state XOR round_key
```
XOR state dengan round key Kᵣ hasil Key Expansion (Rijndael key schedule).

### 4.2 SubBytes (lapisan non-linear, S-box)
Setiap byte b diganti:

```text
new_byte = S_box[old_byte]
```

S-box adalah inversi di lapangan hingga GF(2⁸) diikuti transformasi affine. Ini satu-satunya lapisan non-linear AES, dan menjadi pertahanan utama melawan linear dan differential cryptanalysis.

Polinomial tak-reduksibel AES:

```text
m(x) = x⁸ + x⁴ + x³ + x + 1      (0x11B)
```

### 4.3 ShiftRows
Baris r digeser kiri sebanyak r posisi (r=0,1,2,3), memberi difusi antar kolom.

### 4.4 MixColumns
Setiap kolom diperlakukan sebagai polinomial atas GF(2⁸) dan dikalikan matriks tetap:

```text
[s0']   [02 03 01 01]   [s0]
[s1'] = [01 02 03 01] × [s1]
[s2']   [01 01 02 03]   [s2]
[s3']   [03 01 01 02]   [s3]
```

Setiap byte baru adalah campuran dari keempat byte di kolomnya, jadi mengubah satu byte input akan mengubah seluruh kolom. Perkaliannya mengikuti aturan GF(2⁸), bukan aritmetika biasa.

Perkalian dengan `02` adalah shift-kiri ditambah XOR kondisional dengan `0x1B` (reduksi m(x)).

### 4.5 Kekuatan brute-force
Ruang kunci AES-128:

AES-128 punya 2¹²⁸ kemungkinan kunci, sekitar 3,4 × 10³⁸. Itu bilangan dengan 39 digit.

Bahkan dengan 10¹⁸ percobaan per detik (skala ekstrem hipotetis), waktu rata-rata sekitar 2¹²⁷ operasi, jauh dari praktis. Ancaman realistis lebih sering datang dari manajemen kunci buruk, nonce reuse, atau side-channel, bukan dari memecahkan AES secara matematis.

AES adalah SPN: bergantian substitusi (SubBytes) dan permutasi/difusi (ShiftRows + MixColumns), dikunci oleh AddRoundKey. Jangan membuat varian "mirip AES" sendiri; gunakan library dan mode yang sudah teruji.

```
┌──────────────────────────────────────────────────────────┐
│                    AES ENCRYPTION FLOW                   │
│  Plaintext (128-bit)                                     │
│       │                                                  │
│       ▼                                                  │
│  AddRoundKey (K0)                                        │
│       │                                                  │
│   ┌───┴───────────────────────────────┐                  │
│   │  Repeat Nr-1 times:               │                  │
│   │   SubBytes → ShiftRows →          │                  │
│   │   MixColumns → AddRoundKey (Kr)   │                  │
│   └───────────────────────────────────┘                  │
│       │                                                  │
│  Final: SubBytes → ShiftRows → AddRoundKey (K_Nr)        │
│       │                                                  │
│       ▼                                                  │
│  Ciphertext (128-bit)                                    │
└──────────────────────────────────────────────────────────┘
```

## 5. Mode Operasi: Dari ECB ke AEAD

Misalkan pesan dipotong menjadi blok P₁,...,Pₜ (setelah padding bila perlu).

### 5.1 ECB, Electronic Codebook (jangan dipakai)

```text
Cᵢ = E(k, Pᵢ)      setiap blok dienkripsi sendiri-sendiri
```

Blok identik menghasilkan ciphertext identik, sehingga pola bocor (kasus klasik "ECB penguin"). Tidak ada IV atau nonce.

### 5.2 CBC, Cipher Block Chaining

```text
C₀ = IV
Cᵢ = E(k, Pᵢ XOR Cᵢ₋₁)      enkripsi
Pᵢ = D(k, Cᵢ) XOR Cᵢ₋₁      dekripsi
```

Sebelum dienkripsi, setiap blok di-XOR dengan blok ciphertext sebelumnya. Karena itu dua blok plaintext yang sama tidak lagi menghasilkan output yang sama.

IV harus unpredictable, idealnya acak 128-bit, dan unik per pesan dengan kunci yang sama. CBC hanya memberi kerahasiaan, bukan integritas, sehingga praktik klasiknya adalah AES-CBC + HMAC (encrypt-then-MAC), lihat Wong §4.4.

### 5.3 CTR, Counter Mode

```text
Sᵢ = E(k, nonce ‖ counterᵢ)
Cᵢ = Pᵢ XOR Sᵢ
```

Cipher mengenkripsi counter, bukan pesannya langsung, untuk menghasilkan keystream. Keystream itu lalu di-XOR dengan plaintext.

Bisa diparalelkan dan tidak butuh padding. Nonce/counter tidak boleh dipakai ulang dengan kunci yang sama; keystream reuse membocorkan XOR plaintext.

### 5.4 GCM, Galois/Counter Mode (AEAD modern)

AES-GCM menggabungkan CTR untuk kerahasiaan dengan otentikasi di lapangan Galois GF(2¹²⁸).

```text
Yᵢ = E(k, nonce ‖ i)
Cᵢ = Pᵢ XOR Yᵢ                              enkripsi (sama seperti CTR)
T  = GHASH(H, AAD, C) XOR E(k, nonce ‖ 0)   tag otentikasi
```

di mana H = E(k, 0¹²⁸) dan GHASH adalah perhitungan polinomial atas ciphertext yang bekerja seperti checksum cepat berkunci.

AEAD (Authenticated Encryption with Associated Data):
- Output: $(C, T)$, ciphertext plus tag (biasanya 128-bit).
- AAD (header, alamat, metadata) ikut diautentikasi tanpa dienkripsi.
- Bila verifikasi tag gagal, tolak seluruh pesan. Jangan "decrypt anyway".

| Mode | Kerahasiaan | Integritas | Paralel | Catatan keamanan |
|:---|:---:|:---:|:---:|:---|
| ECB | Pola bocor | Tidak | Ya | Broken untuk hampir semua kasus |
| CBC | Ya | Tidak | Tidak (enc) / ya (dec) | Butuh MAC; IV harus unpredictable |
| CTR | Ya | Tidak | Ya | Keunikan nonce kritikal |
| GCM | Ya | Ya | Ya | Standar TLS; nonce reuse katastrofik |
| ChaCha20-Poly1305 | Ya | Ya | Ya | Kuat di CPU tanpa AES-NI |

Wong menekankan: enkripsi tanpa otentikasi berbahaya. Prefer satu primitive AEAD (AES-GCM / ChaCha20-Poly1305) daripada merakit CBC+HMAC sendiri kecuali Anda memang ahli protokol. Jika terpaksa menggabungkan CBC dan HMAC, pakai encrypt-then-MAC dengan kunci independen, bandingkan tag secara constant-time, dan jangan bocorkan perbedaan padding-error vs MAC-error secara ceroboh.

## 6. Padding (PKCS#7) dan Risiko Oracle

Untuk mode yang membutuhkan panjang kelipatan blok (CBC), PKCS#7 menambahkan p byte bernilai p:

```text
p = n - (len(m) mod n)
pad(m) = m ditambah p byte, masing-masing bernilai p
```

Contoh dengan blok 16 byte: pesan 13 byte butuh p = 3, jadi byte `03 03 03` ditambahkan di akhir.

Jika |m| sudah kelipatan n, tambahkan satu blok penuh berisi n.

Padding oracle (konsep): jika dekripsi membedakan "padding invalid" dari "MAC/app error", penyerang bisa belajar informasi tentang plaintext lewat adaptasi ciphertext (serangan gaya Vaudenay). Mitigasi: AEAD, atau encrypt-then-MAC dengan respons error yang seragam.

> Catatan edukasi: langkah eksploitasi oracle secara detail sengaja tidak dijabarkan sebagai prosedur serangan di sini. Fokusnya adalah deteksi dan mitigasi dalam desain protokol.

Menyeragamkan penanganan error, ditambah AEAD, menghilangkan kelas kebocoran padding-oracle klasik.

## 7. Prinsip Kerckhoffs, Panjang Kunci, dan Biaya Komputasi

### Prinsip Kerckhoffs
Keamanan hanya bergantung pada kerahasiaan kunci, bukan kerahasiaan algoritma.

### Estimasi brute-force
Jika penyerang menguji R kunci per detik, waktu harapan untuk AES-κ:

```text
waktu rata-rata ≈ 2^(κ-1) / R detik
```

Rata-rata penyerang menemukan kunci yang benar setelah mencoba separuh dari semua kemungkinan kunci. Dari situlah angka 2^(κ-1) berasal.

Contoh: κ=128, R=10¹², menghasilkan T_avg ~ 5 × 10¹⁸ tahun, jauh melampaui usia alam semesta.

### Aturan praktis (Wong / industri)
- AES-128 cukup untuk hampir semua aplikasi modern.
- AES-256 memberi margin ekstra, dipakai untuk kebijakan jangka panjang atau beberapa standar pemerintah.
- Jangan "double AES" sendiri; gunakan mode dan standar yang sudah dianalisis.

## 8. Cheatsheet OpenSSL (Operasi Sah / Lab Sendiri)

```bash
# ── AES-256-CBC + PBKDF2 (file lokal Anda) ───────────────────
openssl enc -aes-256-cbc -salt -pbkdf2 -iter 100000 \
  -in confidential.txt -out secret.enc

openssl enc -d -aes-256-cbc -pbkdf2 -iter 100000 \
  -in secret.enc -out decrypted.txt

# ── AES-256-GCM (kunci & IV heksadesimal eksplisit) ──────────
# IV/nonce harus unik per pesan untuk kunci yang sama
openssl enc -aes-256-gcm -in secret.txt -out secret.gcm \
  -K <64_HEX_CHARS_KEY> -iv <24_HEX_CHARS_IV>

# ── Benchmark ────────────────────────────────────────────────
openssl speed -evp aes-256-gcm aes-256-cbc chacha20-poly1305

# ── Random key material ──────────────────────────────────────
openssl rand -hex 32    # 256-bit key
openssl rand -hex 12    # 96-bit GCM nonce (umum)
```

## Catatan Keamanan: Ancaman dan Pertahanan

| Ancaman | Mekanisme | Pertahanan |
|:---|:---|:---|
| Pattern leakage | ECB | Larang ECB; pakai CBC/CTR/GCM |
| Bit-flipping | CBC tanpa MAC | AEAD atau encrypt-then-MAC |
| Nonce reuse | CTR/GCM | Nonce unik / counter monoton |
| Key disclosure | Logging, backup, swap | HSM/KMS, least privilege, wipe |
| Side-channel | Timing/cache pada S-box | Library constant-time, AES-NI |
