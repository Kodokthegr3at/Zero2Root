## 1. Apa Itu Fungsi Hash

Fungsi hash menerima input dengan panjang **berapa pun** (satu kata, sebuah file, satu disk utuh) dan menghasilkan output dengan panjang **tetap**, seperti sidik jari:

```text
SHA-256("hello") → 2cf24dba5fb0a30e26e83b2ac5b9e29e1b161e5c1fa7425e73043362938b9824
SHA-256("Hello") → 185f8db32271fe25f561a6fc938b2e264306ec304eda518007d1764826381969
```

Mengganti satu huruf kecil menjadi huruf besar menghasilkan output yang benar-benar berbeda. Itulah **efek avalanche**.

Hash kriptografi yang baik punya sifat-sifat sehari-hari ini (Wong, Ch.2):

- **Deterministik:** input yang sama selalu menghasilkan hash yang sama.
- **Avalanche:** mengubah satu bit saja membalik sekitar separuh bit output.
- **Cepat:** cepat dihitung di CPU biasa. (Bagus untuk file, tapi buruk untuk password; lihat Bagian 8.)

Di mana hash dipakai: mengecek file unduhan tidak rusak, tanda tangan digital (yang ditandatangani hash-nya, bukan seluruh file), ID commit Git, Merkle tree, dan penurunan kunci.

Satu batasan penting: **hash biasa tidak membuktikan siapa pengirimnya.** Siapa pun bisa menghitung SHA-256 dari file yang sudah diubah. Untuk membuktikan keaslian, kamu butuh kunci rahasia, yaitu MAC, HMAC, atau AEAD (Bagian 6).

## 2. Tiga Sifat Keamanan

Hash kriptografi harus membuat tiga hal ini praktis mustahil. Di sini n adalah ukuran output dalam bit (256 untuk SHA-256).

| Sifat | Tugas penyerang | Biaya generik | Analogi |
|:---|:---|:---:|:---|
| **Preimage resistance** | Diberi sebuah hash, cari input *apa saja* yang menghasilkannya | sekitar 2ⁿ percobaan | Diberi sidik jari, cari orangnya |
| **Second-preimage resistance** | Diberi satu input, cari input *lain* dengan hash yang sama | sekitar 2ⁿ percobaan | Cari orang yang sidik jarinya sama dengan Alice |
| **Collision resistance** | Cari dua input *apa saja* dengan hash yang sama | sekitar 2^(n/2) percobaan | Cari dua orang *mana saja* yang sidik jarinya sama |

Perhatikan bahwa collision resistance paling lemah: penyerang bebas memilih kedua input, jadi jauh lebih mudah. Bagian 3 menjelaskan kenapa angkanya 2^(n/2), bukan 2ⁿ.

Karena itu, untuk tingkat keamanan 128-bit, desain modern memakai hash minimal 256 bit.

## 3. Masalah Ulang Tahun: Kenapa Collision Datang Lebih Cepat dari Dugaan

Berapa orang yang harus ada di satu ruangan supaya peluang ada dua orang dengan tanggal ulang tahun yang sama mencapai 50%? Kebanyakan orang menebak sekitar 180 (separuh dari 365). Jawaban sebenarnya **hanya 23**.

Alasannya: kamu tidak sedang mencari orang yang sama dengan *dirimu*, tapi mencari *pasangan mana saja* yang cocok. Dengan 23 orang, sudah ada 253 kemungkinan pasangan.

Hal yang sama berlaku untuk hash. Kalau sebuah hash punya N kemungkinan output, kamu hanya butuh kira-kira akar kuadrat dari N percobaan sebelum collision kemungkinan besar terjadi:

```text
percobaan untuk peluang collision 50% ≈ 1,18 × √N

ulang tahun:  N = 365       →  1,18 × √365 ≈ 23 orang
SHA-256:      N = 2²⁵⁶      →  sekitar 2¹²⁸ percobaan
```

Artinya dalam praktik (Wong, "The birthday bound"):

- SHA-256 memberi sekitar 128 bit collision resistance. Ini sesuai target keamanan 128-bit, karena itu SHA-256 dianggap aman.
- **Memotong hash itu berbahaya.** Hash yang dipotong jadi 64 bit bisa ditemukan collision-nya dengan sekitar 2³² percobaan saja, dan itu bisa dikerjakan komputer biasa. Kalau collision penting (sertifikat, content addressing), pertahankan minimal 256 bit.

## 4. Cara Fungsi Hash Dibangun

### 4.1 Merkle-Damgård (SHA-1, SHA-2)

Dipakai oleh SHA-1 dan SHA-256. Idenya:

1. Tambahkan padding ke pesan supaya panjangnya pas dibagi menjadi blok (panjang asli pesan ditulis di dalam padding).
2. Potong menjadi blok-blok.
3. Mulai dari nilai awal yang tetap, lalu masukkan satu blok setiap kali. Setiap langkah mencampurkan blok berikutnya ke state yang terus berjalan.
4. State terakhir itulah hash-nya.

```text
nilai awal → campur(blok 1) → campur(blok 2) → campur(blok 3) → ... → hash
```

Kelemahannya: output hash **adalah** state internal terakhir. Orang yang tahu hash-nya bisa terus "mencampurkan" blok tambahan tanpa tahu pesan aslinya. Inilah **serangan length-extension** (Bagian 7).

### 4.2 Sponge (SHA-3 / Keccak)

SHA-3 bekerja dengan cara berbeda. State internalnya besar dan terbagi dua:

- **Rate:** bagian tempat input "diserap" (absorb) dan output "diperas keluar" (squeeze).
- **Capacity:** bagian tersembunyi yang tidak pernah dikeluarkan langsung. Keamanannya berasal dari bagian ini (kira-kira separuh ukurannya, dalam bit).

Karena sebagian state tidak pernah diperlihatkan, SHA-3 **tidak** rentan terhadap length extension. Desain yang sama juga bisa menghasilkan output dengan panjang berapa pun (SHAKE128/256, disebut XOF).

```
 Merkle–Damgård                 Sponge (SHA-3)
 M1  M2  M3                     absorb → squeeze
  │   │   │                     ┌──────────────┐
  ▼   ▼   ▼                     │ rate r       │
 IV→f→f→f→ digest               │ capacity c   │──→ digest/XOF
                                └──────────────┘
```

## 5. Fungsi Hash Mana yang Aman Saat Ini

| Fungsi | Ukuran output | Desain | Status | Catatan |
|:---|:---:|:---|:---|:---|
| MD5 | 128 | MD | **Rusak** | Collision bisa ditemukan dalam hitungan detik |
| SHA-1 | 160 | MD | **Rusak** | Collision nyata dipublikasikan tahun 2017 (SHAttered) |
| SHA-256 | 256 | MD | Aman | Waspadai length extension kalau salah pakai |
| SHA-512 | 512 | MD | Aman | Sering lebih cepat di CPU 64-bit |
| SHA3-256 | 256 | Sponge | Aman | Alternatif dengan struktur berbeda |
| SHAKE256 | bebas | Sponge (XOF) | Aman | Panjang output bisa dipilih |
| BLAKE3 | 256 | Tree | Aman, sangat cepat | Memakai banyak core dan SIMD |

Aturan praktis: pakai SHA-256 atau BLAKE3 untuk integritas file, dan SHA-256, SHA-3, atau BLAKE3 untuk protokol baru. **Jangan pernah pakai MD5 atau SHA-1 untuk urusan keamanan.**

## 6. MAC dan HMAC: Hash dengan Kunci Rahasia

Hash biasa membuktikan file tidak rusak *secara tidak sengaja*. Hash biasa tidak menghentikan penyerang, karena penyerang bisa mengubah file lalu menghitung ulang hash-nya.

**MAC** (Message Authentication Code) mencampurkan kunci rahasia. Hanya orang yang punya kunci yang bisa membuat tag yang valid:

```text
tag = MAC(kunci, pesan)
Verify(kunci, pesan, tag) → true / false
```

Kalau pesan berubah sedikit saja, tag-nya tidak cocok lagi. Dan tanpa kunci, penyerang tidak bisa membuat tag baru yang valid.

### HMAC (RFC 2104)

HMAC adalah cara standar mengubah hash seperti SHA-256 menjadi MAC. HMAC melakukan hash **dua kali**, dengan kunci dicampurkan setiap kali:

```text
HMAC(K, m) = Hash( kunci_luar ‖ Hash( kunci_dalam ‖ m ) )

kunci_dalam = kunci XOR 0x36 0x36 ...   (ipad)
kunci_luar  = kunci XOR 0x5c 0x5c ...   (opad)
```

Hash luar "menyegel" hasilnya, dan inilah yang menghentikan serangan length-extension. HMAC-SHA256 tetap aman walaupun SHA-256 sendiri rentan length extension.

### Poly1305

MAC yang sangat cepat, dipakai bersama ChaCha20 dalam skema AEAD ChaCha20-Poly1305.

### Dua aturan

- **Jangan pernah membuat MAC dengan `Hash(kunci ‖ pesan)` atau `Hash(pesan ‖ kunci)`.** Pakai HMAC, KMAC, Poly1305, atau tag AEAD.
- **Bandingkan tag secara constant-time.** Perbandingan biasa berhenti di byte pertama yang salah, jadi mengukur lamanya waktu bisa membocorkan berapa byte yang sudah benar. Pakai `hmac.compare_digest` (Python) atau `CRYPTO_memcmp` (C).

## 7. Serangan Length-Extension (Konsep)

Pada hash Merkle-Damgård (SHA-1, SHA-256), output hash adalah state internal di akhir proses. Kalau penyerang tahu `Hash(rahasia ‖ pesan)` dan panjang input-nya, dia bisa melanjutkan perhitungan dan menghasilkan hash yang valid untuk `rahasia ‖ pesan ‖ padding ‖ data_tambahan`, **tanpa tahu rahasianya.**

Jadi desain buatan sendiri yang sering dipakai ini **tidak** aman:

```text
auth_tag = SHA256(rahasia ‖ pesan)         ✗  rentan length extension
auth_tag = HMAC-SHA256(rahasia, pesan)     ✓  aman
```

Solusinya: pakai HMAC, pakai hash yang tidak punya kelemahan ini (SHA-3, BLAKE3), atau pakai AEAD.

> Catatan edukasi: bagian ini menjelaskan kenapa desain naif itu gagal dan cara memilih konstruksi yang benar. Bagian ini tidak menjelaskan cara mengeksploitasi sistem pihak ketiga.

## 8. Menyimpan Password dengan Aman

SHA-256 dirancang supaya cepat, dan justru itulah masalahnya untuk password. Satu GPU bisa mencoba **miliaran** tebakan SHA-256 per detik, jadi database hash password SHA-256 yang bocor akan cepat jebol.

Password butuh fungsi yang **sengaja dibuat lambat** dan juga memakai banyak memori, supaya GPU dan chip khusus kehilangan keunggulannya:

```text
hash_tersimpan = KDF(password, salt, pengaturan biaya)
```

| KDF | Sifat | Catatan |
|:---|:---|:---|
| **Argon2id** | Lambat dan memory-hard | Pemenang Password Hashing Competition; pilihan default modern (Wong) |
| scrypt | Memory-hard | Bagus, tapi pengaturannya perlu diatur hati-hati |
| bcrypt | Lambat (CPU-hard) | Masih umum; hanya memakai 72 byte pertama dari password |
| PBKDF2 | Mengulang HMAC berkali-kali | Tidak memory-hard; butuh jumlah iterasi yang sangat tinggi |

### Salt dan pepper

- **Salt:** nilai acak (16+ byte), berbeda untuk setiap user, disimpan di samping hash. Dua user dengan password yang sama mendapat hash yang berbeda, dan "rainbow table" yang dihitung sebelumnya jadi tidak berguna.
- **Pepper (opsional):** rahasia tambahan yang disimpan di server, bukan di database. Kalau hanya database yang bocor, hash-nya tetap terlindungi.

Yang disimpan: output KDF, salt, dan pengaturan yang dipakai. Saat login, hitung ulang hash dengan salt dan pengaturan yang sama, lalu bandingkan secara constant-time. Untuk sistem baru, **pakai Argon2id**.

## 9. HKDF: Mengubah Satu Rahasia Menjadi Banyak Kunci

Setelah pertukaran kunci (misalnya ECDH), kamu mendapat satu rahasia bersama. Rahasia itu tidak benar-benar acak, dan biasanya kamu butuh beberapa kunci terpisah darinya (satu untuk tiap arah, satu untuk IV, dan seterusnya). HKDF menanganinya dalam dua langkah:

```text
1. Extract:  PRK = HMAC(salt, rahasia_mentah)          → "membersihkan" rahasia jadi acak merata
2. Expand:   kunci = HKDF-Expand(PRK, label, panjang)  → menghasilkan kunci sebanyak yang dibutuhkan
```

`label` (disebut `info`) membuat setiap kunci turunan berbeda, misalnya `"client key"` dan `"server key"`.

HKDF dipakai di TLS 1.3, Signal, dan framework protokol Noise.

## 10. Cheatsheet

```bash
# ── Cek integritas file ──────────────────────────────────────
sha256sum file.iso
sha256sum -c SHA256SUMS          # cek terhadap daftar yang dipublikasikan
b2sum file.tar                   # BLAKE2b (bagian dari coreutils)

# ── Digest / HMAC dengan OpenSSL ─────────────────────────────
openssl dgst -sha256 file.bin
echo -n 'payload' | openssl dgst -sha256 -hmac 'secret-key'

# ── Hash password dengan Argon2 (Python, argon2-cffi) ────────
python3 -c "
from argon2 import PasswordHasher
ph = PasswordHasher()          # Argon2id dengan default yang aman
h = ph.hash('correct horse battery staple')
print(h)
print(ph.verify(h, 'correct horse battery staple'))
"
```

## Catatan Keamanan

| Praktik buruk | Risiko | Gantinya |
|:---|:---|:---|
| MD5 atau SHA-1 untuk keamanan | Collision bisa dibuat | SHA-256 atau yang lebih kuat |
| `Hash(rahasia ‖ pesan)` sebagai MAC | Length extension | HMAC atau AEAD |
| Hash cepat (SHA-256) untuk password | Dibobol dengan GPU | Argon2id |
| Memotong hash jadi 64 bit | Collision dalam sekitar 2³² percobaan | Minimal 128 bit (preimage) / 256 bit (collision) |
| `==` biasa untuk membandingkan tag | Kebocoran timing | `hmac.compare_digest` / `CRYPTO_memcmp` |
