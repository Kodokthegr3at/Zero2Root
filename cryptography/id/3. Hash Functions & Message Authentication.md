## 1. Definisi Formal

Fungsi hash kriptografi adalah pemetaan efisien:

```text
H(input sepanjang apa pun) → output tetap n-bit

SHA-256("hello") → 2cf24dba5fb0a30e26e83b2ac5b9e29e1b161e5c1fa7425e73043362938b9824
```

yang mengompresi input berukuran arbitrer menjadi digest tetap n-bit (misalnya n=256 untuk SHA-256).

Sifat operasional yang diinginkan (Wong, Ch.2):
- Deterministik: H(m) selalu sama untuk m yang sama.
- Avalanche: mengubah 1 bit input membuat sekitar 50% bit output berubah.
- Efisien: evaluasi cepat di CPU umum, kebalikan dari KDF untuk password.

Hash membuat sidik jari (fingerprint) berukuran tetap untuk pemeriksaan integritas, commitment, Merkle tree, tanda tangan digital (hash-then-sign), dan KDF. Namun hash telanjang bukan autentikasi tanpa kunci rahasia; untuk itu pakai MAC/HMAC/AEAD.

## 2. Properti Keamanan Klasik

Misalkan lawan A dengan batas komputasi praktis.

### 2.1 Preimage resistance (one-way)
Diberikan h, sulit menemukan m dengan H(m)=h:

Artinya: penyerang yang kuat sekalipun hampir tidak punya peluang menemukan m seperti itu.

Kompleksitas generik sekitar 2ⁿ percobaan.

### 2.2 Second-preimage resistance
Diberikan m₁, sulit mencari m₂ ≠ m₁ dengan H(m₁)=H(m₂). Kompleksitas generik juga sekitar 2ⁿ.

### 2.3 Collision resistance
Sulit mencari sembarang pasangan m₁ ≠ m₂ dengan H(m₁)=H(m₂).
Karena birthday bound, kompleksitas generik sekitar 2^(n/2).

### 2.4 Hubungan antar properti
Collision resistance mengimplikasikan second-preimage resistance (secara asimptotik dalam banyak formalisasi). Sebaliknya tidak selalu berlaku. Desain modern menargetkan collision security sekitar 2^(n/2) dengan n ≥ 256 untuk level keamanan 128-bit.

## 3. Batas Ulang Tahun: Rumus Probabilitas

Masalah ulang tahun: berapa orang dibutuhkan agar peluang dua orang berulang tahun sama mencapai 50% atau lebih? Jawabannya sekitar 23 orang, bukan √365 seperti dugaan naif tanpa deret hitung.

Untuk k sampel seragam dari ruang berukuran N=2ⁿ:

peluang ada dua sampel yang sama naik jauh lebih cepat daripada yang biasanya dibayangkan.

Untuk peluang sekitar 1/2:

```text
k ≈ 1,18 × √N   yaitu sekitar 2^(n/2) percobaan
```

Jadi untuk hash 256-bit, menemukan collision *apa saja* butuh sekitar 2¹²⁸ percobaan, bukan 2²⁵⁶.

Implikasi (Wong, "The birthday bound"):
- SHA-256 (n=256) memberi collision generik sekitar 2¹²⁸, target level keamanan 128-bit.
- Truncation berbahaya: untuk mempertahankan collision resistance sekitar 128-bit, digest harus minimal 256-bit; untuk preimage saja, minimal 128-bit sudah cukup.

Selalu ukur digest sesuai properti yang dibutuhkan. Aplikasi yang sensitif terhadap collision (sertifikat, content-addressing model git di bawah pilihan adversarial) butuh margin birthday penuh.

## 4. Konstruksi: Merkle-Damgard vs Sponge

### 4.1 Merkle-Damgard (SHA-1, SHA-2)
1. Pad pesan (panjang pesan dikodekan di akhir padding).
2. Pecah menjadi blok M₁,...,M_L selebar compression function.
3. Iterasi:

```text
H₀ = IV
Hᵢ = f(Hᵢ₋₁, Mᵢ)      untuk setiap blok i = 1 ... L
H(M) = H_L
```

Setiap blok dicampurkan ke state yang terus berjalan, dan state terakhir itulah hasil hash-nya.

di mana f adalah compression function (untuk SHA-256, berbasis round SHA family).

Konsekuensinya: rentan length-extension (lihat §7) jika dipakai naif sebagai MAC lewat `H(K‖M)`.

### 4.2 Sponge (SHA-3 / Keccak)
State b-bit terdiri dari rate r ditambah capacity c (b=r+c). Input diserap (absorb) ke rate, dipermutasi lewat π, lalu output diperas (squeeze):

Keamanannya terhadap serangan generik sekitar c/2 bit.

SHA-3 kebal terhadap length-extension gaya MD. Konstruksi ini juga menyediakan XOF (SHAKE128/256) dengan keluaran berpanjang fleksibel.

```
 Merkle–Damgård                 Sponge (SHA-3)
 M1  M2  M3                     absorb → squeeze
  │   │   │                     ┌──────────────┐
  ▼   ▼   ▼                     │ rate r       │
 IV→f→f→f→ digest               │ capacity c   │──→ digest/XOF
                                └──────────────┘
```

## 5. Daftar Algoritma Hash dan Statusnya

| Fungsi | Digest | Konstruksi | Status | Catatan |
|:---|:---:|:---|:---|:---|
| MD5 | 128 | MD | Broken | Collision praktis |
| SHA-1 | 160 | MD | Broken | SHAttered (2017) |
| SHA-256 | 256 | MD | Aman | Rentan length-extension jika disalahgunakan |
| SHA-512 | 512 | MD | Aman | Baik di CPU 64-bit |
| SHA-3-256 | 256 | Sponge | Aman | Alternatif struktural |
| SHAKE256 | variabel | XOF | Aman | Output fleksibel |
| BLAKE3 | 256 | Tree | Aman, cepat | Paralel / SIMD |

Aturan praktis: untuk integritas file, pakai SHA-256/BLAKE3; untuk protokol baru, pakai SHA-256 atau SHA-3/BLAKE3. Jangan pakai MD5/SHA-1 untuk keperluan keamanan.

## 6. Message Authentication Code (MAC) dan HMAC

MAC memakai kunci rahasia untuk memberi autentikasi sekaligus integritas:

```text
t = MAC(K, m)
Verify(K, m, t) → true / false
```

### HMAC (RFC 2104)
```text
HMAC(K, m) = H( (K' XOR opad) ‖ H( (K' XOR ipad) ‖ m ) )
```

Artinya: hash kunci (dicampur ipad) bersama pesan, lalu hash hasilnya sekali lagi dengan kunci (dicampur opad). Dua lapis inilah yang mencegah serangan length-extension.

- K' adalah kunci yang dipad atau dipotong ke ukuran blok hash.
- ipad=0x36..., opad=0x5c...

HMAC tetap aman dengan SHA-256 walaupun konstruksi MD rentan length-extension pada penggunaan naif.

### Poly1305
MAC cepat berbasis polinomial modulo 2¹³⁰-5, dipasangkan dengan ChaCha20 sebagai AEAD (ChaCha20-Poly1305).

Jangan pernah membuat sendiri `H(K‖m)` atau `H(m‖K)` sebagai MAC. Gunakan HMAC, KMAC, Poly1305, atau tag AEAD. Bandingkan tag dalam waktu konstan (constant time).

---

## 7. Serangan Length-Extension (Konsep)

Untuk hash Merkle-Damgard, jika lawan mengetahui H(M) dan panjang |M|, lawan dapat menghitung H(M ‖ pad ‖ M') tanpa mengetahui M, dengan cara meneruskan state internal.

Implikasinya: `auth = SHA256(secret ‖ message)` bukan MAC yang aman. Mitigasi: HMAC, SHA-3/BLAKE3, atau AEAD.

> Fokus catatan ini adalah memahami mengapa desain naif gagal dan bagaimana memilih konstruksi yang benar, bukan prosedur eksploitasi terhadap sistem pihak ketiga.

## 8. Hashing Password dan KDF Memory-Hard

SHA-256 sengaja dibuat cepat, sehingga GPU/ASIC bisa menguji miliaran kandidat per detik. Password wajib memakai KDF yang lambat atau memory-hard.

Misalkan cost parameter t (iterasi/waktu), memori m, paralelisme p:

```text
stored_hash = KDF(password, salt, t, m, p)
```

| KDF | Sifat | Catatan |
|:---|:---|:---|
| Argon2id | Memory-hard, seimbang terhadap side-channel | Pemenang PHC; pilihan default modern (Wong) |
| scrypt | Memory-hard | Baik; parameter harus dipilih hati-hati |
| bcrypt | CPU-hard (berbasis Blowfish) | Masih umum dipakai; ada batas panjang password |
| PBKDF2 | Iterasi HMAC | Bukan memory-hard; butuh iterasi sangat tinggi |

Salt unik per user (16 byte acak atau lebih) mencegah rainbow table. Pepper (rahasia di sisi server) adalah tambahan opsional.

Simpan hanya output KDF, salt, dan parameternya. Saat login, hitung ulang dan bandingkan dalam waktu konstan. Argon2id direkomendasikan untuk sistem baru.

## 9. HKDF: Extract-then-Expand

Dari shared secret mentah (misalnya hasil ECDH) yang belum seragam sempurna:

```text
PRK = HKDF-Extract(salt, IKM) = HMAC(salt, IKM)
OKM = HKDF-Expand(PRK, info, L)
```

- Extract: menyeragamkan entropi.
- Expand: menghasilkan L byte kunci aplikasi (traffic key, IV key, dan sebagainya).

Dipakai luas di TLS 1.3, Signal, dan Noise.

## 10. Cheatsheet

```bash
# ── Integrity ────────────────────────────────────────────────
sha256sum file.iso
sha256sum -c SHA256SUMS
b2sum file.tar                 # BLAKE2b (util-linux)

# ── OpenSSL digest / HMAC ────────────────────────────────────
openssl dgst -sha256 file.bin
echo -n 'payload' | openssl dgst -sha256 -hmac 'secret-key'

# ── Argon2 example (Python) ──────────────────────────────────
python3 -c "
from argon2 import PasswordHasher
ph = PasswordHasher()          # Argon2id defaults
h = ph.hash('correct horse battery staple')
print(h)
print(ph.verify(h, 'correct horse battery staple'))
"
```

## Catatan Keamanan

| Anti-pattern | Risiko | Ganti dengan |
|:---|:---|:---|
| MD5/SHA-1 untuk keamanan | Collision | SHA-256 atau lebih tinggi |
| `H(secret‖msg)` sebagai MAC | Length extension | HMAC / AEAD |
| Hash cepat untuk password | GPU cracking | Argon2id |
| Truncate ke 64-bit | Birthday break cepat | Minimal 128-bit (preimage) / 256-bit (collision) |
| Perbandingan tag non-constant-time | Timing leak | `hmac.compare_digest` / `CRYPTO_memcmp` |
