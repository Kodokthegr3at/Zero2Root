## 1. 公開鍵モデル

公開鍵暗号(非対称暗号)は、数学的に関連づけられた鍵ペア $(pk, sk)$ を使う。

- pk(公開鍵):公開してよく、暗号化や署名検証に使う。
- sk(秘密鍵):絶対に秘密にし、復号や署名生成に使う。

```text
KeyGen()     → (pk, sk)
c = Enc(pk, m)     公開鍵を使えば誰でも暗号化できる
m = Dec(sk, c)     復号できるのは秘密鍵の持ち主だけ
```

安全性は一方向性トラップドア関数に依存する。pk を使えば一方向は簡単に計算できるが、sk なしでは逆方向の計算が難しい。

公開鍵演算はAESより遅い。実際のシステムでは、公開鍵暗号を鍵の確立や認証に使い、その後は共通鍵のAEADで大量データを暗号化する。この構成はハイブリッド暗号と呼ばれる。

## 2. 数論の基礎

### 2.1 合同算術(モジュラー演算)
```text
a ≡ b (mod n)   a と b を n で割った余りが等しい

例: 17 ≡ 5 (mod 12)   (12時間時計では17時は5時)
```

剰余類は ℤ/nℤ と表す。p が素数のとき、ℤ/pℤ は体(field)になる。

### 2.2 フェルマーの小定理とオイラーの定理
p が素数で gcd(a,p)=1 のとき、

```text
a^(p-1) ≡ 1 (mod p)        フェルマーの小定理

例: p = 5, a = 2 → 2⁴ = 16 = 3·5 + 1 → 余り 1
```

オイラーのトーシェント関数 φ(n) は、{1,...,n-1} のうち n と互いに素な整数の個数を表す。異なる素数 p,q について n=pq のとき、

```text
φ(n) = (p-1)(q-1)

例: p = 3, q = 11 → n = 33, φ(n) = 2 × 10 = 20
```

オイラーの定理:gcd(a,n)=1 ならば、

```text
a^φ(n) ≡ 1 (mod n)
```

### 2.3 モジュラー逆元
d が e の φ(n) を法とした逆元であるとは、次を満たすことをいう。

```text
e × d ≡ 1 (mod φ(n))

例: φ(n) = 20, e = 3 → d = 7(3 × 7 = 21 = 20 + 1 だから)
```

拡張ユークリッドの互除法で計算でき、計算量は古典的なユークリッドの互除法と同様 O(log n) である。

### 2.4 離散対数問題(DLP)
大きな位数を持つ巡回群 ⟨g⟩ と A=gᵃ が与えられたとき、次を求める問題である。

```text
既知:  g、p、A = gᵃ mod p
求める: a
```

a から A を計算するのは速いが、p が大きいと A から a を逆算するのは非常に遅い。

適切に選ばれた群では困難であり、ディフィー・ヘルマン鍵交換の基盤となっている。

## 3. RSA(Rivest-Shamir-Adleman)

RSAの古典的な安全性は、整数の素因数分解問題に基づく。n=pq から p と q を求めるのは困難である。

### 3.1 鍵生成
1. 大きな秘密の素数 p ≠ q を選ぶ。
2. n ← p·q を計算する(公開モジュラス)。
3. φ(n) ← (p-1)(q-1) を計算するか、カーマイケル関数 λ(n)=lcm(p-1,q-1) を使う(現代的な実践)。
4. gcd(e,φ(n))=1 を満たす e を選ぶ。業界標準は e=65537=2¹⁶+1。
5. 秘密指数 d ← e⁻¹ mod φ(n) を計算する。

```text
公開鍵 = (n, e)
秘密鍵 = (n, d)      復号を速くするため p と q も一緒に保存することが多い
```

### 3.2 教科書的RSA(理論目的のみ。そのまま使ってはならない)

```text
暗号化:  C = Mᵉ mod n
復号:    M = Cᵈ mod n

例: n = 33, e = 3, d = 7 のとき
  M = 4   →  C = 4³ mod 33 = 64 mod 33 = 31
  C = 31  →  M = 31⁷ mod 33 = 4   ✓
```

教科書的RSAは危険である(Wong §6.3)。決定的であり、展性(malleability)があり(C' ≡ C·2ᵉ ⇒ 平文が2倍になる)、古いスキームではパディングオラクルにも弱い。

### 3.3 正当性(簡潔な証明)
なぜ元に戻るのか: e と d は、ある整数 t について e × d = 1 + t·φ(n) となるように選ばれている。オイラーの定理より M^φ(n) ≡ 1 なので、M を e × d 乗すると M だけが残る。

これは gcd(M,n)=1 の場合であり、一般の場合は p と q に対するCRTで扱う。

### 3.4 RSA-OAEP(正しい非対称暗号化)
OAEP(Optimal Asymmetric Encryption Padding)は、暗号化を確率的にし、理想モデルにおいてIND-CCA安全にする。

```text
C = RSA(pk, OAEP(M, random r))
```

OAEPは暗号化の前に新しい乱数をメッセージに混ぜるので、同じメッセージでも毎回違う暗号文になる。

生のモジュラー指数計算ではなく、ライブラリのAPI(`RSA_PKCS1_OAEP_PADDING`)を使うこと。

### 3.5 CRTによる高速復号
n を法とした大きな計算を1回行う代わりに、p を法とした計算と q を法とした計算の2回に分け、結果を中国剰余定理(CRT)で組み合わせる。

n を法とした完全な指数計算に比べ、およそ4倍高速である。

暗号化にはRSA-OAEP、署名にはRSA-PSSを使うこと。PKCS#1 v1.5暗号化はオラクル攻撃の歴史があるため、新規設計では避ける。TLS 1.3の鍵交換では、RSA key transportは完全に廃止され、(EC)DHEに置き換えられている。

| 目標とする安全性強度(目安) | RSAモジュラス | ECC(第5節参照) |
|:---|:---:|:---:|
| 約128ビット | 3072ビット以上 | 約256ビット |
| 約192ビット | 7680ビット以上 | 約384ビット |
| 約256ビット | 15360ビット以上 | 約521ビット |

## 4. ディフィー・ヘルマン鍵交換

DHは、AliceとBobが公開チャネル上で、秘密そのものを送信することなく共有秘密に合意できる仕組みである(Wong, 第5章)。

### 公開パラメータ
- 安全な素数 p。
- 大きな位数 q の部分群の生成元 g(small-subgroup攻撃を避けるため)。

### プロトコル
```text
Alice: 秘密の a を選び、A = gᵃ mod p を送る
Bob:   秘密の b を選び、B = gᵇ mod p を送る
Alice は Bᵃ mod p、Bob は Aᵇ mod p を計算  →  どちらも gᵃᵇ mod p になる

例: p = 23, g = 5 のとき
  a = 6   →  A = 5⁶ mod 23 = 8
  b = 15  →  B = 5¹⁵ mod 23 = 19
  Alice: 19⁶ mod 23 = 2      Bob: 8¹⁵ mod 23 = 2   ✓ 同じ鍵
```

指数は可換なので K_A = K_B = gᵃᵇ mod p となる。

### 困難性
観測者は (p,g,A,B) を見ることができるが、gᵃᵇ を計算するのは計算量的ディフィー・ヘルマン(CDH)問題であり、離散対数問題と密接に関係する。

```
Alice                                              Bob
  │ a random                                         │ b random
  │ A = g^a mod p                                    │ B = g^b mod p
  │─────────────── A ───────────────────────────────>│
  │<────────────── B ────────────────────────────────│
  │ K = B^a                                          │ K = A^b
  │═══════════════ K = g^{ab} ═══════════════════════│
```

PFS(Perfect Forward Secrecy、前方秘匿性):セッションごとにエフェメラル鍵(DHE/ECDHE)を使うことで、将来長期鍵が漏洩しても過去のセッションは復号されない。

公開鍵が正しい部分群に属することを必ず検証する。RFC 7919のFFDHEなど標準化されたグループを使うか、さらに望ましくは楕円曲線を使う。

## 5. 楕円曲線暗号(ECC)

素数体 p 上の楕円曲線(短ワイエルシュトラス形式)は次の式で表される。

```text
y² = x³ + ax + b  (mod p)
```

判別式が非特異であること(4a³+27b² ≢ 0 (mod)p)が条件となる。曲線上の点に無限遠点 O を加えたものがアーベル群を成す。

### 群演算(幾何的な直感から式へ)
P=(x₁,y₁)、Q=(x₂,y₂)、P+Q=(x₃,y₃) とすると、

2点 P と Q を足すには、両方を通る直線を引き、その直線が曲線と交わる3つ目の点を見つけ、x軸に対して折り返す。同じ点どうしを足す(2倍算)ときは接線を使う。実際の計算はライブラリが p を法とした厳密な式で行うので、手で計算する必要はない。

スカラー倍算:k·G = G+...+G (k ×)(double-and-add法)。一方向は容易だが、逆問題(ECDLP)は困難である。

### ECDH
```text
Alice: a  →  A = a·G
Bob:   b  →  B = b·G
a·B = b·A = (a·b)·G
```

a と b は秘密のままで、ネットワークを流れるのは A と B だけだ。それでも両者は同じ点にたどり着く。

一般的な曲線はP-256 / prime256v1 / secp256r1である。現代的な代替としてX25519(モンゴメリ曲線、RFC 7748)があり、こちらはAPIが誤用されにくい設計になっている。

ECCはRSAと同等の安全性を、はるかに小さい鍵長かつ高速な演算で実現するため、TLS、SSH、モバイル環境に適している。生の点演算より高水準API(`X25519`、`Ed25519`)を使うべきである。

| レベル | 共通鍵 | RSA | ECC |
|:---|:---:|:---:|:---:|
| 標準 | 128 | 3072 | 256(P-256 / X25519) |
| 高 | 192 | 7680 | 384 |
| 最高 | 256 | 15360 | 521 / Ed448 |

## 6. デジタル署名

### モデル
```text
σ = Sign(sk, m)
Verify(pk, m, σ) → true / false
```

署名を作るのは秘密鍵で、公開鍵を持っていれば誰でも検証できる。

### RSA-PSS(推奨されるRSA署名方式)
Probabilistic Signature Scheme(確率的署名方式)であり、PKCS#1 v1.5より強い安全性証明を持つ。

### ECDSA(概要)
base point G の位数を n、秘密鍵を d、Q=dG とすると、

1. ノンス k ← random ℤₙ^(*) を選ぶ。これは一意かつ秘密でなければならない。k を再利用すると秘密鍵が漏洩する。これはPlayStation 3で実際に起きた古典的な事例である。
2. r = (kG)ₓ mod n を計算する。
3. s = k⁻¹(H(m)+d·r) mod n を計算する。
4. 署名は (r,s) となる。

検証では u₁=H(m)s⁻¹、u₂=rs⁻¹ を用い、(u₁G+u₂Q)ₓ ≡ r を確認する。

### EdDSA(Ed25519)
ハッシュから決定的に導出されるノンスを使うことで、ECDSAで問題になるRNG関連のバグのクラスを排除する。SSH、Git、その他多くのプロトコルで現代的な標準となっている。

## 7. ハイブリッド暗号(KEM + DEM)

大きなファイルを素のRSAだけで暗号化するのは非効率で、標準的な手法でもない。一般的なパターンは次のとおりである。

1. セッション鍵 k ← random {0,1}²⁵⁶ を生成する。
2. データを暗号化する: c_data ← AEADₖ(m)(AES-GCM / ChaCha20-Poly1305)。
3. k をラップする: cₖ ← Enc_pk(k)(RSA-OAEP)、またはECDHの共有秘密からHKDFで k を導出する。

これはKEM/DEM(Key Encapsulation + Data Encapsulation)パターンであり、ECIESの基盤にもなっている(Wong §6.4)。

TLS、Signal、その他多くの現代的なメッセージングアプリは、このハイブリッド設計に従っている。鍵合意と認証は非対称暗号、レコードの保護は共通鍵のAEADという役割分担である。

## 8. 量子コンピュータの脅威とPQC(展望)

大規模な量子コンピュータ上のShorのアルゴリズムは、素因数分解とDLP/ECDLPの両方を解いてしまうため、RSA、DH、ECCは長期的なリスクにさらされている。

業界の方向性(NIST PQC)としては、鍵カプセル化にはML-KEM(Kyber)、署名にはML-DSA(Dilithium)やSLH-DSAが選ばれている。従来方式とPQCを組み合わせたハイブリッド展開は、実験的なTLSですでに試行が始まっている。

共通鍵暗号(AES-256)とハッシュ(SHA-256)は比較的耐性が高い。Groverのアルゴリズムは2次的な高速化しかもたらさないため、AES-256は依然として十分な安全マージンを保っている。

## 9. OpenSSLチートシート

```bash
# ── RSA 4096ビット鍵ペア ─────────────────────────────────────────
openssl genrsa -out private_rsa.pem 4096
openssl rsa -in private_rsa.pem -pubout -out public_rsa.pem

# ── OAEPで小さなデータを暗号化/復号(教科書的RSAではない) ────
openssl pkeyutl -encrypt -pubin -inkey public_rsa.pem \
  -pkeyopt rsa_padding_mode:oaep -in key.bin -out key.enc
openssl pkeyutl -decrypt -inkey private_rsa.pem \
  -pkeyopt rsa_padding_mode:oaep -in key.enc -out key.bin

# ── ECC P-256 / Ed25519 ──────────────────────────────────────
openssl ecparam -name prime256v1 -genkey -noout -out private_ec.pem
openssl genpkey -algorithm ED25519 -out private_ed25519.pem
openssl pkey -in private_ed25519.pem -pubout -out public_ed25519.pem

# ── 署名と検証(RSA-SHA256) ───────────────────────────────
openssl dgst -sha256 -sign private_rsa.pem -out doc.sig document.pdf
openssl dgst -sha256 -verify public_rsa.pem -signature doc.sig document.pdf
```

| リスク | 原因 | 対策 |
|:---|:---|:---|
| 教科書的RSA | パディングなし | OAEP。生のRSAは使わない |
