## 重要な用語

この教材でよく出てくる言葉である。

| 用語 | 意味 |
|:---|:---|
| 平文(plaintext) | 元の、読めるメッセージ |
| 暗号文(ciphertext) | 暗号化されて読めなくなったメッセージ |
| 鍵(key) | メッセージに鍵をかけたり開けたりするための秘密の値 |
| 共通鍵(symmetric) | 暗号化と復号に同じ鍵を使う方式 |
| ブロック暗号 | データを決まった大きさのかたまりごとに暗号化する(AESは16バイトのブロック) |
| ストリーム暗号 | ランダムに見えるビット列とデータを混ぜて、1ビットずつ暗号化する |
| XOR | 単純なビット演算: 0⊕0=0、1⊕1=0、0⊕1=1。同じ値で2回XORすると元に戻る |
| IV / ノンス | 「一度だけ使う数」。メッセージごとに必ず変える値で、同じメッセージが同じ暗号文にならないようにする |
| 利用モード | 1ブロックより長いメッセージを暗号化するためのルール |
| MAC / タグ | 秘密鍵を使って作る短いチェックサム。メッセージが改ざんされていないことを証明する |
| AEAD | タグ付きの暗号化。1回の処理で秘密性と改ざん検知の*両方*が得られる(例: AES-GCM) |

## 1. 暗号が目指すもの

暗号は、データを読もうとしたり書き換えようとしたりする相手からデータを守る(David Wong『Real-World Cryptography』第1章)。目指すものは主に4つある。

| 目標 | 答える問い | 代表的な道具 |
|:---|:---|:---|
| 機密性 | ほかの人に読まれないか? | 暗号化 |
| 完全性 | 途中で書き換えられていないか? | MAC、AEADのタグ |
| 認証 | 本当に思っている相手から来たのか? | MAC、デジタル署名 |
| 否認防止 | 送信者が後から「送っていない」と言えないか? | デジタル署名 |

共通鍵暗号だけで得られるのは**機密性**だけだ。メッセージを読めない攻撃者でも、書き換えることはできるかもしれない。だから現代のシステムは、改ざんを検知するタグを付けたAEAD(AES-GCMやChaCha20-Poly1305)を使う。

## 2. 共通鍵暗号のしくみ

鍵が1種類だけの箱を想像してほしい。2人とも同じ鍵の合い鍵を持っている。1人が箱に鍵をかけ、もう1人が開ける。

共通鍵暗号は3つの手順でできている。

```text
KeyGen()   → k     秘密鍵を作る
Enc(k, m)  → c     平文 m を暗号文 c に暗号化する
Dec(k, c)  → m     c を復号して m に戻す
```

常に成り立たなければならないルールが2つある。

1. **元に戻せること。** 同じ鍵で暗号化してから復号すれば、必ず元のメッセージに戻る。
2. **暗号文から何も漏れないこと。** 暗号文を見た人には、だいたいの長さ以外、中身について何も分からない。

### 秘密にするのはアルゴリズムではなく鍵

この考え方を**ケルクホフスの原理**という。攻撃者がどのアルゴリズムを使っているか完全に知っていても、システムは安全でなければならない。AESは公開されていて、しくみは誰でも知っている。安全性は鍵を秘密にすることだけから生まれる。「秘密のアルゴリズム」は守りにならない。いずれ誰かが解析してしまうからだ。

### 共通鍵暗号と公開鍵暗号の比較

| | 共通鍵 | 公開鍵 |
|:---|:---|:---|
| 鍵 | 共有する秘密が1つ | 公開鍵と秘密鍵のペア |
| 速度 | 非常に速い(CPUにAES専用命令がある) | ずっと遅い |
| 代表的なサイズ | AES-128 / AES-256 | RSA-2048以上 / ECC-256以上 |
| 主な用途 | データそのものの暗号化: ファイル、ディスク、通信 | 鍵の合意、署名 |
| 攻撃者がやるべきこと | すべての鍵を試す | 難しい数学の問題(素因数分解、離散対数)を解く |

共通鍵暗号の大きな弱点は、鍵を安全に相手へ届ける方法だ。その問題を解決するのが公開鍵暗号である(LC-055を参照)。

## 3. ブロック暗号とストリーム暗号

### ブロック暗号

ブロック暗号は、決まった大きさの平文のかたまりと鍵を受け取り、同じ大きさの暗号文のかたまりを出力する。

```text
C = E(k, P)        P = 平文ブロック1つ、C = 暗号文ブロック1つ
```

AESは常に128ビット(16バイト)のブロックで動く。それより長いメッセージはブロックに分割する必要があり、ブロック同士のつなぎ方は**利用モード**(第5節)が決める。

### ストリーム暗号

ストリーム暗号は、鍵からランダムに見える長いビット列(**キーストリーム**)を作り、それをメッセージとXORする。

```text
暗号文     = メッセージ XOR キーストリーム
メッセージ = 暗号文 XOR キーストリーム     (2回XORすると元に戻る)
```

現代の代表例は**ChaCha20**で、タグには**Poly1305**を組み合わせることが多い。

ストリーム暗号の鉄則: **同じキーストリームを二度と使わないこと**。2つのメッセージを同じキーストリームでXORすると、攻撃者は2つの暗号文同士をXORできる。キーストリームが打ち消し合い、2つのメッセージが混ざったものだけが残る。そこから両方のメッセージを推測するのは、たいてい簡単だ。

## 4. AESの中身

AES(Advanced Encryption Standard、元の名前はRijndael)は、NISTの公開コンペで選ばれ、今ではほぼどこでも使われている(Wong 第4章)。

| 種類 | 鍵長 | ラウンド数 | ブロック長 |
|:---|:---:|:---:|:---:|
| AES-128 | 128ビット | 10 | 128ビット |
| AES-192 | 192ビット | 12 | 128ビット |
| AES-256 | 256ビット | 14 | 128ビット |

AESは16バイトのブロックを4 × 4のバイトの表として扱う。これを**状態(state)**と呼ぶ。そして同じ4つの手順(1**ラウンド**)を何回も繰り返す。ラウンドのたびにデータが少しずつかき混ぜられ、最後には完全にランダムに見える出力になる。

```
┌──────────────────────────────────────────────────────────┐
│                    AES ENCRYPTION FLOW                   │
│  Plaintext (128-bit)                                     │
│       │                                                  │
│       ▼                                                  │
│  AddRoundKey (K0)                                        │
│       │                                                  │
│   ┌───┴───────────────────────────────┐                  │
│   │  Repeat Nr-1 times:               │                  │
│   │   SubBytes → ShiftRows →          │                  │
│   │   MixColumns → AddRoundKey (Kr)   │                  │
│   └───────────────────────────────────┘                  │
│       │                                                  │
│  Final: SubBytes → ShiftRows → AddRoundKey (K_Nr)        │
│       │                                                  │
│       ▼                                                  │
│  Ciphertext (128-bit)                                    │
└──────────────────────────────────────────────────────────┘
```

各手順がやっていること:

| 手順 | 内容 | なぜ重要か |
|:---|:---|:---|
| **SubBytes** | 各バイトを、決まった変換表(**S-box**)の別のバイトに置き換える | 唯一の非線形な手順。これがないと、AESは単純な連立方程式のように解けてしまう |
| **ShiftRows** | 1行目を左に1つ、2行目を2つ、3行目を3つずらす | バイトを別々の列へ散らす |
| **MixColumns** | 各列の4バイトを混ぜ合わせる | 入力の1バイトが変わると列全体が変わるようになる |
| **AddRoundKey** | 鍵から作った**ラウンド鍵**と状態をXORする | ここで初めて鍵が処理に入る |

数ラウンド経つと、平文か鍵の1ビットを変えるだけで出力のおよそ半分のビットが変わる。この効果を**拡散**、またはアバランシェ効果という。

最終ラウンドではMixColumnsを行わない。これは、復号が暗号化をきれいに逆にたどれるようにするための設計上の工夫である。

> S-boxとMixColumnsは、GF(2⁸)という特殊な数の体系で計算する。そこでは「足し算」がXORになる。AESを使うだけならこれは必要ない。必要になるのはAESを自分で実装するときだけで、そもそも自分で実装すべきではない。検証済みのライブラリを使うこと。

### 総当たりでAESを破るのはどれくらい難しいか

AES-128の鍵は2¹²⁸通り、およそ3.4 × 10³⁸個(39桁の数)ある。攻撃者は平均すると、その半分を試したところで正しい鍵に当たる。

仮に1秒間に10¹²個(1兆個)の鍵を試せる機械があっても、約5 × 10¹⁸年かかる。宇宙の年齢の数億倍だ。

つまり現実には、鍵を当てずっぽうで探してAESを破る人はいない。実際の攻撃が狙うのは**AESの使い方**である。弱い鍵管理、ノンスの再利用、完全性チェックの欠如、タイミングなどのサイドチャネルだ。

## 5. 利用モード: ECBからAEADまで

AESが暗号化できるのは16バイトのブロック1つだけだ。長いメッセージをどう扱うかは利用モードが決める。モードの選択ミスは、暗号で最もよくある失敗の1つである。

### 5.1 ECB(Electronic Codebook): 使ってはいけない

各ブロックを同じ鍵で個別に暗号化する。

```text
C1 = E(k, P1)    C2 = E(k, P2)    C3 = E(k, P3)  ...
```

問題は、**同じ平文ブロックが同じ暗号文ブロックになる**ことだ。データの模様がそのまま見えてしまう。有名な例が「ECBペンギン」で、ペンギンの画像をECBで暗号化しても、暗号化後の画像にペンギンの形がはっきり残る。

### 5.2 CBC(Cipher Block Chaining)

各ブロックは暗号化の前に、1つ前の暗号文ブロックとXORされる。最初のブロックには代わりにランダムな**IV**を使う。

```text
C1 = E(k, P1 XOR IV)
C2 = E(k, P2 XOR C1)
C3 = E(k, P3 XOR C2)  ...
```

これで各ブロックがそれより前のすべてに依存するので、同じブロックが並んでも同じには見えない。

CBCのルール:
- IVはランダムで予測できず、メッセージごとに新しくしなければならない。
- CBCはデータを隠すが、**改ざんは検知しない**。攻撃者は暗号文のビットを反転させて、復号結果に予測可能な変化を起こせる。CBCには必ずMACを組み合わせること(先に暗号化し、その暗号文に対してHMACを付ける「encrypt-then-MAC」)。

### 5.3 CTR(Counter Mode)

CTRはAESをストリーム暗号に変える。メッセージではなくカウンタ(ノンス + 1、ノンス + 2、…)を暗号化してキーストリームを作り、それをメッセージとXORする。

```text
i番目のキーストリームブロック = E(k, ノンス ‖ カウンタ i)
Ci = Pi XOR i番目のキーストリームブロック
```

利点は、並列処理ができ、パディングが不要なこと。大事なルールは、**同じ鍵でノンスを絶対に繰り返さない**こと。繰り返すと、第3節のキーストリーム再利用の問題に戻ってしまう。

### 5.4 GCM(Galois/Counter Mode): 現代の標準

GCM = 暗号化のためのCTRモード + 組み込みの認証タグ。これが**AEAD**で、1回の処理で秘密性と改ざん検知の両方が得られる。

```text
暗号化:  (暗号文, タグ) = AES-GCM(鍵, ノンス, 平文, 追加データ)
復号:    まずタグを確認 → 一致しなければすべて捨てる
```

- タグは通常16バイト。
- `追加データ`(AAD、additional authenticated data)は、読めるままだが改ざんからは守られるデータで、たとえばパケットのヘッダーがこれに当たる。
- **タグの確認に失敗したら、メッセージ全体を拒否する。**「とりあえず復号する」は絶対にしない。
- CTRと同じく、同じ鍵でノンスを一度でも再利用するとGCMは崩れる。GCMではさらに深刻で、ノンスが重なると攻撃者がタグを偽造できてしまう。

### まとめ

| モード | データを隠す | 改ざん検知 | 並列処理 | 評価 |
|:---|:---:|:---:|:---:|:---|
| ECB | 模様が漏れる | なし | 可 | ほぼすべての用途で壊れている |
| CBC | あり | なし | 復号のみ | MACと組み合わせる場合のみ可。IVはランダムに |
| CTR | あり | なし | 可 | MACが必要。ノンスは一意に |
| GCM | あり | あり | 可 | TLSの標準。ノンスの再利用は厳禁 |
| ChaCha20-Poly1305 | あり | あり | 可 | AESのハードウェアがない端末で有利 |

Wongの忠告は今も正しい。**認証のない暗号化は危険だ。** CBCとHMACを自分で組み合わせるのではなく、完成品のAEAD(AES-GCMかChaCha20-Poly1305)を使うこと。どうしても組み合わせるなら、別々の2つの鍵でencrypt-then-MACにし、タグは定数時間で比較し、どんな失敗でも同じエラーを返すこと。

## 6. パディングとパディングオラクル問題

CBCでは、メッセージの長さがちょうど16バイトの倍数でなければならない。足りなければ末尾にバイトを足す。標準的な方法が**PKCS#7**で、値Nのバイトを N 個足す。

```text
13バイトのメッセージ → あと3バイト必要  → 03 03 03 を足す
10バイトのメッセージ → あと6バイト必要  → 06 06 06 06 06 06 を足す
16バイトのメッセージ → すでにちょうど   → 10 10 ... 10 の1ブロック(0x10が16バイト)を丸ごと足す
```

最後のルールがあるおかげで、受信側は推測せずに必ずパディングを取り除ける。

### パディングオラクル(考え方)

あるサーバーがCBCのメッセージを復号し、「パディングが不正」と「データが不正」で**違うエラー**を返すとする。その違いが情報を漏らす。少しずつ書き換えた暗号文を大量に送り、どちらのエラーが返るかを見ることで、攻撃者は鍵を知らないまま最終的に平文を取り出せてしまう。これはVaudenay型の攻撃として知られている。

防ぎ方:
- AEAD(GCM / ChaCha20-Poly1305)を使う。AEADは何よりも先にタグを確認する。
- どうしてもCBCを使うなら、encrypt-then-MACにして、どんな失敗にも**まったく同じエラー**を返す。

> 教育上の注記: この教材では、攻撃が成り立つ理由と止め方を説明する。具体的な悪用手順は意図的に記載していない。

## 7. 鍵の強さは実際どのくらいか

### 数学が弱点になることはまずない

第4節で見たとおり、AES-128の鍵を当てるのは絶望的だ。攻撃者は平均して全鍵の半分を試す必要がある。

```text
平均時間 ≈ (鍵の総数 ÷ 2) ÷ 1秒あたりの試行回数
```

鍵が1ビット長くなるごとに、攻撃者の作業量は2倍になる。AES-256はAES-128の「2倍強い」のではなく、総当たりが2¹²⁸倍難しいのだ。

### 実践的なルール(Wong / 業界)

- ほとんどの現代的な用途では**AES-128で十分**。
- **AES-256**は余裕を上乗せする。長期間守る秘密、一部の政府規格、将来の量子コンピュータへの備えに使われる。
- **独自の方式を作らない**(「二重AES」、自作モード、「AESっぽい」暗号など)。よく研究されたモードを、よくテストされたライブラリで使うこと。
- **鍵そのものを守る:** ログ、ソースコード、バックアップに鍵を入れない。可能ならHSMやKMSに保管する。

## 8. OpenSSLチートシート(自分のファイル / ラボのみ)

```bash
# ── パスワードでファイルを暗号化 / 復号(AES-256-CBC + PBKDF2) ──
openssl enc -aes-256-cbc -salt -pbkdf2 -iter 100000 \
  -in confidential.txt -out secret.enc

openssl enc -d -aes-256-cbc -pbkdf2 -iter 100000 \
  -in secret.enc -out decrypted.txt

# ── ランダムな鍵素材を作る ───────────────────────────────────
openssl rand -hex 32    # 256ビットの鍵
openssl rand -hex 12    # GCM用の96ビットのノンス

# ── 自分のマシンで速度を比べる ───────────────────────────────
openssl speed -evp aes-256-gcm
openssl speed -evp chacha20-poly1305
```

注意: `openssl enc` はGCMのようなAEADモードに**対応していない**。CBCの出力にMACを付けることもしない。認証付き暗号化にはライブラリを使うこと。たとえばPythonの `cryptography` パッケージなら次のようになる。

```python
from cryptography.hazmat.primitives.ciphers.aead import AESGCM
import os

key = AESGCM.generate_key(bit_length=256)
nonce = os.urandom(12)                       # メッセージごとに新しいノンス
ct = AESGCM(key).encrypt(nonce, b"secret data", b"header")
pt = AESGCM(key).decrypt(nonce, ct, b"header")   # 何か書き換えられていればエラーになる
```

## セキュリティノート: 脅威と防御

| 脅威 | 何がまずいか | 防御 |
|:---|:---|:---|
| 模様の漏えい | ECBを使う | ECBは使わない。GCMかChaCha20-Poly1305を使う |
| ビット反転 | MACなしのCBC | AEAD、またはencrypt-then-MAC |
| ノンスの再利用 | CTR/GCMで同じノンスを2回使う | ランダムな96ビットのノンス、または繰り返さないカウンタ |
| パディングオラクル | パディングとデータで違うエラーを返す | AEAD。エラーメッセージを1つに統一する |
| 鍵の漏えい | 鍵がログ、バックアップ、スワップ、gitに入る | HSM/KMS、最小権限、シークレットスキャン |
| サイドチャネル | S-boxの参照でタイミングやキャッシュから漏れる | 定数時間のライブラリ、ハードウェアAES(AES-NI) |
