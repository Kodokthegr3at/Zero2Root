## 重要な用語

この教材でよく出てくる言葉である。

| 用語 | 意味 |
|:---|:---|
| STA(ステーション) | Wi-Fiのクライアント。ノートPCやスマホなど |
| AP(アクセスポイント) | クライアントが接続する機器(Wi-Fiの「基地」) |
| SSID | ネットワークの名前。Wi-Fiの一覧から選ぶもの |
| BSSID | APのMACアドレス。APを一意に識別する |
| PSK | 事前共有鍵。家庭ネットワークでみんなが共有するWi-Fiのパスワード |
| ハンドシェイク | クライアントとAPが鍵を知っていると証明し、暗号化を準備するやりとり |
| CCMP / AES | WPA2/WPA3でWi-Fiのデータに使う暗号 |
| 管理フレーム | 接続・切断・ビーコンなど、実データとは別の制御メッセージ |
| PMF | Protected Management Frames。その制御メッセージを保護するしくみ |
| エビルツイン | 本物のネットワークの名前をまねてクライアントを誘い込む偽のAP |

## 1. Wi-Fiはどう構成されているか

IEEE 802.11(「Wi-Fi」)は、**ステーション**(STA、あなたの機器)を**アクセスポイント**(AP)につなぐ。ネットワークの名前が**SSID**で、各APはそのMACアドレス、すなわち**BSSID**で一意に識別される。複数のAPが1つのSSIDを共有すれば、途切れずに移動(ローミング)できる。

```
  ┌────────────── Wi-Fiネットワーク: SSID "CORP" ──────────────┐
  │   AP1                        AP2                            │
  │    ↑↑↑                        ↑↑↑                           │
  │  スマホ、ノートPC           ノートPC                        │
  └─────────────────────────────────────────────────────────────┘
          │
          └── 有線接続 ──► LAN / インターネット
```

Wi-Fiのトラフィックは3種類のフレームに分かれる。

| フレームの種類 | 役割 | 例 |
|:---|:---|:---|
| データ | 実際のトラフィックを運ぶ | Webページ、動画 |
| 制御 | 電波を分け合うのを助ける | 確認応答(ACK) |
| 管理 | 参加と発見 | ビーコン、接続、切断 |

ひとつ腹に落とすべきこと: **Wi-Fiは電波なので、近くにいる誰もがそれを聞ける。** 壁は当てにならない。機密性と完全性は、そのネットワークが使うリンク層のセキュリティからしか得られない。それがこの教材の残りの主題だ。

## 2. Wi-Fiのセキュリティはどう育ってきたか

Wi-Fiのセキュリティは、はっきりした世代を追って良くなってきた。選べるなら、自分の機器が対応する最新のものを選ぶこと。

| 世代 | 使うもの | 使ってよいか? |
|:---|:---|:---|
| オープン | 暗号化なし | キャプティブポータル + アプリ層のHTTPSと併用する場合だけ |
| WEP | 古くて破られた暗号 | 絶対に使わない。何十年も前に破られている |
| WPA(TKIP) | 過渡期のもの | 避ける。レガシー |
| WPA2-Personal | 共有パスワード + AES | まだ一般的。パスワードの強さまでしか強くない |
| WPA2-Enterprise | 802.1Xによるユーザーごとのログイン | 事務所の標準 |
| WPA3-Personal | 現代的なパスワードのやりとり(SAE) | 推奨。オフラインの推測に強い |
| WPA3-Enterprise | ユーザーごとのログイン、より強い暗号 | 高い保証 |

実践的なルール: 使えるならWPA3、最低でも強いパスワードのWPA2、WEPやTKIPは絶対に使わない。

## 3. WPA2: 鍵と4ウェイハンドシェイク

WPA2のハンドシェイクのねらいは、共有パスワードを接続ごとに**新しくて一意なセッション鍵**に変え、両者がパスワードを知っていることを確かめることだ。しかもそのすべてを、**パスワードを一度も電波に乗せずに**行う。

鍵は層になって組み上がる。

- **PMK**(マスター鍵): 家庭ネットワークでは、Wi-Fiのパスワードとネットワーク名を混ぜて作る。企業Wi-Fiでは、ユーザーごとのログインから作る。
- **PTK**(セッション鍵): PMKに、両者からの新しい乱数(**ノンス**)とMACアドレスを加えて導出する。ノンスが毎回新しいので、セッション鍵は接続ごとに異なる。
- **GTK**(グループ鍵): ブロードキャスト用に、APが全クライアントと共有する。

### 4ウェイハンドシェイク

```
  AP                                         STA(クライアント)
   │  1. 私の乱数だ(ANonce)                  │
   │─────────────────────────────────────────►│  (クライアントはPTKを計算できる)
   │  2. こちらの乱数(SNonce)+ 証明           │
   │◄─────────────────────────────────────────│  (APがPTKを計算し、証明を確認)
   │  3. グループ鍵 + 証明 +「インストールを」 │
   │─────────────────────────────────────────►│
   │  4. 了解                                  │
   │◄─────────────────────────────────────────│
   │     以降データは鍵で暗号化される          │
```

各側が**同じ**セッション鍵を導いたことを証明する。それは両者が本当にパスワードを知っているときにしかできない。パスワードそのものは誰も送らない。

家庭Wi-Fiの落とし穴: このセキュリティはすべて**パスワードの強さ**に乗っている。短い、またはありふれたパスワードは、ハンドシェイクを捕まえた者にオフラインで推測されうる。(この教材はそのクラッキングのやり方は扱わない。)対策は、長いランダムなパスワード、できればWPA3かEnterpriseだ。

## 4. WPA3: より良いパスワードのやりとり

WPA3-Personalは、ハンドシェイクを**SAE**(Simultaneous Authentication of Equals。Dragonflyという方式に基づく)に置き換える。重要な違いは、両者がパスワードを知っていることを生のやりとりで証明し、しかも**盗聴者にオフラインで試せるものを何も渡さない**ことだ。

| 性質 | あなたにとっての意味 |
|:---|:---|
| 安上がりなオフライン推測がない | やりとりを捕まえても、攻撃者が自分のマシンでパスワードを総当たりすることはできなくなる |
| 推測はオンラインのみ | 攻撃者は生きたAPに対して推測するしかなく、APはそれをレート制限できる |

SAEでも、そこそこのパスワードは必要だ(オンラインの推測を絶望的に保つため)。また、WPA2+WPA3を混在させる「移行モード」は、古い機器がネットワークをWPA2に引き下げると弱くなりうる。組織にとっては、EAP-TLS(ユーザーごとの証明書)を使うEnterpriseが依然として最高の基準だ。SAEは本物の改善であって、`password123` を使ってよい言い訳ではない。

## 5. 認証解除(deauth)とそのリスク

歴史的に、機器に切断を指示する管理フレーム(「deauth」)は**何の保護もなく**送られていた。つまり電波の届く範囲にいる者が切断を偽造し、機器をネットワークから叩き落とせる。それ自体がサービス妨害だ。機器は落ち、再接続しなければならない。

より大きな危険は、その後に起きうることだ。切断された機器は、よく似たネットワーク、すなわち**エビルツイン**に自動で再接続してしまうことがある。同じSSIDを放送してクライアントを誘い込み、認証情報を奪う偽のAPだ。

防御は**Protected Management Frames(PMF / 802.11w)**で、これらの制御メッセージを認証し、偽の切断を拒否する。PMFは**WPA3では必須**だ。ほかに役立つもの: 利用者の意識、そしてEnterprise Wi-Fiでのサーバー証明書の検証。

> この教材は概念と防御を説明するもので、フレームの注入やジャミング攻撃のやり方ではない。

突然の大量切断の波は、可用性のインシデントとして扱う。APのログを確認し、近くのRFの変化を探し、PMFが強制されているか確かめること。

## 6. 防御と監視

| 対策 | 目的 |
|:---|:---|
| WPA3 / PMF必須 | 古典的なdeauth攻撃を防ぎ、パスワードベースのWi-Fiを強くする |
| 802.1X + EAP-TLS | 機器/ユーザーごとの識別、セッションごとに新しい鍵 |
| WEP / TKIPを無効化 | 破られた暗号を取り除く |
| 強く一意なパスワード(PSKを使うなら) | 高いエントロピー。定期的にローテーション |
| クライアント分離 | Wi-Fiのクライアントどうしが届かないようにする |
| ゲストSSIDと職員SSIDを分ける | ゲストネットワークを内部からファイアウォールで隔てる |
| 不正AP検出 | 自分のチャネル上の見知らぬ、または似たネットワークを見つける |
| WPS PINを無効化 | パスワードを復元する弱い手段を取り除く |

検出のアイデア: 予期しないBSSIDから自分のSSIDを広告する2つ目のビーコン(エビルツインの可能性)、自分のネットワークのキャプチャでの切断の急増、認証失敗の急増。

## 7. セキュリティノート

| 問題 | リスク | 防御 |
|:---|:---|:---|
| 弱いパスワード | リンク全体の機密性が崩れる | 長いランダムなパスワード、またはWPA3 / Enterprise |
| レガシーなWEP / TKIP | 簡単に破られる | AES(CCMP/GCMP)だけを強制する |
| 保護されない管理フレーム | deauthによるサービス妨害 | PMF / WPA3 |
| 平らなWi-Fi + LAN | 参加後の横移動 | クライアント分離 + ネットワークアクセス制御 |
| エビルツイン | 認証情報のフィッシング | 利用者の意識、EAPサーバー証明書の検証 |
| 弱いIoTのWi-Fi | ネットワークへの柔らかい入口 | IoT用に別のSSID / VLAN |

ラボの衛生: 許可されているAPと電波空間だけを監査すること。トラブルシューティングのキャプチャは自分のネットワークで行い、隣人のものでは決してしない。

## 8. チートシート

```bash
# ── 自分のリンク状態(Linux) ─────────────────────────────────
iw dev                         # 自分の無線インターフェース
iw dev wlan0 link              # 現在のBSSID、周波数、信号
iw dev wlan0 info

# ── 近くのネットワークを調べる(自分の無線での観察) ─────────
sudo iw dev wlan0 scan | egrep 'BSS|SSID|RSN|signal'

# ── NetworkManager ───────────────────────────────────────────
nmcli device wifi list
nmcli connection show

# ── 規制 / チャネル情報 ──────────────────────────────────────
iw reg get

# ── 自分が運用するAPでは、次の設定を優先する ────────────────
# クライアントが対応するならWPA3(SAE)、そうでなければWPA2 + 強いパスワード
# PMF必須(ieee80211w=2)、AES/CCMPのみ、WPS PINは無効
```

| コマンド | 用途 |
|:---|:---|
| `iw … link` | 自分のBSSID、周波数、信号を表示する |
| `iw … scan` | 近くのネットワークを調べる(現地の法律に従う) |
| `nmcli device wifi` | デスクトップでWi-Fiプロファイルを管理する |
