## 1. IPv4とIPv6

IPアドレスは、パケットをネットワーク間でルーティングできるようにするための、ネットワーク層（OSIのL3、TCP/IPのインターネット層）における論理的な識別子である。

| 特性 | IPv4 | IPv6 |
|:---|:---|:---|
| 長さ | 32ビット（4オクテット） | 128ビット |
| 表記 | ドット付き10進数 `192.168.1.1` | 16進数 `2001:db8::1` |
| アドレス空間 | 2³² ≈ 4.29 × 10⁹ | 2¹²⁸ ≈ 3.4 × 10³⁸ |
| ヘッダー | 20〜60バイト（オプション含む） | 40バイト固定 + 拡張ヘッダー |
| 設定方法 | 手動 / DHCP | SLAAC / DHCPv6 |
| ブロードキャスト | あり | なし（マルチキャスト/エニーキャストで代替） |

IPv4アドレスの枯渇は、CIDR、NAT、そして最終的にIPv6の採用を後押しした。セキュリティ関連のツールは両方のスタックを理解しておく必要があり、デュアルスタックのホストや、管理者が見落としがちなIPv6側の露出にも注意しなければならない。

## 2. 2進数表現とマスクの計算

### 2.1 オクテット

1オクテットは 8 ビットであり、値の範囲は 0..255 である。

```text
ビット: b7   b6   b5   b4   b3   b2   b1   b0
値:    128   64   32   16    8    4    2    1
```

10進数の値は、1になっているビットの値を足せば求まる。`11000000` なら 128 + 64 = 192 だ。

例: `192` = `11000000`、`168` = `10101000`。

### 2.2 ネットワークマスク

プレフィックス長 p（CIDR表記の `/p`）は、左から p ビットが **ネットワーク** 部分であり、残りの h=32-p ビットが **ホスト** 部分であることを意味する（IPv4の場合）。

```text
マスク = 1 が p 個、続いて 0 が (32 - p) 個

/24  →  11111111.11111111.11111111.00000000  =  255.255.255.0
```

基本となる演算:

```text
ネットワークアドレス = アドレス AND マスク        (ホスト部をすべて0に)
ブロードキャスト     = アドレス OR (NOT マスク)   (ホスト部をすべて1に)
ホスト部             = アドレス AND (NOT マスク)

例 192.168.1.77/26:  ネットワーク = 192.168.1.64、ブロードキャスト = 192.168.1.127
```

2つのアドレス A,B が同一サブネットに属するのは、次の条件が成り立つときに限る。

```text
(A AND mask) = (B AND mask)
```

つまり、2つのアドレスから同じネットワークアドレスが得られるということだ。

## 3. CIDRの基本公式

IPv4のプレフィックス `/p`（0 ≤ p ≤ 32）を考え、h = 32 - p とする。

| 量 | 公式 |
|:---|:---|
| ブロックサイズ（総アドレス数） | N = 2ʰ = 2³²⁻ᵖ |
| 利用可能なホスト数（一般的なサブネット） | N_usable = 2ʰ - 2（ただしRFC 3021によるポイントツーポイント用の`/31`と、ホストルートとしての`/32`は例外） |
| 親ブロックから n ビットを借用したときのサブネット数 | 2ⁿ |
| 10進表記のサブネットマスク | mask(p) を4オクテットに変換したもの |
| サブネット間の増分（stride） | 該当するオクテットにおける 2ʰ |

**マスク早見表:**

| プレフィックス | マスク | h | 総数 | 利用可能数 |
|:---:|:---|:---:|:---:|:---:|
| /8 | 255.0.0.0 | 24 | 16,777,216 | 16,777,214 |
| /16 | 255.255.0.0 | 16 | 65,536 | 65,534 |
| /24 | 255.255.255.0 | 8 | 256 | 254 |
| /25 | 255.255.255.128 | 7 | 128 | 126 |
| /26 | 255.255.255.192 | 6 | 64 | 62 |
| /27 | 255.255.255.224 | 5 | 32 | 30 |
| /28 | 255.255.255.240 | 4 | 16 | 14 |
| /30 | 255.255.255.252 | 2 | 4 | 2 |
| /32 | 255.255.255.255 | 0 | 1 | 1（ホスト） |

### VLSM（可変長サブネットマスク）

VLSMでは、均一でないサイズのブロックを割り当てる。アクセス用ネットワークには大きなサブネットを、ルーター間リンクには`/30`や`/31`を割り当てる、といった具合である。条件として、ブロック同士が重複してはならず、2ʰ の境界に整列（アライン）していなければならない。

手順:

1. ホスト数の要件を大きい順に並べる。
2. 必要なホスト数 H に対して、2ʰ-2 ≥ H を満たす最小の h を選ぶ（ポイントツーポイントリンクのような特殊なケースでは 2ʰ ≥ H）。
3. まだ空いていて、かつアラインされている次のプレフィックスを割り当てる。

## 4. 計算例: `192.168.1.0/26`

```text
プレフィックス p = 26   →   ホストビット h = 32 - 26 = 6
全アドレス数    = 2⁶ = 64
使えるホスト数  = 64 - 2 = 62   (ネットワークアドレスとブロードキャストアドレスを除く)
```

マスク: `255.255.255.192`（`11111111.11111111.11111111.11000000`）。

`192.168.1.0/24` を `/26` のブロックに分割すると、n=2 ビットを借用することになり、2²=4 個のサブネットが得られる。

| # | ネットワーク | 利用可能範囲 | ブロードキャスト |
|:---:|:---|:---|:---|
| 0 | 192.168.1.0/26 | .1 – .62 | .63 |
| 1 | 192.168.1.64/26 | .65 – .126 | .127 |
| 2 | 192.168.1.128/26 | .129 – .190 | .191 |
| 3 | 192.168.1.192/26 | .193 – .254 | .255 |

アライン確認: ネットワークアドレスの最後のオクテットは64で割り切れる必要がある。

常に成り立つ規則: `broadcast = network + size - 1` であり、次のサブネットは `network + size` から始まる。

## 5. RFC 1918と特殊アドレス

```
┌────────────────────────────────────────────────────────────┐
│ RFC 1918 PRIVATE BLOCKS                                    │
│  10.0.0.0/8        (10.0.0.0 – 10.255.255.255)             │
│  172.16.0.0/12     (172.16.0.0 – 172.31.255.255)           │
│  192.168.0.0/16    (192.168.0.0 – 192.168.255.255)         │
├────────────────────────────────────────────────────────────┤
│ SPECIAL                                                    │
│  127.0.0.0/8       loopback                                │
│  169.254.0.0/16    link-local (APIPA)                      │
│  224.0.0.0/4       IPv4 multicast                          │
│  0.0.0.0/8         "this network" / unspecified            │
│  100.64.0.0/10     CGNAT (RFC 6598)                        │
└────────────────────────────────────────────────────────────┘
```

プライベートアドレスはグローバルに一意ではなく、組織間で重複してもよい。インターネットへの到達性が必要な場合は、NATまたはパブリックなデュアルスタックアドレスが必要になる。

## 6. ルーティング: 最長プレフィックスマッチ

ルーターは、宛先にマッチするプレフィックスのうち最も長いものを選ぶ。

例: D= `192.168.1.10` について、ルーティングテーブルに `192.168.0.0/16` 経由Aと `192.168.1.0/24` 経由Bの両方が存在する場合、より具体的な `/24` の経路が選ばれる。

デフォルトルート: IPv4では `0.0.0.0/0`、IPv6では `::/0`。

## 7. NATとPAT

NAT（Network Address Translation）は、ネットワークの境界、多くの場合プライベートアドレス空間とパブリックアドレス空間の間でアドレスを変換する。

| 種類 | マッピング | 用途 |
|:---|:---|:---|
| Static NAT | 固定の1対1 | 安定したパブリックIPが必要なサーバー |
| Dynamic NAT | パブリックのアドレスプールから割り当て | SOHO環境で単体で使われることは少ない |
| PAT / オーバーロード | ポート単位でのmany対1 | 一般的な家庭・オフィスの構成 |

PATの直感的なモデル:

```text
(プライベートIP, プライベートポート, 宛先IP, 宛先ポート, プロトコル)  ⇄  (グローバルIP, 新しいポート SPORT', 宛先IP, 宛先ポート, プロトコル)
```

NAT機器のステートテーブルは SPORT' を記憶しており、応答パケットを正しいプライベートホストへ戻せるようにしている。

セキュリティ上の含意: NATはファイアウォールではない。ネットワークにはステートフルなフィルタリング、リバースプロキシ、追加のハードニングが依然として必要である。またNATはVoIPやIPsecのようなエンドツーエンド通信を複雑にする。IPv6はホスト間の直接的なアドレス到達性を取り戻すため、セキュリティ設計もそれに合わせて調整する必要がある。

NATはトラブルシューティングやアーキテクチャ検討のために理解しておくべきものであり、それ単体をアクセス制御の仕組みとして扱ってはならない。

## 8. ICMPと診断

### Ping

- IPv4: Echo RequestはType 8、Echo ReplyはType 0。
- Pingはスループットではなく、到達性とサンプリングされたRTTを計測する。

**TTL / Hop Limitの経験則**（大まかな目安であり、管理者が変更可能）:

| 観測される初期TTL | OSの推定 |
|:---:|:---|
| 約64 | 多くのLinux/Unix |
| 約128 | 多くのWindows |
| 約255 | 多くのネットワーク機器 |

### Traceroute

Tracerouteは TTL=1,2,3,... と増加させながらパケットを順に送信する。TTLが0になった各ホップはICMP Time Exceeded（Type 11）で応答する。これらの応答を連ねることで、ホップごとの経路を再構築できるが、経路は非対称であったり、一部がフィルタされていたりすることもある。

## 9. セキュリティノート

| 課題 | リスク | 防御策 |
|:---|:---|:---|
| IPスプーフィング | パケットの送信元を偽装し、しばしばリフレクション攻撃に使われる | uRPF、ingress/egress ACL、BCP38 |
| L3が過度にフラットである | ホストが1台侵害されると横方向への移動が容易になる | VLAN/サブネットによるセグメンテーションとeast-westファイアウォール |
| 管理インターフェースの露出 | SSH/RDPが一般ユーザーのセグメント上にある | 管理専用のVRF/VLANを分離する |
| 見落とされたIPv6（Shadow IPv6） | 監視されていないデュアルスタックホスト | IPv6のインベントリ管理、RA Guard |
| ICMPポリシーが過度に開放的 | 偵察や悪用の材料になる | レート制限を行い、ICMPを一律にすべてブロックしない（PMTUDにはType 3 Code 4が必要） |

ラボでの心得: ルーティングやファイアウォールの実験を行う前に、自分が所有するマシンでインターフェースと経路を把握しておく（`ip addr`、`ip route`）。プレフィックスの設定ミスは、障害の原因としてよくあるものである。

## 10. チートシート

### CIDRの暗算

- `/24` → 256アドレス、最後のオクテットでのstrideは1
- `/25` → 128アドレス、strideは128
- `/26` → 64アドレス、strideは64
- `/27` → 32アドレス、strideは32
- `/28` → 16アドレス、strideは16
- `/30` → 4アドレス、strideは4（ポイントツーポイントリンクで典型的）

```bash
# ── Inspection (your host) ────────────────────────────────────
ip -c addr show
ip route show
ip -4 route get 1.1.1.1
ip neighbor show

# ── Diagnostics ──────────────────────────────────────────────
ping -c 4 1.1.1.1
traceroute -n 1.1.1.1
mtr -n 1.1.1.1

# ── Subnet calculator helpers ────────────────────────────────
ipcalc 192.168.1.0/26          # if installed
python3 -c "import ipaddress as i; n=i.ip_network('192.168.1.0/26');
print(n.network_address, n.broadcast_address, n.num_addresses)"
```
