## 重要な用語

この教材でよく出てくる言葉である。

| 用語 | 意味 |
|:---|:---|
| IPアドレス | ネットワーク上の機器の論理アドレス。たとえば `192.168.1.10` |
| オクテット | IPv4アドレスの4つの数字の1つ(それぞれ8ビット、0〜255) |
| サブネット | 大きなネットワークから切り出した、より小さな区画 |
| サブネットマスク | アドレスのどこまでが「ネットワーク部」でどこからが「ホスト部」かを示す目印 |
| CIDR `/n` | マスクの短い書き方。`/24` は先頭24ビットがネットワーク部という意味 |
| ネットワークアドレス | サブネットの最初のアドレス。サブネットそのものを指す |
| ブロードキャストアドレス | サブネットの最後のアドレス。その中の全員宛てのメッセージ |
| ゲートウェイ | 宛先が別のネットワークにあるとき、機器が送る先のルーター |
| NAT | 多数のプライベート機器が1つのグローバルIPアドレスを共有すること |
| プライベートアドレス | `192.168.x.x` のような、ローカルネットワーク内でだけ使えるアドレス。公開インターネットでは使えない |

## 1. IPv4 と IPv6

**IPアドレス**は、機器がネットワーク上で使う論理的な名前だ(OSI第3層)。パケットをあるネットワークから別のネットワークへ届けられるのは、これがあるからだ。

| | IPv4 | IPv6 |
|:---|:---|:---|
| 長さ | 32ビット | 128ビット |
| 見た目 | `192.168.1.1` | `2001:db8::1` |
| アドレスの数 | 約43億 | 約3.4 × 10³⁸(事実上無尽蔵) |
| 設定 | 手動またはDHCP | 自動(SLAAC)またはDHCPv6 |
| ブロードキャスト | あり | なし(マルチキャストを使う) |

IPv4は単純にアドレスが足りなくなり、そこでNAT(第7節)、そして最終的にIPv6が登場した。セキュリティのツールは両方を理解する必要がある。1台の機器が**両方を同時に**持つこと(デュアルスタック)が多く、見張られていないIPv6アドレスは見落としやすいからだ。

## 2. アドレスを2進数で読む

IPv4アドレスの4つの数字(各**オクテット**)は、実は8ビットだ。各ビットは1つの値を表す。

```text
ビット:   b7   b6   b5   b4   b3   b2   b1   b0
値:      128   64   32   16    8    4    2    1
```

ビットを10進数に直すには、ビットが1になっている位置の値を足す。

```text
11000000  →  128 + 64            = 192
10101000  →  128 +    32 + 8     = 168
```

つまり `11000000.10101000.00000001.00000001` は `192.168.1.1` にすぎない。サブネット化とは、この32ビットのどこに線を引くか、という話だ。

## 3. サブネットマスクとCIDR

アドレスには2つの部分がある。**ネットワーク部**(自分はどのネットワークにいるか)と**ホスト部**(自分はどの機器か)だ。**サブネットマスク**がその境目を示す。CIDR表記では、`/n` は「先頭 n ビットがネットワーク部、残りがホスト部」という意味だ。

```text
/24  →  11111111.11111111.11111111.00000000  =  255.255.255.0
        └──── 24ビットのネットワーク部 ────┘└ 8ビットのホスト部 ┘
```

マスクから、サブネットの3つの重要なアドレスが分かる。

```text
ネットワークアドレス = いちばん低いアドレス(ホスト部がすべて0)  → サブネットを指す
ブロードキャスト     = いちばん高いアドレス(ホスト部がすべて1)  → 「ここにいる全員」
使えるホスト         = その間のすべて

例、192.168.1.0/24:
  ネットワーク   = 192.168.1.0
  ブロードキャスト = 192.168.1.255
  使える範囲     = 192.168.1.1  …  192.168.1.254   (254台)
```

2つのアドレスが**同じサブネット**にあるのは、ネットワーク部が同じときだけだ。それがまさに、あなたのコンピュータが別の機器と直接話すのか、それともゲートウェイ経由で送るのかを決める。

### マスク早見表

| CIDR | マスク | ホストビット | 全アドレス数 | 使える機器数 |
|:---:|:---|:---:|:---:|:---:|
| /24 | 255.255.255.0 | 8 | 256 | 254 |
| /25 | 255.255.255.128 | 7 | 128 | 126 |
| /26 | 255.255.255.192 | 6 | 64 | 62 |
| /27 | 255.255.255.224 | 5 | 32 | 30 |
| /28 | 255.255.255.240 | 4 | 16 | 14 |
| /30 | 255.255.255.252 | 2 | 4 | 2 |

パターン: ホスト部のビットが1つ増えるごとに、アドレス数は**2倍**になる。「使える」数が常に2少ないのは、ネットワークアドレスとブロードキャストアドレスを機器に割り当てられないからだ。(使えるホストが2つの `/30` は、2台のルーター間のリンクの定番だ。)

## 4. 例: ネットワークを分割する

`192.168.1.0/24`(256アドレス)を持っていて、**4つの同じ大きさのサブネット**に分けたいとしよう。

4つに分けるにはホスト部からもう2ビット借りる(2² = 4 だから)。これで `/24` が `/26` になる。各 `/26` は64アドレスだ。

| # | ネットワーク | 使える範囲 | ブロードキャスト |
|:---:|:---|:---|:---|
| 1 | 192.168.1.0/26 | .1 – .62 | .63 |
| 2 | 192.168.1.64/26 | .65 – .126 | .127 |
| 3 | 192.168.1.128/26 | .129 – .190 | .191 |
| 4 | 192.168.1.192/26 | .193 – .254 | .255 |

2つのルールで頭の中でも計算しやすくなる。

- 各サブネットは幅64なので、ネットワークは64ずつ進む: `.0, .64, .128, .192`。
- ブロードキャストは常に `次のネットワーク − 1`。

サブネットごとに必要な大きさが違うとき(大きな事務所LAN、アドレス2個の小さなルーターリンクなど)は、大きいものから順に、重ならないように、収まる最小のサブネットを割り当てる。これを**VLSM**(可変長サブネットマスク)という。

## 5. プライベートアドレスと特別なアドレス

いくつかの範囲は、ローカルネットワーク内で使うために予約されている。これらは世界で一意ではないので、公開インターネットにそのまま現れることはできず、NAT(第7節)を通じてインターネットに届く。

```
┌────────────────────────────────────────────────────────────┐
│ プライベート(RFC 1918) — 自分のネットワーク内で自由に使える │
│  10.0.0.0/8        10.0.0.0     – 10.255.255.255           │
│  172.16.0.0/12     172.16.0.0   – 172.31.255.255           │
│  192.168.0.0/16    192.168.0.0  – 192.168.255.255          │
├────────────────────────────────────────────────────────────┤
│ 特別                                                       │
│  127.0.0.0/8       ループバック(「このマシン」)           │
│  169.254.0.0/16    リンクローカル(DHCP失敗時に現れる)     │
│  224.0.0.0/4       マルチキャスト                          │
└────────────────────────────────────────────────────────────┘
```

機器に `169.254.x.x` のアドレスが見えたら、それは役立つ手がかりだ。たいていDHCPが応答せず、機器が自分でアドレスを選んだことを意味する。

## 6. ルーターが経路を選ぶ仕組み

ルーターは、1つの宛先に合いそうな経路を複数知っていることがある。ルールは単純で、**いちばん具体的なものが勝つ**(ロンゲストプレフィックスマッチ)。

```text
宛先: 192.168.1.10

経路A: 192.168.0.0/16  via ルーターX   (広い: /16 全体)
経路B: 192.168.1.0/24  via ルーターY   (具体的: この /24 だけ)

→ ルーターはBを選ぶ。/24 のほうが /16 より具体的だから
```

何も当てはまらなければ、トラフィックは**デフォルトルート** `0.0.0.0/0`(IPv6では `::/0`)に落ちる。あなたのマシンがゲートウェイ経由で広いインターネットに届くのは、これのおかげだ。

## 7. NAT: 1つのグローバルアドレスを共有する

家にはグローバルIPが1つしかないのに、機器はたくさんある。**NAT**(ネットワークアドレス変換)は、それらすべてでそのIPを共有させる。ルーターは、外向きトラフィックのプライベートな送信元アドレスを自分のグローバルアドレスに書き換え、どの会話がどの内部機器のものかを(ポート番号を追って)覚えておく。だから返信が正しい機器に戻ってくる。

```text
ノートPC 192.168.1.10:51000  →  ルーター  →  グローバル 203.0.113.5:62000  →  インターネット
                                   (対応を覚えておく)
返信 ←──────────────────────────── ルーター  ←─────────────────────────────────  返信
```

| 種類 | 役割 |
|:---|:---|
| 静的NAT | 固定の1対1変換。安定したグローバルIPが必要なサーバー向け |
| PAT /「オーバーロード」 | 1つのグローバルIPの後ろに多数の機器(普通の家庭・オフィスの構成) |

重要なセキュリティポイント: **NATはファイアウォールではない。** NATは副作用として内部アドレスを隠すが、何を許可するかは決めない。本物のフィルタリングは別途必要だ。IPv6はNATを使わないことが多い(アドレスが十分にある)ので、「NATがあるから守られている」と思い込まないこと。

## 8. ICMP、ping、traceroute

**ICMP**は、ネットワーク層の使者のようなプロトコルだ。到達性の確認やエラー報告を運ぶ。

**ping**はICMPの「そこにいる?」を送り、返事を待つ。ホストに届くかどうかと、往復におよそどれくらいかかるかが分かるだけで、それ以上ではない。

返事の**TTL**は、相手のシステムの大まかなヒントになる(あくまでデフォルト値で、変更できる)。

| 見えたTTL | 可能性の高いシステム |
|:---:|:---|
| 約64 | Linux / Unix / macOS |
| 約128 | Windows |
| 約255 | ネットワーク機器(ルーター、スイッチ) |

**traceroute**はTTLの巧みな使い方だ。TTL = 1、次に2、次に3…とパケットを送る。TTLが0になってパケットを捨てた各ルーターが報告を返すので、経路が1ホップずつ分かる。

```bash
ping -c 4 1.1.1.1      # 届くか? 往復時間は?
traceroute -n 1.1.1.1  # どの経路を通るか?
```

## 9. セキュリティノート

| 問題 | リスク | 防御 |
|:---|:---|:---|
| IPスプーフィング | 送信元を偽り、身を隠したり他人を踏み台にしたりする | 入口での送信元フィルタ(BCP38 / uRPF) |
| 1つの大きく平らなネットワーク | 1台が乗っ取られると、攻撃者がすべてに簡単に届く | サブネット/VLANに分け、間でフィルタする |
| 管理経路の露出 | SSH/RDPが通常の利用者ネットワークにある | 管理用のサブネットを分ける |
| 忘れられたIPv6 | v6で誰も監視していないデュアルスタックの機器 | IPv6も棚卸しする。RA Guard |
| ICMPを全部ブロック | 役立つ診断や経路MTU探索が壊れる | 全面ブロックではなくレート制限 |

ラボの衛生: 何かを変える前に、自分のインターフェースと経路を確認する(`ip addr`、`ip route`)。サブネットマスクや経路の誤りは、障害の最も多い原因の1つだ。

## 10. チートシート

### 頭の中での計算

- `/24` → 256アドレス、最後のオクテットで1ずつ進む
- `/25` → 128アドレス、128ずつ
- `/26` → 64アドレス、64ずつ
- `/27` → 32アドレス、32ずつ
- `/28` → 16アドレス、16ずつ
- `/30` → 4アドレス(使えるのは2)、ルーター間リンクの定番

```bash
# ── 自分のマシンを調べる ─────────────────────────────────────
ip -c addr show
ip route show
ip -4 route get 1.1.1.1    # どの経路/ゲートウェイが使われるか?
ip neighbor show

# ── 診断 ─────────────────────────────────────────────────────
ping -c 4 1.1.1.1
traceroute -n 1.1.1.1
mtr -n 1.1.1.1             # リアルタイムで連続する traceroute

# ── サブネット計算 ───────────────────────────────────────────
ipcalc 192.168.1.0/26       # インストールされていれば
python3 -c "import ipaddress as i; n=i.ip_network('192.168.1.0/26'); \
print(n.network_address, n.broadcast_address, n.num_addresses)"
```
