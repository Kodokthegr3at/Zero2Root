## 1. OSINTとは何か（そして何でないか）

OSINT（Open Source Intelligence）とは、公開されており合法的にアクセスできる情報から収集されたインテリジェンスを、実際に行動につなげられる洞察へと処理したものである。

```text
収集(合法な公開情報源) → 処理 → 分析 → 結果を共有
```

| OSINTに含まれるもの | OSINTではないもの |
|:---|:---|
| ニュース、公式サイト、開示資料 | 許可のないアカウントへのアクセス |
| 公開されているメタデータ | データ取得のためのハッキングやフィッシング |
| 公開されている衛星画像/地図 | 盗んだ認証情報でのペイウォール突破 |
| 公開された投稿 | ドキシングや嫌がらせ |

OSINTの質を決めるのは「秘密のツール」の有無ではなく、トレードクラフトである。明確な問い、情報源に対する批判的検証、相関分析、そして文書化がそれにあたる。ツールは変わっていくが、インテリジェンスサイクル自体は変わらない。

## 2. インテリジェンスサイクル

```
        ┌──────────── Direction / Requirements ────────────┐
        │                                                  │
        ▼                                                  │
   Collection ──▶ Processing ──▶ Analysis ──▶ Dissemination ┘
        ▲                         │
        └────── Feedback / gaps ──┘
```

| フェーズ | 鍵となる問い | 成果物 |
|:---|:---|:---|
| Direction | 何に答えるべきか。利用者は誰か | PIR（Priority Intelligence Requirements） |
| Collection | どの情報源が合法かつ関連性があるか | 生データ + provenance |
| Processing | どう正規化し保存するか | 構造化されたデータセット |
| Analysis | 何が意味を持ち、何がまだ不確かか | Assessment + confidence |
| Dissemination | 過大な主張をせずどう報告するか | レポート/ブリーフ |
| Feedback | まだ埋まっていない穴は何か | 新しいPIR |

### confidenceの言葉遣い（規律）

絶対的な言い切りは避ける。次のようなスケールを使う。

```text
確信度:  低  /  中  /  高
```

観測された事実と推論を明確に区別すること。

## 3. 計画と方向付け: 良い問いの立て方

悪いPIRの例: 「Xについてすべて調べろ」

良いPIRの例:

1. 組織 X は自前のASNや公開IPレンジを運用しているか。
2. WHOIS/CTログといった公開データによれば、ブランド X に関連するドメインはどれか。
3. 求人情報から技術スタックが読み取れるか（防御目的での技術的OSINT）。

良いPIR(優先情報要求)とは、実際に答えられ、期限があり、現実の意思決定に結びついているものだ。

収集計画: 情報源 → 手法 → 法的チェック → 保管 → 分析担当者、という流れで組み立てる。

## 4. 収集の規律（合法な情報源）

### 4.1 情報源のカテゴリ

| カテゴリ | 例 | 備考 |
|:---|:---|:---|
| Official | 規制当局、企業の開示資料、政府ポータル | 信頼性が高い。更新の有無を確認する |
| Media | ニュース、インタビュー | バイアスや誤りが含まれる可能性がある |
| Technical public | DNS、CTログ、公開BGP、公開パースト（ToSを確認） | レート制限に注意し、乱用しない |
| Social / UGC | 公開された投稿 | 文脈が失われやすいのでアーカイブしておく |
| Imagery | 地図、ストリートビュー、公開衛星画像 | 機微な場所については倫理面に注意 |
| Academic / papers | 会議録、プレプリント | バージョンを確認する |

### 4.2 Provenanceの記録（必須）

すべての証拠について、次を記録する。

```text
URL  |  時刻(UTC)  |  ハッシュ  |  収集者  |  使用ツール  |  メモ
```

Provenanceがなければ、分析結果は容易に疑義を呈される。

### 4.3 情報源への批判的検証

- 誰が書いたのか。どのような動機があるか。
- 一次情報か二次情報か。
- 独立した別の情報源と相関を取れるか。

## 5. 処理と分析

### 処理

- エンティティ（人物、組織、ドメイン、IP）の重複を排除する。
- タイムラインを構築する。
- 名前を正規化する（unicodeやホモグリフに注意）。
- 情報源の信頼性にタグを付ける。

### 分析パターン

| パターン | 説明 | 誤りのリスク |
|:---|:---|:---|
| Link analysis | エンティティ同士を結びつける | 誤った関連付け、同名異人 |
| Temporal | 出来事の順序 | タイムゾーンの取り違え |
| Geospatial | 地図や影、ランドマーク | 確証バイアス |
| Technical correlation | DNS ↔ 証明書 ↔ ホスティング | 共有ホスティングによるノイズ |

```
Raw captures
    │
    ▼
Structured entities (graph)
    │
    ▼
Hypotheses H1..Hn
    │
    ├─ corroborate
    └─ falsify
         │
         ▼
Assessment + confidence + gaps
```

### 出力テンプレート（概略）

1. BLUF（結論を先に）
2. Key judgments（主要な判断）
3. 証拠のまとめ（リンク/ハッシュ付き）
4. 検討した代替仮説
5. Gapsと次の収集計画

## 6. 検証スキルとしてのジオロケーション

OSINTにおけるジオロケーションとは、公開された写真や動画から場所の主張を検証することであり、嫌がらせ目的の追跡ではない。

### 概念的な技法（検証であって攻撃ではない）

| シグナル | 使い方 |
|:---|:---|
| ランドマーク | 建物のシルエットを公開地図と照合する |
| 看板/言語 | 国や都市の手がかりになる |
| 太陽/影 | 時刻や方角のおおまかな推定 |
| 植生/気候 | 地域的な整合性 |
| インフラ | 電柱、道路標示、左側通行か右側通行か |
| EXIF（存在する場合） | メタデータが残っており、かつ合法的にアクセスできる場合のみ |

位置の推定は、互いに独立した手がかりが少なくとも2つ一致したときにだけ確定とみなす。

倫理: 個人の自宅住所を公開してはならない。ドキシングをしてはならない。組織内のIR/DFIR業務では、組織のプライバシーポリシーに従うこと。

## 7. 調査者のためのOPSEC

調査者自身もターゲットになりうる（counter-OSINT）。

| リスク | 緩和策 |
|:---|:---|
| 実在の身元の漏洩 | 調査用の身元と私生活の身元を分離する |
| ブラウザのフィンガープリンティング | 別のプロファイルを使い、拡張機能を制限する |
| 位置情報の漏洩 | VPN/組織のポリシーを使い、個人アカウントと混在させない |
| 悪意あるドキュメント | サンドボックスで扱い、マクロを不用意に有効化しない |
| 対象側からの逆監視 | 証拠を無関係なプラットフォームにアップロードしない |

```
Personal life  ≠  Investigation workspace
     │                    │
   private            logged, policy-bound, legal
```

OPSECをひと言でいうと:

同じ身元、端末、支払い手段、言葉づかいの癖を複数の調査で使い回すほど、追跡されやすくなる。

コンテキストをまたいだ使い回しを最小限にすること。

## 8. ソックパペット: 倫理上の警告

ソックパペットとは、情報収集のために使われるペルソナアカウントである。多くのプロフェッショナルな文脈では次のように位置づけられる。

| 立場 | 見解 |
|:---|:---|
| 学術/趣味 | プラットフォームのToSに違反することが多い |
| 法執行機関/公的インテリジェンス | 厳格な方針と法律によって規律されている |
| バグバウンティ/ペンテスト | 明示的な許可がない限り通常はスコープ外 |
| ジャーナリズム | 倫理規定と現地の法律に拘束される |

### 強い警告

- 脆弱な個人を欺いたり、グルーミングや詐欺のためにペルソナを使ってはならない。
- 偽の身元を要求するログインの裏でデータを収集することが、法律やToSに反する場合は行ってはならない。
- 欺瞞的な認証を必要としない、真に公開された情報源を優先すること。
- 組織がペルソナの利用を許可している場合は、承認内容、制約、データ保持ポリシーを文書化すること。

この文書は、あるコミュニティに潜入するためのペルソナの作り方を教えるものではない。ここでの焦点は、それがなぜ法的・倫理的にリスクが高いのか、そしてそれへの依存をどう避けるかである。

## 9. 法的・倫理的な境界

| 境界 | 実務 |
|:---|:---|
| コンピュータアクセスに関する法律 | アクセス制御を回避しない |
| プライバシー（GDPR的な枠組み） | データを最小化し、目的を明確にし、保持期間を限定する |
| プラットフォームのToS | 過度な自動化は契約違反になりうる |
| 著作権 | 保護されたコンテンツを大量に再配布しない |
| 安全性 | ドキシングをしない。機微なPIIを公開しない |
| 職場 | RoE（活動規定）と法務の助言に従う |

倫理の簡易チェック:

```text
1. これが公開されても問題ないか?
2. 法廷で正当性を説明できるか?
3. 最も害の少ないやり方か?
```

いずれかに「いいえ」と答えるなら、そこで止まり、法務レビューを依頼すること。

## 10. ワークフローのチートシート

```text
1. PIRを書く（1〜3個の問い）
2. 法的チェック: 公開されているか。ToSは。管轄は。
3. provenance付きで収集する（URL、UTC、ハッシュ）
4. Process → entity graph + timeline
5. Analyze → judgments + confidence + alternatives
6. BLUFで報告し、gapsに印を付ける
7. データを削減し、保持ポリシーに従って保管する
8. 調査者自身のOPSECをレビューする
```

| ニーズ | 公開情報での収集方針（例） |
|:---|:---|
| ドメインの足跡 | 公開DNS履歴、CTログ |
| 組織構造 | 企業の開示資料、プレス、採用ページ |
| インフラのヒント | 求人情報、公開クラウドのドキュメント、ステータスページ |
| インシデントの文脈 | ベンダーのアドバイザリ、公開タイムライン |
| 画像の検証 | 地図 + ランドマークによる裏付け |

## セキュリティノート: 脅威と防御

| 脅威 | メカニズム | 防御 |
|:---|:---|:---|
| 調査者がドキシングされる | Counter-OSINT | ポリシーに基づくペルソナ/デバイスの分離 |
| 汚染された情報源 | 偽情報/偽のリーク | 複数情報源による裏付け |
| Overcollection | PIIの過剰な蓄積 | 最小化と保持ポリシー |
| ToS/法律違反 | 過度なスクレイピング | 手動または公開APIの利用、法務への相談 |
| バイアスの連鎖 | 見たいものだけを見てしまう | 自分の仮説をレッドチーム的に検証する |
| 安全でない取り扱い | 悪意あるファイル | サンドボックスでの分析 |

扱っていない内容: 盗んだ認証情報によるペイウォール突破、アカウントのハッキング、収集目的のマルウェア、ドキシングの手順書。
