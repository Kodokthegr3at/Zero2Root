## Key terms

| Term | Meaning |
|:---|:---|
| Active Directory (AD) | Microsoft's directory service that stores the users, computers, and rules of a Windows network |
| Domain | An administrative boundary in AD, such as `corp.local`. All members share one account database |
| Domain controller (DC) | A server that holds the AD database and checks logins |
| Forest | One or more domains that share a schema and trust each other |
| OU | Organizational Unit: a folder for grouping objects and attaching policies |
| GPO | Group Policy Object: a set of settings applied automatically to users or computers |
| LDAP | The protocol for reading and changing directory contents |
| Kerberos | The main login protocol in AD |
| SID | Security Identifier: a unique ID for every account or group |
| NTDS.dit | The AD database file on every domain controller |

## 1. Why Active Directory matters

Nearly every medium or large company that runs Windows manages its employee accounts with Active Directory. One AD account is used to sign in to laptops, email, file shares, VPN, and many internal applications.

That also makes AD a prime target. Once an attacker controls a Domain Admin account, they effectively control the whole network. Almost every major ransomware report contains a line like "the attackers obtained Domain Admin rights, then pushed ransomware through Group Policy".

| Role | Why you need to understand AD |
|:---|:---|
| SOC Analyst | Most Windows login and privilege alerts come from domain controllers |
| Pentester | Nearly every internal network test ends up in AD |
| Incident responder | Ransomware timelines usually move from one laptop to a domain controller |
| Sysadmin | A small AD misconfiguration can open a path to Domain Admin |

## 2. Domains, trees, and forests

```
  Forest: corp.local
  ┌────────────────────────────────────┐
  │             corp.local             │  ← root domain
  │            /          \            │
  │   jkt.corp.local   osk.corp.local  │  ← child domains (one tree)
  └────────────────────────────────────┘
                    │ trust
  ┌────────────────────────────────────┐
  │        Forest: partner.local       │  ← another forest
  └────────────────────────────────────┘
```

| Structure | Explanation |
|:---|:---|
| Domain | One account database and one DNS namespace, such as `corp.local` |
| Tree | A parent domain and child domains with contiguous names, such as `jkt.corp.local` under `corp.local` |
| Forest | One or more trees. The forest is the real security boundary |

The key point for security: **the domain is not a security boundary, the forest is.** An admin in a child domain can become admin of the whole forest. If two business units truly have to be separated, they need different forests.

## 3. Domain controllers and what they store

A domain controller is a Windows server with the AD DS (Active Directory Domain Services) role. There are usually at least two DCs so logins keep working if one fails. Changes on one DC are replicated to the others.

What a DC holds:

| Component | Location | Contents |
|:---|:---|:---|
| `NTDS.dit` | `C:\Windows\NTDS\` | The database of every object, including each user's password hash |
| SYSVOL | `C:\Windows\SYSVOL\` | Logon scripts and Group Policy files, readable by every domain user |
| DNS | DNS service on the DC | Records computers use to find a DC |
| KDC | Kerberos service | Issues login tickets |

Anyone who can copy `NTDS.dit` from a DC gets the password hashes of every user in the domain. That is why logon access to DCs, and to their backups, has to be tightly restricted.

Viewing DCs from a domain-joined computer:

```powershell
nltest /dclist:corp.local         # list domain controllers
echo %LOGONSERVER%                # the DC that handled your login (in cmd)
Get-ADDomainController -Filter *  # needs the RSAT ActiveDirectory module
```

## 4. Objects: users, groups, computers, OUs

Everything in AD is stored as an **object** with **attributes**.

| Object | Example attributes | Security note |
|:---|:---|:---|
| User | `sAMAccountName`, `memberOf`, `pwdLastSet`, `servicePrincipalName` | Accounts with an SPN deserve extra attention |
| Group | `member`, `groupType` | Groups can contain other groups, so membership can be nested |
| Computer | `dNSHostName`, `operatingSystem` | Every domain-joined computer also has its own account and password |
| OU | `gPLink` | Where GPOs are linked |
| GPO | `gPCFileSysPath` | Its contents live in SYSVOL |

An object's full name is written as a **distinguished name (DN)**:

```text
CN=Rina Putri,OU=Finance,OU=Jakarta,DC=corp,DC=local
```

Read it right to left: domain `corp.local`, OU Jakarta, OU Finance, then the user Rina Putri.

Viewing objects with PowerShell (RSAT ActiveDirectory module):

```powershell
Get-ADUser rina -Properties memberOf, pwdLastSet, lastLogonDate
Get-ADGroupMember "Domain Admins" -Recursive    # includes nested group members
Get-ADComputer -Filter * -Properties operatingSystem | Select Name, operatingSystem
```

Every domain user can read most of AD over LDAP. That is by design, but it means an attacker who has stolen one ordinary account can already map the whole domain.

## 5. Groups you need to know

| Group | Rights | Why it is dangerous if abused |
|:---|:---|:---|
| Domain Admins | Full admin of the domain | The main target |
| Enterprise Admins | Admin across the whole forest | Exists only in the root domain |
| Administrators (built-in) | Admin on domain controllers | Equivalent to Domain Admin |
| Account Operators | Can create and change most accounts | Often forgotten, and a known route to Domain Admin |
| Backup Operators | Can back up files on DCs, including `NTDS.dit` | A backup is a copy of every hash |
| Server Operators | Can log on to DCs and change services | Changing a service on a DC means running code as SYSTEM |
| DnsAdmins | Manages DNS on DCs | Has been abused to load a DLL into the DNS service |
| Group Policy Creator Owners | Creates new GPOs | GPOs can run scripts on many computers |
| Protected Users | A hardening group, not an admin group | Members cannot use NTLM or RC4 |

Rule of thumb: keep the members of the groups above to a minimum and review them regularly.

```powershell
"Domain Admins","Enterprise Admins","Administrators","Account Operators","Backup Operators","Server Operators" |
  ForEach-Object { "== $_"; Get-ADGroupMember $_ -Recursive | Select -Expand SamAccountName }
```

## 6. Group Policy

Group Policy applies settings to many computers at once: password policy, firewall, logon scripts, installed software, and more.

```
GPO "Laptop Policy"  ──link──►  OU=Laptops  ──contains──►  50 computers
```

Order of application (the last one wins): **Local → Site → Domain → parent OU → child OU**, abbreviated LSDOU.

| Command | Purpose |
|:---|:---|
| `gpupdate /force` | Make the computer fetch the latest policy |
| `gpresult /r` | Show which GPOs apply to this user and computer |
| `gpresult /h report.html` | Full report as HTML |

Two points to remember from a security angle:

1. **Anyone who can edit a GPO linked to many computers can run code on all of them.** Edit rights on a GPO are equivalent to admin rights on those computers.
2. **SYSVOL is readable by every domain user.** An old feature, Group Policy Preferences, stored passwords in XML files (`cpassword`) in SYSVOL, and Microsoft had published the key. The feature was closed by patch MS14-025, but old files sometimes remain. Searching SYSVOL for `cpassword` is one of the first checks in an audit.

```powershell
# Audit check: any leftover files containing cpassword?
findstr /S /I cpassword \\corp.local\SYSVOL\corp.local\Policies\*.xml
```

## 7. Protocols AD uses

| Protocol | Port | Purpose |
|:---|:---|:---|
| DNS | 53 | Computers find DCs through SRV records such as `_ldap._tcp.dc._msdcs.corp.local` |
| Kerberos | 88 | Logins and access tickets |
| LDAP / LDAPS | 389 / 636 | Reading and changing the directory |
| Global Catalog | 3268 / 3269 | Searching objects across the forest |
| SMB | 445 | SYSVOL access, file shares, remote administration |
| RPC | 135 + dynamic ports | Replication and many admin functions |
| NTLM | (inside SMB, HTTP, etc.) | The older login protocol, still enabled as a fallback |

Why DNS matters: if DNS is wrong, computers cannot find a DC and logins fail. DNS and its link to AD were covered earlier in [LC-041](../../networking/en/DNS%20%26%20Domain%20Name%20System%20Security.md).

```powershell
nslookup -type=SRV _ldap._tcp.dc._msdcs.corp.local
```

## 8. Trusts between domains

A trust lets users from one domain access resources in another.

| Trust type | Direction | Example |
|:---|:---|:---|
| Parent-child | Two-way, transitive, automatic | `jkt.corp.local` ↔ `corp.local` |
| Forest trust | One- or two-way | `corp.local` ↔ `partner.local` after an acquisition |
| External trust | One- or two-way, not transitive | To an old domain in another forest |

Trust direction confuses people. If domain A **trusts** domain B, then **users in B can access resources in A**. Access flows opposite to the direction of the trust.

Trusts created years ago for projects that have since ended are often forgotten and become a way in. Taking an inventory of trusts is part of an AD audit.

```powershell
Get-ADTrust -Filter * | Select Name, Direction, TrustType, ForestTransitive
nltest /domain_trusts
```

## 9. Practice

### Task 1: concepts

1. What is the real security boundary in AD: the domain or the forest?
2. Which file holds the password hashes of every user on a domain controller?
3. What is the order in which Group Policy is applied, first to last?
4. Domain A trusts domain B. Users of which domain can access resources of which domain?

<details><summary>Answer key</summary>

1. The forest. An admin in a child domain can become admin of the whole forest.
2. `NTDS.dit` in `C:\Windows\NTDS\`.
3. Local, Site, Domain, parent OU, child OU (LSDOU). The last one wins when settings conflict.
4. Users of domain B can access resources in domain A.

</details>

### Task 2: read a distinguished name

```text
CN=svc_backup,OU=Service Accounts,OU=IT,DC=jkt,DC=corp,DC=local
```

1. Which domain is this object in?
2. Which OUs?
3. Judging by the name, why does this account deserve a closer look?

<details><summary>Answer key</summary>

1. `jkt.corp.local`, a child domain of `corp.local`.
2. The `Service Accounts` OU inside the `IT` OU.
3. It is a service account for backups. Accounts like this often have old passwords that are never changed, often have an SPN, and if they belong to Backup Operators they can back up `NTDS.dit`.

</details>

### Task 3: a small audit in your lab

In an AD lab you own, run the following and note the results:

1. Who is in Domain Admins, including members of nested groups?
2. How many user accounts have a `pwdLastSet` older than 365 days?
3. Are there any `.xml` files in SYSVOL that contain `cpassword`?

<details><summary>Example commands</summary>

```powershell
Get-ADGroupMember "Domain Admins" -Recursive | Select SamAccountName
Get-ADUser -Filter * -Properties pwdLastSet |
  Where-Object { [datetime]::FromFileTime($_.pwdLastSet) -lt (Get-Date).AddDays(-365) } |
  Select SamAccountName
findstr /S /I cpassword \\corp.local\SYSVOL\corp.local\Policies\*.xml
```

</details>

## 10. Quick reference

```text
STRUCTURE
  Forest (security boundary) > Tree > Domain > OU > Object

DOMAIN CONTROLLER
  NTDS.dit = every hash · SYSVOL = GPOs + scripts (readable by all users)

SENSITIVE GROUPS
  Domain Admins · Enterprise Admins · Administrators · Account/Backup/Server Operators · DnsAdmins

GROUP POLICY
  LSDOU order, last one wins · gpresult /r · gpupdate /force

PORTS
  53 DNS · 88 Kerberos · 389/636 LDAP · 445 SMB · 3268 GC

TRUSTS
  A trusts B  →  users in B can access A
```
