## Istilah penting

| Istilah | Artinya |
|:---|:---|
| Active Directory (AD) | Layanan direktori Microsoft yang menyimpan daftar user, komputer, dan aturan di jaringan Windows |
| Domain | Batas administrasi di AD, misalnya `corp.local`. Semua anggotanya memakai database akun yang sama |
| Domain controller (DC) | Server yang menyimpan database AD dan memeriksa login |
| Forest | Kumpulan satu atau lebih domain yang berbagi skema dan saling percaya |
| OU | Organizational Unit: folder untuk mengelompokkan objek dan menempelkan kebijakan |
| GPO | Group Policy Object: kumpulan pengaturan yang diterapkan otomatis ke user atau komputer |
| LDAP | Protokol untuk membaca dan mengubah isi direktori |
| Kerberos | Protokol login utama di AD |
| SID | Security Identifier: ID unik untuk setiap akun atau grup |
| NTDS.dit | File database AD di setiap domain controller |

## 1. Kenapa Active Directory penting

Hampir semua perusahaan menengah dan besar yang memakai Windows mengelola akun karyawannya dengan Active Directory. Satu akun AD dipakai untuk login ke laptop, email, file share, VPN, dan banyak aplikasi internal.

Karena itu AD juga jadi sasaran utama penyerang. Begitu penyerang menguasai akun Domain Admin, ia praktis menguasai seluruh jaringan. Hampir setiap laporan ransomware besar memuat kalimat seperti "penyerang mendapatkan hak Domain Admin, lalu menyebarkan ransomware lewat Group Policy".

| Peran | Kenapa perlu paham AD |
|:---|:---|
| SOC Analyst | Sebagian besar alert login dan privilege di Windows berasal dari domain controller |
| Pentester | Hampir semua tes jaringan internal berakhir di AD |
| Incident responder | Timeline serangan ransomware biasanya bergerak dari satu laptop ke domain controller |
| Sysadmin | Salah konfigurasi kecil di AD bisa membuka jalan ke Domain Admin |

## 2. Domain, tree, dan forest

```
  Forest: corp.local
  ┌────────────────────────────────────┐
  │             corp.local             │  ← domain root
  │            /          \            │
  │   jkt.corp.local   osk.corp.local  │  ← child domain (satu tree)
  └────────────────────────────────────┘
                    │ trust
  ┌────────────────────────────────────┐
  │        Forest: partner.local       │  ← forest lain
  └────────────────────────────────────┘
```

| Struktur | Penjelasan |
|:---|:---|
| Domain | Satu database akun dan satu namespace DNS, misalnya `corp.local` |
| Tree | Domain induk dan child domain yang namanya bersambung, misalnya `jkt.corp.local` di bawah `corp.local` |
| Forest | Satu atau lebih tree. Forest adalah batas keamanan yang sebenarnya |

Poin penting untuk keamanan: **domain bukan batas keamanan, forest yang batas keamanan.** Admin di child domain bisa naik menjadi admin di seluruh forest. Kalau dua unit bisnis benar-benar harus terpisah, mereka butuh forest yang berbeda.

## 3. Domain controller dan apa yang disimpannya

Domain controller adalah server Windows dengan peran AD DS (Active Directory Domain Services). Biasanya ada minimal dua DC supaya login tetap jalan kalau satu mati. Perubahan di satu DC direplikasi ke DC lain.

Isi utama sebuah DC:

| Komponen | Lokasi | Isi |
|:---|:---|:---|
| `NTDS.dit` | `C:\Windows\NTDS\` | Database semua objek, termasuk hash password setiap user |
| SYSVOL | `C:\Windows\SYSVOL\` | Script login dan file Group Policy, bisa dibaca semua user domain |
| DNS | Layanan DNS di DC | Record yang dipakai komputer untuk menemukan DC |
| KDC | Layanan Kerberos | Memberi tiket login |

Siapa pun yang bisa menyalin `NTDS.dit` dari DC mendapatkan hash password seluruh user domain. Karena itu, akses login ke DC harus sangat dibatasi, termasuk backup-nya.

Cara melihat DC dari komputer anggota domain:

```powershell
nltest /dclist:corp.local         # daftar domain controller
echo %LOGONSERVER%                # DC yang memproses login kamu (di cmd)
Get-ADDomainController -Filter *  # butuh modul RSAT ActiveDirectory
```

## 4. Objek: user, grup, komputer, OU

Semua isi AD disimpan sebagai **objek** yang punya **atribut**.

| Objek | Contoh atribut | Catatan keamanan |
|:---|:---|:---|
| User | `sAMAccountName`, `memberOf`, `pwdLastSet`, `servicePrincipalName` | Akun dengan SPN perlu perhatian lebih |
| Grup | `member`, `groupType` | Grup bisa berisi grup lain, jadi keanggotaan bisa berlapis |
| Komputer | `dNSHostName`, `operatingSystem` | Setiap komputer anggota domain juga punya akun dan password sendiri |
| OU | `gPLink` | Tempat GPO ditempelkan |
| GPO | `gPCFileSysPath` | Isinya ada di SYSVOL |

Nama lengkap objek ditulis sebagai **distinguished name (DN)**:

```text
CN=Rina Putri,OU=Finance,OU=Jakarta,DC=corp,DC=local
```

Dibaca dari kanan: domain `corp.local`, OU Jakarta, OU Finance, lalu user Rina Putri.

Melihat objek dengan PowerShell (modul RSAT ActiveDirectory):

```powershell
Get-ADUser rina -Properties memberOf, pwdLastSet, lastLogonDate
Get-ADGroupMember "Domain Admins" -Recursive    # termasuk anggota grup bersarang
Get-ADComputer -Filter * -Properties operatingSystem | Select Name, operatingSystem
```

Setiap user domain bisa membaca sebagian besar isi AD lewat LDAP. Ini memang desainnya, tapi artinya penyerang yang baru mencuri satu akun biasa sudah bisa memetakan seluruh domain.

## 5. Grup penting yang wajib kamu kenal

| Grup | Hak | Kenapa berbahaya kalau disalahgunakan |
|:---|:---|:---|
| Domain Admins | Admin penuh di domain | Target utama penyerang |
| Enterprise Admins | Admin di seluruh forest | Hanya ada di domain root |
| Administrators (built-in) | Admin di domain controller | Setara Domain Admin |
| Account Operators | Bisa membuat dan mengubah sebagian besar akun | Sering dilupakan, dan dikenal sebagai jalan ke Domain Admin |
| Backup Operators | Bisa membackup file di DC, termasuk `NTDS.dit` | Backup = salinan semua hash |
| Server Operators | Bisa login ke DC dan mengubah service | Mengubah service di DC = menjalankan kode sebagai SYSTEM |
| DnsAdmins | Mengelola DNS di DC | Pernah disalahgunakan untuk memuat DLL ke service DNS |
| Group Policy Creator Owners | Membuat GPO baru | GPO bisa menjalankan script di banyak komputer |
| Protected Users | Grup pengaman, bukan grup admin | Anggotanya tidak bisa memakai NTLM atau RC4 |

Aturan praktis: anggota grup-grup di atas harus sesedikit mungkin, dan dicek rutin.

```powershell
"Domain Admins","Enterprise Admins","Administrators","Account Operators","Backup Operators","Server Operators" |
  ForEach-Object { "== $_"; Get-ADGroupMember $_ -Recursive | Select -Expand SamAccountName }
```

## 6. Group Policy

Group Policy menerapkan pengaturan ke banyak komputer sekaligus: kebijakan password, firewall, script login, software yang dipasang, dan lainnya.

```
GPO "Kebijakan Laptop"  ──link──►  OU=Laptops  ──berisi──►  50 komputer
```

Urutan penerapan (yang terakhir menang): **Local → Site → Domain → OU induk → OU anak**. Singkatannya LSDOU.

| Perintah | Fungsi |
|:---|:---|
| `gpupdate /force` | Paksa komputer mengambil kebijakan terbaru |
| `gpresult /r` | Lihat GPO apa saja yang berlaku untuk user dan komputer ini |
| `gpresult /h laporan.html` | Laporan lengkap dalam HTML |

Dua hal yang perlu diingat dari sisi keamanan:

1. **Siapa pun yang bisa mengedit GPO yang ter-link ke banyak komputer bisa menjalankan kode di semua komputer itu.** Hak edit GPO setara dengan hak admin di komputer-komputer tersebut.
2. **SYSVOL bisa dibaca semua user domain.** Dulu ada fitur Group Policy Preferences yang menyimpan password dalam file XML (`cpassword`) di SYSVOL, dan kuncinya sudah dipublikasikan Microsoft. Fitur itu sudah ditutup lewat patch MS14-025, tapi file lama kadang masih tertinggal. Mencari `cpassword` di SYSVOL adalah salah satu pemeriksaan pertama saat audit.

```powershell
# Pemeriksaan audit: masih ada file lama berisi cpassword?
findstr /S /I cpassword \\corp.local\SYSVOL\corp.local\Policies\*.xml
```

## 7. Protokol yang dipakai AD

| Protokol | Port | Fungsi |
|:---|:---|:---|
| DNS | 53 | Komputer menemukan DC lewat record SRV, misalnya `_ldap._tcp.dc._msdcs.corp.local` |
| Kerberos | 88 | Login dan tiket akses |
| LDAP / LDAPS | 389 / 636 | Membaca dan mengubah direktori |
| Global Catalog | 3268 / 3269 | Pencarian objek di seluruh forest |
| SMB | 445 | Akses SYSVOL, file share, administrasi jarak jauh |
| RPC | 135 + port dinamis | Replikasi dan banyak fungsi administrasi |
| NTLM | (di dalam SMB, HTTP, dll.) | Protokol login lama, masih aktif sebagai cadangan |

Kenapa DNS penting: kalau DNS salah, komputer tidak bisa menemukan DC dan login gagal. Hubungan DNS dan AD dibahas lebih dulu di [LC-041](../../networking/id/DNS%20%26%20Domain%20Name%20System%20Security.md).

```powershell
nslookup -type=SRV _ldap._tcp.dc._msdcs.corp.local
```

## 8. Trust antar domain

Trust membuat user dari satu domain bisa mengakses resource di domain lain.

| Jenis trust | Arah | Contoh |
|:---|:---|:---|
| Parent-child | Dua arah, transitif, otomatis | `jkt.corp.local` ↔ `corp.local` |
| Forest trust | Satu atau dua arah | `corp.local` ↔ `partner.local` setelah akuisisi |
| External trust | Satu atau dua arah, tidak transitif | Ke domain lama di forest lain |

Arah trust sering membingungkan. Kalau domain A **trust** domain B, maka **user B bisa mengakses resource A**. Akses mengalir berlawanan dengan arah trust.

Trust yang dibuat bertahun-tahun lalu untuk proyek yang sudah selesai sering terlupakan dan menjadi jalan masuk. Inventaris trust adalah bagian dari audit AD.

```powershell
Get-ADTrust -Filter * | Select Name, Direction, TrustType, ForestTransitive
nltest /domain_trusts
```

## 9. Latihan

### Task 1: konsep

1. Apa batas keamanan yang sebenarnya di AD: domain atau forest?
2. File apa yang menyimpan hash password semua user di domain controller?
3. Urutan penerapan Group Policy dari yang pertama sampai yang terakhir?
4. Domain A trust domain B. User domain mana yang bisa mengakses resource domain mana?

<details><summary>Kunci jawaban</summary>

1. Forest. Admin di child domain bisa naik menjadi admin seluruh forest.
2. `NTDS.dit` di `C:\Windows\NTDS\`.
3. Local, Site, Domain, OU induk, OU anak (LSDOU). Yang terakhir menang kalau ada konflik.
4. User domain B bisa mengakses resource domain A.

</details>

### Task 2: baca distinguished name

```text
CN=svc_backup,OU=Service Accounts,OU=IT,DC=jkt,DC=corp,DC=local
```

1. Objek ini ada di domain apa?
2. Di OU apa saja?
3. Dari namanya, kenapa akun ini perlu diperiksa lebih teliti?

<details><summary>Kunci jawaban</summary>

1. `jkt.corp.local`, child domain dari `corp.local`.
2. OU `Service Accounts` di dalam OU `IT`.
3. Ini akun layanan untuk backup. Akun seperti ini sering punya password lama yang tidak pernah diganti, sering punya SPN, dan kalau tergabung di Backup Operators bisa membackup `NTDS.dit`.

</details>

### Task 3: audit kecil di lab

Di lab AD milikmu sendiri, jalankan dan catat hasilnya:

1. Siapa saja anggota Domain Admins, termasuk anggota grup bersarang?
2. Berapa akun user yang `pwdLastSet` lebih dari 365 hari lalu?
3. Apakah ada file `.xml` berisi `cpassword` di SYSVOL?

<details><summary>Contoh perintah</summary>

```powershell
Get-ADGroupMember "Domain Admins" -Recursive | Select SamAccountName
Get-ADUser -Filter * -Properties pwdLastSet |
  Where-Object { [datetime]::FromFileTime($_.pwdLastSet) -lt (Get-Date).AddDays(-365) } |
  Select SamAccountName
findstr /S /I cpassword \\corp.local\SYSVOL\corp.local\Policies\*.xml
```

</details>
