## 1. 🎯 Definition

### 🇮🇩 Bahasa Indonesia
**SSRF** terjadi ketika aplikasi server-side mengambil resource berdasarkan **referensi yang dipengaruhi penyerang** (URL, host, path), sehingga server menjadi wakil (confused deputy) yang mengakses target yang tidak dimaksudkan untuk publik: layanan internal, localhost, link-local, atau metadata cloud.

$$
\mathsf{Fetch}(\mathsf{url}_{\mathsf{user}})
\;\Rightarrow\;
\text{request originates from trusted server IP / VPC}
$$

Berbeda dengan CSRF (browser korban): pada SSRF, **server aplikasi** yang mengirim request.

### 🇬🇧 English
SSRF is dangerous because firewalls and “internal-only” services often trust the application subnet. The bug class is **insufficient restriction on server-side outbound requests**.

### 日本語
SSRFは、サーバーが攻撃者の指定した宛先へリクエストすることで、内部サービスやクラウドメタデータなど**本来外から届かない対象**へ到達できてしまう欠陥です。

## 2. 💥 Impact Classes (Conceptual)

| Class | Description | Defense emphasis |
|:---|:---|:---|
| **Internal recon** | Touch ports/services inside VPC | Egress allowlist; network policy |
| **Local service abuse** | Hit `localhost` admin ports / agents | Block loopback; unix sockets not via HTTP URL |
| **Cloud credential exposure** | Reach instance metadata endpoints | IMDSv2/hop limit; firewall metadata |
| **File/handler schemes** | Dangerous URL schemes if library allows | Scheme allowlist `https` only |
| **Response misuse** | App relays internal body to attacker | Do not reflect raw fetch bodies; size limits |
| **Blind SSRF** | Only side effects (DNS, timing, webhooks) | Same URL controls; monitor egress |

Catatan: beberapa library historis mendukung skema non-HTTP. Catatan ini **tidak** membahas rantai eksploit skema tersebut — cukup pahami: **batasi skema dan parser**.

## 3. 🧬 Root Cause

Fitur produk yang sering memicu SSRF:

- “Preview URL” / unfurl / thumbnail generator  
- Webhook tester / “fetch this callback”  
- Import from URL / PDF generators / document converters  
- SSO/metadata discovery dengan URL user-controlled  
- Image proxy / CDN pull from arbitrary origin  

Root cause: memperlakukan string URL sebagai **aman karena HTTP client library “hanya mengunduh.”** Keamanan bergantung pada **kebijakan destinasi**, bukan pada “kami memakai HTTPS.”

## 4. 🧪 URL Validation Pitfalls

Validasi naif sering gagal karena lapisan berbeda:

### 4.1 Hostname allowlist vs IP allowlist
Memblokir string `127.0.0.1` tidak cukup jika:

- DNS mengembalikan IP internal setelah cek (**DNS rebinding** / TOCTOU: resolve → check → resolve lagi berbeda).  
- Decimal/hex/IPv6 mapped forms untuk loopback.  
- Alias hostname internal.

**Pola aman:** resolve DNS → verifikasi alamat IP hasil ∈ allowlist kebijakan → connect **hanya** ke IP yang sudah diverifikasi (pin), dengan TTL pendek dan tanpa redirect ke host lain tanpa cek ulang.

### 4.2 Redirects
`http://allowed.example` → `302` → `http://169.254.169.254/`. Jika client mengikuti redirect tanpa re-validate, kontrol bypassed.

### 4.3 Parser discrepancies
Library URL di bahasa A ≠ parser di bahasa B (`The Tangled Web` menekankan inkonsistensi parser). Satu sisi melihat host “aman”, sisi lain menghubungi host berbeda.

### 4.4 Formal policy sketch

$$
\begin{aligned}
&\mathsf{scheme}(u) \in \{\mathsf{https}\} \\
&\mathsf{ip}(\mathsf{resolve}(u)) \in \mathcal{A}_{\mathsf{public\_allow}} \\
&\mathsf{ip}(\cdot) \notin \mathcal{B}_{\mathsf{blocked}} \\
&\quad \mathcal{B} \supseteq \{\mathsf{loopback},\,\mathsf{link\text{-}local},\,\mathsf{RFC1918},\,\mathsf{CGNAT},\,\mathsf{metadata}\}
\end{aligned}
$$

Prefer **positive allowlist** of destinations (partner hosts) over giant blocklists alone.

## 5. ⚖️ Unsafe vs Safe Patterns

### 5.1 Unsafe

```python
# UNSAFE — attacker controls URL; server fetches anything reachable
import requests
url = request.args["url"]
resp = requests.get(url, timeout=3)
return resp.text  # may leak internal responses
```

### 5.2 Safer sketch — scheme + block private IP + no redirects + size cap

```python
# HARDENED SKETCH — still review for DNS rebinding in production
from urllib.parse import urlparse
import ipaddress, socket, requests

ALLOWED_PORTS = {443}
BLOCK_NETS = [
    ipaddress.ip_network("0.0.0.0/8"),
    ipaddress.ip_network("10.0.0.0/8"),
    ipaddress.ip_network("127.0.0.0/8"),
    ipaddress.ip_network("169.254.0.0/16"),
    ipaddress.ip_network("172.16.0.0/12"),
    ipaddress.ip_network("192.168.0.0/16"),
    ipaddress.ip_network("::1/128"),
    ipaddress.ip_network("fc00::/7"),
    ipaddress.ip_network("fe80::/10"),
]

def ip_blocked(ip: str) -> bool:
    addr = ipaddress.ip_address(ip)
    return any(addr in net for net in BLOCK_NETS)

def safe_fetch(user_url: str) -> bytes:
    u = urlparse(user_url)
    if u.scheme != "https" or not u.hostname:
        raise ValueError("scheme")
    port = u.port or 443
    if port not in ALLOWED_PORTS:
        raise ValueError("port")
    infos = socket.getaddrinfo(u.hostname, port, type=socket.SOCK_STREAM)
    ips = {info[4][0] for info in infos}
    if not ips or any(ip_blocked(ip) for ip in ips):
        raise ValueError("ip")
    # Production: connect via pinned IP + SNI/Host carefully; re-check redirects
    r = requests.get(user_url, timeout=3, allow_redirects=False, stream=True)
    return r.content[: 200_000]
```

Untuk banyak produk, **lebih aman**: jangan terima URL mentah — terima `resource_id` internal yang dipetakan server ke URL tetap.

## 6. ☁️ Cloud Metadata Hardening (Concept)

Instance metadata services (IMDS) menyediakan kredensial sementara ke workload cloud. SSRF ke IMDS adalah pola dampak tinggi di laporan WAHH-era modern / cloud IR.

| Control | Intent |
|:---|:---|
| IMDSv2 (session-oriented) | Requires method/header hop not trivial via basic SSRF GET |
| Hop limit / firewall | Prevent containers from reaching metadata unexpectedly |
| Least-privilege roles | Stolen creds limited blast radius |
| No raw metadata proxying | App never fetches metadata URL from user input |

Catatan ini tidak menyediakan resep eksploit metadata — hanya **hardening**.

## 7. 🛡️ Defense-in-Depth Stack

1. **Prefer indirection** — IDs, not free-form URLs.  
2. **Scheme allowlist** — typically `https` only.  
3. **Destination allowlist** — known partners.  
4. **Block private/link-local/metadata** after DNS resolve; pin IP.  
5. **Disable redirects** or re-validate every hop.  
6. **Network egress policy** — app subnet cannot reach sensitive segments.  
7. **Dedicated proxy** for outbound with DLP / allowlist.  
8. **Do not return raw bodies** from internal fetches to clients.  
9. **Timeouts, size limits, content-type allowlists**.  
10. **AuthZ** on the feature itself (who may trigger fetch).

### 🇮🇩 Bahasa Indonesia
WAHH menekankan mapping permukaan “dari mana aplikasi membuat koneksi keluar.” Inventarisasi semua HTTP client di monorepo (termasuk PDF, ffmpeg wrappers, webhook deliverers).

### 🇬🇧 English
SSRF fixes that only filter string equality on hostnames without addressing redirects and DNS TOCTOU remain fragile.

### 日本語
ホスト名の文字列一致だけでは不十分です。DNS再解決・リダイレクト・スキームを含めて制御します。

## 8. 🔍 Authorized Detection Signals

- Code search: `requests.get(user`, `HttpClient`, `curl_exec`, `file_get_contents("http`.  
- Egress monitoring: app pods connecting to `169.254.169.254` or RFC1918 unexpectedly.  
- Unit tests: reject loopback, reject redirects to private IP, reject non-HTTPS.

## 9. ✅ Developer Checklist

| Check | Pass |
|:---|:---|
| User-supplied URL needed? | Prefer IDs |
| Scheme | `https` only |
| Redirects | Off or re-validated |
| IP policy | Block private/link-local/metadata |
| DNS | TOCTOU considered / pinned |
| Response | Not reflected raw; capped |
| Egress | Network policy deny-by-default |
| Cloud | IMDSv2 + minimal roles |

```
 Client URL ─► Policy gate ─► Egress proxy ─► Allowlisted targets only
                 │ reject
                 └── private / metadata / bad scheme
```

## 🔐 Security Notes — Threats & Defenses

| Threat pattern | Mechanism | Defense |
|:---|:---|:---|
| Internal port touch | Server reaches VPC services | Egress allowlist |
| Metadata access | Link-local IMDS | IMDSv2; block; no user URL |
| Redirect bypass | 302 to internal | `allow_redirects=False` + recheck |
| DNS rebinding | IP changes after check | Pin IP; short TTL; re-validate |
| Scheme smuggling | Non-HTTP handlers | Scheme allowlist |
