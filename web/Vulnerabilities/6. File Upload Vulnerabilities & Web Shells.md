## 1. 🎯 Threat Model

### 🇮🇩 Bahasa Indonesia
Fitur unggah file mengubah klien menjadi penulis di sistem file (atau object store) server. WAHH menekankan dampak berantai: jika file yang diunggah **dapat dieksekusi** oleh runtime web, atau diproses oleh parser rentan, hasilnya dapat berupa RCE, XSS tersimpan (SVG/HTML), SSRF via parser URL, atau DoS (zip bomb, dekompresi).

**Web shell** (sebagai konsep): skrip yang diunggah lalu dipanggil lewat HTTP sehingga server mengeksekusi perintah penyerang. Catatan ini menjelaskan cara **mencegah kelas itu**, bukan cara menulis/mengunggah shell.

### 🇬🇧 English
CWE-434: *Unrestricted Upload of File with Dangerous Type*. Dangerous ≠ only “`.php`”; it includes any content the environment will interpret (templates, server-side includes, certain “document” formats in office converters, HTML served with wrong MIME).

### 日本語
危険なアップロードとは、サーバーやブラウザが**解釈・実行**してしまう種別のファイルを、制御不足で置けてしまうことです。

## 2. 🧬 Root Causes

| Failure | What goes wrong |
|:---|:---|
| Trust client `Content-Type` / filename | Attacker-controlled metadata |
| Store under web-executable root | URL maps to code runtime |
| Keep user extension | `.php`, `.aspx`, `.jsp`, double extensions, trailing dots |
| No random object key | Overwrite, predict paths, cache poison |
| Serve with wrong `Content-Type` | Browser executes as HTML/JS (XSS) |
| Process with unsafe parsers | ImageTragick-class / XML XXE in “previews” |
| Symlink / path in filename | Traversal into other dirs |

## 3. 🧪 Content Validation — Principles

### 3.1 Layered checks (none sufficient alone)

1. **Extension allowlist** — e.g. `{png,jpg,webp,pdf}` mapped server-side.  
2. **Magic-byte / file(1) sniff** — verify matches declared type.  
3. **Re-encode / transcode** — for images, decode then write new file with trusted library (destroys many polyglots).  
4. **Size limits** — per file + per user quota.  
5. **Filename discard** — never reuse raw user filename as storage key.

$$
\mathsf{accept}(f)
\;\iff\;
\mathsf{ext}(f)\in\mathcal{A}
\;\wedge\;
\mathsf{magic}(f)\in\mathcal{M}(\mathsf{ext})
\;\wedge\;
|f|\le L
$$

### 3.2 Polyglots (concept)
Satu berkas dapat valid sebagai lebih dari satu format (mis. gambar + konten skrip) tergantung parser. **Re-encoding** dan **Content-Type yang ketat saat serving** mengurangi risiko.

### 3.3 SVG / HTML
SVG dapat berisi skrip jika disajikan inline sebagai `image/svg+xml` di konteks tertentu. Opsi aman: rasterize SVG ke PNG server-side; atau serve dengan `Content-Disposition: attachment` + CSP ketat.

## 4. 🗄️ Safe Storage Design

```
 ┌──────── viewer / CDN ────────┐
 │  signed URL, short TTL       │
 └─────────────▲────────────────┘
               │
 ┌─────────────┴────────────────┐
 │ Object store bucket          │
 │  - random keys               │
 │  - no public execute         │
 │  - antivirus/async scan opt. │
 └─────────────▲────────────────┘
               │
         app writes only
```

### Principles
- Store **outside** document root; or bucket with **no** script execution.  
- Object key: `uuid + fixed_ext` from allowlist.  
- DB maps `user_id → object_key → declared_type`.  
- Access via **authorized** download handler or signed URLs.  
- For Apache/Nginx: directory `location` disables script engines explicitly (defense in depth even if mis-deployed).

## 5. 🚧 Execution Barrier

### 🇮🇩 Bahasa Indonesia
Tujuan: $P(\text{HTTP GET unggahan mengeksekusi kode server}) \approx 0$.

Kontrol:
- Jangan petakan path unggahan ke interpreter PHP/ASP/JSP.  
- Header unduhan: `Content-Type` yang benar + `X-Content-Type-Options: nosniff`.  
- `Content-Disposition: attachment` untuk tipe berisiko.  
- Nonaktifkan *handlers* di folder unggah (contoh ops konfigurasi — sesuaikan stack Anda).

### 🇬🇧 English
Even with perfect extension checks, a later vulnerability (LFI of upload path, template include) can revive risk — keep uploads **non-executable** and **non-includable as code**.

### 日本語
アップロードをコードとして`include`しない、Webルートで実行しない、が基本です。

## 6. ⚖️ Unsafe vs Safe Patterns

### 6.1 Unsafe

```python
# UNSAFE — trusts filename & stores in web root
f = request.files["file"]
f.save("/var/www/html/uploads/" + f.filename)
# later: https://app/uploads/evil.php may execute if PHP enabled there
```

### 6.2 Safer sketch

```python
import uuid
from pathlib import Path

ALLOWED = {
    "image/png": ".png",
    "image/jpeg": ".jpg",
}
STORE = Path("/var/app/upload_data")  # not served as scripts

def save_upload(file_storage, sniffed_mime: str) -> str:
    if sniffed_mime not in ALLOWED:
        raise ValueError("type")
    if file_storage.content_length and file_storage.content_length > 5_000_000:
        raise ValueError("size")
    key = f"{uuid.uuid4().hex}{ALLOWED[sniffed_mime]}"
    dest = STORE / key
    # Prefer: decode/re-encode image here instead of raw save when applicable
    file_storage.save(dest)
    return key
```

```nginx
# Defense-in-depth example: deny script execution in a mistaken alias
location ^~ /media/ {
    internal;  # or alias to read-only files with types {}
    add_header X-Content-Type-Options nosniff always;
    default_type application/octet-stream;
}
```

## 7. 🖼️ Media & Document Processors

Unggahan sering diproses: thumbnail, virus scan, office→PDF.

| Risk class | Mitigation |
|:---|:---|
| Command injection in converter CLI | argv arrays; allowlist; sandbox |
| Parser vulns (images, XML, fonts) | Updated libs; isolate workers; resource limits |
| XXE in XML-based formats | Disable external entities; use safe parsers |
| Zip bombs / ratios | Limit uncompressed size & entries |
| SSRF via remote linked resources | Disable network in worker |

Jalankan worker di isolasi (container non-root, no egress, seccomp).

---

## 8. 🛡️ Defense-in-Depth Stack

1. AuthN/AuthZ on upload API (who can upload what).  
2. Allowlist MIME + magic + size.  
3. Random keys; discard user filenames.  
4. Re-encode images when possible.  
5. Non-executable storage; separate bucket/account.  
6. Safe serving headers / signed URLs.  
7. Async malware scanning where appropriate.  
8. Rate limits & quotas.  
9. Monitoring: spike in upload errors / new object types.  
10. No include/LFI paths pointing at upload dir.

## 9. ✅ Developer Checklist

| Check | Pass criteria |
|:---|:---|
| Storage location | Outside script roots |
| Type policy | Allowlist + magic |
| Filename | Server-generated |
| Serving | nosniff + correct MIME |
| SVG/HTML | Rasterize or attachment |
| Workers | Sandboxed converters |
| Path | No user-controlled destination dirs |
| Tests | Reject disallowed types; verify non-exec config |

```
 Client file
    │
    ▼
 Validate type/size ──► Re-encode? ──► Store random key
    │                                   │
    └ reject                            ▼
                              Serve via authz + safe headers
```

## 🔐 Security Notes — Threats & Defenses

| Threat pattern | Class | Defense |
|:---|:---|:---|
| Executable upload | RCE via web runtime | Non-exec storage + type allowlist |
| Stored XSS via HTML/SVG | Browser script | MIME + CSP + sanitize/rasterize |
| Overwrite critical files | Integrity | Random keys; no user paths |
| Malicious archives | DoS / path write | Limits; safe extract |
| Converter abuse | RCE/SSRF | Sandbox; argv; no egress |
