## 1. 🎯 Threat Model — Why SQLi Matters

### 🇮🇩 Bahasa Indonesia
**SQL Injection** terjadi ketika data yang tidak dipercaya mempengaruhi **struktur** pernyataan SQL, bukan hanya nilai literal di dalamnya. Menurut WAHH (Ch.9), database sering menjadi “sumber kebenaran” aplikasi: kredensial, PII, otorisasi, audit trail. Jika penyerang mengendalikan sintaks SQL, dampak tipikal:

| Impact class | Contoh konsekuensi |
|:---|:---|
| Confidentiality | Pembacaan baris/tabel di luar otorisasi |
| Integrity | UPDATE/DELETE di luar intent bisnis |
| Availability | Query mahal / lock / truncate (DoS logika) |
| Privilege | Penggunaan fungsi DB berbahaya jika hak akun DB berlebih |
| Lateral | Pivot ke OS hanya jika DB + konfigurasi memungkinkan (bukan default aman) |

SQLi adalah kelas **CWE-89** / OWASP A03:2021 *Injection*.

### 🇬🇧 English
Treat every boundary that reaches a SQL engine (HTTP params, headers, cookies, JSON fields, file names, message-queue payloads) as **untrusted**. The vulnerability is not “having a database”; it is **mixing code and data in one string**.

### 🇯🇵 日本語
SQLエンジンに到達するすべての入力を**信頼できない**とみなします。問題はDBそのものではなく、**コードとデータを一つの文字列に混ぜること**です。

## 2. 🧬 Root Cause — Query Construction

### 🇮🇩 Bahasa Indonesia
Misalkan query dibangun sebagai concatenasi:

$$
Q = T_0 \,\|\, u_1 \,\|\, T_1 \,\|\, u_2 \,\|\, \cdots \,\|\, T_n
$$

di mana $T_i$ adalah fragmen SQL tetap (kode), dan $u_j$ adalah input pengguna (data). Keamanan membutuhkan:

$$
\mathsf{parse}(Q) = \mathsf{parse}\!\big(T_0 \,\|\, \mathsf{lit}(u_1) \,\|\, T_1 \,\|\, \cdots\big)
$$

dengan $\mathsf{lit}(\cdot)$ yang **tidak pernah** mengubah struktur AST. Concatenation mentah gagal memenuhi ini: karakter seperti kutip, komentar, atau operator dapat menutup literal dan membuka klausa baru.

**Prepared statements / parameter binding** memisahkan fase:

1. **Prepare:** parser menerima template dengan placeholder (`?`, `$1`, named params).
2. **Execute:** driver mengirim nilai terikat *di luar* teks SQL (protokol biner / typed parameters).

Secara abstrak:

$$
Q_{\mathsf{safe}} = \mathsf{Prepare}(T),\qquad
\mathsf{Execute}(Q_{\mathsf{safe}},\; \vec{v})
$$

$\vec{v}$ tidak digabung ke $T$ sebagai teks yang di-parse ulang sebagai SQL.

### 🇬🇧 English
Escaping *can* work if perfect for the exact dialect and charset — historically it fails under encoding tricks, partial escaping, or wrong API. Prefer **parameters**, not DIY quote escaping.

### 日本語
エスケープは方言・文字コード次第で破綻しがちです。**バインド変数（プリペアド）を標準**にし、手作業のクォート処理に依存しないでください。

## 3. 📚 Injection Classes — Conceptual Taxonomy (WAHH)

Kelas di bawah menjelaskan *bagaimana efek diamati*, bukan resep serangan.

| Class | Observability | Intuition | Defense note |
|:---|:---|:---|:---|
| **In-band** | Hasil/error muncul di response HTTP yang sama | Input mengubah hasil yang terlihat | Params + least privilege; hide DB errors |
| **Inferential (blind)** | Hanya perbedaan perilaku (true/false, latency) | Aplikasi “menjawab” lewat side channel | Same root fix; also normalize error/timing |
| **Out-of-band** | Channel samping (DNS/HTTP dari DB host) jika fitur DB + jaringan mengizinkan | Jarang; butuh kemampuan DB & egress | Block egress dari DB tier; disable dangerous features |
| **Second-order** | Payload disimpan dulu, dieksekusi di query lain | Validasi di *setiap* sink SQL | Parameterize all sinks, including admin/reporting jobs |

### 🇮🇩 Bahasa Indonesia
WAHH menekankan: blind/OOB bukan “jenis SQL berbeda”, melainkan **strategi observasi** ketika aplikasi tidak menampilkan data query secara langsung. Mitigasi primer tetap sama: **jangan biarkan input menjadi sintaks**.

### 🇬🇧 English
Do not chase class-specific “payload catalogs.” Fix the construction model everywhere a query is built (including batch jobs, exports, search, and ORMs that fall back to raw SQL).

### 日本語
クラス別の攻撃カタログを追う必要はありません。クエリが作られる**すべての箇所**で構文とデータを分離します。

## 4. 🔁 Second-Order & Multi-Sink Reality

### 🇮🇩 Bahasa Indonesia
Pola berbahaya klasik:

1. Input disimpan dengan aman ke kolom (INSERT berparameter).
2. Nanti, proses lain membaca nilai itu dan **menggabungkannya** ke SQL dinamis (laporan, cron, “advanced search”).

Jadi “input sudah di-sanitize saat insert” **tidak** cukup. Setiap **sink** SQL harus aman secara independen.

### 🇬🇧 English
Threat-model every code path that calls `query()`, `execute()`, or builds SQL in string templates — including low-frequency admin tools.

### 日本語
INSERT時に安全でも、後段の動的SQLが危険なら二次インジェクションになります。**すべてのSQLシンク**を防御します。

## 5. ⚖️ Unsafe vs Safe Code Patterns

### 5.1 Anti-pattern — string concatenation (illustrative)

```php
// UNSAFE — user data becomes SQL syntax
$sql = "SELECT id, role FROM users WHERE email = '" . $_GET['email'] . "'";
$rows = $db->query($sql);
```

```python
# UNSAFE
sql = f"SELECT * FROM products WHERE category = '{category}' AND q = '{q}'"
cursor.execute(sql)
```

### 5.2 Safe — bound parameters

```php
// SAFE — structure fixed; values bound
$stmt = $pdo->prepare('SELECT id, role FROM users WHERE email = ?');
$stmt->execute([$email]);
```

```python
# SAFE (DB-API style)
cursor.execute(
    "SELECT * FROM products WHERE category = %s AND q = %s",
    (category, q),
)
```

```java
// SAFE
PreparedStatement ps = conn.prepareStatement(
    "SELECT id, role FROM users WHERE email = ?");
ps.setString(1, email);
```

### 5.3 Dynamic identifiers (table/column/ORDER BY)

Parameter binding **tidak** mengikat nama identifier. Untuk `ORDER BY` / nama kolom:

- Allowlist ketat: `{"name","price","created_at"}` → map ke literal SQL tetap.
- Tolak input di luar himpunan.

$$
\mathsf{col} \in \mathcal{A} \subset \mathsf{Identifiers},\quad
\text{else reject}
$$

Jangan: `"ORDER BY " + userInput`.

### 5.4 LIKE / wildcards

Binding mencegah injeksi sintaks, tetapi `%` / `_` tetap wildcard. Escape wildcard di lapisan aplikasi jika pencarian literal diperlukan.

## 6. 🧩 ORM, Stored Procedures & NoSQL

| Technology | False sense of safety | Real requirement |
|:---|:---|:---|
| ORM | “We don’t write SQL” | Avoid raw/string interpolations; review `whereRaw`, `order`, criteria APIs |
| Stored procedures | “Logic in DB” | Procedures that concat SQL internally are still injectable |
| Query builders | Fluent API | Ensure final SQL uses placeholders, not glued strings |
| NoSQL (e.g. Mongo query objects) | “Not SQL” | Operator injection (`$gt`, `$where`) if JSON merges untrusted objects |

### 🇮🇩 Bahasa Indonesia
Untuk NoSQL: jangan `JSON.parse` body lalu merge langsung ke filter query. Parse field yang diizinkan saja; bangun filter di server.

### 🇬🇧 English
WAHH’s injection chapter mindset applies beyond SQL: **any interpreter** (LDAP, OS shell, XPath, template engines) fails the same way when code and data mix.

### 日本語
SQL以外（シェル、LDAP、テンプレート等）も、コードとデータの混在が同じクラスの欠陥です。

## 7. 🛡️ Defense-in-Depth Stack

### 7.1 Primary control (mandatory)
- **Parameterized queries** / stored procs *without* dynamic SQL concat.
- **Allowlists** for identifiers and enum-like filters.

### 7.2 Secondary controls
| Control | Purpose |
|:---|:---|
| Least-privilege DB account | App role: DML limited; no FILE/SUPER/xp_cmdshell-style rights |
| Separate credentials | Read-only replica creds for reporting where possible |
| Network segmentation | App ↔ DB private; DB no general Internet egress |
| Error handling | Generic client errors; detailed SQL errors only in secure logs |
| Input validation | Length/type/charset — *defense in depth*, not a substitute for params |
| WAF / RASP | Temporary signal & virtual patch — not root fix |
| Secrets | No DB creds in frontend; rotate; vault/KMS |

### 7.3 Output encoding ≠ SQLi fix
Encoding HTML (XSS defense) **tidak** memperbaiki SQLi. Controls must match the sink language.

### 🇮🇩 Bahasa Indonesia
Urutan prioritas: (1) parameterize semua sink → (2) least privilege → (3) validasi/allowlist → (4) monitoring. Jangan mengandalkan “filter kata kunci SQL” (blacklist `OR`/`UNION`) — mudah dilumpuhkan dan merusak input sah.

### 🇬🇧 English
Keyword blacklists are fragile and hostile to legitimate text. Prefer structural safety (bind parameters) over lexical filters.

### 日本語
キーワード禁止リストは回避されやすく、正当入力も壊します。**構文の分離（バインド）**を最優先します。

## 8. 🔍 Authorized Detection & Verification Signals

Untuk lab sendiri / pentest berizin, fokus pada **indikator kelas**, bukan katalog payload:

- Diff perilaku saat input memutus literal (error 5xx generik vs 200) — lalu perbaiki akar, jangan “tutup error saja”.
- Code review: regex/cari string SQL + variabel; SASt rules untuk concatenasi.
- Unit/integration tests: pastikan driver memakai bind; CI semgrep/CodeQL rules `sql-injection`.
- Logging: query templates + parameter metadata — **jangan** log password fields.

```bash
# Lab only: inspect that YOUR app uses TLS to DB and least-priv account
# (example connectivity check — not an attack tool)
psql "host=127.0.0.1 dbname=app user=app_rw sslmode=verify-full" -c 'SELECT current_user;'
```

## 9. ✅ Developer Mitigation Cheatsheet

| Check | Pass criteria |
|:---|:---|
| All SQL sinks | Prepared/bound parameters |
| ORDER BY / columns | Allowlist map only |
| Multi-tenant filters | Server-side `tenant_id` from session, never from client alone |
| Errors | No stack/SQL text to clients |
| DB role | Minimal grants; no OS integration features |
| Migrations / admin scripts | Same standards as production request path |
| Second-order paths | Reports, queues, search indexers parameterized |
| Tests | At least one regression test per historical concat bug |

```
 Trust boundary          Safe interior
 ┌─────────────┐         ┌──────────────────────────┐
 │ HTTP / MQ   │  values │  Prepare(T) + Bind(v)    │──► SQL engine
 │ untrusted   │────────►│  Allowlist(identifiers)  │
 └─────────────┘         └──────────────────────────┘
        ✗ never:  sql = "SELECT ... " + user
```

## 🔐 Security Notes — Threats & Defenses

| Threat pattern | Why it works | Defense |
|:---|:---|:---|
| Auth bypass via altered WHERE | Data becomes boolean logic | Bind params; server-side session authZ |
| UNION-style result shaping | Attacker aligns columns when output reflected | Params; minimize reflective SQL errors/data |
| Blind inference | App leaks boolean/time side channels | Params; constant-time-ish error pages; rate limits |
| Privileged DB features | Over-powered account | Drop dangerous privileges; egress control |
| ORM raw SQL | Escape hatch concat | Ban/review raw APIs; SAST |
