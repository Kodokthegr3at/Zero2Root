## 1. 🧬 Shared Root Cause — Mixing Code and Data

### 🇮🇩 Bahasa Indonesia
Baik **command injection** maupun **file inclusion** adalah saudara dari SQL injection (WAHH: *injecting into interpreted languages*): string yang dipengaruhi penyerang digabung ke dalam perintah yang akan diinterpretasikan (shell, PHP `include`, template engine, dll.).

$$
\mathsf{Interpreter}(T_0 \,\|\, u \,\|\, T_1)
\;\neq\;
\mathsf{Interpreter}(T_0 \,\|\, \mathsf{lit}(u) \,\|\, T_1)
$$

Ketika $u$ dapat mengubah parsing, data menjadi **kode** atau **path di luar kontrak**.

### 🇬🇧 English
Primary fix is always structural: **don’t start a shell**, **don’t include arbitrary paths**, use APIs that take argument vectors or fixed allowlisted resources.

### 日本語
シェル文字列連結や任意パスの`include`をやめ、引数配列APIと許可リストで構造的に防ぎます。

## 2. ⌨️ OS Command Injection (CWE-78)

### 2.1 When it appears
Fitur yang memanggil alat eksternal: image magick, `ping`, converters, git wrappers, backup scripts, “diagnose hostname” admin tools.

### 2.2 Dangerous pattern
Shell metacharacters (konsep: pemisah perintah, substitusi, pipe) mengubah satu perintah menjadi beberapa — **jangan** daftar payload di sini; cukup paham kelas risiko.

### 2.3 Safe approach — argv array, no shell

```python
# UNSAFE — shell=True + user input
os.system("ping -c 1 " + host)
subprocess.call("convert " + user_path + " out.png", shell=True)

# SAFE — no shell; fixed executable; validate host/path first
subprocess.run(
    ["/usr/bin/ping", "-c", "1", "--", host],
    check=False,
    capture_output=True,
    timeout=3,
)
# host must still match allowlist regex (e.g. DNS label rules)
```

```php
// UNSAFE
shell_exec("dig " . $_GET["d"]);

// SAFER — avoid shell; use library or escapeshellarg *only* if shell unavoidable
// Best: do not expose dig; use PHP DNS APIs / internal service
```

Jika shell **benar-benar** tidak terhindarkan: `escapeshellarg` / equivalent per platform — tetap inferior dibanding argv array.

### 2.4 Defense extras
- Allowlist arguments (enum of jobs), not free-form strings.  
- Drop privileges; seccomp/AppArmor; containers without unnecessary binaries.  
- Remove debugging utilities from production images.

## 3. 📂 Local File Inclusion (LFI)

### 3.1 Definition
Aplikasi memilih file lokal untuk di-`include`/`require`/`read` berdasarkan input, sehingga membaca (atau mengeksekusi sebagai kode) file di luar yang dimaksud.

Contoh anti-pola konseptual:

```php
// UNSAFE sketch — user controls path segment
include($_GET["page"] . ".php");
```

### 3.2 Why it hurts
| Outcome | Mechanism (class) |
|:---|:---|
| Information disclosure | Read configs, keys, logs |
| Code execution | Including uploaded files / logs that become PHP (when misconfigured) |
| Auth bypass | Including unexpected “pages” |

Catatan: rantai “log poisoning → include” adalah pola kelas lanjut; mitigasi adalah **jangan include path user** dan **jangan simpan konten user sebagai file yang dieksekusi**.

### 3.3 Safe pattern — allowlist map

```php
// SAFE — explicit map, no filesystem path from user
$pages = [
  "home" => __DIR__ . "/pages/home.php",
  "about" => __DIR__ . "/pages/about.php",
];
$key = $_GET["page"] ?? "home";
if (!isset($pages[$key])) {
  http_response_code(404);
  exit;
}
include $pages[$key];
```

## 4. 🌍 Remote File Inclusion (RFI)

### 🇮🇩 Bahasa Indonesia
**RFI** = inclusion/execution dari resource **remote** (URL) ketika bahasa/konfigurasi mengizinkan (historis: `allow_url_include` di PHP). Ini menggabungkan masalah trust URL dengan eksekusi kode.

### 🇬🇧 English
Modern default configs often disable remote include — still verify. Prefer never using URL-capable include. If you need remote content, **fetch as data** with SSRF controls, never `include` it as code.

### 日本語
リモートをコードとして`include`しないでください。取得するならデータとして扱い、SSRF対策を適用します。

| Control | RFI relevance |
|:---|:---|
| Disable URL includes in language runtime | Critical |
| No user-controlled include targets | Critical |
| Network egress deny | Defense in depth |

## 5. 🧭 Path Traversal Relation (CWE-22)

Traversal (`../` style concepts) sering menyertai LFI/file download:

$$
\mathsf{canon}(\mathsf{base} \,\|\, u) \;\overset{?}{\in}\; \mathsf{Tree}(\mathsf{base})
$$

**Safe file read pattern:**

```python
from pathlib import Path

BASE = Path("/var/app/static").resolve()

def read_user_file(name: str) -> bytes:
    # name: allowlist characters only, e.g. [A-Za-z0-9._-]+
    candidate = (BASE / name).resolve()
    if not candidate.is_relative_to(BASE):  # py3.9+: use try relative_to
        raise PermissionError("escape")
    return candidate.read_bytes()
```

Jangan mengandalkan filter string `../` saja (encoding, nested tricks, absolute paths).

## 6. ⚖️ Side-by-Side Summary

| Pattern | Unsafe idea | Safe idea |
|:---|:---|:---|
| Commands | `shell=True` + concat | `argv` list + allowlist |
| Includes | `include($user)` | Map key → fixed path |
| Downloads | `open("/data/"+user)` | Resolve + `is_relative_to` |
| Templates | User picks template path | Allowlist template names |
| RFI | Include URL | Disabled; never include remote code |

## 7. 🛡️ Defense-in-Depth Stack

### Command injection
1. Prefer native libraries over OS tools.  
2. `subprocess`/`execve` argv arrays; never `/bin/sh -c` with user data.  
3. Validate with allowlists (charset + length).  
4. Least privilege + sandbox.  
5. Structured logging of exit codes (not attacker-controlled command strings).

### File inclusion / traversal
1. Allowlist resource IDs.  
2. Canonicalize and enforce base directory jail.  
3. Separate **data storage** from **executable code** roots.  
4. Store uploads outside web root; serve via controlled handlers.  
5. Disable remote include features; harden `open_basedir` / chroot where applicable.  
6. PHP: jangan `include` unggahan; gunakan `readfile` untuk data jika perlu.

### 🇮🇩 Bahasa Indonesia
*The Tangled Web* relevan saat path/URL parsing tidak konsisten antar lapisan (proxy, app, FS). Selalu normalize di **satu** titik kepercayaan server-side.

### 🇬🇧 English
WAHH treats these as injection into OS and into the language runtime — review every `exec`, `system`, `popen`, `include`, `require`, `file_get_contents` with variable paths.

## 8. ✅ Developer Checklist

| Area | Check |
|:---|:---|
| Shell | No `shell=True` / `system` with request data |
| Binaries | Full path to binary; fixed flags |
| Includes | Map/allowlist only |
| Files | `resolve` + base containment |
| Uploads | Non-executable storage |
| Config | Remote include disabled |
| Tests | Attempted escape paths rejected in unit tests |
| SAST | Rules for command exec & dynamic include |

```
 User input          Safe control plane
 ──────────          ──────────────────
  host/name    ──►   allowlist / map
  path piece   ──►   jail under BASE
  “command”    ──►   fixed argv, no shell
  remote URL   ──►   never include-as-code
```

## 🔐 Security Notes — Threats & Defenses

| Threat class | Root | Defense |
|:---|:---|:---|
| Command injection | Shell grammar | Argv + allowlist |
| LFI | Dynamic include/read | ID map + jail |
| RFI | Remote-as-code | Disable; don’t include URLs |
| Traversal | Relative path escape | Canonical containment |
| Upload+include chain | Executable upload dirs | Decouple store/execute |
