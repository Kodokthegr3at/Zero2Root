## Istilah penting

Istilah-istilah ini akan sering muncul di materi.

| Istilah | Artinya |
|:---|:---|
| File upload | Fitur yang membolehkan user mengirim file ke server |
| Web shell | File unggahan berbahaya yang membuat penyerang bisa menjalankan perintah |
| Content-Type | Jenis yang dinyatakan sebuah unggahan (mudah dipalsukan, jangan dipercaya sendirian) |
| Magic bytes | Tanda jenis file sebenarnya di awal sebuah file |
| Allowlist ekstensi | Hanya menerima ekstensi file yang diketahui aman |
| Eksekusi | Bahaya sebenarnya: server menjalankan file unggahan sebagai kode |
| Re-encoding | Membangun ulang gambar untuk menghapus payload tersembunyi |

## 1. Model ancaman

Fitur unggah file mengubah klien menjadi penulis di filesystem atau object store server. WAHH menekankan dampak berantainya: kalau file yang diunggah bisa dieksekusi oleh web runtime, atau diproses oleh parser yang rentan, hasilnya bisa berupa RCE, stored XSS (lewat SVG atau HTML), SSRF lewat parser yang mengikuti URL, atau denial of service (zip bomb, penyalahgunaan dekompresi).

Web shell, sebagai konsep, adalah skrip yang diunggah lalu dipanggil lewat HTTP, sehingga server mengeksekusi perintah penyerang. Catatan ini menjelaskan cara mencegah kelas bug itu, bukan cara menulis atau mengunggahnya.

CWE-434 mencakup *Unrestricted Upload of File with Dangerous Type*. Berbahaya bukan berarti hanya "`.php`"; ini mencakup apa pun yang akan diinterpretasikan oleh environment: template, server-side include, format "dokumen" tertentu di dalam office converter, atau HTML yang disajikan dengan MIME type yang salah.

Singkatnya, unggahan berbahaya adalah tipe file apa pun yang akan diinterpretasikan atau dieksekusi oleh server atau browser, dan yang ditempatkan di sana tanpa kontrol yang memadai.

## 2. Akar masalah

| Kegagalan | Apa yang salah |
|:---|:---|
| Mempercayai `Content-Type` atau filename dari klien | Keduanya adalah metadata yang dikendalikan penyerang |
| Menyimpan di bawah web-executable root | URL langsung terpetakan ke code runtime |
| Mempertahankan ekstensi asli pengguna | `.php`, `.aspx`, `.jsp`, ekstensi ganda, titik di akhir |
| Tanpa object key acak | Overwrite, path yang bisa ditebak, cache poisoning |
| Menyajikan dengan `Content-Type` yang salah | Browser mengeksekusinya sebagai HTML/JS (XSS) |
| Memproses dengan parser yang tidak aman | Bug sekelas ImageTragick, XXE di "preview" berbasis XML |
| Symlink atau path yang disematkan di filename | Traversal ke direktori lain |

## 3. Validasi konten, prinsip

### 3.1 Pemeriksaan berlapis (tak satu pun cukup sendirian)

1. Allowlist ekstensi, misalnya `{png,jpg,webp,pdf}`, dipetakan di server.
2. Sniffing magic-byte / gaya `file(1)`, dicek terhadap tipe yang dideklarasikan.
3. Re-encode atau transcode: untuk gambar, decode lalu tulis file baru dengan library tepercaya, yang menghancurkan sebagian besar trik polyglot.
4. Batas ukuran, baik per file maupun kuota per pengguna.
5. Buang filename: jangan pernah memakai ulang filename mentah dari pengguna sebagai storage key.

```text
terima file hanya jika:
  ekstensinya ada di allowlist
  dan magic byte-nya cocok dengan ekstensi itu
  dan ukurannya ≤ batas
```

### 3.2 Polyglot (konsep)

Satu file bisa valid sebagai lebih dari satu format, misalnya gambar plus konten skrip yang disematkan, tergantung parser mana yang membacanya. Re-encoding, plus `Content-Type` yang ketat saat penyajian, mengurangi risiko ini.

### 3.3 SVG / HTML

SVG bisa mengandung skrip kalau disajikan inline sebagai `image/svg+xml` di konteks tertentu. Opsi yang lebih aman: rasterize SVG ke PNG di sisi server, atau sajikan dengan `Content-Disposition: attachment` plus CSP yang ketat.

## 4. Desain penyimpanan aman

```
 ┌──────── viewer / CDN ────────┐
 │  signed URL, short TTL       │
 └─────────────▲────────────────┘
               │
 ┌─────────────┴────────────────┐
 │ Object store bucket          │
 │  - random keys               │
 │  - no public execute         │
 │  - antivirus/async scan opt. │
 └─────────────▲────────────────┘
               │
         app writes only
```

Prinsip:

- Simpan file di luar document root, atau di bucket yang sama sekali tidak menjalankan skrip.
- Object key: UUID plus ekstensi tetap yang diambil dari allowlist.
- Database memetakan `user_id → object_key → declared_type`.
- Akses hanya lewat handler download yang berotorisasi atau signed URL.
- Di Apache/Nginx, blok `location` untuk direktori upload secara eksplisit menonaktifkan script engine, yang merupakan pertahanan berlapis meski lapisan lain salah konfigurasi.

## 5. Penghalang eksekusi

Tujuannya: membuka file unggahan lewat HTTP tidak boleh pernah menjalankan kode di server.

Kontrol:

- Jangan pernah petakan path unggahan ke interpreter PHP, ASP, atau JSP.
- Header download: `Content-Type` yang benar, plus `X-Content-Type-Options: nosniff`.
- `Content-Disposition: attachment` untuk tipe yang berisiko.
- Nonaktifkan handler di folder upload di lapisan ops/config (sesuaikan dengan stack Anda sendiri).

Bahkan dengan pengecekan ekstensi yang sempurna sekalipun, bug lain di tempat berbeda (LFI dari path unggahan, atau template include) bisa menghidupkan kembali risikonya. Jaga agar unggahan tetap non-executable dan tidak bisa di-include sebagai kode, terlepas dari sebaik apa pengecekan unggahannya sendiri.

## 6. Pola berbahaya vs aman

### 6.1 Berbahaya

```python
# UNSAFE — trusts filename & stores in web root
f = request.files["file"]
f.save("/var/www/html/uploads/" + f.filename)
# later: https://app/uploads/evil.php may execute if PHP enabled there
```

### 6.2 Sketsa yang lebih aman

```python
import uuid
from pathlib import Path

ALLOWED = {
    "image/png": ".png",
    "image/jpeg": ".jpg",
}
STORE = Path("/var/app/upload_data")  # not served as scripts

def save_upload(file_storage, sniffed_mime: str) -> str:
    if sniffed_mime not in ALLOWED:
        raise ValueError("type")
    if file_storage.content_length and file_storage.content_length > 5_000_000:
        raise ValueError("size")
    key = f"{uuid.uuid4().hex}{ALLOWED[sniffed_mime]}"
    dest = STORE / key
    # Prefer: decode/re-encode image here instead of raw save when applicable
    file_storage.save(dest)
    return key
```

```nginx
# Defense-in-depth example: deny script execution in a mistaken alias
location ^~ /media/ {
    internal;  # or alias to read-only files with types {}
    add_header X-Content-Type-Options nosniff always;
    default_type application/octet-stream;
}
```

## 7. Prosesor media dan dokumen

Unggahan sering diproses lebih lanjut: thumbnail, virus scan, atau konversi office-ke-PDF.

| Kelas risiko | Mitigasi |
|:---|:---|
| Command injection di CLI converter | Array argv; allowlist; sandbox |
| Kerentanan parser (gambar, XML, font) | Library terbaru; isolasi worker; batas resource |
| XXE di format berbasis XML | Nonaktifkan external entity; pakai parser aman |
| Zip bomb / rasio kompresi | Batasi ukuran hasil dekompresi dan jumlah entry |
| SSRF lewat resource tertaut remote | Nonaktifkan akses jaringan di dalam worker |

Jalankan worker pemrosesan secara terisolasi: container non-root, tanpa egress, seccomp diterapkan.

## 8. Tumpukan pertahanan berlapis

1. AuthN/AuthZ pada API upload, mengontrol siapa boleh mengunggah apa.
2. Allowlist MIME type, magic byte, dan ukuran.
3. Key acak; buang filename pengguna.
4. Re-encode gambar bila memungkinkan.
5. Penyimpanan non-executable, di bucket atau akun terpisah.
6. Header penyajian yang aman, atau signed URL.
7. Pemindaian malware asinkron bila masuk akal.
8. Rate limit dan kuota.
9. Monitoring untuk lonjakan error upload atau tipe object baru yang tidak terduga.
10. Tidak ada path include atau LFI yang bisa mengarah balik ke direktori upload.

## 9. Checklist developer

| Cek | Kriteria lulus |
|:---|:---|
| Lokasi penyimpanan | Di luar script root |
| Kebijakan tipe | Allowlist plus pengecekan magic-byte |
| Filename | Dibuat server |
| Penyajian | `nosniff` plus MIME type yang benar |
| SVG/HTML | Di-rasterize, atau dipaksa diunduh sebagai attachment |
| Worker | Converter yang di-sandbox |
| Path | Tidak ada direktori tujuan yang dikendalikan pengguna |
| Test | Tipe terlarang ditolak; konfigurasi non-exec diverifikasi |

```
 Client file
    │
    ▼
 Validate type/size ──► Re-encode? ──► Store random key
    │                                   │
    └ reject                            ▼
                              Serve via authz + safe headers
```

## Catatan keamanan: ancaman dan pertahanan

| Pola ancaman | Kelas | Pertahanan |
|:---|:---|:---|
| Unggahan executable | RCE lewat web runtime | Penyimpanan non-exec plus allowlist tipe |
| Stored XSS lewat HTML/SVG | Eksekusi skrip di browser | Kontrol MIME, CSP, sanitasi atau rasterize |
| Overwrite file kritis | Integrity | Key acak; tanpa path dari pengguna |
| Arsip berbahaya | DoS, atau path write | Batasan; ekstraksi aman |
| Penyalahgunaan converter | RCE/SSRF | Sandbox; array argv; tanpa egress |
