## 1. Akar masalah bersama: mencampur kode dan data

Command injection dan file inclusion adalah saudara dari SQL injection; WAHH menyebut seluruh keluarga ini "injecting into interpreted languages." String yang dipengaruhi penyerang digabung ke sesuatu yang akan diinterpretasikan: shell, `include` PHP, template engine, dan sejenisnya.

$$
\mathsf{Interpreter}(T_0 \,\|\, u \,\|\, T_1)
\;\neq\;
\mathsf{Interpreter}(T_0 \,\|\, \mathsf{lit}(u) \,\|\, T_1)
$$

Ketika $u$ bisa mengubah cara interpreter mem-parsing input, data berubah menjadi kode, atau menjadi path di luar kontrak yang dimaksud.

Perbaikan utamanya selalu struktural: jangan memulai shell, jangan meng-include path sembarang, dan gunakan API yang menerima vektor argumen atau resource tetap yang sudah di-allowlist, alih-alih membangun string lalu menyerahkannya ke interpreter.

## 2. Injeksi perintah OS (CWE-78)

### 2.1 Kapan ini muncul

Ini muncul di fitur apa pun yang memanggil tool eksternal: ImageMagick, `ping`, converter, wrapper git, skrip backup, atau utilitas admin "diagnose hostname".

### 2.2 Pola berbahaya

Metakarakter shell, secara konsep: pemisah perintah, substitusi, pipe, mengubah satu perintah yang dimaksud menjadi beberapa perintah. Catatan ini tidak mendaftar katalog payload; poinnya adalah memahami kelas risikonya.

### 2.3 Pendekatan aman: array argv, tanpa shell

```python
# UNSAFE — shell=True + user input
os.system("ping -c 1 " + host)
subprocess.call("convert " + user_path + " out.png", shell=True)

# SAFE — no shell; fixed executable; validate host/path first
subprocess.run(
    ["/usr/bin/ping", "-c", "1", "--", host],
    check=False,
    capture_output=True,
    timeout=3,
)
# host must still match allowlist regex (e.g. DNS label rules)
```

```php
// UNSAFE
shell_exec("dig " . $_GET["d"]);

// SAFER — avoid shell; use library or escapeshellarg *only* if shell unavoidable
// Best: do not expose dig; use PHP DNS APIs / internal service
```

Kalau shell benar-benar tidak terhindarkan, pakai `escapeshellarg` atau yang setara di platform Anda, tapi pahami bahwa itu tetap lebih lemah dibanding array argv.

### 2.4 Tambahan pertahanan

- Allowlist argumen sebagai enum job yang dikenal, bukan string bebas.
- Turunkan privilege; terapkan seccomp atau AppArmor; jaga container bebas dari binary yang tidak perlu.
- Hapus utilitas debugging dari image produksi.

## 3. Local File Inclusion (LFI)

### 3.1 Definisi

Aplikasi memilih file lokal untuk di-`include`, `require`, atau dibaca berdasarkan input, sehingga berujung membaca, atau di beberapa bahasa mengeksekusi sebagai kode, file di luar yang dimaksud.

Anti-pola konseptual:

```php
// UNSAFE sketch — user controls path segment
include($_GET["page"] . ".php");
```

### 3.2 Mengapa ini berbahaya

| Akibat | Mekanisme (kelas) |
|:---|:---|
| Information disclosure | Membaca config, key, log |
| Code execution | Meng-include file unggahan atau log yang berubah jadi PHP yang bisa dieksekusi kalau salah konfigurasi |
| Auth bypass | Meng-include "halaman" yang tidak terduga |

Rantai "log poisoning ke include" adalah versi lanjut dari kelas yang sama; mitigasinya tetap sama: jangan include path dari pengguna, dan jangan simpan konten pengguna sebagai file yang nanti dieksekusi.

### 3.3 Pola aman: allowlist map

```php
// SAFE — explicit map, no filesystem path from user
$pages = [
  "home" => __DIR__ . "/pages/home.php",
  "about" => __DIR__ . "/pages/about.php",
];
$key = $_GET["page"] ?? "home";
if (!isset($pages[$key])) {
  http_response_code(404);
  exit;
}
include $pages[$key];
```

## 4. Remote File Inclusion (RFI)

RFI adalah inclusion atau eksekusi resource remote (URL) ketika bahasa atau konfigurasi mengizinkannya, secara historis `allow_url_include` di PHP. Ini menggabungkan masalah kepercayaan URL dengan eksekusi kode.

Konfigurasi default modern sering menonaktifkan remote include, tapi verifikasi hal itu, jangan hanya mengasumsikannya. Utamakan tidak pernah memakai include yang menerima URL sama sekali. Kalau butuh konten remote, ambil sebagai data dengan kontrol SSRF diterapkan, jangan pernah `include` sebagai kode.

| Kontrol | Relevansi RFI |
|:---|:---|
| Nonaktifkan URL include di language runtime | Kritis |
| Tanpa target include yang dikendalikan pengguna | Kritis |
| Network egress deny | Pertahanan berlapis |

## 5. Hubungan dengan path traversal (CWE-22)

Path traversal, kelas trik gaya `../`, sering menyertai fitur LFI dan download file.

$$
\mathsf{canon}(\mathsf{base} \,\|\, u) \;\overset{?}{\in}\; \mathsf{Tree}(\mathsf{base})
$$

Pola baca file yang aman:

```python
from pathlib import Path

BASE = Path("/var/app/static").resolve()

def read_user_file(name: str) -> bytes:
    # name: allowlist characters only, e.g. [A-Za-z0-9._-]+
    candidate = (BASE / name).resolve()
    if not candidate.is_relative_to(BASE):  # py3.9+: use try relative_to
        raise PermissionError("escape")
    return candidate.read_bytes()
```

Jangan mengandalkan penyaringan string literal `../` saja; trik encoding, urutan bersarang, dan path absolut semuanya bisa melewati filter yang naif.

## 6. Ringkasan berdampingan

| Pola | Ide berbahaya | Ide aman |
|:---|:---|:---|
| Perintah | `shell=True` plus konkatenasi string | List `argv` plus allowlist |
| Include | `include($user)` | Map dari key ke path tetap |
| Download | `open("/data/"+user)` | `resolve()` plus `is_relative_to` |
| Template | Pengguna memilih path template | Allowlist nama template |
| RFI | Meng-include URL | Dinonaktifkan; jangan pernah include kode remote |

## 7. Tumpukan pertahanan berlapis

### Command injection

1. Utamakan library native dibanding memanggil tool OS lewat shell.
2. Pakai array argv `subprocess` atau `execve`; jangan pernah `/bin/sh -c` dengan data pengguna.
3. Validasi dengan allowlist (charset plus panjang).
4. Least privilege plus sandbox.
5. Logging terstruktur untuk exit code, bukan string perintah yang dikendalikan penyerang.

### File inclusion dan traversal

1. Allowlist ID resource.
2. Kanonisasi path dan tegakkan base-directory jail.
3. Pisahkan root direktori penyimpanan data dari root kode yang dieksekusi.
4. Simpan unggahan di luar web root; sajikan lewat handler yang terkontrol.
5. Nonaktifkan fitur remote-include bahasa; hardening `open_basedir` atau chroot bila relevan.
6. Di PHP, jangan pernah `include` file unggahan; pakai `readfile` untuk menyajikan data kalau perlu.

*The Tangled Web* relevan di sini karena parsing path dan URL sering tidak sepakat antar lapisan (proxy, aplikasi, filesystem). Selalu normalisasi di satu titik kepercayaan sisi server.

WAHH memperlakukan ini sebagai injeksi ke OS dan ke language runtime; tinjau setiap pemanggilan `exec`, `system`, `popen`, `include`, `require`, dan `file_get_contents` yang menerima path variabel.

## 8. Checklist developer

| Area | Cek |
|:---|:---|
| Shell | Tanpa `shell=True` / `system` dengan data request |
| Binary | Path lengkap ke binary; flag tetap |
| Include | Hanya map atau allowlist |
| File | `resolve()` plus containment base |
| Upload | Disimpan di lokasi non-executable |
| Config | Remote include dinonaktifkan |
| Test | Percobaan escape path ditolak di unit test |
| SAST | Rule mencakup command exec dan dynamic include |

```
 User input          Safe control plane
 ──────────          ──────────────────
  host/name    ──►   allowlist / map
  path piece   ──►   jail under BASE
  "command"    ──►   fixed argv, no shell
  remote URL   ──►   never include-as-code
```

## Catatan keamanan: ancaman dan pertahanan

| Kelas ancaman | Akar | Pertahanan |
|:---|:---|:---|
| Command injection | Grammar shell | Argv plus allowlist |
| LFI | Include atau read dinamis | ID map plus jail |
| RFI | Konten remote diperlakukan sebagai kode | Nonaktifkan; jangan pernah include URL |
| Traversal | Escape path relatif | Containment kanonik |
| Rantai upload+include | Direktori upload yang executable | Pisahkan penyimpanan dari eksekusi |
