## 1. 🧬 JSON Web Token (JWT) Anatomy

JWT terdiri dari tiga bagian berbasis string Base64Url yang dipisahkan oleh tanda titik (`.`):

$$\underbrace{\text{eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9}}_{\text{Header}}.\underbrace{\text{eyJzdWIiOiIxMjM0NTY3ODkwIiwidXNlciI6ImFkbWluIn0}}_{\text{Payload}}.\underbrace{\text{TJVA95OrM7E2cBab30RMHrHDcEfxjoYZgeFONFh7HgQ}}_{\text{Signature}}$$

- **Header**: Mendefinisikan algoritma penandatanganan kriptografi (misal `HS256`, `RS256`, `none`).
- **Payload**: Berisi klaim pengguna (*claims*: `sub`, `user`, `role`, `exp`).
- **Signature**: Hash kriptografi dari `Header + Payload` menggunakan kunci rahasia server.

---

## 2. 💥 High-Impact JWT Attack Vectors

### 1. The `alg: none` Vulnerability (Unsigned Token)
Jika pustaka parser JWT di server menerima algoritma `none`, penyerang cukup memodifikasi payload menjadi `role: admin`, menyetel header `{"alg":"none"}`, dan menghapus tanda tangan:

```json
Header:  {"alg": "none", "typ": "JWT"}
Payload: {"user": "attacker", "role": "admin"}
Signature: (Kosong)
Result:  eyJhbGciOiJub25lIiwidHlwIjoiSldUIn0.eyJ1c2VyIjoiYXR0YWNrZXIiLCJyb2xlIjoiYWRtaW4ifQ.
```

### 2. HMAC Secret Brute-Forcing
Jika token menggunakan algoritma simetris `HS256`, penyerang dapat melakukan cracking password rahasia server secara offline menggunakan **Hashcat** atau **jwt_tool**:

```bash
hashcat -m 16500 jwt_token.txt /usr/share/wordlists/rockyou.txt
```

### 3. Algorithm Confusion (Key Confusion: RS256 to HS256)
- Aplikasi biasanya menggunakan kunci publik RSA (`RS256`) untuk memverifikasi tanda tangan.
- Jika penyerang mengubah header token menjadi `HS256` (HMAC), dan server salah mengimplementasikan verifikasi dengan memperlakukan **kunci publik RSA (yang dapat diunduh siapa saja)** sebagai **kunci rahasia HMAC**, penyerang dapat menandatangani token admin palsu yang sah!

---

## 3. 🛡️ Robust Authentication & JWT Defenses

1. **Explicit Algorithm Whitelisting**: Jangan percayai header `alg` dari client. Hardcode algoritma verifikasi di server:
   ```javascript
   jwt.verify(token, publicKey, { algorithms: ['RS256'] });
   ```
2. **Short Token Lifetimes**: Tetapkan masa berlaku JWT singkat (misal 5–15 menit) dan gunakan **Refresh Token Rotation** yang disimpan dalam cookie `HttpOnly; Secure; SameSite=Strict`.
3. **Session Invalidation**: Simpan daftar token yang dicabut (*revocation blacklist*) di cache Redis in-memory untuk logout instan.
