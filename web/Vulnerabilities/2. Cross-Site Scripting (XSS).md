## 1. 🌐 Browser Trust Model (*The Tangled Web*)

### 🇮🇩 Bahasa Indonesia
Browser menjalankan JavaScript dengan hak **origin** dokumen (Same-Origin Policy). Jika penyerang menyuntikkan skrip ke halaman origin aplikasi, skrip itu berjalan sebagai bagian dari aplikasi: dapat memanggil API same-origin, membaca DOM, dan dalam banyak kasus menyalahgunakan sesi pengguna yang sedang login (**session riding via script**, distinct from classical CSRF).

XSS = kegagalan menjaga batas: **data tidak dipercaya diperlakukan sebagai kode aktif**.

### 🇬🇧 English
Zalewski’s *Tangled Web* frames XSS as a **confused deputy** inside the browser: the victim’s browser is deputized to run attacker-controlled script with the site’s privileges. Fixing XSS is about **safe composition of untrusted strings into documents and scripts**, not about “filtering bad words.”

### 日本語
XSSは、信頼できない文字列をHTML/JSとして解釈させてしまうことで、被害者のブラウザが攻撃者のコードを**そのオリジンの権限**で実行する問題です。

## 2. 📚 XSS Classes (Conceptual)

| Class | Where script is introduced | Persistence | Typical sink |
|:---|:---|:---|:---|
| **Reflected** | Request → immediate response | No | Search echo, error messages |
| **Stored** | Saved then served to victims | Yes | Comments, profiles, tickets |
| **DOM-based** | Client-side JS writes untrusted data into dangerous sinks | Varies | `innerHTML`, `document.write`, URL → HTML |

### 🇮🇩 Bahasa Indonesia
WAHH memisahkan reflected vs stored berdasarkan **apakah aplikasi menyimpan** data berbahaya. DOM XSS terjadi meski server “benar”, jika JavaScript klien menggabungkan `location`, `postMessage`, atau fragment ke sink berbahaya.

### 🇬🇧 English
All three share one root: a **JavaScript (or HTML markup) injection sink** consumes attacker-influenced data without context-appropriate encoding or safe APIs.

### 日本語
共通点は、攻撃者の影響を受けたデータが**危険なシンク**にエンコードなしで渡ることにあります。

## 3. 🧮 Output Contexts — Encoding Is Context-Dependent

Misalkan string tidak dipercaya $u$ disisipkan ke dokumen. Encoding yang benar bergantung pada **konteks gramatikal**:

| Context | Dangerous if raw | Safe approach (principle) |
|:---|:---|:---|
| HTML body text | Markup / tags interpreted | HTML entity encode |
| HTML attribute (quoted) | Break out of quotes | Attribute encode + always quote attrs |
| JavaScript string literal | Break out of JS string | JS string encode / avoid inline |
| URL query / path | `javascript:` / rogue scheme | URL encode + scheme allowlist |
| CSS | Expressions / escapes (legacy) | Avoid untrusted CSS; strict allowlist |
| JSON in `<script>` | `</script>` breakouts | Safe JSON serialization patterns |

Secara formal, encoding $E_c$ untuk konteks $c$ harus memastikan:

$$
\mathsf{parse}_c\big(T_0 \,\|\, E_c(u) \,\|\, T_1\big)
\;=\;
\mathsf{parse}_c\big(T_0 \,\|\, \mathsf{data}(u) \,\|\, T_1\big)
$$

yaitu $u$ tetap **data**, bukan non-terminal baru dalam grammar $c$.

### 🇮🇩 Bahasa Indonesia
Satu fungsi “escape HTML” **tidak** cukup untuk semua konteks. Menyisipkan ke event handler (`onclick=...`) atau ke URL adalah konteks berbeda.

### 🇬🇧 English
Prefer **not putting untrusted data in script/style contexts at all**. Pass data via `data-*` + `textContent`, or `JSON.parse` of correctly escaped JSON blobs designed for that purpose.

### 日本語
信頼できないデータを`<script>`やイベントハンドラに埋め込まないのが最善です。`textContent`や安全なデータ受け渡しを使います。

## 4. 🧬 Root Cause Patterns

1. **Server HTML concatenation** of request/DB fields into templates without auto-escaping.
2. **Disabled escaping** in template engines (`| safe`, `raw`, `{{{ }}}`).
3. **DOM sinks** that parse HTML (`innerHTML`, `outerHTML`, `insertAdjacentHTML`).
4. **jQuery-like** APIs that interpret strings as HTML (`$(userString)`).
5. **Mishandled `postMessage`** / `outerHTML` of rich widgets.
6. **Content-Type confusion** — user content served as `text/html` instead of attachment / safe type.

## 5. ⚖️ Unsafe vs Safe Patterns

### 5.1 HTML body

```html
<!-- UNSAFE (template sketch) -->
<p>Hello {{ user.name }}</p>
<!-- dangerous if engine does not auto-escape, or name contains markup -->
```

```javascript
// UNSAFE
el.innerHTML = "Hello " + userName;

// SAFE — text node, not HTML parser
el.textContent = "Hello " + userName;
```

### 5.2 Attributes

```html
<!-- UNSAFE -->
<img src="{{ url }}">
<!-- prefer scheme allowlist https: only; never untrusted javascript: -->

<!-- SAFER pattern: fixed attribute structure + encoded value + validation -->
<a href="https://example.com/u?id={{ id | urlencode }}">profile</a>
```

### 5.3 Avoid inline script concatenation

```html
<!-- UNSAFE pattern -->
<script>var u = "{{ user_input }}";</script>
```

```html
<!-- SAFER: data island consumed as text, then JSON.parse -->
<div id="cfg" data-user=""></div>
<script>
  const raw = document.getElementById('cfg').dataset.user;
  // populate dataset from server with HTML-attribute encoding;
  // or serve application/json on a separate endpoint
</script>
```

### 5.4 Framework defaults
Modern frameworks (React `{}` text children, Angular default escaping, Vue text interpolation) reduce XSS **if developers avoid** `dangerouslySetInnerHTML` / `[innerHTML]` / `v-html` without sanitizer.

## 6. 🛡️ CSP, Cookie Flags & Trusted Types

### 6.1 Content-Security-Policy (defense in depth)

CSP membatasi asal skrip yang boleh berjalan. Kebijakan ketat:

- `default-src 'self'`
- `script-src` dengan **nonce** atau **hash** (hindari `'unsafe-inline'` / `'unsafe-eval'` bila memungkinkan)
- `object-src 'none'`; `base-uri 'none'`; `frame-ancestors` sesuai kebutuhan

CSP **bukan** pengganti encoding; CSP adalah jaring pengaman saat ada regresi.

### 6.2 Cookie hardening (session impact reduction)

| Attribute | Effect |
|:---|:---|
| `HttpOnly` | Blocks `document.cookie` access to that cookie |
| `Secure` | Sent only over TLS |
| `SameSite=Lax/Strict` | Reduces cross-site cookie sends (CSRF-related) |
| `__Host-` prefix | Cookie path/domain constraints |

`HttpOnly` mengurangi pencurian cookie via XSS, tetapi XSS tetap dapat memanggil API sebagai korban.

### 6.3 Trusted Types (where supported)
Browser policy yang memaksa assignment berbahaya (`innerHTML`, etc.) hanya menerima objek bertipe trusted dari policy factory — mendorong sink review.

### 🇮🇩 Bahasa Indonesia
*The Tangled Web* menekankan kompleksitas parser HTML/JS. Semakin sedikit konteks “string → HTML”, semakin kecil permukaan XSS.

### 🇬🇧 English
Sanitize HTML **only** when rich text is a product requirement; use a well-maintained sanitizer configured with an allowlist of tags/attrs — never regex “strip scripts.”

### 日本語
リッチテキストが必要なら、許可リスト型のサニタイザを使います。正規表現で`<script>`を除去する方式は避けます。

## 7. 🧭 DOM XSS — Sources & Sinks (Defensive Map)

| Untrusted sources (examples) | Dangerous sinks (examples) |
|:---|:---|
| `location`, `location.hash`, `location.search` | `innerHTML`, `outerHTML`, `document.write` |
| `document.referrer` | `eval`, `new Function`, `setTimeout(string)` |
| `postMessage` event `data` | `element.src` / `href` with unvalidated URL |
| Web storage values copied to HTML | jQuery HTML-interpreting APIs |

**Defense:** treat all sources as untrusted; use safe sinks (`textContent`, `setAttribute` with validated values); validate `postMessage` `origin` + schema.

---

## 8. 🧱 Defense-in-Depth Stack

1. **Context-aware output encoding** / framework auto-escape on by default.  
2. **Avoid dangerous sinks**; ban `v-html` / `dangerouslySetInnerHTML` without review.  
3. **HTML sanitizer allowlist** only for rich content.  
4. **CSP** nonces/hashes; strip `unsafe-inline` over time.  
5. **Cookie flags** + short session lifetime + re-auth for sensitive actions.  
6. **Security headers:** see HTTP series (`X-Content-Type-Options`, etc.).  
7. **Code review + SAST** for raw HTML sinks.  
8. **Abuse reporting / CSP report-to** in production (careful with PII).

## 🔐 Security Notes — Threats & Defenses

| Threat pattern | Mechanism | Defense |
|:---|:---|:---|
| Reflected XSS | Request echoed into HTML | Encode; CSP; don’t reflect raw |
| Stored XSS | Persisted content to other users | Encode on output; sanitize rich text |
| DOM XSS | Client sink parses attacker data | Safe DOM APIs; CSP |
| Mutation / mXSS | Sanitizer vs browser parser mismatch | Battle-tested sanitizer; simplify HTML |
| JS in PDF/flash legacy | Plugin surfaces | Disable plugins; modern browsers |
