## 1. Header field model

A header is a name/value pair in the start line of a message (RFC 9110). Names are case-insensitive; values must be free of dangerous control characters. Many web security features are expressed only through response headers, including `CSP`, `Set-Cookie`, and `HSTS`.

```text
Name: value

Content-Type: text/html; charset=utf-8
```

*The Tangled Web* makes a point worth keeping in mind: the browser is a complicated trust engine, and headers are policy levers that need to be set deliberately, not copy-pasted from somewhere without understanding them.

Never trust request headers for authorization alone (`X-Forwarded-For`, `X-Original-URL`, and a `Host` that can be spoofed behind a misconfigured proxy). Treat them as hints until a trusted edge normalizes them.

## 2. Core request headers

<img width="626" height="401" alt="image" src="https://github.com/user-attachments/assets/923366e1-b7c0-4c29-be66-052cfc1d22bf" />

| Header | Role | Security note |
|:---|:---|:---|
| `Host` | Virtual host | Reject invalid values; do not trust the raw value for SSRF decisions |
| `User-Agent` | Client product token | Do not authenticate on UA; log it carefully |
| `Authorization` | Credentials | Bearer, JWT, or Basic; TLS only; never in logs |
| `Cookie` | Stored state | CSRF and XSS interactions |
| `Origin` | Fetch initiating origin | CORS decisions |
| `Referer` | Navigation source | Privacy concern; may leak tokens embedded in URLs |
| `Accept` | Preferred media types | Content negotiation |
| `Content-Type` | Body type | Enforce it on mutating endpoints |
| `If-None-Match` / `If-Modified-Since` | Conditionals | Cache correctness |
| `Sec-Fetch-*` | Fetch metadata | CSRF isolation policies |
| `X-Forwarded-For` | Client IP via proxy | Spoofable unless the trusted hop enforces it |

```http
GET /api/profile HTTP/1.1
Host: app.lab.local
Authorization: Bearer <access_token>
Cookie: session=<sid>
Origin: https://app.lab.local
Sec-Fetch-Site: same-origin
Sec-Fetch-Mode: cors
Accept: application/json
```

## 4. Security response headers, baseline

### 4.1 Table: modern baseline

<img width="748" height="472" alt="image" src="https://github.com/user-attachments/assets/b7b95d03-366c-45c2-99e1-97a1e965782a" />

| Header | Example direction | Mitigates |
|:---|:---|:---|
| `Content-Security-Policy` | `default-src 'self'; script-src 'nonce-...'` | Reduces XSS impact |
| `Strict-Transport-Security` | `max-age=31536000; includeSubDomains` | Downgrade attacks, cookie-stripping issues |
| `X-Content-Type-Options` | `nosniff` | MIME-sniffing XSS |
| `Referrer-Policy` | `strict-origin-when-cross-origin` | Token leaks via Referer |
| `Permissions-Policy` | Disable unused powerful APIs | Feature abuse |
| `Cross-Origin-Opener-Policy` | `same-origin` | Cross-origin window attacks |
| `Cross-Origin-Resource-Policy` | `same-origin` / `same-site` | Spectre-adjacent resource-read classes |
| `Cross-Origin-Embedder-Policy` | `require-corp` (when needed) | Isolation, paired with COOP |
| `X-Frame-Options` | `DENY` / `SAMEORIGIN` | Clickjacking (legacy; prefer CSP `frame-ancestors`) |

### 4.2 CSP sketch

A solid CSP sets at least these directives: `default-src`, `script-src`, `object-src`, `base-uri`, and `frame-ancestors`.

Prefer nonces or hashes over `'unsafe-inline'`. CSP is defense in depth. It is not a license to skip output encoding; see the XSS note.

### 4.3 HSTS

```http
Strict-Transport-Security: max-age=31536000; includeSubDomains; preload
```

Only enable it once HTTPS is correctly deployed across all included subdomains.

Per WAHH-style lab hardening, audit headers on the login response, the JSON API, and file downloads; policies are often inconsistent across routes.

Start with report-only CSP (`Content-Security-Policy-Report-Only`) on a brownfield production app, then move to enforcement.

## 5. Cookie attributes (RFC 6265)

```text
Set-Cookie: session=abc123; Secure; HttpOnly; SameSite=Lax; Path=/
```

| Attribute | Purpose |
|:---|:---|
| `Secure` | HTTPS-only transport |
| `HttpOnly` | Hidden from `document.cookie` |
| `SameSite=Strict\|Lax\|None` | Cross-site send policy (`None` requires `Secure`) |
| `Max-Age` / `Expires` | Lifetime |
| `Path` / `Domain` | Scope; keep it narrow |
| `__Host-` / `__Secure-` | Prefix rules for stronger cookies |

Session cookie baseline for many apps:

```http
Set-Cookie: __Host-session=...; Path=/; Secure; HttpOnly; SameSite=Lax
```

## 6. Same-origin policy and CORS

### 6.1 SOP (browser)

A script from origin A cannot read responses from origin B by default. Cross-origin writes, such as form posts, still happen, which is the root of the CSRF class.

### 6.2 CORS

A server opts into controlled reads via:

| Header | Meaning |
|:---|:---|
| `Access-Control-Allow-Origin` | Exact origin, or (non-credentialed) `*` |
| `Access-Control-Allow-Credentials` | Allows cookies; forbids the `*` origin |
| `Access-Control-Allow-Methods` | Methods allowed for preflight |
| `Access-Control-Allow-Headers` | Request headers allowed |
| `Access-Control-Max-Age` | Preflight cache duration |

Safe pattern: reflect only allowlisted origins:

```text
Origin is on the allowlist  → Access-Control-Allow-Origin: <that origin>
otherwise                   → leave the header out
```

Never set `ACAO = request.Origin` for an arbitrary origin combined with credentials.

## 7. Header injection and trust failures

| Class | Idea | Defense |
|:---|:---|:---|
| CRLF injection | Attacker inserts `\r\n` into a header value, enabling response splitting or cookie injection | Strip CR/LF; use framework cookie APIs |
| Host header attacks | Poison absolute-URL generation or cache keys | Enforce a trusted `Host` / `X-Forwarded-Host` policy |
| Cache poisoning | An unkeyed header influences the cached body | Vary correctly; ignore untrusted inputs in the cache key |
| IP spoofing via `XFF` | AuthZ decisions based on a client IP taken from a header | Trust only the last hop from your own proxy |
| Verbose `Server` / `X-Powered-By` | Aids reconnaissance | Remove or genericize |

```python
# UNSAFE sketch
location = "https://app/" + user_next  # open redirect, and header issues if mis-sent

# SAFE - allowlist the path
ALLOWED = {"/home", "/settings"}
if user_next not in ALLOWED:
    user_next = "/home"
# use the framework's redirect helper (encodes safely)
```

## 8. Authorized header audit with curl

```bash
# OWN LAB - dump security-relevant response headers
curl -sSI https://localhost:8443/login | egrep -i \
  'HTTP/|content-security-policy|strict-transport|x-content-type|referrer-policy|permissions-policy|set-cookie|access-control|x-frame|cross-origin'

# Check the redirect target
curl -sSI https://localhost:8443/old | egrep -i 'HTTP/|location'

# Observe a CORS preflight against YOUR API
curl -sSI -X OPTIONS https://localhost:8443/api/data \
  -H "Origin: https://app.lab.local" \
  -H "Access-Control-Request-Method: PUT" \
  -H "Access-Control-Request-Headers: authorization,content-type"
```

Interpret the results against the baseline table, and fix the server configuration or application middleware. Bypassing a control is never the goal here.

## 9. Baseline checklist

| Control | Target |
|:---|:---|
| HTTPS + HSTS | On for production hosts |
| `nosniff` | All responses |
| CSP | Nonce or hash based; no unnecessary `unsafe-inline` |
| `frame-ancestors` / XFO | Clickjacking defense |
| Referrer-Policy | Non-leaky default |
| Cookies | `Secure; HttpOnly; SameSite` |
| CORS | Explicit allowlist; never credentials plus `*` |
| Cache | `no-store` for authenticated JSON/HTML |
| Strip | `X-Powered-By` / a detailed `Server` value |
| Proxies | Normalize `Host` and forwarding headers |

```
 Browser trust levers              Server must set intentionally
 -------------------               -----------------------------
 CSP / COOP / CORP        <------  security middleware
 Cookie flags             <------  session layer
 CORS ACAO                <------  API gateway / app
 HSTS                     <------  TLS-enabled edge
```

## Security notes: threats and defenses

| Threat | Header angle | Defense |
|:---|:---|:---|
| XSS | CSP, nosniff, encoding | Defense in depth |
| CSRF | SameSite, tokens, Sec-Fetch | See the CSRF note |
| Clickjacking | `frame-ancestors` | Deny by default |
| MITM downgrade | HSTS | Correct HTTPS deployment first |
| Token in Referer | Referrer-Policy | No secrets in URLs |
| Mis-configured CORS | ACAO reflection | Allowlist |
| Response splitting | CR/LF in header values | Reject them; use framework APIs |
