## 1. 📡 HTTP in the Network Stack

### 🇮🇩 Bahasa Indonesia
**HTTP** (Hypertext Transfer Protocol) adalah protokol **aplikasi** untuk manipulasi resource beridentitas URI. Semantik inti (metode, status, header) didefinisikan di **RFC 9110**; mapping ke koneksi TCP klasik di **RFC 9112** (HTTP/1.1).

$$
\text{Client} \;\xrightarrow{\text{request}}\; \text{Server} \;\xrightarrow{\text{response}}\; \text{Client}
$$

HTTP sendiri **tidak** menyediakan kerahasiaan/integritas — itu peran **TLS** (HTTPS). Port de-facto: `80` (cleartext), `443` (TLS).

### 🇬🇧 English
WAHH treats HTTP fluency as the foundation for understanding almost every web vulnerability class: injection sinks appear in parameters, headers, and bodies; trust decisions appear in cookies and origins (*Tangled Web*).

### 日本語
HTTPはリソース操作の意味論を定義します。機密性はTLS（HTTPS）が担います。脆弱性理解の土台です。

| Layer | Example | Security note |
|:---|:---|:---|
| Application | HTTP methods, headers | AuthZ, input trust |
| Presentation-ish | TLS record | Confidentiality, integrity |
| Transport | TCP / QUIC | Reliability / multiplexing |
| Network | IP | Routing, firewall |

## 2. 🔗 URL, Authority & Origin

### 2.1 URL anatomy (conceptual)

```
https://user:pass@app.example:443/path/res?x=1&y=2#frag
└─┬─┘  └────┬────┘ └────┬────┘ └┬┘ └──┬──┘ └─┬─┘ └─┬─┘
scheme   userinfo      host    port  path  query fragment
```

| Part | Sent to server? | Notes |
|:---|:---|:---|
| Scheme | Indirect (TLS vs not) | `https` required for sensitive apps |
| Userinfo | Rarely used; discouraged | Leaks in logs/Referer historically |
| Host + port | `Host` / `:authority` | Virtual hosting |
| Path + query | Request-target | Primary injection surface |
| Fragment | **No** (browser-only) | Can feed DOM XSS sources |

### 2.2 Origin tuple (*Tangled Web*)

$$
\mathsf{Origin} = (\mathsf{scheme},\, \mathsf{host},\, \mathsf{port})
$$

Same-Origin Policy compares origins. Understanding this tuple is mandatory before CORS, cookies, and CSRF notes.

### 🇮🇩 Bahasa Indonesia
Jangan menaruh rahasia di query string: muncul di log akses, history, `Referer`. Prefer body + TLS untuk kredensial.

### 🇬🇧 English
Normalize URLs at security boundaries carefully — parser differentials have caused bypasses (open redirects, SSRF, cache keys).

### 日本語
機密をクエリに置かないでください。パーサ差分にも注意します。

## 3. 📚 Protocol Versions (Security-Relevant Differences)

| Version | Multiplexing | Head-of-line | Typical transport |
|:---|:---|:---|:---|
| HTTP/1.0 | No | Per connection | TCP |
| HTTP/1.1 | Pipelining (rarely used) | Yes (TCP) | TCP + `Host` required |
| HTTP/2 | Streams | App-layer mitigated | TCP + TLS usual |
| HTTP/3 | Streams | Better with QUIC | QUIC/UDP |

### Security notes
- HTTP/2/`HPACK` and HTTP/3 add complexity — keep implementations patched (request smuggling research historically targeted desync between front/back parsers; see also note #2).  
- Prefer TLS 1.2+ / 1.3; disable cleartext where possible.  
- `Connection: keep-alive` is normal; do not invent custom framing.

## 4. 🔐 TLS Boundary & Trust

$$
\text{HTTPS} = \text{HTTP semantics} \;+\; \text{TLS record protection}
$$

```bash
# OWN LAB — inspect certificate chain of a host you control / public test host
openssl s_client -connect example.com:443 -servername example.com </dev/null 2>/dev/null | \
  openssl x509 -noout -subject -issuer -dates
```

| Control | Purpose |
|:---|:---|
| Valid cert + hostname | Authenticate server |
| HSTS | Force HTTPS in browsers |
| TLS 1.3 | Modern ciphers, forward secrecy defaults |
| Cert pinning (mobile/extra) | Extra trust lock (ops cost) |

cURL verifies certs by default — jangan biasakan `-k` di produksi.

## 5. 🔄 Resolution → Request Flow

```
 URL typed/clicked
        │
        ▼
  DNS resolve ──► TCP/QUIC connect ──► TLS (if https) ──► HTTP request
        │                                                    │
        └──────── /etc/hosts override (lab) ─────────────────┘
                                                             ▼
                                                      HTTP response
                                                             ▼
                                                      render / API parse
```

| Step | Failure class | Defensive check |
|:---|:---|:---|
| DNS | Spoof / cache poison | DNSSEC where applicable; app not trust DNS alone for SSRF |
| TCP | Scan / abuse | Firewalls, rate limits |
| TLS | MITM | PKI validation |
| HTTP | Injection / logic | Secure coding (vuln series) |

## 6. 🧪 cURL for Defensive / Authorized Labs

**cURL** speaks HTTP(S) without a browser renderer — ideal to inspect raw status lines, headers, and bodies of **systems you own**.

### 6.1 Safe baseline habits

```bash
# Show response headers + body; fail on TLS errors (good)
curl -sS -D - -o body.bin https://localhost:8443/health

# Timing / status only
curl -sS -o /dev/null -w "code=%{http_code} time=%{time_total}\n" https://localhost:8443/

# Explicit method + JSON to YOUR API
curl -sS -X POST https://localhost:8443/api/echo \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $TOKEN" \
  --data '{"ping":true}'
```

### 6.2 Useful flags (lab)

| Flag | Use |
|:---|:---|
| `-v` / `--trace-ascii` | Debug wire (careful: secrets) |
| `-D -` | Dump response headers |
| `-H` | Add header |
| `-A` | User-Agent |
| `-L` | Follow redirects (**re-validate** in SSRF tooling you write) |
| `--http1.1` / `--http2` | Force version |
| `--cacert` / `--cert` | Custom trust / mTLS lab |
| `-x http://127.0.0.1:8080` | Send via local authorized proxy |

### 6.3 Anti-patterns

| Habit | Risk |
|:---|:---|
| `-k` always | Hides MITM / bad deploys |
| Putting passwords in shell history | Secret leak |
| Logging full `-v` in CI | Token leakage |
| Blind `-L` to user URLs | SSRF class |

## 7. 🕵️ Authorized Proxying (Burp/ZAP/mitmproxy)

Untuk lab berizin, arahkan klien ke proxy lokal:

```bash
export HTTPS_PROXY=http://127.0.0.1:8080
export HTTP_PROXY=http://127.0.0.1:8080
curl -sS https://app.lab.local/login --proxy http://127.0.0.1:8080
```

Pasang CA lab di trust store **hanya** pada VM latihan. Jangan memasang CA tidak dikenal di browser harian.

WAHH workflow: intercept → understand parameters → fix code / config — bukan menjalankan eksploit publik di target tanpa izin.

## 8. ✅ Cheatsheet

```bash
# Headers only
curl -sSI https://localhost:8443/

# POST form
curl -sS -X POST https://localhost:8443/login \
  -H "Content-Type: application/x-www-form-urlencoded" \
  --data "user=alice&pass=$PASS"

# Save body
curl -sS -o out.json https://localhost:8443/api/me -H "Authorization: Bearer $TOKEN"

# mTLS lab
curl -sS https://localhost:8443/secure \
  --cacert lab-ca.pem --cert client.pem --key client.key
```

| Concept | One-liner |
|:---|:---|
| Origin | scheme + host + port |
| HTTPS | HTTP + TLS |
| cURL default | verifies TLS |
| Fragment | not sent to server |
| Lab rule | only systems in scope |

## 🔐 Security Notes — Threats & Defenses

| Issue | Defense |
|:---|:---|
| Cleartext HTTP | Redirect + HSTS; disable :80 where possible |
| Secret in URL | Use body/headers; strip logs |
| `-k` in prod scripts | Remove; pin CA |
| Proxy CA on daily browser | Isolate lab profiles |
| Redirect chains | Bound hops; validate destinations |
