## 1. 📤 Core Request Headers — Client Metadata

### 🇮🇩 Bahasa Indonesia
HTTP Request Headers dikirim oleh browser atau klien untuk memberikan informasi konteks tentang permintaan ke server:
- **`Host`**: Nama domain atau IP target (wajib pada HTTP/1.1). Menentukan *virtual host* mana di server yang dituju.
- **`User-Agent`**: String identitas perangkat lunak klien (browser, OS, engine rendering).
- **`Authorization`**: Token atau kredensial autentikasi (misal `Bearer <JWT>` atau `Basic <base64>`).
- **`Cookie`**: Kumpulan cookie sesi yang disimpan klien untuk dikirimkan kembali ke server.
- **`Referer`**: URL halaman asal yang memicu request saat ini.
- **`Origin`**: Asal domain (*scheme + host + port*) dari request lintas-domain (CORS).
- **`X-Forwarded-For` / `X-Real-IP`**: Header proxy yang mencatat IP asli klien di belakang load balancer.

### 🇬🇧 English
HTTP Request Headers are transmitted by clients (browsers, automated agents) to provide execution context to the receiving server:
- **`Host`**: The targeted domain name or IP (mandatory in HTTP/1.1). Dictates virtual host routing on multitenant servers.
- **`User-Agent`**: Identification string characterizing the client software, architecture, and browser engine.
- **`Authorization`**: Encapsulates authentication credentials (e.g., `Bearer <JWT_TOKEN>` or `Basic <base64>`).
- **`Cookie`**: State management tokens sent by the client back to the originating origin.
- **`Referer`**: URL of the previous web resource from which a link was followed.
- **`Origin`**: Indicates the protocol, hostname, and port of the initiating document for Cross-Origin requests.
- **`X-Forwarded-For` / `X-Real-IP`**: De-facto proxy headers tracking original client IP addresses traversing load balancers.

### 🇯🇵 日本語
HTTPリクエストヘッダーは、クライアントがサーバーに対して通信の文脈や追加情報を伝達するために送信されます：
- **`Host`**: 対象のドメイン名またはIPアドレス（HTTP/1.1で必須）。バーチャルホストのルーティングを決定します。
- **`User-Agent`**: クライアントのOS、ブラウザ種別、レンダリングエンジンを示す識別文字列。
- **`Authorization`**: 認証トークンや認証情報（`Bearer <JWT>` や `Basic <base64>` 等）。
- **`Cookie`**: サーバーから以前発行されたセッショントークンを送信。
- **`Referer`**: リクエストの遷移元となったページのURL。
- **`Origin`**: クロスオリジンリクエストにおいて、送信元のオリジン（プロトコル＋ホスト＋ポート）を示す。
- **`X-Forwarded-For` / `X-Real-IP`**: プロキシやロードバランサーを経由した際のクライアント実IPアドレス。

```http
GET /api/v1/user/profile HTTP/1.1
Host: target.htb
User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64)
Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
Cookie: session=k8s_99201a; theme=dark
Origin: https://app.target.htb
Referer: https://app.target.htb/dashboard
Accept: application/json
Connection: keep-alive
```

## 2. 📥 Core Response Headers — Server Metadata

### 🇮🇩 Bahasa Indonesia
HTTP Response Headers dikirim oleh server untuk menginstruksikan browser mengenai penanganan konten dan manajemen state:
- **`Content-Type`**: Menentukan tipe media MIME dari payload body (misal `text/html; charset=UTF-8`, `application/json`, `image/png`).
- **`Content-Length`**: Ukuran body response dalam hitungan byte.
- **`Set-Cookie`**: Mengirim cookie baru ke browser beserta atribut keamanannya.
- **`Location`**: Menentukan URL tujuan saat server mengembalikan redirect (301, 302, 307).
- **`Server`**: Mengungkap software dan versi web server (misal `Apache/2.4.52`, `nginx/1.18.0`).

### 🇬🇧 English
HTTP Response Headers are returned by web servers to direct client rendering, caching strategies, and security states:
- **`Content-Type`**: Declares the MIME type and character set of the response body.
- **`Content-Length`**: Denotes the exact decimal payload byte size.
- **`Set-Cookie`**: Directs the browser to store key-value cookies along with security policy attributes.
- **`Location`**: Designates the target destination URI in redirection responses (3xx).
- **`Server`**: Exposes the underlying web server software and versioning information.

### 🇯🇵 日本語
HTTPレスポンスヘッダーは、サーバーがブラウザに対してコンテンツの解釈方法、キャッシュ方針、セッション管理を指示します：
- **`Content-Type`**: 本文のMIMEタイプおよび文字コード（`text/html; charset=UTF-8`、`application/json` 等）。
- **`Content-Length`**: レスポンス本文のバイトサイズ。
- **`Set-Cookie`**: ブラウザにCookieの保存を指示（セキュリティ属性付き）。
- **`Location`**: リダイレクト（301/302等）時の転送先URLを指定。
- **`Server`**: Webサーバーソフトウェアおよびバージョン情報を開示。

## 3. 🛡️ Modern Security Headers — Web Defense Baseline

### 🇮🇩 Bahasa Indonesia
Security Headers adalah header respons HTTP yang dirancang khusus untuk memitigasi serangan web seperti Cross-Site Scripting (XSS), Clickjacking, MIME-confusion, dan Man-in-the-Middle (MitM) (*The Tangled Web*, Zalewski).

### 🇬🇧 English
Security Headers are hardened HTTP response directives engineered to restrict browser capabilities and neutralize attack classes including Cross-Site Scripting (XSS), Clickjacking, MIME-sniffing, and SSL Strip Man-in-the-Middle (*The Tangled Web*, Zalewski).

### 🇯🇵 日本語
セキュリティヘッダーは、XSS、クリックジャッキング、MIMEスニッフィング、MitM（中間者攻撃）などの攻撃を緩和するために設計されたHTTPレスポンスディレクティブです（『The Tangled Web』参照）。

| Security Header | 🇮🇩 Fungsi Keamanan | 🇬🇧 Security Purpose | 🇯🇵 セキュリティ機能 | Recommended Value |
|-----------------|---------------------|---------------------|-------------------|-------------------|
| **`Content-Security-Policy` (CSP)** | Batasi sumber script, media & style | Restricts trusted sources for scripts/assets | スクリプト等の読み込み元を厳格に制限 | `default-src 'self'; script-src 'self'` |
| **`Strict-Transport-Security` (HSTS)** | Paksa browser selalu gunakan HTTPS | Enforces strict HTTPS communication | HTTPS通信の常時強制（SSL Strip防止） | `max-age=31536000; includeSubDomains; preload` |
| **`X-Frame-Options`** | Cegah rendering dalam `<iframe>` (Clickjacking) | Mitigates Clickjacking via frame embedding | iframe埋め込み制限（クリックジャッキング防止） | `DENY` atau `SAMEORIGIN` |
| **`X-Content-Type-Options`** | Cegah MIME-type sniffing | Prevents browser MIME-type sniffing | MIMEスニッフィングによるスクリプト誤実行防止 | `nosniff` |
| **`Referrer-Policy`** | Kontrol kebocoran URL di header Referer | Controls Referer header data leakage | Refererヘッダーによる機密URL漏洩制御 | `strict-origin-when-cross-origin` |
| **`Permissions-Policy`** | Kontrol fitur hardware (kamera, mic, gps) | Restricts browser APIs (camera, geolocation) | ブラウザAPI（カメラ、マイク、位置情報）制限 | `camera=(), geolocation=(), microphone=()` |

## 4. 🍪 Cookie & Session Security Flags

### 🇮🇩 Bahasa Indonesia
Cookie yang digunakan untuk otentikasi sesi **wajib** dikonfigurasi dengan flag keamanan berikut untuk mencegah pembajakan sesi (*Session Hijacking*):
1. **`HttpOnly`**: Mencegah JavaScript klien mengakses cookie via `document.cookie`. Melindungi session token dari pencurian saat terjadi serangan Cross-Site Scripting (XSS).
2. **`Secure`**: Memastikan cookie **hanya** dikirim melalui koneksi terenkripsi HTTPS (mencegah sniffing di jaringan publik/cleartext).
3. **`SameSite`**: Mengatur apakah cookie dikirim pada cross-site requests untuk mencegah Cross-Site Request Forgery (CSRF):
   - `Strict`: Cookie tidak pernah dikirim pada request dari domain lain.
   - `Lax`: Cookie dikirim pada navigasi top-level yang aman (misal klik link `GET`).
   - `None`: Cookie dikirim pada semua cross-site request (wajib menyertakan flag `Secure`).

### 🇬🇧 English
Session cookies governing authentication states **must** enforce standard security attributes to preclude Session Hijacking:
1. **`HttpOnly`**: Prohibits client-side scripts from reading `document.cookie`. Neutralizes cookie theft via XSS vulnerabilities.
2. **`Secure`**: Enforces cookie transmission exclusively across TLS/HTTPS channels, preventing eavesdropping over untrusted networks.
3. **`SameSite`**: Restricts cookie inclusion on cross-site requests to mitigate CSRF:
   - `Strict`: Withheld on all cross-origin requests.
   - `Lax`: Permitted only on top-level safe GET navigations.
   - `None`: Dispatched on third-party requests (strictly requires `Secure`).

### 🇯🇵 日本語
セッション認証に使われるCookieには、セッションハイジャックを防ぐため以下の保護属性を必ず付与する必要があります：
1. **`HttpOnly`**: JavaScript（`document.cookie`）からのアクセスを禁止し、XSSによるCookie盗難を防止。
2. **`Secure`**: 暗号化されたHTTPS通信でのみCookieを送信させ、平文盗聴を防止。
3. **`SameSite`**: クロスサイトリクエスト時の送信制限（CSRF対策）：
   - `Strict`: 外部サイトからの遷移時は一切Cookieを送信しない。
   - `Lax`: 安全なトップレベルナビゲーション（リンククリック等）でのみ送信。
   - `None`: すべての外部リクエストで送信（`Secure` 属性が必須）。

```http
Set-Cookie: session_token=a9f193c72b89; Secure; HttpOnly; SameSite=Strict; Path=/; Max-Age=3600
```

## 5. 🌐 Same-Origin Policy (SOP) & CORS Overview

### 🇮🇩 Bahasa Indonesia
- **Same-Origin Policy (SOP)**: Fondasi keamanan browser (*The Tangled Web*, Zalewski) yang membatasi dokumen atau script dari satu origin (*Protocol + Hostname + Port*) untuk membaca resource dari origin yang berbeda.
- **Cross-Origin Resource Sharing (CORS)**: Mekanisme berbasis HTTP header yang memungkinkan server mengizinkan akses terpilih dari origin lain menggunakan header respons:
  - `Access-Control-Allow-Origin: https://app.trusted.com`
  - `Access-Control-Allow-Credentials: true`
  - `Access-Control-Allow-Methods: GET, POST, PUT`

### 🇬🇧 English
- **Same-Origin Policy (SOP)**: The foundational browser security boundary (*The Tangled Web*, Zalewski) prohibiting scripts on one origin (*Protocol + Hostname + Port*) from reading document data loaded from another origin.
- **Cross-Origin Resource Sharing (CORS)**: An opt-in HTTP header mechanism allowing servers to relax SOP constraints for designated origins:
  - `Access-Control-Allow-Origin: https://app.trusted.com`
  - `Access-Control-Allow-Credentials: true`
  - `Access-Control-Allow-Methods: GET, POST, PUT`

### 🇯🇵 日本語
- **同一生成元ポリシー（SOP / Same-Origin Policy）**: ブラウザセキュリティの基本原則（『The Tangled Web』参照）。異なるオリジン（プロトコル＋ホスト＋ポート）間でスクリプトによるリソースの読み取りを制限します。
- **CORS（Cross-Origin Resource Sharing）**: サーバーがHTTPヘッダーを用いて、特定の外部オリジンからのリソースアクセスを明示的に許可する仕組み。

## 6. 🔐 Security Note — Header Injection, CORS Misconfiguration & Cache Poisoning

### 🇮🇩 Bahasa Indonesia
Dalam *The Web Application Hacker's Handbook* (WAHH) dan riset web security modern:
1. **CORS Misconfiguration**: Server yang mengembalikan `Access-Control-Allow-Origin: null` atau memantulkan kembali header `Origin` klien secara dinamis (`Access-Control-Allow-Origin: https://attacker.com`) dengan `Access-Control-Allow-Credentials: true` memungkinkan penyerang mengekstrak data sensitif (PII, API keys) korban via JavaScript.
2. **HTTP Host Header Attack & Web Cache Poisoning**: Manipulasi header `Host` atau `X-Forwarded-Host` dapat memicu password reset poisoning atau menyebabkan cache proxy menyimpan payload jahat untuk semua pengunjung lain.
3. **Missing Security Headers**: Ketiadaan `Content-Security-Policy` atau `X-Frame-Options` membuka jalan bagi eksploitasi XSS dan Clickjacking.

### 🇬🇧 English
Documented across *The Web Application Hacker's Handbook* and offensive web security research:
1. **CORS Misconfigurations**: Servers reflecting untrusted `Origin` values with `Access-Control-Allow-Credentials: true` or permitting `null` origins grant attacker scripts full authorization to read authenticated confidential responses.
2. **Host Header Attacks & Web Cache Poisoning**: Tampering with `Host`, `X-Forwarded-Host`, or `X-Original-URL` can poison password reset links or deceive intermediate caching layers into serving malicious scripts to all users.
3. **Lack of Defensive Headers**: Missing CSP and frame controls immediately facilitates weaponized stored XSS and Clickjacking attacks.

### 🇯🇵 日本語
『The Web Application Hacker's Handbook』に記載された主要な攻撃シナリオ：
1. **CORSの不適切な設定**: 任意の `Origin` をそのまま `Access-Control-Allow-Origin` に反射し、`Access-Control-Allow-Credentials: true` を設定している場合、悪意あるサイトからユーザーの機密データが窃取されます。
2. **Hostヘッダー攻撃とWebキャッシュ汚染**: `Host` や `X-Forwarded-Host` を改ざんしてパスワードリセットURLを乗っ取ったり、プロキシキャッシュに不正なレスポンスを登録させる攻撃。
3. **セキュリティヘッダーの欠落**: CSP や `X-Frame-Options` の未設定は、XSS やクリックジャッキングの被害を拡大させます。

```bash
# ── AUDITING HEADERS WITH CURL ───────────────────────────────

# 1. Inspect all response security headers
$ curl -s -I https://target.htb/

# 2. Test for CORS Origin Reflection
$ curl -s -I -H "Origin: https://evil-attacker.com" https://target.htb/api/user \
  | grep -i "access-control"

# 3. Test Host Header Poisoning
$ curl -s -I -H "Host: evil.com" http://target.htb/password_reset
```
