## 1. 📋 Header Field Model

### 🇮🇩 Bahasa Indonesia
Header adalah pasangan nama/nilai di start-line message (RFC 9110). Nama case-insensitive; nilai harus bebas dari kontrol karakter berbahaya. Banyak fitur keamanan web diekspresikan **hanya** lewat header respons (`CSP`, `Set-Cookie`, `HSTS`).

$$
\mathsf{Header} ::= \mathsf{field\text{-}name} \,\texttt{:}\, \mathsf{OWS}\, \mathsf{field\text{-}value}
$$

*The Tangled Web* menekankan: browser adalah mesin kepercayaan rumit — header adalah tuas kebijakan yang harus disetel sadar, bukan copy-paste mistis.

### 🇬🇧 English
Never trust request headers for authZ alone (`X-Forwarded-For`, `X-Original-URL`, spoofable `Host` behind misconfigured proxies). Treat them as **hints** until the trusted edge normalizes them.

### 日本語
リクエストヘッダーを認可の唯一の根拠にしないでください。信頼できるエッジで正規化します。

## 2. 📤 Core Request Headers
<img width="626" height="401" alt="image" src="https://github.com/user-attachments/assets/923366e1-b7c0-4c29-be66-052cfc1d22bf" />

| Header | Role | Security note |
|:---|:---|:---|
| `Host` | Virtual host | Reject invalid; don’t trust raw for SSRF |
| `User-Agent` | Client product token | Don’t auth on UA; log carefully |
| `Authorization` | Credentials | Bearer/JWT/Basic — TLS only; no logs |
| `Cookie` | Stored state | CSRF/XSS interactions |
| `Origin` | Fetch initiating origin | CORS decisions |
| `Referer` | Navigation source | Privacy; may leak tokens in URLs |
| `Accept` | Preferred media types | Content negotiation |
| `Content-Type` | Body type | Enforce on mutators |
| `If-None-Match` / `If-Modified-Since` | Conditionals | Cache correctness |
| `Sec-Fetch-*` | Fetch metadata | CSRF isolation policies |
| `X-Forwarded-For` | Client IP via proxy | Spoofable unless trusted hop |

```http
GET /api/profile HTTP/1.1
Host: app.lab.local
Authorization: Bearer <access_token>
Cookie: session=<sid>
Origin: https://app.lab.local
Sec-Fetch-Site: same-origin
Sec-Fetch-Mode: cors
Accept: application/json
```

## 4. 🧱 Security Response Headers (Baseline)

### 4.1 Table — modern baseline
<img width="748" height="472" alt="image" src="https://github.com/user-attachments/assets/b7b95d03-366c-45c2-99e1-97a1e965782a" />

| Header | Example direction | Mitigates (class) |
|:---|:---|:---|
| `Content-Security-Policy` | `default-src 'self'; script-src 'nonce-…'` | XSS impact reduction |
| `Strict-Transport-Security` | `max-age=31536000; includeSubDomains` | Downgrade / cookie strip issues |
| `X-Content-Type-Options` | `nosniff` | MIME sniffing XSS |
| `Referrer-Policy` | `strict-origin-when-cross-origin` | Token leak via Referer |
| `Permissions-Policy` | disable unused powerful APIs | Feature abuse |
| `Cross-Origin-Opener-Policy` | `same-origin` | Cross-origin window attacks |
| `Cross-Origin-Resource-Policy` | `same-origin` / `same-site` | Spectre-ish resource read classes |
| `Cross-Origin-Embedder-Policy` | `require-corp` (when needed) | Isolation with COOP |
| `X-Frame-Options` | `DENY` / `SAMEORIGIN` | Clickjacking (legacy; prefer CSP `frame-ancestors`) |

### 4.2 CSP sketch

$$
\mathsf{CSP} \supseteq \{\mathsf{default\text{-}src},\, \mathsf{script\text{-}src},\, \mathsf{object\text{-}src},\, \mathsf{base\text{-}uri},\, \mathsf{frame\text{-}ancestors}\}
$$

Prefer **nonces/hashes** over `'unsafe-inline'`. CSP is **defense in depth**, not a license to skip output encoding (see XSS note).

### 4.3 HSTS

```http
Strict-Transport-Security: max-age=31536000; includeSubDomains; preload
```

Only enable when HTTPS is correctly deployed on all subdomains you include.

### 🇮🇩 Bahasa Indonesia
WAHH / lab hardening: audit header pada respons login, API JSON, dan unduhan file — kebijakan sering tidak konsisten antar route.

### 🇬🇧 English
Start with report-only CSP (`Content-Security-Policy-Report-Only`) in production brownfield, then enforce.

### 日本語
既存アプリはまずReport-OnlyでCSPを試し、からenforceへ移行します。

## 5. 🍪 Cookie Attributes (RFC 6265)

$$
\texttt{Set-Cookie:}\ \mathsf{Name}=\mathsf{Value};\ \mathsf{Attrs…}
$$

| Attribute | Purpose |
|:---|:---|
| `Secure` | HTTPS only transport |
| `HttpOnly` | Hide from `document.cookie` |
| `SameSite=Strict\|Lax\|None` | Cross-site send policy (`None` needs `Secure`) |
| `Max-Age` / `Expires` | Lifetime |
| `Path` / `Domain` | Scope — keep narrow |
| `__Host-` / `__Secure-` | Prefix rules for stronger cookies |

Session cookie baseline for many apps:

```http
Set-Cookie: __Host-session=…; Path=/; Secure; HttpOnly; SameSite=Lax
```

## 6. 🌍 Same-Origin Policy & CORS

### 6.1 SOP (browser)
Script from origin $A$ cannot read responses from origin $B$ by default. Cross-origin **writes** (form posts) still happen → CSRF class.

### 6.2 CORS
Server opts into controlled reads via:

| Header | Meaning |
|:---|:---|
| `Access-Control-Allow-Origin` | Exact origin or (non-credentialed) `*` |
| `Access-Control-Allow-Credentials` | Allow cookies; **forbids** `*` origin |
| `Access-Control-Allow-Methods` | Methods for preflight |
| `Access-Control-Allow-Headers` | Request headers allowed |
| `Access-Control-Max-Age` | Preflight cache |

**Safe pattern:** reflect only allowlisted origins:

$$
\mathsf{ACAO}(req) =
\begin{cases}
O & \text{if } O=\mathsf{Origin}(req) \in \mathcal{L} \\
\text{omit} & \text{otherwise}
\end{cases}
$$

Never: `ACAO = request.Origin` for arbitrary Origin with credentials.

## 7. ⚠️ Header Injection & Trust Failures (Classes)

| Class | Idea | Defense |
|:---|:---|:---|
| CRLF injection | Attacker inserts `\r\n` into header values → response splitting / cookie injection | Strip CR/LF; use framework cookie APIs |
| Host header attacks | Poison absolute URL generation / cache keys | Trusted `Host` / `X-Forwarded-Host` policy |
| Cache poisoning | Unkeyed header influences body | Vary correctly; ignore untrusted inputs in cache key |
| IP spoof via `XFF` | AuthZ by client IP from header | Trust only last hop from your proxy |
| Verbose `Server`/`X-Powered-By` | Recon aid | Remove or genericize |

```python
# UNSAFE sketch
location = "https://app/" + user_next  # open redirect + potential header issues if mis-sent

# SAFE — allowlist path
ALLOWED = {"/home", "/settings"}
if user_next not in ALLOWED:
    user_next = "/home"
# use framework redirect helper (encodes safely)
```

## 8. 🧪 Authorized Header Audit with cURL

```bash
# OWN LAB — dump security-relevant response headers
curl -sSI https://localhost:8443/login | egrep -i \
  'HTTP/|content-security-policy|strict-transport|x-content-type|referrer-policy|permissions-policy|set-cookie|access-control|x-frame|cross-origin'

# Check redirect target
curl -sSI https://localhost:8443/old | egrep -i 'HTTP/|location'

# Observe CORS preflight against YOUR API
curl -sSI -X OPTIONS https://localhost:8443/api/data \
  -H "Origin: https://app.lab.local" \
  -H "Access-Control-Request-Method: PUT" \
  -H "Access-Control-Request-Headers: authorization,content-type"
```

Interpret results against the baseline table; fix server config / app middleware — don’t “bypass” as a goal.

## 9. ✅ Baseline Checklist

| Control | Target |
|:---|:---|
| HTTPS + HSTS | On for production hosts |
| `nosniff` | All responses |
| CSP | Nonce/hash; no needless `unsafe-inline` |
| `frame-ancestors` / XFO | Clickjacking defense |
| Referrer-Policy | Non-leaky default |
| Cookies | `Secure; HttpOnly; SameSite` |
| CORS | Explicit allowlist; no cred+`*` |
| Cache | `no-store` for authed JSON/HTML |
| Strip | `X-Powered-By` / detailed `Server` |
| Proxies | Normalize Host / forwarding headers |

```
 Browser trust levers              Server must set intentionally
 ────────────────────              ─────────────────────────────
 CSP / COOP / CORP        ◄──────  security middleware
 Cookie flags             ◄──────  session layer
 CORS ACAO                ◄──────  API gateway / app
 HSTS                     ◄──────  TLS-enabled edge
```

## 🔐 Security Notes — Threats & Defenses

| Threat | Header angle | Defense |
|:---|:---|:---|
| XSS | CSP + nosniff + encoding | Defense in depth |
| CSRF | SameSite + tokens + Sec-Fetch | See CSRF note |
| Clickjacking | `frame-ancestors` | Deny by default |
| MITM downgrade | HSTS | Correct HTTPS first |
| Token in Referer | Referrer-Policy | No secrets in URLs |
| Mis-CORS | ACAO reflect | Allowlist |
| Response splitting | CR/LF in values | Reject / framework APIs |
