## 1. Peran HTTP di stack jaringan

HTTP (Hypertext Transfer Protocol) adalah protokol lapisan aplikasi untuk memanipulasi resource yang diidentifikasi lewat URI. Semantik inti, yaitu metode, kode status, dan header, didefinisikan di RFC 9110. Pemetaannya ke koneksi TCP klasik didefinisikan di RFC 9112 (HTTP/1.1).

$$
\text{Client} \;\xrightarrow{\text{request}}\; \text{Server} \;\xrightarrow{\text{response}}\; \text{Client}
$$

HTTP sendiri tidak menyediakan kerahasiaan maupun integritas. Itu tugas TLS (HTTPS). Port yang lazim dipakai: 80 untuk cleartext, 443 untuk TLS.

WAHH memperlakukan penguasaan HTTP sebagai fondasi untuk memahami hampir semua kelas kerentanan web: sink injeksi muncul di parameter, header, dan body, sementara keputusan trust muncul di cookie dan origin (lihat *The Tangled Web*).

| Layer | Contoh | Catatan keamanan |
|:---|:---|:---|
| Application | Metode HTTP, header | AuthZ, kepercayaan input |
| Presentation-ish | TLS record | Kerahasiaan, integritas |
| Transport | TCP / QUIC | Keandalan, multiplexing |
| Network | IP | Routing, firewall |

## 2. URL, authority, dan origin

### 2.1 Anatomi URL (konseptual)

<img width="1940" height="480" alt="image" src="https://github.com/user-attachments/assets/eeb6bbf0-c21f-4911-b6f7-7d7a62b2f58b" />

```
https://user:pass@app.example:443/path/res?x=1&y=2#frag
└─┬─┘  └────┬────┘ └────┬────┘ └┬┘ └──┬──┘ └─┬─┘ └─┬─┘
scheme   userinfo      host    port  path  query fragment
```

| Bagian | Dikirim ke server? | Catatan |
|:---|:---|:---|
| Scheme | Tidak langsung (TLS atau bukan) | `https` wajib untuk aplikasi sensitif |
| Userinfo | Jarang dipakai, tidak dianjurkan | Secara historis bocor di log dan Referer |
| Host + port | `Host` / `:authority` | Virtual hosting |
| Path + query | Request-target | Permukaan injeksi utama |
| Fragment | Tidak (hanya di browser) | Bisa menjadi sumber DOM XSS |

### 2.2 Tuple origin (*The Tangled Web*)

$$
\mathsf{Origin} = (\mathsf{scheme},\, \mathsf{host},\, \mathsf{port})
$$

Same-Origin Policy membandingkan origin. Memahami tuple ini wajib sebelum masuk ke catatan CORS, cookie, dan CSRF.

Jangan menaruh rahasia di query string: rahasia itu akan muncul di log akses, riwayat browser, dan header `Referer`. Gunakan body dan TLS untuk kredensial.

Normalisasi URL harus dilakukan dengan hati-hati di batas keamanan. Perbedaan parser secara historis pernah menyebabkan bypass, termasuk open redirect, SSRF, dan kebingungan cache-key.

## 3. Versi protokol (perbedaan yang relevan untuk keamanan)

| Versi | Multiplexing | Head-of-line blocking | Transport umum |
|:---|:---|:---|:---|
| HTTP/1.0 | Tidak | Per koneksi | TCP |
| HTTP/1.1 | Pipelining (jarang dipakai) | Ya (TCP) | TCP, `Host` wajib |
| HTTP/2 | Streams | Dimitigasi di app layer | TCP + TLS umumnya |
| HTTP/3 | Streams | Lebih baik, lewat QUIC | QUIC/UDP |

Catatan keamanan:

- HPACK di HTTP/2 dan HTTP/3 menambah kompleksitas parsing. Jaga implementasi tetap ter-patch; riset request smuggling secara historis menargetkan desync antara parser front-end dan back-end.
- Utamakan TLS 1.2 ke atas, idealnya 1.3; nonaktifkan cleartext bila memungkinkan.
- `Connection: keep-alive` adalah perilaku normal. Jangan membuat framing kustom di atasnya.

## 4. Batas kepercayaan TLS

$$
\text{HTTPS} = \text{Semantik HTTP} \;+\; \text{Proteksi record TLS}
$$

```bash
# LAB SENDIRI - periksa rantai sertifikat host yang Anda kendalikan atau host uji publik
openssl s_client -connect example.com:443 -servername example.com </dev/null 2>/dev/null | \
  openssl x509 -noout -subject -issuer -dates
```

| Kontrol | Tujuan |
|:---|:---|
| Sertifikat valid + hostname cocok | Mengautentikasi server |
| HSTS | Memaksa HTTPS di browser |
| TLS 1.3 | Cipher modern, forward secrecy sebagai default |
| Certificate pinning (mobile, ekstra) | Pengunci trust tambahan, dengan biaya operasional |

cURL memverifikasi sertifikat secara default. Jangan biasakan memakai `-k` di produksi.

## 6. cURL untuk lab defensif dan berizin

cURL berbicara HTTP(S) tanpa renderer browser, sehingga cocok untuk memeriksa status line, header, dan body mentah pada sistem yang Anda miliki.

### 6.1 Kebiasaan dasar yang aman

```bash
# Tampilkan header respons + body; gagal saat error TLS (bagus)
curl -sS -D - -o body.bin https://localhost:8443/health

# Hanya timing / status
curl -sS -o /dev/null -w "code=%{http_code} time=%{time_total}\n" https://localhost:8443/

# Metode eksplisit + JSON ke API ANDA
curl -sS -X POST https://localhost:8443/api/echo \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $TOKEN" \
  --data '{"ping":true}'
```

### 6.2 Flag yang berguna (lab)

| Flag | Kegunaan |
|:---|:---|
| `-v` / `--trace-ascii` | Debug wire format (hati-hati: bisa membocorkan rahasia) |
| `-D -` | Dump header respons |
| `-H` | Menambah header |
| `-A` | Mengatur User-Agent |
| `-L` | Mengikuti redirect (validasi ulang perilaku ini di tooling SSRF yang Anda buat) |
| `--http1.1` / `--http2` | Memaksa versi protokol |
| `--cacert` / `--cert` | Trust store kustom atau lab mTLS |
| `-x http://127.0.0.1:8080` | Mengirim lewat proxy lokal berizin |

### 6.3 Anti-pola

| Kebiasaan | Risiko |
|:---|:---|
| Selalu memakai `-k` | Menyembunyikan MITM dan deployment yang salah |
| Menaruh password di shell history | Kebocoran rahasia |
| Mencatat output `-v` penuh di CI | Kebocoran token |
| Memakai `-L` secara membabi buta pada URL dari pengguna | Kelas SSRF |

## 7. Proxy berizin (Burp, ZAP, mitmproxy)

Untuk lab berizin, arahkan klien ke proxy lokal:

```bash
export HTTPS_PROXY=http://127.0.0.1:8080
export HTTP_PROXY=http://127.0.0.1:8080
curl -sS https://app.lab.local/login --proxy http://127.0.0.1:8080
```

Pasang CA lab di trust store hanya pada VM latihan. Jangan pernah memasang CA tidak dikenal di browser harian.

Alur kerja WAHH: intercept, pahami parameternya, lalu perbaiki kode atau konfigurasi. Ini bukan soal menjalankan exploit publik terhadap target tanpa izin.

## 8. Referensi cepat

```bash
# Hanya header
curl -sSI https://localhost:8443/

# POST form
curl -sS -X POST https://localhost:8443/login \
  -H "Content-Type: application/x-www-form-urlencoded" \
  --data "user=alice&pass=$PASS"

# Simpan body
curl -sS -o out.json https://localhost:8443/api/me -H "Authorization: Bearer $TOKEN"

# Lab mTLS
curl -sS https://localhost:8443/secure \
  --cacert lab-ca.pem --cert client.pem --key client.key
```

| Konsep | Ringkasan |
|:---|:---|
| Origin | scheme + host + port |
| HTTPS | HTTP + TLS |
| Default cURL | memverifikasi TLS |
| Fragment | tidak dikirim ke server |
| Aturan lab | hanya sistem dalam scope |

## 9. Catatan keamanan: ancaman dan pertahanan

| Isu | Pertahanan |
|:---|:---|
| HTTP cleartext | Redirect ke HTTPS + HSTS; nonaktifkan port 80 bila memungkinkan |
| Rahasia di URL | Pakai body atau header; bersihkan log |
| `-k` di skrip produksi | Hapus; pin CA |
| CA proxy di browser harian | Pisahkan profil lab |
| Rantai redirect | Batasi jumlah hop; validasi tujuan |
