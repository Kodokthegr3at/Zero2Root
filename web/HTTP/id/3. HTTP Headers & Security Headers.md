## 1. Model field header

Header adalah pasangan nama/nilai di start line sebuah message (RFC 9110). Nama bersifat case-insensitive; nilai harus bebas dari karakter kontrol berbahaya. Banyak fitur keamanan web hanya diekspresikan lewat header respons, termasuk `CSP`, `Set-Cookie`, dan `HSTS`.

```text
Name: value

Content-Type: text/html; charset=utf-8
```

*The Tangled Web* menyampaikan poin yang layak diingat: browser adalah mesin kepercayaan yang rumit, dan header adalah tuas kebijakan yang perlu disetel dengan sengaja, bukan disalin dari tempat lain tanpa dipahami.

Jangan pernah mempercayai header permintaan untuk otorisasi semata (`X-Forwarded-For`, `X-Original-URL`, dan `Host` yang bisa dipalsukan di belakang proxy yang salah konfigurasi). Perlakukan header itu sebagai petunjuk saja sampai edge tepercaya menormalkannya.

## 2. Header permintaan inti

<img width="626" height="401" alt="image" src="https://github.com/user-attachments/assets/923366e1-b7c0-4c29-be66-052cfc1d22bf" />

| Header | Peran | Catatan keamanan |
|:---|:---|:---|
| `Host` | Virtual host | Tolak nilai tidak valid; jangan percayai nilai mentah untuk keputusan SSRF |
| `User-Agent` | Token produk klien | Jangan autentikasi berdasarkan UA; log dengan hati-hati |
| `Authorization` | Kredensial | Bearer, JWT, atau Basic; TLS wajib; jangan pernah masuk log |
| `Cookie` | State tersimpan | Interaksi dengan CSRF dan XSS |
| `Origin` | Origin asal fetch | Keputusan CORS |
| `Referer` | Sumber navigasi | Isu privasi; bisa membocorkan token yang tertanam di URL |
| `Accept` | Jenis media yang disukai | Content negotiation |
| `Content-Type` | Jenis body | Wajib diterapkan pada endpoint yang mengubah data |
| `If-None-Match` / `If-Modified-Since` | Kondisional | Ketepatan cache |
| `Sec-Fetch-*` | Metadata fetch | Kebijakan isolasi CSRF |
| `X-Forwarded-For` | IP klien lewat proxy | Bisa dipalsukan kecuali hop tepercaya yang menegakkannya |

```http
GET /api/profile HTTP/1.1
Host: app.lab.local
Authorization: Bearer <access_token>
Cookie: session=<sid>
Origin: https://app.lab.local
Sec-Fetch-Site: same-origin
Sec-Fetch-Mode: cors
Accept: application/json
```

## 4. Header respons keamanan, baseline

### 4.1 Tabel: baseline modern

<img width="748" height="472" alt="image" src="https://github.com/user-attachments/assets/b7b95d03-366c-45c2-99e1-97a1e965782a" />

| Header | Contoh arah | Mengurangi |
|:---|:---|:---|
| `Content-Security-Policy` | `default-src 'self'; script-src 'nonce-...'` | Dampak XSS |
| `Strict-Transport-Security` | `max-age=31536000; includeSubDomains` | Serangan downgrade, isu cookie-stripping |
| `X-Content-Type-Options` | `nosniff` | XSS lewat MIME-sniffing |
| `Referrer-Policy` | `strict-origin-when-cross-origin` | Kebocoran token lewat Referer |
| `Permissions-Policy` | Nonaktifkan API kuat yang tidak dipakai | Penyalahgunaan fitur |
| `Cross-Origin-Opener-Policy` | `same-origin` | Serangan window lintas origin |
| `Cross-Origin-Resource-Policy` | `same-origin` / `same-site` | Kelas serangan baca resource sejenis Spectre |
| `Cross-Origin-Embedder-Policy` | `require-corp` (bila perlu) | Isolasi, berpasangan dengan COOP |
| `X-Frame-Options` | `DENY` / `SAMEORIGIN` | Clickjacking (legacy; lebih baik pakai CSP `frame-ancestors`) |

### 4.2 Sketsa CSP

CSP yang kuat setidaknya mengatur directive berikut: `default-src`, `script-src`, `object-src`, `base-uri`, dan `frame-ancestors`.

Utamakan nonce atau hash dibanding `'unsafe-inline'`. CSP adalah pertahanan berlapis. Ini bukan lisensi untuk melewati output encoding; lihat catatan XSS.

### 4.3 HSTS

```http
Strict-Transport-Security: max-age=31536000; includeSubDomains; preload
```

Aktifkan hanya setelah HTTPS diterapkan dengan benar di semua subdomain yang tercakup.

Sesuai gaya hardening lab WAHH, audit header pada respons login, API JSON, dan unduhan file; kebijakan sering tidak konsisten antar route.

Mulai dengan CSP report-only (`Content-Security-Policy-Report-Only`) pada aplikasi produksi brownfield, lalu pindah ke enforcement.

## 5. Atribut cookie (RFC 6265)

```text
Set-Cookie: session=abc123; Secure; HttpOnly; SameSite=Lax; Path=/
```

| Atribut | Tujuan |
|:---|:---|
| `Secure` | Transport HTTPS saja |
| `HttpOnly` | Tersembunyi dari `document.cookie` |
| `SameSite=Strict\|Lax\|None` | Kebijakan pengiriman lintas situs (`None` mewajibkan `Secure`) |
| `Max-Age` / `Expires` | Masa berlaku |
| `Path` / `Domain` | Cakupan; jaga tetap sempit |
| `__Host-` / `__Secure-` | Aturan prefix untuk cookie yang lebih kuat |

Baseline cookie session untuk kebanyakan aplikasi:

```http
Set-Cookie: __Host-session=...; Path=/; Secure; HttpOnly; SameSite=Lax
```

## 6. Same-origin policy dan CORS

### 6.1 SOP (browser)

Script dari origin A tidak bisa membaca respons dari origin B secara default. Penulisan lintas origin, seperti form post, tetap terjadi, dan inilah akar dari kelas serangan CSRF.

### 6.2 CORS

Server ikut serta memberi izin baca terkontrol lewat:

| Header | Makna |
|:---|:---|
| `Access-Control-Allow-Origin` | Origin persis, atau (tanpa kredensial) `*` |
| `Access-Control-Allow-Credentials` | Mengizinkan cookie; melarang origin `*` |
| `Access-Control-Allow-Methods` | Metode yang diizinkan untuk preflight |
| `Access-Control-Allow-Headers` | Header permintaan yang diizinkan |
| `Access-Control-Max-Age` | Durasi cache preflight |

Pola aman: pantulkan hanya origin yang ada di allowlist:

```text
Origin ada di allowlist     → Access-Control-Allow-Origin: <origin itu>
selain itu                  → jangan kirim header-nya
```

Jangan pernah menyetel `ACAO = request.Origin` untuk origin sembarang yang dikombinasikan dengan kredensial.

## 7. Injeksi header dan kegagalan kepercayaan

| Kelas | Ide | Pertahanan |
|:---|:---|:---|
| Injeksi CRLF | Penyerang menyisipkan `\r\n` ke nilai header, memungkinkan response splitting atau injeksi cookie | Buang CR/LF; gunakan API cookie framework |
| Serangan header Host | Meracuni pembuatan URL absolut atau cache key | Terapkan kebijakan `Host` / `X-Forwarded-Host` tepercaya |
| Cache poisoning | Header yang tidak masuk cache key memengaruhi body yang di-cache | Terapkan Vary dengan benar; abaikan input tidak tepercaya di cache key |
| Pemalsuan IP lewat `XFF` | Keputusan otorisasi berdasarkan IP klien yang diambil dari header | Percayai hanya hop terakhir dari proxy milik sendiri |
| `Server` / `X-Powered-By` yang verbose | Membantu reconnaissance | Hapus atau buat generik |

```python
# UNSAFE sketch
location = "https://app/" + user_next  # open redirect, dan isu header jika salah kirim

# SAFE - allowlist path
ALLOWED = {"/home", "/settings"}
if user_next not in ALLOWED:
    user_next = "/home"
# gunakan helper redirect dari framework (encoding aman)
```

## 8. Audit header berizin dengan curl

```bash
# OWN LAB - dump header respons yang relevan dengan keamanan
curl -sSI https://localhost:8443/login | egrep -i \
  'HTTP/|content-security-policy|strict-transport|x-content-type|referrer-policy|permissions-policy|set-cookie|access-control|x-frame|cross-origin'

# Cek target redirect
curl -sSI https://localhost:8443/old | egrep -i 'HTTP/|location'

# Amati CORS preflight terhadap API milik sendiri
curl -sSI -X OPTIONS https://localhost:8443/api/data \
  -H "Origin: https://app.lab.local" \
  -H "Access-Control-Request-Method: PUT" \
  -H "Access-Control-Request-Headers: authorization,content-type"
```

Tafsirkan hasilnya terhadap tabel baseline, lalu perbaiki konfigurasi server atau middleware aplikasi. Membypass kontrol bukan tujuan di sini.

## 9. Checklist baseline

| Kontrol | Target |
|:---|:---|
| HTTPS + HSTS | Aktif untuk host produksi |
| `nosniff` | Semua respons |
| CSP | Berbasis nonce atau hash; tanpa `unsafe-inline` yang tidak perlu |
| `frame-ancestors` / XFO | Pertahanan clickjacking |
| Referrer-Policy | Default yang tidak bocor |
| Cookies | `Secure; HttpOnly; SameSite` |
| CORS | Allowlist eksplisit; jangan gabungkan kredensial dengan `*` |
| Cache | `no-store` untuk JSON/HTML yang terautentikasi |
| Strip | `X-Powered-By` / nilai `Server` yang detail |
| Proxy | Normalisasi header `Host` dan forwarding |

```
 Tuas kepercayaan browser           Server harus menyetel dengan sengaja
 -------------------               -----------------------------
 CSP / COOP / CORP        <------  security middleware
 Cookie flags             <------  session layer
 CORS ACAO                <------  API gateway / app
 HSTS                     <------  TLS-enabled edge
```

## Catatan keamanan: ancaman dan pertahanan

| Ancaman | Sudut pandang header | Pertahanan |
|:---|:---|:---|
| XSS | CSP, nosniff, encoding | Pertahanan berlapis |
| CSRF | SameSite, token, Sec-Fetch | Lihat catatan CSRF |
| Clickjacking | `frame-ancestors` | Tolak secara default |
| Downgrade MITM | HSTS | Penerapan HTTPS yang benar lebih dulu |
| Token di Referer | Referrer-Policy | Jangan taruh secret di URL |
| CORS salah konfigurasi | ACAO reflection | Allowlist |
| Response splitting | CR/LF di nilai header | Tolak; gunakan API framework |
